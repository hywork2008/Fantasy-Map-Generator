## 1. 決定事項と互換性の範囲

全拡張機能を有効にした基準 master の「新しい世界の初期化がすべて完了した時点」を、人物生成の基準にする。feature ブランチで必要人数や財布の目安を独自に作り直すことをやめ、master が実際に作る人物の集合、兼任、初期所持金、家族人数を先に確定し、その集合からプリセットで必要な人物だけ詳細化する。

ユーザーの操作は引き続き世界全体 → 国家 → 組織 → 役職・個人。地図生成で公開 Character を一括追加しない。人物を詳細化するかどうかによって、他の人物の初期資金・家族・生成可否を変えない。

### 1.1 優先する契約

1. **master 基準の人物集合**：初期生成の条件・間引き・兼任・生成対象外をそのまま引き継ぐ。「世界に本来必要な全役職」と「master が初期化で人物化した席」を区別する。
2. **master 基準の所持金**：固定6周期、都市家計25%上限、元首優先や全役職按分では置き換えない。master の実際の初期化順・資金付与・最初の経済処理を反映した残高を基準にする。
3. **master 基準の家族**：人物ごとの配偶者・子・孫・曾孫の人数と、存在する実参照を保存する。家系図を開くために配偶者や子を余分に作ったり、未詳細化を理由に人数を0へ戻したりしない。
4. **遅延生成と保存**：基準初期残高を世界開始時に一度だけ計上し、後日の詳細化は口座への接続にする。削除・死亡時の通貨保存、錠前、追跡と時間送り停止は維持する。
5. **表示と参加設定の分離**：メモ用でも在職する役職を表示・保持する。人物シミュレーションへの参加だけを別に指定する。

このプロファイルでは、本書が既存設計の独自人数・初期資金係数より優先する。既存の有限家計からの配分は `household-funded-v1` として別プロファイルに残せるが、「master と同じ」と表示しない。新しい世界の既定生成プロファイルは `master-20261022-v1` とする。保存済み世界のプロファイルは自動変更しない。

### 1.2 「同じ」の判定

同一の開始前世界スナップショット、設定、生成乱数入力とタスク実行順について、次を個人単位で一致させる。

| 比較対象 | 一致条件 |
| --- | --- |
| 人物の種類・人数 | master の実生成人物集合と一致。官職数だけでなく生成されなかった席と兼任も一致 |
| 所属・役職 | 称号、領地・州・軍部隊・市場・ギルド・商会への参照を対応付けて一致 |
| 所持金 | 初期化完了時の各人物の実残高と合計が小数第2位まで一致。正しい0も一致 |
| 家族 | `spouses / children / grandchildren / greatGrandchildren` と、master に存在する親子・配偶者参照を一致 |
| 生成条件 | 種族・年齢・性別・能力方式・政体・宗教的役割等、上記3領域を決める入力・補正を一致 |
| 周辺依存 | 性格・技能・威信・関係・家門・装備等、生成可否・資金・家族に影響する値は基準候補から引き継ぐ |
| 数値ID | 実装上の通し番号は一致を要求しない。永続的な人物キーで比較し、全参照を一貫して変換する |

同じ地図seedだけでは保証条件を満たさない。feature 側の領地・市場・生産条件が異なる世界を、seedが同じという理由だけで同じ入力と見なさない。地形・人口・国家・州・文化・種族・経済設定・商品表等の入力ハッシュを記録する。master に非決定的な入力が残る箇所は乱数記録も固定し、未固定のまま完全一致を宣言しない。

対象は初期生成の再現。世界全体の歴史進行を永久に master と同じにする設計ではない。拡張した領地制度や人物の参加設定を変更した後のシミュレーションは分岐してよい。

## 2. 基準 master で確認した初期人物

以下は固定人数の想像上の構成ではなく、基準 master のコード上の条件である。世界ごとの実人数は基準実行から確定する。「全拡張機能」は、文化セットや能力方式などすべての生成条件を無視する意味ではない。

### 2.1 人物集合

| 種類 | 基準 master の初期生成条件・人数 | 兼任・例外と feature との差 |
| --- | --- | --- |
| 国家元首 | 有効国家ごとに1人。`Characters.generate` は `ck3e` のとき政治人物を生成 | Anarchy も Warlord 等を生成する。現 feature の Anarchy 除外は互換プロファイルへ持ち込まない |
| 中央官職 | 中世官職表の先頭N職。通常5職だが、`selectCentralOffices` の種族密度でNを減らす | Lich 国家は元首だけを生成し、中央官職を作らない。敵専用種族には官職の追加フィルターがある |
| 野戦・艦隊指揮官 | 非近衛・兵力80以上の部隊の空席に、初回 `assignOfficers` の35%抽選で専任者 | 近衛は既存 Marshal を参照し新人物を作らない。Lich 国家は専任指揮官を生成しない。毎回再抽選して全席を埋める方式にしない |
| 辺境州領主 | 脅威対象の州で、既存領主がいない場合に種族密度による抽選 | 内陸州の全州知事・全領主を作るわけではない。Lich 国家は対象外 |
| Gaelic 領地の人物 | 対象文化・中世の Gaelic 手続きが選ばれた国家で、領地台帳の `holderKind === character` の席を生成 | Sheriff は非領有官、Thane は任命/世襲で年齢入力が異なる。他地域の新しい欧州領地全体を master 初期集合へ加えない |
| 市場管理者 | 対象市場ごとに1人 | 敵専用種族の平和的商人生成を除外。担当市場の都市を出自・所属に使う |
| 市場の競合商人 | 同じ市場ごとに2人 | 都市ごとに2人を増やさない。管理者と合わせ原則3人/市場 |
| 商会代表 | 市場管理者を代表として参照し、商会代表の役職を追加 | 代表を別人物として作らない。基準 master の `MERCHANT_ORGANIZATION_STAFF_ENABLED` は false。書記・護衛・追加役員を自動生成しない |
| ギルド親方 | 初回 GuildSuccession が対象にする、知識stockが正の都市・分野に1人 | `SUCCESSION_DOMAINS` は metallurgy のみ。他分野の全ギルド長を互換初期集合へ追加しない。敵専用種族は対象外 |
| ギルド徒弟 | 冶金親方の熟練度40以上等の条件を満たすと生成。新親方の初回募集を強制する経路がある | 上限2人は初期人数2人の意味ではない。実際の初回呼出しと条件で確定。師弟関係は実子関係にしない |
| 潜伏 Demon | Fantasy 文化セットで、原則として有効国家数と同数の潜伏者候補を割り当てる | 既存人物を転換できる場合は人数を増やさない。宿主国家は割当関数に従い、必ず各国1人とは限らない。カバー層は ruler 15%、military 20%、influential 25%、commoner 40%を端数調整 |

基準 master の中央官職は `Chancellor / Marshal / Steward / Spymaster / Court Chaplain`。主能力は順に diplomacy / martial / stewardship / intrigue / learning。modern 官職表は定義されていても `CENTRAL_OFFICES` は中世表に固定されているので、互換プロファイルで無断で Prime Minister 等に置き換えない。独自の表示名・時代別官職は拡充側で扱う。

全拡張機能を有効にしても、船舶ごとの船長や船員、すべての都市の市長・参事会・司祭長、世界中の教会聖職者、御用商人が初期人物として一律に増えるわけではない。初期生成の入口と実際の生成記録を基準に含有を決める。

一般住民/冒険者は `generateBurgResidents` の明示操作で追加するもの。独立都市統治者の生成関数も存在するが、それだけでは初期化で呼ばれることの根拠にならない。基準初期メニューには実呼出しが記録された人物だけを入れ、手動追加は別メニューにする。

### 2.2 人物を作る際の入力

元首と領有領主は主に `marriageExpectation: dynastic`、中央官職と専任指揮官は `elite`、経済人物は既定の `ordinary` を使う。宗教的役割は政体と主能力から判定し、家族・性格・技能の生成へ渡される。中央軍務官は commander、宗教官は religious といった役割クラスの違いも残す。

`raceOverride`、国家の人種構成、従属種族、生成年齢の専用関数、generationBias、経済人物の男女数の均衡、出自・在職開始年、来歴、関係、家門生成、装備・称号の後処理を、汎用 `roleClass + primarySkill` だけに縮めない。特に経済人物の性別は既存の経済人物全体の男女数に依存するので、プリセットの実行順で決め直さない。

## 3. master 基準の所持金

### 3.1 付与処理を共通式に潰さない

`B` は `backPayCycles()` が返す4〜10の整数。原則として人物ごと・実際の呼出しごとに抽選される。`H` は `raceHoardBonus`。金額は `nominal()` による世界の moneyScale と既存の丸めを適用する。

| 対象 | master の初期資金の算定・付与経路 |
| --- | --- |
| 元首 | `getRulerHouseholdStipend(state, income) * B + H`。income は pollTax × (rural + urban)。俸給は政体別家政配分、下限・上限・実収入の制約を使う |
| 中央官職 | 部署の基準予算に対する個人俸給 × B + H。部署対応、丸め、軍務部署の `getMilitaryStructuralMultiplier` を含める |
| 専任指揮官 | `getFieldCommanderStipend(regiment) * B + H`。部隊維持費の15%、名目下限1.5・上限4.5に従う |
| 州領主 | `nominal(3) * B + H`。初期付与は都市金庫の残高や座都市の有無で制限しない |
| Holding の人物 | `entityType: holding` は既存の「州領主の初期金」ループと別。基準実行で資金付与がなければ0を再現し、領主というラベルだけで3 × Bを付けない |
| 市場管理者 | 作製時に `nominal(2.1) * B + H` を設定。その後の最初の給与等も初期化完了残高へ反映 |
| 市場の競合商人 | 作製時に `nominal(0.9) * B + H` を設定。同上 |
| 商会代表 | 兼任している市場管理者の同じ口座。代表という理由で開始資金を二度付けない |
| ギルド親方 | 実際の初回は GuildTreasury の開始資金と `seedGuildMasterStartingAssets` を追う。正残高を持った後は汎用バックフィルが上書きしない |
| ギルド徒弟 | 汎用バックフィルが実行された時点で、正のギルド金庫・双方向の師弟連帯20以上等が必要。年齢別小遣い × 関係補正 × 2〜6周期。初回付与がない個体は0 |
| 潜伏者 | 転換した既存人物の財布を共有。新規カバー人物は、その実役職に適用された資金処理だけを使う。Demon 専用資金を推測で追加しない |
| その他 | 基準実行で資金を付与されなかった人物は0。家族がいることだけで別の財布を発生させない |

基準定数の名目俸給は元首3〜15、中央官職2.4〜9、専任指揮官1.5〜4.5、州領主3、親方1.05、市場管理者2.1、競合商人0.9。収入や部署予算が小さい場合は下限未満や0にもなるので、全員の正残高を互換性の条件にはしない。

親方の初回経路は特に区別する。`cycles = max(1, rn(B * guildBootstrapMultiplier, 2))` によりギルド金庫へ `nominal(1.05) * cycles` を加え、その金庫から個人へ `rn(min(guildTreasury, min(nominal(3.15), max(nominal(1.05), guildTreasury * 0.12))), 2)` を移す。これを「すべての親方に1.05 × B + H」と読み替えると master の初期残高と一致しない。後続の `seedMissingCharacterWealth` が実際に呼ばれる順も記録する。

種族の蓄財は年齢依存で、`nominal(max(0, age - maturity) * raceRate)`。基準の race catalog と解決関数を使う。長命種全体への一律加算や、全員同じ固定貯蓄に置き換えない。

### 3.2 初期化完了残高を比較する

比較点 `T0` は、全拡張の map-ready task とその初期化イベントに伴う同期処理が完了し、ユーザーがまだ Advance Time を実行していない時点とする。比較ハーネスは完了境界を記録し、非同期の未完了処理を残さない。

Economy 初期化は生産・最初の徴税/給与・暖房・冶金処理・ギルド知識・親方/徒弟・ギルド資金等を進める。人物の作製直後の seed 金額と T0 の残高は同一とは限らない。互換側で master のT0残高を設定した後、もう一度「最初の1周期」を実行してはならない。逆に、ギルド初回処理の前に比較して全ギルドを0人と確定してもならない。

タスクの順序は `mapReadyTaskCoordinator` が依存関係と登録順から解決する。名称から Nobility → Economy の順と決めつけず、基準実行の順序、イベント、乱数消費を採取する。

### 3.3 通貨の総額と遅延生成を両立する

master の初期資金には、既存家計を引かず所持金を設定する経路がある。都市家計25%を取り分ける feature の方式とは、世界の開始時通貨量自体が異なる。両方式の総額を同じと仮定しない。

互換プロファイルは、master の **初期経済全体の予算** を採用する。初期個人資金は、基準実行の作製・付与・移管・最初の収支を記録した開始残高計画として世界開始時に一度だけ確定する。基準T0の金庫・家計・法人・個人口座の合計と一致させる。親方の金庫から個人への移管等は発行と二重計上しない。

- 未詳細化の基準人物の資金も、基準人物キーに対応する予約口座へ置く。人物が未表示でも世界の通貨量に含める。
- プリセット生成は予約口座を Character に接続する操作。選択範囲・生成順・再実行で通貨を増減させない。
- 個別残高の分布を保存する。4〜10周期や年齢別蓄財を、役職集団の平均額へ潰さない。既存の等分区間は、同額の集団にだけ使うか、キー付きの個別配分列へ拡張する。
- 0口座も初期化済みとする。`!wealth` を未初期化判定に使って再補填しない。
- 詳細削除、人物取消、死亡、相続では既存の移管・遺産口座を使う。master の旧処理で名前付き台帳から消えた相続資金を、feature でも消す必要はない。
- 開始残高確定後の新設役職・後任・追加の住民へ、T0の4〜10周期分を無制限に発行しない。master 初期集合の人物と、開始後に新しく作る人物を区別する。

有限家計の世界へ互換人物の差額だけ黙って足す移行は行わない。既存世界での扱いは§8に定める。

## 4. 家族・家門の再現

### 4.1 保存すべき master の家族

master の `generateFamily` は年齢・性別・政体・宗教的役割・結婚期待・種族の生殖特性を入力にして、主に家族の人数を返す。配偶者や子の Character を、その人数だけ初期作製する処理ではない。`spouseIds / childIds` は通常空配列であり、`marriages` や関係・家門は別の後処理である。

- 短命種は未婚確率、初婚年齢、婚姻期間、生殖可能期間、配偶者数、出産間隔・多産性から子の人数を求める。恒久的未婚率は ordinary 0.20 / elite 0.10 / dynastic 0.03、宗教的な場合0.20を使い、若年未婚の追加条件も適用される。
- Horde / Khaganate / Khanate / Empire の男性は配偶者基数1に2〜6、Emirate / Caliphate / Satrapy / Beylik / Sultanate の男性は0〜3を加える経路がある。役職名の King だけを見て家族を決めない。
- 長命種の断続的なペア形成では、過去に子を持ったかと現在の配偶者数を独立に扱う。「配偶者0なら子0」と補正しない。
- 孫・曾孫は子や年齢からの別の乱数計算であり、同じ乱数順・丸めを維持する。
- 未成熟者、非CK3能力方式、Lich / Zombie / Skeleton 等には家族を作らない経路がある。全拡張ONでもこの条件を外さない。
- `finalizeCharacterSociety` の家門生成は別に保持する。家門の共有を実親子の証明にしない。後から追加した人物への incremental finalize は、初回一括の家門割当と同じ処理ではない。

現在の `materializeSlots` のように、createPerson が返した family を直後に全項目0へ置き換えることを禁止する。`synchronizeFamily` も、名前の付いた子や配偶者の数だけで全家族人数を上書きしない。

### 4.2 人数と家系図を接続する

`HouseholdSnapshot` に基準時点の4種の人数と基準実参照を保存し、家系の「未詳細の続柄枠」と結び付ける。人数には、名前付き関係と未解決の人数の両方を含める。子を1人詳細化する操作は未詳細枠を1人分解決する操作であり、家族総数を1人増やす操作ではない。

master が持たない子の名前・年齢・生死・母父の対応を、master と同じデータと称して作らない。基準人数は正確に再現し、後からの具体化は「続柄の詳細を補完」と表示する。

- 配偶者・子・孫・曾孫を勝手に全員 Character 化しない。必要な枝と人数だけ具体化する。
- 初期人数の未解決分は、人物を作らない集計でも保持できる。家系図を開いただけでは、全員が生存中・同居中などの条件を付けない。
- 子の具体化は、年齢・種族・親の出産可能期間・既存親子関係の制約内で行う。基準にない情報は補完であることを記録し、錠前を優先する。矛盾を人数の切捨てや架空の出産で解消しない。
- 孫の親が不明なときは、未解決の枝として扱える。適当な子へ割り当てて「完全な master 家系図」が再現されたとはしない。
- master に実参照がある場合は、同じ referencePersonKey を再利用する。師弟関係、家門、政治的 marriage/bond と実親子・配偶者の種類を区別する。
- 家族枠を詳細化しても、親の所持金を複写しない。資金のある基準人物なら予約口座、基準にない新しい家族なら明示配分・相続等の別処理で対応する。

錠前・子孫追跡・指定年齢/死亡前停止はこの枠へ接続する。家族人数の互換再現と、基準にない家族の生涯を推測して進めることは別の操作にする。

## 5. プリセットメニュー

Characters Overview → Organizations & families のプリセット領域に「生成基準」を追加する。既定は **master 初期生成互換**。すぐ下に基準コミット、世界開始日、対象国家/組織、参加モード、資金の基準を表示する。

| メニュー | 対象・内訳 |
| --- | --- |
| master と同じ初期人物をすべて | 基準T0の実人物の和集合。下記の兼任や潜伏者の転換を重複排除 |
| All heads of state — master | 基準元首。Anarchy・Lich等の生成条件も基準のまま |
| National leadership — master | 基準元首＋基準で実生成された中央官職。元首メニューとの同時選択でも元首は一人 |
| Military commanders — master | 基準で生成された専任指揮官。近衛の Marshal は既存の同一人物を表示 |
| Provincial & holding nobility — master | 基準の辺境州領主と Gaelic 領地人物。新しい欧州全土の領主定員は混ぜない |
| Market & merchant leaders — master | 管理者1＋競合商人2/対象市場。商会代表は管理者の兼任として表示 |
| Guild masters & apprentices — master | 基準初回の冶金親方と条件を満たした徒弟。役職・師匠・人数を表示 |
| Covert characters — master | Fantasy 条件下の潜伏者。既存人物の転換と追加人物を別計数。世界設定者向けのネタバレ表示を明示 |
| Family details | 選択した基準人物の家族人数と既知参照。家族全員/子1人等の補完は別ボタンで実行 |

既存の `All heads of state / National leadership` 等は、生成基準に応じて意味を解決する。master モードで画面に同じ名前の異なる人数のメニューを二重に並べない。

「制度を拡充して生成」は別グループにする。全必要軍団長、全主要封建領主、全ギルド分野の長、商会書記/護衛、都市統治者、越境教会の司祭、御用商人、一般住民・冒険者等はここから選ぶ。master の初期再現セットに含まれない理由を表示する。master プリセットを選んだだけで拡充役職を自動追加しない。

### 5.1 プレビュー

役職ごとに、機関名、master の生成可否と理由、役職席数、兼任先、実人数、新規詳細人数、既存人物、初期資金の個人別範囲/合計、家族4種の人数、0残高の理由を表示する。抽選対象席数と、基準で当選した実生成人数を別に出す。

例：近衛部隊長1席の行に「Marshal が兼任・新規0人」、商会代表1席に「市場管理者が兼任・新規0人」。徒弟上限2に対して基準初回1なら、人数は1とする。プリセット同時選択の合計は役職席数の単純加算にしない。

プレビューは確定済み基準計画を読むだけにする。画面を開くたびに35%抽選や家族・バックペイを引き直さず、家計・口座・個人枠を変更しない。初回計画の準備が必要なら「master 基準計画を準備」と進捗を表示し、その処理とプレビューを区別する。

### 5.2 メモ用とシミュレーション参加

生成ダイアログ内に **メモ用（設定を固定） / 人物シミュレーションに参加** の選択を表示する。既定は master の稼働状態に合わせて参加。現在のようなプリセット呼出しの `mode: memo` 固定を廃止する。

どちらでも、基準の在職・称号・職業・家族を持つ。メモ用を選んだ理由だけで無職にしない。参加の有無、在職の有無、未詳細化の有無は別の状態とし、運用参照と人物AIの有効化を同じboolで兼用しない。初期の経済集計は詳細化人数に依存させない。

メモ用の固定年齢と、世界経済内で変動する口座残高も区別して表示する。master T0 の参照所持金は履歴として見られるが、現在の財布をT0に戻すボタンではない。

## 6. 再現計画・乱数・実装構造

### 6.1 安定キーだけの再seedでは master と一致しない

master は `Math.random = Alea(...)` と既存人物配列、後処理、他の生成処理が消費する乱数に依存する。`rosterRandom(seed, roleId)` を使って同じ分布の別人を生成するだけでは、同じ個人資金・家族人数にならない。プリセットの実行順による差も解消する必要がある。

実装は、基準 master の初期化を再現する **ReferenceGenerationCompiler** と、その出力を必要な部分だけ読む **Materializer** に分ける。

1. 開始前世界のコピー、設定・カタログ、拡張一覧、タスク順・乱数入力を固定する。
2. 基準ロジックを隔離された worker/評価コンテキストで評価し、人物候補・兼任・家族・初期経済イベントを含む参照計画を作る。本体の `Math.random`、時計、口座、描画・通知へ書き込まない。
3. 乱数区間/再生記録と、候補依存の性別・種族・年齢・家族・技能等、再現に必要な値を保存する。人物名・家門・完全容姿上限・関係生成が他候補に依存する場合は、全候補を同じ順序で評価する。
4. 基準T0の状態と初期イベント計画を検証し、実世界の軽量在職枠・口座・家族集計へ一度だけコミットする。初期化の相互作用を、現在の feature の汎用初期化の後に上乗せしない。
5. プリセットは referencePersonKey の集合を選び、保存された基準候補から Character を25人ずつ公開する。先に選んだ人物を入力にして他候補の生成内容を変えない。

厳密互換の準備には、master の人物生成に相当する全候補の計算が必要になる場合がある。公開Character数と保存する詳細は遅延できても、**初回計算量まで常にゼロにできるとは約束しない**。現在のグローバル乱数と全候補依存を残したまま「任意順で同一個体を完全に遅延計算できる」としない。準備は中断・進捗表示できるようにし、失敗・中断した計画は本体へ部分適用しない。

本体の `pack.characters` に全NPCを一時追加してから消す実装は禁止する。隔離候補を軽量なレシピ/共通集計へコンパイルする。保存時に再生不能な参照が残る箇所は必要最小限の候補値を保存する。既定は家族まで全員分の完全Characterを重複保存する方式にしない。

製品実行中にgitの master を読み出す依存を作らない。必要なコードをバージョン付きの生成プロファイルへ抽出し、基準masterを動かす比較ハーネスは開発用に分離する。ロジックの二重保守を避けるため、共有可能な純粋関数は共通化するが、基準結果が変わったら別バージョンにする。

### 6.2 データ

| データ | 必須内容 |
| --- | --- |
| GenerationProfile | profileId、schemaVersion、masterCommit、入力/カタログ/乱数のhash、基準日時、初期化タスク列、能力方式、対応拡張一覧 |
| ReferenceGenerationPlan | 対象全体、準備状態、候補数、重複排除索引、基準経済状態のhash、初期資金コミットID、生成レシピ版 |
| ReferencePerson | 永続key、master上の生成順/ID対応、生成条件、役職・兼任、所属、年齢等の再生入力、家族snapshot参照、口座参照、必要な候補依存値 |
| HouseholdSnapshot | 基準4種人数、既知関係、未解決人数、追加補完の出所、固定基準日 |
| OpeningBalancePlan | 受取口座、金額、master資金イベント種別、初期予算の加算と既存金庫からの移管の区別、処理済みID |
| MaterializationPlan | referencePlanId、選択人物key列、モード、基準/実行日時、入力revision、cursor、破棄/完了状態 |

個人枠と `PresetQuery / PresetPlan` に profileId と参照計画IDを追加する。資金口座の所有者は数値Character IDでなく永続人物keyで識別できるようにする。Marshal、商会代表、潜伏転換の別名索引も同じkeyへ解決する。

Role の必要定員は既存組織設定として保持し、master eligibility / selected / omittedReason を別属性にする。互換プリセットの人数を合わせるために、ユーザーが編集した定員や拡充領地を破壊しない。

### 6.3 未詳細化でも読むべき情報

master 初期処理が元首の性格、官職の能力、市場管理者、親方を参照する箇所を棚卸しする。そこで「Characterがないので未就任・能力0・支払先なし」とすると、生産や資金付与が変わる。`PersonResolver` 等の読み取りポートで基準候補の役職・能力・関係・口座投影を参照できるようにする。

公開Characterがなくても、基準に従う運用上の在職・指揮・代表・師弟関係は有効に扱う。`rulerId / commanderId / managerCharacterId / organizationId(masterId)` の数値参照だけを前提にした箇所はkey対応を追加し、公開時に一貫してIDへ接続する。親方口座と法人金庫、元首と家政金庫は統合しない。

## 7. 時間送り後に人物化する場合

master T0 と同じ値を保証するのは、基準日時における初期人物の記録である。世界を10年進めた後に、T0の若さと財布を現在の人物へそのまま再配布することではない。

- 初期人物の在職・家族・口座は未詳細化の間も同じ人物keyで保持する。後日の人物化は現在の状態に接続し、T0の資金は再発生させない。
- メモ用なら固定参照日を表示し、年齢等の設定を保持する。参加人物は既存の寿命・承継・追跡・停止規則に従う。
- 初期人物がすでに死亡・退任した場合は、その記録を見るか、現職の後任を生成するかを区別する。基準人物を黙って新しい若い後任へ差し替えない。
- master が初期に持たなかった具体的な子孫の年齢・生死を後付けで一気に進め、観察対象を失わせない。補完時の基準日と見守りを表示する。

初回受入はT0の厳密比較を優先する。歴史進行でのmasterとの完全一致は受入条件にせず、遅延生成・通貨保存・追跡の不変条件を検証する。

## 8. 保存と既存世界

| 世界の状態 | 対応 |
| --- | --- |
| 新規世界 | master互換を既定とし、開始前に基準計画・資金を確定してから選択生成可能にする |
| master保存をfeatureで読む | 実在人物・所持金・家族・兼任を正本として移行。再抽選・再seedしない。未生成の初期人物がいたと推測して追加しない |
| feature保存、有限家計プロファイル | 現在の資金・定員・家族を維持してそのプロファイルを表示。互換化したと偽らない |
| 編集・時間送り済みのfeature世界 | masterの開始前入力がない場合は完全復元不能と表示。現在日から同じ規則で追加生成する操作と、master初期世界の再現を区別 |
| 新規基準を試す | 元の世界を上書きせず、同じ開始前スナップショットから派生世界を作る。人物数・資金・家族の差分をプレビューする |

旧世界に対して元首の貯金を徴収したり、全有給人物へ4〜10周期分を配り直したりしない。既存の明示的な0残高補正は家計からの任意移管であり、master互換世界への変換ではない。UIの名称と結果でも区別する。

保存検証は、人物keyの一意性、兼任の同一性、口座の一対一接続、家族人数の非負整数、参照整合、初期資金の二重適用禁止、準備中計画と完了計画の区別を検査する。新旧保存の読込に必要なschema移行を用意する。

## 9. 実装順と検証

### 9.1 実装順

1. **基準採取**：固定masterを独立worktree/検証環境で実行し、開始前入力・全拡張設定・タスク列・乱数・T0の人物/財布/家族/運用参照を採取する。先に差分の正解を固定する。
2. **プロファイル抽出**：人口・種族条件、官職間引き、軍抽選、領主、経済人物、潜伏者、家族、初期資金をバージョン付きレシピにする。各抽出で基準出力と照合する。
3. **参照計画と読み取りポート**：未詳細化の候補を使って初期の役職/経済依存を満たし、兼任と軽量家族集計を保存する。
4. **初期経済の接続**：masterの開始予算・一度限りの付与・移管・初期収支を再現する。既存25%按分を互換経路へ重ねない。
5. **プリセットと画面**：masterモードの一覧、家族表示、範囲選択、参加切替、プレビュー、中断/再開を接続する。
6. **移行と文書**：master保存の移行と旧featureプロファイルの維持を実装する。比較が通った範囲だけ互換と表示し、既存設計書の実装メモを更新する。

### 9.2 必要な比較ケース

少数の固定入力を用意し、関連テストとして明示実行する。全件テストや多数の無作為seedを完了条件にしない。

| 入力・操作 | 確認内容 |
| --- | --- |
| 人間の王国・共和制・Anarchy | 元首、5官職/条件、称号、家族期待、初期金の役職別一致 |
| 長命単一種族・混合国家 | 官職N、種族・年齢・断続家族、蓄財、男女均衡 |
| Lich・敵専用種族 | 生成抑止と家族0。masterにない席を補填しない |
| 近衛・兵力79/80以上・艦隊 | Marshal兼任、閾値、初回35%抽選、新規人物数 |
| Gaelic領地・その他の内陸/辺境州 | 領地人物、Sheriff、辺境密度、0財布を含む実結果 |
| 市場・商会 | 1＋2、代表兼任、書記/護衛0、生成時所持金とT0差分 |
| 冶金stockと親方技能・師弟関係 | 対象分野、親方と徒弟の実人数、親方開始資産、徒弟の正当な0 |
| Fantasy と非Fantasy | 潜伏転換/追加の区別、元の人物・口座・家族との対応 |
| 両首脳プリセット同時/逆順/別々 | 人物数、個別所持金、家族がすべて同じ。元首を重複作製しない |
| 保存・再読込・中断再開・詳細取り外し | 名前、役職、key、口座、家族を維持。資金再付与なし |
| 家族を1人→残り全員の順で具体化 | 基準人数は不変。既知関係を重複せず、補完情報を明示 |
| メモ/参加切替・時間送り | 役職を失わない。現在の財布をT0へ戻さない。見守りで停止 |

比較は人物keyをそろえた上で、役職・種族・年齢・性別・家族4項目・所持金・兼任・機関側参照の差を一件ずつ出す。金額差は整数の最小通貨単位で0を要求し、平均や分布が近いだけでは合格にしない。

完全選択でmasterの実人物集合に一致することと、何も人物化しない/一部だけ人物化する場合も基準初期通貨量が同じであることを両方検証する。masterの全人物表示とfeatureの全人物表示を比較するだけでは、遅延生成の保存則の検証にならない。

### 9.3 この設計作成時に実施した確認

設計時はローカルmasterとfeatureのソースをread-onlyで比較した。その後の実装で、上記実装メモの固定入力2条件についてmasterの別実行との人数・個別金額・家族を実測比較した。本文の制度上の定数・式と、実装メモの固定入力の実測結果は区別する。
