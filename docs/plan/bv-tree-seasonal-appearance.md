# BV樹木の季節の姿と結実層の設計

作成日：2026-10-30

## 1. 目的と派生元

[Crop climate guideの作物に対応するBV果樹追加計画](fmg-crop-climate-bv-fruit-tree-tasks.md) §18（P6最終台帳と後続作業）から派生する。BVの全32樹種は現在、1樹種につき1つの静的な姿しか持たない。本書は次の3点を設計する。

1. 1年を通じて樹木に必要な姿（落葉・開花・結実・収穫後・紅葉など）の種類を定義し、**樹種ごとに必要な姿の数**を確定する。
2. 姿の切り替えを、樹種ごとのモデルを作り直さずに「骨格は不変、層と配色を切り替える」方式で実現する生成器・登録・CE接続の契約を決める。
3. 果実が描かれていない、または三角形のマーカーだけで表した木（オリーブ・ナツメヤシほか）へ、**果実を後から加えられる共通の結実層**を設計する。あわせて、森林の木として作られたオリーブ・ナツメヤシとは別に、果樹園で育てる姿（栽培形）を登録する方法を決める。

経済・作物暦・収量の計算は変更しない。描画側が収穫量や気候を算出・書き換えることはしない。

## 3. 姿の分類

### 3.1 基本の姿（7種）

樹木の「姿」は植物学上の生育段階そのものではなく、**見た目が変わり、地図上で描き分ける価値がある状態**とする。月単位で切り替える（FMGの時間解像度が月であるため）。

| キー | 名称 | 内容 | 対象 |
| --- | --- | --- | --- |
| `bare` | 落葉 | 葉のない冬の枝。樹種固有の冬の付属物（ハンノキの球果と雄花序など）を含む | 落葉樹 |
| `bloom` | 開花 | 遠目にも分かる花・花序。開花が葉より先か同時かは樹種で異なる | 花が目立つ樹種 |
| `leaf` | 葉 | 夏の葉。果樹では未熟で目立たない時期（小さい緑の実を高品質だけに描く） | 全樹種 |
| `unripe` | 未熟果 | 色の変化が目立つ果実の熟す前の段階（オリーブの緑果、ナツメヤシの黄・赤のハラール） | 果実の色の変化が大きい樹種 |
| `fruit` | 結実 | 熟した実、または収穫期の実 | 実を描く樹種 |
| `harvested` | 収穫後 | 実を取り終えた姿。多くの樹種は「葉＋実なし」と同じ形で、月に応じて夏または秋の配色 | 果樹 |
| `autumn` | 紅葉・黄葉 | 落葉前の葉の色 | 色づく落葉樹 |

### 3.2 姿に数えない派生配色

形を変えず、配色だけを月で変える。姿の数には数えず、各姿の上に重ねる。

| 派生 | 内容 | 例 |
| --- | --- | --- |
| `flush` | 芽吹き直後の明るい黄緑 | ヤナギ・シラカバ・ブナ・ナラ |
| `winterTint` | 常緑針葉の冬の黄緑化・ブロンズ化 | ヨーロッパアカマツ・ベイスギ・コノテガシワ |
| 果樹の秋色 | `harvested` の葉を秋の配色にする | リンゴ・セイヨウナシ・イチジク等 |

### 3.3 姿として扱わないもの

- **積雪**：樹種によらない覆いとして、CE・BV共通の別設計とする。樹種ごとの姿に含めない。
- **乾季の落葉**（カポック・アンブレラソーン・インドボダイジュ）：FMGの月別降水に季節差がまだなく、乾季を判定できない。降水の季節性が入るまで `leaf` の1種とし、後続課題 X01 とする。
- **落ちた実・いが・落ち葉**：樹木モデルではなくCEの地表の表現として後続にする。
- **2D表示**（FMG・RE・CEのSVG森林）：本書の対象外。CEの3Dが完成した後に別途扱う。

## 5. 姿を決める規則

### 5.1 樹種の季節プロファイル

`src/buildings/landscape/treePhenology.ts` の `TREE_PHENOLOGY` に32樹種のデータを置く（T0で実装）。BVのプレビューとCEが同じ表と判定関数を使う。

| 項目 | 内容 |
| --- | --- |
| `leafHabit` | `deciduous`／`evergreen`／`leafless` |
| `appearances` | §4の「必要な姿」。判定関数はこれ以外を返さない |
| `defaultAppearance` | §4の「既定」。現行モデルの姿 |
| `bloom` | 描画の手がかり。`beforeLeaves`（冬枝に花）／`withLeaves`／`summer`（果実を持たない樹種は暑い月に開花） |
| `fruitDevelopmentMonths` | 収穫開始の何か月前から実が育つか。その最初の月が開花 |
| `harvestAnchor` | 収穫開始の月を気温の目印（`autumn`＝秋の始まり、`warmest`、`coldest`）からの月数で表す |
| `fruitMonths` | 作物暦がないときの収穫の長さ（既定2か月） |
| `perennialCrop` | 実を作物として採る樹種の、`PERENNIAL_CROP_PROFILES` のキー（例 `"Apples"`）。翻訳名・数値IDから引かない |

落葉の判定は全落葉樹で共通の係数 `TREE_DORMANCY` を使う。T0で、絶対温度だけの閾値では冬の月平均が10°Cある地中海で落葉しないことが分かったため、**年較差の中の位置**（最寒月0〜最暖月1）と絶対温度の下限を組み合わせた。

| 係数 | 値 | 意味 |
| --- | ---: | --- |
| `ceilingC` | 13°C | 最寒月がこれ以上なら休眠しない（通年葉） |
| `leafOutFraction`・`leafOutMinC` | 0.3・7°C | 暖かくなる半年で、両方を満たす月から葉 |
| `autumnFraction` | 0.55 | 涼しくなる半年で、これを下回る月が紅葉 |
| `bareFraction`・`bareBelowC` | 0.22・6°C | 涼しくなる半年で、どちらかを下回る月から落葉 |
| `summerBloomFraction` | 0.85 | 果実を持たない夏咲きの樹種の開花月 |
| `aseasonalRangeC` | 5°C | 年較差がこれ未満の気候は季節がないとみなす |

値は初期のゲーム係数で、T1以降のBV・CEの実表示で較正する。月単位の判定であり、日別の霜や積算温度を再現しない。

### 5.2 判定関数

`resolveTreeAppearanceYear(species, input)` は12か月分、`resolveTreeAppearance(species, month, input)` は1か月分（`simulationContext.currentMonth` と同じ1始まり）の `{ appearance, autumnPalette }` を返す純関数とする。描画側から経済・気候を書き換えない。

- `monthlyMeanTemperatureC[12]`：セルの月平均気温。南半球は気温の並びで自然に反転するため、緯度による分岐を持たない。
- `harvestWeights[12]`（任意）：経済拡張が計算した多年生作物の月別収穫重み。

**収穫の時期**：T0で、経済の作物暦は全月が生育可能な気候で生育期を1月から始めるため、地中海・熱帯の全果樹の収穫が5〜6月になることが分かった（[T0記録](../analytics/tree-phenology-t0-20261030.md)）。そのため、

- 年較差が `aseasonalRangeC` 以上の気候では、収穫開始を `harvestAnchor` から決め、作物暦からは収穫の月数だけを使う（作物暦がなければ `fruitMonths`）。
- 季節のない気候、または `harvestAnchor` を持たない樹種（カカオ・アラビカコーヒー）では、作物暦の収穫月に従う。
- 経済の作物暦そのものは変更しない。描画の収穫月と経済の収穫月が地中海で一致しないことは後続課題X06とする。

**月ごとの姿**：収穫開始から1年を順にたどる。

| 条件 | 姿 |
| --- | --- |
| 収穫の月 | `fruit` |
| 収穫開始の `fruitDevelopmentMonths` か月前 | `bloom` |
| 開花の後、収穫の前 | `unripe` |
| 収穫の後 | `harvested`。落葉を経た後の春は `leaf` |
| 落葉樹で落葉の月 | `bare`（冬枝に咲く `bloom` は残す） |
| 落葉樹で紅葉の月 | `leaf`・`harvested` は `autumn`。未熟果・実は姿を保ち、`autumnPalette` で秋の配色 |
| 実の時期を決められない（季節がなく作物暦もない） | 落葉樹は気温の判定だけ、常緑樹は `defaultAppearance` |
| 入力がない | `defaultAppearance` |

樹種が持たない姿は近い姿に置き換える（例：`unripe` を持たないリンゴは `leaf`、`leaf` を持たないヨーロッパグリは形が同じ `harvested`、`autumn` を持たない果樹は `harvested`）。

### 5.3 果樹園の収穫の途中

収穫期の果樹園では、取り終えた木とまだの木が並ぶ。判定関数が決めた収穫の月の中での経過（作物暦の時期に従う気候では、その月までの `harvestWeights` の累積）を収穫の進み具合とし、木ごとの安定したハッシュがそれ以下なら `harvested`、それ以外を `fruit` にする。1本の木の中で実を間引くのではなく、木単位で切り替える。CEの同時prototypeは1樹種につき最大2つ（`fruit` と `harvested`）になる（§8.3）。

## 6. 生成器と登録の契約

### 6.1 骨格は不変、層を切り替える

```ts
createDomesticApple(quality, { appearance: "harvested", autumn: true })
```

- 樹木を **木部（幹・枝）／冬枝／葉／花／果実／付属物** の層に分ける。各層は1つのmesh・1つの材質にまとめ、姿の切り替えでdraw callを増やさない。
- 木部の乱数列は姿に依存しない。葉・花・果実・冬枝は木部の乱数から導いた**層ごとの別の乱数列**を使い、ある層の有無で他の層の位置がずれないようにする。既存の「全品質が同じ乱数列を消費する」約束を「全品質・全姿が同じ骨格の乱数列を消費する」へ拡張する。
- 葉・花・果実は骨格が出す**取り付け点**（葉の付け根・短果枝・節・幹）に置く。冬枝は同じ取り付け点へ向かう細い小枝として作るので、葉があるときの枝先と冬枝の枝先が一致する。

### 6.2 層の品質別の扱い

| 層 | ultra / high | medium | low |
| --- | --- | --- | --- |
| 冬枝 | 取り付け点まで先細りの小枝。highは本数を縮約 | 2次枝までの管と、小枝の束を不透明の薄い錐で近似 | 幹と主枝6〜10本。樹冠の外形に沿う低密度の小枝の殻を試作して判断 |
| 花 | 花の形と付き方（短果枝の花房・節の群・雄花序） | 樹冠の房の頂点色を花の色へ寄せ、少数の花房 | 樹冠の頂点色だけ |
| 果実 | §7の結実層 | 果実群の少数の形・色 | 省略。レモン等の目立つ色だけ樹冠の点で任意 |
| 配色（紅葉・未熟果・派生） | 層の頂点色を変換 | 同左 | 同左 |

既存の制作目安（low≤500、medium≤3,000、high≤25,000、ultra≤120,000三角形）を**姿ごとに**満たす。bareは葉を外すので通常は目安内に収まるが、ultraの冬枝が葉の代わりにならないよう本数を計測して決める。

medium・lowの冬枝は、葉群を楕円体の房で表す現行方式（[tree-medium-canopy-lobes.md](tree-medium-canopy-lobes.md)）がそのまま使えない。不透明な灰褐色の房は「灰色の茂み」に見えるため採らない。透明・ディザの材質を使うかはT1の試作で判断する。

### 6.3 登録

- `TREE_DEFINITIONS` の各品質のfactoryを `(appearance?: TreeAppearanceOptions) => CityStructureMeshes` に広げる。`ModelVariant` は引数を型引数で持てる（`ModelVariant<Args>`）ので、樹木の版を `ModelVariant<[TreeAppearanceOptions?]>` にする。
- **姿はeditionにしない**。editionは同じ作者の代替実装で、CE採用表が選ぶもの。姿は採用した版に渡す表示の引数である。
- ある作者の版に別の作者が姿の層を加えた場合は、その版の `credits` に記録する。同じ姿の層に競合する2つの実装ができたときだけ、新しいeditionとして分ける。
- `43-landscape-treesModels.ts` の説明文の "seasonal changes are omitted" は、姿を実装した樹種から順に、対応する姿の一覧へ書き換える。

### 6.4 既定の姿の不変

`appearance` を省略した呼び出しは、現行モデルと**頂点・色・index・mesh名が同一**の出力を返す。既存のCE出力・BV採用・保存計測を変えないための回帰条件であり、各樹種の姿を実装する際に既定の姿のジオメトリのハッシュを比較するテストを1本置く。

## 7. 結実層：果実を後から加える仕組み

### 7.1 構成

```ts
interface FruitSite { position; hang; parentRadius; order; kind: "spur" | "node" | "axil" | "trunk" | "strand" }
interface FruitSpec {
  shape: "pome" | "pyriform" | "drupe" | "citrus" | "pod" | "bur" | "berryCluster" | "bunch";
  sizeMeters; stalkMeters; cluster: { count; spread };
  palettes: { unripe; ripe; afterRipe? };
}
buildFruitLayer(sites: FruitSite[], spec: FruitSpec, quality, { stage, density }): THREE.BufferGeometry
```

- 骨格が取り付け点 `FruitSite` を出し、樹種の `FruitSpec` から共通の作り方で1つのgeometryを作る。果実ごとのmesh・材質を作らない。
- `stage` は `unripe` / `ripe` / `afterRipe` の配色、`density` は0〜1。`order`（木の中で安定した順番）で部分集合を選ぶので、密度を変えても残る実の位置は動かない。レモンの収穫後（黄果を少数残す）やカカオの若果はこの密度で表す。
- 果実の数を収量に換算しない。
- §6.4の不変は姿を追加するときの条件である。オリーブ・ナツメヤシの三角形のマーカーの置き換えは既定の姿そのものの改訂なので、新しいeditionとして登録し、CE採用表で切り替える。旧版は比較用に残す。

### 7.2 適用

| 対象 | 内容 |
| --- | --- |
| オリーブ（O02） | 葉群の頂点色に混ぜた三角形のマーカーをやめ、1年枝の葉腋に短い果柄で付く楕円の核果へ置き換える。緑（unripe）→緑と暗紫の混在（fruit） |
| ナツメヤシ（D02） | 4本の軸の周りの点を、枝分かれした果房の軸と果柄に付く楕円の実へ置き換える。黄〜赤（unripe）→茶（fruit）。収穫後は房を切った果柄の残りを付属物の層で描く |
| ヨーロッパグリ | 既存の緑のいがはunripeとして保ち、fruitは茶色に割れたいがと見える実を加える |
| 既存8果樹 | 既に果実meshを分けているので作り直さない。`stage` の配色と `density` の部分集合だけを既存の果実生成へ加える |
| 森林の木（任意） | ナナカマドの実（既存）、イチイの仮種皮、ナラのどんぐり、シデの苞は、取り付け点があれば同じ層で加えられる。景観の大きさでほぼ見えないものは制作の優先度を低くする |

### 7.3 果樹園の栽培形

既存のオリーブとナツメヤシは森林・景観用の姿で、果樹園で手入れされた木とは形が違う。栽培形は**別の樹種キー**として登録する。

| キー | 内容 | 既存との関係 |
| --- | --- | --- |
| `olive_orchard` | 対象地域・時代の剪定資料に基づく、開いた中心と3〜4本の主枝、低い樹高の管理樹形（O01） | `olive` は地中海の森林・景観用の老木として残す |
| `date_palm_orchard` | 枯葉を払った幹、整えた冠、ひこばえの扱いを定めた管理樹形（D01）。雌木・雄木・若木の区別はD03 | `date_palm` はオアシスの景観用の雌木として残す |

- 季節プロファイル・`FruitSpec`・作物との対応は元の樹種と共有する。
- 新規8果樹は既に果樹園の独立成木として作ってあるため、栽培形のキーを追加しない。
- 現代の垣根状の密植を全時代の既定にしない。CEでの選択（森林か果樹園か）は果樹園接続計画で決める。

## 8. CEへの接続

### 8.1 記述子

| 追加する項目 | 出所 | 層 |
| --- | --- | --- |

### 8.2 表示の月

- CEの表示の月は、既定で記述子の月とする。CE上で月を変えるのは**表示の設定**で、配置・保存される都市の内容・Undo/Redoの対象にしない。
- 自然林・公園・墓地の木は気温の規則、果樹園の木は作物暦の規則で姿を決める（§5.2）。

### 8.3 描画と予算

- BV prototypeのキャッシュキーを `${variant.id}|${appearance}${autumn ? "+autumn" : ""}` にする。月を変えると新しいprototypeを作り、使わなくなったものは既存の追い出しで解放する。
- 近景の詳細木の上限（同時4樹種）を「同時のprototype数」に読み替える。果樹園の収穫途中で1樹種が2つを使う場合も上限内に収め、超える分は既存の簡略木に回す。
- 遠景の集合林冠（`forestMeshes.ts`）は、落葉樹の割合に応じて冬の灰褐色・秋の色へ配色を変える。形は変えない。
- 季節の切り替えで森林の配置・樹種の選択・寸法を変えない。
