# CE：人口入力による都市生成とパリ級都市の面積・表示設計

- 作成日: 2026-10-15
- 状態: 設計案。人口入力UI・集約住宅・可変セルは未実装。本書の数値は試算であり、性能測定結果ではない。
- 対象: `src/city-editor`。FMGからの人口引継ぎも共通化する。廃止予定のCGは対象外。
- 関連: [経済に依存しない城外成長](ce-extramural-growth-without-economy.md)、特に§6.1・§6.2・§11。

## 1. 目的と採用方針

CEの都市生成オプションに人口入力を追加し、人口から必要住戸、住宅容量、都市面積、セル解像度、表示フレームを順に求める。15万人を「パリ級」の初期対応上限とする。これは製品上の対象範囲であり、史実の中世ヨーロッパ最大人口という意味ではない。

都市全体の敷地面積と距離を維持しながら、住宅群を10〜20住戸単位で表現し、全住戸・全建物の詳細ポリゴン生成を避ける。道路・河川・城壁・主要施設は実寸で配置する。画面上の住宅群は代表的な図形であり、実在する巨大な一棟として扱わない。

採用する原則:

1. 人口、住戸、推定実棟数、表示住宅群数を別の量とする。
2. 面積は人口と住宅モデルから決め、セル数や表示図形数から逆算しない。
3. 全座標をメートルのまま維持する。粗いセルは広い実面積を担当し、scale barは実際の座標に追従する。
4. パリ級の標準表示フレームはまず4.8kmで検証する。必要範囲が超えた場合にのみ広げる。
5. 人口収容を理由に城外成長、河川、固定建物、橋の制約を破らない。不足は未配置として表示する。

## 2. 根拠と計算の位置付け

### 2.1 歴史資料から得られる面積

セッションで参照した資料:

- [パリ市：フィリップ・オーギュストの囲郭](https://www.paris.fr/pages/sur-la-piste-de-l-enceinte-medievale-philippe-auguste-rive-gauche-episode-2-2-21081): 約273ha。一部資料の253haとの差を平均せず、本書では273haを参考値に採用する。
- [La population de Paris avant la peste noire](https://www.persee.fr/doc/crai_0065-0536_1966_num_110_4_12047?pageId=T1_542): 後のシャルル5世の囲郭に対応する都市範囲439haと、城外にも人口が存在したことを論じる。439haを1328年時点の城壁面積と誤記しない。
- [Centre André-Chastel：Atlas de Paris au Moyen Âge](https://www.centrechastel.sorbonne-universite.fr/en/works/atlas-de-paris-au-moyen-age): 1300年頃の人口約20万人を紹介。15万人は史実の最大人口と断定できない。

囲郭面積には道路、水面、施設、庭、未建築地が含まれる。都市住民全員が囲郭内に居住したとも限らない。これらは同一年・同一範囲の人口密度統計ではなく、都市規模の較正資料として使う。

| 面積基準 | 面積 | 円相当直径 | 50m四方換算セル数 |
| --- | ---: | ---: | ---: |
| 初期の囲郭参考値 | 2.73km² | 1.86km | 1,092 |
| 後期の囲郭参考値 | 4.39km² | 2.36km | 1,756 |

円相当直径は `2 × sqrt(A / π)`。4.39km²を長短比1.5〜2.0の楕円と仮定すると長径2.90〜3.34kmとなる。実際の城壁端点や城外集落の末端を測量した距離ではない。Google Maps上の現代パリ約11kmを中世都市の目標幅に転用しない。

### 2.2 住宅容量による試算

既存計画§6.1の暫定値を採用する。これらは歴史統計ではなく生成器の較正係数である。

```text
P = 入力人口（人）
H = ceil(P / 4.5)                     必要住戸
c_i = floor(F_i × s_i × r_i × 0.75 / 40)
F_i = 建築面積m²、s_i = 階数
r_i = 住宅0.85、混合用途0.55
```

容量0の建物を1戸に切り上げない。4.5は既存の`URBAN_DWELLING_SIZE`を共有する。

15万人では33,334戸。80m²の住宅を仮定し、市街地全体に対する住宅建築面積比を暫定30%と置くと次のようになる。

| 構成 | 必要住宅棟数 | 住宅建築面積 | 市街地面積 | 50m換算セル数 |
| --- | ---: | ---: | ---: | ---: |
| 全棟1階・1戸/棟 | 33,334 | 2.667km² | 8.889km² | 3,556 |
| 全棟2階・2戸/棟 | 16,667 | 1.333km² | 4.445km² | 1,778 |
| 全棟3階・3戸/棟 | 11,112 | 0.889km² | 2.963km² | 1,186 |
| 2階と3階を棟数で半々 | 約13,334 | 約1.067km² | 約3.556km² | 約1,423 |

30%は住宅屋根の面積比であり、敷地占有率、住宅用途の土地比率、居住床比率とは別物。混合用途、階数、庭、道路、施設によって変動する。後期中世の目安は約1,200〜1,800の50m換算セルだが、全時代・全地形に強制する定数にはしない。

上表は全人口を同じ密度の市街地に収容した比較計算。実生成では壁内コアと城外を分け、低層の城外住宅を別密度で積算する。表全体を壁内人口容量とみなし、さらに城外へ同じ人口を加算してはならない。

## 4. UIと入力の意味

生成オプションに次を配置する。

| 項目 | 仕様 |
| --- | --- |
| 都市人口（人） | 整数入力。新規CEの初期値3,000人。初期対応1〜150,000人 |
| 人口の取得元 | 単独CEは手動。FMG連携はFMGの人口を既定表示。明示的にCE用の上書きへ切替可能 |
| 住宅表示 | 自動／詳細／10住戸ごと／20住戸ごと。単位は「棟」でなく「住戸」 |
| 地図サイズ | 人口から自動を新規既定とし、既存の手動サイズも選べる |
| 生成前の概算 | 必要住戸、推定住宅棟数、市街地面積、表示幅、セル幅、予定セル数、表示住宅群数 |

人口入力の変更だけで地図を再生成しない。「生成」で確定する。入力中の空欄・小数・負値・NaN・無限大・上限超過は理由を表示し、値を黙って丸めたり上限へ切り詰めたりしない。1〜4人でも1住戸が必要だが、人口そのものは入力値を維持する。

FMG連携の上書きはCE内の生成条件として保存し、FMGの人口を変更しない。FMGから15万人超が来た場合は実人口を保持したまま、初期対応範囲外として新方式の生成を止め、既存表示を維持する。通常のFMG読込を不正データ扱いにしない。

Historical periodは既存欄を使用する。新規のパリ級サンプルは`lateMedieval`。他の時代では既存の時代別階数を使い、15万人だからと中世後期へ自動変更しない。初期対応は既存morphologyの対応時代までとし、未対応の後期時代に中世係数を無断適用しない。

旧文書は人口設定欠落をlegacy扱いとし、開くだけで3,000人へ変更しない。利用者が人口生成へ切り替えた時点で新設定を確定する。

## 5. 人口から都市面積を求める

### 5.1 共通需要と住宅テンプレート

`PopulationDemand`をFMG descriptorから独立させる。単独CEのために架空のburg IDや国家・交易情報を作らない。時代・文化・地形が不足する場合は、出典付きの既定住宅プロファイルを使う。

住宅テンプレートは建築面積、整数階数、用途、1棟容量、敷地面積の構成を持つ。各テンプレートの容量は既存§6.1と同じ純粋関数で計算する。平均階数を先にfloorする処理は避け、各棟種の整数容量を合計する。屋根面積から直接住戸数を計算する別公式を作らない。

初期のパリ級較正プロファイルは80m²住宅・2階/3階を棟数で半々、住宅建築面積比0.30を出発点とする。実配置で用途混在や城外低層化を反映し、係数の版を保存する。

### 5.2 壁内・城外と面積台帳

1. 必要住戸Hを求める。
2. 既存都市史・城外成長計画に従い壁内と城外の需要を配分する。城外比上限は最低配分ではない。
3. 各領域の住宅構成から必要建築面積を求め、領域ごとの住宅建築面積比で割って面積目標を得る。
4. 道路、施設、庭・空地、水面を明示した土地利用台帳へ分解する。住宅比の分母に含めた道路・施設面積を再び加算しない。大河川など標準プロファイルを超える障害は利用可能地を測り直して調整する。
5. 地形上に壁・領域・街路を置き、建築可能敷地の実面積で容量を検証する。
6. 空地活用、時代内の階数調整、許可される壁の拡張候補、城外の支道の順に調整し、最大3回で未配置を確定する。既存生成リトライと掛け合わせて無制限に再試行しない。

面積レポートは`wallEnvelopeArea`（水面を含む囲郭内）、`coreLandArea`（壁内の陸地）、`outsideDevelopedArea`、`residentialFootprintArea`、`frameArea`を別々に出す。無壁都市は囲郭面積をnullとし、市街地領域で扱う。歴史資料439haとの比較は囲郭面積を用いる。

## 6. 可変セルとフレーム

### 6.1 50m換算と実際のメッシュ

50m換算セル数は `N50 = A / 2,500` として報告する。これは面積比較の指標であり、実際の不規則セル数ではない。

集約モードの初期目標は市街地コア256セル。面積Aに対して次を初期解像度とする。

```text
cellWidth = max(50, 25 × ceil(sqrt(A / 256) / 25))  [m]
```

15万人・3.556km²の概算例:

| 公称セル幅 | 面積換算セル数 |
| --- | ---: |
| 50m | 約1,423 |
| 100m | 約356 |
| 125m（上式の採用値） | 約228 |
| 150m | 約159 |

Voronoiではサイト間隔を`cellWidth × 44.8 / 50`から較正する。Hexは辺長と面積の関係`A = 3√3/2 × side²`を使い、辺長を街区幅と同一視しない。Evolutionの`nPatches`もセル数そのものではないため、生成後の市街地セル面積中央値で較正する。

粗いセルは複数の街区・住宅群を収める管理領域となる。道路・水際・壁をその辺へ強制スナップしない。細い地峡や橋頭、門付近は局所細分化または独立ベクター境界を使う。コア256セルは目標であり地形保全より優先しない。背景全域への細密メッシュ展開を避ける。

### 6.2 地図の表示範囲

人口から求めた市街地、城外成長領域、必要施設のboundsへ各辺15%の余白を加える。初期自動サイズは収容できる最小の既存プリセットとする。4.8kmを超える場合は必要幅を100m単位で切り上げたカスタム値を使い、9.6km・19.2kmへ固定倍増しない。

FMGからの地形・接続道路に必要な表示範囲は維持し、市街地のboundsとは分離する。地形の取得範囲を超える場合は再取得または不足診断が必要であり、未取得部分を陸地とみなして拡張しない。手動フレームが小さすぎる場合は必要幅を示して生成を止め、都市を縮小して押し込まない。

セルを50mから125mへ変えると同じ距離内のセル数が減る。都市を2.5倍へ拡大する操作ではない。scale bar、距離測定、道路幅、河川幅、橋長、建築面積は同じメートル座標を使用する。`blockSizeMeters`等のメタデータだけの変更やscale barの文字だけの変更は禁止する。

## 7. 10〜20住戸の集約住宅

### 7.1 表現と容量

`ResidentialCluster`を新設し、通常の`BuildingLot`と識別する。住宅群のポリゴンは占有する敷地領域、描画用の屋根シルエットはその内部の代表図形とする。ポリゴン面積を「一棟の建築面積」として`residentialCapacity()`へ渡さない。

住宅群はテンプレート別の整数棟数、建築面積合計、敷地面積、住戸容量、配分住戸数、配分人口を持つ。容量は実建物と共通のテンプレート計算から求める。見かけの大きさに倍率10・20を掛けて人口を作らない。

「10住戸ごと」「20住戸ごと」は配分住戸の目標上限。建物単位の容量により空室が生じてもよい。33,334戸なら最低限必要な表示群数は概算3,334群または1,667群。道路・領域・用途による分割で増えるため、厳密な描画上限とはしない。前回答の約560〜1,670個は「実棟を10〜20棟ずつ」の別計算であり、本設計の住戸単位の集約数には採用しない。

### 7.2 生成と操作

- 詳細モードは通常建物を生成する。集約モードは軽量な棟種台帳と群の敷地から直接生成し、1万棟以上の詳細ポリゴンを先に生成しない。
- 道路、水面、城壁、成長領域境界をまたいで集約しない。庭・中庭・路地・防御空地を残す。
- 住宅群を選ぶと住戸容量、配分人口、推定実棟数、代表表示であることを示す。
- 手動固定済みの実建物は個別維持し、その容量を群の需要から差し引く。
- 初期版はズームだけでは実建物へ展開しない。必要なら選択住宅群の詳細化を明示操作とし、同じseed・台帳で生成して容量と敷地を検証する。詳細化失敗時は元の群を維持する。
- SVG等にも集約表示であることと人口・住戸のメタデータを保存する。

自動表示は必要住戸が2,000以下なら詳細、2,001〜20,000なら10住戸、20,001以上なら20住戸を暫定採用する。閾値は性能検証後に確定する。利用者の明示選択を保存し、性能都合で黙って切り替えない。

## 8. データ契約と人口保存則

以下は新規型の概念案であり既存実装ではない。

```ts
interface PopulationGenerationSettings {
  version: 1;
  source: "manual" | "fmg" | "ce-override";
  targetPopulation: number;
  housingDisplay: "auto" | "detailed" | "cluster-10" | "cluster-20";
  frameMode: "auto" | "manual";
  profileId: string;
  profileVersion: number;
}

interface ResidentialCluster {
  id: string;
  regionId: string;
  faceIds: string[];
  polygon: [number, number][];
  templateCounts: Record<string, number>;
  residentialFootprintM2: number;
  capacityDwellings: number;
  assignedDwellings: number;
  assignedPopulation: number;
}
```

設定に加え、解決済みの時代・係数・セル幅・フレーム・領域面積・群台帳・未配置理由・計画seedを文書へ保存する。推計値と生成後の実測値を別フィールドにする。`profileId`が未知でも保存済み地図は表示可能とし、無検証の再生成は行わない。

保存則:

```text
H_inside + H_outside + H_unplaced = ceil(P / 4.5)
P_inside + P_outside + P_unplaced = P
各領域: assignedDwellings <= capacityDwellings
```

`ceil(P / 4.5) × 4.5`は人口容量であり、実人口ではない。15万人の33,334戸には150,003人分の容量があるが、人口表示は150,000人を保つ。配分住戸を重みとする最大剰余法で整数人口を領域・群へ配分し、同順位は安定ID順にする。未配置住戸も同じ配分に含める。4.5は平均人数であって個別住戸の整数上限ではない。

既存`assignedPopulation()`は容量換算値を返すため、入力人口がある新モードではそのまま実人口表示に使わない。旧文書・既存レポートとの互換性を明示して改修する。

## 9. 生成パイプラインと再現性

```text
入力検証・人口源確定
 → 住戸需要・時代別住宅構成
 → 壁内/城外配分と面積計画
 → セル幅・表示範囲・地形範囲の解決
 → メッシュ・都市領域・城壁・道路・施設
 → 詳細住宅または集約住宅
 → 容量・接道・土地利用の検証、最大3回の調整
 → 人口配分・未配置診断
 → 保存・描画・scale bar更新
```

単独CEとFMG経由は人口需要以降の経路を共有する。morphologyがない単独都市は既存の時代プロファイルから生成用の推定構成を作り、FMG国家の実測史と混同しない。人口変更時は既存`completeSource`やプレビューキャッシュを無効化し、新しい計画に対応した入力を作る。表示モードだけの変更では人口、土地利用、壁、道路を再抽選しない。

乱数は都市計画、地域、住宅群、詳細建物で派生seedを分ける。集約率変更が都市の形を変えないよう、土地利用・容量台帳を先に確定する。詳細モードも同じ台帳を消費し、両者の容量比較を可能にする。

Worker内で計画・生成を実行し、進捗とキャンセルを維持する。取消後の古い結果で新しい入力を上書きしない。文書、共有レシピ、Undo/Redo、生成ステップの再実行に同じ設定を渡す。`mesh-first`を初期検証経路とし、`skeleton-first`も対応判定を明示する。未対応組合せを黙って旧人口なし生成へ戻さない。

## 10. 性能と受入条件

### 10.1 正しさ

- 1、4、5、3,000、15,000、50,000、150,000人で住戸計算・整数人口保存則が成立する。
- 時代別階数上限、城外人口上限、固定建物、用途ごとの容量0判定を守る。
- 15万人の後期中世・平坦な通常fixtureで未配置0。目標面積との差を報告し、較正プロファイルでは実土地利用面積が目標の±10%を目安とする。パリ史料面積との一致は歴史的再現の証明としない。
- 大河川・海岸・狭い土地・固定壁の不足fixtureでは人口を減らさず、未配置と理由を正確に出す。
- 詳細/10戸/20戸で人口・容量台帳・都市面積・壁・幹線道路が一致する。集約群は他の敷地・水面へ越境しない。
- 50m/125m相当のセル変更で、目標面積と実距離が保存される。実配置の離散化誤差を別計測する。
- scale barと距離測定が1,000mの既知線分に一致する。セル粗密変更で橋の幅・長さ・角度を変えない。
- 橋は`src/utils/bridgeSkewPolicy.ts`を共通使用し、時代・技術の斜交上限を全件検査する。人口収容の例外を設けない。
- 保存再読込・共有・Undo/Redo・同seed再生成で人口と台帳が一致する。旧文書の読込だけでは再生成しない。

### 10.2 性能測定

15万人の同一計画で詳細、10戸、20戸を比較する。計測環境（CPU、メモリ、OS、ブラウザ、commit）、seed、地形、セル方式を記録し、ウォームアップ後5回以上の中央値と最大値を出す。

計測項目は計画、メッシュ、住宅、住宅fit、SVG構築、初回描画、保存/読込、DOM要素数、頂点数、メモリ、パン/ズームのフレーム時間、取消応答。既存性能計測へ追加する。

暫定目標は、15万人20戸モードで生成中央値10秒以内、初回描画2秒以内、パン/ズームのp95フレーム時間33ms以下、取消応答500ms以内。基準環境で未達ならボトルネックを特定して修正し、面積・人口を減らして合格扱いにしない。数値は本設計時点で未測定である。

コアセル数約200〜300と住宅群約1,700は別の予算である。セルを粗くしただけで住宅ポリゴン数が減るとは仮定しない。詳細モードとの比較で、集約時に全実建物の形状を内部生成していないことも計測する。

## 11. 実装順序

1. **需要・面積計算**: 人口需要型、共通住宅容量、テンプレート台帳、面積計画と人口保存則を実装。15万人の固定fixtureで数式を検証。
2. **人口入力と接続**: 生成欄、FMG人口源、設定保存、Worker、キャッシュ無効化、サイズ自動解決を接続。詳細生成で既存住宅fitを単独CEにも適用。
3. **集約住宅**: 軽量台帳から直接住宅群を配置し、土地利用・接道・城外予算・レポート・選択・書出しへ接続。
4. **可変セル**: 各グリッドを実面積基準で較正し、局所地形、壁、道路、橋、scale barの整合を検証。
5. **保存互換・性能**: 旧文書、共有、再生成、取消、人口境界値を確認し、15万人の同縮尺比較と性能報告を残す。

完了条件は、CE単独で人口150,000を入力して生成でき、人口・住戸・推定実棟数・表示群数を説明できること。都市面積とscale barが一致し、集約表示で生成負荷と操作負荷の目標を満たすこと。地形制約で未配置が出るケースも正しく報告できることとする。
