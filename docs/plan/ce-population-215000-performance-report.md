# CE 人口215,000人の生成性能計測

計測日: 2026-10-15。対象コミット: `180a121d0e796d2616232107be7ddfd50c36e667` に、本報告の計測用変更を加えた作業ツリー。

## 結果

CEを新規に開き、人口初期値15,000人を確認して215,000人へ変更し、「Generate complete city」を押した。通常計測2回のクリックから表示完了までの時間は **97.710秒 / 97.166秒**。Worker内の生成だけでなく、受信後のメインスレッド処理にも約46秒かかっている。

| 区間 | 1回目 | 2回目 |
| --- | ---: | ---: |
| クリックから表示完了 | 97.710秒 | 97.166秒 |
| Worker内の生成 | 50.774秒 | 50.510秒 |
| Worker起動・入力受け渡し等の残差 | 0.113秒 | 0.088秒 |
| 完了結果の受け渡し | 0.150秒 | 0.149秒 |
| 完了結果受信からUI更新終了 | 46.651秒 | 46.396秒 |
| UI更新終了から2回のrequestAnimationFrame | 0.022秒 | 0.022秒 |

クリック前のページ読込・人口変更時間は含めない。表示完了は生成中の`aria-busy`解除後、2回の`requestAnimationFrame`到達と定義した。ブラウザ内部の実際の画素提示時刻を測った値ではない。クリック直後のメインスレッド処理約0.002秒は独立した端数である。

両回とも候補1回目で成功し、住宅調整も1パスで未配置0。リトライによる遅延ではない。

## 条件

- Apple M4、10論理CPU、16 GiB RAM、macOS、Headless Chromium 151、画面1485×1070。
- Vite開発サーバー。製品ビルドや別端末での時間は未測定。
- 起動後の生成設定を維持。再現のためseedだけ`ppi409`に固定し、人口を変更。
- Voronoi、mesh-first、Organic、Age of Exploration、Medieval建物パターン。
- 内陸、河川1本、二重城壁、広場・寺院・shanty有効、城・港なし。
- 人口源Manual、住宅表示Automatic、地図サイズFrom population、描画品質Automatic（lightweight）。
- 最終フレーム4.8 km四方、基準セル幅50 m、生成後9,021 faces。
- 住戸需要47,778戸。Worker報告の推定実棟数47,911棟、表示群12,186個、描画対象building lot 12,211個。表示群数と全描画lot数は集計対象が異なる。
- 人口215,000人を全員配分。市街地コア面積約5.596 km²。

過去の15万人・125 mセルの計測とは解像度・時代・河川・城壁条件が異なるため、人口比だけで性能比較しない。

以下は2回目の排他的な主要区間。`ProcessingProfiler`の親・子時間を二重加算していない。

| 人口計画・新規メッシュ準備 | 0.185秒 | 0.4% |
| 候補の入力準備 | 0.013秒 | 0.0% |
| 地形・市域・城壁・道路・地区の計画 | 2.387秒 | 4.7% |
| 計画をメッシュに反映・経路接続 | 12.356秒 | 24.5% |

| 市街地fabric計画 | 1.978秒 | 3.9% |

| 合計 | 50.510秒 | 100% |

計画2.387秒の内訳は、edge graph約0.012秒、海岸0.001秒未満、河川0.025秒、市域0.013秒、城壁計画0.111秒、道路計画0.072秒、地区割当等2.153秒。

計画反映12.356秒の段階ログは、地形反映0.427秒、境界平滑化0.396秒、城壁接合1.846秒、内壁1.222秒、経路接続8.385秒、メッシュ検証0.079秒。`road-routing`は診断イベントで`elapsedMs=0`を送るため、経路探索が無料という意味ではない。

住宅調整は最初のfabric構築・容量確認に4.389秒、その後の最終fabric取得・人口集計等に約3.054秒。`fitPopulationHousing`は成功後にも`buildBlockFabric`を呼ぶ。最終設定と同一の中間結果を再利用できるかが改善候補になる。

従来の`generationTimer`の`wall-defense-closure=21.811秒`には、その前に行う通過道路の直線化なども含まれる。**城壁の閉鎖検証だけに約22秒かかるわけではない。** 同様に`plan-total`・`apply-total`は集計値なので内訳と足さない。

## CPUサンプリングで分かった呼び出し元

別途メインスレッドを2 ms間隔でサンプリングした。同じ都市のWorker生成51.178秒に対し、全体は143.249秒まで伸びた。したがって、この回の時間は通常計測の代表値に混ぜず、呼び出し元の特定に使う。

最も大きなself timeは`nearestOnPolyline`の約87.36秒。主な呼び出し経路は次のとおり。

1. `prepareTownFacts → buildBlockFabric → finishCoastalBuildings → buildAerialLandmarkPlan → placeDomesticWater → add → nearestOnPolyline`
2. `renderTownFabric → farmSheds → 道路との距離比較 → nearestOnPolyline`

サンプリング回の`placeDomesticWater`包括時間は約63.57秒、`farmSheds`は2描画合計約17.93秒。これらはサンプリングによる増加を含み、通常計測でそれぞれ同じ秒数かかるという意味ではない。

`domesticWater.ts`は配置候補ごとに全routeを順番に走査し、`farmSheds.ts`は各農地の各辺について全道路区間への距離を計算する。住宅を集約しても、こうした市域全体への反復探索は残る。

井戸・小屋を削除する、人口・敷地面積を減らす、橋の角度条件を緩める、といった変更を高速化の達成条件にしない。50 mセルを粗くする方式は都市表現そのものが変わるため、同一出力を保つ上記改善とは別に判断する。

## 再現手順・成果物

開発サーバーを起動して実行する。

```sh
node scripts/profileCePopulation.mjs \
  http://127.0.0.1:5173/Fantasy-Map-Generator/city-editor/ \
  temp/population-validation/profile-215000.json ppi409
```

CPUサンプリングを付ける場合は`CE_CPU_PROFILE=1`を設定する。CPUプロファイルは大きくなり得るため通常時間の測定と分ける。

スクリプトはCEの実際の入力欄と生成ボタンを操作する。新しい専用Workerごとに計測し、設定・seed・進捗・Worker内の入れ子時間・結果転送・描画診断・人口報告・環境をJSONへ、表示結果をPNGへ保存する。`profile: true`は計測時のみ注入し、通常生成でProfilerを作らず、都市の保存データにも時間情報を追加しない。

今回の生データはgit管理外の`temp/population-validation/`にある。

- `profile-215000.json` / `.png`: 通常計測1回目。
- `profile-215000-repeat.json` / `.png`: 描画の詳細区間を追加した通常計測2回目。
- `profile-215000-cpu.json` / `.png` / `.cpuprofile`: CPUサンプリング回。

初期調査では計測と対象の洗い出しを実施し、高速化の実装は行っていなかった（後続の実装は下記）。同じseedで2回の通常計測と1回のCPU計測を行った結果であり、異なる地形・seedやリトライが発生するケースの性能は別途確認する。

## チューニング第1段（2026-10-15）

道路形状・住宅・井戸・小屋を減らさず、探索と重複描画を改善した。

- `NearbyPolylineIndex`を追加。既存の`SpatialBoundsIndex`へ道路・laneの線分bboxを登録し、距離上限の正方形と交わる候補を取得する。同一路線の重複を除き、入力のroute順に戻してから従来の`nearestOnPolyline`で厳密に判定する。長い線分の途中も候補に含み、最近傍区間の選び方は変更しない。
- `placeDomesticWater`は井戸等の配置ごとに12 m／45 m圏の候補だけを調べる。近すぎる道路の除外、アクセス通路と建物・壁・水域等の衝突判定は維持する。
- `farmSheds`は農地各辺の中点から設置可能距離以内の道路を調べる。上限外の辺の距離は順位に不要なので厳密計算を省略し、小屋頂点の道路離隔も最大離隔幅のbboxで候補を絞る。キャッシュは追加せず、編集時には現在の道路と農地から再計算する。
- `acceptCompleteGeneration`の成功通知は`showNotice(..., false)`でUIのみ更新する。通知表示と1.8秒後の消去の両方でSVG再構築を省く。
- 計測スクリプトに通知消去前後のSVG同一性・追加描画イベント・ステータス文言の記録を追加。通知検証の待ち時間はクリックから表示までの計測には含めない。

### 検証

`nearbyPolylineIndex`・`domesticWater`・`farmSheds`の7テストが成功。候補順序、長い・退化した線分、距離境界、空のroute、および全routeを候補にした場合との井戸の位置・アクセス／小屋の出力一致を確認した。周辺の`aerialLandmarks`・`landmarkIntegration`・`landmarkLaneNetwork`の30テストも成功。`tsc --noEmit`、変更したTypeScriptのBiomeチェック、計測スクリプトの構文チェックが成功した。

同seed・人口215,000人の通常計測を実施。生成後の人口報告は元の通常計測と全項目が完全一致し、人口215,000人、未配置0、推定47,911棟、表示群12,186個、面積値を維持した。初回計測のスクリーンショットは、元の`profile-215000-repeat.png`の地図表示範囲`(790,200)–(1200,900)`と`(530,840)–(1030,1030)`で画素差0。これは可視領域の比較であり、都市全体の全地物を照合した証明ではない。

初回の変更後計測には一部の時間帯で周辺テストの並行実行があるため、2回目はそれらが終了した状態で計測した。どちらも開発サーバーの値であり、製品ビルド・別seedの性能は未測定。

道路直線化、経路接続、住宅fabricの再利用は未対応。橋の斜交ポリシーとメッシュの更新・検証手順は変更していない。次の優先対象は、引き続きWorkerで約20秒を占める`straightenThroughStreets`のコピー・検証コストとなる。
