# 高額商品の値段に応じた需要 (Luxury Value Demand) 設計

2026-10-19 設計。L0(計測)・L1(都市の予算と価格帯)・L2(交易側の需要)・L3(人物の購入)実装済み。[initial-wealth-calibration.md](initial-wealth-calibration.md) §5.4「高額商品の流通の調整」の対応。

## 状態

- L0〜L3 を実装した(§10〜§13)。L1〜L3 は設定で `on` にした地図だけで働く(既定は `off`)。残りは L4(較正)。
- 前提の計測(§1)は 2026-10-19 に実施した。§5.4 の前提とした「買い手(家計・都市)の余剰」は満たされている。高額品が流れないのは、お金ではなく需要の仕組みが原因。
- 本設計の対象は次の 2 つ。
  - A: 都市の高額品の需要を、個数ではなく予算と価格帯で決める(§3)。
  - B: 人物の余剰の支出の一部で、高額品を実際に買う(§4)。
- 計測で見つかった次の 2 件は対象外(§9)。
  - 安い原料(毛皮・薬草・樹脂)が高額品の需要を満たす割合 `demandCoverage.luxury` の見直し。
  - 海軍の偽装交易の持ち込みを帳簿に記録すること(L0 で記録だけは行った。§10)。

## 2. 問題

### 2.1 安い品が高額品の需要を満たしてしまう

- `production-generator.ts` の `fillDemandFromMarket` は、都市の需要を `人口点 × DEMAND_TARGET_FACTORS.luxury(0.07)` の**個数**で数える。在庫のある候補を「価格 ÷ 充足の重み」の安い順に、`burg.treasury` で買う。
- 毛皮は 1 個 1.6 SP(価値 6 × 相場 0.26)で、充足の重みは 0.5 なので、充足 1 単位あたり 3.1 SP。彫刻は充足 1 単位あたり 35〜42 SP。安い品が在庫切れにならない限り、高い品は選ばれない。
- 毛皮・薬草・樹脂は、どの市場にも 1.3 万〜3.3 万個の在庫がある。そのため高額品は永久に買われない。
- 宝飾(Jewelry、価値 55)には `demandCoverage` がなく、消費者の需要の対象にそもそも入っていない。

### 2.2 交易側と消費側の需要が食い違う

- 市場間交易の需要(`markets-generator.ts` の `collectConsumerDemand` / `calculateGoodDemand`)は、高額品の需要 0.07 を各品の充足の重みの比で全品に配る。このため交易側からは、彫刻にも宝飾にも需要があるように見える。
- 実際に買う側(§2.1)は安い品しか買わない。
- 結果として、価格差と商会の支店がそろった市場の組で高額品が運ばれ、着いた先で売れずに在庫が積み上がる。seed 102 では価値 20 以上の在庫が 1 万個あり、年の運び込みと運び出しがほぼ同じ量だった。

### 2.3 人物の支出は現金を移すだけ

- `characterLivingCosts.ts` は、生活費の 5 年分(`WEALTH_RESERVE_YEARS`)を超える富の 10%(`SURPLUS_WEALTH_SPEND_SHARE`)を毎周期使う。ただし使い道は `spendInBurg` による居住都市の家計への現金の移動だけで、品物は動かない。
- 支配者は数千の富を持つが、高額品の市場には一度も現れない。

## 3. A: 都市の高額品の需要を予算と価格帯で決める

### 3.1 価格帯

`demandCoverage.luxury > 0` の品を `good.value` で 3 つの価格帯に分ける。区切りは定数とし、品目の表には持たせない。

| 価格帯 | `good.value` | 例 |
| :--- | :--- | :--- |
| `common`(並) | 10 未満 | 毛皮・樹脂・染料・琥珀・明礬・大理石 |
| `fine`(上) | 10〜20 未満 | 香・茶・カカオ・絹・珊瑚・香辛料・書物・薬草 |
| `precious`(極上) | 20 以上 | 宝石・楽器・香水・美術品・象牙・彫刻・タペストリー・聖遺物 |

- 宝飾(Jewelry)に `demandCoverage: { luxury: 1 }` を足し、`precious` に入れる。
- 金・銀の地金は対象外のまま(鋳造の材料。`demandCoverage.luxury` を持たない)。
- 燻製チーズ(食料と高額品の両方)は `precious` に入るが、食料の需要が先に買うことがある。そのままとする。

### 3.2 都市の予算

高額品は需要の優先順位(`DEMAND_PRIORITY`)の最後に買う。この点は変えない。個数の目標を、周期ごとの予算に置き換える。

```text
luxuryBudget = population × nominal(LUXURY_SPEND_PER_POP) × wealthIndex
wealthIndex  = clamp(treasuryPerPop / profile.burgTreasuryPerPopulation, 0.25, WEALTH_INDEX_MAX)
```

- `LUXURY_SPEND_PER_POP` は人口点・周期あたりの基準額。初期値は、現状の支出額(都市人口点あたり年 2.4〜2.8 SP)の 2〜3 倍を目安に、§7 の計測で決める。`nominal()` で K を掛ける(定額のお金、[money-scale-calibration.md](money-scale-calibration.md) §3 の区分 B)。
- `wealthIndex` は、豊かな町ほど多く使うことを表す。金庫が開始時の配分を下回る町は使う額を減らす。上限 `WEALTH_INDEX_MAX` の初期値は 3。
- 実際に払う額は `min(luxuryBudget, 先の需要を買った後の burg.treasury)` とする。食料・道具などの需要を削ってまで高額品を買うことはない。

### 3.3 価格帯への配分

予算を価格帯ごとの比に分ける。比は町の格で変える。

| 町の格 | `common` | `fine` | `precious` |
| :--- | ---: | ---: | ---: |
| 小さな町(人口点 5 未満) | 0.7 | 0.3 | 0 |
| 町 | 0.5 | 0.35 | 0.15 |
| 大きな町(人口点 20 以上)・港 | 0.4 | 0.35 | 0.25 |
| 首都 | 0.3 | 0.35 | 0.35 |

- 価格帯の中では、在庫のある品を「価格 ÷ 充足の重み」の安い順に買う(現行と同じ選び方)。
- 価格帯の予算を使い切れなかった分(在庫がない場合)は、1 つ安い価格帯へ回す。高い価格帯へは回さない。極上品がない町は上の品を買い、上の品もなければ並の品を買う。
- それでも残った分は金庫に残す(使わない)。
- 比と町の格の区切りは定数とし、§7 の計測で調整する。「中心の小売・高価品」は大きな町に集まる([approach-commerce-quarters.md](approach-commerce-quarters.md) §3.1、Cheapside)。

### 3.4 生産の手掛かり

`getDemandFocus` / `getDemandEffect` は需要の不足の個数で生産を後押しする。高額品については、価格帯ごとの使い残しの予算を、その価格帯の品の平均価格で割った個数を不足として渡す。これで極上品の在庫がない町は、極上品の生産を後押しする。

L1 の実装はこれを簡略化した(§11)。前の周期の使い残しを持ち越す状態を作らないように、不足の個数は従来の個数の目標のままとし、後押しの重みに町の格の価格帯の比(最大の比を 1 とした相対値)を掛ける。極上品の比が 0 の小さな町は極上品の生産を後押ししない。首都・大きな町は極上品も並の品に近い重みで後押しする。

### 3.5 交易側の需要を消費側に合わせる

`calculateGoodDemand` の高額品の部分(`collectConsumerDemand` の `luxury` 項)を、§3.2〜3.3 の予算から見込む購入量に置き換える。

```text
expectedUnits(good) = Σ_burg luxuryBudget × tierShare(burg, tier(good)) × goodShareInTier(good) / price(good)
goodShareInTier = demandCoverage.luxury(good) / Σ_{価格帯内} demandCoverage.luxury
```

- 交易は「消費側が実際に買う見込み」のある品だけを運ぶ。売れない高額品の運び込み(§2.2)がなくなる。
- 価格の弾力性(`priceElasticity.ts`、高額品 −1.2)はこの量に掛ける。

L2 の実装では次の 3 点を変えた(§12)。
- 予算 ÷ 価格がすでに価格に応じて減るので、弾力性は重ねて掛けない。
- 1 周期分では、極上品 1 品あたり 0.01 個前後になり、最小の交易単位(0.1)に届かない。そのため市場の商人が半年分(`LUXURY_STOCK_CYCLES` = 6 周期)を在庫として持つ量を需要とした。
- 推測取引(`addSpeculativeGlobalTradeOpportunities`)は需要を見ずに在庫の多寡だけで品を動かす。そのため `on` では高額品の推測取引を止めた。

## 4. B: 人物の余剰の支出で高額品を買う

### 4.1 支出の分け方

`applyCharacterLivingCosts` の支出は「生活費(`computeLivingCost` = 格ごとの定額 + 富に応じた体面の費用)+ 余剰の 10%」。生活の格(`LifestyleTier`)ごとに、次の 2 つを高額品の購入に充てる。残りは今までどおり `spendInBurg` に入れる。

- **生活費のうちの比**(`LIFESTYLE_LUXURY_SHARE`): 宮廷・館の生活費の一部は、もともと衣装・香・蝋燭・調度にあたる。余剰がない人物にも、毎周期少しずつ需要が生まれる。
- **余剰のうちの比**(`SURPLUS_LUXURY_SHARE`): 蓄えを超えた富の使い道としての、建築・贈答・美術品。

| `LifestyleTier` | 生活費のうち | 余剰のうち | `precious` / `fine` / `common` |
| :--- | ---: | ---: | :--- |
| `ruler` | 0.25 | 0.4 | 0.6 / 0.3 / 0.1 |
| `centralOffice`・`provinceLord` | 0.2 | 0.3 | 0.4 / 0.4 / 0.2 |
| `marketManager`・`guildMaster`・`fieldCommander` | 0.1 | 0.2 | 0.2 / 0.5 / 0.3 |
| その他 | 0 | 0 | — |

- 比は定数の初期値で、§7 で調整する。貴族・聖職者・商人が建築・衣装・贈答・調度に多くを使ったことは、家政の帳簿の研究で知られている(Dyer の後期中世イングランドの生活水準の研究「消費者としての貴族」。数値の出典は要確認)。

### 4.2 買い方

- 買う場所は、居住都市(`character.location`)の市場。`Markets.buy` を居住都市を買い手として呼び、代金は人物の富から引く。
- 価格帯の中では、人物の好み(`backstory.tastes` と `TASTE_GOOD_MATCH`。たとえば `luxury` → 絹・宝飾・香水・衣装、`art` → 美術品など)に合う品を先に選ぶ。合う品がなければ、価格帯の中で在庫の価値が大きい品から買う。
- 使い切れなかった分(在庫がない、居住都市が不明、市場がない)は、今までどおり `spendInBurg`(なければ `payStateHouseholds`)に入れる。お金の総量は変わらない。
- 買った品は消費する(在庫から消える)。人物の持ち物として残す仕組み(贈答・賄賂・相続)は本設計の対象外とする(§9)。

### 4.3 規模の見込み

- `ruler` の生活費は、定額 2.55 × K(16)= 40.8 と体面の費用(富 × 0.02、上限は定額の 1.5 倍 = 61.2)の合計で、富 3,000 以上なら周期あたり約 102 になる。蓄えの基準は生活費の 5 年分で約 6,100。
- 15 年目の支配者の富(2,500〜4,400)は蓄えの基準に届かず、**今の定数では余剰の支出は 0**。支配者の富は増え続けている(seed 101 で 2,489 → 4,422)。
- 余剰だけに頼ると B はほとんど働かない。そのため生活費のうちの比を設けた。`ruler` は周期 約 25(年 約 300)を高額品に使い、うち 6 割が極上品になる。
- 都市全体の高額品への支出(年 1,000〜2,600)の 1〜3 割の規模で、首都の市場に極上品の需要が毎年生まれる。富が蓄えを超えた後は、余剰の支出が加わる。
- 生活費の総額は変えない(内訳の一部を品物の購入に回すだけ)。そのため人物の富の推移は、高額品の在庫が足りる限り今と同じになる。支配者の富が増え続ける問題は本設計では直さない(§9)。

## 5. お金と物の保存

- 都市の購入(A)も人物の購入(B)も `Markets.buy` を通す。代金は市場の現金に入り、`payOutMarketSurplus` で家計・商人に戻る。お金は生まれも消えもしない。
- 帳簿(`goodsBalanceLedger`)に区分を 2 つ足す: `luxuryPurchase`(A、L1)、`characterLuxury`(B、L3)。今は `burgDemand` にまとめているものを分けて数えられるようにする。記録する処理と同じ段階で足す。
- テスト: 人物の購入の前後で、人物の富 + 市場の現金 + 家計の合計が変わらないこと。価格帯の予算が下の価格帯へだけ回ること。

## 6. 互換性

- 新しい保存の状態は持たない(予算は毎周期その場で計算する)。旧セーブはそのまま読める。
- 経済の値が変わるので、golden(`test:sim-golden`)を更新する。
- 計測と比較のために、世界の設定 `fmg-luxury-value-demand`(`"on"` で有効、それ以外は無効)を置く。シミュレーションの結果を変える設定なので `WORLD_SETTING_KEYS` に入れ、.fmg に保存する。地図の生成時にブラウザの値(localStorage)を写し、`worldSettings` を持たない古い地図だけは実行時のブラウザ・`--settings` の値を使う。既定は §7 の較正が済んだら `on`。`off` は従来どおりの個数の需要と、人物の現金の移動だけになる。

## 9. リスクと未決事項

- **安い品の売れ行きが落ちる**: 毛皮は今、高額品の需要の 3 割前後を占める(年 320〜840 個)。`common` の価格帯で引き続き買われるが、量は減る。毛皮・樹脂・薬草を売る農村の収入(`ruralHarvest` の代金)が減る可能性がある。`demandCoverage.luxury` の見直し(計測結果の案 3)と合わせて、L4 で確かめる。
- **首都への集中**: 人物の多くは首都に住むので、極上品の需要は首都の市場に集まる。史実の傾向(宮廷・高位聖職者が奢侈品の主な買い手)とは合う。地方の町の需要は A で別に持たせる。
- **極上品の供給**: 彫刻・タペストリー・楽器などは材料(布・大理石・象牙)が足りず、作れない市場が多い(「Failed to acquire 1 units of Cloth … for production of Artworks」が出る)。需要ができても供給が追いつかない間は、価格が上がる(弾力性 −1.2)ことで調整されるかを L1 で確かめる。
- **支配者の富が増え続ける**: K=16 では生活費の 5 年分の蓄え(約 6,100)が支配者の富を上回り、余剰の支出が起きない。蓄えの年数(`WEALTH_RESERVE_YEARS`)・体面の費用の上限を見直すかは、B の効果を見てから決める。
- **商人の人物の富**: 7 割前後が 0 のまま。本設計では、商人を買い手にはしない(市場の利益の分配の問題で、別に扱う)。
- **持ち物としての高額品**: 宝飾・美術品は本来、消費されずに保有・贈答・相続される。人物の持ち物の台帳は本設計の対象外。将来、贈答(`TASTE_GOOD_MATCH` を使う賄賂・贈り物)と結び付けるときに検討する。
- **海軍の偽装交易**: L0 で帳簿に載せ(§10)、L2 で `on` のときの空回りを止めた(§12)。`off` は従来どおり。
- **価格帯の区切り**: 価値 10・20 は今の品目の表に合わせた値。品目の追加・価値の変更で偏る場合は、品目の表に価格帯を持たせることを検討する。
