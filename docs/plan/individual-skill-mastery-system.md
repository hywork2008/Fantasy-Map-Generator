# 個人熟練・才能・技法システム設計

## 状態

**提案段階 — 未実装**（2026-08-03）

本書は、[知識・技術蓄積システム](./knowledge-guild-system.md)が扱う都市・国家・組織の知識と、個々の職人・武人の能力を接続するための設計である。

既存の `CharacterSkills` は、`engineering` や `martial` などを 1〜100 の単一値で持つ。これは人物の大まかな資質・社会的役割を表すには有用だが、鍛冶・裁縫・弓術・馬術のような実践技能の成長、師弟継承、希少な天才を一つの値で表すには粒度が足りない。

本設計は、UO 型の「実践によって 0〜100 まで蓄積する技能」を採り入れつつ、数値のインフレと生得的才能による完全な決定論を避ける。

---

## 1. 目標

- 生産技能から武術まで、共通の個人技能モデルで扱えるようにする。
- 実践・師弟教育・工房や訓練場といった環境が、人物の成長に明確に寄与するようにする。
- 才能は存在させるが、才能の低い人物を絶対的に排除しない。
- 個人の死と組織の継続を分離し、名人の死が痛手でありながら都市全体の技術を即時消滅させない。
- 「100 を超える数値」を継続的に増やすのではなく、卓越者を技法・発見・教育能力で表現する。
- 既存の GuildKnowledgeStock / MartialDisciplineStock と競合させず、相補的にする。

非目標:

- プレイヤーキャラクター向けの UO のような総スキルポイント上限を導入すること。人口シミュレーションでは、個人間の選択制約より都市・組織の分業を表す方が重要である。
- 全住民を個別 Character として常時シミュレートすること。個人技能は親方、弟子、指揮官、名人などの重要人物に限定する。

---

## 2. 結論: 4 軸モデル

個人の能力を、以下の四つに分ける。

| 軸 | スコープ | 例 | 失われ方 | 主な用途 |
| --- | --- | --- | --- | --- |
| 実践熟練 | 個人 | 刀鍛冶 72、弓術 48、裁縫 91 | 本人の死・長期離職・障害 | 生産物・戦闘行動の品質 |
| 適性 | 個人 | 金属加工への適性、反応、空間認識 | 原則固定。加齢・負傷で一部変化可 | 成長速度、高度な技法の習得 |
| 技法 | 個人・組織 | 折り返し鍛錬、騎射、隊列転換 | 秘伝者の断絶、征服、記録喪失 | 品質段階、特殊行動、発見 |
| 組織知 | Burg / State | 冶金ギルド、訓練体系、国家機密 | 年次減衰、征服撹乱、投資停止 | 教育効率、道具・制度、集団成果 |

この区別により、「稀有な名人がいるが、工房全体は弱い」「名門の訓練体系はあるが、将軍個人は凡庸」「小都市にも少人数の優れた職人がいる」といった状態を自然に表せる。

## 3. 実践熟練: UO 型の 0〜100

### 3.1 基本方針

`DomainSkill` は、特定分野を実際に遂行する能力を表す 0〜100 の連続値とする。

- 0〜19: 見習い。単純作業のみ。
- 20〜49: 一人前。標準的な作業・兵士として任務を果たせる。
- 50〜79: 熟練者。高品質品、難しい任務、弟子の初等教育が可能。
- 80〜94: 親方・達人。工房や部隊の中核となり、高度技法を扱える。
- 95〜100: 大家。極めて希少で、技法の創出・改良や後進への大きな波及を担う。

100 は「人間として到達可能な完成域」であり、通常の数値上限である。100 到達後も成果は得られるが、数値を 101、120 と増加させない。

### 3.2 対象ドメイン

開始時は、既存の組織知ドメインと対応する少数の技能だけを実装する。広すぎる技能一覧を初期から作らない。

| 組織知ドメイン | 個人技能の初期案 | 備考 |
| --- | --- | --- |
| metallurgy | blacksmithing, smelting | 製錬と鍛造を分ける。Phase 6 の `engineering` 流用を段階的に置換 |
| textiles | weaving, tailoring | 製織と仕立てを分ける |
| woodworking | carpentry, shipwrighting | 造船は shipbuilding 拡張との接続を後続で検討 |
| swordsmanship | swordsmanship | `martial` / `prowess` とは別の実技 |
| archery | archery | 弓の製造技能とは別 |
| horsemanship | horsemanship | 馬の取り扱いと騎兵運用の個人技 |

一人の人物が複数技能を持つことは許可する。ただし重要 Character の生成時には、主技能 1 個と副技能 0〜1 個を基本にして「何でもできる人物」の量産を避ける。

### 3.3 成長

熟練は年次で集計し、実践した量に応じて増加する。日次の作業一回ごとの経験値計算は不要である。

```text
annualGrowth = basePracticeGain
  × practiceCoverage
  × trainingQuality
  × aptitudeGrowthMultiplier
  × diminishingReturns(currentProficiency)
```

- `practiceCoverage`: その年に当該仕事・訓練へ従事できた割合。失業、負傷、戦争、材料不足で下がる。
- `trainingQuality`: 親方、ギルド知識、工房・訓練場、書物・教材から得る教育環境。
- `aptitudeGrowthMultiplier`: 適性による小さな補正。後述する。
- `diminishingReturns`: 熟練が高いほど成長を遅くする関数。90 以降は特に緩やかにする。

経験がないことだけで熟練を急減衰させない。長期離職・重傷・老化で緩やかに下げ、死亡時に個人値は失われる。これにより、歴戦の老兵や休職した職人の価値を保てる。

## 4. 適性: 才能を「速度と難度」に限定する

### 4.1 設計原則

現実の才能差は認めるが、才能を「到達不能な固定上限」にしない。低適性の人物でも、十分な実践とよい教育があれば 90〜100 に到達できる。

適性は次の二点にだけ影響させる。

1. 熟練の成長速度
2. 高度な技法の習得・創出の成功率

生産量や戦闘力へ常時大きな直接倍率を掛けない。そうすると、才能が熟練・技法・組織知の全てを上書きし、生得的な「当たり Character」を引くゲームになる。

### 4.2 値の形式

初期実装では、ドメインごとの細かい遺伝パラメータを多数持たず、`aptitudeTier` の五段階を採る。

| Tier | 出現の目安 | 成長補正の目安 | 意味 |
| --- | ---: | ---: | --- |
| poor | 10% | ×0.80 | 習得に時間が掛かる |
| ordinary | 55% | ×1.00 | 標準 |
| promising | 25% | ×1.12 | 伸びがよい |
| gifted | 9% | ×1.25 | 高度域まで到達しやすい |
| exceptional | 1% | ×1.40 | 時代を代表しうる稀有な才能 |

これは初期バランス用の目安であり、世界生成時の文化・家系・生活環境のバイアスを追加する場合も、`exceptional` の確率を大幅に引き上げない。

### 4.3 才能と努力・制度の関係

`ordinary` の人物が優れた親方・整ったギルド・安定した材料供給を得た場合、`gifted` だが孤立した人物を上回れてよい。逆に `exceptional` の人物は、適切な場を得たときに初めて大きな歴史的影響を持つ。

才能は個人の可能性であり、組織知の代替ではない。

## 5. 技法: 100 超の数値ではなく、質的な到達点

### 5.1 技法を導入する理由

100 に達した後の成長、天才の特別さ、秘伝の喪失をすべて数値で表そうとすると、上限が際限なく上がる。これを避けるため、卓越の差は `Technique` の習得・創出として表現する。

例:

| 分野 | 技法例 | 効果の例 |
| --- | --- | --- |
| 鍛冶 | patternWelding | 高品質武器の生産を可能にする |
| 鍛冶 | heatTreatment | 品質のばらつきを減らし、材料損失を抑える |
| 裁縫 | fittedArmorTailoring | 衣服・防具の適合性を上げる |
| 剣術 | counterCut | 熟練者同士の決闘・小競り合いで有利になる |
| 弓術 | volleyDiscipline | 部隊の斉射効率を高める |
| 馬術 | mountedSkirmishing | 騎兵の追撃・離脱の選択肢を増やす |

### 5.2 習得条件

技法は単一の乱数抽選にせず、次の条件を満たした人物だけが学べるものとする。

```text
eligible = proficiency threshold
  + technique prerequisite
  + access to teacher, record, or institution
```

適性は最終的な成功率を補正する。95〜100 の高熟練と `exceptional` 適性を兼ねる人物には、新技法の創出または既存技法の改良という希少イベントを許可する。

個人が発見した技法は、ただちに都市全体の共有財産にはしない。親方の存命中は個人秘伝であり、弟子・文書・組織によって伝承されて初めて GuildKnowledgeStock や MartialDisciplineStock の一部になる。

## 6. 組織知との接続

既存の組織知は、個人の能力の平均値ではなく、教育制度・分業・標準・蓄積された作業手順を表す。この役割分担を維持する。

| 種別 | 個人熟練が表すもの | 組織知が表すもの |
| --- | --- | --- |
| 鍛冶 | 親方の加工精度、弟子への直接指導、希少技法 | 工房網、標準工程、道具、材料選別、職人の集積 |
| 裁縫 | 一着の仕立て・裁断の巧みさ | 染色・織物・流通を含む都市の産業基盤 |
| 剣術 | 兵士・指揮官の武器操作 | 訓練場、教範、部隊の連携、補充兵の教育 |
| 弓術 | 射手の照準・射法 | 斉射指揮、射場、弾薬・装備の整備 |

個人の生産・戦闘への寄与は、以下の形を基本とする。

```text
resultQuality = individualProficiencyFactor
  × institutionKnowledgeFactor
  × materialAndFacilityFactor
  × techniqueFactor
```

`aptitude` はこの最終式へ原則含めない。才能は育つ過程と技法への到達を変え、成果は実際に身につけた熟練と環境が決める。

### 6.1 集団成果への制限

一人の天才が Burg 全体の生産量や State 全軍を過剰に強化しないよう、個人寄与には対象範囲を設ける。

- 親方は、自身の工房・弟子・割り当てられた高級品レシピへ強く影響する。
- GuildKnowledgeStock の年次成長は従来どおり実践者数を主因とし、名人は小さな加算または教育効率への補正に留める。
- 指揮官の剣術は本人の戦闘や小規模部隊に効かせ、国家全体の MartialDisciplineStock は兵数・継続訓練を主因とする。

これにより、天才は物語上重要でありながら、都市制度や人口規模を無意味にしない。

## 7. 既存 CharacterSkills との関係

`CharacterSkills` は削除しない。用途を以下のように再定義する。

| 既存値 | 今後の主な役割 | DomainSkill との関係 |
| --- | --- | --- |
| engineering | 発明・工房管理・複合技術の理解 | 鍛冶等の成長速度・技法研究を少し補助。実際の鍛造熟練ではない |
| martial | 指揮・軍事判断・部隊運用 | 個人の剣術／弓術とは別 |
| prowess | 身体的な武勇・近接戦の基礎 | 剣術などの実技に対する状況補正。技能の代替ではない |
| learning | 理論知識・書物からの学習 | 技法を記録から再発見する速度に関係しうる |
| artistry | 意匠・装飾・美的評価 | 工芸品の意匠品質に関係しうる |

特に、Phase 6 で冶金の実践技能として流用している `engineering` は、将来 `blacksmithing` / `smelting` が導入された時点で移行対象とする。移行時は既存 `engineering` を初期熟練と適性の生成材料に使い、既存セーブデータを破壊しない。

## 8. 最小データモデル案

初期段階では、必要な Character にだけ技能レコードを持たせる。

```ts
type SkillDomain =
  | "blacksmithing"
  | "smelting"
  | "weaving"
  | "tailoring"
  | "swordsmanship"
  | "archery"
  | "horsemanship";

type AptitudeTier = "poor" | "ordinary" | "promising" | "gifted" | "exceptional";

interface CharacterDomainSkill {
  domain: SkillDomain;
  proficiency: number; // 0..100
  aptitude: AptitudeTier;
  lastPracticedYear?: number;
  techniques: string[];
}
```

`Character` へ直接大きな新規配列を追加するか、Economy / Nobility 側の `Map<CharacterId, CharacterDomainSkill[]>` に分離するかは、保存形式と拡張間依存を調査して決定する。初期の metallurgy 垂直スライスは既存の `guildSuccession.ts` に近接させ、Characters の汎用型を不用意に膨張させない方針を推奨する。

## 9. 実装段階案

### Phase A: 冶金の個人熟練への置換

1. `blacksmithing` を導入し、現行 metallurgy の親方・弟子に限定してレコードを作る。
2. 現行 `engineering` を初期 `blacksmithing` と適性 Tier のシードに用いる。
3. 師弟の年次成長式を、親方の `blacksmithing` と GuildKnowledgeStock に置き換える。
4. 親方が担当する高級品生産だけへ、熟練・技法の品質補正を接続する。
5. 既存の GuildKnowledgeStock の成長・減衰ルールは変更しない。

### Phase B: 技法と継承

1. metallurgy 用の少数技法を追加する。
2. 師弟または記録媒体による技法伝承を実装する。
3. 親方が弟子も記録も残さず死亡した場合、個人秘伝だけを失う。既存のギルド撹乱ペナルティとは別に扱う。

### Phase C: 武術への適用

1. `swordsmanship` と `archery` を、既存の MartialDisciplineStock と並列に追加する。
2. 指揮官・部隊教官など、個人が戦闘結果に意味ある影響を持つ人物から使う。
3. regiment 全員を Character 化せず、部隊の基礎戦力は従来どおり MartialDisciplineStock と装備・兵数で扱う。

### Phase D: 他の生産分野

織物、木工、裁縫などへ横展開する。各分野は、対応するレシピ・雇用記録・親方ロール・品質消費先が揃ったものから一つずつ実装する。

## 10. バランス上の検証項目

- `ordinary` 適性の弟子が、安定したギルドで数十年実践すれば 80 以上へ到達できるか。
- `poor` 適性でも、長期実践によって 90 へ届く余地があるか。
- `exceptional` の人物が、孤立・材料不足・師匠不在なら過剰な成果を出さないか。
- 親方 1 人の存在・死亡が Burg 全体の生産量を不自然に上下させないか。
- 高熟練者が少ない小国にも、技術流入・引き抜き・弟子育成による追い上げ手段があるか。
- 100 到達後の技法が、単純な数値倍率ではなく、新しい選択肢や品質差として機能するか。
- Characters / Economy / Nobility の各拡張が個別に無効な場合、機能が例外なく優雅に劣化するか。

---

## 11. 決定事項

1. 実践技能には UO 型の 0〜100 熟練値を採用する。
2. 100 は通常の最終到達域とし、継続的な数値上限の拡張は行わない。
3. 100 以後の卓越性・天才性は、技法の発見・改善・教育能力で表す。
4. 才能は成長速度と技法習得率に限定し、原則として到達不能な固定上限を作らない。
5. 個人熟練、技法、組織知、既存の広域 CharacterSkills を別概念として維持する。
6. 初期実装は metallurgy の親方・弟子に限定し、既存の GuildKnowledgeStock を置換しない。
