# 樹木mediumモデルの作り直し（Claude Opus 5.5、2026-10-29）

ライム（`garden_parkland`、Small-leaved lime · Tilia cordata）とイチイ（`sacred_yew`）のmediumを作り直した記録である。何を、なぜ、どの方法で行ったかを、後から作業するAIモデルが同じ手法を他の樹種へ適用・調整できるように残す。

- 実装コミット：`eb36c33b8`（feat: Implement canopy lobe fitting and enhance tree quality author tracking）
- 元にしたmedium：Codex GPT-6.1 Solが commit `45e24d51d` で作った版。比較用としてBVに残してある（§6）。

## 1. 目的

CEの森は、画面上の樹冠の高さ（px）で品質の段階を切り替える（`src/buildings/landscape/treeQuality.ts`）。

| 段階 | 樹冠の高さ |
| --- | --- |
| low | 28 px未満 |
| medium | 28〜90 px |
| high | 90〜240 px |
| ultra | 240 px以上 |

Codexのmediumには、次の問題があった。

1. **見た目が安っぽい。** 正二十面体（細分1、80三角形）の球を24個並べただけで、平らな面ごとの陰影がそのまま見え、ブロッコリーのように見えた。
2. **highとの形の差が大きい。** highとは無関係の配置だったため、樹冠が小さく丸すぎた。90 pxでmediumとhighが切り替わるとき、形が飛んで見えた。
3. **三角形が多い割に効いていない。** 2,446三角形のうち、ほかの球に埋もれて見えない面が多かった。

目標は、**三角形を増やさずに**、60〜90 pxでhighと見分けにくいmediumにすることである。

### 検討して採らなかった方法

カメラの向きに合わせて葉の殻を回転させる方法も試した（ブランチ `feature/ce-mimic-medium-tree`、`limeMediumPreview.ts`）。採らなかった理由は次の2つである。

- 森の木は `InstancedMesh` で描いている。木ごとに向きが違うので、毎フレームCPUで全インスタンスの行列を書き換える必要がある。
- 片面だけの殻が太陽から影を落とすので、影がカメラの回転に合わせて動く。

また、28〜90 pxでは葉の1枚が1〜2 pxになり、三角形を細かくしても細部として見えず、ちらつくだけである。見た目を決めるのは、輪郭・陰影・色の揺らぎだと判断した。

## 2. 方法の概要

| # | 方法 | 狙い |
| --- | --- | --- |
| A | mediumをhighの枝構造から作る | 形をhighと一致させ、切り替え時の飛びをなくす |
| B | 葉の房1つを、楕円体1つ（房の葉の分布に当てはめたもの）で置き換える | 樹冠の量と配置をhighと揃える |
| C | 法線を樹冠全体の楕円体の法線へ寄せる | 角ばった陰影を消し、樹冠を一つの柔らかい塊に見せる |
| D | 頂点AO（内側と下側を暗くする陰影を頂点カラーに焼き込む） | 奥行きを出す。追加コストはない |
| E | 面ごとの色むら・頂点の揺らぎ・埋もれた面の削除 | 葉のきめを出し、輪郭を自然にし、三角形を減らす |

lowも、形はそのままでC〜Eの陰影を同じにした。lowとmediumを切り替えたときに、色や陰影が急に変わらないようにするためである。

## 3. 実装

### 3.1 共通部品：`src/buildings/landscape/canopyLobes.ts`

#### `fitCanopyLobe(points, coverage)`

葉の中心点の集まりから、楕円体を1つ作る。

- 中心：点の平均。
- 半径：点の二次モーメント（中心からの距離の二乗の平均）から逆算する。
  - 中身が一様に詰まった楕円体では、E[x²+z²] = 2a²/5、E[y²] = b²/5 になる。
  - これを解いて、水平半径 a = √(2.5·E[x²+z²])、鉛直半径 b = √(5·E[y²]) とする。
- 最後に `coverage` を掛ける。房の葉はまばらで、楕円体よりも見かけの面積が小さいので、見え方を合わせるための係数である。

#### `createCanopyLobes(lobes, palette, seed)`

楕円体ごとに正二十面体（細分0、20三角形）を置き、次の処理をする。

1. **向きのばらつき**：楕円体ごとにY軸まわりの回転を乱数で決め、面の向きが揃わないようにする。
2. **頂点の揺らぎ**：頂点ごとに半径を0.82〜1.12倍にし、輪郭をギザギザにする。共有する頂点は同じ量だけ動かすので、隙間は開かない。
3. **埋もれた面の削除**：3頂点すべてがほかの楕円体の内側にある面は出力しない。判定は正規化した距離の二乗が0.92未満。
4. **法線**：
   - 房の楕円体の法線と樹冠全体の楕円体の法線を 15：85 で混ぜる。樹冠全体の楕円体は、全房を包む直方体から作る。
   - さらに上向き (0, 0.3, 0) を足して正規化する。葉を透過した光を近似し、樹冠の下側が真っ黒にならないようにするためである。
   - 法線は頂点ごとに明示的に持たせる。`computeVertexNormals` は使わない。
5. **頂点AO**：
   - `depth` は、樹冠の楕円体で正規化した距離を smoothstep(0.35, 0.95) したもの。
   - `height` は、樹冠内での高さを0〜1にしたもの。
   - 明るさに `(0.62 + 0.38·depth) × (0.86 + 0.14·height)` を掛ける。
6. **色むら**：面ごとに、色相 ±0.015、彩度 ±0.04、明度 ±0.07 をずらす。房ごとにも明度を ±0.02 ずらす。

色は `TEMPERATE_CANOPY`（`temperateTreeLod.ts`）を使う。

| 樹種 | 色相 | 彩度 | 明度 |
| --- | --- | --- | --- |
| lime | 0.258 | 0.42 | 0.235 |
| yew | 0.32 | 0.40 | 0.25 |

### 3.2 highの枝構造からmediumを作る：`smallLeavedLime.ts`・`europeanYew.ts`

highとultraの生成関数は、もともと「同じ乱数列を消費し、highでは葉を間引くだけ」という作りである。mediumもこの関数の中に入れた。

- **乱数列を変えない。** 葉の出力を `if (medium || (quality === "high" && …)) continue;` で止め、その手前までの乱数は必ず消費する。こうすると、枝の位置がhigh・ultraと完全に一致する。
- **葉の房1つ → 楕円体1つ。**
  - ライム：`spray()` が作る葉の中心を集め、`fitCanopyLobe(centers, 1.3)` に渡す。
  - イチイ：`foliage()` が作る針葉の扇の全頂点を集め、`fitCanopyLobe(points, 0.78)` に渡す。
  - `coverage` の値は、林として並べた見え方をhighに合わせて決めた（§4）。イチイは扇が外に長く伸びて楕円体が太りすぎるので、1未満にしている。
- **枝の簡略化。**
  - 根元の半径が0.05 m未満の小枝は出力しない（`if (medium && bottom < 0.05) return;`）。
  - 残す枝は、円柱の分割を4、側面だけ（`openEnded`）にした。
  - 幹は `createTreeBase` を共有している。

lowは `createTemperateTreeLod(species)` に専用化した。7つの楕円体の形は元のままで、陰影だけ `createCanopyLobes` を通す。

## 4. 調整の手順（再現・他樹種への適用時）

数値は推測で決めず、CEと同じ条件で描画して比べて決めた。

1. **比較ページを一時的に作る。** `src/` の下に置かないとViteで配信されない。作業後に必ず削除する。
   - 光源はCEと同じにする：`HemisphereLight(0xf4f0e6, 0x6d7a62, 0.9)` と `DirectionalLight(1.15)`、方向は `sunDirection(DEFAULT_SUN)`。
   - 背景は `0xc5c5bf`、`outputColorSpace = SRGB`、`pixelRatio = 1` にする。
2. **森と同じ形で描く。** モデルは必ず `createBvPrototypeCache().acquire()` を通す。森ではこれで頂点カラーにまとめられ、材質は両面描画（`DoubleSide`）になるので、見え方が変わるためである。
3. **2種類の画像で比べる。**
   - 1本ずつ：樹冠の高さ45／90 px、仰角12°／40°／70°。
   - 林：260本をインスタンス描画し、仰角35°・距離130 mから見る。
   - 1本ずつで最適な色にすると、林では明るすぎた。最終判断は林の見え方で行った。
4. **主な調整の流れ**（ライム）
   - 最初は、法線を樹冠全体へ寄せる比率が0.7、上向きの補正がなかった。房の下側が暗くなりすぎた。
   - 比率を0.85にし、上向きの補正を入れた（一時0.55、最終0.3）。
   - 色むらの明度幅を0.09から0.14に広げた。
   - 林で淡すぎたので、明度を0.31から0.235に下げた。
   - 真上から見ると隙間が目立ったので、`coverage` を1.05から1.3に上げた。

他の樹種に適用するときは、葉の房を作る関数で葉の点を集めて `fitCanopyLobe` に渡し、`coverage` と色を上の手順で決める。北方樹種（`borealTrees.ts`）では、すでに `coverage` 1.1 で使われている。

## 7. 未着手の選択肢

この方法で足りない場合の次の手は、インポスターである。高品質モデルを多方向から撮影した画像を、1本につき四角形1枚で描く方法で、mediumの帯域を置き換えられる。半球のオクタヘドラル配置で6×6〜8×8方向を撮影し、色と法線のアトラスにする想定である。ただし、設計も実装もまだしていない。

## 8. ベイスギ・モミへの適用（Codex GPT-6.1 Sol、2026-10-29）

F1-3で同じ手法を `western_red_cedar` と `silver_fir` へ適用した。highが作る鱗葉／針葉の頂点を、主枝ごとの隣接した枝葉の房として集め、同じ乱数列・枝の位置を維持して `fitCanopyLobe` に渡す。法線・頂点AO・色むら・頂点の揺らぎ・隠れた面の除去も共用する。

平たい枝葉を円形の水平断面へまとめると、highより丸く密になったため、`fitCanopyLobe(points, coverage, true)` の任意の引数を追加した。XZ共分散の固有値から水平の長軸・短軸を求め、房にカメラと無関係な固定の `rotationY` を持たせる。陰影と隠れた面の判定も同じ向きで計算する。既存の呼出しは引数を増やさず、従来の結果を維持する。

CEと同じprototype・材質・照明で、単木45／90 px・仰角12°／40°／70°と、260本の林・35°／130 mを比較した。最終mediumはベイスギ2,719三角形、モミ2,962三角形。色とcoverageの調整、作者・派生元、画像、テストと限界は [作製記録](../analytics/ce-tree-lod-cedar-fir-20261029.md) に記録した。元のOpus defaultはultraとして保持し、新作3段階をCodexとして登録している。

## 9. ナツメヤシ・アンブレラソーンへの適用（Codex GPT-6.1 Sol、2026-10-29）

F2-1で `date_palm` と `umbrella_thorn` へ適用した。ナツメヤシはhighの羽状葉を前後半に分けた頂点群、アンブレラソーンはhighの平たい葉群ごとの頂点群を使う。元の乱数列・枝の位置を維持する。

ナツメヤシの初期の水平近似は、垂れた枯葉を丸い房にしていた。葉軸の接線から局所座標を作り、その座標で当てはめた房を固定Quaternionで元の傾きへ戻す任意の `orientation` を追加した。外接範囲・法線・隠れた面も同じ回転で扱う。既存の `rotationY` と向き未指定の房は従来の計算経路を維持する。カメラに依存しない。

群生時の密度差を見て、ナツメヤシのcoverageを0.85から0.65へ下げた。アカシアは1。最終mediumはそれぞれ2,455・1,887三角形。CEと同じprototype・照明による単木45／90 px・3仰角・260本の林、実BVと森林LODの確認、highとの透け方の差、樹形比の補正は [作製記録](../analytics/ce-tree-lod-arid-20261029.md) に残した。
