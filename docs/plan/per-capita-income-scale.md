## 1. 問題

### 1.1 経済が人口に比べて1桁小さい

1人・年あたり、主食の必要量（0.43 wain = 200 kg）の何年分か。シムは地図2102・2103の2〜5年目の値。

| | シム | 1500年ごろのイングランド |
| --- | ---: | ---: |
| 労働者の日給（主食 kg） | 1.0 | 約11 |
| 家計の貨幣所得 | 0.67 | — |
| 1人あたりの GDP | 測っていない（§5.1） | 5〜6 |
| 貨幣 | 0.68 | 1.5〜2 |
| 貨幣 ÷ 貨幣所得 | 約1年 | GDP の3〜4か月 |

- 人口で比べると、貨幣は史実の約1/3。回っている経済で比べると、貨幣はむしろ多い（回転が史実の1/3〜1/4）。小さいのは経済の側である。
- 史実の値は概数で、出典は確認していない（price-level-20261116 §1）。±30〜50%で読む。

### 1.2 原因は賃金の定義

- `subsistenceWage.ts` の賃金は「働き手自身の食費 × `WAGE_SUBSISTENCE_MULTIPLE`（1.5）」。1日で主食1 kgしか買えない。
- この倍率は [craft-wage-subsistence-scale.md](craft-wage-subsistence-scale.md) §2 で「労働者1人で家族1.5人分の食費」として決めた。この時の目的は、都市の家計が食費を払えるようにすることだった。史実の実質賃金との比較はしていない。
- 史実の労働者（日給 4 d、年約250日）は、年に主食約 2,900 kg を買えた。これは自分の必要量の約14年分にあたる。家族4〜5人の食費を払っても、穀物は家計の4割程度で、残りは肉・乳製品・ビール・布・燃料・家賃に回った。
- 品の値段（`Good.value`）は、主食に比べると多くが史実に近い。肉・蝋燭・亜麻布・靴・ワイン・塩は0.7〜1.7倍に収まる。ずれているのは主に賃金の方である。

### 1.3 賃金を上げると、労働の多い品の値段が足りなくなる

賃金が品の値段に占める割合（`laborPointsPerLotAtDefaultRate`、主食 0.8 SP/wain、材料費は含まない）。

| 品 | 倍率 1.5（今） | 倍率 14（史実の日給） | 史実比較（price-level §2） |
| --- | ---: | ---: | --- |
| Ink | 2,565% | — | 未比較（労働量の誤りとみられる） |
| Lime | 87% | 813% | 未比較 |
| Sails | 58% | 542% | 未比較 |
| Garments（3種） | 32% | 300% | — |
| Harnesses | 23% | 217% | — |
| Glass | 19% | 181% | — |
| Wool Cloth・Cloth | 11% | 106% | 史実の0.3倍 |
| Linen | 7% | 65% | 史実の1.3倍 |
| Meat | 2% | 19% | 史実の1.4倍 |
| Boots | 1% | 6% | 史実の0.7倍 |
| Cheese | 1% | 6% | 史実の6倍 |

- 賃金だけで値段を超える品の多くは、史実比較でも安すぎる側にある（毛織物0.3倍、羊毛0.15倍）。史実の毛織物は、羊毛の代金に紡ぎ・織りの賃金を足すと値段にほぼ一致する（12 d/kg ≈ 羊毛 5.5 d + 労働 1.6日 × 4 d）。
- 逆に、労働が少なく値段が高い品（チーズ6倍、鉄2.8倍）は、賃金を上げても値段は直らない。別の原因（需給・下限）として扱う。

## 2. 方針

1. **尺度の基準は、労働者の1日の賃金で買える主食の量（実質賃金）とする。** 今の1 kgを、史実の約11 kgに近づける。
2. 賃金の倍率を Simulation settings の設定 `wageSubsistenceMultiple` にする（既定 1.5、今の値）。§4 の計測の後に既定を変える。値は 1.5〜16 の範囲で選べる。
3. 品の値段は、一律では上げない。賃金を上げた時に「材料費 + 賃金」が値段を超える品だけを、史実比較と照らして個別に直す（§3.2）。主食に対する相対価格が史実に合っている品は動かさない。
4. お金の側（K、開始時の配分）は、この設計では変えない。賃金が上がると家計に入るお金と回転は増える。貨幣の量は、その結果を測ってから [start-provisioning.md](start-provisioning.md) 側で決め直す（§6）。

選ばない案:

- **主食の値段を1/10にする。** 実質賃金の比は同じになるが、農家の貨幣所得（主食を売った代金）も1/10になり、今でも小さい貨幣経済がさらに縮む。主食に比べて多くの品の値段が史実に合っている現状を崩すことにもなる。
- **K（`MONEY_SCALE_BASE`）を上げる。** 定額のお金だけが増え、賃金と品の値段は変わらない。回転がさらに落ちる。

## 3. 変更

### 3.1 賃金の倍率を設定にする

- `subsistenceWage.ts` の倍率を、`marketSettings` の `wageSubsistenceMultiple` から読む（既定 1.5）。定数 `WAGE_SUBSISTENCE_MULTIPLE` は既定値と基準の倍率として残す。
- この倍率は次の所でも使われている。どこまで同じ倍率に連動させるかを、実装の前に一覧にする:
  - `extractionPayments.ts` の `UNFREE_UPKEEP_SHARE_OF_WAGE = 1 / WAGE_SUBSISTENCE_MULTIPLE`（不自由労働の扶養費は食費に固定したいので、倍率で割る式は残す）
  - `householdWealth.ts`、`mineOperations.ts`、`saltProduction.ts`、`textileCommissions.ts`、`transportAssetOrders.ts`、`production-generator.ts`、`strategicLaborMarkets.ts`
- `NAVY_CREW_WAGE_PER_YEAR`（0.25）などの、賃金と別に決めた定額の給与も一覧にする。賃金と同じ尺度の給与は、倍率に連動させる。

### 3.2 値段が足りなくなる品の直し方

- 倍率ごとに、品ごとの「材料費（基準の値）+ 賃金」と `Good.value` の比を出すスクリプトを作る（シムは回さない）。
- 比が1を超える品は、次の順で扱う。
  1. 労働量が明らかに誤っている品は、労働量を直す。Ink（1ロット 3.4 SP に約 1,500 人・月）がこれにあたる。
  2. 史実比較で安すぎる品は、値段を「材料費 + 賃金 + 利幅」まで上げる。毛織物・衣服・羊毛がこれにあたる。羊毛を上げると毛織物の材料費も上がるので、鎖の上流から順に決める。
  3. 史実の値段が分からない品は、利幅を同じ系統の品の中央値として値段を決める。
- 値段を上げる品の需要（家計の予算の配分）が変わる。生産量と家計の充足率を §4 で測る。

### 3.3 変えないもの

- 主食の値段、`GROSS_FOOD_NEED`、`PRICE_FLOOR`。主食の値段が下限に張り付く問題（price-level §4の2）は別に扱う。
- `MONEY_SCALE_BASE`、開始時の配分。

## 4. 計測

- 地図2103（必要なら2102も）、36か月、戦争なし、略奪なし。
- 倍率 1.5・4・8・14 の4点。§3.2 の値段の直しの前と後で測る。
- 1人あたりの GDP を測る（§5.1）。

| 指標 | 目標（倍率14の時） |
| --- | --- |
| 実質賃金（1日の賃金 ÷ 主食 kg の値段） | 8〜14 kg |
| 1人あたりの GDP（主食の何年分） | 4〜6 |
| 家計の貨幣所得 | 倍率1.5の時より増える。増え方を記録する |
| 品目別の生産量 | 値段を直した後に、倍率1.5の時から大きく減らない |
| 町の金庫が0の町の割合 | 大きく増えない（賃金は町の金庫から払う） |
| 都市の食費 / 必要量 | 下がらない |
| 国の軍需工場の支出 | 国庫が数年で尽きない |

## 5. 未確定事項

### 5.1 GDP の測り方

- GDP = 農村の生産（自家消費を含む主食・家畜・乳・羊毛を農家渡しの値段で）+ 町の工房の付加価値（売上 − 材料費）+ 国・人物への給与。
- 自家消費は、今の `--money-flows` に現れない。観測（`scripts/lib/observeViews.mts` の `wealth`）に、食料の帳簿の生産量と農家渡しの値段を足す必要がある。

### 5.2 倍率の決め方

- 史実の日給（約11 kg）は、年約250日働く成人男子の値である。シムの労働点（1,000人・月）は女・子供・季節の働き手を含むので、1人・月あたりの賃金は史実の日給×25日より低くてよい可能性がある。§4 で GDP を見ながら、8〜14 の範囲で決める。
- 農村の賃金（`householdWealth.ts` の農村と町の重み）の扱いも、倍率を決める時に見る。

### 5.3 開始時の配分への引き継ぎ

- §4 の結果から、開始時の貨幣を「GDP の3〜4か月分」、国庫を「年の収入の1年分未満」として配り直す。この作業は [start-provisioning.md](start-provisioning.md) 側の後続とする。
- 1年目の公共の支出の大きさ（money-sink-20261116 §3の1）は、開始時の国庫と `getComfortableTreasuryLevel()` の関係で決まる。開始時の配分と一緒に扱う。

## 6. 実装の順序

1. §3.1 の一覧を作り、`wageSubsistenceMultiple` を設定にする（既定 1.5 で、動きは変わらない）。単体テストは「既定で今の値」「倍率に比例する」の2点に限る。
2. §3.2 のスクリプトで、倍率 4・8・14 の時に値段が足りない品の一覧を作る。
3. §5.1 の GDP の観測を足す。
4. §4 を倍率 1.5・4・8・14 で測る（値段を直す前）。
5. 値段を直す（§3.2）。もう一度 §4 を測り、既定の倍率を決める。
6. 結果を本書に記録し、開始時の配分の見直し（§5.3）に進む。
