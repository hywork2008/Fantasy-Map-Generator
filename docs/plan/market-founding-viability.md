# 市場の開設と、成り立たない市場の取り込み

作成: 2026-10-31。根拠の計測: [market-founding-20261031.md](../analytics/market-founding-20261031.md)、[salt-residual-shortfall-20261031.md](../analytics/salt-residual-shortfall-20261031.md)。

## 1. 問題

- 煮詰めの人手の見直しの後、残る家畜の塩の不足は市場24・25・27だけにある（[salt-supply-calibration.md](salt-supply-calibration.md)§3.16）。原因は農村の財布の小ささである。
- これらの市場は、シミュレーション中に村が町へ昇格した時に開かれた。中心は500〜1,100人の村1つで、1万〜2.6万人の農村が付き、町の割合は2〜7%である。
- 農村の千人あたりの財布は4〜22で、ほかの市場（48〜171）の10分の1から40分の1しかない。農村には、穀物や家畜を売る相手がほとんどいない。
- 原因は2つある。
  - **開く時の規則が無い。** 地図の生成では、既存の市場から間隔`minSpacing`（固定入力で161）以上離れた町だけを中心にする。シミュレーション中の`Markets.addMarket`は、間隔も規模も見ない。10の新しい市場のうち9が、間隔より近い所に開かれた。
  - **畳む仕組みが無い。** `removeMarket`は画面からの手動だけで、金庫・掛け・在庫を引き継がない。
- このままでは、区割りの時点で成り立たない市場を、塩・肉・草などの側でいつまでも校正することになる。

## 2. 史実の目安

- 13世紀のイングランドでは、国王が多くの市場の開設を許した。多くの小さい市場は、長く続かずに消えた。
- 法学者ブラクトンは、新しい市場が既存の市場から6⅔マイル（約11 km、1日の行程の3分の1）以内にあれば、既存の市場の害になるとした。
- 市場が成り立つかは、許しの有無ではなく、周りに売り手と買い手が集まるかで決まった。

（どちらも一般的な説明による。原典は確かめていない。）

## 3. 方針

### 3.1 M1: 昇格した村は、間隔を守る時だけ市場を開く

- `addMarket`をシミュレーション中の昇格から呼ぶ時（`simulation.ts`の`fmg:settlement-promoted`）は、地図の生成と同じ間隔の基準を使う。
  - 既存のどの市場の中心からも`minSpacing`以上離れている時だけ、新しい市場を開く。
  - それより近い時は市場を開かず、村はそのセルの今の市場に入る（`burg.market = column[cell]`）。区割りは塗り直さない。
- 間隔の式は、`createSpacedMarkets`と同じものを関数に分けて使う。
- 画面からの`addMarket`（Markets Overview）は、今のまま制限しない。
- 国ごとの区割り（frontier・marches・scattered）は、もともと国に1つの市場なので変わらない。

### 3.2 M2: 成り立たない市場を畳み、隣の市場に取り込む

- **判定:** 毎年12月（昇格と同じ時）に、次の両方を満たす市場を畳む。
  - 農村の1人あたりの財布が、全市場の中央値の20%（仮値）より小さい月が、12か月続いた。
  - 国の首都を中心にした市場ではない。
- 基準は、全市場の中央値に対する比にする。お金の量の校正が変わっても、基準を直さなくてよい。
- 84か月目の固定入力（中央値は農村の千人あたり89）では、次のようになる見込みである。
  - 市場19・23・24・25・27（中央値の5〜19%）が畳まれる。
  - 市場22・26（24%）はぎりぎり残る。
  - 市場10・13（54〜62%）は入らない。
- **取り込み先:** 畳む市場のセルを、ほかの中心から塗り直す（`expandTerritories`）。畳む市場の中心の町が入った市場を、取り込み先とする。
- **引き継ぐもの:** 塩の優先順位の3（掛けを正しく返す）を守るため、お金と掛けを消さずに移す。
  - 市場の金庫の残高。
  - 市場が負う掛け: 製塩所への塩の掛け（`saltPayables`）、農村の穀物の掛け（`ruralGrainPayable`）、交易の掛け。
  - 市場が持つ貸し: 農村の塩の掛け（`ruralSaltReceivable`）。
  - 財の在庫（値段は取り込み先の値段にする）。
  - 運送中の塩の送り先（`toMarketId`）と取り引き（`deals`）。
  - 商人・運送の資産、町の店の帳簿（`syncBurgMarketLedgers`）。
- 農村の財布は、今の`moveRuralPursesWithFarms`が畑と一緒に移す。
- 一度畳んだ市場の中心の町は、同じ年にまた市場を開かない。
- 詳しい項目は、M2の実装の前に、市場が持つ欄をすべて洗い出して決める。

### 3.3 M3（別の設計書）: 市場の外で暮らす地域

- 僻地や離島の人は、市場の経済から外れ、村の中の物々交換で暮らしていた。塩だけは、定期市・行商人・物々交換（チーズ・羊毛・皮・家畜と）で手に入れた。10分の1税は、穀物や子羊を現物で納めた。
- 区割りに届く範囲（中心からの移動の費用の上限）を設け、届かないセルを、どの市場にも属さない自給の地域にする。
- 自給の地域では、次のようにする。
  - 塩は物々交換で手に入れる。お金は動かない。
  - 教会は10分の1税を現物で集め、市場で売る。これが僻地から市場へお金が入る道にもなる。
- 塩の側には、市場に属さない人を不足として数える仕組み（`unmarketedPeople`）が既にある。物々交換が入るまでは、自給の地域を作らない。
- M1・M2の結果を見てから、別の設計書にする。

## 4. 段階

| 段階 | 内容 | 完了条件 |

| M0 | 市場が開かれる時と、84か月目の姿の計測 | 済み（[記録](../analytics/market-founding-20261031.md)） |

| M2a | 市場が持つ欄の洗い出しと、引き継ぎの処理 | 単体テスト（金庫・掛け・在庫・運送中の塩が、合計を変えずに移る） |

M3で確かめること:

1. 塩の優先順位: 家畜と人の塩の不足、値段÷仕入れ値、掛けの残高。
2. 農村の千人あたりの財布の、市場ごとの広がり。
3. 都市の主食の充足、budgetGap、町の家計の財布（市場14・16・21）。
4. 市場の数と、畳まれた市場。お金の合計が、畳む前後で変わらないこと。

### 4.1 M1・M2a・M2bの実装と84か月（2026-10-31、[記録](../analytics/market-founding-m1-20261031.md)）

- **設定:** 調整の値は、ワールドと一緒に保存する`fmg-market-settings`（`src/simulation/marketSettings.ts`）に置いた。Options の Simulation タブの「市場（経済）」で変えられる。
  - 新しい市場の間隔の倍率（既定1.0）。161は地図の大きさと町の数で決まる値なので、生成の時の間隔に対する倍率にした。画面には、今の地図での距離を並べて出す。
  - 市場を畳む農村の財布の割合（既定20%、0で畳まない）と、続く月数（既定12）。
- **M1:**
  - `Markets.addMarket(burgId, { spaced: true })`は、どの市場の中心からも間隔×倍率より近い時、市場を開かずに今の市場に入れる。
  - 昇格（`fmg:settlement-promoted`）だけがこれを使う。世界の誕生の時の昇格も同じ経路を通るので、§5の3つ目の問いはこれで決まった（同じ規則にする。前の開き方は選べるようにしない）。
  - 間隔の式は`getMarketGenerationSpacing`に分け、生成でも使う。
- **M2a・M2b（`marketDissolution.ts`、`Markets.dissolveUnviableMarkets`）:**
  - 毎月の決済の最後に判定する（早送りの時は判定しない）。
  - 首都の市場を除き、続く月数に達した市場の区割りを、その市場を除いて塗り直す。中心の町が入った市場に、次を移す。
    - 金庫・農村の穀物の掛け・塩の掛け・交易の掛け（ほかの市場がこの市場に負う分は、取り込み先に付け替え、2つの市場の間の分は消す）。
    - 農村の塩の貸し、財の在庫、蓄えた穀物、農村の財布、運送の資産、商人組合の本拠。
  - 運送中の荷・注文・遠征がある月は待つ（`marketTrafficInFlight`）。
- **84か月の結果:**
  - 昇格した村10のうち9が既存の市場に入り、市場は18（前は27）になった。
  - 家畜の塩の不足は7年間0（前は1306年に4,651袋）、人の塩の不足は30〜72%減った。国28の不足は7,207から875になった。都市の主食とbudgetGapも良くなった。
  - **M2は一度も畳まなかった。** 唯一の新しい市場18（中央値の16%）は72か月目から条件に達したが、毎月どれかの荷が動いていた（商隊・町への荷・荷に入った資本・前払いの代金）。荷の無い月を待つ方式は成り立たない。
- テスト: `markets-generator.test.ts`（66件、2件追加）、`marketDissolution.test.ts`（3件、新規）、`householdWealth`・`newMarketProvisions`・`worldSettings`の関連テストは成功。

### 4.2 畳む市場の運送中の荷: 店じまいと引き継ぎ（2026-10-31、[記録](../analytics/market-dissolution-m2-20261031.md)）

- 2つの方式を実装し、Simulation設定の「畳む市場の運送中の荷」で選べるようにした（`dissolveCargo`）。
  - **店じまい（`windDown`、既定）:** 条件に達した市場に`dissolving`を付ける。市場どうしの交易（`isMarketTradePermitted`）と戦略物資の調達で、その市場を相手にしない。市場どうしの運送中の荷が無くなった月に畳む。財布が基準を上回れば、印を外して取り引きを戻す。
  - **引き継ぎ（`handOver`）:** すぐに畳む。商隊・輸出の待ち荷・運送の予約・海外の遠征の行き先や出どころを付け替える。前払いの代金と荷に入った資本は取り込み先の金庫に、運送の資産の予約中・運送中の数は取り込み先の帳簿に移す。
  - どちらも、自分の町への荷（`MarketShipment`）・塩の荷・運送の資産の注文は、取り込み先に付け替える。町の人の塩と品物を止めないためである。
  - 商船は造船の拡張が市場の番号で持つので、商船を持つ市場はどちらでも畳まない。
- 待つ判定が、使い終わった運送の予約（`released`など）も数えていた誤りを直した。
- **84か月:**
  - 市場18は71か月目に条件に達した。店じまいでは73か月目、引き継ぎでは71か月目に、市場13に取り込まれた。
  - 畳む前後で、全市場のお金・掛け・貸しの合計の差は0だった。
  - 塩と家計は、M1だけの時とほぼ同じか少し良かった（1306年の製塩所への掛け1,367 → 1,222・957）。
- テスト: `marketDissolution.test.ts`（5件）、`markets-generator`・`merchantOrganizations`・`strategicProcurement`の関連テストは成功。
- 設定画面: ブラウザー（Playwright）で、Simulationタブに4つの項目が出ること、倍率を変えると距離の表示が変わること、値が保存されることを確かめた（[記録](../analytics/town-purse-after-market-founding-20261031.md)§5）。

## 5. 未決の事項

- 間隔の倍率1.0・中央値の20%・12か月は既定値で、Simulation設定で変えられる（§4.1）。
- 市場の区割りが変わるので、goldenの値は変わる。goldenの作り直しは、区切りの時にまとめて行う。
