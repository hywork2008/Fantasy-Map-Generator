# CEの高さの層: 地面・川・用地・城を独立させ、セルから高さを外す

作成日: 2026-10-24
状態: 2026-10-24 実装（L0〜L4）。川の回廊は保存し、高さ場への焼き込みは止めた。用地は多角形の pad で、セル標高の編集は高さ場では pad になる。cells モードは川に食い込んだ擁壁だけを水面で切り抜く。受入は Vitest（段差のある用地・川の単調な水面・用地が川を動かさないこと・崖上城塞の既存試験）と headless Chromium の BV 確認用サンプルで見る。

## 1. 目的

山の斜面のような地形をメッシュ（高さ場）で作り、そこに家を建てるための水平な用地を造り、家と重ならないように川を引けるようにする。川と城は、それぞれ固有の高さを持つ。崖の上に城を建てられるようにする。

`ce-terrain-field-mode.md` は、自然の地面の高さを細かい高さ場（`field`）に移した。本設計はその続編で、川と用地の高さもセルから切り離す。

### 1.1 受入基準

高さ場モードの tiny（600 m）または small（1,200 m）の図枠で、次をすべて満たせば合格とする。

1. 斜面の上に、高さの違う水平な用地を3段以上造り、それぞれに家が載る。家は浮かず、埋もれない。
2. 川は、上流から下流へ下り続ける水面を持つ。川幅の方向には水平である。
3. 川の水面と岸は、用地の高さに引きずられない。用地の縁は川岸に沿い、セルの辺には立たない。
4. 用地と川が同じセルにあっても、2026-10-24 の不具合（セルの外周の壁が、クッキーの型のように川の上に立つ）が起きない。
5. 崖の上の城（`ce-terrain-field-mode.md` §1.1 の1〜6）が、これまでどおり成り立つ。
6. 旧文書（`field` を持たない文書）の見た目は変わらない。ただし §8 の小修正を除く。
7. コンソールにエラーが出ない。

## 2. 現状と問題

調査で確かめた事実:

- セル（`face.properties.elevation`）が、区・街路・区画のトポロジーと地面の高さの両方を持つ。セルは水平な1枚の板として押し出され、隣のセルとは土手か擁壁でつながる（`cellRelief.ts`、`ce-terrain-grading-layer.md` §7.18）。
- 川はセルの辺に引かれる（`featureGroups` の `kind: "river"` の頂点列）。FMGから取り込んだ川は `riverFlows` と `waterAreas`（連続した多角形）で持ち、街区のメッシュとは独立している。
- 川幅はセルの辺からセルの中心へ向けて取られる。そのため、同じセルの中に、同じ elevation を共有する陸地と川ができる。
- 3Dの水面は、川の多角形の頂点ごとに `terrain.heightAt` から決めている（`city3d/three/waterMeshes.ts`）。2026-10-24 に、`cells` では近くの頂点の最低値（`cellBedAt`）、`field` では岸の高さに上限を付けた値（`rimAt`）に改めた。どちらも「地面の高さから水面を推測する」方式である。
- 高さ場モードの川は、`carveRivers`（`terrainField/conform.ts`）で高さ場を削って作る。川床は下流へ単調に下る。しかし川床の高さは保存されず、水面の描画は削った後の `heightAt` から推測し直している。
- 用地を表す造成物は、すでに `TerrainPlatform`（`kind: "platform"`、`role?: "terrace"`、`summit` は円かセルの集まり、縁は `cliff` か `slope`）がある。summit がセルの集まりなので、台地の縁は必ずセルの辺に立つ。

問題は、セルのグリッドではなく、高さの持ち主がセルであることにある。2026-10-24 の不具合は次のように起きた。

1. 川沿いのセルの elevation を 10 にする。
2. セルの板は 10 m の高さで押し出され、その外周に壁が立つ。
3. 川の多角形はセルの中に食い込んでいるので、水面は低いところに描かれても、壁はセルの辺に立ったまま川の上に残る。

水面の決め方を直しても、壁の位置はセルの辺から動かない。高さの持ち主をセルから外さない限り、別の形で同じ問題が出る。

## 3. 方針: 高さの持ち主を層に分ける

| 層 | 高さの持ち主 | 形の決まり方 | 保存 |
| --- | --- | --- | --- |
| 自然の地面 | 高さ場 `field` | テンプレート・部品・FMGとの整合 | レシピ（既存） |
| 川 | 川の回廊 `riverCorridor`（新設） | 中心線・幅・川床の縦断・岸の形 | 回廊そのもの |
| 用地 | 敷地 `pad`（`TerrainPlatform` を拡張） | 多角形・高さ・縁の形 | 敷地そのもの |
| 城 | 城の台地（既存の platform、縁は崖） | 城郭の回路 | 既存 |
| 道 | 道路の縦断（既存の `roadGrading.ts`） | 道の中心線 | 生成時に解く（既存） |
| セル | 持たない | 区・街路・区画のトポロジーだけ | 既存 |

セルの elevation は、高さ場モードでは表示と既存の処理のための導出値とする（`attachTerrainField` がセル内の平均を書く今の扱いのまま）。高さを決める処理は、セルの elevation を読まない。

### 3.1 合成の順

地面の高さは、次の順に重ねて決める。

1. 高さ場（自然の地面）
2. 川の回廊が削る。回廊の中は川床、岸の帯は岸の形に従う。
3. 用地と城の台地が、盛るか削る。用地の多角形からは、川の回廊（岸の帯を含む）を差し引いてから重ねる。
4. 道の縦断が、道の帯を削るか盛る。

川を用地より先に置き、用地から回廊を差し引く。これで、用地の縁は川岸に沿い、セルの辺に立つことはない。川の上に用地の壁が残ることもない。

`evaluateTerrainFeatures` の合成規則（`ce-terrain-grading-layer.md` §3.3）は変えない。回廊を新しい造成物の種類として加え、適用の順を上のとおりにする。

### 3.2 水面は回廊から直接決める

水面の高さは、回廊の縦断（川床の高さ + 水深）から決める。`heightAt` から推測しない。2026-10-24 に入れた `rimAt` と `cellBedAt` は、回廊を持たない文書（旧文書と `cells` モード）のためだけに残す。

## 4. 川の回廊 `riverCorridor`

### 4.1 データ

```ts
interface TerrainRiverCorridor {
  kind: "riverCorridor";
  id: Id;
  /** Source feature group or riverFlow, so an edit to the river can rebuild the corridor. */
  sourceId: Id;
  /** Upstream first. */
  centerline: Point[];
  /** Water width at each centerline point, in metres. */
  widthsMeters: number[];
  /** Bed height at each centerline point. Never rises downstream. */
  bedMeters: number[];
  /** Water depth above the bed. */
  depthMeters: number;
  bank: { kind: "slope"; runMeters: number } | { kind: "quay"; heightMeters: number };
}
```

- `TerrainFeature` の和に加え、`document.terrain.features` に保存する。
- 岸の形は2種類とする。`slope` は土の岸（川床から地面まで `runMeters` で上がる）、`quay` は石の護岸（鉛直の壁）である。町の中は `quay`、郊外は `slope` を既定にする。

### 4.2 作り方

- 中心線は、FMGから取り込んだ川では `riverFlows` を、CEで描いた川では `featureGroups` の川の頂点列を使う（`terrainField/build.ts` の `riversOf` と同じ選び方）。
- 川床の縦断は、今の `carveRivers` の計算（上流の地面から水深分下げ、下流へ単調に下る）を流用する。結果を `bedMeters` として保存する。
- 川の向きは `riverFlow.ts` の結果に従う（`ce-terrain-field-mode.md` §4.3 の3）。

### 4.3 セルとの関係

回廊はセルの辺に縛られない。セルの辺に引かれた川（`featureGroups`）も、回廊は中心線と幅だけを使い、回廊の多角形は中心線から幅で張る。

区・街路・区画の生成は今のまま、セルの辺の川を障害として扱う。回廊の多角形が区画に重なる場合は、区画から回廊を差し引く（`waterAreas` の扱いと同じ）。

### 4.4 描画

- 3Dの水面: 回廊の多角形を、中心線に沿う断面ごとに `bedMeters + depthMeters` の高さで張る。断面の中は水平にする。
- 岸: `slope` は回廊の縁から外側へ地面まで下ろす面、`quay` は水面の少し下から岸の地面までの鉛直の壁にする。
- 2D: 今の川の描き方を変えない。`quay` の岸は線で示す。

## 5. 用地 `pad`

### 5.1 データ

既存の `TerrainPlatform` の `summit` に、多角形を加える。

```ts
type TerrainShape =
  | ({ kind: "circle" } & TerrainCircle)
  | { kind: "faces"; faceIds: Id[] }
  | { kind: "polygon"; points: Point[] }; // new
```

- `role` に `"pad"` を加える。`"terrace"`（段々の町の自動の段）とは分ける。
- 縁の形は既存の `cliff`・`slope` に、`wall`（石の擁壁）を加える。擁壁の上限の高さは `RETAINING_MAX_METERS`（3 m）を既定にする。

### 5.2 セルの標高の編集を用地の作成に読み替える

高さ場モードでセルの elevation を編集すると、今はセルの板の高さが変わる。これを次のように読み替える。

1. 編集したセルの多角形から、川の回廊（岸の帯を含む）と、道の帯を差し引く。
2. 残った多角形を summit とし、編集した値を高さとする `pad` を作る。セルに `pad` が既にあれば、その高さを変える。
3. セルの elevation には何も書かない（導出値のまま）。

`cells` モード（旧文書）では、セルの elevation の編集を今のまま残す。

### 5.3 自動の用地

生成の時に、家を建てる区画ごとに `pad` を作るかは、T3（`ce-terrain-field-mode.md` §6）の敷地の造成で決まる。今は建物ごとに `foundationAt` が切土と盛土を釣り合わせた高さを返している。本設計では、次の段階で区画単位の `pad` にまとめる（§7 の L3）。

- 1つの区画の建物は、1つの `pad` を共有する。隣り合う建物の基礎の高さがばらばらになるのを防ぐ。
- `pad` の多角形は区画の多角形とし、川の回廊と道の帯を差し引く。

## 6. 建物と道

- `foundationAt` は、足元が `pad` の上ならその高さを返す。`pad` の外では、今の釣り合いの計算（`fieldFoundation`）を使う。
- 道の縦断（`roadGrading.ts`）は、`pad` の縁を段差として扱う。道と `pad` の差が階段で上れる範囲（3 m）を超える場合は、`pad` の縁に階段を付ける（P4 の段々の町の階段と同じ）。
- 川を渡る橋は、回廊の幅を最短で渡す。橋の角度は `src/utils/bridgeSkewPolicy.ts` の判定に従う。橋の床の高さは、両岸の地面の高さと、回廊の水面より上の余裕から決める。

## 7. 段階

| 段階 | 内容 |
| --- | --- |
| L0 | `cells` モードの小修正（§8）。並行して先に出せる |
| L1 | 川の回廊。データ・生成時の作成・保存・`carveRivers` の置き換え・3Dの水面と岸。高さ場モードでのみ使う |
| L2 | 用地 `pad`。多角形の summit、`wall` の縁、セルの標高の編集の読み替え、回廊と道の差し引き |
| L3 | 区画単位の自動の `pad`。`foundationAt` を `pad` に合わせる。道と `pad` の階段 |
| L4 | 受入基準（§1.1）の確認。BVに、斜面の段々の用地と川を持つ編集可能な確認用サンプルを置く |

L1 と L2 は、高さ場モード（`document.terrain.field` を持つ文書）だけを対象にする。旧文書は今の動作のまま残す。

## 8. `cells` モードの小修正（L0）

旧文書の `cells` モードでも、セルの板の外周の壁が川の上に立つ。セルの板を押し出す前に、セルの多角形から水面の多角形（`waterAreas` と川の多角形）を差し引き、残りの縁にだけ壁を立てる。

- 差し引いた縁のうち、水面に面する部分には壁を立てず、`bankMesh` の岸の面に任せる。
- 水面の高さは、2026-10-24 の `cellBedAt` のまま（近くの頂点の最低値）とする。

これは本設計の層の分離とは独立した修正で、旧文書の見た目のうち変わるのはこの壁だけである。

## 9. 保存

- 川の回廊と用地は `CityDocument.terrain.features` に保存する。どちらも高さを持つ造成物なので、高さ場のレシピと違って結果そのものを保存する。
- 読み込みの検査（`incomingCity.ts`）に、`riverCorridor` と `polygon` の summit を加える。`bedMeters` が下流へ上る文書は、読み込みで単調に直す。
- 川の中心線を編集したら、回廊を作り直す。用地は、回廊と道との差し引きをやり直す。

## 10. 範囲外

- 地形に合わせた街路と区画の生成（等高線に沿う区画、勾配をコストにした街路の経路探索）。`ce-terrain-field-mode.md` §12 と同じく、別の設計で扱う。
- 川の蛇行や流路そのものの自動生成。川の位置は、FMGか手で描いたものを使う。
- 滝・堰・水車の水路の造成。
- 高さ場の筆による手の編集。

## 11. 採用しない案

- **なだらかな山を作る新しいツールを作り、そこに建物を配置する:** 街路・区画・建物の配置・城郭・3D表示をCEと二重に持つことになる。山を作る部分は、すでに `terrainField` の部品（hill・range・crag・spur・noise など）が受け持っている。足りないのは地形を作る機能ではなく、川と用地の高さを地形から独立させる仕組みである。
- **セルを細かくして、セルの elevation のまま川と用地を分ける:** セルは街区のトポロジーも兼ねるので、地形のためだけに細かくすると街路と区画の生成が変わる（`ce-terrain-field-mode.md` §13 と同じ理由）。
- **水面を `heightAt` から推測する方式を磨く:** 2026-10-24 の `rimAt`・`cellBedAt` で水面の傾きは消えたが、セルの外周の壁は残った。壁の位置はセルの辺で決まるので、水面の決め方では直らない。
- **川をセルの辺ではなく、セルの中に引くよう生成を変える:** 区・街路・区画の生成全体に影響する。回廊をセルから独立させれば、生成を変えずに済む。
