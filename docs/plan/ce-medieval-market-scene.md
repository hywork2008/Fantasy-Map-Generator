# CE：中世ヨーロッパの市場景観

作成日：2026-11-03  
状態：調査・設計とM0実装を完了。既存06の手動配置に対応。市場の自動配置は未実装。

## 1. 結論と対象

**BVの「Medieval 06 · Market Stalls」は利用できる。青果屋台と布地屋台のLow／Highがあり、モデルを作り直す必要はない。調査時点ではCE配置カタログに未登録だったが、M0で登録・品質指定・保存・配置判定の接続を完了した（§10）。**

再現対象は主に1250〜1450年の西・中央ヨーロッパの市場日とする。「バザール」は賑わう市場風景という依頼上の呼称として扱い、全域を一様な東方風の屋根付き商店街にはしない。英国、フランドル、ヴェネツィアの事例を参照するが、各地の形を混ぜた一つの史実都市の復元とは呼ばない。

最初に作る構成は次の二つとする。

- **内陸の広場市場**：街路が集まる広場、周縁の店舗兼住宅、青果・パン・布地の販売台。中央の通行帯と教会・市庁舎の入口を開ける。
- **海港の市場**：荷揚げ場から少し内陸へ退いた魚・食料の売場、倉庫、港から中央市場へ向かう街路。貨物の荷役と買い物客の動線を分ける。

海のない地域でも航行可能な川に港と魚市場を置ける。海岸があっても港・漁業・交易がない地点に港市場を作らない。中央市場と港市場は同じ都市に併存できる。

資料から確認できることを「確認」、それをCEの空間やモデルに翻訳したものを「設計」と区別する。通路幅、店舗数、配置比率は史料で得た中世共通の規格ではない。年代の違う写真・復元建物を、そのまま中世の形の証拠にはしない。

### 2.1 立地の判断

**確認**：広場だけでなく、教会隣接地、街路、河岸の荷揚げ場、交易会館前に市場が成立した（H1〜H5）。市場の「中央」は幾何学的な都市中心と同義ではない。

**設計**：立地を「広場」「市場街路」「河川港」「海港」「会館前」に分ける。城門付近は搬入路と接続する市場の候補にするが、すべての中世都市が門前市場を持つとは扱わない。既存の `approachCommerce` がある場合はその市場街路・門内の空地を利用し、独立に別の商業軸を作らない。

以下の店舗構成は史料の販売比率ではなく、CE用の美術・配置プリセットである。

| プリセット | 市場位置・接続 | 売場 | 周囲と空間の特徴 |
| --- | --- | --- | --- |
| Inland plaza | 主街路が集まる既存プラザ。教会・市庁舎等があれば入口を尊重 | 青果、穀類、パン、乳製品、布、革・木製品。肉売場は別列にできる | 周縁に08、地域に適する場合26。中央通行帯、井戸・水盤への接近を残す |

| Inland river port | 実在する航行可能な河川港と背後街路 | 淡水魚、交易で届く保存魚、穀類、地域産品 | 河岸、搬入経路、倉庫。海がないことだけを理由に魚市場や船を除かない |

| Cloth-hall forecourt | 布会館の入口と接続する広場・沿道 | 布の台、巻布、小露店 | 27の会館と06の布地屋台。大規模会館を小村の必須要素にしない |

### 3.1 初回に作る二場面

**A：内陸広場、想定敷地40×30 m**

- 実測外接箱約4.7×3.6 mの06 Highを単位に、青果4・布地2の最大6店を候補とする。最初は既存2モデルの範囲で作り、青果をパン屋や肉屋と表示しない。
- 周縁に列を置き、広場を横切る主動線を最低4 m確保する。井戸・水盤と教会・会館への接近を残す。
- 後続段階でパン2、穀類・乳製品等2を追加して最大10店を目安にする。衝突や出口不足で減店する。敷地面積から定数で10店を押し込まない。

**B：海港背後地、想定敷地45×25 m**

- 魚モデル追加後、魚4・青果2・布地1を候補とする。魚がない初回接続時点では「港の食料・布地露店」として確認し、魚市場の完成扱いにしない。
- `岸壁／荷揚げ → 荷役専用帯 → 市場を通り抜けない搬入路 → 売場 → 背後街路` の接続を作る。岸壁全長を店で埋めない。
- 通常の荷役帯は暫定4 m以上とし、既存のクレーン旋回・落荷位置等の予約空間が広ければそちらを優先する。

40×30 m等はデモ用の設計寸法で、実在する中世市場の復元寸法ではない。小さな既存プラザでは1〜2店または0店でもよい。

## 5. モデル追加の優先順位

**第1群は既存06を無改変で接続する。第2群で不足する商品と簡素な屋台を足す。**

1. 無屋根の販売台、籠売り、布のない木製小屋。現在の06の全店舗反復を避ける。
2. 魚台：木の台、浅い容器・籠、魚、保存魚の樽。氷山盛りの近代売場にはしない。肉台とは商品を共有しない。
3. パン、穀類・豆、乳製品の陳列。袋・量器・籠を共用し、各商品は判別できる形にする。
4. 肉屋の台と支持梁、革・陶器・木工品。肉売場と屠畜作業は別機能にし、全市場に屠畜場を置かない。
5. 地域別の半常設小屋と店先販売台。市場十字架等は地域選択式。

既存 `marketDetails.ts` 内のframe／awning／counterは現在private関数で、商品・屋根の公開切替APIはない。追加時は必要な範囲を共通factoryへ取り出し、BV単体とCE配置で共有する。`stall shell + goods set + storage set` を構成単位とし、既存2モデルの既定出力を維持する。共通容器は既存の `props/medievalContainers` を優先し、青果Lowの重い籠を大量配置向けに無条件で複製しない。

史実モードでは地域・季節・交易に合う商品を選ぶ。ジャガイモ、トマト、トウガラシ、トウモロコシ、コーヒーを本対象期間の標準陳列に加えない。ファンタジーの商品は任意の追加プロファイルとする。

## 6. 配置と保存の設計

### 6.1 保存するもの

初回の手置きは既存の `CityElement(kind: "object")` を使う。モデルIDは既存06のIDを維持し、品質はモデルIDへ埋め込まず明示的な配置属性で渡す。`objectQuality?: "low" | "high" | "ultra"` を追加する案とし、06にUltraがないことはUIと解決規則で明示する。欠落時の06はHighを採用し、従来の他オブジェクトの既定品質を変えない。

自動配置の段階で、`CityDocument` に市場計画の任意フィールドを追加する。以下は**提案型であり、現状のAPIではない**。

```ts
interface MarketSite {
  id: string;
  setting: "plaza" | "street" | "river-port" | "sea-port" | "hall-front";
  boundary: Point[];
  anchorElementId?: string;
  accessPaths: Point[][];
  reservedAreas: Point[][];
  stallElementIds: string[];
  activity: "market-day" | "closed";
  regionalProfile: string;
  seed: number;
  locked: boolean;
}
```

- 区域・通路は計画情報、各屋台の位置・方位・品質はobjectが正本とする。市場側に別の屋台座標を二重保存しない。
- 自動配置は区域の確定後に一度行い、確定したobjectを保存する。カメラ移動・再描画・再読込で配置を変えない。
- 再生成は対象市場が所有する未ロックobjectだけを更新し、手動配置・ロックしたobjectを維持する。削除された参照の補修規則もcodecで定義する。
- 通常CEの旧文書に市場フィールドがなくても従来表示を維持し、読込だけで市場を自動追加しない。
- Freeformではplacements／plotsが正本。自動市場を対応させる段階で区域メタデータもFreeform台帳へ保存し、通常CEだけへ残さない。版変更・旧版補完をその段階で設計する。初回は手置きの品質往復までを必須にする。

`closed` は後続仕様である。陳列商品は片付け、仮設屋台は撤収状態、固定小屋・店舗は戸を閉じた状態とする。閉場モデルができるまでは `market-day` のみを提供する。

### 6.2 候補地と衝突

候補は既存プラザ形状、商業街路の拡幅部、港の乾いた背後地、会館前面から抽出する。点と `sizeMeters` しかないプラザではその値から保守的な区域を作り、形状・安全域を確定できなければ自動配置を省く。`faceIds: []` の広場やFreeformを「地面なし」と誤判定しない。

配置は候補生成→水・斜面等の拒否→動線確保→屋台割当の順とする。道路中心線への近さだけで店舗を並べない。

- 衝突箱は商品、布、張り綱、杭まで含む実測値から作る。屋根だけを範囲内にして張り綱を道へ出さない。
- 主歩行帯4 m、店舗間の通路2 m、背面の作業・在庫帯1.2 mを初期値とする。すべて**調整用の設計値**で、史料由来の規格ではない。買い物客の滞留分を別に確保する。
- 店舗正面は客用通路へ向け、店主の横入口・背面へ通じる道を確保する。+ZとCE方位の変換は [`placementContract.ts`](../../src/buildings/placementContract.ts) を使う。
- 水面、河川回廊、崖、建物敷地、城壁、門の通行部分、道路の有効幅、井戸・水盤・会館の出入口へ置かない。
- 岸壁の荷揚げ点・クレーン作業域・倉庫出入口への搬入路を禁止域にする。水域の予約と陸上の作業域を混同しない。現在データだけで陸上の全経路を得られない箇所は追加の予約ポリゴンを作る。
- Freeformの既存 [`validatePlacement.ts`](../../src/city-editor/generators/freeform/validatePlacement.ts) の水・勾配・重なり・道の拒否を共用する。隣接する屋台ごとに大きな擁壁・盛土を作るのではなく、先に平坦な市場面を選ぶ。
- 不足時は店舗数を減らす。海側へ押し出す、道幅を縮める、橋を増やす等で帳尻を合わせない。橋が関係する場合は既存 `bridgeSkewPolicy.ts` の判定に従う。

## 7. 描画・品質・負荷

屋台は既存 [`bvInstances.ts`](../../src/city3d/three/bvInstances.ts) のprototype共有とインスタンス化へ載せる。同一モデル・品質・商品・配色で共有し、位置・回転だけをinstanceに持たせる。共有材質を直接変更して他店の色まで変えない。バリエーションは少数の配色定義に限定し、キャッシュキーへ含める。

06 Highを青果10・布10置くと約620,960三角形となる。インスタンス化しても描く三角形数は消えない。青果Lowへ落とすと逆に増える。初回デモは6〜10店程度とし、全都市へ大量適用する前に簡素な距離用モデルを追加する。品質選択と距離LODは別の契約とし、既存Lowを黙って作り替えない。

負荷判定では屋台追加前後の描画呼び出し、三角形、geometry数、フレーム時間、品質切替・再生成後の解放を測る。BV factoryのメッシュ数をそのままCEの描画呼び出し数として報告しない。非対応材質がprototype結合で脱落しないかも確認する。

人混み・家畜・荷車移動のシミュレーションは初回から必須にしない。まず売場、商品、在庫、運搬用具で市場を読める場面を作る。人物を追加するときは、売り手を台の内側、買い手を通路側へ置く静的な表現から始める。
