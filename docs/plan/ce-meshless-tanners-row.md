# メッシュなしCEのなめし職人の河岸（Tanners' Row）と給水・排水

作成: 2026-11-12
状態: T0・T1a・T1完了、T2は配置まで完了（[T0記録](../analytics/ce-meshless-tanners-row-t0-20261112.md)、[T2記録](../analytics/ce-meshless-tanners-row-t2-20261112.md)）。次はT2b（水路と護岸の描画）
対象: メッシュなしCE（`src/city-editor/generators/vector`）。メッシュありCEは対象外（道と川の間隔の調整が煩雑なため）。

## 1. 目的

施設モードのなめし場（`trade-workshop.dedicated-wet-tannery`）を、同じ区画を川辺に点在させる今の置き方から、町の川下に連続した一列の「なめし職人の河岸」としてまとめて置く方式に改める。各工房の給水口と排水口を川（または工房用の水路）へ実際につなぐ。

メッシュなしの川は今は直線に近いが、今後ベジェ曲線で曲がりを加える予定がある。曲がった川でも、四角い工房と水路が不自然にならない方法を定める。

## 2. 史実から CE への翻訳

| 史実 | CEの規則 |
|---|---|
| 原皮は地元の肉屋から出るため、どの都市にもなめし職人がいた。地域の中で一つの都市に集中したのは近世後期以降 | 工房数は今と同じく人口から求める（`medievalTradeDemand`）。地域の中での再配分はしない |
| 都市の中では、川下・市壁の外の一つの地区（Gerbergasse、Cowgate など）に固まった | 町に一つの連続した列として置く。工房を離れ離れの区画にしない |
| 工房は狭い間口と奥行きのある区画で、ピットは背面の水際に並んだ。発掘例は1区画に8基、地区全体で46基など | 背面を必ず水に接する。水に接しない2列目は作らない |
| 時間（漬け込み1年前後）が律速で、大規模化の利益がなかった | 工房1軒＝1区画を維持し、大きな1施設には統合しない |
| 川から分水した工房用の水路（Gewerbekanal、Gerbergraben。ストラスブールのPetite France、コルマール、バーゼルのSt. Alban-Teich など）に職人が並んだ | 川が曲がって並べにくい所では、まっすぐな水路を引いてそこへ並べる（§6） |
| 数軒ごとに川へ下りる公共の小路（Wassergasse、water lane）があった | 列の切れ目を水への小路にする |

## 3. 現状

- `populationFacilityRequests.ts`: なめし業は `dedicated-wet-tannery`（敷地18×16 m）を職人2.5人あたり1軒とし、`zone: "outskirts"`、`riverbankMaxDistanceMeters: 50` で要求する。
- `suburbs.ts`: 市壁を出た後の川から80 m以内を通る街道の帯を「川下の帯」とし、川沿いの作業場の長さだけ延ばす。住戸の不足分は割り当てない。
- `facilityLots.ts`: 水に近いロットから試し、入口をロットの前面の線（街道）へ向ける。次の点は扱っていない。
  - 背面（モデルの `-Z`、`waterSide`）を川へ向けること
  - 流れの向きと給水・排水口の順序の整合（`requiredExternalFlowDirectionXZ: [1, 0]`）
  - 水に接していること（50 m以内なら2列目でも通る）
- `DEDICATED_TANNERY.waterPorts`（`intake` x=-7.5、`effluent` x=+7.5、背面 z=-8）を読むコードはまだない（`externalConnectionVerified: false`）。
- `VectorPlacement` には位置と `facingDegrees` しかなく、鏡像の指定がない。レンダラーにも鏡像の処理はない。
- 結果として、街道の両側に同じ工房が点在し、間にロットの余りが残る。水から離れた2列目もできる（2026-11-12のスクリーンショット）。

## 4. 曲がった川で壊れるもの

1. **背面と岸の隙間**: 長さ L の直線の背面を半径 R の岸に当てると、中央と端の差（矢高）は s = L²/(8R) になる。18 mの工房1軒なら R=60 mで0.68 m、3軒並び（54 m）なら R=200 mで1.8 m、R=100 mで3.6 mになる。岸に合わせて区画を台形に切ると、四角いモデルが入らない。
2. **流れの向き**: 給水口を上流側、排水口を下流側に置くには、モデルの `+X` を下流方向へ向ける必要がある。背面を川に向けたまま `+X` を下流に合わせられるのは、岸の片側だけである。反対側の岸では鏡像が要る。
3. **水路の向き**: 曲がった岸へ工房の法線のまま水路を伸ばすと、水路の長さがそろわず斜めに岸へ当たる。

## 5. 方式A（既定）: 岸の直線区間に並べ、隙間を護岸で埋める

### 5.1 手順

1. **対象の岸**: `downstreamOf` と同じく、市壁を最後に出た後の川の区間で、川下の帯の街道がある側の岸線を1 m間隔で得る。川の点の順序が流れの向きである（`riverFlow.ts` で向きを合わせ済みの前提）。
2. **直線区間に分ける**: 上流端（防御クリアランスの外）から、次の条件を満たす最長の弦を貪欲に取る。
   - 弦を陸側へずらし、岸の点がすべて水側に来るようにする（弦が水に入らない）。
   - 弦と岸の最大の隙間が `APRON_MAX_METERS`（案: 2.0 m）以下。
   - 弦の長さが工房1軒の間口（18 m）以上。満たさない短い区間は「曲がり」として残す。
3. **工房を並べる**: 各直線区間に、間口18 mの工房を側壁を共有して `floor(L / 18)` 軒並べる。余りの長さは区間の端に寄せ、3 m以上なら水への小路にする。
4. **曲がりの扱い**: 区間の間にできるくさび形の土地には建てない。水への小路、または皮の乾燥場（物干し枠と空き地）にする。
5. **奥行きの確認**: 工房の前面（`+Z`）から街道の路肩までの距離を確かめる。前庭0〜6 mなら受け入れて前庭とする。足りない区間は使わない。広すぎる区間は、前面を街道へ寄せ、背面との間を護岸ではなく「作業場の裏庭」として区画に含める（裏庭が6 mを超えたらその区間は使わない）。
6. **向き**: 背面の法線を弦の水側の法線に、`+X` を弦の下流方向の接線に合わせる。両方を同時に満たせない岸では鏡像にする（§5.3）。
7. **護岸と水路**: 弦と岸の間の帯を護岸（木の杭と板、または石積み）の多角形として描く。給水・排水口からは弦に垂直な水路（幅0.6 m）を岸線まで伸ばす。水路の長さは、その位置の隙間（0〜2 m）である。隙間が2 m以下に抑えてあるため、川がどう曲がっていても水路は短く垂直になり、不自然にならない。

### 5.2 除外と間隔

- 橋の取付部、渡し場、水車、港の岸からは15 m（案）離す。
- 列は橋をまたがない。橋の手前で列を終える。
- 列の工房と水路は道と交差しない。交差が生じる区間は使わない。そのため `bridgeSkewPolicy` の判定が必要な新しい横断は生まれない。

### 5.3 鏡像

- **決定（2026-11-12）: 鏡像は配置データ側で持つ。** `VectorPlacement` に `mirrored?: boolean` を加える。2Dの敷地・足跡は X を反転し、3Dは `scale(-1, 1, 1)` で描いて面の向き（巻き順）を直す。BVの左右反転モデルは作らない。
- 鏡像の可否は岸の側で決まるので、乱数で反転はしない。

### 5.4 汚水の連鎖

上流の工房の排水口は、下流の工房の給水口より上流にある。史実でもなめし場の列はこの状態で、川下の町外れに置かれた理由そのものである。v1ではそのまま描く。

## 6. 方式B: 工房用水路（Gerbergraben）

### 6.1 使う条件

方式Aの結果が次のどれかに当たる時に方式Bへ切り替える（閾値は §8 のT0で計測してから決める）。

- 直線区間1つあたりの工房が平均2軒未満（曲がりで列が細切れになる）
- 曲がりのくさびに取られる長さが岸の長さの30%を超える
- 必要な工房数が、方式Aで並べられる数を上回る

### 6.2 形

- 川の上流側の点から分水し、街道と平行に一定の距離を保つ直線の水路を引き、下流側で川へ戻す。
  - 分水・合流の角度は流れに対して30〜45°にする。
  - 継ぎ目は半径15 m以上の3次ベジェでなめらかにつなぐ。
- 水路と街道の間の距離は「工房の奥行き16 m＋前庭」とする。工房はこの間に一列に並び、背面が水路に直接接する（護岸は不要で、水路の長さは0）。
- 水路の内側（水路と川の間）の土地は建てない。皮の乾燥場と牧草地にする。
- 水路は `VectorPath`（`role: "river"`、id `leat:tanners:<n>`、幅2〜3 m、`origin: "automatic"`、`editPolicy: "editable"`）として持つ。点の順序を川の流れに合わせる。

### 6.3 制約と影響

- 水路は道と交差させない。交差が避けられない場合は方式Bを使わず、方式Aの結果で止める（新しい橋の角度判定を持ち込まない）。
- 市壁の防御クリアランスと枠の外に出さない。長さの上限は400 m（案）。
- 既存処理での扱い:
  - `downstreamOf` と橋・渡しの生成では、堀（`moat`）と同じく `leat:` を除外する。
  - `waterDistance` と水面の描画では水として数える。
  - `validation/environment.ts` に、水路は両端が川に接すること、道と交差しないことの検査を加える。
- 将来の拡張: 中世の水路は水車と共用されることが多い。水路の分水口付近に水車（`milling`、同じく `riverbankMaxDistanceMeters: 50`）を置く余地を残す。

## 7. 置けない分の扱い

- 2列目は作らない。
- 列に入りきらない工房は、次の候補へ順に回す。
  1. 同じ川の対岸（川下に帯があれば）
  2. 別の川下の帯
  3. 方式B
- それでも残れば、今と同じく `unplaced` の理由 `"river"` で報告する。
- **決定（2026-11-12）: 地図の表示範囲の外にはみ出す分は問題にしない。** 川下の岸が地図の枠の外まで続き、列が枠で切れて置ききれない工房は、「枠の外に建っているが、CEの地図をなめし場のためだけには広げないので見えていない」と見なす。
  - CEの地図は都市を見せるためのものである。なめし場を置くためだけに、都市から離れた場所まで枠を広げることはしない（各都市から2 km離れた隔離施設を描くために、小さな町まで大きな地図にしないのと同じ）。
  - 枠で切れた分は、`unplaced` の理由を `"frame"` として `"river"` と区別する。診断の警告にも、T2の完了条件の失敗にも数えない。
  - 枠の中に岸があるのに置けない分（`"river"`）だけを不具合として扱う。

### 8.1 T1aの結果

- 職人数の基準（`occupations.csv` の tanning、人口1,000人あたり11人）は、出典E2の「tanners+curriers+tawers」をまとめた値である。curriers（仕上げ）とtawers（明礬なめし）は水辺の作業場を使わない。
- それでも、要求数を多くしていた主な原因は、1軒あたりの職人数が乾いた作業場と同じ2.5人だったことにある。湿式のなめし場は、モデルの3つの作業場所（石灰・樹皮の槽、肉削ぎ台、乾燥枠）にそれぞれ人が付き、親方が加わる。そこで `PRACTITIONERS_PER_FACILITY` に `tanning: 4` を加えた。
- 要求数は人口5,000人で22軒から14軒に、20,000人で88軒から55軒に減った。
- curriersとtawersを職人数から分けるかどうか（分ければ水辺の工房はさらに減る）は、出典の内訳が得られるまで据え置く。
- 試験の期待値（5,000人の施設要求258→250、小さな町の48→47）を更新した。

### 8.2 T1の結果

- `tannersRow(bank, landSide, options)` は、下流向きに並んだ岸線を受け取る。岸線を1 m間隔と元の頂点で取り直し、上流から貪欲に最長の弦を取る。弦は、岸が弦より陸側に出ないところまで陸側へずらし、護岸の幅が2 m以下の範囲で止める。
- 弦1本に間口18 mの工房を `floor(弦の長さ / 18)` 軒、中央に寄せて並べる。工房1軒に足りない区間は「曲がり」（`bendMeters`）として残す。
- 工房ごとに次の値を返す。
  - 位置と `facingDegrees`（前面を陸へ向ける。CEの配置と同じ向きの約束）
  - `mirrored`（給水口を上流に保つための左右反転）
  - 給水・排水の水路（背面の口から、弦に垂直に岸までの線と、その長さ）
- 試験（`tannersRow.test.ts`、5件）で次を確かめた。
  - 直線の岸では工房11軒が護岸なしで並ぶ。
  - 岸の左右で反転が入れ替わる。
  - R=60・150 mの曲がりとS字でも、護岸は2 m以下で、岸が弦より陸側に出ない。
  - 給水口はいつも上流にあり、水路は弦に垂直で2 m以下。
  - R=150 mでは1本の弦に2軒以上が並ぶ。

## 9. 未決事項

- 護岸の上限 `APRON_MAX_METERS`（2.0 m案）と、方式Bへ切り替える閾値。T0・T1の後に決める。
