# 都市周辺の開墾と森林: 史料調査と設計

状態: 設計のみ（未実装）。決定事項は末尾の「11. 決定事項」を参照。

## 1. 問題

都市セルが森林バイオームのとき、RE では都市が森林に完全に囲まれて描かれる。これは非現実的である。

### 原因

1. **FMG の `forestStock` は未開墾のまま初期化される。**
   - `initializeForestStock`（`generators/forestStock.ts`、`main.ts:1249`）は、全セルを `forestCover` の上限値で初期化する。都市セルも例外ではない。
   - 経済拡張 OFF では開墾処理が一切走らない。
2. **経済拡張 ON でも、開墾はセル単位のスカラー量だけである。**
   - `reconcileForestClearanceForAgriculture`（`agriculturalLandUse.ts`）が担当する。
   - 空間的な位置情報、種族、文化、技術、耕地以外の開墾（市街地、薪、街道、城壁前の視界）は考慮されていない。
3. **RE に渡す `RegionSiteCell` は `biomeName` と `polygon` だけを持つ。**
   - `forestCover`、`forestStock`、耕地面積、`cultureId`、`raceKey`、技術レベルは渡されない。
   - そのため RE は、森林バイオームのポリゴン全面を樹冠で塗る。
4. **RE の `farmland.ts` は人口あたり 0.5 ha で計算している。**
   - 経済拡張の `requiredFieldAreaHectares` は約 1.02 ha/人であり、両者が食い違っている。
   - 種族、文化、技術は参照していない。
5. **`svg.ts` の開墾マスク半径が固定である。**
   - 半径は capital 34、city 28、town 22、その他 17。種族に依存しない。

## 2. 史料調査

| 時代・出典 | 内容 | 設計への含意 | 信頼度 |
|---|---|---|---|
| ローマ・百分割地 (centuriation) | 20×20 actus ≈ 710 m の方格に、cardo と decumanus を通す。ager（耕地）、silva（森）、saltus（森林を含む管理地）に分ける。 | 都市周辺は計画的な方格の畑にする。森は畑の外側に置く。 | ◎ |
| ローマの木材・燃料需要 | 都市と鉱山の周囲が大きく伐採された。4〜5世紀以降に森は回復した。 | 都市規模に比例する薪の消費を、開墾量に加える。 | ◎ |
| ウィトルウィウス『建築十書』第1書 | 都市は健康、風向、水、木材と食料の供給を見て立地を選ぶ。 | 開けた肥沃地を優先する。 | ○ |
| タキトゥス『ゲルマニア』(98年頃) | ゲルマン人の集落は散在し、各家の周りに空き地を持つ。泉、草地、小森の近くに立地した。 | 小規模集落でも、周囲に必ず最小の空地をとる。 | ◎ |

| Chisholm の農業立地論 | 耕作は徒歩約 1 時間、4〜5 km 圏にとどまる。 | 耕地リングの最大半径の上限にする。 | ○ |

### 結論

- 集落と都市は、すでに開けた土地か、最初に開墾された土地に立つ。
- 森は、**耕地・草地・牧草地のリングの外側**にある。
- 森の手前には、管理された薪炭林が帯状にある。
- 街道には広い開けた帯がある。城壁の前には視界を確保した空地がある。

## 3. 設計方針

1. 既定は「開墾する文化」とする。
   - 森林セルの都市でも、森に囲まれた状態にしない。
2. 例外はエルフ系である。
   - 対象は `RaceKey` の `elf` と `dark_elf`。
   - 文化セットが `highFantasy` か `darkFantasy` のときだけ有効にする（`isFantasyCulturesSet`）。
   - エルフ都市は森に埋まって描く。開けるのは小さな林間空地、道、水辺だけにする。
3. 開墾量は**共有の純関数**で一元的に計算する。
   - FMG と RE が、それぞれ別の定数で計算することを避ける。
4. 開墾の所有者は 1 つにする（`frontier-expansion.md` で指摘済みの二重開墾の防止）。
   - 経済拡張 ON では `reconcileForestClearanceForAgriculture` が所有する。
   - OFF では、新設する事前開墾関数が所有する。

## 4. 起点: 共有純関数 `settlementClearance`

配置: `src/generators/settlementClearance.ts`（FMG 本体と RE ハンドシェイクの両方から呼べる純関数）

### 入力

- 人口（人）
- `initialPopulationSaturation`
- セルの `forestCover`
- 耕作可能上限（`getCroplandConstraints`）
- 年間降水量と取水可能量
- `raceKey`
- `culturesSet`
- 解放済み技術
- 街道の有無
- 城壁の有無

### 出力: 同心リングモデル

| リング | 内容 | 面積の決め方 |
|---|---|---|
| 0 | 市街地コア | `calculateBurgBuiltAreaHectares`（0.02 ha/人口ポイント） |
| 1 | 菜園・畑 | `requiredFieldAreaHectares`（約 1.02 ha/人）を、耕作可能上限、労働力、水の各制約で頭打ちにする |
| 2 | 草地・牧草地 | 畑の 30〜60% |
| 3 | 管理薪炭林（コピス、Stadtwald） | 薪の需要から算出する。ここは樹冠として描いてよい |
| 4 | 自然林 | 残り |

追加で、次の値も出力する。

- 街道の開けた帯の幅（約 60 m）
- 城壁の視界確保半径

### 補正

**1. 種族・文化: 新規の `forestAffinity`**

- `Race` に `forestAffinity` を追加する。値は `"embedded"` と `"clears"` の 2 種類。
- `elf` と `dark_elf` は、ファンタジー文化セットのときだけ `embedded` にする。
  - `embedded` の場合、開墾量の倍率は 0〜0.1 とする。
  - リング 0 だけ小さな空地として開ける。
- それ以外は `clears` とする。

**2. 技術: 開墾能力の倍率**

- `threeFieldAgriculture`、`ironToolsAndDraftAnimals`、`fourCourseRotation` などで倍率を掛ける。
- 低技術でも下限を設け、中核は必ず開ける。
  - 下限の目安は、リング 0 と、リング 1 の 30%。
  - 開墾が難しい分は、リング 1 の半径が小さくなる形で表現する。「森に囲まれる」状態にはしない。
- 未確認事項: 解放済み技術を国や文化単位で取得するアクセサがまだ見つかっていない。

**3. Initial population %**

- 係数は `saturation/100` である。
  - 100 のときは、セルが支えられる最大人口の食料生産を想定して、全量を開墾する。
  - 30 のときは 30% とする。
  - 下限は上記の中核部分。
- `initialPopulationCohorts.ts` の `startingPopulationScaleOfK`（上限 0.6）と整合させる。

## 5. 経済拡張 ON/OFF の対応表

| | OFF | ON |
|---|---|---|
| 開墾の所有者 | 新設の `applyInitialSettlementClearance`。`initializeForestStock` の直前に呼び、都市セルの `forestStock` を減らす。 | `reconcileForestClearanceForAgriculture` を拡張する。 |
| 拡張内容 | 純関数のリング 0〜2 を、セルの `forestStock` に反映する。 | 同じ純関数を呼び、種族、技術、市街地、薪、街道の各項を追加する。 |
| 年次更新 | なし（静的）。 | `updateAnnualAgriculture` で継続する。 |
| 特例 | なし。 | megacity モードは都市の食料需要を開墾から除外する現行仕様を維持する。 |

どちらの場合も、RE は FMG が書き出したセルの値を読む。RE 側で再計算しない。

## 6. 記述子の拡張

- `RegionSiteCell` と `RegionSiteDescriptor` に、次の項目を追加する。
  - `forestCover`
  - `forestStock`
  - `clearedFraction`
  - `cultivatedAreaHa`
- 都市（集落）側には、次の項目を追加する。
  - `cultureId`
  - `raceKey`
  - `forestAffinity`
  - `clearanceProfile`（リング半径、街道帯幅）
- ハンドシェイク（`region-editor-handshake.ts`）で、上記を設定する。
- 既存の `annualPrecipitationMm` と `population`（人数）は維持する。

## 7. RE 側の変更

1. `farmland.ts` の 0.5 ha/人を廃止し、FMG の値（`cultivatedAreaHa`、リング半径）を使う。
2. `svg.ts` の開墾マスク半径を、データ駆動にする。
   - リング 0〜2 を、空地として樹冠から切り抜く。
   - リング 3 は薪炭林として、樹冠を薄く残す。
   - 街道の帯幅は、約 60 m を基準にする。
3. エルフ都市（`embedded`）は、樹冠を都市の近くまで残す。小さな林間空地だけを開ける。
4. 畑は、街道と河川に沿った短冊状（Waldhufendorf 型）か、方格（百分割地型）で並べる。
5. 河川を渡る橋は、河川の進行方向に対して直角、かつ最短で渡る（AGENTS.md の原則）。畑や空地を追加しても、この規則は変えない。

## 9. テスト

- 純関数の単体テスト
  - elf と human で結果が違うこと。
  - saturation が 30 のときと 100 のときで結果が違うこと。
  - 低技術と高技術で結果が違うこと。
  - どの場合も、リング 0 が必ず開いていること。
- 経済拡張 ON と OFF で、都市セルの開墾済み割合が大きく乖離しないこと（整合性テスト）。
- RE の描画テスト
  - human の都市は、リング 0〜2 が樹冠で覆われていないこと。
  - エルフの都市は、樹冠が都市の近くまで残っていること。
- 実行は `npx vitest run src/region-editor` で行う。
