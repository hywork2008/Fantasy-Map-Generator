# メッシュなしCE M9 受入と公開判断

2026-11-07。設計元は[メッシュなしCE設計](ce-meshless-city-editor.md)。M9の検証・改善・公開判断を完了し、公開区分は**試験運用の継続**とする。既存CEを既定方式として維持し、保存済み都市を自動移行しない。

## 判断の基準

M0の16機能群を[受入対応表](data/ce-meshless-m9-coverage.json)で管理する。`verified`は代表入力における契約を確認したもの、`limited`は機能基盤はあるが旧CEとの完全な同等性や規模への制約が残るもの。外観の一致だけで判定せず、入力・所有権・接続・寸法・容量・保存を比較する。

正式移行には以下が必要である。

- 対応表の制約を解消し、機能維持の必要条件を満たすこと。
- 実現可能な代表都市で合意した人口・施設目標を満たし、用地不足時は不足を明示すること。
- 型検査と本番bundleがともに成功すること。
- 生成時間の暫定目標は固定ケース当たり10秒以内とする。Workerの60秒取消上限は安全な実行境界であり、快適さの目標とは別に扱う。
- 曲線の位置誤差はM0の5mm上限を維持し、門・橋・接道・固定入力の参照を保持すること。

計測は少数の固定入力を使う。同じseedの500人・1,000人・5,000人、保存済み6文書、独立したベジェ式による4,097点を対象とした。多数seed探索や全件テストは行わない。数値目標の達成を、未計測の都市規模・地形・全ハードウェアへ一般化しない。

## 今回の判定

| 項目 | 結果 |

| 生成と取消 | 初期骨格・施設住宅もWorker化。設定変更・別履歴・取消・終了後の遅延結果を破棄。候補の3D確認や出力操作は採用候補を取り消さない |

11機能群を代表ケースで確認し、5機能群を制約付きとした。よって試験運用は継続できるが、全面移行・既定方式の変更は承認しない。これはM9の未実行ではなく、検証結果に基づく公開判断である。

## 再実行と証拠

```sh
node --import tsx scripts/city-editor/meshless/m9Acceptance.ts --out docs/analytics/raw/m9-new-observation.json
```

出力先が既に存在する場合は上書きしない。明示実行時のみ性能受入テストを有効にし、通常のVitestでは重い計測をskipする。計測順に共有cacheが温まる可能性がある単回測定であり、統計的な性能保証ではない。
