# 生産の賃金を生活費の尺度にそろえる (Craft Wage Subsistence Scale) 設計

2026-10-18 設計。[money-scale-calibration.md](money-scale-calibration.md) §8.3 の残課題(都市の家計が食費の 2〜3 割しか払えない)の対応。

## 状態

- 実装済み(2026-10-18)。`WAGE_SUBSISTENCE_MULTIPLE = 1.5` のまま。計測では都市の食費は改善せず、別の制約が見つかった(§8)。

## 1. 問題

### 1.1 賃金が実人数の生活費の 1/36

- 生産の賃金は `production-generator.ts` の `wageBill = laborUsed × wageRate` で、都市の家計に入る。
- `laborUsed` は労働点。`laborPointsForLots()`(`craftDemandCalibration.ts`)は既定の `populationRate`(1,000)での人口点で数えるので、**労働点 1 = 1,000 人・月**。
- `wageRate` は `getManufactureWageRate()`(`strategicLaborMarkets.ts`)。
  - 戦略職種(林業・帆・綱・タール)は `good.value × 需要倍率`(約 1 SP)。
  - その他の工芸は林業の賃金を流用する。
  - 労働市場が無い市場は 0。
- 1 人・月あたりにすると 0.001 SP、年 0.012 SP。1 人の年間の食費(`GROSS_FOOD_NEED` 0.43 × 約 1 SP)の 1/36 にしかならない。
- 計測(K=16、seed 101・102・103、5〜15 年目)では、生産の賃金は都市の家計の収入の 1% 前後だった。都市の家計は払える分しか食べない(`drawBurgMonthlyNeed`)ので、都市の食費は必要量の 2〜3 割にとどまる。

### 1.2 価格の側は実人数の尺度で、そろっている

- 商品 1 ロットの価格(`Good.value`)と、1 ロットに必要な労働(`laborPointsPerLotAtDefaultRate`、人・月の実数)は、どちらも実在の量から作られている。
- 賃金を生活費の 1.5 倍(1 人・月 0.054 SP、労働点 1 あたり月 54 SP)にすると、ロットの価格に占める賃金の割合は次のようになる。

| 割合 | 商品 |
| :--- | :--- |
| 100% 超 | Garments 262%、Lime 109% |
| 50〜100% | Cloth 93%、Sails 73% |
| 20〜50% | Bullets、Roman Concrete、Lab Glassware、Harnesses、Glass |
| 20% 未満 | Liquor、Boots、Paper、Arms、Ink、Books、Arrows、Leather、Ropes、Bronze、Barrels、Tools、Ceramics |

- 中央値は約 15%。前近代の手工業として妥当な範囲にある。
- **ずれているのは賃金の尺度だけ**で、価格と労働量には手を入れない。100% を超える 2 品目は §4 で扱う。

## 2. 方針

賃金の基準を、地元の穀物の小売価格で測った生活費にする。

```text
生活賃金(労働点 1・月あたり) = WAGE_SUBSISTENCE_MULTIPLE × GROSS_FOOD_NEED × 1000 / 12 × 地元の穀物の小売価格
                              ≈ 1.5 × 0.43 × 1000 / 12 × 約 1 SP ≈ 54 SP
```

- 生活費 × 倍率で決まるので、§3 の区分 G(量 × 価格)にあたる。通貨量の係数 K は掛けない。
- 1,000 は `DEFAULT_PEOPLE_PER_POPULATION_POINT`。労働点は `populationRate` によらず 1,000 人・月なので、`populationRate` を変えても 1 人あたりの賃金は変わらない。
- `WAGE_SUBSISTENCE_MULTIPLE` は 1.5 から始め、§6 の計測で 1.2〜2.0 の範囲で決める。目安は、労働者 1 人で家族 1.5 人分の食費をまかなえる程度。
- 穀物の小売価格は Food Ledger の値(`market.goods[主食]` の価格)を使う。不作で穀物が値上がりすると賃金も上がり、生産の費用が上がる。

## 3. 変更

1. `strategicLaborMarkets.ts` に `getSubsistenceWage(market)` を追加する。
2. `getManufactureWageRate()` の基準を、林業の賃金から `getSubsistenceWage()` に変える。
   - 戦略職種は `生活賃金 × 需要倍率` とする。`good.value` は使わない。
   - 労働市場が無い場合は 0 のまま(テストと経済拡張が無効な経路だけ。実際の市場には生産の周期ごとに労働市場が作られる)。
3. 生産の量は、既存の予算の上限(`costPerLot = 材料費 + 賃金`、都市の金庫で払える量まで)がそのまま抑える。賃金の割合が高い商品から生産が止まる。
4. `money-scale-calibration.md` §8.1 の「掛けなかったもの」に、生産の賃金(生活費の尺度)を追記する。

## 4. 賃金の割合が 100% を超える商品

- **Garments(262%)**: 1 ロットに 972 人・月かかる。ロットの単位が大きすぎるか、労働量の見積もり(紡ぎ・織り・縫製の合算)が過大な可能性がある。
- **Lime(109%)**: 焼成の燃料と運搬が労働に含まれている可能性がある。
- この 2 品目は、生産が止まるかどうかを §6 の計測で確かめる。止まった場合は、`craft-demand-calibration.md` の根拠を見直して労働量を直す(価格は変えない)。
- 賃金の割合を一律で頭打ちにする処理は入れない。根拠のずれを隠してしまうため。

## 5. 実装の順序

1. `getSubsistenceWage()` を実装し、`getManufactureWageRate()` の基準を差し替える。
2. 関連する単体テストを直す(`strategicLaborMarkets.test.ts`、`production-generator` の賃金の検証)。
3. §6 で計測し、`WAGE_SUBSISTENCE_MULTIPLE` を決める。
4. 結果を本書 §7 に記録する。

## 6. 計測

- 地図は [money-scale-calibration.md](money-scale-calibration.md) と同じ K=16 の seed 101・102・103(15 年)。
- `NODE_OPTIONS=--max-old-space-size=1024` を付け、1 本ずつ実行する。`--sample-every-months 3` とする。

| 指標 | 目標 |
| :--- | :--- |
| 都市の食費 / 必要量 | 7 割以上 |
| 都市の家計の収入に占める生産の賃金 | 2 割以上 |
| 都市の金庫が 0 の都市の割合 | 現状から大きく増えない |
| 品目別の生産量 | Garments・Lime 以外が大きく減らない |
| 通貨量(年間食費の何か月分か) | 3〜6 か月を保つ |

## 7. 注意

- 賃金は都市の金庫から都市の家計への移転で、お金は生まれない。
- 都市の家計が増える分、`spendUrbanHouseholdSurplus`(手元の現金のうち一定額を超えた分を町で使う処理)で都市の金庫に戻る流れも増える。
- 国の軍需工場(`getStateMilitaryManufacturingFund`)も同じ賃金を払うので、国庫の支出が増える。

## 8. 実施結果(2026-10-18)

- `subsistenceWage.ts`(`getSubsistenceWage`)を追加し、`getManufactureWageRate()` は生活賃金 × 職種の指数を返す。`wageByOccupation` は需要倍率そのもの(指数)になった。
- 計測(K=16、seed 101・102・103、15 年、5〜15 年目、3 か月ごとの標本):

| 指標 | 変更前 | 変更後 | 目標 |
| :--- | :--- | :--- | :--- |
| 都市の家計の収入に占める生産の賃金 | 0〜2% | 5〜11% | 2 割以上 |
| 都市の食費 / 必要量(地元の穀物価格で換算) | — | 2〜13% | 7 割以上 |
| 金庫が 0 の都市 | 82〜96% | 80〜98% | 大きく増えない |
| 通貨量(年間食費の何か月分か) | 2.4〜4.2 | 2.2〜4.2 | 3〜6 |

- 変更前の都市の食費は、穀物価格を 1 と仮定した計算(20〜24%)で、変更後と直接は比べられない。
- **賃金を上げても都市の食費は増えなかった。** 原因は 3 つ:
  1. **都市の金庫が空**: 8〜10 割の都市で金庫が 0。生産は「材料費 + 賃金」を金庫で払える分しか行わないので、賃金を払う生産そのものが起きない。
  2. **都市の現金が一部の都市に偏る**: 1 か月分の食費以上の現金を持つ都市の人口は 15〜23%。国の給与は首都を 3 倍に重み付けして配り(`CAPITAL_PAYROLL_WEIGHT`)、人物の生活費も居住都市に落ちる。この都市では手元の現金が一定額を超え、超えた分を町で使う(`spendUrbanHouseholdSurplus`、年 3.5 万)。残りの都市は現金がなく食料を買えない。
  3. **穀物そのものが足りない市場がある**: 多くの市場で穀物の小売価格が上限の 2.0 に張り付いている。お金があっても買える量が限られる。
- 次の一手は、金庫が空になる原因(都市の金庫から国庫への流れ)と、国の給与・人物の支出が首都に偏る配分の見直し。賃金の倍率の較正は、その後に行う。

## 9. 追加の是正(2026-10-18)

- **人頭税から K を外した**: 人頭税の税率(人口点・月あたり 0.3〜0.6)は、実人数 1 人あたりで年間食費の約 1.7% にあたり、もともと妥当な水準だった。K を掛けると 27% になり、農村の現金を国庫が吸い上げていた(開始後 2 年で農村の家計が 1/4 に減った)。`taxes-generator.ts` の `pollTaxRatePerHead` は K を掛けない。
- **農家が町でお金を使う**: `spendRuralHouseholdsInTowns()`(`householdWealth.ts`)。市場の農村の財布から毎月 5%(`RURAL_HOUSEHOLD_TOWN_SPEND_SHARE`)を、その市場の町の金庫へ人口比で入れる。塩・道具・布・鍛冶・粉挽き・市の代金にあたる。これまで農村のお金は人頭税にしか出ていかず、町が食料に払ったお金が町に戻らなかった。

| 指標(5〜15 年目) | seed 101 | 102 | 103 |
| :--- | ---: | ---: | ---: |
| 金庫が 0 の都市 | 0%(89%) | 0%(80%) | 2%(98%) |
| 都市の家計の収入に占める生産の賃金 | 36%(11%) | 35%(11%) | 69%(5%) |
| 都市の食費 / 必要量 | 29%(13%) | 20%(11%) | 28%(2%) |
| 通貨量(年間食費の何か月分か) | 3.5 | 2.6 | 4.7 |
| 国庫の割合(通貨量のうち) | 53% | 62% | 72% |
| 農村の家計の年変化 | −2.8% | −9.7% | −2.3% |
| 穀物価格が上限 2.0 近くの市場 | 61% | 80% | 61% |

(括弧内は §8 の賃金の変更だけの値)

- 都市の家計は 3〜4 か月分の食費の現金を持つようになったが、食費は必要量の 2〜3 割のまま。6〜8 割の市場で穀物価格が上限に張り付いており、**お金ではなく穀物の量が足りない**。市場に出る穀物(農村の余剰の買い取り・市場間の穀物輸送)の調査は、お金の較正とは別に扱う。
- `WAGE_SUBSISTENCE_MULTIPLE` は 1.5 のまま。食料の量の問題が残る間は、倍率を変えても都市の食費は変わらない。
