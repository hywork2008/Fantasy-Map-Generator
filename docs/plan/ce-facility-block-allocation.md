# CE施設の街区内配置と住宅不足の補填

更新: 2026-11-06。作業ブランチ: `feature/ce-guild-hall-2`。開始点: developの`4e3f953f2`。

## 目的

[目標値](medieval-urban-calibration-targets.md)の人口別必要施設数を使い、既存の建物を配置できる街区へBVモデルの実測敷地を割り当てる。配置後の居住容量が人口に必要な戸数に不足するときだけ、市街地コア相当のセルを増やす。

既存の建物配置のみの生成方法を維持し、施設を含む生成を別のオプションにする。施設は都市生成の一部として配置し、生成後の追加ボタンを必須にしない。モデルがない施設は必要面積の仮表示を使い、モデルの完成を配置検証の前提にしない。

旧ブランチの計画A・BのCE配置エンジンは移植しない。既存BVモデル、目標値、人口から必要数を計算する純粋関数、モデル検証に必要な固定資料だけを再利用する。

## 配置の手順

1. 建築可能な街区から、道路・小路・交差点・水面・保護対象などを除いた部分を候補にする。
2. BVモデルの実測寸法をメートルのまま使い、敷地全体が入る候補を選ぶ。小路をまたいで置かず、縮小して押し込まない。
3. 既存の井戸・ランドマークで使っている接続処理で、入口から近くの小路・道路へ短い通路を伸ばす。小路の迂回、元の網の保存、迂回の巻き戻しは追加しない。
4. 既存の住宅生成処理に敷地と接続通路を予約地として渡し、残った建物の居住容量を再計算する。通常建物との間に施設専用の一律な空地は設けない。
5. 必要戸数と残存容量との差だけを住宅不足とし、既存の面積調整処理に接続してコアを拡張する。減った建物の全棟数を住宅不足と扱わない。

人口別必要数、都市内・郊外・川辺の条件と面積が確認できることを優先する。敷地が見つからない施設は未配置として報告し、不正な敷地で数だけ満たさない。

通常生成への接続は完了。住宅不足時のコア拡張は作業3が残っている。探索は実寸敷地が入る中心位置の範囲を街区の境界から求め、その範囲内で入口接続を1施設256回まで試す。すべての幾何学的な配置可能性を探索するものではない。

## 2026-11-06の実装・確認

- `generators/bvFacilityAsset.ts`: 選択したBV品質の実測外接寸法・高さと入口から敷地を作る。
- `generators/allocateBVFacilities.ts`: 既存街区への割当と、配置前後の居住容量・不足戸数を返す。作業2で都市内／郊外に加え、川岸からの最大距離条件を接続。
- 保存の所有者は既存のランドマークだけ。BVの描画要素はそこから導出し、別々の配置台帳を同期しない。
- 街区を横断する小路があって実寸敷地が入らない場合の拒否、小路沿いの配置・入口接続、住宅再計算と小路の維持、保存・3Dの単一描画をテスト。
- 固定入力では建物346棟→338棟、居住容量61戸→61戸。失われた建物がそのまま失われた住宅とは限らないため、補填は棟数ではなく必要戸数との差で決める。
- 関連Vitest: 配置・人口需要・既存ランドマーク・3Dの5ファイル、およびBVモデル8ファイル117件が成功。型検査は変更外の既存エラー2件（`charts-overview.ts:560`、`approachPrior.ts:259`）で失敗。アーキテクチャ検査成功。実画面での一連の生成確認は未実施。

### 作業2の実装結果

- 「建物の生成」に「中世の敷地＋人口に応じた施設」を追加。従来の2方式を維持し、FMG由来の都市でも選択可能。施設付き方式は人口の指定が必要。街路完成後、住宅容量の調整前に施設を配置する。
- `generators/populationFacilities.ts`が目標値CSVと人口から必要数を計算。作成済み会館・住居兼工房・パン・鍛冶・樽・なめし場と、既存の醸造所・陶工・印刷工房を実測寸法で配置する。対応モデルのない職種は寸法の出典を「仮」と明示した敷地を使用する。
- 都市内は会館・住居兼工房など、郊外は鍛冶・樽・危険工程など。なめし場・水車用地は郊外かつ川岸から50 m以内。これは配置確認用の距離条件であり、取排水や水車の作動確認ではない。仮の標準敷地は10×12 m、縄場は5×60 m、窯業は20×20 m。BVに対応付けた際は実測寸法へ置き換える。
- 最初の固定例は53施設中8施設だった。建物中心を順に試す探索を、施設が収まる中心位置の範囲を求める処理に変更して49施設に改善。道路・小路を迂回する処理は追加していない。
- 1,000人・川なしの固定例で49施設を配置し、なめし場4施設を`river-required`で未配置と報告。人口1,000人の住宅は充足。別の固定街区で郊外・川辺25 m以内の配置を確認。
- 5,000人の必要数は工房285＋会館9＝294施設、うち住居兼工房155戸。これは必要数とモデル対応の確認で、5,000人都市への全配置を確認した結果ではない。
- 住居兼工房の1戸を既存の住宅容量報告へ加算。再生成時には自動施設を作り直す。従来方式への切り替えで残留しないこと、ネイティブ保存・レシピ再現・共有URLで方式を保持することを確認。
- `facilityReport`に必要数・配置数・仮敷地数・配置面積・地域条件・未配置理由を保存。「建物の生成」の下にも集計を表示し、未配置の詳細はツールチップで確認できる。
- 生成層からサービス層へ依存しないよう、前回の敷地割当・BV実測・純粋な需要計算を`generators`へ移動。
- 検証: 関連7ファイル38件成功。追加の川辺正例1件・共有1件成功。既存モデル追加後の通常生成・共有・3D関連2ファイル26件成功。型検査は変更外の既存2エラーのみ。実ブラウザでの新しい選択肢の操作確認は未実施。
