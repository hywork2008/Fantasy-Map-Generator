## 0. 結論

Japan テンプレートの地図は、地図ピクセルと経緯度が一次式で対応する（`mapPointToLonLat`、正距円筒）。戦場の窓を経緯度に戻せば、セル標高（約21km間隔）ではなく実在DEMを窓の中だけ読める。セル内の起伏を作り出す必要はない。

- 窓の既定は「中心から徒歩3日」（半幅84km、一辺約170km）。2〜4日で調整する。
- 都道府県GeoJSONは、DEMを焼く単位（都道府県ごとのタイル束）と、調整用の試験地点の位置合わせに使う。地図の境界線としては既定で出さない（戦国期には無い線）。
- DEMは解像度の段（2km、1km、500m、250m、100m）を持ち、窓の中心ほど細かい段を読む同心LODにする。どの段まで要るかは、試験地点の見た目と負荷を測って決める。最初から仕様を固定しない。
- 調整の第一歩は新規データ無しで行う。既存の `japan.bin`（0.02°、約2km）を窓の高さ関数に差すだけで、今の双線形（約5km間隔で21kmセルを補間）との差が見られる。

## 1. いまの状態

| 項目 | 値・場所 |
| :--- | :--- |
| Japan 領域 | 118.5–146.4°E、29.9–46.6°N。`mapSize` 7.75、中心緯度38.25°（`JAPAN_REGION`） |
| セル間隔 | 既定の点数で約21km（`earthRegionHeightmap.ts` のコメント）。面積はおおよそ 2,440km × 1,850km |
| 生成時の標高 | `japan.bin`。Terrarium z7 を 0.02° 格子で取り直した int16。経度方向約1.75km、緯度方向約2.2km。3.7MB |
| セル標高 | `fromEarthRegion` がセル中心で `japan.bin` を読み、`metersToHeight` で 0–100 に落とす |
| 窓 | `campaignWindow`。既定 `CAMPAIGN_FOOT_DAYS` 7、`FOOT_SPEED_KM_PER_DAY` 28 |
| 窓の地面 | `buildCampaignMesh` の `heightAt` 注入。`ThreeDRenderer.sampleTerrainHeight`（`cells.h` の双線形）を渡している |
| 間隔 | `max(格子間隔/4, 2km)`（`CAMPAIGN_MIN_STEP_KM`）、1辺最大200点（`CAMPAIGN_MAX_SAMPLES_PER_SIDE`）。Japan では約5km |

`heightAt` が注入されているので、窓の地面は高さ関数を差し替えるだけで変わる。差し替え口はこの1か所に限る。

[`war-campaign-mesh.md`](./war-campaign-mesh.md) は「セルより細かい標高は作らない」「20mの地形を補間で捏造しない」と決めている。本設計は捏造ではなく実測DEMを読むので、その方針と矛盾しない。ただし、地理参照のある Earth 領域の地図に限る例外として扱う。

## 2. 窓の広さ

戦国期の行軍は1日20〜30kmを目安とし、既存の28km/日をそのまま使う。

| 徒歩日数 | 半幅 | 一辺 | Japan のセル数（一辺） |
| :--- | :--- | :--- | :--- |
| 2日 | 56km | 112km | 約5 |
| 3日（初期値） | 84km | 168km | 約8 |
| 4日 | 112km | 224km | 約11 |
| 7日（現行） | 196km | 392km | 約19 |

Japan の地理参照があるときだけ、`footDays` の既定を3にする。他のテンプレートは7のまま。日数はUIで選べるようにして、調整の結果で既定を決め直す。

## 3. 一様格子の負荷見積もり

一辺168km（徒歩3日）の窓を一様格子にした場合。三角形は頂点の約2倍。

| 間隔 | 1辺の点数 | 頂点数 | 窓のDEM（int16、陸海とも） |
| :--- | :--- | :--- | :--- |
| 5km（現行相当） | 34 | 1,200 | — |
| 2km（`japan.bin`） | 85 | 7,200 | 既存 |
| 1km | 169 | 28,600 | 57KB |
| 500m | 337 | 114,000 | 227KB |
| 250m | 673 | 453,000 | 0.9MB |
| 100m | 1,681 | 2,830,000 | 5.7MB |

250mより細かい段を窓全体に敷くのは、Mac mini（16GB）で常用するには重いと見込む。そのため、中心だけを細かくする同心LODを本命にする。初期案は次のとおりで、数値はすべて調整対象である。

| 環 | 範囲（中心から） | 間隔 | 頂点数の目安 |
| :--- | :--- | :--- | :--- |
| 接敵 | 半幅15km | 100m | 90,000 |
| 戦域 | 半幅40km | 250m | 約92,000（内側を除く） |
| 作戦 | 窓全体（半幅84km） | 1km | 約22,000（内側を除く） |
| 合計 | | | 約20万 |

環のつなぎ目は、外側の辺の点を内側の環も持つ（T字の継ぎ目を作らない）か、スカートで隠す。どちらを使うかは R2 で見た目を比べて決める。

## 4. データ

### 4.1 標高の出典

| 出典 | 解像度 | 使いどころ | 注意 |
| :--- | :--- | :--- | :--- |
| AWS Terrain Tiles（Terrarium） | z7で約1km、z10で約120m、z12で約30m（日本付近） | 既存の焼き込みと同じ経路。初期の全段 | 日本の陸域はSRTM系。谷底の細部は粗い |
| 国土地理院 標高タイル（DEM10B） | z14で約10m | 接敵の環（100m）の既定 | 公共データ利用規約（第1.0版）。出典を記載する（Encyclopedia `feature:data-sources`）。PNG標高タイルの符号化は Terrarium と別 |

最初は Terrarium だけで全段を作る。地理院タイルは R3 で、接敵の環の見た目が Terrarium で足りないと分かった場合にだけ足す。

### 4.2 都道府県GeoJSON

| 出典 | 内容 | 使い方 |
| :--- | :--- | :--- |
| Natural Earth 10m admin-1（パブリックドメイン） | 都道府県の多角形（海岸は粗い） | 初版。既存の admin-0 と同じ系列なので出典の扱いが揃う |
| 国土数値情報 行政区域（N03） | 市区町村単位の精密な境界 | 必要になったときの後続。サイズと出典表記を確認してから使う |

GeoJSON の役目は三つだけにする。

1. **焼く単位**。都道府県ごとの外接矩形に、海岸の誤差を見込んで陸側へ数kmのバッファを足し、その範囲のDEMタイルを `pref-<code>` の束にする。窓が交わる都道府県の束だけを読む。
2. **陸だけを保存する**。束の中で、バッファ付き多角形の外にあるタイルは保存しない（海は0mの平面で描く）。
3. **試験地点の位置合わせ**。下の §6 の地点が、どの束に入っているかを確かめる。

地図の上の国境（FMGの国家・州）とは結び付けない。FMGの州は生成物であり、都道府県とは一致しない。3Dに都道府県界を重ねる表示は、調整時の目印として開発用のオプションに留める。

入力のGeoJSONは `temp/`（Git管理外）に置き、焼き込みスクリプトの冒頭で SHA-256 を出力する。

### 4.3 焼き込みの出力

`scripts/bakeJapanLocalDem.mjs`（新規）。段ごとに、0.25°四方のタイル（int16、NODATA -32768、FMGE と同じヘッダ系列の v2）を都道府県の束にまとめる。

| 段 | 日本の陸域全体の目安 | 置き場所 |
| :--- | :--- | :--- |
| 1km | 約0.8MB | `public/heightmaps/earth/japan-local/` |
| 500m | 約3MB | 同上 |
| 250m | 約12MB | 調整が終わるまでは `temp/japan-local/`。採用時に置き場所を決める |
| 100m | 約76MB | `temp/japan-local/` のみ。コミットしない |

陸域は約37.8万km²として計算した（海の分を含めない）。250m以上の細かい段をリポジトリに入れるか、別配布にするか、必要な都道府県だけにするかは、R4 の結論で決める。

## 5. ランタイム

### 5.1 地理参照の保存

窓を経緯度に戻すには、地図が Japan テンプレートから作られたことと、その bbox が要る。現状、`template` はオプションのストアにはあるが、`.map` の保存に入るかは未確認である。R0 で確かめ、入っていなければ `worldContext.options` に `earthRegion: { id, west, east, south, north }` を保存する。

地理参照が無いとき、または R0 の整合チェックが落ちたときは、今の双線形のまま描く。

**整合チェック**。窓の中の格子点（`grid.points`。パックセルではない。R0 参照）について、その点で読んだDEMを `encodeEarthCellHeight` で 0–100 に落とし、`cells.h` と比べる。ずれたセルの割合がしきい値（初期値10%）を超えたら、標高を手で編集した地図とみなして実DEMを使わない。

### 5.2 高さ関数

`localTerrainSampler(region, levels)` を新設し、`metersAt(mapX, mapY, stepMeters)` を返す。

1. 地図ピクセルを `mapPointToLonLat` で経緯度にする。
2. `stepMeters` 以下で最も粗い段のタイルを双線形で読む。その段がまだ読み込まれていなければ一段粗い段で代用し、読み込みが終わったら環を作り直す。
3. 海（DEM ≤ 0 かつパックセルが水面）は0m。

`buildCampaignMesh` に渡す `heightAt` は、`metersAt` をワールドYへ変換したものにする。

**垂直スケール**。今の世界メッシュは、指数100（`heightToMeters(100)` ≈ 2,785m）が3Dスライダの `scale` になる。窓の地面を同じ変換に乗せると、水平（`kmPerPx`）との比が地図ごとに変わる。局地窓は「水平と同じ縮尺 × 誇張率」に替える。

```text
worldY = meters / (kmPerPx * 1000) * exaggeration
```

誇張率の初期値は2。1〜3で調整する。川・街道・連隊・境界線も同じ `heightAt` で地表に載せる（`buildPolylines`、`buildMarkers` は既にそれを呼んでいる）。

### 5.3 LODメッシュ

`buildGround` を一様格子から環の列に一般化し、`CAMPAIGN_MAX_SAMPLES_PER_SIDE` は環ごとに適用する。視点を動かしたときに環を動かすかは、まず「窓を開いたとき1回だけ作る」で測り、R2 で必要と分かったら追う。

色は今のとおり、パックセルの頂点色（国家色・バイオーム色）。陰影は法線から出す。テクスチャを焼かない方針（`war-campaign-mesh.md`）は維持する。

### 5.4 シミュとの食い違い

実DEMを描くと、21kmセルから作ったシミュの地物と食い違う。どれも初版で直し切らない。R5 で量を測り、目立つものから手当てする。

| 食い違い | 例 | 手当ての候補 |
| :--- | :--- | :--- |
| 河川 | FMGの川は `cells.h` から流れを作っており、実在の谷を通らない。実DEMの上では尾根を越える | 川の折れ線に沿って幅数百mの廊下を掘り、下流ほど低くする。廊下の掘り下げ量を測る |
| 海岸 | セルの水陸は21km単位。実際の海岸線とは最大で半セル（約10km）ずれる | 局地窓では実DEMの海岸を描き、海上に来た街・連隊は表示だけ最寄りの陸へ寄せる |
| 都市 | 街のセル中心が実DEMの山腹や峰に当たる | 街の周りの半径（初期値1.5km）を、中心の標高で平らにする |
| 街道 | 峠を越える経路が実DEMの稜線を直登する | 初版はそのまま載せる。勾配の上限を測り、超えた区間を数える |

`cells.h`、河川、経路、戦闘解決は変えない。食い違いは、表示側の掘り下げ・平坦化・寄せで吸収する。

## 6. 調整の進め方

一度で正解を決めず、ラウンドごとに測って次の値を決める。各ラウンドの結果は `docs/analytics/japan-local-terrain-<日付>.md` に記録する。スクリーンショットなど大きな出力は `docs/analytics/raw/` に置き、記録には SHA-256 だけを書く。

### 6.1 試験地点

地形の見え方が異なる地点を固定する。座標は概略で、R0 で地図ピクセルへ戻して確かめる。

| 地点 | 経緯度（概略） | 見たいもの |
| :--- | :--- | :--- |
| 関ヶ原 | 35.37°N, 136.47°E | 盆地と、周囲の山（松尾山・南宮山など、比高200〜300m） |
| 川中島 | 36.60°N, 138.19°E | 千曲川と犀川の合流する平地と、妻女山などの山 |
| 長篠・設楽原 | 34.92°N, 137.55°E | 狭い谷と川沿いの台地 |
| 桶狭間 | 35.06°N, 136.99°E | 低い丘陵の起伏（比高数十m） |
| 厳島 | 34.28°N, 132.32°E | 島と海峡（海岸の扱いの確認） |

桶狭間の丘陵が見えるかが、最も細かい段の要否の目安になる。

### 6.2 測る値

| 値 | 測り方 | 目安（初期値。R1で見直す） |
| :--- | :--- | :--- |
| 頂点数・三角形数 | ビルドの戻り値 | — |
| 構築時間 | `buildCampaignMesh` の前後 | 500ms以下 |
| フレーム時間 | 作戦カメラ・接敵カメラで各10秒 | 16ms以下（Mac mini） |
| メモリ | ジオメトリのバイト数とDEMキャッシュ | 窓1つで100MB以下 |
| 読み込み量 | 窓が読むタイルの合計 | 窓1つで5MB以下 |
| 見た目 | 地点ごとの固定カメラ2枚（作戦・接敵）を並べて比べる | §6.1 の「見たいもの」が見えるか |

見た目は数値にしない。同じカメラの画像を段ごとに並べ、ユーザーが選ぶ。

### 6.3 ラウンド

| ラウンド | 内容 | 決めること |
| :--- | :--- | :--- |
| R0 前提 | 地理参照が保存に入るか確認。整合チェック。試験地点を地図ピクセルへ。現行（双線形、徒歩7日）の画像と数値 | 基準値と、地理参照の保存の要否 |

| R2 一様格子 | Terrarium で1km・500m・250mを焼き、窓全体に一様に敷く | 見た目が頭打ちになる間隔と、負荷が目安を超える間隔 |
| R3 LOD | 同心の環。環の半径と間隔、継ぎ目の方式 | 本命のLOD構成 |
| R4 最細段 | 接敵の環に100m（Terrarium z10〜11）。足りなければ地理院10mと比べる | 最も細かい段とその出典、配布方法 |
| R5 食い違い | 河川の廊下、都市の平坦化、海岸の寄せを入れ、量を測る | 手当ての既定値 |

R1 の結果で R2 以降の範囲を縮めてよい。たとえば作戦カメラは2kmで十分と分かれば、R2 は接敵の環だけを測る。

### 6.4 調整用の口

開発中は、次の値をURLのクエリか開発用パネルで変えられるようにする（本番UIには出さない）。

```text
footDays, exaggeration, rings=[{halfKm, stepM}], seam=skirt|shared,
source=cells|japanBin|terrarium|gsi, riverCorridorM, burgPadKm, showPrefBorders
```

Playwright で、§6.1 の地点ごとに作戦・接敵の固定カメラを開いて撮るスクリプトを用意し、同じ設定の画像を並べられるようにする。

## 7. 実装順

1. R0。地理参照の確認と整合チェック。試験地点を地図ピクセルへ。現行の基準画像。
2. `localTerrainSampler` と `japan.bin` 経路、局地窓の垂直スケール、調整用の口。R1。
3. `scripts/bakeJapanLocalDem.mjs`。都道府県GeoJSONの取得、Terrarium の段、都道府県束。R2。
4. `buildGround` の環への一般化。R3。
5. 最細段と出典の比較。R4。
6. 河川の廊下・都市の平坦化・海岸の寄せ。R5。
7. 既定値の確定と、本設計・`war-campaign-mesh.md`・`public/heightmaps/earth/README.md` の更新。R6。

テストは、地図ピクセルから経緯度への往復、環の継ぎ目で隣の環と高さが一致すること、地理参照が無いときと整合チェックに落ちたときに双線形へ戻ることに絞る。

## 8. やらないこと

- `cells.h` を実DEMで細かくしない。セル数を増やさない。
- 河川・経路・行軍・戦闘解決を実DEMに合わせて作り直さない。
- 日本全域の100m以下の段をリポジトリに入れない。
- 本番のランタイムで外部のタイルサーバーを読まない。焼き込み時だけ取得する。
- 都道府県をFMGの州や国家に割り当てない。
- Japan 以外の Earth 領域へ広げるのは、R6 の後にする（同じ仕組みで足りるはず）。
- CEやREの高さ場は変えない。

## 9. R0 の結果（2026-11-17）

- `.map` は `options.template` を保存しない（`save.ts` の settings に無い）。`worldContext.options` は JSON で丸ごと保存されるので、`WorldOptions.earthRegion`（id・bbox・生成時のグラフ寸法）を足した。`HeightmapGenerator.defineHeightmap` が Earth 領域のとき設定し、それ以外と Islet スコープでは消す。この変更より前に作った地図は地理参照を持たず、双線形のまま描く。
- 座標変換と整合チェックは `src/utils/localTerrainGeoref.ts`（`georefMapToLonLat`、`georefLonLatToMap`、`georefConsistency`、試験地点 `JAPAN_LOCAL_TERRAIN_SITES`）。変換は生成器の `mapPointToLonLat` と一致する。
- `japan.bin`（約2km）で試験地点の起伏を読んだ。単位はm。

| 地点 | 中心 | 半径5km（最低–最高） | 半径15km | 半径84km（徒歩3日の窓） |
| :--- | :--- | :--- | :--- | :--- |
| 関ヶ原 | 136 | 54–759 | 0–1044 | 海–2197 |
| 川中島 | 348 | 341–803 | 324–1491 | 海–2976 |
| 長篠 | 60 | 29–593 | 海–734 | 海–2906 |
| 桶狭間 | 46 | 1–54 | 海–289 | 海–2895 |
| 厳島 | 43 | 海–245 | 海–821 | 海–1835 |

- 関ヶ原・川中島・長篠は、2kmの段でも半径5km内に数百mの比高がある。R1（`japan.bin` を差す）だけで、今の約21kmセルの補間とは見た目が大きく変わる見込み。桶狭間は半径5km内の比高が約50mで、2kmでは平地に近い。最細段の要否は桶狭間で判断する。

## 10. R1 の結果（2026-11-17）

記録: [`../analytics/japan-local-terrain-20261117.md`](../analytics/japan-local-terrain-20261117.md)。

## 11. R2 の結果（2026-11-17）

記録: [`../analytics/japan-local-terrain-20261117.md`](../analytics/japan-local-terrain-20261117.md)。

- 実装：`scripts/bakeJapanLocalDem.mjs`。§4.3 の0.25°タイルの代わりに、R2 では段ごとに1枚の FMGE ラスタ（`japan.bin` と同じ形式）で選んだ県の外接矩形を覆う。標高は県の多角形を3km膨らませた範囲だけ持ち、外は NODATA。出力と `manifest.json` は Git 管理外の `public/heightmaps/earth/japan-local/`（調整中のため）。タイル分割は、配布の形を決める R4 で行う。
- ランタイム：`source=dem` のとき、地面の間隔以下で最も粗い段を読み、NODATA なら他の段、最後に `japan.bin` に落ちる（`demLevelOrder`）。`maxSamplesPerSide`（既定1200）で、窓の1辺の頂点上限を DEM のときだけ200から上げる。開発ビルドでは `window.__fmgLocalTerrain` から調整値を変えられる。撮影は `scripts/japanLocalTerrainHarness.js`（Playwright MCP の `browser_run_code_unsafe` に渡す）。
- 5県で1km 0.2MB、500m 0.9MB、250m 3.5MB。§4.3 の陸域全体の見積もりと矛盾しない。
- 一辺168kmの窓に一様に敷くと、250mで約45万頂点・ジオメトリ27MB・描き直し約0.5秒、表示は60fps。500mは約11万頂点・0.15秒。
- 見た目は250mが最もよい。関ヶ原の盆地と周りの山、善光寺平と谷筋が読める。桶狭間の丘陵は250m×5で初めて読める。

## 13. R4 の結果（2026-11-17）

記録: [`../analytics/japan-local-terrain-20261117.md`](../analytics/japan-local-terrain-20261117.md)。

- 愛知・岐阜・長野で100m（Terrarium z12）を焼いた（2.2〜5.8MB/県）。接敵の環（半幅6km）に100mを足すと約16.9万頂点・描き直し約0.22秒。
- 桶狭間の丘陵は100m×5で初めて形になる。川中島の平地と縁の尾根、関ヶ原の盆地を囲む尾根と谷筋も100mで描き分けられる。250mまでは「作戦の地形」、100mは「接敵の地形」と位置付けられる。
- 既定は R3 の D（100mなし）のまま。100mの環は、カメラが接敵の高さに下りたときだけ足す（R5 で実装）。
- 地理院 DEM10B との比較は行っていない。利用規約（出典の表示、加工の扱い）をユーザーが確認してから行う。Terrarium z12 では、尾根の形はすでに十分出ており、モアレも100mの段では目立たない。
- 配布の目安（全国）：1km と500m は合わせて約10MBで、県ごとのタイルにすればリポジトリに入れられる。250m（約30MB）と100m（約160MB）は、県ごとの別配布かオンデマンド取得にする。いまの「束ごとに外接矩形1枚」は陸だけの量の2〜3倍なので、全国化の前に0.25°タイルへ分ける（§4.3）。

## 14. R5 の結果（2026-11-17）

記録: [`../analytics/japan-local-terrain-20261117.md`](../analytics/japan-local-terrain-20261117.md)。

- 標高タイルの出典：国土地理院 標高タイルは公共データ利用規約（第1.0版）で、出典の記載で使える（ユーザー確認済み）。出典とライセンスは Encyclopedia の `feature:data-sources`（地理データの出典とライセンス）にまとめた。焼き込みは `--source gsi`。100mでは GSI が Terrarium より細かく縞も無いので、同じ段では GSI を優先する（`demSource`）。
- §5.4 の手当てを実装した（`createLocalTerrainField`）。海岸は段の陸ビット、都市は半径1.5kmの平坦化、駒は海と陸の正しい側へ表示だけ移す、川は上がらない断面で廊下を掘る。
- 河川は根本的に食い違う。FMG の川の標本の約4割が30m以上の尾根を横切る。掘る深さを30mで頭打ちにし、峡谷を作らない。
- 接敵の環はカメラ距離で自動に切り替える（25km未満で入り、40km超で出る）。駒とラベルはカメラ距離に比例した大きさにした。
- 描き直しは0.26〜0.30秒（R3 より約0.1秒増）。主に河川の標本読み。
