## 0. 結論

セルの危険度は、怪物の足し算でも、どの怪物の中心も 255 になる相対減衰でもなく、**レアリティごとの頂点を、距離で二乗減衰させ、セルでは最大値を採る**。

0〜255 は居住と領土の圧力だけを表す。255 はレアリティ 5 の中心だけが取る。レアリティ 1 と 2 の中心は 80 未満で、人は住める。レアリティ 3 以上の中心は 80 以上で、今の適合式がそこを無人にする。

死因は、このバイトを読まない。同じ再計算で、そのセルを半径がまだ覆っている怪物の**いちばん高いレアリティ**を別に持つ。脅威の死は、後の設計がそれを読む。

## 1. 今の算出

この節は、この式を入れる前の塗りである。入ったあとの式は §3 以降である。

既定の `threatCalculation` は `nonlinear` である（`optionsStore`、`threatProfiles.ts`）。`rebuildDangerFromMonsters` は、生きている怪物ごとに幅優先で隣へ進み、`remaining = max(0, power - dist)` を使う。

| モード | セルへの書き方 | 中心 |
| :--- | :--- | :--- |
| `nonlinear`（既定） | `max( round(255 * (remaining / power)^2) )` | どのレアリティも 255 |
| `max` | `max( remaining * 5 )`、上限 255 | `power * 5`。災厄 50 なら 250 |
| `additive` | 合計 `remaining * 4`、上限 255 | 災厄単独は 200。弱い密集が 255 になる |

`power` はホップ半径である。既定では強さの差は半径だけで、中心の数値は揃う。獣（`power` 5）の中心も災厄（`power` 50）の中心も 255 で、適合は 80 以上を 0 にするので、獣の周囲約 2 ホップも無人になる。

[table-background.md](table-background.md) と [danger-layer.md](../danger-layer.md) が「レアリティ 5 は 255 に届かず、弱い密集が 255 になる」と書いたのは、`additive` の説明である。既定のモードはそれとは別の崩れ方をしている。どちらも、一つの数値が「どれだけ住みにくいか」と「何が居るか」を同時に表せない。

獣害は怪物のあとに足す。`applyBiomePredatorDanger` は、足すセルについて合計を 79 で切る。

```typescript
cells.danger[id] = Math.min(STATE_EXPAND_DANGER_BAN - 1, cells.danger[id] + add);
```

森や山のセルに怪物の 255 があると、獣害が 1 でも 79 まで落ちる。コメントは「獣害だけでは併合禁止に届かせない」と読める。実装は合計を切るので、怪物の頂点を獣害が消す。テストは `power` 2 の獣（`max` で中心 10）しか見ていない。

消費側は次のとおりである。

| 読み手 | 見ているもの |
| :--- | :--- |
| `dangerSuitabilityMultiplier` | 0 で 1、80 以上で 0 の直線。生成時の `rankCells` と定住の基礎 |
| 領土の拡大 | 80 以上は主張できない。未満は 1 点あたり費用 30 |
| `classifyWildLand` | 25 未満は辺境、25〜79 は縁、80 以上は怪物の領域 |
| ヒートマップ | 0〜255 の色 |
| 討伐の再計算 | 怪物の `power` を変えたあと、フィールドを描き直す |
| 怪物ノートの死亡推計 | 失われた適合の 20% を死者として文に書く |
| 仕事板の `estimateLocalDangerDrop` | `powerReduced * 4` を診断値にする |

年次の生態は危険度を描き直す。保存済みの人口を、毎年この式で掛け直してはいない。

## 3. 一つの式

`additive` / `max` / `nonlinear` は廃止する。保存された `threatCalculation` は読み捨てる。Danger の設定からこの選択を外す。`highFantasy` と `darkFantasy` のプロファイルは、モードを既定値として書き込まない。

怪物一つがセルに与える値は次である。`dist` は隣接グラフのホップである。頂点の固定点は、水面で切らないグラフで測る。陸が水面を越えないこと、空が越えること、水棲が岸の 1 ホップで止まることは [monster-nature.md](monster-nature.md) が決め、頂点の式は変えない。

```typescript
const RARITY_DANGER_PEAK = [0, 48, 72, 140, 200, 255] as const;

function rarityPeak(rarity: number): number {
  if (rarity >= 5) return 255;
  if (rarity <= 0) return 0;
  return RARITY_DANGER_PEAK[rarity] ?? 0;
}

function monsterContribution(rarity: number, power: number, dist: number): number {
  if (power <= 0 || dist >= power) return 0;
  const remaining = power - dist;
  return Math.round(rarityPeak(rarity) * (remaining / power) ** 2);
}
```

セルの怪物分は、そのセルを覆う貢献の最大値である。足さない。`power <= 0` の個体は源にしない。

頂点の意味は、今の閾値に合わせたものである。

| レアリティ | 中心 | 適合（式は不変） | 無人の領域（80 以上） | 荒野の区分 |
| :--- | ---: | :--- | :--- | :--- |
| 1 獣 | 48 | 0.40 | 無い | 縁（25 以上）。深林より薄い |
| 2 強獣 | 72 | 0.10 | 無い | 縁。深林より濃い |
| 3 上位 | 140 | 0 | 中心から数ホップ | 怪物の領域 |
| 4 大獣 | 200 | 0 | より広い | 怪物の領域 |
| 5 災厄 | 255 | 0 | 広い。255 はここだけ | 怪物の領域 |

既定の `power` で、80 以上になるホップは次のとおりである。実装の固定点にする。

| 個体 | まだ無人 | 人が住める内側 |
| :--- | :--- | :--- |
| レアリティ 1、`power` 5 | 無し。中心 48、1 ホップ 31、2 ホップ 17 | 中心から |
| レアリティ 3、`power` 14（highFantasy） | 0〜3 ホップ（3 ホップは 86） | 4 ホップは 71 |
| レアリティ 3、`power` 20 | 0〜4 ホップ（4 ホップは 90） | 5 ホップは 79 |
| レアリティ 5、`power` 50 | 0〜22 ホップ（22 ホップは 80） | 23 ホップは 74 |

災厄の無人半径は、今の `nonlinear`（頂点 255）と同じである。変わるのは、獣と強獣が無人の穴を開けなくなることと、上位以上の中心だけが 80 を超えることである。弱い個体を何体重ねても、中心は 48 を超えない。

負傷で `power` が減ると、半径が縮む。頂点はレアリティのままである。傷ついた災厄の残りの円は、まだ中心 255 である。`power` が 0 になり個体が消えたとき、その源は塗らない。

## 4. 獣害との合成

獣害の出し方（バイオーム、深林の深さ、統治地で半減、害獣抑え）は今のままである。深林の上限 65 と、獣害だけでは 80 に届かない、も今のままである。

合成は足し算にしない。

```typescript
cells.danger[id] = Math.max(monsterDanger, predatorDanger);
```

合計を 79 で切らない。森の中の災厄は 255 のままである。獣害だけのセルは 80 未満のままである。

深林の 65 は、獣の中心 48 より濃い。そのセルの色は深林が勝つ。強獣の 72 は深林より濃い。獣の存在は、次節のレアリティで残す。色の濃さでは、深林に埋もれてよい。

## 5. 覆っているいちばん高いレアリティ

バイトの最大値を出した個体を、死因の正体にしない。災厄の肩（例: 30 ホップで約 41）に獣の中心 48 が乗ると、バイトは獣が勝つ。ここを獣の土地として死を計算すると、災厄が消える。

再計算のとき、バイトと別に `threatRarity`（0〜5 のセル配列）を書く。

- そのセルを `dist < power` で覆う生きた怪物（ダンジョンのボス源を含む）の、最大のレアリティ。
- 覆う怪物が無いときは 0。獣害だけでは上がらない。
- バイトが深林の 65 で、獣の貢献 48 より大きくても、獣が覆っていれば 1 である。災厄の半径内なら 5 である。

古い保存にこの配列が無いときは 0 として読む。ロードで危険度のバイトを換算しない。次の再計算まで、両方とも保存されたままである。

町の摘要が「いちばん近い怪物の名前」を出すのは、今どおり怪物の一覧から距離で探す。`threatRarity` は近い個体のレアリティではない。

## 6. 討伐は power を変えてから、一度だけ描く

危険度と `threatRarity` は、生きている源と獣害層だけの関数である。源は地図上の怪物と、ダンジョンのボス源である。

討伐は個体の `power` を減らし、消すときは源から外し、そのあとで一度だけ描き直す。`estimateLocalDangerDrop`（`powerReduced * 4`）を、同じ年のバイトからさらに引かない。診断値が要るときは、描き直す前と後の差を使う。係数 4 は、廃止する `additive` の名残である。

軍と冒険者が同じ年に同じ個体を削る資格は、本書では変えない。削った結果の `power` から一度描く、までを本書の規則とする。危険度の差分を二本のパイプラインがそれぞれ引く、は採らない。

## 7. 居住と保存

適合の関数は動かさない。新しく生成するファンタジーの地図では、入力が変わる。

- レアリティ 1〜2 の周囲は、今の `nonlinear` より人が住める。獣のたびに半径 2 ホップの無人はできない。
- レアリティ 3 以上の中心は、今どおり無人である。災厄の無人半径は、上の表のとおり今の `nonlinear` と同じである。
- 脅威モード `none` は、怪物を置かず、獣害の倍率も 0 である。危険度は 0、`threatRarity` も 0 である。標準の地図の人口は、この式では動かない。

保存した地図は、ロード時に `rankCells` をやり直さない。年次の再計算は、主張と荒野の区分が読むバイトを更新する。既にいる人口を、この再計算で掛け直さない。

怪物ノートが、失われた適合の 20% を死者数として書く処理は外す。住まなくなった人数を、死んだ人数にしない。代わりの死者数は、本書では書かない。

## 8. 死因へ渡すもの

[table-background.md](table-background.md) の年率は、まだ実装しない。後の設計が読んでよいのは、`threatRarity`、その個体までのホップ、適合を掛けたあともそのセルに残る成人、である。

読んでならないのは、`danger / 255` と、失われた適合の割合である。

レアリティ 5 の半径に人がいるときの死は、年率ではない。数日で少なくとも数万から数十万人、という規模を受けられる事象である。人数と日数は [cr-distribution.md](cr-distribution.md) に置いた。実装はまだである。レアリティ 3 以上の中心は適合が 0 なので、毎年の滴下にはしない。人がまだいる肩と、個体が現れたときの事象だけが死を持ちうる。

レアリティ 1〜2 は人が住める。ここだけの小さい年率も、同じ文書に置いた。48 や 72 には比例させない。

[danger-layer.md](../danger-layer.md) の CR 帯は、[cr-distribution.md](cr-distribution.md) が確定した。頂点の表へは換算しない。

## 9. 採用しない読み

- 三つのモードを残し、既定だけ変える。同じ地図が設定で別の順位になる。
- バイトをレアリティの段に量子化し、距離減衰をやめる。半径は `power` のまま要る。
- 獣害を怪物の頂点に足してから 79 で切る。旧実装の不具合である。
- 貢献が最大の個体を、死因のレアリティにする。災厄の肩が獣に負ける。
- ロード時に、古い 0〜255 を新しい頂点へ写す。古い合計に、新しい順位は無い。
- この式の実装で、脅威の死の年率、CR の一覧、セル収量、適合の係数を一緒に変える。

## 10. 実装するときの確認

固定点は `src/generators/dangerField.test.ts` と `src/generators/dangerExpandPolicy.test.ts` で見ている。地図全体の多シード検証はしていない。

- レアリティ 1、`power` 5 の単独は、中心 48、1 ホップ 31、2 ホップ 17。255 にならない。適合の倍率は 0 より大きい。
- 同じ獣を何体重ねても、セルは 48 を超えない。
- レアリティ 5、`power` 50 の中心は 255。22 ホップは 80、23 ホップは 74。
- レアリティ 3、`power` 20 は、4 ホップ 90、5 ホップ 79。`power` 14 は、3 ホップ 86、4 ホップ 71。
- 森のセルに災厄の 255 があり獣害が乗っても、79 に落ちない。獣害だけの深林は 80 未満である。
- 災厄の肩でバイトが獣の 48 に負けても、`threatRarity` は 5 である。怪物が無い深林は 0 である。
- 脅威モード `none` は、危険度も `threatRarity` も 0 である。
- 同じ源で二度描くと、バイトもレアリティも一致する。`power` を減らしたあとの一度の描き直しは、減らしたあとの半径と一致し、`powerReduced * 4` をさらに引いた値にはならない。
- `dangerSuitabilityMultiplier(80)` は 0 のまま、`dangerSuitabilityMultiplier(40)` は 0.5 のままである。
