# 11. 検証・テスト

v2 の核心は「中世らしさ」を検証可能にすることである。メトリクスは `src/validation/metrics.ts` に実装し、**(a) Vitest のテスト、(b) HUD の常時表示、(c) 生成直後の console 警告** の 3 箇所から同じ実装を使う。

## 1. 構造妥当性メトリクス

| ID | メトリクス | 合格基準 | 検証対象の原則 |
|----|-----------|---------|--------------|
| M1 | フロンテージ率: 建物可敷地のうち接道スパンを持つ割合 | ≥ 0.98 | 「すべての敷地は道に面する」 |
| M2 | 敷地縦横比（奥行/間口）の中央値 | ∈ [2, 5]（壁内 organic 地区） | バーゲージ・プロット |
| M3 | 間口分布 | P10 ≥ 3 m, P90 ≤ 15 m | 同上 |
| M4 | 幹線の曲がり: 頂点あたり方向変化 | 最大 ≤ 40°, 平均 ≤ 12° | 連続した緩いカーブ |
| M5 | T字路率: 壁内交差点のうち次数 3 の割合 | ∈ [0.6, 0.85] | 有機的成長パターン |
| M6 | 街区面積分布 | ∈ [300 m², 1.2 ha]（壁内、プレシンクト除く） | 街区スケール |
| M7 | 凹街区率: 壁内街区のうち凹多角形の割合 | ≥ 0.2（organic モード） | 凸限定の禁止 |
| M8 | 建物直角率: 内角が 90°±5° の割合 | ≥ 0.95 | 建材の制約 |
| M9 | 建物の接道整合: 主屋前面と接道スパンの角度差 | ≤ 4°（95 パーセンタイル） | フロンテージ原則 |
| M10 | 道路網連結性 | 単一連結成分。全門⇔広場が到達可能 | 動線 |
| M11 | 密度勾配: 建蔽率の壁内/壁外近傍/耕地帯の比 | おおよそ 1 : 0.3 : 0.05（±50%） | 城壁による断絶 |
| M12 | 越境ゼロ: 建物×道路空間・建物×プレシンクト・敷地相互の重なり | 0 件 | 幾何整合 |
| M13 | 門の数と位置 | = numGates、全て幹線上 | 城壁ロジック |
| M14 | 生成時間 | 中都市 < 1.5 s | 性能予算 |

しきい値の変更は本表を更新し、変更理由をコミットメッセージに記録した場合のみ許可（[01-goals.md](01-goals.md) 禁止事項）。

### 必須帯と目標帯

史実レビュー（[14](14-historical-morphology-review.md)）に基づき、次のように読む:

| 帯 | メトリクス | 意味 |
|----|-----------|------|
| **必須** | M1, M8, M9, M10, M12（運河プリセット時は C2 も） | 不合格 = 形態原則の破綻。リリース阻止 |
| **目標** | M4, M5, M6, M7, M11, M13 | 不合格でも即史実破綻とは限らない。要調査・要プロファイル調整 |

### 地域プリセット時の上書き

`regionPreset` が `northWestBurgage` 以外のとき、M2・M3・M5 の合格帯は [15-region-presets.md](15-region-presets.md) §5 の表で上書きする。新メトリクス C1（中庭率）・C2（運河越境）・C3（主軸直交）も同書を参照。

## 2. テスト戦略

| 種別 | 対象 | 内容 |
|------|------|------|
| 単体テスト | `core/geometry`, `core/graph`, `core/curves`, `core/grid` | 面抽出（三角形・井桁・行き止まり・8の字）、inset、クリップ、A* の既知ケース |
| ステージ契約テスト | 各 generation ステージ | 固定シード数種で [03-pipeline.md](03-pipeline.md) の不変条件を検証 |
| プロパティテスト | パイプライン全体 | ランダムシード 20 個 × 全サイズ × 全アーキタイプで M1–M13 が全合格。**例外を投げず生成が完走する**こと自体も検証項目 |
| スナップショットテスト | `generateCity` | 固定シードの CityModel ハッシュが不変（決定論）。意図的変更時のみ更新 |
| 性能テスト | `generateCity` | M14 |

CI 相当として `npm test` に全部を含める。プロパティテストが重い場合は `npm run test:full` に分離し、マイルストーン完了判定では必ず full を実行する。

## 3. 目視チェックリスト（参照都市との突き合わせ）

メトリクスで測れない「絵の説得力」は、マイルストーンごとに以下を目視確認し、結果を PR/コミットに記録する:

- [ ] 幹線が門から広場へ「一本の道」として目で追える（ローテンブルク）
- [ ] 通り沿いに妻壁（三角破風）が律動的に並ぶ（ブルージュ）
- [ ] 路地が細く不規則で、行き止まりがある（ヨーク The Shambles）
- [ ] 等高線に沿って道が巻いている(hillTop)（シエナ）
- [ ] 壁の内外で密度が断絶し、壁外に耕地短冊が広がる（カルカソンヌ）
- [ ] 川の蛇行に市街が抱かれている(riverCrossing)（チェスキー・クルムロフ）
- [ ] 大聖堂・城がスカイラインで際立つ
- [ ] 広場が「道の膨らみ」として自然に街路網に繋がっている
- [ ] 三角地に隙間（空地）が残っており、無理な充填がない
- [ ] 遠目に見てボロノイ的な「泡」の印象がない

## 4. リグレッション運用

- 「良い」と合意したシード（golden seeds）を 5 個選び、そのスクリーンショットを `docs/plan/golden/` に保存する。生成ロジック変更時は同シードで再生成して並べ、劣化がないか目視比較する。
- メトリクス値も golden seeds について JSON で保存し、±10% 超の変動はテスト失敗として検知する。
