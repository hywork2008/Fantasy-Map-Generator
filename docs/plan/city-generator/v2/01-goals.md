# 01. 背景・目的・設計原則

## 1. 背景

初期実装はボロノイ分割（トップダウン）で都市を生成したが、`docs/current.md` が指摘する通り、中世都市の構造と根本的に矛盾する（バーゲージ・プロットを作れない、道がジグザグになる、街区が凸多角形に限られる、計画都市グリッドを表現できない）。

その後 street-first 方式（道を生成し `turf.polygonize` で街区を抽出）へ部分的に移行したが、現行実装には以下の問題が残っている。

### 現行実装の具体的な問題点

1. **道路がランダムウォーク**（`src/generation/streets.ts`）: 角度をランダムに揺らして伸ばすだけで、目的地（門・広場・橋）へ向かう動線になっていない。`_terrainField` を引数に受け取りながら **未使用** で、地形をまったく反映しない。
2. **道路がセグメントの寄せ集め**: `Street` が 2 点のセグメント単位で、連続したポリラインに統合されていない。ランク別の道幅の概念も実質なく、スムージングもない。
3. **街区抽出が脆い**: `turf.polygonize` に丸投げしており、非ノード化された線分・微小ポリゴン・スナップの副作用で壊れる。隣接判定も「重心距離 < radius×0.3 なら交差判定」というヒューリスティック。
4. **フロンテージの保証がない**: 敷地分割（`lots.ts` の peelLots）は方向性は正しいが、「すべての敷地が道路に面する」ことを検証する仕組みがなく、道路に面しない敷地・建物が生成され得る。
5. **脆い分岐だらけの施設配置**: `cityModel.ts` は「plaza 地区の街区が存在しなければ地下構造をすべて諦める」など、前段の偶然の出力に依存した分岐が多い。
6. **妥当性を測る仕組みが皆無**: 「それっぽく見えるか」を人間の目視でしか判定できず、リグレッションに気づけない。
7. **ボロノイ時代の残滓**: `numWards`（ボロノイセル数）などの意味を失ったパラメータが残っている。

## 2. 目的

**史実の中世ヨーロッパ都市の形態的特徴を、定量的に検証可能な形で再現するランダム都市生成アプリを作る。**

「それっぽい」の判定を人間の主観からメトリクス（[11-validation.md](11-validation.md)）に移すことが、v1 との最大の違いである。

### 再現すべき形態的特徴（ゴール）

- 地形（川・丘）に沿って曲がる、**連続した緩いカーブの幹線道路**
- 門と広場を結ぶ動線としての道路網、**T字路支配**の街路パターン
- **バーゲージ・プロット**: 通りに直角な細長い短冊状敷地の連なり
- 通りにゼロセットバックで面する**直角・四角形ベースの建物**、共有壁の町家列
- 凹多角形・三日月型を含む**自然な街区形状**
- **城壁による密度の断絶**: 壁内は密、壁外は街道沿いのリボン状郊外と耕地
- 市場広場・教会・城などの**ランドマークを核とした構造**
- オプションで**バスティード（計画都市グリッド）**モード
- **村落（農村）モード**: 城壁を持たない小集落 — 教会 + 緑地（green）を核に、街道沿いのリボン集落または広場村。周囲は耕地。都市と同じパイプラインの縮退形として生成する（[12-roadmap.md](12-roadmap.md) M10、詳細 [16-compact-village.md](16-compact-village.md)）。長期的には **人口を一次入力**とし開拓村（~10 人）から市場村・城壁都市へ帯を拡張する（16 §1.5）。**経済・人口シミュレーション自体は非ゴール**（人数→形態予算の写像に限る）
- **FMG 立地入力への適合**: Fantasy Map Generator が出力する立地サーベイ（川の弦位置・流向・実幅、街道の進入方位、海岸線、マクロ標高）を入力に取り、**地図上の地形にぴったりはまる**街を生成できること（[13-fmg-site-input.md](13-fmg-site-input.md)）

参照都市: ローテンブルク、シエナ、ブルージュ、ヨーク、カルカソンヌ、チェスキー・クルムロフ（`docs/bottom-up.md` §4）。

### 史実スコープ

- **既定**は北西ヨーロッパ城壁市の形態制約モデルである（短冊敷地・門–市場動線・壁内外密度など）。全中世ヨーロッパの平均再現ではない。
- 地中海中庭型・運河都市・ローマ格子残存型などは `regionPreset` で切り替える（[15-region-presets.md](15-region-presets.md)）。
- 史実妥当性のレビュー: [14-historical-morphology-review.md](14-historical-morphology-review.md)。

### 非ゴール

- 写実的 3D レンダリング（2.5D 押し出し表示で十分）
- 経済・人口シミュレーション
- 実在都市の GIS 再現
- 街の時系列成長アニメーション（内部的に成長プロセスを使うのは可）

## 3. 設計原則

実装上の判断に迷ったら、以下の原則に立ち返ること。

1. **道が先、建物が後（ボトムアップ）**: 空間を分割して道を引くのではなく、動線として道を引き、道が囲んだ場所が街区になる。
2. **すべての敷地は道に面する**: フロンテージのない敷地は存在してはならない。分割の結果生じた袋地は建物を建てず庭・空き地にする。
3. **建材の制約 = 直角・四角形**: 建物は矩形の組み合わせ。隣接辺は直角。斜めの組み合わせはしない。
4. **地形が形を決める**: 道は等高線と川を尊重する。地形入力を無視するコードは書かない。
5. **不完全さの許容**: 数学的に完璧な充填より、隙間・歪み・不揃いが中世らしさを作る。三角地の余りは埋めない。
6. **決定論**: `generateCity(params)` は純関数。同一シードは常に同一の都市を返す。
7. **段階的解像度**: 骨格 → 道路 → 街区 → 敷地 → 建物の順で解像度を上げる。各ステージは単体で描画・検証できる。
8. **検証されない生成は存在しないのと同じ**: 各ステージは不変条件（invariant)を持ち、メトリクスとテストで守る。

## 4. 禁止事項（アンチパターン）

以下は理由の如何を問わず導入してはならない。コードレビュー時の却下基準とする。

| 禁止事項 | 理由 |
|---------|------|
| ボロノイ図による街区・敷地・地区境界の生成 | `docs/current.md` の通り構造的に不整合。v1 失敗の根本原因 |
| ランダムウォークによる道路生成 | 動線にならず、ジグザグで連続性を失う |
| 街区を凸多角形に限定・凸化する処理 | 実際の街区は凹多角形が普通 |
| フロンテージ検証なしの敷地への建物配置 | 道に面しない家という致命的な嘘を生む |
| 道路方向と無関係な向きの建物 | フロンテージ原則違反。±数度の揺らぎのみ許容 |
| 三角地・端数空間の無理な充填 | 隙間は正しい。埋めると不自然になる |
| ステージ間の暗黙依存（「たまたま plaza があるから動く」等） | 脆い。各ステージの入出力契約を明示する |
| 検証メトリクスを通すためのしきい値の無断緩和 | 緩和が必要なら [11-validation.md](11-validation.md) に理由を記録した上で行う |
