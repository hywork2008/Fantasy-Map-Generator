# 12. 実装ロードマップ・作業指示

## 1. 実装者（AI エージェント）への作業指示

1. **マイルストーンは順番に、1 つずつ**。複数マイルストーンをまとめて実装しない。
2. 各マイルストーンの作業ループ:
   ```
   関連仕様書を読む → 実装 → npm test（full）→ デバッグレイヤーで目視確認
   → 受け入れ基準を 1 項目ずつ確認 → golden seeds のスクリーンショット更新 → コミット
   ```
3. **受け入れ基準を満たすまで次へ進まない**。満たせない場合、しきい値を緩めるのではなく実装を直す。どうしても仕様側が誤っていると判断した場合は、該当仕様書を修正しその理由をコミットメッセージに残す。
4. 旧実装（v1 の `src/generation/*`）は対応する新ステージが受け入れ基準を満たした時点で削除する。新旧の共存期間を長引かせない。
5. コミットは 1 マイルストーン 1 コミット以上。メッセージにマイルストーン ID（M0 など）とメトリクス結果の要約を含める。
6. 迷ったら [01-goals.md](01-goals.md) の設計原則と禁止事項に立ち返る。禁止事項に抵触する実装は理由の如何を問わず却下。

## 2. マイルストーン

### M0: 基盤整備
- **スコープ**: `core/`（rng fork, geometry 移設, graph, curves, grid+A*）、`model/types.ts` v2、`validation/metrics.ts` の骨組み、パイプラインの空実装（各ステージがダミー出力を返し、描画まで貫通）。
- **受け入れ**: 面抽出の単体テスト（三角形・井桁・行き止まり・8の字）合格。決定論スナップショット合格。ダミー都市が描画される。

### M1: 地形と骨格（S1–S2）
- **スコープ**: [04-terrain.md](04-terrain.md) 全部。4 アーキタイプの高度場・川・橋候補・アンカー・プレシンクト。デバッグレイヤー（高度・傾斜・アンカー）。
- **受け入れ**: 川が単調に下る。4 アーキタイプが目視で区別できる。プレシンクトが重ならない。

### M2: 幹線道路（S3）
- **スコープ**: [05-roads.md](05-roads.md) §2。コスト場 A*、再利用ボーナス、スムージング、RoadGraph 登録。
- **受け入れ**: M4（曲がり）・M10（連結性）合格。hillTop で道が等高線を巻くのが目視確認できる。プレシンクト・川（橋以外）を横断しない。

### M3: 城壁と門（S4）
- **スコープ**: [06-walls.md](06-walls.md) §1–2。壁線・塔・門・壁内周回路・門前広場。
- **受け入れ**: M13 合格。壁が川岸・急斜面を活用している（riverCrossing/hillTop で目視）。壁占有帯が道路空間と整合。

### M4: 街路網（S5）と街区抽出（S6）
- **スコープ**: [05-roads.md](05-roads.md) §3–4、[07-blocks-lots.md](07-blocks-lots.md) §1。成長ループ、T字路支配、壁内周回路との接続、面抽出・スリバー併合・接道タグ。
- **受け入れ**: M5（T字路率）・M6（街区面積）・M7（凹街区率）合格。ランダムシード 20 個で例外なく完走。
- **注意**: ここが v1 が崩壊した箇所。ノード化不変条件のテストを先に書いてから成長ループを実装すること。

### M5: 敷地分割（S8）
- **スコープ**: [07-blocks-lots.md](07-blocks-lots.md) §2。フロンテージ帯ピーリング、袋地処理、三角地・凹街区・湾曲辺の特殊ケース。
- **受け入れ**: **M1（フロンテージ率）**・M2・M3 合格。デバッグ表示で袋地警告（赤）が庭以外に出ない。
- **注意**: v2 の価値の中心。ここで妥協しない。

### M6: 建物（S9 前半）
- **スコープ**: [08-buildings.md](08-buildings.md)。ローカルフレーム矩形合成、共有壁列、屋根、押し出し描画。
- **受け入れ**: M8（直角率）・M9（接道整合）・M12（越境ゼロ）合格。目視: 妻壁の律動（ブルージュ項目）、三角地の隙間。

### M7: 地区・施設・ランドマーク（S7・S9 後半）
- **スコープ**: [09-districts-facilities.md](09-districts-facilities.md) 全部。地区割当、施設カタログ、ランドマーク実体化、密度勾配。
- **受け入れ**: 施設個数レンジ内。皮なめしが壁外下流にある。目視: スカイライン項目。

### M8: 城壁外と仕上げ（S6b・S10）
- **スコープ**: [06-walls.md](06-walls.md) §3（郊外・耕地・壁外施設）、plannedQuarter、HUD の ValidationReport 化、エクスポート v2 追従、golden seeds 確定。
- **受け入れ**: M11（密度勾配）・M14（性能）を含む **全メトリクス合格**。目視チェックリスト全項目クリア。README の背景資料（docs/*.md）との矛盾がないか最終確認。

### M9: FMG site モード
- **スコープ**: [13-fmg-site-input.md](13-fmg-site-input.md) 全部。`BurgSiteDescriptor` の io バリデータと UI インポート欄、S1 の heightfield 合成・descriptor 中心線河川・waterbody 再構成、S2 の門アンカー全数採用、S3 の街道端点接続、fit メトリクス F1–F5。
- **受け入れ**: FMG から実出力した descriptor 数種（riverCrossing / harbor / hillTop / crossroads / 村落規模）で fit メトリクス F1–F5 合格。site なし生成の golden seeds に差分がない（回帰なし）。
- **注意**: FMG 側は実装済み（`window.fmg.actions.getBurgSiteDescriptor` / Burg エディタのコピー・ボタン）。契約の変更が必要になった場合は 13 を更新し、FMG 側 `src/services/burgSiteDescriptor.ts` と `version` を同期させること。

### M10: 村落モード（settlementType: "village"）
- **スコープ**: 城壁・地区割当・バスティードを省いた縮退パイプライン。教会 + 緑地（village green）核、街道沿いリボン集落または広場村の 2 類型、農家敷地（間口 15–40 m、母屋 + 納屋 + 囲い庭）、集落を囲む耕地短冊。site モード（FMG の village / hamlet 規模 burg）でも成立すること。
- **受け入れ**: フロンテージ保証（M1）は維持。建物数 15–80。壁関連メトリクス（M13 等）はスキップとして明示。FMG の村 descriptor からの生成が目視で「地図の川・街道と整合した村」になっている。

## 4. リスクと対応

| リスク | 対応 |
|--------|------|
| 面抽出・幾何演算の数値誤差でパイプラインが不安定 | M0 で ε 方針を決め単体テストを厚くする。turf 依存箇所は隔離済み（[02-architecture.md](02-architecture.md)） |
| 成長ループが密度目標に到達せず終わらない/スカスカ | イテレーション上限 + 密度メトリクスを HUD で常時監視。上限到達は警告として表面化 |
| メトリクスが厳しすぎて開発が止まる | しきい値変更は 11 の表を更新 + 理由記録で許可。黙って緩めるのは禁止 |
| 性能予算超過 | 空間インデックス（グリッドハッシュ）を core に用意。予算超過でも不変条件は壊さない |
