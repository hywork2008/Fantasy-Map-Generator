本書は、中世ヨーロッパ風世界における都市の上水、灌漑、雨水排水、汚水、廃棄物を、相互に接続した公共インフラとして設計する。

対象は単なる「下水道技術の発明」ではない。開放水路、石張り排水路、暗渠、便所・工房の接続、清掃、放流規制を、都市ごとに異なる条件で発達させる。特に下水は、大規模な科学的発明がなくても、灌漑・治水・土地造成の副産物として導入できる一方、衛生的かつ持続的に運用するには制度と維持費を要するものとして扱う。

## 1. 設計上の結論

### 1.1 下水を一個の技術ノードにしない

下水道は、ポンプや浄水のように特定の発明だけで性能が跳ねる設備ではない。必要な基礎技術は、開始時代の石工、掘削、測量、木工、樋、排水溝で既に部分的に満たせる。

したがって、以下を分ける。

| 層 | 所有者 | 役割 |
| --- | --- | --- |
| 技術グラフ | State / Academy / Guild | 測量、石造暗渠、揚水、配管、衛生工学を利用可能にする |
| 都市インフラ | Burg | 取水・水路・排水路・便所・清掃設備を建設し、容量を運用する |
| 都市制度 | Burg / State | 接続許可、清掃税、工房規制、放流規制、水利権を定める |
| 個人・組織知 | 親方・Guild・行政 | 設計、施工、点検、清掃、修繕を実行する |

技術が `known` でも、都市に勾配、財政、施工者、放流先がなければ建設できない。逆に、初歩的な開放排水路は特別な研究を待たず建設可能とする。

### 1.2 最初の目的は衛生ではなく土地・水・物流である

中世相当の導入動機は、便所の排泄物処理より以下を優先する。

- 湿地・谷底を排水して市場、城下、港の用地を得る。
- 洪水後のぬかるみと道路破損を減らす。
- 灌漑・水車・都市菜園へ水を配り、余水を安全に逃がす。
- 染色、皮なめし、醸造、屠畜、浴場など、水を多く使う地区を操業可能にする。
- 城壁内の水たまり、悪臭、通行不能を抑え、徴税と市場取引を安定させる。

古代ローマのクロアカ・マキシマも、低湿地の排水を主目的とした水路が、覆蓋と延伸を経て都市下水の幹線になった例として参照できる。本世界でも「灌漑・治水の余水路を市場拡張のため覆った」という偶発的な経路を正規の発展経路とする。

### 1.3 排水できることと衛生的であることを分ける

汚水を川へ流せることは、直ちに安全な飲料水や疫病の抑制を意味しない。取水口より上流へ放流する、暗渠の詰まりで汚水が逆流する、洪水で便所があふれる、といった失敗を起こし得る。

衛生改善は、`上流取水・下流放流`、水源保護、清掃、工房排水規制、人口密度に見合う容量を同時に満たした場合だけ得る。近代に近い分流式下水と浄化は、後期の化学・微生物学・機械動力の領域であり、開始時代に遡及させない。

## 2. 水の流れと都市区画

### 2.1 五つの水系を混ぜて扱わない

各 Burg は、同じ水路に全用途を安易に混ぜないため、少なくとも以下の水系を記録する。

| 水系 | 主な源 | 主な用途 | 中世段階の主な危険 |
| --- | --- | --- | --- |
| `drinkingWater` | 泉、井戸、上流河川、雨水 | 飲用、調理、浴場 | 汚水混入、渇水、井戸の枯渇 |
| `serviceWater` | 河川、運河、用水路 | 洗浄、消防、工房、水車 | 争奪、凍結、取水障害 |
| `irrigationWater` | 河川、貯水池、導水路 | 都市菜園、近郊農地 | 塩害、用水権争い、渇水 |
| `stormwater` | 降雨、融雪、湧水 | 側溝、余水路、河川への排水 | 洪水、ぬかるみ、道路損傷 |
| `wastewater` | 家庭、便所、浴場、工房 | 沈殿槽、汚水路、放流先 | 悪臭、逆流、河川・井戸汚染 |

初期段階では `stormwater` と `wastewater` が同じ排水路を共有してよい。`drinkingWater` をその流路の上流側へ確保することが、最低限の衛生条件となる。

### 2.2 地形は技術より先に判定する

下水網の採否は、まず Burg の地理条件で決める。

| 条件 | 影響 |
| --- | --- |
| 河川・海・湖への低い放流点 | 自然流下式の排水に有利。ただし洪水・潮位の逆流に注意 |
| 市街地内の高低差 | 開放側溝・暗渠を機能させる。急すぎる場合は侵食対策が必要 |
| 湿地・高い地下水位 | 排水需要を強くするが、掘削・井戸汚染・維持費を悪化させる |
| 夏季の乾燥・灌漑農業 | 用水と余水路を整備する誘因になる。排水不足は塩害も招く |
| 石材・粘土・木材 | 石張り、焼成管、木樋、覆蓋の選択肢を決める |
| 大河川の上流取水 | 上水保護をしやすい。一方で下流集落との水利紛争を生む |

平坦で放流先のない都市は、初期には沈殿池、汲み取り、堆肥化、堤防内の貯留を主とする。自然流下できない都市が、電力や蒸気以前に大規模下水網を持つことは例外的な高コスト事業に留める。

## 3. インフラ段階

各段階は都市全体の一律レベルではない。同じ Burg の中心市場、工房区、港、貧民街、郊外で異なってよい。便宜上、都市の代表段階を `WaterSanitationTier` とする。

| Tier | 名称 | 必要条件 | 主な機能 | 限界・副作用 |
| --- | --- | --- | --- | --- |
| 0 | 個別処理 | 井戸、桶、汲み取り、自然地形 | 飲水と廃棄物を各戸・各工房で処理 | 路上投棄、井戸汚染、雨季の泥濘 |
| 1 | 開放側溝・余水路 | 掘削労働、最低限の勾配 | 雨水・灌漑余水を排水し、道路を守る | 悪臭、詰まり、転落、汚水混入 |
| 2 | 石張り排水路 | stoneworking Guild、都市予算、維持班 | 流路の侵食を抑え、工房・市場の排水を集める | 集中した汚染、洪水時のあふれ |
| 3 | 被覆暗渠・幹線排水 | civilEngineering / surveying、石材、放流先、接続規約 | 市場・道路上に用地を作り、雨水を幹線へ集める | 点検困難、逆流、無許可接続 |
| 4 | 管理下水網 | 清掃税、都市行政、工房規制、複数排出口 | 便所・浴場・工房の接続を許可制で管理し、都市衛生を部分改善 | 上水保護がなければ水系汚染を増幅 |
| 5 | 上下水分離・衛生工学 | 水質観察、近代的土木、動力、広域行政 | 取水・雨水・汚水を系統分離し、大都市の衛生を安定化 | 大投資、下流環境負債、処理施設への依存 |

Tier 3 は、質問でいう「思いつきからやってしまった」導入を表す主な到達点である。灌漑や治水の既存水路を覆い、市場・倉庫・道路を上に載せた時点では、まだ全戸接続の下水道ではない。そこへ便所・浴場・工房が接続することで、Tier 4 の管理課題が生じる。

## 4. 建設・維持・失敗のライフサイクル

### 4.1 公共事業の工程

都市水利プロジェクトは、技術ノードの採用とは別に、Burg が次の工程を進める。

```text
問題の発生
  → 調査・測量
  → 水利権／放流権の交渉
  → 資金調達と施工者の確保
  → 建設
  → 接続許可・運用
  → 清掃・修繕・拡張
```

| 工程 | 主な入力 | 失敗・遅延条件 |
| --- | --- | --- |
| 調査・測量 | `surveying` 熟練者、地形、水量観測 | 勾配不足、地下水位の誤認、測量者不足 |
| 権利調整 | administration、State 権限、近隣 Burg との関係 | 上流・下流の水利紛争、私有地、宗教施設の反対 |
| 建設 | Stone、Tools、労働者、Treasury、stoneworking Guild | 資材不足、戦争、洪水、施工不良 |
| 接続・運用 | 清掃人、接続税、条例、工房監督 | 無許可接続、容量超過、汚物・ごみの投棄 |
| 維持 | 年次予算、点検・浚渫、修繕技能 | 財政破綻、行政不在、疫病・洪水による作業停止 |

建設済みの Tier は、維持予算が不足すると段階的に劣化する。暗渠は「完成したので永続」ではなく、詰まり、崩落、放流口の埋没、違法接続で能力を失う。

### 4.2 導入を発生させる需要シグナル

次のいずれかを満たす Burg は、対応する事業を提案・投資候補にできる。

| 需要シグナル | 代表的な初期事業 | 成功時の主効果 |
| --- | --- | --- |
| 洪水・頻繁なぬかるみ | 側溝、堤防、余水路 | 道路・市場の稼働日増加 |
| 低湿地の市街化需要 | 幹線排水、土地嵩上げ、被覆渠 | 建設可能な都市用地増加 |
| 大規模灌漑・都市菜園 | 用水路、余水路、排水溝 | 農地利用・水車・都市食料の安定 |
| 浴場・染色・皮なめしの集中 | 工房排水路、沈殿池 | 工房の操業量増。ただし汚染増 |
| 高人口密度・悪臭 | 公衆便所、汲み取り制度、接続規約 | `SanitationBurden` の抑制 |
| 疫病・水源汚染 | 上流取水保護、放流規制、井戸検査 | 水由来リスクの低下。ただし原因理解には時間が必要 |

このため、灌漑は十分に有力な導入契機である。ただし「灌漑があるから自動的に下水道が生える」のではなく、余水の処理、市場用地の不足、洪水被害などが重なったとき、都市が覆蓋・幹線化へ投資する。

### 4.3 失敗も発見を生む

失敗事業は単なる罰で終えない。原因を記録・修繕した Burg / Guild は、後続の技法や制度知を得る。

| 事象 | 短期結果 | 得られ得る知見 |
| --- | --- | --- |
| 暗渠の逆流 | 市場閉鎖、疾病・不満、修繕費 | `backflowValve`、放流口設計、洪水時の遮断規則 |
| 井戸の汚染 | 人口・衛生への悪影響 | 取水源と汚水源の距離、水源保護条例 |
| 工房排水の悪臭 | 近隣不満、地価低下 | 工房区画化、沈殿池、時間帯規制 |
| 灌漑排水の塩害 | 収穫低下、農民不満 | 排水溝の必要性、輪作・用水量規制 |
| 維持費の滞納 | 能力低下、崩落 | 清掃税、接続料、行政の監査 |

## 5. シミュレーション・データ設計

### 5.1 Burg ごとの状態

実装時には Economy 拡張または都市インフラ用の拡張状態として、Burg ごとに次の概念を持たせる。数値の実体・保存場所は実装設計で確定する。

```ts
type WaterSanitationTier = 0 | 1 | 2 | 3 | 4 | 5;

interface UrbanWaterSystem {
  tier: WaterSanitationTier;
  drinkingWaterSecurity: number;
  serviceWaterCapacity: number;
  irrigationCapacity: number;
  stormwaterDrainageCapacity: number;
  wastewaterCapacity: number;
  maintenanceCondition: number;
  sanitationBurden: number;
  waterContamination: number;
  floodExposure: number;
  hasUpstreamIntake: boolean;
  hasDownstreamOutfall: boolean;
  hasSeparateWastewaterRoute: boolean;
}
```

`capacity` は人口・工房・降雨に対する処理能力であり、完成した Tier の値をそのまま表さない。人口増加や工房集中により需要が容量を越えれば、同じ Tier でも衛生・洪水の便益は失われる。

### 5.2 年次更新の概念

```text
降雨・融雪・河川水位 ──> stormwater demand ──┐
人口・浴場・工房 ──────> wastewater demand ───┼─> 容量との差分
灌漑・都市菜園 ───────> irrigation demand ───┘        │
                                                          ↓
維持費・清掃・勾配・放流先 ───────────────────> 洪水、悪臭、汚染、都市機能
                                                          ↓
行政・Guild・個人熟練 ───────────────────────> 修繕、規制、次の建設候補
```

更新は月次または季節単位が適する。豪雨、渇水、疫病、戦争は短期ショックとして扱い、Tier、技法、制度は年次でゆっくり変化させる。

### 5.3 効果の原則

| 指標 | 好条件での効果 | 悪条件での効果 |
| --- | --- | --- |
| 都市用地 | 湿地排水・覆蓋により市場・住宅・倉庫を増設可能 | 放流・洪水失敗で地価と建設可能面積が低下 |
| 交易・生産 | 道路の通行性、港・市場・工房の稼働が改善 | 洪水、悪臭、汚染で操業・市場が停止 |
| 食料 | 灌漑・都市菜園が安定 | 塩害、渇水、用水紛争で生産低下 |
| 健康 | 清掃、水源保護、容量余裕があれば衛生負担を減少 | 未処理汚水と飲水混入で健康負債を増加 |
| 政治 | 目に見える公共事業は正統性・都市魅力を高める | 接続税、強制労働、放流被害が不満・紛争を高める |

衛生は人口への恒久的な万能バフにしない。水源、季節、維持状態、居住密度の相互作用として扱う。

## 6. 技術グラフとの接続

本書は施設・制度の仕様であり、技術グラフの正本ではない。ロードマップには、次の限定したノードだけを置く。

| 技術ノード | 主な解禁内容 | 都市インフラ側で別途必要なもの |
| --- | --- | --- |
| `urbanWaterworks` | 測量、水利設計、石張り排水路、被覆暗渠 | 地形、石材、Treasury、放流権、維持班 |
| `waterLifting` | 揚水、水車利用、高所への限定給水 | 動力源、取水権、配水施設、維持者 |
| `municipalSanitation` | 清掃税、接続許可、工房排水規制、公衆便所管理 | 行政能力、実際の清掃・監査予算 |
| `sanitaryEngineering` | 上水・汚水分離、水質観察、大規模排水計画 | 近代的土木、動力、広域行政、継続投資 |

`urbanWaterworks` は、灌漑・治水または都市化需要と、`civilEngineering`・`surveying`・`stoneworking` の組合せで `known` / `demonstrated` になり得る。Tier 1 と Tier 2 はこのノードが未発見でも地方慣行として許容する。Tier 3 以降は、少なくとも実証済みの測量・石造暗渠技法を要求する。

### 6.1 上水道との非対称性

上水は、水源の確保、導水、揚水、貯水、配水という「水を必要な高さ・量・場所へ運ぶ」技術連鎖を持つ。そのため水車、ポンプ、耐圧管、配水池の発展と強く結び付く。

下水は、自然流下できる限り、より早く・安く始められる。しかし、そのぶん排水先に問題を押し出すだけになりやすい。この非対称性を保つことで、古い都市が開放排水路や暗渠を持ちながら、近代的な上水・衛生下水を持たない状態を表現できる。

### 6.2 蒸気揚水との接続

`Municipal Steam Pumping` は、[蒸気機関後の工業 Good・市場・後続技術設計](./steam-industrial-goods-and-technology-chain.md#34-第4群-蒸気揚水による上水道) が定める後期の接続先である。`Stationary Steam Engine`、Coal、Machine Parts は Economy の市場・運転入力とし、設置後の `Steam Waterworks`、取水量、貯水・配水先、`waterContamination`、維持状態と上水供給への効果は `UrbanWaterSystem` が所有する。

この接続には `urbanWaterworks` と局所的な `waterLifting`、水源・取水権・配水網・維持予算を要求する。蒸気機関を保有する State が、これらを欠くすべての Burg に一律の給水ボーナスを得ることはない。揚水は水の量と到達高度を増やすだけで、汚染水を安全にせず、下水の自然流下能力・処理能力・上下水分離を置き換えない。

## 7. 所有・財政・政治

### 7.1 所有主体

| 施設 | 基本的な所有者 | 補足 |
| --- | --- | --- |
| 井戸、雨水槽、小樋 | 世帯、寺院、工房 | 都市は位置・衛生だけ規制できる |
| 用水路、都市菜園の余水路 | 水利組合、地主、Burg | State は水利権の裁定を担う |
| 市場側溝、幹線排水、公共便所 | Burg | 利用料・接続料・清掃税の対象 |
| 河川堤防、広域導水、放流規制 | State と関係 Burg | 下流・上流間の外部性を調整する |
| 近代的浄化・分流網 | State / 広域連合 | 単独 Burg には重すぎる大規模投資 |

### 7.2 財政モデル

建設費と維持費を明確に分ける。

- 建設費: Stone、Clay、Timber、Tools、労働、土地補償、Treasury。
- 維持費: 清掃人、浚渫、点検、補修材、洪水後の復旧。
- 収入: 市場税、接続料、工房排水料、港湾収入、State 補助、寄進。
- 外部費用: 下流地域の水質悪化、漁業・農業損害、洪水時の被害。

有力者が自らの市場・浴場・工房のために Tier 3 を先行建設することは可能にする。ただし無許可接続や清掃費未払いが増えれば、公共インフラの利益は私益に食い潰される。

### 7.3 制度技法

個人熟練が高くても、次の制度技法がなければ Tier 4 以上へ安定移行しない。

| 技法・制度 | 習得主体 | 効果 |
| --- | --- | --- |
| `drainageSurvey` | 測量士 Guild | 勾配不良・施工失敗の確率を下げる |
| `coveredCulvertMasonry` | 石工 Guild | 被覆暗渠の耐久・容量を上げる |
| `sewerInspection` | 都市行政・清掃組合 | 劣化を早期発見し、無許可接続を抑える |
| `waterSourceProtection` | Burg / State | 取水口付近の汚水・工房排水を規制する |
| `drainageAssessment` | Burg | 接続料を容量負荷に応じて配分する |

## 8. 排泄物・有機廃棄物の文化と資源循環

### 8.1 「捨てる」「運ぶ」「養分として戻す」を区別する

糞尿は一つの Good として在庫化しない。人・家畜・工房の有機廃棄物が、地形・慣習・労働・危険に応じて別の経路を取る状態として扱う。

| 経路 | 主な場所 | 必要条件 | 得るもの | 主な負債 |
| --- | --- | --- | --- | --- |
| `openDisposal` | 路地、側溝、河畔 | 排水先だけ | 目先の処分 | 悪臭、害獣、井戸・河川汚染 |
| `cesspit` | 各戸、修道院、城、工房 | 掘削空間、汲み取り | 保管、後日の搬出 | 地下水汚染、満杯、作業事故 |
| `nightSoilCollection` | 高密度 Burg と近郊農地 | 汲み取り人、容器、運搬路、肥料需要 | 肥料取引、都市の清掃 | 漏出、労働衛生、近隣不満 |
| `managedComposting` | 厩舎、農場、都市外縁 | 炭素資材、湿度・通気、切り返し、保管地 | 安定した土壌改良材、臭気・容量の低減 | 管理不足時の病原体、流出、悪臭 |
| `animalScavenging` | 市場外縁、豚舎、路地 | 家畜管理または放し飼い | 生ごみ・副産物の減量 | 人獣共通感染、家畜の汚染、事故 |
| `waterDischarge` | 河川、海、運河 | 放流点、水量 | 大量の移送 | 下流への外部費用、逆流、漁業被害 |

都市は、このうち複数を併用する。排水路があるからといって堆肥化・汲み取りが不要になるわけではなく、固形ごみ・汚泥・浚渫土・厩肥は別途扱う。

### 8.2 豚便所と欧州都市の豚を混同しない

中国の豚便所は、便所の落下口と豚舎を意図的に結び、排泄物と残飯を豚へ回す**施設型の循環**である。これは農家単位の家畜飼養・飼料・便所を一体化する文化として扱う。食用家畜へ人の排泄物を与えることには寄生虫・病原体の危険があるため、衛生知識のない時代でも「安い飼料と引き換えの健康負債」を持たせる。

一方、中世ヨーロッパの都市では、豚を含む家畜が街路に存在し、有機ごみをあさることがあり、都市当局が豚や廃棄物を規制した事例がある。しかし、これを「人糞を豚へ給餌する豚便所が都市の標準だった」とは扱わない。本設計での位置付けは次の通りとする。

| 形態 | 世界内での扱い | 効果 | 危険 |
| --- | --- | --- | --- |
| 放し飼いの都市豚 | 中世欧州風 Burg で起こり得る非公式の `animalScavenging` | 生ごみ・屠畜残滓を減らすことがある | 路上汚染、作物・市場の被害、家畜事故、感染リスク |
| 規制された豚舎 | 市壁外・市場外縁の管理施設 | 残飯・副産物を飼料に回し、都市の有機ごみを減らす | 汚水処理・屠畜管理を要する |
| 豚便所 | 東方・南方など、明示的に採用する農村文化の固有施設 | 便所・飼料・家畜を一体化する | 特に高い健康負債。食料安全・検疫の後期技法で軽減可能 |

豚が排泄物を食べる出来事自体は、どの文化圏でも起こり得る。ゲーム上の差は、それを放置された事故・路上清掃として扱うか、便所と豚舎を接続した制度的な飼養として扱うかである。

### 8.3 堆肥化は気温だけで可否を決めない

冷涼な地域で分解が遅くなるのは正しいが、堆肥化を不可能にはしない。微生物が発生させる熱を蓄えられる十分な堆積量、窒素源となる糞尿、炭素源となる藁・落葉・泥炭など、適切な水分・通気・切り返しがあれば、外気が低くても内部で発酵が進み得る。逆に暖地でも、湿りすぎ、通気不足、材料不足なら腐敗・悪臭・流出が起きる。

| 地域・季節条件 | 実行しやすい処理 | ゲーム上の制約 |
| --- | --- | --- |
| 温暖・湿潤 | 好気的堆肥化、都市菜園への還元 | 過湿と流出、虫害、悪臭を管理する |
| 温暖・乾燥 | 乾燥・貯留、灌漑農地への計画施用 | 水不足、塩類集積、用水汚染に注意 |
| 冷涼・多雨 | 藁・落葉を混ぜた大きな堆積、屋根付き保管、春の施用 | 冬季は処理が遅い。凍結・融解と浸出を管理する |
| 寒冷・長い冬 | 冬季貯留、断熱された大きな堆積、春以降の切り返し | 小規模な山は発熱不足。未熟なまま施用すると衛生負債が残る |
| 高密度都市 | 汲み取り・郊外搬出・市場外縁の処理場 | 運搬費と住民の反発が大きい |

`managedComposting` の効率は、`ambientTemperature` だけでなく、`pileMass`、`carbonMaterial`、`moisture`、`aeration`、`turningLabor`、`storageCover` から計算する。低温は分解・病原体低減を遅らせる修正値とし、屋根・断熱・大規模堆積・季節保管で部分的に補えるようにする。

近代的な病原体低減を狙う高温堆肥化は、長期に高い内部温度と均一な切り返しを要する。中世段階では「養分を回収するが安全性は保証しない熟成・堆積」と「管理された良質堆肥」を別の品質にし、未処理の人糞を生食用の近接作物へ無条件に施せないようにする。

## 9. 排泄後の洗浄・拭き取りの文化

### 9.1 設計原則

拭き取り方は技術ツリーで一つに収束しない。水の豊富さ、植物相、寒暖、紙・布の価格、宗教・礼法、私的空間の有無によって併存する生活文化である。下表の「主要」「副次」「稀」は、各地域・階層に絶対的な標準があったという意味ではなく、世界設定を作るための重み付けである。

また、古代の資料を中世ヨーロッパの標準へ投影しない。たとえば古典地中海世界の丸い陶片 `pessoi` や棒付き海綿は有名だが、後者を肛門洗浄具ではなく便所清掃具と見る研究上の議論もある。本書では「古代の都市文化に存在し得る候補」とし、中世欧州の一般的な生活習慣とは断定しない。

### 9.2 年代・地域別の材料と洗浄法

| 時代・地域の原型 | 主要 | 副次 | 稀・階層限定・注意点 |
| --- | --- | --- | --- |
| 古代地中海の都市 | 水による洗浄、植物素材、布片 | 丸く整えた陶片・小石 | 棒付き海綿は史料解釈に争いがあるため、共同便所の清掃具／洗浄具のどちらにも設定可能 |
| 中世西・中部ヨーロッパ（1100〜1400 相当） | 水洗浄が可能な場所での洗浄、葉、草、藁、苔、柔らかい植物素材 | 麻・亜麻のくず、ぼろ布、木質繊維、古紙 | 専用の安価な紙は広くは前提にしない。布は洗濯・再利用の負担と階層差を伴う |
| 冷涼な北方・山地 | 苔、乾いた草・藁、柔らかい樹皮・植物素材、布 | 雪、水 | 冬季の水洗浄や採取には不利。雪は季節限定で、刺激・低温の負債を持つ |
| 乾燥地・水を重視する宗教文化圏 | 水による洗浄と手洗い | 布、植物素材 | 水の運搬・私的洗浄空間が必要。紙の有無だけで清潔度を決めない |
| 東アジアの紙・官僚文化圏 | 紙、植物素材、水洗浄 | 木・竹のへら／籌木に相当する道具、布 | 紙の利用は紙の供給・用途上の禁忌・階層に左右される。奈良期の日本の籌木は地域固有の候補 |
| 近世の欧州都市（印刷・紙流通の拡大後） | ぼろ布、麻くず、古紙・包装紙、植物素材 | 水洗浄 | 印刷の失敗紙・不要紙が利用されることはあり得るが、紙はなお地域・所得差が大きい |
| 工業化初期（19世紀） | 安価な紙、古紙、布、既存の地域慣習 | 専用品の平判紙、穿孔紙 | 専用の市販衛生紙は登場するが、普及は製紙・流通・所得・水洗便所の拡大より遅い |
| 大量生産・近代都市 | 薄い衛生紙・ロール紙、水洗浄 | 再生紙・携帯紙 | 安価な木材パルプ、連続製紙、穿孔・包装、都市流通が揃って初めて大衆的な選択肢になる |

「川や水槽に張った縄を使う」方式は、水に浸した素材を共同で用いる民俗的・地域的な候補として扱える。ただし、地域・時代を横断する普遍的な習慣としての確実な根拠は弱い。このため、世界内では河川沿いの特定文化の**稀な共同洗浄具**とし、清流・流水・洗浄習慣・共同設備という条件を要求する。中世ヨーロッパ風の標準としては設定しない。

### 9.3 紙と工業化の関係

紙が発明されただけでは、拭き取り用の紙は大衆化しない。書写、包装、宗教・行政の用途の方が高価値であり、柔らかさ、切断・穿孔、衛生的な保管、低価格の大量流通が別途必要になる。

| 段階 | 必要条件 | 生活文化への効果 |
| --- | --- | --- |
| 手漉き紙 | 繊維原料、職人、少量流通 | 上層・寺院・都市部の紙利用。拭き取りへの転用は高価または限定的 |
| 印刷・紙流通の拡大 | 製紙 Guild、印刷、商業流通 | 端紙・不要紙が副次的な候補になる。需要はまだ不安定 |
| 機械製紙 | 木材パルプまたは大量の繊維、動力、漂白・加工、輸送 | 安価な紙が都市消費財になる条件を形成 |
| 専用衛生紙 | 規格化、柔らかい紙、切断・穿孔、包装・小売 | 公衆便所・家庭で専用品が普及。ロールは都市の消費文化として定着 |

現実史の参照として、中国では遅くとも 6 世紀には紙を便所用途に使う記録があり、19 世紀の北米では専用市販紙と、穿孔されたロール紙が商品・特許として現れる。本世界では特定の現実年代を強制せず、この製紙・流通・所得の連鎖を満たした地域だけが安価な衛生紙を `diffused` できるようにする。

### 9.4 魔法を使う場合の境界

魔法は文化差を豊かにするが、都市衛生の全問題を無効化しない。

| 魔法的手段 | 可能な効果 | 残すべき制約 |
| --- | --- | --- |
| `cleanseBody` | 身体・衣類の洗浄、拭き取り材料の節約 | 術者、魔力、料金、使用場所が必要。排泄物そのものは残る |
| `decomposeWaste` | 便槽・ごみ溜めの容積・悪臭を減らす | 養分・病原体・水質への作用を明示しない限り、飲水安全は保証しない |
| `purifyWater` | 限られた水源の浄化 | 大河川・都市全体を無制限に浄化できない。取水保護と配水はなお必要 |
| `containOdor` | 工房区・便所周辺の不快感を抑える | 汚染と感染リスクを消したことにはしない |

魔法で排泄物を完全に無害な養分へ変換できる文化を置くなら、それは `sanitaryEngineering` と同等以上の社会的影響を持つ。魔法資源の供給、独占、都市人口、農業肥料、下流外交まで設計対象にする。

## 10. 移動体・工業化における衛生の分岐

### 10.1 工業化は「水洗化」ではなく物流と処理責任の移動である

工業化時代の便所は、家庭・都市・乗物が同じ水洗網へ一挙に接続されるのではない。肥料としての回収価値、人口密度、鉄道・港湾による物流、化学肥料、下水道・処理場、環境規制の変化によって、複数の処理方式が長く併存する。

| 型 | 主な時期・場所 | 処理の流れ | 設計上の結果 |
| --- | --- | --- | --- |
| `nightSoilCommodity` | 前工業〜初期工業の農業都市 | 便槽 → 汲み取り → 近郊農地 | 都市の廃棄物が肥料価値を持つ。農地との距離と需要が重要 |
| `railborneNightSoil` | 鉄道網を持つ大都市圏 | 貯留場 → タンク貨車 → 農村／処理地 → 返路で農産物 | 遠距離でも養分循環を保てるが、専用基地・洗浄・漏出管理が必要 |
| `paidCollection` | 化学肥料・都市化の進行後 | 便槽 → 有償汲み取り → 海洋投棄・埋立・処理 | 排泄物は商品から処理費用へ転じ、都市財政を圧迫 |
| `sewerTransition` | 下水道整備中の都市 | 一部は下水、一部は便槽・汲み取り | 貧富・地区・地形ごとの格差が残る。下流汚染も増え得る |
| `centralTreatment` | 近代以降 | 下水・汚泥 → 処理場 → 放流／再利用 | 高い公費・運用能力を要求。容量不足時は広域危機になる |

日本史の参照例として、1944 年には西武鉄道が糞尿輸送用タンク車と沿線貯留場を整備し、夜間に都市から農村へ運び、帰路に野菜を運ぶ循環を作った。このような仕組みは「下水道に勝った古い方式」ではなく、輸送・農業需要・都市清掃を結んだ過渡期の高度な物流として表現できる。

### 10.2 旅客車・軍用車両・長距離輸送

乗物の便所は、都市下水に接続できないため、固有の処理方式を持つ。乗物の快適性を上げるだけでなく、沿線・停泊地・車両基地へ負債を移す設計にする。

| 方式 | 必要技術・設備 | 便益 | 外部性・故障 |
| --- | --- | --- | --- |
| `openDischargeVehicle` | 落下口、最低限の洗浄水 | 軽量・低コスト・停車不要 | 線路・道路・停泊地への直接放流、悪臭、利用制限、衛生被害 |
| `holdingTankVehicle` | 密閉タンク、抜取設備、基地 | 運行中の放流を抑える | 容量・重量・基地不足。抜取作業者へ負担が集中 |
| `recirculatingVehicle` | ろ過、少量の洗浄水、保守 | 水の搭載量を抑える | におい、故障、処理液・フィルタの維持 |
| `treatmentVehicle` | 生物・燃焼・浄化・真空装置 | 排出量・臭気を減らし、長距離運行に対応 | 高価で、動力・保守・専門員が必要 |

日本の旅客列車では、かつて開放式の汚物処理が使われ、沿線への垂れ流しが「黄害」として問題化した。高度成長期には循環式・浄化排水式・燃焼式・生物処理式などが導入され、さらに節水・真空式へ移った。本世界では、鉄道・飛行船・長距離馬車・魔導輸送に同じ選択を適用できる。`holdingTankVehicle` は都市が進んだ証拠ではあるが、車庫・駅・港の抜取施設がなければ成立しない。

### 10.3 帆船・外洋航海

通常の帆船では、一般船員用の便所は船首（`head`）側に置かれ、格子や開口から海へ直接排泄する形式が基本となる。船首は風と波を受け、船内・後方甲板から離れやすいが、荒天時には使用が困難で、桶・便器・甲板上の臨時処理が発生する。士官・船長・高額な旅客には、私的な便器や室内便器を設け、内容物を海へ捨てる形を選べる。

| 船内の条件 | 通常の処理 | 洗浄・拭き取りの設計 | 主な危険 |
| --- | --- | --- | --- |
| 沿岸・短期航海 | `head` からの海洋放流 | 海水洗浄、個人の布・植物素材など、出港地の慣習を持ち込む | 転落、甲板汚染、港内の水質悪化 |
| 外洋の商船・軍艦 | 船首の `head`、士官用便器、荒天時の桶 | 水は貴重であるため、淡水を大量の洗浄に使わない。共同ロープを採用するなら特定船団の慣習・清掃役・流水条件を明示する | 荒天時の桶の滞留、船内悪臭、淡水不足、感染症 |
| 長期・高密度の移民船 | 甲板・便器・桶・限定された放流設備 | 個人用の低価値素材または水洗浄。物資不足時は衛生負債が急増 | 給水不足、感染症、隔離失敗 |
| 奴隷船・強制収容船 | 被拘束者を船倉へ過密に収容し、排泄物・嘔吐物・病人への対応も不十分になり得る | 「選べる船内文化」ではなく `forcedConfinement` による人道危機として扱う | 汚染された食水、赤痢などの流行、死亡率、暴力・抵抗、船主・国家への責任 |

奴隷船の船倉は、過密収容に加えて排泄物・嘔吐物・遺体が十分に除去されないことがあり、食水の汚染と疾病を増幅した。この状態を一般船舶の不便なトイレの変種として矮小化せず、奴隷制・強制移送・暴力を扱う別の人道・政治システムの結果とする。

帆船で「尻を何で拭いたか」は、船の国籍・階層・時代・寄港地の習慣により、確定的な一様の答えを置かない。既存の地域別文化プロファイルから、海水洗浄、個人の布・麻くず・紙・植物素材を選ばせる。海中へ垂らした縄を共同で使う逸話は、特定の船団・地域に限定する候補にはなるが、一般帆船の標準仕様とはしない。

### 10.4 魔法・異世界輸送への転用

- 浮遊船、飛行船、長距離転移路は、`openDischargeVehicle` を使えないか、地上への落下被害を大きくする。
- `holdingTankVehicle` は、魔法で容積・重量を軽くしても、荷下ろし先と処理責任を消さない。
- `decomposeWaste` を車両・船内に使う場合も、魔力消費、故障、残留物、臭気、排出先を定義する。
- 遠洋船で `purifyWater` が使えても、船内の隔離、清掃、配給、強制収容の問題を解決したことにはしない。

## 11. 実装ロードマップ

### Phase 1: 状態と可視化の基礎

1. Burg ごとに `UrbanWaterSystem` の最小状態を追加する。
2. 河川、湿地、勾配、降雨、人口、工房を入力に、排水需要と洪水曝露を算出する。
3. Tier 0〜2 と、洪水・ぬかるみ・悪臭の状態を実装する。
4. 初期化では、河畔の大都市、湿地都市、乾燥地の灌漑都市に異なる初期値を与える。
5. 文化圏ごとに、水洗浄・植物素材・布・紙・共同具の重みと、便槽・汲み取り・堆肥化・家畜利用の重みを設定する。

### Phase 2: 公共事業と維持

1. 側溝、余水路、石張り排水路、被覆暗渠を Burg 投資として実装する。
2. 建設と維持を別予算にし、維持不足による劣化・詰まりを実装する。
3. 洪水、渇水、工房集中を、建設候補を生む需要シグナルとして扱う。

### Phase 3: 制度・汚染・相互作用

1. 接続許可、清掃税、水利権、放流規制を実装する。
2. 井戸・取水口と排水口の位置関係から `waterContamination` を更新する。
3. 工房、港、都市農業、人口・健康システムと効果・外部性を接続する。
4. 便槽、汲み取り、堆肥化、放し飼い家畜、豚便所を、地域文化と都市密度に応じた有機廃棄物の経路として実装する。
5. 寒冷地の堆肥化には、低温・小規模堆積の減速と、断熱・大量堆積・季節保管による補正を実装する。

### Phase 4: 後期技術との接続

1. `waterLifting` と上水配水を、水車・蒸気・電力の技術段階に応じて発展させる。
2. `sanitaryEngineering` で、分流、広域放流、処理を後期の公共事業として実装する。
3. 下流汚染を State 間・Burg 間の外交、補償、紛争に接続する。

## 12. 検証項目

1. 特別な技術ノードがなくても、地形と労働力があれば Tier 1 の開放排水路を建設できる。
2. 灌漑・治水・市場用地需要が重なる Burg で、Tier 3 の被覆暗渠が有力な投資候補になる。
3. Tier 3 の建設だけでは、飲水源が汚水の下流側にない限り衛生ボーナスを得ない。
4. 人口・工房の排水需要が容量を超えた場合、完成済みの排水網でも悪臭・洪水・汚染が増える。
5. 維持予算が不足すると、Tier と無関係に `maintenanceCondition` が低下し、能力が失われる。
6. 上流 Burg の放流が、下流 Burg の取水・漁業・農業へ外部費用を与える。
7. Tier 5 は、近代的技術と広域行政なしには採用できない。
8. 都市の放し飼い豚は有機ごみを減らし得るが、豚便所と同じ生産・衛生効果を自動的には得ない。
9. 寒冷地でも大規模・保温・適切な材料の堆肥は進行し得る一方、無管理の小規模堆積は冬季に停滞する。
10. 紙の安価な大量生産以前、拭き取り用の紙は文化・階層・供給に依存し、全 Burg の既定選択肢にならない。
11. `decomposeWaste` の魔法を採用しても、効果定義がない限り、汚水の病原体・養分・下流水質は自動で消えない。
12. `railborneNightSoil` は、鉄道・貯留基地・農業需要がそろう場合にだけ都市清掃と肥料循環を改善する。
13. `openDischargeVehicle` は運行コストを下げ得るが、沿線・停泊地の汚染負債を生み、環境規制・苦情・都市の正統性へ影響する。
14. 一般帆船の `head` と奴隷船の過密な船倉を同じ衛生ティアの差として扱わず、後者は `forcedConfinement` による別の人道危機として記録する。

## 15. 種族による例外: Giant の古代水利遺産

**実装済み**（2026-08-14 のバイアス、2026-08-21 の Giant 国家全Burgへの遺産シードと重力導水用の立地制約、2026-08-22 の最高水源・流域占有制約）

Fantasy Cultures Set（`highFantasy`/`darkFantasy`。判定は `isFantasyCulturesSet()`, `src/data/raceCivicStance.ts`）で Giant 種族の Burg は、古代ローマ相当（クロアカ・マキシマ級の被覆下水幹線＋導水路）の上下水道技術をあらかじめ持つ民族として扱う。`raceSkillBias.ts` の Giant 定義（`engineering: +8`、dwarf と同水準）と一貫させ、「神系種族が失われていない工学知識を保持している」という設定を反映する。

### 15.1 全集落の生成時遺産と重力導水の立地

Giant 国家（State の文化種族が Giant）の全 Burg — `capital` / `city` / `town` / `village` / `fort` を含む — は、地図生成時に Tier 4（管理下水網）と導水・幹線放流への既存接続を必ず持つ。これは新たに建設する近代設備ではなく、古代ローマ相当の遺産として初期状態を直接シードする。Tier 5 の分流・処理は与えない。

Giant 国家は任意の土地に発生しない。State 拡張直後に、全河川の `River.source` のうち最も標高の高い水源（同標高ならセル番号が小さい方）、その河系の `River.basin`、および首都から水源へ至る**海を渡らない陸上回廊**を、単一の Giant State が占有できる場合にだけ成立する。流域は、当該河系の河道セルに加え、河川生成と同じ「最も低い隣接セルへ流下する」規則でその河道へ達する陸地セルとして復元する。これはこの地図データで得られる集水域の決定的な近似である。

既存のロック済み State 領や他国の首都セルのためにこの回廊または流域を確保できない場合、Giant 国家は生成しない（その State は通常の Human 文化 State として扱う）。複数の Giant 候補がある場合は、最短の陸上回廊を持つ一国だけを残す。これにより、Giant 国家が国境外の源流や上流都市に依存することを防ぎ、最高水源と流域を国家的な保護区として一貫して保有する。

Giant は食料供給・気温・人間用の高地適性で生死を判定しない。通常人口を配置した後、最高水源の集水域を Giant 文化の高地オイコウメネとして再配置し、雪山・寒冷地でも人口と首都候補を残す。各セルの Giant 容量は、同じセルに人間容量がある場合はその **10%**、人間容量がゼロの高地では周辺の人間居住地の平均面積密度の **10%** とする。この容量を食料由来の `subsistenceCapacity` にも直接設定するため、後年の農業・気温計算によって飢餓死しない。最高水源セルの適地スコアだけは首都選定のために上げるが、実人口・都市容量はこの低密度上限を超えない。

重力導水を設定と地形の両方で矛盾させないため、State 生成後の Burg 整列時に、Giant 国家の集落は地図上の最高河川水源より**厳密に低い**標高へ配置する。候補は同じ State 内の未占有・居住可能な低地セルから選び、適地性を優先する。候補がない例外的な地図では既存位置を保持する。

通常の `hasDownstreamOutfall` は地形だけで決まるが、Giant 遺産は `hasInheritedRomanSewer` により同一陸地の低位河川または海岸の幹線放流へ接続済みとして扱う。河川と海岸の候補が共存する場合は、集落から近い方を選び、遠い河川へ低地を横断して接続することはない。このため、村や砦を含めて「排水先のない下水網」にはならない。遺産そのものは State が運営するため、局地文化が異なっても維持できる。

### 15.2 バイアスの内容(`WaterTechRaceBias`)

| フィールド | 効果 | 注入先 |
| --- | --- | --- |
| `ceilingBonus.waterLifting` (+0.3) / `ceilingBonus.municipalSanitation` (+0.25) | 歴史時代天井 (`waterTechCeilings()`) を加算で引き上げる。`sanitaryEngineering` は対象外 | `evolveWaterTechStocks()` |
| `administrationBonusBonus` (+0.15) | `connectionPermitCoverage`/`dischargeRegulation` の目標値(`institutionalTargets()`)を押し上げる。tier 5 ゲート(`SANITARY_ENGINEERING_ADMIN_MIN`)には使わない | `evolveInstitutions()` 呼び出し時の `administrationBonus` のみ |
| `urgencyThresholdMultiplier` (×0.6) | 公共事業を着手する `demandUrgency`/`droughtDemand` の閾値を下げ、危機的需要を待たず先回りで着工させる | `WATER_PROJECT_URGENCY_THRESHOLD` の全比較箇所 |
| `constructionSpeedMultiplier` (×1.35) | 着工後の年次進捗を加速する(継承された工学技能) | `yearProgress`(建設進捗) |

`sanitaryEngineering`(Tier 5・上下水分離)は一切バイアスしない — ローマは分流式下水も処理施設も持たなかったため、Tier 5 は他種族と同じく需要駆動で獲得する対象のままとする。

生成時の遺産判定は Burg 個人の文化ではなく、**Burg を所有する State の文化種族**で行う。従って Giant 国家が初期に持つ全ての集落は、局所文化が異なっていても遺産を得る。`hasInheritedRomanWaterworks` を維持している Giant 国家の集落は、年次の技術バイアスにも State の Giant 種族を用いる。これは導水路・幹線下水を State が運営・修繕する前提であり、局所文化の違いで遺産の維持技能だけが即座に失われることを防ぐ。遺産を持たない都市は従来どおり Burg 文化を読み、征服後の非 Giant 文化都市が新規建設を一律に加速することはない。

- `src/extensions/economy/generators/urbanWaterSupply.ts` / `renderers/drawWaterSupply.ts`: `hasInheritedRomanWaterworks` の集落群について、同一State・同一陸地内の最高位かつ下水放流に汚染されない河川セルを共通の保全取水地として選ぶ。取水地から最寄りの Burg へ、以後は既設導水セルから最寄りの未接続 Burg へ、標高を経路コストに含めないセル間最短経路を追加して樹状の模式導水路を `toggleWaterSupply` レイヤーに描画する。外国領・海・別陸地は経路に使わない。
- `src/extensions/economy/generators/urbanSewerage.ts` / `renderers/drawSewerage.ts`: `hasInheritedRomanSewer` の集落について、同一陸地内で低い河川と海岸の最寄り候補を比較して放流点を決定し、`toggleSewerage` レイヤーに描画する。海岸より近い河川がある場合だけ河川へ放流する。導水・下水とも海・海峡・別島を越えない。
