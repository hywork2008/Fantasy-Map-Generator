# 開拓村のCE 3D表示に必要なBV未登録オブジェクト

作成日: 2026-10-30  
状態: 調査・制作候補一覧。モデル制作・BV登録・CE接続は未着手。

## 1. 目的と調査基準

森に到着した開拓団の野営から、共同小屋、最初の収穫、世帯の屋敷地を持つ村までをCEの3Dクォータービューで表すために、BVに足りないオブジェクトを洗い出す。城壁都市・大規模な都市施設は今回の対象外とする。温帯の初期設定を優先し、全文化・全気候で同じ建物を使う前提にはしない。

照合したGitの基準点は次のとおり。この一覧はモデルの見た目の完成度を実ブラウザーで評価した結果ではなく、登録経路・モデル生成コードとSF設計を照合した結果である。

| 対象 | ブランチ・コミット | 用途 |
| --- | --- | --- |
| 登録済みモデルとCEの現状 | `develop` / `b82c2b73b` | このドキュメントの保存先。BVの登録を判定する基準 |
| 開拓ゲームの仕様・実装 | `feature/ce-simu` / `3fc47a447` | `docs/plan/settlement-founder-game.md` §2.3・§8.6・§10・§22、およびSF描画の参照 |

feature側のファイルは `git show feature/ce-simu:<path>` で確認した。developにSFコードや設計書を取り込む作業は行っていない。以下の `N01` 等は本資料内の制作候補IDであり、実装済みのモデルIDではない。

**「BV未登録」と「CEから配置できない」は別の不足である。** BVの `main.ts` は `src/buildings/medieval/*Models.ts` をglobで登録し、住宅・井戸・荷車・容器・材木置場などは専用の登録経路も持つ。`MEDIEVAL_VARIANTS` や `PLACEABLE_OBJECTS` だけを検索して未登録と判断しない。建物一式に埋め込まれた小物は、単体で使えるBVモデルとしては未登録とする。

## 2. 優先して用意する未登録モデル

優先度は、P0＝伐採・運搬・共同小屋の最小循環、P1＝初収穫・冬越し、P2＝世帯化・家畜・村の成立とする。これは制作順の提案であり、SFの各段階ですべての見た目が実装済みという意味ではない。「新規」は独立した登録モデルがなく、「抽出」は既存の合成モデルの部品を再利用でき、「移設」はfeature側に描画実装があるものを示す。

## 4. BVオブジェクトの追加だけでは解決しない描画

次の項目も開拓景観に必要だが、任意の土地形状に沿うため、固定モデルを追加するだけでは成立しない。BVには代表例を見せる確認用の場面を作り、CE側で実形状に沿って描く。

| ID | 必要な景観 | 主な対応先・既存との関係 |
| --- | --- | --- |
| L01 | 森→伐採跡→根株のある開墾地→抜根済み土面 | CEの地表状態・森林の描画とN04・N05。森の密度を変えるだけで畑完成としない |
| L02 | 菜園、耕起・播種・生育・刈取り後の畑、休閑地、牧草地 | `src/city3d/three/farmMeshes.ts` の面・畝・群落を再利用し、必要な作業状態を追加。近景だけN14を重ね、全域に作物を1本ずつ置かない |
| L03 | 露天の脱穀場、作業土間、仮の資材置場 | 任意輪郭の締め固めた地面。N06・N13の物品と別に描き、建物を自動追加しない |
| L04 | 踏み跡・土道・轍・側溝 | 道の中心線・幅・縦断に沿う帯。水域と建物を避ける。featureの土道表示はBVの未登録小物とは数えない |
| L05 | 便所・ごみ穴・貯蔵穴・竪穴の掘込み、地下室の盛土 | 地面の切抜き・斜面とN07〜N12を組み合わせる。完成した地面の上に暗い箱を置くだけで穴を表したことにしない |
| L06 | 防火・給水用の村の池、川岸の水汲み場 | 保存した水域・岸・地形と接近路。池は固定の青い円盤ではなく任意輪郭の地形として作る。井戸は既存モデル |
| L07 | 工事の縄張り・柱穴・掘削土・足場、部分使用・完成後の差 | N01の施工モデルと実際の施工状態を接続。縄張りの線や選択枠は操作表示として分離し、恒久オブジェクトとして登録しない |

河川を渡る必要が出た場合も、水面上を道でつないで済ませない。既存橋モジュール・渡し場などの条件を別に定義し、橋はプロジェクト共通の斜角制約で判定する。土塁・防御木柵・施療院など町の段階の不足は今回の優先一覧には含めない。

## 5. 制作・登録・CE接続の進め方

1. **最初はN01を共有化する。** `feature/ce-simu` の施工表示・部材配置の依存を確認し、描画に必要な寸法と段階だけを受け取る生成器を `src/buildings` 側へ移す。BVがSFのゲーム状態やWorkerをimportする構成にはしない。SF積算と描画の柱数・垂木数の一致を保持する。developへの取り込みは別の実装作業として行う。
2. **P0を1場面で揃える。** N02〜N06を制作・抽出し、森の縁、伐採跡、道、置場、建築途中・完成した共同小屋を並べて、クォータービューの距離で見分けられるか確認する。先に材木置場の部品を単体化し、同じ丸太・梁を別実装で増やさない。
3. **P1を食料・衛生・冬越しに沿って追加する。** 穀倉・薪小屋・容器は既存を使い、N07〜N15の不足分とL02・L05を優先する。畑の全作物・全季節の精細モデルを先に作り切る必要はない。
4. **P2は実際に導入する暮らしに合わせる。** 住民・家畜、信仰施設、炭焼きを導入する順に追加する。地域・時代の適合と必要種を確定してから変種を増やす。
5. **BV登録後にCE接続を確認する。** BVは閲覧場所であり、登録しただけではCEの生成・手動配置・保存に現れない。`PLACEABLE_OBJECTS` による点配置か、`medievalDefinition` 等による生成配置か、寸法を持つ専用契約かを用途ごとに決める。N01の任意寸法は一様な `objectScale` のみでは保存できない。既存の[手動都市編集計画](ce-manual-city-authoring.md)の未実装部分を完成済みとして扱わない。

モデル共通の受入条件:

- メートル単位、地面に対する原点、正面、実際の包絡寸法を明記する。SFとCEで向き・寸法を変換でき、非等方拡大で柱の太さや屋根勾配を変えない。
- 作者・派生元を既存の仕組みに登録する。独立したBV項目と再利用できる生成関数を用意し、三角形数・材質数・資源解放を確認する。品質・変種は必要なものだけを登録する。
- 物の状態は入力で指定する。空の置場に固定の資材山を描いたり、頭数ゼロで家畜を置いたり、工事中に完成時の屋根を出したりしない。大量の在庫・群れは見た目の代表数と実数量を区別し、表示個数を制限する。
- BVで上面・正面・クォータービュー、CEの実縮尺で他の建物との比較を確認する。穴や地形を伴うモデルは単体と地形込みの両方を確認する。
- CE接続時は位置・回転・寸法・段階が保存と読込で保たれ、再生成で別の施設や住宅が増えないことを関連テストで確認する。施工を共有化する場合は既存SFの部材数・積算との一致も確認する。
