# 遠距離交易の商会の到達範囲と運転資金 (Long-Distance Merchant Reach and Capital) 設計

2026-10-19 設計。未実装。[approach-commerce-quarters.md](approach-commerce-quarters.md) §10「経済モデルの遠距離交易が細い」の対応(再計測は同 §4.5)。

## 状態

- 設計のみ。実装は §8 の段階計画に従う。
- 前提: [luxury-value-demand.md](luxury-value-demand.md) で高額品の継続的な需要(§10 の候補 (1))は入った。それでも、24 日以上の高額品の交易は 3 年目にほぼなくなる(approach-commerce-quarters.md §4.5)。
- 本設計は残る 2 つの関門を扱う。
  - 商会の到達範囲: 高額品の組の 55〜83% を除外している。§10 の候補 (2)。
  - 商人の運転資金: 3 年目に、成立件数の 6〜43 倍の組を止めている。§4.4 にはなかった関門。
- 調査用に追加済みの API: 観測ビュー `trade()`(`--sample-detail trade`、`observe/trade`)。交易の照合で、組がどの段階で止まったかを数える(`tradeStageObserver.ts`)。

## 1. 目的

1. 本拠地から遠い市場どうしでも、両方に支店を持つ商会があれば、高額品を運べるようにする。
2. 運転資金を、実際のお金の流れ(出資と代金の決済)に結び付ける。お金を生まない形で、遠距離の交易に必要な額(所要日数の分だけ寝かせる資本)を賄えるようにする。
3. 遠距離交易の量を、所要日数・商会の網・資本の制約から決まる値にする。「3 年目に消える」状態から、続く状態にする。

### 非目的

- 積荷の規則(価値密度による距離の上限、傷み)は変えない。嵩物を陸路で遠くへ運ばないのは史実に合う(approach-commerce-quarters.md §4.4。候補 (3) は現状維持)。
- 海外交易(`overseasRelations.ts`)と海軍の偽装交易(`navyTrade.ts`)は扱わない。
- 商会の NPC(人物の雇用・役職)は増やさない(`MERCHANT_ORGANIZATION_STAFF_ENABLED` は false のまま)。

## 2. 現状(コード確認)

### 2.1 商会の到達範囲

| 項目 | 現状 | 場所 |
| :--- | :--- | :--- |
| 商会の数と規模 | 市場ごとに 1 つ(管理人と競合商人で構成)。すべて `major` | `merchantOrganizations.ts syncMerchantOrganizations` |
| 所要日数の上限 | `major` 50 日。`local` の 12 日は小さな村の制限にだけ使う。`regional` の 25 日は使われていない | `ORGANIZATION_MAX_TRADE_DAYS` |
| 本拠の範囲(home ground) | 次のいずれかを満たすこと: 一方が本拠地の市場/どちらかが本拠国の市場/本拠地から直線 400 km 以内 | `isInHomeGround` |
| 小さな村 | 端点の中心都市の人口点が 10 未満なら 12 日まで(金属は除く) | `canOrganizationServeTrade` |
| 支店 | 本拠地と、交易範囲内で最も近い 3 市場から始まる。自分のキャラバンが着いた市場に開く | `merchantIntelligence.ts` |
| 相場 | 両方の市場に支店を持つ商会がないと交易しない。支店の相場は本拠地までの所要日数だけ遅れて届く | `knownTradePrices` |

到達範囲の判定(`isMarketTradePermitted`)と支店の判定(`knownTradePrices`)は別々の関門になっている。両方の市場に支店があっても、本拠の範囲の外なら交易できない。

### 2.2 運転資金

| 項目 | 現状 | 場所 |
| :--- | :--- | :--- |
| 資本の元 | 市場の `tradeWorkingCapital`。開始時に、市場内の都市の金庫の合計の 10〜30% から作る。**金庫からは引かない**(お金が生まれる) | `merchantTradeCapital.ts ensureTradeCapital` |
| 輸出の予約 | 輸出の倉庫に積むときに、原価分を固定(lock)。足りなければ予約しない | `exportStaging.ts bookFromRetail` |
| 通貨不足 | 鋳貨が足りない国では、使える額に係数(下限あり)を掛ける | `currencySufficiency.ts` |
| 到着 | 固定を外し、**原価の 8% を利益として資本に足す**(対価のないお金) | `settleArrival` |
| 損失 | 固定の 85% を失う | `settleLoss` |
| 代金の決済 | **市場間の交易で、輸入側の市場から輸出側の市場への支払いはない**。品物だけが動く | `caravans.ts`(`marketTreasury` を動かさない) |

### 2.3 計測(approach-commerce-quarters.md §4.5 と追加の診断)

- ゴールデン fixture(5 市場、3 年):
  - 高額品の組の 55〜83% が、到達範囲の外として除外される。到達範囲の内訳(50 日超・本拠の範囲外・小さな村)は数えていない。
  - 運転資金不足は、3 年目に高額品で 51〜346 組、全品目で 721〜961 組。
- 同じ fixture で、市場ごとの資本を 3 か月ごとに見た:
  - 資本の総額が増えない(例: 186、370、185 のまま 3 年横ばい)。
  - 固定されたまま出荷されない輸出の倉庫の荷がある。市場 1 では 10 件・固定 121 が 2 年以上動かない。市場 2 の荷は 5 件から 24 件に増えた。
  - 通貨不足の係数は 0.55〜0.65。
  - 注意: fixture は `moneyScaleBase` を持たない古い地図(K=1)で、お金の量が今の地図の約 1/16。資本の小ささには、この影響が入っている。
- province 地図(K=16、15 年): 資本の総額が増え続ける(seed 101: 1.3 万 → 4.7 万、年 約 2,400)。到着時の 8% の利益が、対価のないお金として資本に足されている。

## 3. 史料調査の要点

信頼度の目安: ◎ 学術・一次史料に基づく、○ 学術機関の解説・研究プロジェクト、△ 一般向け解説。

- **支店網と所要日数**(○ Wesleyan Travelers Lab の Datini 書簡の分析): Datini 商会は Florence・Prato を本拠とし、Pisa・Genoa・Avignon・Barcelona・Valencia・Palma に支店(fondaco)を持ち、Bruges・London とも取引した。書簡の所要日数は、Barcelona–Valencia(約 350 km)がおおむね 6〜7 日、Palma–Florence が 30〜45 日。
  → 大商会は本拠地から 1 か月以上離れた市場に支店を置き、その間で取引した。到達範囲を決めるのは「本拠地からの距離」ではなく「支店網」。
- **外地の拠点**(○ ハンザの商館(Kontor)。Bruges・London・Bergen・Novgorod): 本国から遠い市場に常設の拠点を置き、そこを起点に取引した。
  → 本拠国・本拠地の 400 km 以内に限る今の規則は、遠い支店の働きを表さない。
- **資本の集め方**(○ commenda / colleganza の解説、◎ Pryor・Williamson の研究): commenda は、居残る出資者が資本を出し、旅する商人が取引する契約。出資者は元本と利益の約 3/4 を受け取り、損失は出資者が負った。Williamson は、Venice の辺境の交易では借入(debt)が主な資金源だったとする。
  → 遠距離交易の資本は、市場に湧く資本ではなく、富を持つ者の出資と借入で集まった。資本は航海の間ずっと寝かされ、帰ってきた代金で返された。

## 4. 到達範囲の見直し

### 4.1 支店があれば本拠の範囲を問わない

`canOrganizationServeTrade` の本拠の範囲の判定を、次のように改める。

```text
両方の市場に、その商会の支店がある     → 本拠の範囲を満たす(外地の商館)
どちらか一方が本拠地の市場             → 満たす(従来どおり)
どちらかが本拠国の市場 / 本拠地から 400 km 以内 → 満たす(従来どおり)
```

- 支店の判定(`knownTradePrices` が見る `housesPresentIn`)と同じ情報を使う。2 つの関門のずれ(§2.1)がなくなる。
- 小さな村の制限(人口点 10 未満は 12 日まで)は残す。大商会は辺境の村とは取引しない。

### 4.2 所要日数の上限を品目で変える

`major` の 50 日を一律に掛けず、積荷の価値密度で上限を変える。

| 積荷 | 上限 | 根拠 |
| :--- | :--- | :--- |
| 高額品(`luxury`・`art`・`gift`・`ritual`、または高額品の需要を持つ上・極上の品) | 90 日 | Palma–Florence の書簡 30〜45 日。往復と荷待ちを含めて約 2 倍 |
| その他 | 50 日(従来どおり) | — |

- 積荷の規則(`isGoodTradePermittedForShipment`)の価値密度による上限は別にかかる。嵩物は今までどおり遠くへは行かない。

### 4.3 支店の開き方

今は「自分のキャラバンが着いた市場」にしか支店を開かない。到達範囲の外の市場には最初の 1 台が出ないので、支店網が広がらない(鶏と卵)。次の 2 つを足す。

1. **外地の商館を初めから置く**: `major` の商会は、本拠国の外の首都の市場のうち、所要日数が上限(§4.2 の高額品の上限)以内のものを最大 2 つ選び、支店を持って始める。地図の生成時と、既存の地図を読み込んだときの初回に置く。
2. **相場の噂で開く**: 支店のない市場との価格差(高額品)が 6 か月続いたら、その市場に支店を開く。開いた支店の相場は、§2.1 と同じく所要日数だけ遅れて届く。

## 5. 運転資金の見直し

### 5.1 代金を決済する(資本の出所と行き先を実際のお金にする)

| 時点 | 今 | 改めた後 |
| :--- | :--- | :--- |
| 輸出の予約 | 原価分を資本の中で固定するだけ | 原価を、商会の資本から輸出側の市場の現金へ払う(資本 → 輸出側の市場) |
| 到着 | 固定を外し、原価の 8% を資本に足す | 輸入側の市場が、知っていた価格(`knownImporterPrice`)で払える分を買い取る(輸入側の市場 → 資本)。利益は売値 − 原価 − 運賃で、損をすることもある |
| 損失 | 固定の 85% を失う | 払った原価は戻らない(品物が消えた分だけ資本が減る) |

- 市場間の交易に、初めて代金の流れができる。今は輸出側の市場が品物を失うだけで、何も受け取っていない(§2.2)。
- 到着時の 8% の利益(対価のないお金)は廃止する。
- 輸入側の市場の現金が足りなければ、払える分だけ買い取り、残りは輸入側の市場の在庫として掛けで受け取る(未払いとして記録し、次の周期以降に返済する)。穀物の掛け(`ruralGrainPayable`)と同じ扱い。

### 5.2 資本を出資で集める(commenda)

商会の資本(`tradeWorkingCapital`)を、湧くものから出資で集まるものに改める。

1. 開始時: 市場の現金の一部を商会の資本に移す(移した分は市場の現金から引く)。都市の金庫から作る今の方式はやめる。
2. 毎周期の出資: 次の 2 つの出資先として商会の資本を加える。
   - 富を持つ人物の余剰の支出(`characterLivingCosts.ts` の余剰の支出のうち、`marketManager`・`marketRival` は一部を自分の商会へ)
   - 市場の利益の払い出し(`payOutMarketSurplus`)の一部
3. 返還: 資本が「固定されていない額 > 直近 1 年の予約額の 2 倍」を超えたら、超過分を出資者の比で返す(人物の富・市場の現金へ)。commenda の利益の配分(出資者 3/4、商人 1/4)は、返還の時に、出資者と商会の構成員の人物に分ける。

これにより、[luxury-value-demand.md](luxury-value-demand.md) §9 の「商人の人物の 7 割が無一文」にも、利益が届く道ができる。

### 5.3 動かない荷の固定を外す

- 輸出の倉庫で、荷待ちの上限(`tradeLogisticsSettings` の `maxWaitDays*`)+ 所要日数を超えて積まれない荷は取り消す(`cancelLot`)。在庫は市場に戻し、資本の固定を外す。
- §2.3 で 2 年以上動かない荷が見つかった。なぜ積まれないのか(輸送手段の不足・積載の目標・行き先の消失)は、R0 で原因を調べてから規則を決める。

### 5.4 通貨不足

通貨不足の係数(§2.2)はそのまま残す。鋳貨が足りない国では、資本を寝かせにくい。これは史実の「地金の飢饉」に合う。

## 6. 設定と互換性

- 世界の設定 `fmg-long-distance-trade`(`"on"` で有効)。シミュレーションの結果を変えるので `WORLD_SETTING_KEYS` に入れ、.fmg に保存する。
- 較正が済むまでは、新しい地図の既定も `off`。較正後に `NEW_WORLD_SETTING_DEFAULTS` で新しい地図だけ `on` にする(既存の地図は変わらない。luxury-value-demand.md §6 と同じ扱い)。
- 新しい保存の状態:
  - 商会の資本の出資者の内訳(出資者の種類ごとの残高)
  - 輸入側の掛け(未払い)
  
  旧セーブにはないので、読み込み時に「出資者 = 市場」として作る。
- `off` では golden を変えない。

### 7.1 計測用の地図

- ゴールデン fixture は K=1 の古い地図で、お金の量が今の地図と違う(§2.3)。到達範囲の比較には使えるが、資本の比較には使えない。
- province 地図は市場どうしが近く、遠距離の検証にならない。
- R0 で、K=16 で市場が 5 以上あり、市場間の所要日数が 24〜90 日になる地図を用意する。候補:
  - `generateSmallMaps.mjs` の province より広い範囲の生成
  - 通常の世界地図の生成(map-server)
  
  用意した地図の所要日数の分布は `trade()` の `deals.*.days` で確かめる。

## 9. リスクと未決事項

- **代金の決済で、輸入側の市場の現金が減る**: 高額品を多く買う首都の市場の現金が、町の購入(luxury-value-demand.md)を支えられなくなるおそれがある。R1 で、市場の現金と町の金庫の推移を見る。
- **門の流れ(CE)への影響**: 遠距離の交易が増えると、通過交通の門の価値の比(approach-commerce-quarters.md §4.2)が変わる。市場内の出荷が主という前提が崩れないかを R4 で確かめる。
- **外地の商館の選び方**: 首都に限るか、港・大きな町を含めるか。戦争中の国(敵国)の市場に支店を置くかは未決。
- **商会の規模**: 今はすべて `major`。`local`・`regional` を復活させて市場の規模で分けるかは、R2 の結果を見て決める。
- **積まれない荷**: 原因によっては、輸送手段(`MerchantTransportAssets`)や荷待ちの規則の設計に及ぶ。R0 の結果で範囲を決め直す。
- **河川と橋**: 本設計は経路を変えない。経路の橋の判定は `src/utils/bridgeSkewPolicy.ts` のまま。
