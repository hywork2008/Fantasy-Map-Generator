# 農業労働の校正（史料調査）

## 0. 目的

[rural-food-labor-audit.md](rural-food-labor-audit.md) の問題 C では、「労働の不足が収穫を減らさない」ことを直すつもりだった。ところが、労働の充足率を収穫に掛けると、充足率は0.43になり、収穫が半分以下に落ちた（同 §6.3）。

本書は、その前提になっている4つの値を史料で確かめ、校正の案を示す。

1. 成人1人の年間の農作業日数（`WORKABLE_DAYS_PER_ADULT = 140`）
2. 月ごとの労働能力（今は一律 `140 ÷ 12 = 11.7日`）
3. 1 ha あたりの労働日数（`LABOUR_DAYS_PER_HECTARE = 30`）と、作業の月への配分（`labourByStage`）
4. 労働で耕せる以上の面積を、土地利用の台帳が割り当てていること

**2026-10-18 起案**。本書は史料調査と校正の案である。

**2026-10-18 実装（案 1〜3）**: §6 に結果を書く。

**2026-10-18 実装（案 4 の収穫の部分）**: すぐに掛ける方式で実装した（§7）。対象は既にある畑だけで、新しい開墾は別の労働の枠（`settlementClearance.ts` の `clearanceLabor`、140日/ha、畑の維持の後の残り）で進む。人口の上限と土地利用の台帳の変更は未着手。

**2026-10-18 実装（案 5）**: 季節の出稼ぎを、市場圏の中の町と農村からの収穫の手伝いとして実装した（§8）。

## 1. 史料

### 1.1 年間の労働日数

| 出典 | 値 | 備考 |
| --- | --- | --- |
| Columella 2.12.8–9 | 290日/年 | 祝日・悪天候45日、播種後の休み30日を除く（ローマ） |
| 中世キリスト教圏の推計 | 約270日 | 日曜と約45の祝日を除く |
| Clark (2018) | 250〜300日 | |
| Kenyon (1934) | 通常は308日、日雇いの一部は120日 | Schor が引いたのは120日の方 |
| Clark (1986、未刊行。二次資料経由) | 家族で自分の土地に150日、成人男子135日 | |
| 14世紀の荘園帳簿 | 隷農の労働者 約175日 | 二次資料経由 |

- 成人男子の実働は250〜300日だった。そのうち自分の畑の作業は135〜150日ほどで、残りは家畜の世話、運搬、雇われ仕事、手工業などである。
- 女性が畑に出るのは主に繁忙期（収穫）で、普段は家事・家内工業・家畜の世話をした。16歳以上の男子は成人の約4分の3、10〜15歳の子は約半分の労働として数える推計がある（Devereaux）。

**判断**: 男女の成人をならした「農作業に回せる日数」140日は、これらの史料と矛盾しない。変えない。

### 1.2 収穫期の集中

- 収穫期は、村じゅうの働ける人が日の出から日没まで働いた（複数の二次資料）。女性は刈り取りの後の束ね・積み上げ（stook）を担い、落ち穂拾いは子ども連れの女性が中心だった。男女の分担はあいまいだった（Many-Headed Monster、State Library Victoria）。
- 荘園の直営地では、1年の作業の大部分を常雇いの famuli がこなした。賦役（boon work、Reapale）と臨時雇いは、収穫と犂耕の時期に集中した（Goose、Meopham 1307–75、Walsham の研究）。c.1300の400超の荘園の帳簿では、famuli は男性中心の1段目と、女性・若者・老人の2段目に分かれていた（LSE の研究）。
- 収穫の前後には大きな祭りが集まるが、収穫期そのものは休みが少ない。

**判断**: 収穫の月は、成人1人が平月の約2倍、日曜・祝日以外のほぼ毎日（約24日）働いたとみてよい。今の一律11.7日では、収穫の月に必要な人手が平月の6倍になってしまう（§2）。

### 1.3 1 ha あたりの労働と、作業の時期

| 出典 | 小麦 | 備考 |
| --- | --- | --- |
| Columella | 44人・日/ha（収穫を除く）＋刈り取り5.7 | 犂耕4回、中耕2回の集約的な地中海の栽培 |
| Columella を補正（Spurr、Rosenstein） | 1 iugerum あたり14.25〜19.5日（57〜78日/ha） | 脱穀など Columella が省いた作業を含む |
| Clark の1300年ごろの推計（既存の設計書） | 1 acre あたり成人男子11〜14日（27〜35日/ha） | イングランド |
| 鎌での刈り取り | 10〜30人・日/ha | 脱穀・風選は刈り取りとほぼ同じ労働 |

- **脱穀は冬の仕事だった**。北欧では刈った穀物を束のまま納屋に置き、冬に屋内の脱穀場で殻竿（flail）で打った（Reading 大学の農村博物館の所蔵品記録、Met Museum の Cloisters の記事、Patcham 荘園の研究）。豊作の年は翌年まで続いた。
- **脱穀は量に比例して支払われた**。1319–20年と1350–51年の荘園の帳簿（Merton）では、脱穀は穀物1 quarter あたりの出来高払いだった。脱穀の労働は、面積ではなく収穫量に比例する。
- 犂耕と播種は、秋分から12月初めまでの2か月余りに分散した（Columella）。休閑地は春・夏・秋に1回ずつ耕した。

**判断**:

- 30日/ha は、イングランドの水準（Clark）として妥当である。地中海の集約栽培（57〜78日/ha）は別の体系とみる。
- 一方、今の作物暦（`stapleCrops.ts` の `labourByStage`）は、収穫と脱穀を合わせた「harvestAndProcessing」の0.50〜0.55を、収穫の30〜45日に詰め込んでいる。史料では、脱穀は収穫の後の冬に分散し、量に比例する。

## 2. モデルとの差（seed 102、地図生成直後〜13か月）

| 項目 | モデル | 史料 |
| --- | --- | --- |
| 年間の農作業日数 | 140日 | 135〜150日（家族、自分の畑） |
| 収穫の月の労働能力 | 11.7日（一律） | 約24日（平月の約2倍） |
| 収穫の月に集中する作業 | 年の50〜55% | 刈り取り・束ね・運搬で約30%。脱穀は冬 |
| 脱穀の労働 | 面積に比例 | 収穫量に比例（出来高払い） |
| 収穫の月の必要人手 ÷ 年平均 | 0.55 × 140 ÷ 11.7 ≒ **6.6倍** | 0.30 × 140 ÷ 24 ≒ **1.75倍** |

seed 102 は南緯43〜57度、年平均気温7℃、年降水量1,500 mm ほどの冷涼で多湿な地図である。収量の倍率の中央値は約0.38（169 kg/ha）と低い。

- 年単位で見ても、畑の作業が成人 × 140日を超えるセルに、農村人口の40%が住んでいる。
- 脱穀を量に比例させても（労働の3〜4割を量比例とする）、その割合は31〜34%までしか下がらない。年単位の充足率で見た収穫 ÷ 必要量は、0.83 → 0.89〜0.91 になる。
- 残る不足の原因は、地図を作る時の人口の上限（`subsistenceCapacity`）が、収量の低い土地で「自分たちの労働で耕せる面積」を見ていないことである。土地利用の台帳も、労働で耕せる面積を超えて `必要面積 × 1.1` を割り当てる（`planSettlementLandUse`）。
- 史実では、こうした冷涼で多湿な土地は、牧畜の比重が高く、人口密度も低かった。

## 3. 校正の案

### 案 1: 作物暦の作業配分を、収穫と脱穀に分ける（`stapleCrops.ts`、`cropCalendars.ts`）

- `harvestAndProcessing` を、次の2つに分ける。
  - `harvest`（刈り取り・束ね・運搬）: 収穫の期間に配分する。
  - `processing`（脱穀・風選）: 収穫の後の4〜5か月（冬）に均等に配分する。
- 出発値は、穀物で `establishment 0.20 / maintenance 0.25 / harvest 0.30 / processing 0.25`。脱穀≒刈り取りという史料に合わせる。
- 犂耕・播種（`establishment`）は、1か月ではなく2か月に分ける。

### 案 2: 脱穀の労働を収穫量に比例させる（`agriculturalLandUse.ts`）

- 1 ha あたりの労働日数を、面積に比例する部分と、収穫量に比例する部分に分ける。
  - `LABOUR_DAYS_PER_HECTARE × (1 − PROCESSING_SHARE + PROCESSING_SHARE × 収量 ÷ 450)`
  - `PROCESSING_SHARE = 0.25`（案 1 の processing の割合）。基準の450 kg/ha は、30日/ha を校正したイングランドの水準である。
- 収量の低い土地では、脱穀の分だけ労働が減る。

### 案 3: 月の労働能力を、収穫の月だけ引き上げる（`ruralOccupationAllocation.ts`）

- 月の労働能力を `WORKABLE_DAYS_PER_ADULT_PER_MONTH × 月の倍率` にする。倍率は、その月の作業量が年平均を超える月で最大2.0（約24日）とする。
- 年間の上限（140日）は `getAnnualRequiredAdults` で今どおり守る。繁忙月に多く働いた分、閑散月は働かない。
- 互助（隣のセル）と家族の手伝い（子ども0.35・老人0.4）は、今の値のまま残す。

### 案 4: 収穫に労働の充足率を掛ける（問題 C の本体）

- 案 1〜3 の後で、`seasonalLaborShortage` から求めた充足率を、セルの収穫に掛ける。
- 地図を作る時の人口の上限（`subsistenceCapacity` の農業の分）にも、同じ労働の充足率を掛ける。自分たちの労働で耕せない面積は、上限に入れない。
- 土地利用の台帳の割り当て（`max(必要面積 × 1.1, 労働で耕せる面積)`）は、労働で耕せる面積を上限にする。
- 旧セーブでは、最初の年に収穫が下がる。それでも人口は数年で、労働と食料の釣り合う水準へ移る。ここは移行の影響として受け入れるか、充足率を数年かけて掛け始めるかを決める必要がある。

### 案 5: 季節の出稼ぎ（問題 E）

- 案 4 の後で、残った `seasonalLaborShortage` を、近くの都市の住民が収穫の月だけ農村で働いて埋める。
- 史料（rural-food-labor-audit.md §1.2）に合わせ、近世以降（Historical period）で強く、中世は互助と家族の手伝いだけにする。

## 4. 実装の順序（提案）

1. 案 1 と案 2（作業配分と脱穀）。月の不足と移住の余力が変わるだけで、収穫は変わらない。
2. 案 3（収穫の月の労働能力）。
3. 計測: 労働の充足率の分布と、年単位で労働が足りないセルの人口の割合。
4. 案 4（充足率を収穫と人口の上限に掛ける）と、移行の方法の決定。
5. 案 5（季節の出稼ぎ）。

案 1〜3 では収穫は変わらない。変わるのは雇用・移住の余力（`migratableAdults`、`ruralReleasePressure`）と、季節の不足の値である。ただし旧セーブの動きも変わるので、Node 用の基準データを更新する。案 1・2 は `agriculturalLandUse.ts` と作物暦を変えるので、地図生成側の収量の推定表（`foodClimateCalibration.json`）も作り直す。

## 6. 案 1〜3 の実装と結果（2026-10-18）

### 6.1 実装した内容

- **案 1**（[cropCalendars.ts](../../src/data/cropCalendars.ts)、[seasonalCropClimate.ts](../../src/extensions/economy/generators/seasonalCropClimate.ts)、[stapleCrops.ts](../../src/data/stapleCrops.ts)）
  - `labourByStage` に `processing`（脱穀・風選）を足した。収穫が終わった月の翌月から4か月（`PROCESSING_MONTHS`）に均等に配分する。
  - 犂耕・播種（`establishment`）は、植え付けの月とその前の月に半分ずつ配分する。
  - 配分の値は次のとおり。根菜と永年作物は変えていない。
    - 寒冷地の穀物: 0.20 / 0.25 / 0.30 / 0.25
    - 温暖地の穀物・豆: 0.22 / 0.28 / 0.28 / 0.22
- **案 2**（[agriculturalLandUse.ts](../../src/extensions/economy/generators/agriculturalLandUse.ts) の `getYieldScaledLabourMultiplier`）
  - 作物の組み合わせのうち脱穀の割合の分だけ、1 ha あたりの労働を `収量 ÷ 450 kg/ha` に比例させる。
  - 年の労働の計算（`calculateAgriculturalLandProfile`）と、開墾・土地利用の台帳への入力（`reconcileForestClearanceForAgriculture`）の両方に入れた。
- **案 3**（`getMonthlyWorkDaysPerAdult`、[ruralOccupationAllocation.ts](../../src/extensions/economy/generators/ruralOccupationAllocation.ts)）
  - 畑の作業が月平均を超える月は、成人1人の月の労働日数を最大2倍（約23日、`PEAK_MONTH_WORK_MULTIPLIER`）にする。
  - 次の4か所で使う: 職の割り当て、隣のセルの互助の余力、家族の手伝い、季節の不足。
  - 年間の必要人数は、今どおり年140日で数える。
- 地図生成側の収量の推定表を作り直した。計算は約290秒かかるため、計算時だけ実行するテストの時間制限を900秒に延ばした。

### 6.2 結果（seed 102、Independent、13か月後）

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| 季節の不足 ÷ 年の必要労働 | （畑の作業の約57%） | 21% |
| 季節の不足を収穫に掛けた場合の、収穫 ÷ 必要量（試算） | 1.04 → 0.45 前後 | 1.05 → **0.94** |
| 必要労働 ÷ 成人（人口加重） | 1.34 | 1.22 |
| 必要労働が成人を超えるセルの人口の割合 | 40% | 38% |

- 案 1〜3 は収穫を変えない。変わるのは、職の割り当て・移住の余力・季節の不足である。
- 季節の不足を収穫に掛けた場合（案 4）の影響は、収穫の約1割減まで小さくなった。案 4 を入れられる段階になった。
- 必要労働が成人を超えるセルは、まだ人口の約4割ある。地図を作る時の人口の上限と土地利用の台帳が、労働で耕せる面積を見ていないためで、案 4 の後半（人口の上限と台帳の面積）で扱う。

### 6.3 次の判断

案 4 の移行の方法を決める必要がある。

- **すぐに掛ける**: 旧セーブと既存の地図では、最初の年に収穫が約1割下がる。
- **数年かけて段階的に掛ける**: 例えば5年かけて、充足率の効き目を0から1まで上げる。

## 7. 案 4（収穫に労働の充足率を掛ける）の実装と結果（2026-10-18）

### 7.1 実装した内容

- `getCropLaborCoverageByCell`（[developmentPotential.ts](../../src/extensions/economy/generators/developmentPotential.ts)）
  - 毎年の農業の更新で、セルごとの充足率を求めて `cropLaborCoverage` 列に保存する。
  - 充足率 = 1 − Σ月 min(畑の作業日数, 季節の不足) ÷ Σ月 畑の作業日数。不足は畑の作業に先に充てる。
- [foodProduction.ts](../../src/extensions/economy/generators/foodProduction.ts) で、セルの収穫に充足率を掛ける。旧セーブで列がない間は 1 として扱う。
- **すぐに掛ける**方式にした。対象は地図を開いた時点で既にある畑で、地図の開始前の開墾は済んでいる扱いである。新しい開墾は、畑の維持の後に残った労働の一部（専用の枠）で、140日/ha をかけて進む。
- 次の2つは見送った。
  - **土地利用の台帳を、労働で耕せる面積に抑える**: 季節の不足は、年単位の不足も含んでいる。両方を入れると不足を二重に引く。
  - **地図を作る時の人口の上限**: 地図生成側の推定に関わるので、別の作業とする。

Megacity で成人が都市へ出ると、村の畑の労働が足りなくなり、農村の自給が下がる。「出しすぎると食料が減る」釣り合いが表れた。

### 7.3 残っている課題

1. 地図を作る時の人口の上限（`subsistenceCapacity`）に、労働の充足率を入れる。
2. 案 5（季節の出稼ぎ）。Megacity では、蓄えの尽きた農村の住民が3割に増えた。都市から農繁期に人が戻る仕組みが効く場面である。
3. 都市の受け入れ枠の後背地の余剰（`hinterlandSurplusUrbanPoints`）は、まだ土地の能力（`ruralFoodCapacity`）で数えていて、労働の充足率を見ていない。
4. seed 103 の15年の sim は、1024MB の上限で、最後の保存の時にメモリが足りなくなった。標本は60件とも出力済み。

## 8. 案 5（季節の出稼ぎ）の実装と結果（2026-10-18）

### 8.1 実装した内容

`applyRegionalHarvestHelp`（[ruralOccupationAllocation.ts](../../src/extensions/economy/generators/ruralOccupationAllocation.ts)）

- 毎月、家族の手伝いと隣のセルの互助で埋めても残る不足を、同じ市場圏の中の次の2つで埋める。
  - **町の手伝い**: 市場圏の町の成人 × `getUrbanHarvestHelpShare`。繁忙月の日数（約23日）で働く。先に使う。
  - **旅する農村の働き手**: 市場圏の他のセルで、その月に手の空いた成人の日数 × `getRegionalHarvestMobility`。
- 埋めた日数は、受け入れたセルの「受けた手伝い」として数える。不足（`seasonalLaborShortage`）と収穫の充足率（`cropLaborCoverage`）が改善する。旅に出た働き手は、自分のセルの暦で雇われた扱いになる（互助と同じ）。
- 時代ごとの値は次のとおり。いずれもゲーム上の校正値である。

| 時代 | 町の成人のうち収穫に出る割合 | 手の空いた農村の成人のうち旅に出る割合 |
| --- | --- | --- |
| lateMedieval 以前（古代を含む） | 5% | 25% |
| 近世（ageOfExploration・maritimeEra） | 10% | 40% |
| それ以降 | 15% | 50% |

- 中世の荘園でも、臨時雇いが収穫の重要な担い手だった（Goose）。数か月だけ来て帰る大規模な出稼ぎは、近世以降に大きくなる（rural-food-labor-audit.md §1.2）。時代ごとの割合の差はこれに合わせた。

## 9. 人口の上限と都市の受け入れ枠に労働を入れる（2026-10-18）

### 9.1 実装した内容

- **自分たちの労働で作れる穀物の割合**（`getFieldLabourFeasibility`、[settlementClearance.ts](../../src/generators/settlementClearance.ts)）
  - 1人が必要とする畑の面積 × 1 ha あたりの労働（脱穀の分は収量に比例）を、成人の割合（0.45）× 年140日と比べる。
  - 収量がおおむね 200 kg/ha 以上なら1（自給できる）。150 kg/ha で0.82、110 kg/ha で0.62、80 kg/ha で0.46。
  - 労働の定数（30日/ha、140日、脱穀の割合0.25、成人の割合0.45）は、地図生成側に移して一本化した。経済拡張側は `LABOUR_DAYS_PER_HECTARE` と `WORKABLE_DAYS_PER_ADULT` として、同じ値を使う。
- **地図を作る時の人口の上限**（[subsistenceCapacity.ts](../../src/generators/subsistenceCapacity.ts)）
  - 農業で養える人数に、上の割合を掛けた（`generateSubsistenceCapacity`、`refreshEstimatedSubsistenceCapacity`）。
  - 毎年の更新（`reconcileSubsistenceCapacityFromFood`）も、労働で耕せる分の畑の能力（`labourLimitedFoodCapacity`）で行う。こちらは作物の組み合わせ・農業技術・輪作を反映した値である。
- **都市の受け入れ枠の後背地の余剰**（[urbanFoodCapacity.ts](../../src/extensions/economy/generators/urbanFoodCapacity.ts)）
  - 耕せる土地の全部ではなく、実際に耕している畑 × 労働の充足率で数える（`getWorkedFoodCapacity`）。
  - 漁村・牧畜の住民の穀物の割合の計算には、今どおり土地の能力を使う。

## 10. Megacity の受け入れ枠の調査（2026-10-18）

§9.3 の課題 1（受け入れ枠が食料に比べて大きすぎる）を調べた。結論として、**受け入れ枠は食料の上限になっていない。原因は、都市の家計のお金が1年の途中で尽きることである**。受け入れ枠は変えていない。

### 10.1 計測（seed 102、Megacity、計測用のスクリプト）

8年目の全体の値。単位は都市の人口点。

| 項目 | 値 |
| --- | --- |
| 都市の人口 | 755 |
| 受け入れ枠（`capacity`） | 1,032（上限は種の能力の3倍） |
| 後背地で実際に作っている余剰 | 2,202 |
| 後背地の土地の能力から見た余剰 | 2,731 |
| 輸入による枠の上乗せ | 67 |

- 後背地の余剰は都市の人口の約3倍ある。受け入れ枠は、余剰ではなく上限の倍率（3倍）で決まっている。
- 食料の充足が0.73〜0.82の市場（1・2・3・9番）では、市場の穀物庫に都市の需要の10〜13四半期分の在庫がある。農家が売りに出した量も、都市の需要の5〜11倍ある。

### 10.2 原因: 都市の家計のお金が尽きる

市場1番の四半期末の値（`settleMonthlyFoodConsumption`）。

| 月 | 農村の必要量 → 充足 | 都市の必要量 → 買えた量 | 在庫 |
| --- | --- | --- | --- |
| 12月 | 20,093 → 20,093 | 8,547 → 8,547 | 53,879 |
| 3月 | 20,134 → 20,134 | 8,551 → 7,040 | 130,869 |
| 6月 | 20,177 → 20,177 | 8,554 → 2,032 | 125,160 |
| 9月 | 20,221 → 20,221 | 8,556 → 169 | 116,932 |

- 在庫は十分にある。それでも都市が買える量は、春から秋にかけて減っていく。都市の購入は家計のお金で頭打ちになる（`drawBurgMonthlyNeed` の `maxAffordableUnits`）。
- 別の年の月ごとの家計を見ると、手元のお金（穀物価格で何か月分の食費か）は、毎月約0.6か月分ずつ減る（9.0 → 1.6か月、2月〜翌1月）。収入が食費の約4割しかない。年の変わり目に町の金庫から家計へまとまったお金が入り、持ち直す。
- これは引き継ぎ時点の「都市の食費 ÷ 必要量 27〜48%」と同じ問題である。Megacity では、移住者が都市の人口を増やすので、家計1人あたりの収入がさらに薄くなる。

### 10.3 見つかった不具合: 不足の割合の振り分け

- 四半期末の食料不足の割合は、農村と都市の不足の合計を両者に同じ割合で振り分けている（農村には揺らぎ0.8〜1.2倍を掛け、残りを都市へ）。
- 実際の取り崩しは農村が先で、上の表のとおり農村は毎月満たされている。それでも農村の不足の割合は0.27と記録され、農村の食料ストレスの数え方（`ruralFoodStressQuarters`）が誤って進む。都市の不足の割合もその分ずれる。

### 10.4 次の判断

1. **都市の家計の収入**（引き継ぎ時点のお金の較正の残り）。食料が足りているのに都市が飢える原因はこれで、Megacity の都市の伸びを止めている。案は2つある。
   - 生産の賃金の倍率（`WAGE_SUBSISTENCE_MULTIPLE = 1.5`）を見直す。
   - 移住者の職（雇用の需要）と賃金の支払いの対応を調べる。
   - → §11 で調べた。原因は別のところ（農家が町で使うお金が町の家計に入らない）にあった。
2. **不足の割合の振り分けの修正**（§10.3）。実際に満たされた量から、農村と都市の不足の割合を別々に求める。
3. **受け入れ枠の上限**（3倍）。家計が直った後に、まだ大きすぎるかを測り直す。

### 10.5 §10.3 の修正（2026-10-18）

- [foodLedgerConsumption.ts](../../src/extensions/economy/generators/foodLedgerConsumption.ts) の四半期末の不足の割合を、農村・都市それぞれの「必要量に対して満たせなかった割合」にした。合計の不足を同じ割合で振り分ける処理と、そのための揺らぎ（`getShortfallJitter`）は削除した。
- 回帰テストを追加した。農家は自分の蓄えで食べ、町には市場の穀物がない場合に、農村の食料ストレスが0のまま、都市だけ不足が数えられることを確かめる。修正前のコードでは、このテストは失敗する。

## 11. 都市の家計の収入（§10.4 の 1、2026-10-18）

### 11.1 計測: 都市の家計のお金の出入り

seed 102、Megacity、7年目から1年。お金を動かす処理ごとの都市の家計・都市の金庫の増減を、都市の年間の食費（地元の穀物価格）の何か月分かで表す（`createMoneyFlowRecorder` を使う計測用のスクリプト）。

| 処理 | 都市の家計 | 都市の金庫 |
| --- | ---: | ---: |
| 食料の購入（`food:consumption`） | −9.9 | — |
| 町での支出（`spendUrbanHouseholdSurplus`） | −1.2 | +1.2 |
| 生産の賃金など（`production:burgLoop`） | +3.1 | −1.8 |
| 市場の利益の払い出し（中心の都市、1月にまとめて） | +1.6 | — |
| 人物の生活費 | +0.8 | — |
| 行政の給与 | +0.6 | −0.5 |
| 海軍の乗員の給与 | +0.4 | — |
| **農家が町で使うお金（`spendRuralHouseholdsInTowns`）** | — | **+2.8** |
| 金庫の余剰の年1回の回収（`GuildTreasury.settleAnnual`） | — | **−20.8** |

- 都市の家計の収入は食費の約55%（12か月分に対して約6.5か月分）で、§10.2 の「収入が食費の約4割」と合う。
- **生産の賃金は需要で頭打ちになっている。** 都市の金庫には食費の8〜28か月分のお金があり、生産は金庫の残高ではなく、商品の需要で止まっている。§10.4 の案（`WAGE_SUBSISTENCE_MULTIPLE` を上げる）は、賃金の割合が高い商品の費用を上げるだけで、雇う量は増えない。
- **農家が町で使うお金が、町の人の収入になっていなかった。** 塩・道具・布・鍛冶・粉挽き・市の代金は、それを作って売った職人・商人・運び手の稼ぎである。ところが全額が都市の金庫に入り、金庫は生産の需要以上のお金を使えないので、年末に余剰として市場と国庫へ回収されていた。
- 移住者の職（§10.4 の2つ目の案）: 都市の雇用は生産の労働だけで、生産は需要で決まるので、人口が増えても賃金の総額は増えない。Megacity で1人あたりの収入が薄くなるのはこのためである。今回は扱わない（§11.4）。

| 生産の賃金 | +3.1 | +1.8 | +2.5 | +2.6 |
| 市場の利益の払い出し | 0 | +4.0 | +0.9 | +1.7 |
| 人物の生活費・海軍の給与 | +5.8 | +2.9 | +0.1 | 0 |
| 町での支出（金庫へ） | −4.8 | −9.1 | −0.8 | −1.6 |

（市場の利益の払い出しは、§12.2 の変更後の値）

- 首都と市場の中心は、食費を超える収入があり、余りを町で使って金庫に入れている。その他の都市は、収入が食費の8〜9割で、手元の現金は食費0.7か月分前後に張り付く。
- 市場ごとに見ると、飢える理由は3通りある（10年目の1年間）。
  1. **金庫にお金がある町で家計が飢える**（市場3）: 町の金庫には食費8.9か月分、家計は0.75か月分。金庫は、生産が使う以上のお金を持っている。
  2. **中心の都市だけが豊か**（市場2）: 首都は家計9か月分・金庫9か月分。周りの町は家計0.7か月分・金庫0.3か月分。市場全体の食料の充足は0.67。
  3. **市場全体にお金がない**（市場5・12・15）: 町の家計も金庫も0で、農家の財布も小さい。穀物の足りない農家が市場から買い戻している（年2万）。在庫は1年分以上あるのに、充足は0.1前後。
- 穀物そのものが尽きている市場はほとんどない（都市の必要量の1%）。

### 12.2 実装した内容

1. **市場の利益の払い出しを、市場のすべての町へ**（`payOutMarketSurplus`、[householdWealth.ts](../../src/extensions/economy/generators/householdWealth.ts)）
   - 商人の利益（1/3）を除いた残りを、市場の中心の都市だけでなく、市場のすべての町へ人口比で入れる。
   - 穀物の小売りの稼ぎ（穀物商・計量人・運搬人・荷馬車引き）は穀物が売られる所、つまり人の住む所で生まれるので、町の人口に比例する。
2. **町の公共事業の賃金**（`payTownWorks`、[townWorks.ts](../../src/extensions/economy/generators/townWorks.ts)）
   - 町の家計の現金が食費の2か月分（`TOWN_WORKS_TARGET_MONTHS`）を下回る間、町は自分の金庫から、町の住民を城壁・舗装・井戸・夜警・穀物庫の運搬などに雇う。
   - 金庫は食費2か月分（`TOWN_WORKS_RESERVE_MONTHS`）を手元に残し、その上の10%（`TOWN_WORKS_TREASURY_SHARE`）を月に使える。家計の不足分までしか払わない。
   - 毎月、市場の利益の払い出しの後、税の前に行う。

- テスト: `townWorks.test.ts`（手元に残す額と、不足分までしか払わないこと）。

### 12.5 見つかったこと: 雇用の需要と賃金が対応していない

- 移住を呼ぶ雇用の需要のうち、賃金が町の家計に入るのは、生産（工芸）と行政（国の給与）、運送・小売（市場の利益の払い出し）だけである。
- **鉱山・製錬・採石・建築の労働者には、賃金が払われていない**（`mineOperations.ts`・`smelterOperations.ts`・`constructionHire.ts`・`constructionEmployment.ts` に家計への支払いがない）。サービスの雇用（基幹の1.5倍）も、町の家計の中を回るだけで、外からのお金にはならない。
- §10.4 の「移住者の職と賃金の支払いの対応」はこれである。対応には、誰が払うか（鉱石・地金の買い手、国の公共事業費 `departmentBalances.publicWorks`、建築の発注者）を決める必要がある。

### 12.6 残っている課題

1. **基幹の雇用の賃金**（§12.5）: 鉱山・製錬・採石・建築の賃金を、産物の売り上げや発注者から町の家計へ払う。 → §13
2. **移住が飢えを見ない**: Megacity の移住の量に、行き先の食料の充足（または家計の現金）を入れるか。入れると、都市は飢える前に伸びが止まる。
3. **市場全体の貧困**（§12.1 の 3）: 穀物の足りない農村の市場は、農家・町・市場のどこにもお金がない。地域をまたぐお金の流れ（国の給与、輸出の代金）を調べる。
4. **都市の現金の偏り**（§11.4 の 1）: 首都と市場の中心は余りを町で使い、金庫から年1回、市場と国庫へ回収される。周りの町には戻りにくい。
5. **時間の進め方で結果が変わる**: 計測の途中で、同じ地図・同じ設定でも、10年を一度に進めた場合（`advance({ years: 10 })`）と1か月ずつ進めた場合で、Megacity の10年目の都市の人口点が約410 → 約740と大きく違った。一度に進めると、月ごとの処理（食料・家計・移住）がまとめて行われるためと考えられるが、未確認。§9〜§12 の計測はすべて1か月ずつ（`npm run sim` は3か月ずつ）進めている。

## 13. 鉱山・製錬・採石・公共事業の賃金（§12.6 の 1、2026-10-18）

### 13.1 史料

採掘と建築の労働は、国家の体制と時代で「誰が払うか」「払うか、養うだけか、課すか」が分かれる。

**採掘**

| 時代・体制 | 組織 | 労働 | 支配者の取り分 |
| --- | --- | --- | --- |
| 古典期アテネ（ラウレイオン銀山） | 国が採掘権を市民に貸す | 借り手が持つ奴隷が主（1,000人の奴隷を貸した例）。貧しい日雇いも | 借地料 |
| ローマ帝国の鉱山（ヴィパスカ銅板、ダキアの契約書） | 皇帝の所有。procurator が管理し、請負人（conductores）に貸す | 主に賃金労働。賃金を記した契約書が残る。囚人（damnati ad metalla）は石切り場の例が知られる | 皇帝の取り分 |
| 中世・近世の中欧（Goslar、イフラヴァ、クトナー・ホラ、ヨアヒムスタール、シュヴァーツ） | 鉱業権（Bergregal）は君主のもの。採掘は出資者の組合（Gewerken）が行い、鉱夫を雇う。12〜13世紀に鉱夫の自由（Bergfreiheit）が成立 | 賃金労働。ヨアヒムスタールでは鉱夫9,200人 | 十分の一税（Zehnt）。銀は君主の造幣所に定価で納める。帝国都市 Goslar は1359年に鉱業権を買い取った |

**賃金の水準**

- 中世以来の賃金の系列は、建築の職人と作業員の日給が基本になっている（Phelps Brown と Hopkins 1956、Allen 2001）。他の職は出来高払いが多く、日給の記録が少ないためである。
- Allen の福祉比率では、作業員の稼ぎで4人家族の最低限の暮らし（bare-bones basket）を支えられるかを測る。多くの地域で1前後だった。

### 13.2 実装の前の状態

- 鉱山・製錬所・採石場・火山の採取場の産物は、市場の在庫にただで入っていた（`Markets.addMineSupply`）。市場はそれを売って利益を得るが、鉱夫の賃金・鉱山税・経営者の利益はどこにも払われていなかった。
- 国の公共事業費（`departmentBalances.publicWorks`）で道・港・穀物庫を造ると、そのお金は誰にも払われず消えていた。
- **雇用の枠が実際の人数の約100倍だった。** 鉱山の雇用の枠は人口点で数える（4 + 豊かさ×6 点。1点 = 1,000人なので最大3.4万人）。一方、同じ鉱山の実際の人数は別に定めてあり（40 + 豊かさ×80人、`getMineEmploymentPeople`）、表示にしか使われていなかった。seed 102・Megacity の9年目では、鉱山・製錬所・採石場の雇用が248点（24.8万人）で、基幹の雇用（592点）の4割を占めた。サービスの雇用（基幹の1.5倍）と合わせると、移住を呼ぶ雇用の需要が実在しない職で大きく膨らんでいた（§12.5）。

### 13.3 実装した内容

1. **採掘の産物の買い取り**（新規 [extractionPayments.ts](../../src/extensions/economy/generators/extractionPayments.ts)）
   - 市場は、産物の市場価格の0.8（`MINE_HEAD_PRICE_SHARE`、農家の庭先価格と同じ）を自分の現金から払う。払えない分は、今までどおり代金なしで入る。製錬所には付加価値（地金 − 鉱石 − 木炭）を払う。
   - 代金は、鉱山税、賃金、経営者の利益の順に分ける。
     - **鉱山税**（`MINING_ROYALTY_SHARE` = 0.1、十分の一税）: 君主国・神権国は国庫へ。共和国・連合は町の金庫へ（Goslar の鉱業権の買い取り）。無政府は取らない。
     - **賃金**: 実際の人数 × 生活賃金（生産の賃金と同じ `getSubsistenceWage`）。払える額までしか払わない。古典古代は労働の6割、古代末期は3割が不自由労働で、その分は賃金ではなく食い扶持（賃金の1/1.5）だけになる（`UNFREE_EXTRACTIVE_LABOUR_SHARE_BY_PERIOD`）。中世以降は0。
     - **経営者の利益**: 町の金庫へ（出資者の組合 Gewerken）。帝国（`formName` が Empire）は国の直営で、国庫へ（ローマの procurator、佐渡奉行）。
2. **公共事業の支払い**（新規 [worksPayments.ts](../../src/extensions/economy/generators/worksPayments.ts)、[publicWorks.ts](../../src/extensions/economy/generators/publicWorks.ts)）
   - 事業費の6割（`WORKS_LABOUR_SHARE`）を賃金、4割を資材とする。
   - 港・穀物庫: 賃金はその町の家計へ、資材はその町の市場へ払う。
   - 道路: 賃金は国の家計（町と農村、`payStateHouseholds`）へ、資材は道が通る市場へ、長さに比例して払う。
   - **道路の賦役**（`ROAD_CORVEE_SHARE_BY_FORM`）: 君主国・神権国は道路の労働の半分を賦役でまかなう。その分は国庫が払わず、道は安く造れる。共和国・連合・無政府は0。蒸気の時代からは、どの体制も0（賦役の廃止）。
3. **採掘の雇用を実際の人数で数える**（`crewSlot`、[basicEmployment.ts](../../src/extensions/economy/generators/basicEmployment.ts)）
   - 鉱山・製錬所の雇用の枠を、実際の人数（`getMineEmploymentPeople`・`getSmelterEmploymentPeople`）の人口点にした。採石場・火山の採取場は、産出が1人あたり（年12トンの石など）で決まるので、枠の数をそのまま人数として扱う。
   - 各施設が使う単位（産出・道具の需要の計算）はそのままにし、割り当てた人数を施設の単位に換算して戻す。

テスト:
- `extractionPayments.test.ts`（新規）: 君主国では国庫・町の家計・町の金庫に分かれ、お金の総量が変わらないこと。共和国では鉱山税が町に残ること。古代では賃金が食い扶持に下がり、帝国では利益が国庫に入ること。
- `basicEmployment.test.ts`: 実際の人数での割り当てに合わせて3件を直した（製錬所が先に人を取る順番、市場全体から人を集めること、行政が先に人を取ること）。
- `publicWorks.test.ts`: 君主国では道の労働の一部が賦役になり、国庫が払う額が減ることに直した。

### 13.5 体制による違い（まとめ）

| 体制 | 鉱山税 | 鉱山の利益 | 道路の労働 |

### 13.6 残っている課題

2. **採石場・火山の採取場の表示**: 雇用の一覧（`employment-overview.ts`、`burgEmploymentComposition.ts`）は、採石場・火山の採取場の人数を人口点として表示している。§13.3 の3では、これを人数として扱った。表示を合わせる。
3. **住宅の建築**: 町の家計が家を建てる費用（石工・大工の賃金と資材）は、町の中のお金の移動なので入れていない。資材は市場から無償で取っており（`consumeForConstruction`）、石の買い手として採石場の収入にはなっていない。

## 14. 採掘の産物の価格と、1人あたりの産出（§13.6 の 1、2026-10-18）

### 14.1 史料: 採掘の労働者1人が1年に生む価値

商品の単位（wagon、bullion、pallet）は会計上のロットで、トンとの換算は決まっていない（[goods-unit-scale.md](goods-unit-scale.md)）。そこで、トンあたりの価格ではなく、**労働者1人の1年の産出が、作業員の年の賃金の何年分にあたるか**で比べた。

| 事例 | 労働者 | 産出 | 1人あたり | 作業員の賃金との比 |
| --- | --- | --- | --- | --- |
| ウィールドの製鉄（1590年代） | 約9,000人（1574年、大半は採鉱と木炭の木の伐採） | 銑鉄 年9,000トン超 | 銑鉄 約1トン | 棒鉄は1596年に1トン10ポンド（ヨークシャーの契約）。銑鉄はその半分強として約0.7〜1年分（作業員は日給8ペンス前後、年250日で約8ポンド） |
| クトナー・ホラ（16世紀後半） | 約3,000人 | 銀 年2〜4トン | 銀 約1 kg | 約1.3年分（1500年頃のイングランドの換算。銀1 kg ≈ 5.4ポンド、作業員の年の賃金 ≈ 4.2ポンド） |
| クレムニツァ（1442年） | — | — | 銀 約1.5 kg | 約2年分（同上の換算） |
| メル（カロリング朝） | 採掘100人を含む250〜300人 | 鉛52トン、銀150 kg（推定の中心） | 銀 約0.5 kg、鉛 約0.2トン | 1年分前後 |

- 換算は国・時代をまたぐので、ずれは大きい。それでも、**採掘の労働者1人の1年の産出は、作業員の賃金のおよそ1〜1.5年分**だった。採掘の費用の大部分は賃金で、残りが鉱山税・坑木・出資者の利益になる。
- 製鉄では、銑鉄1トンに鉱石5.5〜7トンと木炭4.5〜5トンを使った（16世紀の高炉）。費用の大部分は木炭で、炉の作業員は少なかった。

### 14.2 モデルとの比較（seed 102、5年目。基準価格での1人あたり産出 ÷ 作業員の年の賃金）

作業員の年の賃金は、生活賃金（`getSubsistenceWage`）で 1.5 × 0.43 = 0.645（穀物価格1のとき）。

| 鉱山 | §13 の人数（40 + 豊かさ×80人） | 1人あたりの産出（賃金の何年分） |
| --- | ---: | ---: |
| 縞状鉄鉱（豊かさ4） | 360人 | 1.4 |
| 炭層（豊かさ4） | 360人 | 1.3 |
| 砂鉄（豊かさ1〜2） | 120〜200人 | 0.1〜0.4 |
| 金鉱脈（豊かさ1） | 120人 | 0.08 |
| 蒸発岩（硫黄、豊かさ2） | 200人 | 0.4 |
| 錫・銅・銀の花崗岩鉱床（豊かさ2） | 200人 | 人手なし（未稼働） |

- **大きな鉄・石炭の鉱山は史料の範囲（1〜1.5）に入っている。価格を変える必要はない。**
- **小さな鉱床・貴金属の鉱山は、人数が産出に比べて5〜10倍多すぎた。** 人数が鉱種によらず「40 + 豊かさ×80人」で決まっていたためである。
- **製錬所は、基準価格では赤字になる。** 鉱石1トンあたりの付加価値（地金0.8 × 価格 − 鉱石 − 木炭1 × 3）は、鉄 −1.8、銅 −1.5、錫 −1.2、鉛 −2.1、銀 +3、金 +9。卑金属の地金の価格が、鉱石と木炭の価格の合計より安い。人数（8 + 年産×2.5人、120トンで308人）も、炉の作業員が数人〜十数人という史料より多すぎる。
- 実際の市場価格では、鉄鉱石と石炭は在庫が売れ残り、価格が下限（基準の0.25倍）に張り付いていた。それでも鉱山は人を雇い続け、掘り続けていた。

### 14.3 実装した内容

1. **鉱山の人数を、産出の価値で決める**（`getMineEmploymentPeople`、[mineOperations.ts](../../src/extensions/economy/generators/mineOperations.ts)）
   - 人数 = 満員で働いた時の年の産出の基準価値 ÷（1.3 × 作業員の年の賃金）。1.3 は `EXTRACTION_OUTPUT_PER_WORKER_IN_WAGE_YEARS`（§14.1）。最小4人（`MINE_MIN_CREW_PEOPLE`）。
   - 満員の時の産出には、排水・技術・燃料・近づきやすさを入れる（`getMineExtractionFactor`）。条件の悪い鉱山は、同じ人数でも少ししか掘れないので、人数も少なくなる。
   - 雇用（`basicEmployment.ts`）、賃金（`extractionPayments.ts`）、較正の一覧（`calibrationOverview.ts`）が同じ人数を使う。
2. **製錬所の人数も同じ規則で決める**（`getSmelterCrewPeople`、[smelterOperations.ts](../../src/extensions/economy/generators/smelterOperations.ts)）
   - 人数 = 年の付加価値 ÷（1.3 × 作業員の年の賃金）。最小8人（炉の作業員）。卑金属の製錬所は付加価値が負なので、8人になる。
3. **売れない時は人を減らす**（`getMineHiringShare`）
   - 鉱山が雇う割合 = 市場価格 ÷ 基準価値（産出の価値で重み付け）。0.25（`MINE_MIN_HIRING_SHARE`、排水と維持の人員）から1まで。
   - 史料では、鉱石が見合う値で売れない時、出資者は追加の出資（Zubuße）をやめ、坑は止まった。これまでの鉱山は、売れ残っても下限の価格で掘り続けていた。
   - 毎年の雇用の見直しの時の価格で決める。

テスト:
- `mineOperations.test.ts`: 産出の価値から人数が決まること。小さな鉱床は最小の人数になること。価格が下がると雇う割合が下がり、下限で止まること。
- `basicEmployment.test.ts`: 人数の規則が変わったので、製錬所が先に人を取る順番の検証の数値を直した。

## 15. 卑金属の地金の価格（§14.5 の 1、2026-10-18）

### 15.1 原因

- 地金の基準価値は、どの金属も鉱石の2倍で付けてあった（鉄 鉱石2 → 地金4、銅 2.5 → 5、錫 3 → 6、鉛 1.5 → 3、ケイ素 3 → 6、銀 10 → 20、金 20 → 40 など）。
- その後、製錬の燃料として木炭（基準価値3、鉱石1につき1）が入った（`migrateSmeltingFuelAndAshGoods`）。地金の価値は直されなかった。
- その結果、地金1あたりの原料（鉱石1.25 + 木炭1.25）は、鉄 6.25、銅 6.9、錫 7.5、鉛 5.6、ケイ素 7.5 で、地金の価値（4〜6）より高くなった。高価な金属は2倍の幅が木炭を吸収できたので、まだ原料を上回っていた（地金 ÷ 原料：銀 1.23、金 1.39、クロム 1.12、ニッケル 1.16、モリブデン 1.28）。

### 15.2 史料

- 16世紀の高炉は、銑鉄1トンに鉱石5.5〜7トンと木炭4.5〜5トンを使った。重さでは木炭が大きく、費用でも木炭が最大の項目だった。炉の作業員は少なかった（§14.1）。
- 銑鉄・棒鉄の価格は原料の費用を上回り、製鉄は利益の出る事業だった（ウィールドでは1590年代まで炉と鍛冶場が増え続けた。1596年の棒鉄は1トン10ポンド）。
- 費用の内訳（木炭・鉱石・賃金の割合）の数値の史料は、今回は見つけられなかった（Hyde 1977、King 2011 が候補）。そこで、地金の価格が原料を上回る幅は、まだ原料を上回っていた高価な金属の中央値（1.25）に合わせた。この幅（地金の価値の約2割）は、炉の作業員・木炭焼きと運搬の管理・出資者の利益にあたる。

3. **金属ごとの燃料**: 木炭の量は、どの金属も鉱石1につき1である。鉛は少ない燃料で溶け、銅は何度も焼くので多い燃料を使った。金属ごとの量を史料で決める。
4. §14.5 の 2・3、§13.6 の 2〜4、§12.6 の 2〜5 はそのまま残る。

## 16. 地金の値上げと国の予算（§15.5 の 1、2026-10-18）

### 16.1 調べたこと

§15.4 で、地金の値上げの後に道具・武器・大砲の生産が減って見えた。原因として、軍需の発注を払う国庫の不足を疑った。

工房の生産（`executeManufacture`、[production-generator.ts](../../src/extensions/economy/generators/production-generator.ts)）に一時的な計測を入れ、商品と払い手（国の軍需の発注か、町の金庫か）ごとに、1年間の次の値を数えた。

- 作りたい量（労働から決まるロット数）
- 材料の在庫で抑えた後の量
- 払える額で抑えられた回数（`availableFunds ÷ costPerLot` が作りたい量を下回った回数）
- 材料が買えずに作れなかった回数（`Failed to acquire`）
- 実際の生産量

同じ地図で、地金を前の値に戻した場合と比べた（5年目からの1年間）。

### 16.2 結果

**国の予算は足りている。** 国の軍需の発注は、どちらの地図でも一度も払える額で抑えられていない。国庫は25万〜62万あり、1年でほとんど変わらない。1ロットの費用（武器7〜8、マスケット銃47〜53、大砲57〜63）と比べて、国庫は桁違いに大きい。

### 16.3 結論

- 地金の値上げで国の予算が足りなくなる、ということは起きていない。地金の値上げ（§15）はそのままにする。
- 金属の下流の生産を抑えているのは、鉄の地金と木炭の供給である。鉱山の側では鉄鉱石が売れ残っている（§14.4）ので、詰まっているのは製錬（鉱石 → 地金）と木炭焼きである。§14.5 の 2（鉱石の売れ残り）と同じ問題で、次はここを調べる。

## 17. 製錬と木炭焼きの目詰まり（§16.3、2026-10-18）

### 17.1 症状

seed 102、Independent、地金を §15 の値にした状態（8年）。

- 鉄鉱石は鉱山町の市場に売れ残り、増え続ける（1年目120 → 8年目559）。価格は下限。
- 鉄の地金は、一部の小さな鉱山町の市場（中心の町が人口点10未満）に溜まり、価格は下限（基準の0.25倍）。人口の多い市場（人口点43〜46）では在庫0、価格は上限（3倍）。
- 木炭は、どの市場でも在庫が数十しかない。道具・大砲の工房は木炭が買えずに止まる。
- 鉄鉱石・地金・木炭は、実装の時に何度も調整に失敗していた（市場で在庫をほとんど見なかった）。調整の問題ではなく、仕組みが欠けていた。

### 17.2 見つかった欠け（5つ）

計測のための一時的なコード（工房の生産・交易の判断・輸出の予約ごとの記録）で、詰まる場所を順に追った。

1. **森の中の炉しか木炭を焼かなかった**（`smelterOperations.ts`）。炉が自分で木炭を作るのは、炉の敷地が森（`fuelAccess` 0.75以上）の時だけだった。それ以外の炉は、市場に木炭がなければ止まった。市場には木材が数万あった。
   - 史料: 製鉄業者（ironmaster）は薪を買い、炭焼き（collier）を雇って、炉の近くの森で木炭を焼かせた。木炭は崩れやすく、遠くへは運ばなかった。
2. **木炭の労働が1ロット1労働点だった**（`craftDemandCalibration.ts`）。木炭は後から足された商品で、工芸の需要の較正表（`GOOD_DEMAND_CALIBRATION`）に行がない。行のない商品は、1ロットに1労働点（1,000人・月）を使う扱いになる。賃金だけで1ロット約54（基準価値は3）になり、町の金庫で払える分しか作れなかった。
3. **町の工房の鍛冶の注文が、材料を求めていなかった**（`metallurgWork.ts`）。鍛冶の注文（道具・武器など）のうち、材料（地金・木炭）の需要を出すのは国の注文だけだった。家庭の道具の注文は、材料を求めなかった。国の注文は、市場にある在庫を差し引かずに毎月材料を求めたので、地金がなくて止まった注文が木炭を求め続けた。
4. **鉱石と地金は、価格も交易も動かなかった**（`markets-generator.ts`）。
   - 毎月の価格の計算は、分布のある原料と、レシピのある加工品だけを対象にしていた。鉱石と地金はどちらでもない（鉱山と炉が作る）ので、価格が更新されず、地金のない町で価格が上がらなかった。
   - 市場の間の交易も、同じ条件で鉱石と地金を外していた。
   - 町の鍛冶は、人口あたりのロットの目標（`getCalibratedMonthlyLots`）で道具を作る。その材料の地金は、市場の需要に一度も現れなかった。
   - 大きな商会は、中心の町が人口点10未満の市場とは、12日を超える交易をしなかった。鉱山町はたいていこれに当たる。
   - 史料: 大きな商家は、鉱山のある辺地にこそ入った（シュヴァーツのフッガー家、ファールンの銅とハンザ）。
5. **後から作られた市場を、ID で引けなかった**（`context/trade.ts` の `getMarketById`）。市場の一覧の配列が同じなら、ID の表を作り直さない仕組みだった。新しい市場は同じ配列に追加されるので、最初の検索の後にできた市場はすべて見つからなかった。輸出の予約（`ExportStaging.bookFromRetail`）がこの関数を使うので、**ゲーム中にできた市場は、どの商品も輸出できなかった**。seed 102 では14市場のうち10市場がこれに当たり、地金の溜まっていた鉱山町はすべてここに入っていた。

### 17.3 実装した内容

1. **どの炉も、市場の薪を木炭にする**（`ensureCharcoalReserve`）。森の中の炉は、まず自分の森を焼く。足りない分は、市場の木材を買って焼く（1回に在庫の半分まで）。焼く量は、市場にある鉱石を製錬する分までとする（鉱石がない時に木材を焼き尽くさない）。炭焼きには、木材から木炭への付加価値を、鉱夫と同じ規則（`settleExtractionPayment`、人数は `getExtractionCrewPeople`）で払う。
2. **木炭の労働を、価値の規則で決める**（`UNCALIBRATED_LABOR_POINTS_PER_LOT`）。炭焼きの1年は、作業員の賃金1.3年分の価値を足す（§14 と同じ）。1ロットの付加価値は 3 − 木材1.5 = 1.5 なので、労働は 1.5 ÷（1.3 × 53.75）≈ 0.0215 労働点（約21人・月）。需要の較正表の行（ロットの上限が付く）ではなく、労働だけの表にした。木炭の需要は、レシピと鍛冶の注文から来るためである。
3. **すべての鍛冶の注文が材料を求め、在庫を差し引く**（`getProductionDemandByGood`）。町の工房の注文も、材料（地金・木炭）の需要を出す。どの注文も、市場にある材料の在庫を差し引いてから求める。
4. **鉱石と地金を価格と交易に入れる**（`isMineOrFurnaceGood`）。
   - 鉱石・地金・鉱物の商品は、毎月の原料の価格の計算と、市場の間の交易の対象にする。
   - その需要に、鍛冶の注文の材料と、町の鍛冶の人口あたりのロット × 典型的なレシピの材料を足す（`addCalibratedMetalInputDemand`）。
   - 大きな商会は、鉱石と地金に限り、小さな村の市場との交易の制限を受けない（`isMarketTradePermitted` の `metalTrade`）。商会の到達範囲と本拠の圏内の条件は残る。
5. **`getMarketById` は、配列の長さが変わった時か、見つからない時に表を作り直す**。

テスト:
- `smelterOperations.test.ts`: 森のない炉が、市場の木材を木炭にして鉱石を製錬すること。
- `context/trade.test.ts`（新規）: 最初の検索の後に追加された市場を `getMarketById` で引けること。前のコードではこのテストは失敗する。

## 18. 鉛・石炭・道具・木材の現状と史実（§17.5 の 1〜4、判断のための調査、2026-10-18）

コードは変えていない。ゲームの数値は、`goodsBalanceLedger.ts` の物の出入りの記録（`beginGoodsBalanceInterval` / `closeGoodsBalanceInterval`）で、6年目から1年間を測った（seed 101 と 102、Independent）。

### 18.1 鉛（銀と一緒に出る鉛）

**史実**

- 銀の多くは、銀を含む方鉛鉱から取った。鉱石を溶かして銀を含む鉛を作り、灰吹法（cupellation）で鉛を酸化させて取り除き、銀を残す。鉛は銀を集める役で、灰吹法には鉛が要る。
- 灰吹法で出た鉛の酸化物（リサージ）は、売れる所では鉛に戻して売った。ローマ時代のスペインでは、銀を取った後の鉛を水道管に使った。
- 鉛の使い道がない時代・土地では、リサージは捨てられた（ごく初期の例）。
- 銀の製錬所は、鉛が足りなければ外から買った。12世紀後半のプラハの銀の製錬遺跡では、灰吹法の鉛がポーランド産と分析されている。
- 中世の鉛の需要: 教会・城の屋根、尖塔の被覆、窓ガラスの枠、ピューター（錫との合金）、塗料。ダービーシャーでは王が鉱石の13分の1を取った。15世紀末には、掘りやすい鉱脈が尽きて鉛が値上がりした。
- まとめると、鉛は「売れなければ捨てる副産物」ではなく、銀の製錬そのものの材料で、建築の需要もあった。売れない土地では、リサージや鉛のまま積まれた。

**ゲームの現状**（seed 101）

| 項目 | 1年間 |
| --- | ---: |
| 鉛鉱石の採掘 | 58 |
| 鉛の地金の製錬 | 46 |
| 鉛の地金の消費（弾丸・硫酸・軍需・輸出） | 0 |
| 在庫 | 286 → 332（3つの鉱山町の市場に溜まり、価格は下限） |

- 鉛を使うのは、弾丸（火薬の時代）と硫酸（工業）だけである。鉛の地金には「建築 0.3」の需要の分類が付いているが、町の建築の買い物は木材・石が満たすので、鉛は1年で0しか買われない。
- 銀の製錬は鉛を使わない。銀と鉛は同じ鉱石から別々に地金になる。
- 鉱山の雇う割合（§14.3）は鉱石の価格で決まる。炉は鉱石を全部製錬するので、鉛鉱石の価格は下がらず、鉱山は鉛が売れなくても人を減らさない。

**判断の選択肢**

1. 炉の稼働を地金の価格で抑える（売れなければ作らない）。銀鉛の鉱床では、鉛が売れなくても銀のために製錬する。その鉛を市場に出さず、鉱山町のリサージ・鉛の山として積む（売れる時に出す）。
2. 銀の製錬に鉛を使う（灰吹法）。銀の地金1につき鉛を消費し、一部をリサージとして戻す。銀だけの鉱床は、鉛を買う需要になる。
3. 建築の鉛（屋根・窓）を、町の建築の材料に入れる。

### 18.2 石炭

**史実**

- 中世のイングランドで石炭（海上輸送で来るので sea coal）を使ったのは、主に鍛冶・石灰焼き・醸造などの一部の業種だった。煙と臭いが嫌われ、1306〜1307年にロンドンで使用が禁じられ、テムズ川沿いの石灰窯は柴か木炭を使うよう命じられた。
- 鍛冶では、硫黄で鉄がもろくなった。醸造では、煙で酒の味が悪くなった。
- 家庭の暖房に広まったのは16〜17世紀で、木材が足りなくなって値上がりしてからである（1584年、ホリンシェッドが石炭が鍛冶場から台所へ移ったと書いた）。
- 掘る量は売れる量に合わせて抑えられていた。宗教改革の前は修道院が価格を保つために生産を抑え、その後はニューカッスルの商人組合（Hostmen、1600年に特許）が輸出と生産を握った。
- 坑口の捨て石の山には石炭が混じり、自然発火で燃え続けることがあった（フランスのノール＝パ・ド・カレーでは74の山が燃えた例）。
- 売れない細かい石炭（small coal）をどう処理したかは、今回の調査では史料が見つからなかった。

**ゲームの現状**（seed 102）

| 項目 | 1年間 |
| --- | ---: |
| 石炭の採掘 | 37 |
| 消費 | 0 |
| 在庫 | 376 → 413（2つの市場。価格は下限） |

- 暖房（`heating.ts`）は、木材を先に使い、木材で足りない分だけ石炭を使う。木材が市場に余っている（§18.4）ので、石炭は使われない。
- 炭層の鉱山は、価格が下限なので雇う割合が0.25になり、排水と維持の人員だけで掘り続けている。

**判断の選択肢**

1. 売れない石炭は掘らない（雇う割合の下限を、鉱石が売れない時は0にする。坑は止まる）。
2. 坑口の石炭の山が、自然発火・風化で少しずつ失われるようにする（在庫の目減り）。
3. 木材の積み上がり（§18.4）を直せば、木材が高い土地で石炭の暖房が自然に始まる（ロンドンの経過と同じ）。石炭の問題の多くは木材の問題の結果である。

### 18.3 道具（「実際の需要より流通量が少ない」の中身）

ゲームには、道具の需要が3つの別々の数字としてある。

| 数字 | 中身 | seed 102 の値（1年） | 物が消えるか |
| --- | --- | ---: | --- |
| 鍛冶の生産の目標 | 町の住民1人あたり年0.02組（`GOOD_DEMAND_CALIBRATION` の Tools）。鍛冶の労働の配分を決める | 5,771ロット（町の住民28.9万人） | 消えない（生産の目標だけ） |
| 町の家庭の道具の注文 | 町の家庭の道具の保有と修理（`MetallurgWork` の burg の Tools） | 注文179件、残り0 | 消える（ただし量はごく小さい。1年で1） |
| 農村の農具の投資 | 市場が農家のために道具を買う（`agTechInvestment.ts`） | 94 | 消える（道具の消費のほぼ全部） |

- 実際の生産は年79、輸入45。消費は年98（農具の投資94、町の家庭1、輸出3）。
- 生産の目標（5,771）は、実際の消費（98）の約60倍で、物の消費に結び付いていない。生産を抑えているのは、鉄の地金と木炭の在庫と、鍛冶の労働の上限である。
- 道具は、作られた市場（seed 102 の市場1、人口点83）に溜まる（57、価格は基準の0.37倍）。ほかの市場は在庫0で、価格は基準の0.9〜2.4倍。
  - 市場の間の交易は、交易先の需要（消費者の需要 + その材料としての需要）で動く。較正では道具の消費者の需要を0にしている（`residualWeight: 0`。道具は家庭が市場で買う商品として数えない）。そのため、道具はどの市場でも交易の需要がなく、価格が高くても運ばれない。
- 史実の目安: スウェーデンでは、ウップランドの普通の農場で、耕作による鉄のすり減りが年1 kg強（1 ha あたり約100 g）。18世紀半ばの農場の鉄の保有は約150 kg、1870年には約500 kg。農具の需要の主体は農家で、町の住民ではない。

**判断の選択肢**

1. 道具の需要を、農家の農具の保有と、すり減りの補充（農場あたりの鉄の量）で決め直す。町の住民1人あたりの生産の目標は、その需要に合わせる。
2. 道具（と家庭の金属製品）を、交易の需要に入れる。§17 で地金に入れたのと同じ仕組み。

- 史実の目安: 工業化の前のヨーロッパでは、薪が最大のエネルギー源だった（Warde）。家庭の薪の消費は、19世紀まで多くの国で減らなかった。1人あたりの量（立方メートル・トン）は、今回の調査では信頼できる数値が見つからなかった（Warde 2007 の本文、スウェーデンの Lindmark の系列が候補）。
- 開墾の木材の行方: 中世の開墾（assart）で出た木材をどうしたかは、今回の調査では史料が見つからなかった。英国の農民には、建築材と、落ちた枝などの薪を取る権利があった。木の灰は、ガラスの融剤（カリ）として価値があった。

**判断の選択肢**

1. 農村の暖房と調理の薪を、農村の森の産出から先に引き、残りだけを市場に出す。
2. 開墾の木材は、近くの町の需要の分だけ市場に出し、残りはその場で燃やす（灰はカリになる）か、薪として農村が使う。
3. 木材の1単位の量を決め、暖房の量（1,000人あたり月0.16単位）と森の産出を同じ尺度でそろえる。この作業は大きいので、1と2の後に必要かを判断する。

### 18.5 4つの課題のつながり

- 木材が余っているので、石炭の暖房が始まらない（§18.2）。木材を直すと、石炭の問題の一部も変わる。
- 鉛と石炭は「売れない物を作り続ける」点で同じである。鉱山の雇う割合（§14.3）は鉱石の価格で決まるが、炉で地金にした後に売れない場合（鉛）や、下限の人員が掘り続ける場合（石炭）は抑えられない。
- 道具は、作る目標と、使う量と、運ぶ需要が、3つの別の数字になっている。

## 19. 木材・石炭・鉛・道具の実装（§18 の 4-a・4-b・2-a・1-a・3-b、2026-10-18）

§18 の判断の選択肢のうち、木材の1と2（4-a・4-b）、石炭の1（2-a）、鉛の1（1-a）、道具の2（3-b）を実装した。道具の1（3-a）は、§19.5 の理由で実装していない。

### 19.1 §18.4 の訂正

§18.4 は「暖房は町の住民だけ」と書いたが、誤りだった。`heating.ts` は、市場の圏内の町の住民と農村の住民（`cells.pop`）の両方を数えていた。§18.4 の暖房 8,805 は、約890万人全員の暖房である（890万人 ÷ 1,000 × 0.16 × 12 か月 × 寒さの平均 約0.5 ≈ 8,500）。

そのため、4-a（農村の暖房を農村の森から先に引く）だけでは市場の在庫は変わらない。木材が溜まる原因は、農村の森の産出（年2.7万）と開墾の木材（年1.7万）が、売れるかどうかに関係なく全部市場に入ることだった。4-a に加えて、売る分の木を、市場が使う分だけ切るようにした。

### 19.2 木材（4-a・4-b）

実装した内容（`markets-generator.ts` の `supplyRuralWood`、`heating.ts`）:

1. **農村の家庭の燃料を、自分で切った木で先にまかなう**。毎月、市場の圏内の農村の住民の燃料（暖房と調理）を計算し（`getMonthlyHouseholdFuelDemands`）、その分をまず開墾の木材から、次に森から取る。この木は市場に入らない（`market.woodSupply.ruralFuelWood`）。暖房の計算は、農村の燃料からこの分を引き、残りと町の住民の燃料を市場の在庫から取る。
2. **調理の燃料を足した**（`BASE_COOKING_UNITS_PER_1000_RESIDENTS_MONTH` = 0.04、1,000人あたり月）。最も寒い月の暖房（0.16）の4分の1。暖かい月・暖かい土地でも、炉の火は毎日要る。値は仮（4-c の単位が決まるまで）。
3. **売る木は、市場が使う分だけ切る**。市場の在庫の目標 = 6か月分（`WOOD_STOCK_COVER_MONTHS`）×（市場の木材の毎月の減り方の平滑値、町の燃料と森の足りない農村の燃料の大きい方）。毎月の減り方は、前の月の供給の直後の在庫と、今月の供給の前の在庫の差で測る（消費と純輸出を含む）。目標の下限は、売れる産出の1か月分（`WOOD_STOCK_FLOOR_MONTHS`。在庫が0だと工房の買い物が失敗して減り方に現れないため）。目標に足りない分だけ切って市場に出し、残りの森は切らずに残す。
4. **開墾の木材**は、農村の燃料、市場に出す分の順に使い、残りはその場で燃やす（`clearanceBurned`。灰は畑に残る扱いで、市場には出さない。Ash を市場に出すと、今度は Ash が溜まるため）。開墾の受け取りは毎月すべて済ませる。

**結果**（seed 102、6年目の1年間。§18.4 と同じ測り方）

| 項目 | §18.4 | §19 |
| --- | ---: | ---: |
| 市場に入る木材（農村の森 + 開墾 + 輸入） | 約45,000 | 約5,300 |
| 市場から出る木材 | 約11,900 | 約3,900 |
| 市場の在庫（年の初め → 終わり） | 113,421 → 145,005 | 3,159 → 2,981 |
| 家庭の燃料の需要（暖房 + 調理） | 8,805（暖房のみ） | 13,395 |
| うち農村が自分で切った木 | — | 12,679 |
| 市場から取った家庭の燃料 | 8,805 | 784 |
| 足りなかった燃料 | — | 20 |
| 開墾の木材のうちその場で燃やした分 | — | 701 |

seed 101 も同じ形で、在庫は 2,690 → 2,770（§18.4 では1年で約5.3万増えた）。足りなかった燃料は 24。

- 市場の価格は多くの市場でまだ下限の近く（基準の0.25〜0.5倍）。在庫の下限（売れる産出の1か月分）が、価格の計算の需要より大きいためで、在庫そのものは増えない。
- 農村が市場に売る木材が減ったので、その分の農村の家庭の収入も減る。以前の売り上げも下限の価格だったので、額は小さい。

### 19.3 石炭（2-a）

`getMineHiringShare`（`mineOperations.ts`）を変えた。

- 鉱山の産物のうち、価格が基準の0.3倍以下（`EXTRACTION_UNSOLD_PRICE_RATIO`。市場の価格の下限は0.25倍で、在庫が需要の4倍を超えると下限になる）のものは、雇う割合の計算で価値0とする。
- どの産物も売れない鉱山は、雇う割合が0になり、坑は止まる。一部でも売れる鉱山は、これまでどおり0.25（排水と維持の人員）を下限とする。
- 価格が戻れば、次の年の雇用の見直しで再び人を雇う。

**結果**（seed 102、6年目）: 炭層の鉱山は人員0になり、石炭は1年で0しか掘られない（§18.2 では37）。在庫は219のまま。木材が足りなくなった土地で暖房が石炭を使えば、在庫が減って価格が戻り、坑が再開する。

同じ規則で、seed 102 では珪素・金（1か所）・鉄と銅・ニッケルと鉄・鉛と銀・錫と銅と銀の鉱山も人員0になった。これらは前は下限の0.25で掘り続け、産物が鉱山町に溜まっていた。鉛と銀の鉱山は、鉛の地金が売れて価格が戻ると（6年目の終わりに各市場で基準の1〜3倍）、次の見直しで再開する。

### 19.4 鉛（1-a）

`SmelterOperationsModule.produceMonth`（`smelterOperations.ts`）を変えた。

- 炉は、地金の価格が基準の0.3倍以下の鉱石を製錬しない。鉱石は市場に残り、鉱石の価格が下がって、鉱山が人を減らす（§19.3）。
- 同じ鉱床に売れる地金がある時（銀を含む方鉛鉱から銀を取る時など）は、売れない地金も製錬するが、市場に出さず、製錬所に積む（`SmelterOperation.heldIngots`）。地金が再び売れる価格になったら、毎月、炉の1か月の産出までを市場に出す。積んだ地金は、売った時に炉の付加価値に入る。

**結果**（seed 101、6年目）: 市場の鉛の地金の在庫は 26 → 28（§18.1 では 286 → 332）。製錬所に積まれた鉛は143、クロムは32。

### 19.5 道具（3-b、3-a は見送り）

**3-b（実装）**: 農家が次の年に買う道具を、交易の需要に入れた（`getFarmToolsDemandByMarket`、`agTechInvestment.ts`、`MarketsModule.addFarmToolsDemand`）。量は、耕地のすり減り（`TARGET_TOOLS_PER_HECTARE` = 0.02 × 耕地）と、市場の資金のうち農具に使える分（`AGTECH_BUDGET_SHARE_OF_TREASURY` = 15%）÷ 価格の小さい方。

**結果**（seed 102、6年目）

| 項目 | §18.3 | §19 |
| --- | ---: | ---: |
| 生産 | 79 | 114 |
| 輸入 / 輸出 | 45 / 3 | 51 / 41 |
| 農具の投資 | 94 | 106 |
| 在庫のある市場 | 1か所（57、基準の0.37倍） | 2か所（12・19、基準の1.3・1.5倍） |

**3-a（見送り）**: 道具の需要を、農家の農具のすり減りで決め直す案。ゲームの数字を測ると、耕地は14の市場で合計約2,260万 ha、0.02 組/ha のすり減りは年約45万組になる。実際の生産は年114、市場の資金で買える分は合計で年約1,700である。鍛冶の生産の目標（町の住民1人あたり年0.02組、年5,771）をすり減りに合わせると、目標は今の約80倍になり、今よりさらに物の消費と離れる。

- 0.02 組/ha は、1組を約5 kg とすれば、スウェーデンの耕地1 ha あたり年約100 g の鉄のすり減り（§18.3）と合う。しかしゲームの道具の1単位（`set`）が何 kg かは決まっていない。木材の4-c と同じく、単位の量を決めないと、すり減りと生産を同じ尺度にできない。
- 鍛冶の生産を実際に抑えているのは、鉄の地金と木炭と労働で、目標ではない（目標は上限としてしか働かない）。目標を変えても、生産の量は変わらない。目標は鍛冶の労働の需要（ギルドの人数）にも使われるので、変えると雇用に広く影響する。
- 道具の1単位の量を決める作業を、木材の1単位の量（4-c）と一緒に行うかを判断してから扱う。

### 19.6 テスト

- `heating.test.ts`: 暖かい月も調理の燃料を使うこと。農村が自分で切った木を、市場の在庫より先に燃やすこと。
- `markets-generator.test.ts`: 開墾の木材を、市場が使う分だけ売り、残りをその場で燃やし、受け取りを一度だけ済ませること。

- `smelterOperations.test.ts`: 地金が売れない鉱石は製錬しないこと。銀のために製錬した売れない鉛を製錬所に積み、鉛が売れるようになったら市場に出すこと。

3. 長い期間（15年）の全体の指標（都市の食料の充足・都市人口・交易資本、§17.4 の表）への影響は測っていない。

| 攻城の投石機・櫓・防護柵 | なし（軍需は鉄・鉛・火薬・矢・武具・飼料・鋼など） |
| 造船 | あり（市場の木材は建造点10あたり2、ほかに造船所の近くの森を直接切る `LOGGING_RATE_PER_YEAR`）。ただし下の不具合で動いていなかった |
| 火葬の薪 | あり（`funeralGoodsConsumption.ts`） |

**造船が動いていなかった不具合**: 造船所の候補（`getShipyardCandidates`）は地図から導くだけで保存しない。作り直すのは、拡張機能を有効にした瞬間と、地図を新しく作った時だけだった。保存した地図を読み込むと候補は空のままで、造船所の伐採も建造も行われなかった。

- 計測（seed 102）: 外海の港14、造船所の候補0。2年進めても、伐採のイベント0、資材の要求0。
- ヘッドレスのシミュレーション（`npm run sim`、計測用のスクリプト）では、Shipbuilding は有効になっていた（economy・nobility・characters・shipbuilding）。それでも、読み込んだ地図では動いていなかった。ブラウザで保存した地図を読み込んだ時も、読み込みの処理（`load.ts`）は候補を作り直さないので、同じだったと考えられる（ブラウザでは確かめていない）。

### 20.2 単位の確認

木材の1単位の量（4-c）は決まっていないが、ゲームの数字から大きさの見当をつけた（seed 102）。

- 森: セル1つの平均は約12万 ha。森がいっぱいのセルは5,000単位の木を持つ（`FOREST_COVER_PER_WOOD_UNIT` = 0.0002）。1単位は森約24 ha 分で、成熟した森（1 ha に150 m³ 前後）なら約3,600 m³ にあたる。
- 薪: 約890万人の燃料は年約1.34万単位。1単位を1,000〜3,600 m³ とすると、1人あたり年1.5〜5.4 m³。工業化の前のヨーロッパの家庭の薪（1人あたり年10 GJ 前後、1.5〜2 m³）と、桁は合っている。
- 大工: 1人点（1,000人）あたり年10単位は、1人あたり年10〜36 m³ にあたり、ありうる範囲である。

森・薪・大工の数字は、およそ同じ尺度にそろっている。以下の新しい使い道は、この尺度に合わせ、薪との比で決めた。

### 20.3 実装した内容

1. **造船所を読み込みの時に作り直す**（`shipbuilding/simulation.ts`）。`fmg:world-loaded` で、候補と港の能力だけを作り直す。保存してある建造の順番と艦隊はそのままにする。
2. **石造・煉瓦造の木**（`constructionEmployment.ts`）。石工1人点あたり年3単位の木を使う（`WOOD_PER_MASON_WORKER_ANNUAL`、大工の約30%）。屋根と床の梁、足場、アーチの支え、石を運ぶころとそり、踏み車のクレーン。木がなければ、石工の仕事も進まない。
3. **港の桟橋と岸壁**（同）。港町は、住民1,000人あたり年0.02単位の木を市場から使う（`HARBOUR_WOOD_PER_1000_RESIDENTS_ANNUAL`）。
4. **農村の家・納屋・柵**（`markets-generator.ts`）。農村の住民1,000人あたり年0.2単位（`RURAL_BUILDING_TIMBER_PER_1000_RESIDENTS_ANNUAL`）に、そのセルの文化の家の木の割合（`getHouseTimberShare` = 木の割合 +（1 − 木の割合）× 0.3。石造の家でも屋根・床・扉・納屋・柵は木）を掛ける。薪と同じく、農村が自分で切る（市場に入らない）。森が足りない時は薪を先にする。
   - 根拠の見積もり: 農家の家と納屋で約50 m³ の木を約40年ごとに建て直し、5人で住むなら、1人あたり年約0.25 m³。薪の1.5〜2 m³ の約7分の1。
5. **攻城と攻城兵器**（`militaryResources.ts`、軍需の資源に `wood` を足した）。
   - 砲兵の1人点あたり年0.05単位（投石機の枠、火薬の時代は砲車）。火薬の時代かどうかに関係なく使う。
   - 国の陸の連隊が攻囲に向かっている町（`goalTargetBurg`）1つにつき、月0.3単位（その場で組む攻城兵器、防護柵、攻城櫓、陣地の柵と小屋）。

値はいずれも仮（4-c の単位が決まるまで）。

## 21. 造船所の伐採と、木材の使い道の積算（§20.6、2026-10-18）

### 21.1 造船所の伐採を船の材料にする（実装）

造船所の伐採は、もともと船の材料にするための設定だった。しかし実装では、年125 × 森の割合の木を切り倒して森を減らすだけで、その木は船の材料にならずに消えていた。船の材料の木（建造点10あたり2）は、別に市場から買っていた。

- 船の材料を求める時、造船所は隣の森（`loggingCellId`）から木を切り、足りない分だけ市場から買う（`MarketsModule.tryConsumeShipbuildingMaterials` の `timberCellId`、切れる量は `getFellableWood`）。
- 決まった量を毎年切る伐採（`shipbuilding/generators/logging.ts`、`LOGGING_RATE_PER_YEAR`）は取り除いた。森が減る量は、実際に建造した船の分になる。
- テスト（`markets-generator.test.ts`）: 森のある造船所は木を森から切り、市場の木材を減らさないこと。

### 21.2 使い道ごとの積算（工業化の前のヨーロッパ、1人あたり年、丸太の実積 m³）

全体の量を示す史料はない（Warde 2007 も「国全体の消費は需要側からは決められない」と書き、森の生産量から上限を推定している）。そこで、使い道ごとに1単位あたりの量を集め、1人あたりに直した。幅が大きいものは幅のまま示す。

| 使い道 | 1単位あたりの量（出典） | 1人あたり年 m³ の見積もり |
| --- | --- | ---: |
| 暖房と調理 | イングランド 1550年ごろ、供給できたのは1人年1 m³ 程度で、北ヨーロッパより低い（Warde 2007）。ドイツ 18〜19世紀の推定 2.5〜5 m³（Schmidt 2002。書評は高すぎ、スカンディナビア並みとする） | 1（温暖）〜3（寒冷） |
| パン焼き | 家の窯で週2〜3回焼くと、柴束が週8〜12束（Weald & Downland 博物館、16世紀の再現）。共同の窯・領主の窯はこれを大きく減らす | 共同の窯 0.1〜0.2、各家の窯なら 1 前後 |
| 醸造 | クラクフ 16〜17世紀、1回の仕込みに 1.9〜2.5 m³（湯を沸かす 0.9〜1、麦汁を煮る 1〜1.15） | ビールの地域で 0.1〜0.3 |
| 家・納屋 | 1600年ごろのケンブリッジシャーの家で小さな樫72本 + 床板用7本、別の家で300本（ケンブリッジシャーの記録）。地面に柱を埋める家は10〜20年、礎石の上の柱なら約50年もつ | 0.2〜0.4（農家1戸 40〜60 m³ を 20〜50年で建て直し、5人） |
| 柵・竿・荷造り | 1850年のイングランドで、森の産出の8%以上が農業の竿と荷造り（Warde 2007） | 0.1〜0.2 |
| ブドウ畑の支柱 | 1 ha に 7,200〜9,000株、1株に3本（ノルトハイム。1936年に18万本を販売）。別の地方では、ブドウ畑1 ha の棚に雑木林10 ha が要った | ブドウの地域で 0.1〜0.5 |
| 鉄 | 塊鉄炉で鉄1 kg に木炭 8〜9 kg（復元実験）。木炭は木の重さの約25%。鉄1 t に木約50 m³。18世紀の高炉でも、イングランドとウェールズの森の約3分の1を使った（Warde 2007） | 0.05〜0.1（1人年1〜2 kg の鉄） |
| 塩 | 塩1 t に木約1 m³（ザルツカンマーグート） | 0.01〜0.05（濃い塩水の場合） |
| ガラス | 灰のガラス1 kg に、ブナ約200 kg（Krueger & Wedepohl 2003）。博物館の説明では 1〜3 m³ | 0.01〜0.03 |
| 石灰 | 石灰1 t に木約0.5 t（伝統的な窯） | 0.01〜0.02 |
| 船 | 大型の軍艦1隻に数千本の樫 | 港の地域で小さい |

合計は1人あたり年およそ 2〜5 m³ で、燃料（暖房・調理・パン・醸造）が6〜8割を占める。キングとラッカムは、切った木の半分ほど（価値または量で）が燃料以外だったとしている。Warde は、18世紀後半までは森の産出の9割が薪用の萌芽林だったとしている。

### 21.3 ゲームの今の量との比較

seed 102 の6年目（約890万人）で、ゲームは年約1.68万単位の木を使う。内訳は、家庭の燃料 1.34万（80%）、農村の家 0.12万（7%）、町の建築 0.08万（5%）、工房・炉・家庭の買い物 0.13万（8%）。**使い道の割合は史実の構造に近い**。問題は、木材の1単位の大きさが、どの数字から逆算するかで大きく違うことである。

| 何から逆算するか | 木材1単位 | その単位でのゲームの姿 |
| --- | ---: | --- |
| 価格（木材の価値1 = 穀物1単位 ≈ 465 kg。小麦 220 kg ≈ 30シリング、薪1荷 ≈ 8〜10シリング、イングランド 1600年ごろ） | 約10 m³ | 燃料は1人年 0.015 m³ で、史実の約100分の1 |
| 船と家（帆船は建造点10で木2、評価用の家1戸は木2） | 約100 m³ | 燃料は1人年 0.15 m³ で、約10分の1 |
| 燃料（1人年 1〜3 m³） | 約1,000 m³ | 帆船1隻に 2,000 m³ で、約10倍 |
| 森の成長（このマップのセル 約12万 ha。満杯のセルは5,000単位で、年2%回復。1 ha に年3.3 m³ とする） | 約4,000 m³ | 燃料は1人年 5.9 m³ で、多い。しかもセルの面積で単位が変わる |

- **単位がセルの面積に依存している**。`FOREST_COVER_PER_WOOD_UNIT`（0.0002）は「セルの森の割合」で量っているので、セルが大きい地図ほど、木材1単位に含まれる森の面積が大きい。人口と使う量は同じでも、地図によって森の減り方が変わる。
- 価格・船・燃料・森の4つが、互いに10〜400倍ずれている。市場の木材が溜まっていた（§18.4）のは売れ残りを止める仕組みがなかったためで、§19 で直した。しかし、森が人口の割にどれだけ減るかは、この単位の問題で決まる。

### 21.4 提案（判断が必要）

1. 木材の1単位を、地図に依存しない量で決める（例: 丸太 10 m³。価格と合う）。森の伐採の換算を、セルの割合から「ha あたりの立木の量」に変え、セルの面積で割る。
2. 燃料・家・柵・パン・醸造・工業の量を、§21.2 の積算から、その単位で決め直す。森の回復も、1 ha に年3〜4 m³ にそろえる。
3. 単位を価格に合わせると、町の住民が薪を買う額が今の約100倍になり、都市の家計（§10〜12 で較正した）に効く。史実では、イングランドの労働者の家計で燃料は1割前後だった。この影響を、都市の家計の較正と一緒に確かめる。→ §22 で実装した。暖房は市場の在庫を無料で引くので、家計への影響は今の実装では起きない（§22.5）。

## 22. 木材の単位を 10 m³ にそろえる（§21.4 の実装、2026-10-19）

### 22.1 単位と森の換算

- **木材1単位 = 丸太の実積 10 m³**（`WOOD_M3_PER_UNIT`、`src/generators/forestStock.ts`）。価格（木材の価値1 = 穀物1単位 ≈ 465 kg）と合う。
- **森は ha で切る**。`forestStock`（セルの森の割合）と木材の換算を、「セルの面積 × バイオームごとの立木の量 ÷ 10 m³」に変えた（`getWoodUnitsPerForestCoverage`）。これまでの `FOREST_COVER_PER_WOOD_UNIT`（セルの割合 0.0002 が1単位）を取り除いた。同じ量の木は、どの地図でも同じ面積の森を空ける。農村の伐採・開墾の木材・造船所・炭焼き・葬儀の薪が、すべてこの換算を使う。
- **バイオームごとの立木の量**（閉じた森 1 ha あたりの幹の材積）。FAO の世界森林資源評価 2020 では、世界平均の蓄積は 1 ha あたり 137 m³。

| バイオーム | m³/ha | 年の成長（回復 約2%/年） |
| --- | ---: | ---: |
| タイガ | 100 | 約2 |
| 温帯落葉樹林・山地林・雲霧林 | 200 | 約4 |
| 温帯針葉樹林・熱帯雨林 | 250 | 約5 |
| 中央ヨーロッパの大森林 | 300 | 約6 |
| 温帯雨林 | 500 | 約10 |
| 熱帯季節林・氾濫原の森 | 150 | 約3 |
| 熱帯乾燥林 | 80 | 約1.6 |
| マングローブ | 100 | 約2 |
| その他の森 | 150 | 約3 |

  - 年の成長は、既存の森の回復（`FOREST_REGROWTH_PER_YEAR` = 2%、気候で増減）から出る。イングランドの森の 1 ha あたり年 3.3 m³（Warde 2007）と同じ桁になる。
- **木の種類（樫と松）の違い**: 量（m³）では区別しない。重さと熱は、針葉樹が広葉樹の約7割である。しかし、家庭の燃料の量（§22.2）は、その土地に生える木を燃やしていた地域の数字（スカンディナビアは針葉樹と樺）から取ったので、その差はすでに含まれている。取れる量の違いは、上の立木の量で表している。

| 石炭の熱（木材1単位に対して） | `COAL_HEAT_PER_UNIT` | 0.27（前 2.5）。石炭1 t ≈ 27 GJ、薪10 m³ ≈ 6.5 t ≈ 100 GJ | — |

- 暖房と調理を合わせると、イングランドの気候で1人年 約1.5 m³、スカンディナビアで 2.5〜3 m³ になる（§21.2）。
- 火葬の薪（1人 0.12単位 = 1.2 m³）と棺（0.02単位 = 0.2 m³）は、もともと10 m³ の単位で妥当な量だったので変えていない。
- 炭焼きのレシピ（木炭1単位に木材1.5単位）と、製錬の木炭（鉱石1 t に木炭1単位）も変えていない。鉄1 t に木 約19 m³ で、高炉（約15 m³）と塊鉄炉（約50 m³）の間にある。

### 22.3 農村の伐採の上限

農村が切れる木を、バイオームの産出（人口 × 係数）から、**市場の圏内の住民のいるセルの森の、伐れる立木の1%/月**（`RURAL_MONTHLY_FELLING_SHARE`、年12%まで）に変えた。需要がこれを超える市場では、農村の燃料が足りず、市場から買う（交易で輸入する）。在庫の下限（売れる産出の1か月分）は、産出が大きくなったので取り除いた。在庫の目標は、市場の木材の減り方の6か月分だけにした。

## 23. 開墾の量・葬儀の薪・町の薪の支払いと寒さ（§22.5、2026-10-19）

### 23.1 開墾の量（不具合を修正）

**調べたこと**（seed 102、計測用のスクリプト）: 開墾で切る森は、年によって約3万 ha と約42万 ha を行き来していた。耕地の純増は年3〜13万 ha で、焼き畑（耕地が年ごとに移る設定）のセルは0だった。

**原因**: 牧草地が1年おきに現れて消えていた（例: セル672 の牧草地 15,365 ha が 1916年・1918年にあり、1917年・1919年にない）。

1. 土地利用の計画（`developmentPotential.ts`）は、牧草地の広さに「牧夫が足りている割合」（`getHusbandryWorkerFactor`）を掛ける。
2. 牧草地がない年は、そのセルに牧夫の仕事がない（必要な人数0）。その場合は割合を1とみなすので、次の計画で牧草地を全部置く。
3. 牧草地がある年は牧夫が必要になるが、畑が人手を取るので牧夫が雇われず、割合が0になり、次の計画で牧草地が消える。
4. 牧草地が戻るたびに、その下の森が新しく切り開かれたとして数えられ（前の年の配置としか比べないため）、立木が減っていた。

**修正**: 牧草地は、前の年の広さから、牧夫が扱える広さとの差の4分の1ずつ近づける（`PASTURE_ANNUAL_ADJUSTMENT` = 0.25）。家畜の群れは1年で増減しないためである。

**結果**（seed 102、1〜6年目）

| 年 | 修正前の開墾（ha） | 修正後の開墾（ha） | 耕地の純増（ha、修正後） |
| --- | ---: | ---: | ---: |
| 1 | 420,916 | 22,582 | −218,000（最初の計画の調整） |
| 2 | 56,133 | 46,991 | +39,600 |
| 3 | 419,032 | 23,572 | +72,400 |
| 4 | 33,124 | 28,702 | +98,100 |
| 5 | — | 37,284 | +109,800 |
| 6 | — | 42,190 | +122,000 |

開墾は年2〜4万 ha（耕地 約2,200万 ha の0.1〜0.2%）になった。耕地の増加の多くは、森でない土地に広がっている。中世の開墾（assart）の速さと同じ桁である。

### 23.2 葬儀の薪（二重の数えを修正）

棺と火葬の薪は、地表の森から直接切り（`src/generators/funeralRites.ts`）、同じ量を市場の在庫からも引いていた。森から直接切るのをやめ、Economy が市場の在庫から引き、足りない分だけそのセルの森で切るようにした（`funeralGoodsConsumption.ts`）。市場から引いた量は、物の出入りの記録に「葬儀」（`funeral`）として残す（以前は記録されていなかった）。seed 102 で年 約1,700単位。

### 23.3 町の薪の支払いと寒さ

**支払い**（`heating.ts`）

- 町の家庭は、薪（足りなければ石炭）を市場の価格で、自分の財布（`householdWealth`）から買う。在庫が足りない時は、各町が払える量に応じて分ける。
- 薪の代金は、木を切って運んだ農村の財布へ入る（市場に食料の台帳がまだない時は商人の資金へ）。石炭の代金は商人の資金へ入る。月の支払いは `heatingLedger.urbanFuelSpending`。
- 農村の家庭が自分の森で足りない分を市場から取る時は、払わない。同じ市場の農村の財布から出て同じ財布に戻るためである。

**寒さ**

- 薪を買えない・見つからない町は、まず調理に使い、暖房を減らす。`Burg.coldExposure`（0〜1）= 暖房の足りない割合 × その月の寒さ（月平均0 °C で1）。
- 人口（`demography-simulator.ts`）: 寒さ1の月が続くと、年率で老人の30%（月2.5%）が死ぬ。子供はその半分、働く大人は10分の1。4か月の冬で老人の約1割で、薪の飢饉（1709年の大寒波）の冬の死亡の増え方と同じ桁にした。死因は「病気」（冬の死者の多くは悪寒・肺炎・インフルエンザ）として記録する。農村の家庭は自分で燃料を取るので、飢饉と同じく対象外。
- 体調不良: 都市の健康の圧力（`healthPressureFromSanitation`）に、寒さ × 0.2 を足す（石炭の煙は × 0.22）。

**結果**（6年目の1年間）

| 項目 | seed 102 | seed 101 |
| --- | ---: | ---: |
| 町の家庭の燃料の支払い | 32,196 | 11,514 |
| 寒さのあった町・月の数 | 58 | 0 |
| 寒さの最大 | 0.89 | 0 |
| 寒さのあった住民（人・月の合計） | 約18万 | 0 |
| 足りなかった燃料（単位） | 1,643 | 25 |

- seed 102 の町の住民（約29万人）の燃料費は1人年 約0.11で、穀物（1人年 0.43単位）の4分の1ほどにあたる。財布の乏しい町では冬に暖房が足りなくなる。
- 寒さで死んだ人数そのものは、この計測では数えていない。

### 23.4 テスト

- `heating.test.ts`: 町が燃料を払い、代金が失われずに農村（または商人）へ渡ること。払えない町は寒さが0.9を超え、暖かい月は寒さが0になること。
- `demography-cold.test.ts`（新規）: 寒さ1の1か月で、老人2.5%・子供1.25%・大人0.25% が死ぬこと。寒さ0では減らないこと。

### 23.5 残っている課題

1. 寒さの死者を、死因の集計で「病気」と分けて見られるようにするか（新しい死因を足すと、保存の形式と表示が変わる）。
2. 農村の家庭の燃料不足（森も市場もない場合）の影響は入れていない。わら・泥炭・乾いた糞で補ったと考えている。
3. 牧草地の広さは、牧夫が畑に取られて足りないセルで年々小さくなる。家畜と人手の配分は別に確かめる。
