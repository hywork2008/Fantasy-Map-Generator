# 農業労働の校正（史料調査）

## 0. 目的

[rural-food-labor-audit.md](rural-food-labor-audit.md) の問題 C では、「労働の不足が収穫を減らさない」ことを直すつもりだった。ところが、労働の充足率を収穫に掛けると、充足率は0.43になり、収穫が半分以下に落ちた（同 §6.3）。

本書は、その前提になっている4つの値を史料で確かめ、校正の案を示す。

1. 成人1人の年間の農作業日数（`WORKABLE_DAYS_PER_ADULT = 140`）
2. 月ごとの労働能力（今は一律 `140 ÷ 12 = 11.7日`）
3. 1 ha あたりの労働日数（`LABOUR_DAYS_PER_HECTARE = 30`）と、作業の月への配分（`labourByStage`）
4. 労働で耕せる以上の面積を、土地利用の台帳が割り当てていること

**2026-10-18 起案**。本書は史料調査と校正の案である。

**2026-10-18 実装（案 1〜3）**: §6 に結果を書く。

**2026-10-18 実装（案 4 の収穫の部分）**: すぐに掛ける方式で実装した（§7）。対象は既にある畑だけで、新しい開墾は別の労働の枠（`settlementClearance.ts` の `clearanceLabor`、140日/ha、畑の維持の後の残り）で進む。人口の上限と土地利用の台帳の変更は未着手。

**2026-10-18 実装（案 5）**: 季節の出稼ぎを、市場圏の中の町と農村からの収穫の手伝いとして実装した（§8）。

## 1. 史料

### 1.1 年間の労働日数

| 出典 | 値 | 備考 |
| --- | --- | --- |
| Columella 2.12.8–9 | 290日/年 | 祝日・悪天候45日、播種後の休み30日を除く（ローマ） |
| 中世キリスト教圏の推計 | 約270日 | 日曜と約45の祝日を除く |
| Clark (2018) | 250〜300日 | |
| Kenyon (1934) | 通常は308日、日雇いの一部は120日 | Schor が引いたのは120日の方 |
| Clark (1986、未刊行。二次資料経由) | 家族で自分の土地に150日、成人男子135日 | |
| 14世紀の荘園帳簿 | 隷農の労働者 約175日 | 二次資料経由 |

- 成人男子の実働は250〜300日だった。そのうち自分の畑の作業は135〜150日ほどで、残りは家畜の世話、運搬、雇われ仕事、手工業などである。
- 女性が畑に出るのは主に繁忙期（収穫）で、普段は家事・家内工業・家畜の世話をした。16歳以上の男子は成人の約4分の3、10〜15歳の子は約半分の労働として数える推計がある（Devereaux）。

**判断**: 男女の成人をならした「農作業に回せる日数」140日は、これらの史料と矛盾しない。変えない。

### 1.2 収穫期の集中

- 収穫期は、村じゅうの働ける人が日の出から日没まで働いた（複数の二次資料）。女性は刈り取りの後の束ね・積み上げ（stook）を担い、落ち穂拾いは子ども連れの女性が中心だった。男女の分担はあいまいだった（Many-Headed Monster、State Library Victoria）。
- 荘園の直営地では、1年の作業の大部分を常雇いの famuli がこなした。賦役（boon work、Reapale）と臨時雇いは、収穫と犂耕の時期に集中した（Goose、Meopham 1307–75、Walsham の研究）。c.1300の400超の荘園の帳簿では、famuli は男性中心の1段目と、女性・若者・老人の2段目に分かれていた（LSE の研究）。
- 収穫の前後には大きな祭りが集まるが、収穫期そのものは休みが少ない。

**判断**: 収穫の月は、成人1人が平月の約2倍、日曜・祝日以外のほぼ毎日（約24日）働いたとみてよい。今の一律11.7日では、収穫の月に必要な人手が平月の6倍になってしまう（§2）。

### 1.3 1 ha あたりの労働と、作業の時期

| 出典 | 小麦 | 備考 |
| --- | --- | --- |
| Columella | 44人・日/ha（収穫を除く）＋刈り取り5.7 | 犂耕4回、中耕2回の集約的な地中海の栽培 |
| Columella を補正（Spurr、Rosenstein） | 1 iugerum あたり14.25〜19.5日（57〜78日/ha） | 脱穀など Columella が省いた作業を含む |
| Clark の1300年ごろの推計（既存の設計書） | 1 acre あたり成人男子11〜14日（27〜35日/ha） | イングランド |
| 鎌での刈り取り | 10〜30人・日/ha | 脱穀・風選は刈り取りとほぼ同じ労働 |

- **脱穀は冬の仕事だった**。北欧では刈った穀物を束のまま納屋に置き、冬に屋内の脱穀場で殻竿（flail）で打った（Reading 大学の農村博物館の所蔵品記録、Met Museum の Cloisters の記事、Patcham 荘園の研究）。豊作の年は翌年まで続いた。
- **脱穀は量に比例して支払われた**。1319–20年と1350–51年の荘園の帳簿（Merton）では、脱穀は穀物1 quarter あたりの出来高払いだった。脱穀の労働は、面積ではなく収穫量に比例する。
- 犂耕と播種は、秋分から12月初めまでの2か月余りに分散した（Columella）。休閑地は春・夏・秋に1回ずつ耕した。

**判断**:

- 30日/ha は、イングランドの水準（Clark）として妥当である。地中海の集約栽培（57〜78日/ha）は別の体系とみる。
- 一方、今の作物暦（`stapleCrops.ts` の `labourByStage`）は、収穫と脱穀を合わせた「harvestAndProcessing」の0.50〜0.55を、収穫の30〜45日に詰め込んでいる。史料では、脱穀は収穫の後の冬に分散し、量に比例する。

## 2. モデルとの差（seed 102、地図生成直後〜13か月）

| 項目 | モデル | 史料 |
| --- | --- | --- |
| 年間の農作業日数 | 140日 | 135〜150日（家族、自分の畑） |
| 収穫の月の労働能力 | 11.7日（一律） | 約24日（平月の約2倍） |
| 収穫の月に集中する作業 | 年の50〜55% | 刈り取り・束ね・運搬で約30%。脱穀は冬 |
| 脱穀の労働 | 面積に比例 | 収穫量に比例（出来高払い） |
| 収穫の月の必要人手 ÷ 年平均 | 0.55 × 140 ÷ 11.7 ≒ **6.6倍** | 0.30 × 140 ÷ 24 ≒ **1.75倍** |

seed 102 は南緯43〜57度、年平均気温7℃、年降水量1,500 mm ほどの冷涼で多湿な地図である。収量の倍率の中央値は約0.38（169 kg/ha）と低い。

- 年単位で見ても、畑の作業が成人 × 140日を超えるセルに、農村人口の40%が住んでいる。
- 脱穀を量に比例させても（労働の3〜4割を量比例とする）、その割合は31〜34%までしか下がらない。年単位の充足率で見た収穫 ÷ 必要量は、0.83 → 0.89〜0.91 になる。
- 残る不足の原因は、地図を作る時の人口の上限（`subsistenceCapacity`）が、収量の低い土地で「自分たちの労働で耕せる面積」を見ていないことである。土地利用の台帳も、労働で耕せる面積を超えて `必要面積 × 1.1` を割り当てる（`planSettlementLandUse`）。
- 史実では、こうした冷涼で多湿な土地は、牧畜の比重が高く、人口密度も低かった。

## 3. 校正の案

### 案 1: 作物暦の作業配分を、収穫と脱穀に分ける（`stapleCrops.ts`、`cropCalendars.ts`）

- `harvestAndProcessing` を、次の2つに分ける。
  - `harvest`（刈り取り・束ね・運搬）: 収穫の期間に配分する。
  - `processing`（脱穀・風選）: 収穫の後の4〜5か月（冬）に均等に配分する。
- 出発値は、穀物で `establishment 0.20 / maintenance 0.25 / harvest 0.30 / processing 0.25`。脱穀≒刈り取りという史料に合わせる。
- 犂耕・播種（`establishment`）は、1か月ではなく2か月に分ける。

### 案 2: 脱穀の労働を収穫量に比例させる（`agriculturalLandUse.ts`）

- 1 ha あたりの労働日数を、面積に比例する部分と、収穫量に比例する部分に分ける。
  - `LABOUR_DAYS_PER_HECTARE × (1 − PROCESSING_SHARE + PROCESSING_SHARE × 収量 ÷ 450)`
  - `PROCESSING_SHARE = 0.25`（案 1 の processing の割合）。基準の450 kg/ha は、30日/ha を校正したイングランドの水準である。
- 収量の低い土地では、脱穀の分だけ労働が減る。

### 案 3: 月の労働能力を、収穫の月だけ引き上げる（`ruralOccupationAllocation.ts`）

- 月の労働能力を `WORKABLE_DAYS_PER_ADULT_PER_MONTH × 月の倍率` にする。倍率は、その月の作業量が年平均を超える月で最大2.0（約24日）とする。
- 年間の上限（140日）は `getAnnualRequiredAdults` で今どおり守る。繁忙月に多く働いた分、閑散月は働かない。
- 互助（隣のセル）と家族の手伝い（子ども0.35・老人0.4）は、今の値のまま残す。

### 案 4: 収穫に労働の充足率を掛ける（問題 C の本体）

- 案 1〜3 の後で、`seasonalLaborShortage` から求めた充足率を、セルの収穫に掛ける。
- 地図を作る時の人口の上限（`subsistenceCapacity` の農業の分）にも、同じ労働の充足率を掛ける。自分たちの労働で耕せない面積は、上限に入れない。
- 土地利用の台帳の割り当て（`max(必要面積 × 1.1, 労働で耕せる面積)`）は、労働で耕せる面積を上限にする。
- 旧セーブでは、最初の年に収穫が下がる。それでも人口は数年で、労働と食料の釣り合う水準へ移る。ここは移行の影響として受け入れるか、充足率を数年かけて掛け始めるかを決める必要がある。

### 案 5: 季節の出稼ぎ（問題 E）

- 案 4 の後で、残った `seasonalLaborShortage` を、近くの都市の住民が収穫の月だけ農村で働いて埋める。
- 史料（rural-food-labor-audit.md §1.2）に合わせ、近世以降（Historical period）で強く、中世は互助と家族の手伝いだけにする。

## 4. 実装の順序（提案）

1. 案 1 と案 2（作業配分と脱穀）。月の不足と移住の余力が変わるだけで、収穫は変わらない。
2. 案 3（収穫の月の労働能力）。
3. 計測: 労働の充足率の分布と、年単位で労働が足りないセルの人口の割合。
4. 案 4（充足率を収穫と人口の上限に掛ける）と、移行の方法の決定。
5. 案 5（季節の出稼ぎ）。

案 1〜3 では収穫は変わらない。変わるのは雇用・移住の余力（`migratableAdults`、`ruralReleasePressure`）と、季節の不足の値である。ただし旧セーブの動きも変わるので、Node 用の基準データを更新する。案 1・2 は `agriculturalLandUse.ts` と作物暦を変えるので、地図生成側の収量の推定表（`foodClimateCalibration.json`）も作り直す。

## 6. 案 1〜3 の実装と結果（2026-10-18）

### 6.1 実装した内容

- **案 1**（[cropCalendars.ts](../../src/data/cropCalendars.ts)、[seasonalCropClimate.ts](../../src/extensions/economy/generators/seasonalCropClimate.ts)、[stapleCrops.ts](../../src/data/stapleCrops.ts)）
  - `labourByStage` に `processing`（脱穀・風選）を足した。収穫が終わった月の翌月から4か月（`PROCESSING_MONTHS`）に均等に配分する。
  - 犂耕・播種（`establishment`）は、植え付けの月とその前の月に半分ずつ配分する。
  - 配分の値は次のとおり。根菜と永年作物は変えていない。
    - 寒冷地の穀物: 0.20 / 0.25 / 0.30 / 0.25
    - 温暖地の穀物・豆: 0.22 / 0.28 / 0.28 / 0.22
- **案 2**（[agriculturalLandUse.ts](../../src/extensions/economy/generators/agriculturalLandUse.ts) の `getYieldScaledLabourMultiplier`）
  - 作物の組み合わせのうち脱穀の割合の分だけ、1 ha あたりの労働を `収量 ÷ 450 kg/ha` に比例させる。
  - 年の労働の計算（`calculateAgriculturalLandProfile`）と、開墾・土地利用の台帳への入力（`reconcileForestClearanceForAgriculture`）の両方に入れた。
- **案 3**（`getMonthlyWorkDaysPerAdult`、[ruralOccupationAllocation.ts](../../src/extensions/economy/generators/ruralOccupationAllocation.ts)）
  - 畑の作業が月平均を超える月は、成人1人の月の労働日数を最大2倍（約23日、`PEAK_MONTH_WORK_MULTIPLIER`）にする。
  - 次の4か所で使う: 職の割り当て、隣のセルの互助の余力、家族の手伝い、季節の不足。
  - 年間の必要人数は、今どおり年140日で数える。
- 地図生成側の収量の推定表を作り直した。計算は約290秒かかるため、計算時だけ実行するテストの時間制限を900秒に延ばした。

### 6.2 結果（seed 102、Independent、13か月後）

| 項目 | 修正前 | 修正後 |
| --- | --- | --- |
| 季節の不足 ÷ 年の必要労働 | （畑の作業の約57%） | 21% |
| 季節の不足を収穫に掛けた場合の、収穫 ÷ 必要量（試算） | 1.04 → 0.45 前後 | 1.05 → **0.94** |
| 必要労働 ÷ 成人（人口加重） | 1.34 | 1.22 |
| 必要労働が成人を超えるセルの人口の割合 | 40% | 38% |

- 案 1〜3 は収穫を変えない。変わるのは、職の割り当て・移住の余力・季節の不足である。
- 季節の不足を収穫に掛けた場合（案 4）の影響は、収穫の約1割減まで小さくなった。案 4 を入れられる段階になった。
- 必要労働が成人を超えるセルは、まだ人口の約4割ある。地図を作る時の人口の上限と土地利用の台帳が、労働で耕せる面積を見ていないためで、案 4 の後半（人口の上限と台帳の面積）で扱う。

### 6.3 次の判断

案 4 の移行の方法を決める必要がある。

- **すぐに掛ける**: 旧セーブと既存の地図では、最初の年に収穫が約1割下がる。
- **数年かけて段階的に掛ける**: 例えば5年かけて、充足率の効き目を0から1まで上げる。

## 7. 案 4（収穫に労働の充足率を掛ける）の実装と結果（2026-10-18）

### 7.1 実装した内容

- `getCropLaborCoverageByCell`（[developmentPotential.ts](../../src/extensions/economy/generators/developmentPotential.ts)）
  - 毎年の農業の更新で、セルごとの充足率を求めて `cropLaborCoverage` 列に保存する。
  - 充足率 = 1 − Σ月 min(畑の作業日数, 季節の不足) ÷ Σ月 畑の作業日数。不足は畑の作業に先に充てる。
- [foodProduction.ts](../../src/extensions/economy/generators/foodProduction.ts) で、セルの収穫に充足率を掛ける。旧セーブで列がない間は 1 として扱う。
- **すぐに掛ける**方式にした。対象は地図を開いた時点で既にある畑で、地図の開始前の開墾は済んでいる扱いである。新しい開墾は、畑の維持の後に残った労働の一部（専用の枠）で、140日/ha をかけて進む。
- 次の2つは見送った。
  - **土地利用の台帳を、労働で耕せる面積に抑える**: 季節の不足は、年単位の不足も含んでいる。両方を入れると不足を二重に引く。
  - **地図を作る時の人口の上限**: 地図生成側の推定に関わるので、別の作業とする。

Megacity で成人が都市へ出ると、村の畑の労働が足りなくなり、農村の自給が下がる。「出しすぎると食料が減る」釣り合いが表れた。

### 7.3 残っている課題

1. 地図を作る時の人口の上限（`subsistenceCapacity`）に、労働の充足率を入れる。
2. 案 5（季節の出稼ぎ）。Megacity では、蓄えの尽きた農村の住民が3割に増えた。都市から農繁期に人が戻る仕組みが効く場面である。
3. 都市の受け入れ枠の後背地の余剰（`hinterlandSurplusUrbanPoints`）は、まだ土地の能力（`ruralFoodCapacity`）で数えていて、労働の充足率を見ていない。
4. seed 103 の15年の sim は、1024MB の上限で、最後の保存の時にメモリが足りなくなった。標本は60件とも出力済み。

## 8. 案 5（季節の出稼ぎ）の実装と結果（2026-10-18）

### 8.1 実装した内容

`applyRegionalHarvestHelp`（[ruralOccupationAllocation.ts](../../src/extensions/economy/generators/ruralOccupationAllocation.ts)）

- 毎月、家族の手伝いと隣のセルの互助で埋めても残る不足を、同じ市場圏の中の次の2つで埋める。
  - **町の手伝い**: 市場圏の町の成人 × `getUrbanHarvestHelpShare`。繁忙月の日数（約23日）で働く。先に使う。
  - **旅する農村の働き手**: 市場圏の他のセルで、その月に手の空いた成人の日数 × `getRegionalHarvestMobility`。
- 埋めた日数は、受け入れたセルの「受けた手伝い」として数える。不足（`seasonalLaborShortage`）と収穫の充足率（`cropLaborCoverage`）が改善する。旅に出た働き手は、自分のセルの暦で雇われた扱いになる（互助と同じ）。
- 時代ごとの値は次のとおり。いずれもゲーム上の校正値である。

| 時代 | 町の成人のうち収穫に出る割合 | 手の空いた農村の成人のうち旅に出る割合 |
| --- | --- | --- |
| lateMedieval 以前（古代を含む） | 5% | 25% |
| 近世（ageOfExploration・maritimeEra） | 10% | 40% |
| それ以降 | 15% | 50% |

- 中世の荘園でも、臨時雇いが収穫の重要な担い手だった（Goose）。数か月だけ来て帰る大規模な出稼ぎは、近世以降に大きくなる（rural-food-labor-audit.md §1.2）。時代ごとの割合の差はこれに合わせた。

## 9. 人口の上限と都市の受け入れ枠に労働を入れる（2026-10-18）

### 9.1 実装した内容

- **自分たちの労働で作れる穀物の割合**（`getFieldLabourFeasibility`、[settlementClearance.ts](../../src/generators/settlementClearance.ts)）
  - 1人が必要とする畑の面積 × 1 ha あたりの労働（脱穀の分は収量に比例）を、成人の割合（0.45）× 年140日と比べる。
  - 収量がおおむね 200 kg/ha 以上なら1（自給できる）。150 kg/ha で0.82、110 kg/ha で0.62、80 kg/ha で0.46。
  - 労働の定数（30日/ha、140日、脱穀の割合0.25、成人の割合0.45）は、地図生成側に移して一本化した。経済拡張側は `LABOUR_DAYS_PER_HECTARE` と `WORKABLE_DAYS_PER_ADULT` として、同じ値を使う。
- **地図を作る時の人口の上限**（[subsistenceCapacity.ts](../../src/generators/subsistenceCapacity.ts)）
  - 農業で養える人数に、上の割合を掛けた（`generateSubsistenceCapacity`、`refreshEstimatedSubsistenceCapacity`）。
  - 毎年の更新（`reconcileSubsistenceCapacityFromFood`）も、労働で耕せる分の畑の能力（`labourLimitedFoodCapacity`）で行う。こちらは作物の組み合わせ・農業技術・輪作を反映した値である。
- **都市の受け入れ枠の後背地の余剰**（[urbanFoodCapacity.ts](../../src/extensions/economy/generators/urbanFoodCapacity.ts)）
  - 耕せる土地の全部ではなく、実際に耕している畑 × 労働の充足率で数える（`getWorkedFoodCapacity`）。
  - 漁村・牧畜の住民の穀物の割合の計算には、今どおり土地の能力を使う。

## 10. Megacity の受け入れ枠の調査（2026-10-18）

§9.3 の課題 1（受け入れ枠が食料に比べて大きすぎる）を調べた。結論として、**受け入れ枠は食料の上限になっていない。原因は、都市の家計のお金が1年の途中で尽きることである**。受け入れ枠は変えていない。

### 10.1 計測（seed 102、Megacity、計測用のスクリプト）

8年目の全体の値。単位は都市の人口点。

| 項目 | 値 |
| --- | --- |
| 都市の人口 | 755 |
| 受け入れ枠（`capacity`） | 1,032（上限は種の能力の3倍） |
| 後背地で実際に作っている余剰 | 2,202 |
| 後背地の土地の能力から見た余剰 | 2,731 |
| 輸入による枠の上乗せ | 67 |

- 後背地の余剰は都市の人口の約3倍ある。受け入れ枠は、余剰ではなく上限の倍率（3倍）で決まっている。
- 食料の充足が0.73〜0.82の市場（1・2・3・9番）では、市場の穀物庫に都市の需要の10〜13四半期分の在庫がある。農家が売りに出した量も、都市の需要の5〜11倍ある。

### 10.2 原因: 都市の家計のお金が尽きる

市場1番の四半期末の値（`settleMonthlyFoodConsumption`）。

| 月 | 農村の必要量 → 充足 | 都市の必要量 → 買えた量 | 在庫 |
| --- | --- | --- | --- |
| 12月 | 20,093 → 20,093 | 8,547 → 8,547 | 53,879 |
| 3月 | 20,134 → 20,134 | 8,551 → 7,040 | 130,869 |
| 6月 | 20,177 → 20,177 | 8,554 → 2,032 | 125,160 |
| 9月 | 20,221 → 20,221 | 8,556 → 169 | 116,932 |

- 在庫は十分にある。それでも都市が買える量は、春から秋にかけて減っていく。都市の購入は家計のお金で頭打ちになる（`drawBurgMonthlyNeed` の `maxAffordableUnits`）。
- 別の年の月ごとの家計を見ると、手元のお金（穀物価格で何か月分の食費か）は、毎月約0.6か月分ずつ減る（9.0 → 1.6か月、2月〜翌1月）。収入が食費の約4割しかない。年の変わり目に町の金庫から家計へまとまったお金が入り、持ち直す。
- これは引き継ぎ時点の「都市の食費 ÷ 必要量 27〜48%」と同じ問題である。Megacity では、移住者が都市の人口を増やすので、家計1人あたりの収入がさらに薄くなる。

### 10.3 見つかった不具合: 不足の割合の振り分け

- 四半期末の食料不足の割合は、農村と都市の不足の合計を両者に同じ割合で振り分けている（農村には揺らぎ0.8〜1.2倍を掛け、残りを都市へ）。
- 実際の取り崩しは農村が先で、上の表のとおり農村は毎月満たされている。それでも農村の不足の割合は0.27と記録され、農村の食料ストレスの数え方（`ruralFoodStressQuarters`）が誤って進む。都市の不足の割合もその分ずれる。

### 10.4 次の判断

1. **都市の家計の収入**（引き継ぎ時点のお金の較正の残り）。食料が足りているのに都市が飢える原因はこれで、Megacity の都市の伸びを止めている。案は2つある。
   - 生産の賃金の倍率（`WAGE_SUBSISTENCE_MULTIPLE = 1.5`）を見直す。
   - 移住者の職（雇用の需要）と賃金の支払いの対応を調べる。
   - → §11 で調べた。原因は別のところ（農家が町で使うお金が町の家計に入らない）にあった。
2. **不足の割合の振り分けの修正**（§10.3）。実際に満たされた量から、農村と都市の不足の割合を別々に求める。
3. **受け入れ枠の上限**（3倍）。家計が直った後に、まだ大きすぎるかを測り直す。

### 10.5 §10.3 の修正（2026-10-18）

- [foodLedgerConsumption.ts](../../src/extensions/economy/generators/foodLedgerConsumption.ts) の四半期末の不足の割合を、農村・都市それぞれの「必要量に対して満たせなかった割合」にした。合計の不足を同じ割合で振り分ける処理と、そのための揺らぎ（`getShortfallJitter`）は削除した。
- 回帰テストを追加した。農家は自分の蓄えで食べ、町には市場の穀物がない場合に、農村の食料ストレスが0のまま、都市だけ不足が数えられることを確かめる。修正前のコードでは、このテストは失敗する。

## 11. 都市の家計の収入（§10.4 の 1、2026-10-18）

### 11.1 計測: 都市の家計のお金の出入り

seed 102、Megacity、7年目から1年。お金を動かす処理ごとの都市の家計・都市の金庫の増減を、都市の年間の食費（地元の穀物価格）の何か月分かで表す（`createMoneyFlowRecorder` を使う計測用のスクリプト）。

| 処理 | 都市の家計 | 都市の金庫 |
| --- | ---: | ---: |
| 食料の購入（`food:consumption`） | −9.9 | — |
| 町での支出（`spendUrbanHouseholdSurplus`） | −1.2 | +1.2 |
| 生産の賃金など（`production:burgLoop`） | +3.1 | −1.8 |
| 市場の利益の払い出し（中心の都市、1月にまとめて） | +1.6 | — |
| 人物の生活費 | +0.8 | — |
| 行政の給与 | +0.6 | −0.5 |
| 海軍の乗員の給与 | +0.4 | — |
| **農家が町で使うお金（`spendRuralHouseholdsInTowns`）** | — | **+2.8** |
| 金庫の余剰の年1回の回収（`GuildTreasury.settleAnnual`） | — | **−20.8** |

- 都市の家計の収入は食費の約55%（12か月分に対して約6.5か月分）で、§10.2 の「収入が食費の約4割」と合う。
- **生産の賃金は需要で頭打ちになっている。** 都市の金庫には食費の8〜28か月分のお金があり、生産は金庫の残高ではなく、商品の需要で止まっている。§10.4 の案（`WAGE_SUBSISTENCE_MULTIPLE` を上げる）は、賃金の割合が高い商品の費用を上げるだけで、雇う量は増えない。
- **農家が町で使うお金が、町の人の収入になっていなかった。** 塩・道具・布・鍛冶・粉挽き・市の代金は、それを作って売った職人・商人・運び手の稼ぎである。ところが全額が都市の金庫に入り、金庫は生産の需要以上のお金を使えないので、年末に余剰として市場と国庫へ回収されていた。
- 移住者の職（§10.4 の2つ目の案）: 都市の雇用は生産の労働だけで、生産は需要で決まるので、人口が増えても賃金の総額は増えない。Megacity で1人あたりの収入が薄くなるのはこのためである。今回は扱わない（§11.4）。

| 生産の賃金 | +3.1 | +1.8 | +2.5 | +2.6 |
| 市場の利益の払い出し | 0 | +4.0 | +0.9 | +1.7 |
| 人物の生活費・海軍の給与 | +5.8 | +2.9 | +0.1 | 0 |
| 町での支出（金庫へ） | −4.8 | −9.1 | −0.8 | −1.6 |

（市場の利益の払い出しは、§12.2 の変更後の値）

- 首都と市場の中心は、食費を超える収入があり、余りを町で使って金庫に入れている。その他の都市は、収入が食費の8〜9割で、手元の現金は食費0.7か月分前後に張り付く。
- 市場ごとに見ると、飢える理由は3通りある（10年目の1年間）。
  1. **金庫にお金がある町で家計が飢える**（市場3）: 町の金庫には食費8.9か月分、家計は0.75か月分。金庫は、生産が使う以上のお金を持っている。
  2. **中心の都市だけが豊か**（市場2）: 首都は家計9か月分・金庫9か月分。周りの町は家計0.7か月分・金庫0.3か月分。市場全体の食料の充足は0.67。
  3. **市場全体にお金がない**（市場5・12・15）: 町の家計も金庫も0で、農家の財布も小さい。穀物の足りない農家が市場から買い戻している（年2万）。在庫は1年分以上あるのに、充足は0.1前後。
- 穀物そのものが尽きている市場はほとんどない（都市の必要量の1%）。

### 12.2 実装した内容

1. **市場の利益の払い出しを、市場のすべての町へ**（`payOutMarketSurplus`、[householdWealth.ts](../../src/extensions/economy/generators/householdWealth.ts)）
   - 商人の利益（1/3）を除いた残りを、市場の中心の都市だけでなく、市場のすべての町へ人口比で入れる。
   - 穀物の小売りの稼ぎ（穀物商・計量人・運搬人・荷馬車引き）は穀物が売られる所、つまり人の住む所で生まれるので、町の人口に比例する。
2. **町の公共事業の賃金**（`payTownWorks`、[townWorks.ts](../../src/extensions/economy/generators/townWorks.ts)）
   - 町の家計の現金が食費の2か月分（`TOWN_WORKS_TARGET_MONTHS`）を下回る間、町は自分の金庫から、町の住民を城壁・舗装・井戸・夜警・穀物庫の運搬などに雇う。
   - 金庫は食費2か月分（`TOWN_WORKS_RESERVE_MONTHS`）を手元に残し、その上の10%（`TOWN_WORKS_TREASURY_SHARE`）を月に使える。家計の不足分までしか払わない。
   - 毎月、市場の利益の払い出しの後、税の前に行う。

- テスト: `townWorks.test.ts`（手元に残す額と、不足分までしか払わないこと）。

### 12.5 見つかったこと: 雇用の需要と賃金が対応していない

- 移住を呼ぶ雇用の需要のうち、賃金が町の家計に入るのは、生産（工芸）と行政（国の給与）、運送・小売（市場の利益の払い出し）だけである。
- **鉱山・製錬・採石・建築の労働者には、賃金が払われていない**（`mineOperations.ts`・`smelterOperations.ts`・`constructionHire.ts`・`constructionEmployment.ts` に家計への支払いがない）。サービスの雇用（基幹の1.5倍）も、町の家計の中を回るだけで、外からのお金にはならない。
- §10.4 の「移住者の職と賃金の支払いの対応」はこれである。対応には、誰が払うか（鉱石・地金の買い手、国の公共事業費 `departmentBalances.publicWorks`、建築の発注者）を決める必要がある。

### 12.6 残っている課題

1. **基幹の雇用の賃金**（§12.5）: 鉱山・製錬・採石・建築の賃金を、産物の売り上げや発注者から町の家計へ払う。 → §13
2. **移住が飢えを見ない**: Megacity の移住の量に、行き先の食料の充足（または家計の現金）を入れるか。入れると、都市は飢える前に伸びが止まる。
3. **市場全体の貧困**（§12.1 の 3）: 穀物の足りない農村の市場は、農家・町・市場のどこにもお金がない。地域をまたぐお金の流れ（国の給与、輸出の代金）を調べる。
4. **都市の現金の偏り**（§11.4 の 1）: 首都と市場の中心は余りを町で使い、金庫から年1回、市場と国庫へ回収される。周りの町には戻りにくい。
5. **時間の進め方で結果が変わる**: 計測の途中で、同じ地図・同じ設定でも、10年を一度に進めた場合（`advance({ years: 10 })`）と1か月ずつ進めた場合で、Megacity の10年目の都市の人口点が約410 → 約740と大きく違った。一度に進めると、月ごとの処理（食料・家計・移住）がまとめて行われるためと考えられるが、未確認。§9〜§12 の計測はすべて1か月ずつ（`npm run sim` は3か月ずつ）進めている。

## 13. 鉱山・製錬・採石・公共事業の賃金（§12.6 の 1、2026-10-18）

### 13.1 史料

採掘と建築の労働は、国家の体制と時代で「誰が払うか」「払うか、養うだけか、課すか」が分かれる。

**採掘**

| 時代・体制 | 組織 | 労働 | 支配者の取り分 |
| --- | --- | --- | --- |
| 古典期アテネ（ラウレイオン銀山） | 国が採掘権を市民に貸す | 借り手が持つ奴隷が主（1,000人の奴隷を貸した例）。貧しい日雇いも | 借地料 |
| ローマ帝国の鉱山（ヴィパスカ銅板、ダキアの契約書） | 皇帝の所有。procurator が管理し、請負人（conductores）に貸す | 主に賃金労働。賃金を記した契約書が残る。囚人（damnati ad metalla）は石切り場の例が知られる | 皇帝の取り分 |
| 中世・近世の中欧（Goslar、イフラヴァ、クトナー・ホラ、ヨアヒムスタール、シュヴァーツ） | 鉱業権（Bergregal）は君主のもの。採掘は出資者の組合（Gewerken）が行い、鉱夫を雇う。12〜13世紀に鉱夫の自由（Bergfreiheit）が成立 | 賃金労働。ヨアヒムスタールでは鉱夫9,200人 | 十分の一税（Zehnt）。銀は君主の造幣所に定価で納める。帝国都市 Goslar は1359年に鉱業権を買い取った |

**賃金の水準**

- 中世以来の賃金の系列は、建築の職人と作業員の日給が基本になっている（Phelps Brown と Hopkins 1956、Allen 2001）。他の職は出来高払いが多く、日給の記録が少ないためである。
- Allen の福祉比率では、作業員の稼ぎで4人家族の最低限の暮らし（bare-bones basket）を支えられるかを測る。多くの地域で1前後だった。

### 13.2 実装の前の状態

- 鉱山・製錬所・採石場・火山の採取場の産物は、市場の在庫にただで入っていた（`Markets.addMineSupply`）。市場はそれを売って利益を得るが、鉱夫の賃金・鉱山税・経営者の利益はどこにも払われていなかった。
- 国の公共事業費（`departmentBalances.publicWorks`）で道・港・穀物庫を造ると、そのお金は誰にも払われず消えていた。
- **雇用の枠が実際の人数の約100倍だった。** 鉱山の雇用の枠は人口点で数える（4 + 豊かさ×6 点。1点 = 1,000人なので最大3.4万人）。一方、同じ鉱山の実際の人数は別に定めてあり（40 + 豊かさ×80人、`getMineEmploymentPeople`）、表示にしか使われていなかった。seed 102・Megacity の9年目では、鉱山・製錬所・採石場の雇用が248点（24.8万人）で、基幹の雇用（592点）の4割を占めた。サービスの雇用（基幹の1.5倍）と合わせると、移住を呼ぶ雇用の需要が実在しない職で大きく膨らんでいた（§12.5）。

### 13.3 実装した内容

1. **採掘の産物の買い取り**（新規 [extractionPayments.ts](../../src/extensions/economy/generators/extractionPayments.ts)）
   - 市場は、産物の市場価格の0.8（`MINE_HEAD_PRICE_SHARE`、農家の庭先価格と同じ）を自分の現金から払う。払えない分は、今までどおり代金なしで入る。製錬所には付加価値（地金 − 鉱石 − 木炭）を払う。
   - 代金は、鉱山税、賃金、経営者の利益の順に分ける。
     - **鉱山税**（`MINING_ROYALTY_SHARE` = 0.1、十分の一税）: 君主国・神権国は国庫へ。共和国・連合は町の金庫へ（Goslar の鉱業権の買い取り）。無政府は取らない。
     - **賃金**: 実際の人数 × 生活賃金（生産の賃金と同じ `getSubsistenceWage`）。払える額までしか払わない。古典古代は労働の6割、古代末期は3割が不自由労働で、その分は賃金ではなく食い扶持（賃金の1/1.5）だけになる（`UNFREE_EXTRACTIVE_LABOUR_SHARE_BY_PERIOD`）。中世以降は0。
     - **経営者の利益**: 町の金庫へ（出資者の組合 Gewerken）。帝国（`formName` が Empire）は国の直営で、国庫へ（ローマの procurator、佐渡奉行）。
2. **公共事業の支払い**（新規 [worksPayments.ts](../../src/extensions/economy/generators/worksPayments.ts)、[publicWorks.ts](../../src/extensions/economy/generators/publicWorks.ts)）
   - 事業費の6割（`WORKS_LABOUR_SHARE`）を賃金、4割を資材とする。
   - 港・穀物庫: 賃金はその町の家計へ、資材はその町の市場へ払う。
   - 道路: 賃金は国の家計（町と農村、`payStateHouseholds`）へ、資材は道が通る市場へ、長さに比例して払う。
   - **道路の賦役**（`ROAD_CORVEE_SHARE_BY_FORM`）: 君主国・神権国は道路の労働の半分を賦役でまかなう。その分は国庫が払わず、道は安く造れる。共和国・連合・無政府は0。蒸気の時代からは、どの体制も0（賦役の廃止）。
3. **採掘の雇用を実際の人数で数える**（`crewSlot`、[basicEmployment.ts](../../src/extensions/economy/generators/basicEmployment.ts)）
   - 鉱山・製錬所の雇用の枠を、実際の人数（`getMineEmploymentPeople`・`getSmelterEmploymentPeople`）の人口点にした。採石場・火山の採取場は、産出が1人あたり（年12トンの石など）で決まるので、枠の数をそのまま人数として扱う。
   - 各施設が使う単位（産出・道具の需要の計算）はそのままにし、割り当てた人数を施設の単位に換算して戻す。

テスト:
- `extractionPayments.test.ts`（新規）: 君主国では国庫・町の家計・町の金庫に分かれ、お金の総量が変わらないこと。共和国では鉱山税が町に残ること。古代では賃金が食い扶持に下がり、帝国では利益が国庫に入ること。
- `basicEmployment.test.ts`: 実際の人数での割り当てに合わせて3件を直した（製錬所が先に人を取る順番、市場全体から人を集めること、行政が先に人を取ること）。
- `publicWorks.test.ts`: 君主国では道の労働の一部が賦役になり、国庫が払う額が減ることに直した。

### 13.5 体制による違い（まとめ）

| 体制 | 鉱山税 | 鉱山の利益 | 道路の労働 |

古典古代・古代末期は、どの体制でも採掘の労働の一部が不自由労働になる（アテネの民主政のラウレイオン銀山も奴隷労働だった）。

### 13.6 残っている課題

1. **採掘の産物の価格**: 鉱石・石の価格が、掘る人の賃金に届かない。価格（`Good.value`）か1人あたりの産出量を、史料で較正する。 → §14
2. **採石場・火山の採取場の表示**: 雇用の一覧（`employment-overview.ts`、`burgEmploymentComposition.ts`）は、採石場・火山の採取場の人数を人口点として表示している。§13.3 の3では、これを人数として扱った。表示を合わせる。
3. **住宅の建築**: 町の家計が家を建てる費用（石工・大工の賃金と資材）は、町の中のお金の移動なので入れていない。資材は市場から無償で取っており（`consumeForConstruction`）、石の買い手として採石場の収入にはなっていない。
4. **賦役の負担**: 道路の賦役は、国庫の支出を減らすだけで、農民の労働の時間を奪っていない（年8〜40日）。農業労働（§6〜§8）の季節の不足に足すかを決める。
5. §12.6 の 2〜5 はそのまま残る。

## 14. 採掘の産物の価格と、1人あたりの産出（§13.6 の 1、2026-10-18）

### 14.1 史料: 採掘の労働者1人が1年に生む価値

商品の単位（wagon、bullion、pallet）は会計上のロットで、トンとの換算は決まっていない（[goods-unit-scale.md](goods-unit-scale.md)）。そこで、トンあたりの価格ではなく、**労働者1人の1年の産出が、作業員の年の賃金の何年分にあたるか**で比べた。

| 事例 | 労働者 | 産出 | 1人あたり | 作業員の賃金との比 |
| --- | --- | --- | --- | --- |
| ウィールドの製鉄（1590年代） | 約9,000人（1574年、大半は採鉱と木炭の木の伐採） | 銑鉄 年9,000トン超 | 銑鉄 約1トン | 棒鉄は1596年に1トン10ポンド（ヨークシャーの契約）。銑鉄はその半分強として約0.7〜1年分（作業員は日給8ペンス前後、年250日で約8ポンド） |
| クトナー・ホラ（16世紀後半） | 約3,000人 | 銀 年2〜4トン | 銀 約1 kg | 約1.3年分（1500年頃のイングランドの換算。銀1 kg ≈ 5.4ポンド、作業員の年の賃金 ≈ 4.2ポンド） |
| クレムニツァ（1442年） | — | — | 銀 約1.5 kg | 約2年分（同上の換算） |
| メル（カロリング朝） | 採掘100人を含む250〜300人 | 鉛52トン、銀150 kg（推定の中心） | 銀 約0.5 kg、鉛 約0.2トン | 1年分前後 |

- 換算は国・時代をまたぐので、ずれは大きい。それでも、**採掘の労働者1人の1年の産出は、作業員の賃金のおよそ1〜1.5年分**だった。採掘の費用の大部分は賃金で、残りが鉱山税・坑木・出資者の利益になる。
- 製鉄では、銑鉄1トンに鉱石5.5〜7トンと木炭4.5〜5トンを使った（16世紀の高炉）。費用の大部分は木炭で、炉の作業員は少なかった。

### 14.2 モデルとの比較（seed 102、5年目。基準価格での1人あたり産出 ÷ 作業員の年の賃金）

作業員の年の賃金は、生活賃金（`getSubsistenceWage`）で 1.5 × 0.43 = 0.645（穀物価格1のとき）。

| 鉱山 | §13 の人数（40 + 豊かさ×80人） | 1人あたりの産出（賃金の何年分） |
| --- | ---: | ---: |
| 縞状鉄鉱（豊かさ4） | 360人 | 1.4 |
| 炭層（豊かさ4） | 360人 | 1.3 |
| 砂鉄（豊かさ1〜2） | 120〜200人 | 0.1〜0.4 |
| 金鉱脈（豊かさ1） | 120人 | 0.08 |
| 蒸発岩（硫黄、豊かさ2） | 200人 | 0.4 |
| 錫・銅・銀の花崗岩鉱床（豊かさ2） | 200人 | 人手なし（未稼働） |

- **大きな鉄・石炭の鉱山は史料の範囲（1〜1.5）に入っている。価格を変える必要はない。**
- **小さな鉱床・貴金属の鉱山は、人数が産出に比べて5〜10倍多すぎた。** 人数が鉱種によらず「40 + 豊かさ×80人」で決まっていたためである。
- **製錬所は、基準価格では赤字になる。** 鉱石1トンあたりの付加価値（地金0.8 × 価格 − 鉱石 − 木炭1 × 3）は、鉄 −1.8、銅 −1.5、錫 −1.2、鉛 −2.1、銀 +3、金 +9。卑金属の地金の価格が、鉱石と木炭の価格の合計より安い。人数（8 + 年産×2.5人、120トンで308人）も、炉の作業員が数人〜十数人という史料より多すぎる。
- 実際の市場価格では、鉄鉱石と石炭は在庫が売れ残り、価格が下限（基準の0.25倍）に張り付いていた。それでも鉱山は人を雇い続け、掘り続けていた。

### 14.3 実装した内容

1. **鉱山の人数を、産出の価値で決める**（`getMineEmploymentPeople`、[mineOperations.ts](../../src/extensions/economy/generators/mineOperations.ts)）
   - 人数 = 満員で働いた時の年の産出の基準価値 ÷（1.3 × 作業員の年の賃金）。1.3 は `EXTRACTION_OUTPUT_PER_WORKER_IN_WAGE_YEARS`（§14.1）。最小4人（`MINE_MIN_CREW_PEOPLE`）。
   - 満員の時の産出には、排水・技術・燃料・近づきやすさを入れる（`getMineExtractionFactor`）。条件の悪い鉱山は、同じ人数でも少ししか掘れないので、人数も少なくなる。
   - 雇用（`basicEmployment.ts`）、賃金（`extractionPayments.ts`）、較正の一覧（`calibrationOverview.ts`）が同じ人数を使う。
2. **製錬所の人数も同じ規則で決める**（`getSmelterCrewPeople`、[smelterOperations.ts](../../src/extensions/economy/generators/smelterOperations.ts)）
   - 人数 = 年の付加価値 ÷（1.3 × 作業員の年の賃金）。最小8人（炉の作業員）。卑金属の製錬所は付加価値が負なので、8人になる。
3. **売れない時は人を減らす**（`getMineHiringShare`）
   - 鉱山が雇う割合 = 市場価格 ÷ 基準価値（産出の価値で重み付け）。0.25（`MINE_MIN_HIRING_SHARE`、排水と維持の人員）から1まで。
   - 史料では、鉱石が見合う値で売れない時、出資者は追加の出資（Zubuße）をやめ、坑は止まった。これまでの鉱山は、売れ残っても下限の価格で掘り続けていた。
   - 毎年の雇用の見直しの時の価格で決める。

テスト:
- `mineOperations.test.ts`: 産出の価値から人数が決まること。小さな鉱床は最小の人数になること。価格が下がると雇う割合が下がり、下限で止まること。
- `basicEmployment.test.ts`: 人数の規則が変わったので、製錬所が先に人を取る順番の検証の数値を直した。

## 15. 卑金属の地金の価格（§14.5 の 1、2026-10-18）

### 15.1 原因

- 地金の基準価値は、どの金属も鉱石の2倍で付けてあった（鉄 鉱石2 → 地金4、銅 2.5 → 5、錫 3 → 6、鉛 1.5 → 3、ケイ素 3 → 6、銀 10 → 20、金 20 → 40 など）。
- その後、製錬の燃料として木炭（基準価値3、鉱石1につき1）が入った（`migrateSmeltingFuelAndAshGoods`）。地金の価値は直されなかった。
- その結果、地金1あたりの原料（鉱石1.25 + 木炭1.25）は、鉄 6.25、銅 6.9、錫 7.5、鉛 5.6、ケイ素 7.5 で、地金の価値（4〜6）より高くなった。高価な金属は2倍の幅が木炭を吸収できたので、まだ原料を上回っていた（地金 ÷ 原料：銀 1.23、金 1.39、クロム 1.12、ニッケル 1.16、モリブデン 1.28）。

### 15.2 史料

- 16世紀の高炉は、銑鉄1トンに鉱石5.5〜7トンと木炭4.5〜5トンを使った。重さでは木炭が大きく、費用でも木炭が最大の項目だった。炉の作業員は少なかった（§14.1）。
- 銑鉄・棒鉄の価格は原料の費用を上回り、製鉄は利益の出る事業だった（ウィールドでは1590年代まで炉と鍛冶場が増え続けた。1596年の棒鉄は1トン10ポンド）。
- 費用の内訳（木炭・鉱石・賃金の割合）の数値の史料は、今回は見つけられなかった（Hyde 1977、King 2011 が候補）。そこで、地金の価格が原料を上回る幅は、まだ原料を上回っていた高価な金属の中央値（1.25）に合わせた。この幅（地金の価値の約2割）は、炉の作業員・木炭焼きと運搬の管理・出資者の利益にあたる。

1. **金属の下流の生産の減少**: 道具・武器・大砲の生産が減った。国の軍需の発注と、町の工房の予算（材料費 + 賃金を金庫で払える分だけ作る）のどちらで減ったかを調べる。
2. **製錬所の人数**: 価値の規則では鉄の製錬所（年120トン）が約200人になる。史料の炉の作業員（十数人）より多い。製錬は資本（炉・水車）の割合が大きく、付加価値のうち賃金の割合が採掘より小さい。製錬所には別の割合を使うか、木炭焼きと運搬を含む人数と読むかを決める。
3. **金属ごとの燃料**: 木炭の量は、どの金属も鉱石1につき1である。鉛は少ない燃料で溶け、銅は何度も焼くので多い燃料を使った。金属ごとの量を史料で決める。
4. §14.5 の 2・3、§13.6 の 2〜4、§12.6 の 2〜5 はそのまま残る。
