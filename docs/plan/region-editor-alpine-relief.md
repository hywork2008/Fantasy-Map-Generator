# RE 高山の真上視点表現（Alpine Relief）設計

状態: R1〜R3 実装済み（2026-10-06）。R4（テーマ別配色の作り込み・Worker 化・峰シンボル表示トグル UI）は未着手。

実装メモ:

- 本体 `src/region-editor/render/relief.ts`（純粋関数 `computeReliefRaster`）、data URI 化とキャッシュは `reliefImage.ts`、トグルは `terrain.showRelief`（UI「山岳の陰影・雪線（真上視点）」）。
- 帯の気温しきい値は §4.2 の初期値から FMG の気候に合わせて較正した。FMG では Glacier セル ≈ −1°C、Alpine tundra 5〜8°C、Montane forest ≈ 10°C になるため、雪線 0.5°C・岩 3°C・森林限界 6.5°C とした。
- 谷筋の間隔はラスタの 5px 以上、深さは間隔の 12% 以下に制限する。300km 規模の州（1px ≈ 185m）で 1px 未満の縞が立ち、急な微小斜面が判定されて全面が岩になる不具合を、実データで確認して修正した。
- 陰影と高度帯は 1 枚のラスタに合成する。CSS の blend mode は使わない（SVG 出力をビューア非依存にするため）。
関連: [region-editor.md](region-editor.md) §山脈（L97 の斜め描き峰シンボル案を、真上視点の代替表現で補う）

## 1. 目的と前提

RE は真上から見下ろした地図である。高山を「斜めから見た峰アイコン」で描くと、真上視点のバイオーム面・農地区画・直角橋と視点が矛盾する。
衛星画像（例: 富士山）の高山の立体感は、次の3要素だけで成り立っている。本設計はこれをそのまま再現する。

| 要素 | 衛星画像での現れ方 | RE での担当 |
| --- | --- | --- |
| 垂直帯 | 森林 → 低木 → 裸岩 → 雪 が同心円状に並び、境界はギザギザ | 森林限界・雪線マスク（§4） |
| 放射状のシワ | 谷筋と尾根が斜面方向に走り、森にも雪にも同じシワが入る | 斜面方向のディテール標高（§3） |
| 陰影と落ち影 | 光源側が明るく、反対側の谷に大きな影が落ちる | ヒルシェード＋落ち影（§5） |

トリックアート的な遠近（立ち上がる山）は使わない。すべて真上視点のまま、色と明暗だけで標高を読ませる。

## 2. 現状の制約（コード調査結果）

- **標高グリッドが粗い**: `generateHeightfieldFromCells`（[contours.ts](../../src/region-editor/core/gen/contours.ts)）は FMG セル中心から IDW で補間し、最大 160×160。100km 四方の州なら 1 マスあたり約 600m になる。富士山の谷筋の間隔（200〜500m）より粗く、そのままではシワが出ない。
- **雪がセル単位**: `resolveCellLandscape`（[landscapeBiomes.ts](../../src/region-editor/core/gen/landscapeBiomes.ts) L244）は標高 2000m 以上のセルを `snow_mountains` の単色ポリゴンにしている。そのため雪原が Voronoi の角ばった形で出る。
- **温度はすでに受け取っている**: `RegionSiteCell.annualTemperatureC`（[region-editor-handshake.ts](../../src/controllers/region-editor-handshake.ts) L421）は FMG の grid 温度で、標高による逓減も反映済み。森林限界・雪線を「標高の固定値」ではなく気候から決められる。
- **描画は SVG 文字列**: [svg.ts](../../src/region-editor/render/svg.ts) の `renderRegionSvg` がレイヤを連結している。ラスタ描画はまだ無い。region-editor.md L573 に `canvas.ts`（陰影ラスタライザ）の構想だけがある。

## 3. ディテール標高（シワの源）

シワは陰影とバイオームの両方に効かせる。そのため、絵ではなく**標高そのもの**に刻む。
同じ標高 `H` から陰影も雪線も森林限界も求めれば、森と雪が自然に同じシワを共有する。

### 3.1 アップサンプル

- `heightfield` を双三次補間で、ラスタ解像度 `R` px/unit（既定 2、上限は長辺 2048px）に拡大する。これをベース `H0` とする。
- 先に `H0` を 1 回ガウス平滑化し、IDW 由来のセル中心の「こぶ」を消す。

### 3.2 斜面方向の谷筋（LIC）

- `H0` の勾配 `∇H0` から、最急降下方向の単位ベクトル場 `v` を作る。
- 決定的ホワイトノイズ（`makeRng(seed)`、世界座標固定）を `v` に沿って線積分畳み込み（LIC、片側長さ L ≈ 300m 相当）する。斜面方向に伸びた縞 `S ∈ [-1,1]` ができる。円錐火山なら自動的に放射状になり、尾根の多い山脈なら尾根ごとに枝分かれした谷になる。
- 等高線方向の縞の間隔は、ノイズを谷間隔 λ ≈ 250m 相当でぼかして決める。
- 谷を V 字に刻むため、`S` を `−|S|`（リッジ化）してから加える。

### 3.3 合成

```
H = H0 + A(x) · ridge(S)
A(x) = k · relief(x) · smoothstep(slope0, slope1, |∇H0|)
```

- `relief` は近傍の標高レンジ。平野（傾斜が小さい所）ではほぼ 0 にして、農地や湿地にシワを入れない。
- `k` は初期値 0.08。ライブ表示で較正する（memory: 調整定数はライブ計測で較正する）。

`H` は描画用の派生データとし、文書には保存しない。seed と `heightfield` から決定的に再計算する。

## 4. 垂直帯（森林限界・雪線）

### 4.1 気温場

- 各セルの `annualTemperatureC` と `elevationMeters` を IDW で補間する（標高と同じ空間インデックスを使う）。
- ディテール標高との差を逓減率 6.5°C/km で補正する: `T(x) = Tcell(x) − 0.0065 · (H(x) − Hcell(x))`。
- これにより谷は暖かく尾根は寒くなり、帯の境界がシワに沿ってギザギザになる。

### 4.2 帯の判定（1 px ごと）

| 帯 | 条件（初期値、要較正） |
| --- | --- |
| 雪 | `T + aspectBias + n1 < T_snow`（−3°C） |
| 裸岩 | 傾斜が急（> 35°）、または `T < T_alpine`（−1°C） |
| 高山草地・低木 | `T < T_tree`（+1.5°C） |
| 以下 | 既存バイオーム面のまま |

- **aspectBias**: 光源の反対側（北半球の北斜面）は雪線を下げる（+1.5°C 相当）。
- **急斜面には雪が付かない**: 雪の判定は傾斜 > 45° で無効にし、黒い岩肌が雪の中にスジとして残るようにする。富士山の冠雪のシワはこれで出る。
- **谷に残る雪**: 雪線の少し下でも、`ridge(S)` が谷側にある所だけ雪を残す。雪が谷筋に沿って舌状に下へ伸びる。
- `n1`: 低周波ノイズ（振幅 ±0.7°C）で、帯の境界を自然に揺らす。

### 4.3 既存レイヤとの整合

- 森林（`forestPolygons` / `re-forest-layer`）は、森林限界より上の部分をマスクで消す。ポリゴン自体は編集データなので変更しない。
- Relief 有効時は、`snow_mountains` セルの面色を岩色（`mountains` 色）に落とす。雪はラスタ側が担当し、セル形の白い雪原を出さない。
- 斜め描きの峰シンボル（`mountain_*`）は、Relief 有効時に既定で非表示にする（トグルで再表示可）。丘陵・樹木などの他シンボルは残す。

## 5. 陰影と落ち影

- **光源**: 方位 315°（北西）、高度 35°。地図の慣例どおり左上から照らす。衛星画像の多くは南（下）から照らされていて、北が上の地図では谷と尾根が反転して見える（レリーフ反転）。地図ではこの慣例を優先する。
- **ヒルシェード**: `H` から Lambert 陰影を求める。垂直誇張 `z` は既定 3、地図の広さに応じて調整する。
- **落ち影**: 各 px から光源方向へ高さマップ上をレイマーチし、地形に遮られたら影にする（最大距離 = 最高峰の比高 / tan(高度) 相当）。影の長さが比高に比例するので、高い山ほど大きな影が谷へ落ちる。
- **雪面の陰影**: 雪面は白く単調になりやすいので、影色を青灰（#8fa3b8 系）にしてコントラストを保つ。森や岩の上では、影を乗算で暗くするだけにする。

## 6. 描画構成

ラスタを 2 枚作り、`<image href="data:image/png…">` として SVG に埋め込む。

| レイヤ | 位置 | 内容 | 合成 |
| --- | --- | --- | --- |
| `layer-alpine` | `layer-forests` の直後 | 低木・岩・雪の色（透明度付き） | 通常（森を覆う） |
| `layer-relief` | `layer-alpine` の直後、`layer-rivers` の前 | ヒルシェード＋落ち影（中間灰 = 変化なし） | `mix-blend-mode: multiply`（明部は soft-light 相当で別処理） |

- 河川・街道・橋・集落・ラベルは陰影の上に描き、可読性を保つ。
- 海・湖は `re-land-clip` でクリップする。
- **テーマ**: `schley`/`parchment` は彩度を落として紙色に寄せ、`monochrome` は陰影だけを使う（帯は濃淡のみ）。
- **キャッシュ**: ラスタは `heightfield`・seed・光源設定のハッシュでメモリにキャッシュする。編集（ブラシ・選択）では再生成しない。SVG エクスポートには同じ data URI を埋め込む。
- **性能目安**: 2000×1600px で LIC（L=20 サンプル）が約 6,400 万演算、レイマーチも同程度で、JS で 0.5 秒前後の見込み。1 秒を超えるなら Worker に移す（Phase R4）。

## 7. データモデル

`RegionTerrain` に表示設定だけを追加する。ラスタやディテール標高は保存しない。

```ts
/** 高山の真上視点表現（陰影・垂直帯）。未設定は非表示。 */
showRelief?: boolean;
relief?: {
  sunAzimuthDeg?: number;      // 既定 315
  sunAltitudeDeg?: number;     // 既定 35
  verticalExaggeration?: number; // 既定 3
  hideMountainSymbols?: boolean; // 既定 true
};
```

FMG から受け取る気温を使うため、`RegionTerrain` に `cellTemperaturesC?: number[]` を追加し（`cellPolygons` と同じ並び）、`generateFromFmgDescriptor` で格納する。スタンドアロン生成では標高から推定する（海面 14°C − 逓減）。

## 8. フェーズ

| Phase | 内容 | 完了条件 |
| --- | --- | --- |
| R1 | `render/relief/` 新設: アップサンプル＋ヒルシェード＋落ち影、`showRelief` トグル | 実データの州で、陰影が左上光源で正しく出る（反転なし）。Playwright でスクリーンショット確認 |
| R2 | 気温場＋垂直帯（雪・岩・低木）、`snow_mountains` 面色の差し替え、森林限界マスク | 雪原がセル形でなく、等温線に沿ったギザギザの形になる |
| R3 | LIC ディテール標高と、谷に残る雪・急斜面の岩スジ | 単独峰で放射状、山脈で枝分かれした谷筋が、森・雪・陰影に一貫して出る |
| R4 | テーマ別配色、Worker 化（必要なら）、峰シンボル非表示トグル UI | 大きな州で再生成 1 秒以内 |

各 Phase の定数（`k`, `T_snow`, `T_tree`, `z` など）は、実際の FMG 州（高山を含むもの）を開いて目で確認しながら較正する。単体テストでは、決定性（同 seed で同ラスタ）・帯の単調性（標高が上がるほど帯が上位になる）・水域に陰影が出ないことを検証する。

## 9. 採らなかった案

- **峰アイコンを増やす・立体化する**: 真上視点と矛盾する。既存の Schley 風表現はトグルで残す。
- **ケバ（Lehmann 式ハッチュア）の SVG ベクタ描画**: 真上視点の伝統的な手法で羊皮紙テーマと相性が良い。ただし線の本数が数万本になり、SVG が重くなる。R3 の流向場 `v` をそのまま流用できるので、将来の別テーマとして候補に残す。
- **FMG 側で高解像度標高を作る**: FMG のセル解像度を超える情報は FMG にも無い。ディテールは RE 側で決定的に合成するしかない。
