# CEの高さ場モード: 標高メッシュの下地に崖の上の城塞を描く

作成日: 2026-10-24
状態: 設計。未実装。

## 1. 目的

CEの街区の割り出しと建物の配置はそのまま使い、セルより細かい標高メッシュ（高さ場）を下地にして、立体的な都市を3Dで描くモードを加える。

`ce-terrain-grading-layer.md` と `modular-hill-fortress.md` では、セル（約50 m）の標高を使って3D化を試した。しかし、セルの標高は粗すぎて、岩山の起伏や崖の形を表せない。本設計では、高さを細かい格子で持つ地面を新しい基盤地形として加え、既存の造成フィーチャー（台地・登城路・道路縦断・階段）をその上に載せる。

### 1.1 受入基準: 崖の上の城塞

合格の条件は、崖の上の城塞を描けることとする（坂の多い長崎型の密集市街を基準とする案は取り下げた）。tiny（600 m）または small（1,200 m）の図枠で岩山の地形を生成し、城を置いたとき、次をすべて満たせば合格とする。

1. 城の頂面は、城下の地面より20 m以上高い。
2. 頂面の外周の半分以上が、勾配60°以上の崖になり、岩の色で描かれる。
3. 城の建物の床は水平で、頂面に造成した共通の敷地に載る。浮いたり埋もれたりしない。
4. 城門から城下の町の門まで、勾配の上限（荷車10%、登城路8%）を守る道か登城路でつながる。
5. どの道も崖をまたがない。
6. 勾配35%を超える地面には、城の建物以外の建物を建てない。
7. 3D表示の地面の構築時間と描画の1フレームの時間が、M0で決める目標以内に収まる。
8. コンソールにエラーが出ない。

### 1.2 対象とする都市の規模

地面が平らでない用地は住むのに向かず、人が密集しにくい。そこで、高さ場モードで描く都市は小さい規模を主な対象とする。

| 規模 | 図枠 | 本設計での扱い |
| --- | --- | --- |
| micro | 300 m | 対象 |
| tiny | 600 m | 対象（受入基準の対象） |
| small | 1,200 m | 対象（受入基準の対象） |
| medium | 2,400 m | M0の計測の結果を見て決める。粗い格子でだけ許す可能性がある |
| large | 4,800 m | M0の計測の結果を見て決める。初期は対象外とする可能性が高い |

高さ場モードで選べる最大の規模は、M0の計測で決める（§9）。決まるまでは、生成パネルで高さ場モードを選べるのを small までとする。

## 2. 現状

調査で確かめた事実:

- FMGから渡る高さ場は 17×17 の点だけで（`src/services/burgSiteDescriptor.ts` の `HEIGHTFIELD_SIZE`）、1,200 mの図枠では約75 m間隔になる。合成敷地（`synthSite.ts` の `synthTerrain`）も同じ 17×17 で、丘はガウス形の山1つである。
- CEのセルは約50 m（`BLOCK_SIZE_METERS`）。セルの標高は、セル全体を水平にし、隣のセルとは土手か擁壁でつなぐ（`cellRelief.ts`、`ce-terrain-grading-layer.md` §7.18）。
- 3D表示は、地面を `CityTerrain`（`heightAt`・`foundationAt`・`surfaceAt`・`triangles`・`ramps`・`roads`）だけを通して受け取る（`types/terrain.ts`、`renderers/cityView.ts` の `cityTerrain(city, { roads })`）。
- `TerrainModel` の基盤地形は `cells` と `flat` の2種類である（`terrainElevation.ts` の `cityTerrainModel`）。
- `foundationAt` は、足元の地形の最高点を返す。盛土しかしないので、斜面では谷側に高い基礎が立つ。
- `CityTerrain.triangles` を直接読む処理が、地面の描画のほかに2つある。農地の判定（`ruralSuitability.ts`）と水面の描画（`city3d/three/waterMeshes.ts`）である。
- FMGの3D表示は、規則格子の `THREE.PlaneGeometry` の各頂点に高さを与える（`src/renderers/three-d-renderer.ts` の `createMesh`）。
- FMGの Landscape outline の地形の部品（Hill・Range・Trough・Pit・Strait・smooth・mask など）は `src/generators/heightmap-generator.ts` にある。FMGのセルの格子と0〜100の高さを前提にしている。

## 3. 解像度: 3つの層を分ける

敷地・CEのグリッド・標高メッシュは、1:1:1の比率にしない。3つはトポロジーを共有せず、高さ場から値を引く（標本化する）関係でつなぐ。

| 層 | 解像度 | 役割 |
| --- | --- | --- |
| 高さ場（新設） | 生成の格子 `sampleMeters`（既定2 m）。描画の格子は1・2・4・8 mから選ぶ（§8） | 地面の高さの正本。`heightAt` は生成の格子を双一次補間する |
| CEのVoronoiセル | 現状のまま（約50 m） | 区・街路・城郭の回路のトポロジーを受け持つ。高さは持たない |
| 区画・建物の敷地 | ベクター（多角形） | 敷地ごとの水平な面（§6）。縁は擁壁 |

道・崖・敷地の縁は、格子ではなくベクターの造成フィーチャーで表す。そのため、描画の格子を粗くしても、これらの位置と高さは変わらない。格子の粗さが影響するのは、自然の地面の見た目と、格子とベクターの継ぎ目の誤差だけである（§8.3）。

### 3.1 生成と描画の分離

生成の結果は描画の格子に依存させない。

- 敷地の高さ・道の縦断・城の頂面の高さ・建てられる場所の判定は、生成の格子から補間した `heightAt` で決める。
- 描画の格子は表示の設定で、文書には保存しない。描画の格子を変えても、都市は変わらない。

これにより、M0で描画の格子を1〜8 mと変えて計測しても、比べるのは同じ都市になる。

## 4. 高さ場の生成

### 4.1 方式

FMGの Landscape outline と同じように、部品を順に重ねて高さ場を作る。部品の手順（レシピ）とシードから毎回同じ高さ場ができるようにする。

- 格子は図枠の全体に `sampleMeters` 間隔で張る。高さはメートルの `Float32Array` で持つ。
- 部品は `heightmap-generator.ts` の考え方を、メートルと規則格子の上に移植する。FMGの実装はセルの隣接グラフと0〜100の値を前提にしているので、関数をそのまま共有はしない。

| 部品 | 内容 | FMGでの対応 |
| --- | --- | --- |
| `hill` | 中心・半径・高さの丘。減衰をノイズで乱す | Hill |
| `range` | 折れ線に沿う尾根 | Range |
| `trough` | 折れ線に沿う谷 | Trough |
| `pit` | 窪地 | Pit |
| `crag` | 岩山。頂面がほぼ平らで、側面が急な台状の高まり（新設） | なし |
| `spur` | 台地から細く突き出す尾根の先端（新設） | なし |
| `noise` | 振幅と波長を指定した fBm ノイズ | なし |
| `smooth` | 平滑化 | smooth |
| `mask` | 図枠の縁へ向けて地面を下げる・上げる | mask |

### 4.2 城塞用のテンプレート

部品の組み合わせを、テンプレートとして用意する。

| テンプレート | 地形 | 原型の例 |
| --- | --- | --- |
| `crag` | 平地に孤立した岩山。頂に城、麓に町 | 孤立丘の上の城 |
| `spur` | 台地から突き出した尾根の先端。三方が崖で、付け根の一方だけが緩い | 尾根の先端の城（付け根を堀で切る） |
| `meander` | 川の蛇行に囲まれた高い岬 | 川の湾曲部の上の城 |
| `escarpment` | 長い崖の上端。崖下に町 | 崖の縁に沿う城 |

### 4.3 FMGとの整合

FMGから取り込んだ都市では、高さ場を次の条件に合わせる。

1. **低周波をFMGに合わせる。** 17×17の高さ場を双一次補間した面を土台にし、テンプレートの起伏はその上に足す。17×17の各点のまわりの平均がFMGの値から大きくずれたら、ずれの分だけ低周波の補正を引いて戻す。
2. **海・湖の水際を合わせる。** CEの水面の多角形の内側は水面の高さより下、外側は上にする。水際の帯で、水面の高さへ向けて下げる。
3. **川を下らせる。** 川の中心線に沿って、上流から下流へ下り続ける谷を刻む。川の流れの向きは、既存の `riverFlow.ts` の結果に従う。

合成敷地（FMGなし）では、`synthTerrain` の 17×17 の代わりに、テンプレートから直接作る。

### 4.4 置き場所

- `src/city-editor/generators/terrainField/` を新設し、格子・部品・テンプレート・FMGとの整合を置く。
- 生成はCEのワーカーで行える。格子は `Float32Array` のまま転送する。

## 5. 地形モデルへの組み込み

### 5.1 基盤地形 `field`

`TerrainBase` に `field` を加える。

```ts
type TerrainBase =
  | { kind: "cells" }
  | { kind: "flat"; elevationMeters: number }
  | { kind: "field"; field: TerrainField };

interface TerrainField {
  origin: Point;
  sampleMeters: number;
  columns: number;
  rows: number;
  elevationsMeters: Float32Array;
}
```

- `cityTerrainModel` は、文書が高さ場のレシピを持つとき `field` を返す。
- `field` のとき `cellRelief` は使わない。セルの標高は持たず、表示や既存の処理が必要とする場合だけ、セル内の高さ場の平均から導く。
- 台地・堀・登城路・道路の回廊は、`evaluateTerrainFeatures` で `field` の上に重ねる。合成規則（`ce-terrain-grading-layer.md` §3.3）は変えない。

### 5.2 崖

高さ場の上の崖は、2つの方法で表す。

- **自然の崖:** 高さ場の急な斜面である。勾配が45°を超える面を、描画で岩の色にする。格子が粗いと、鉛直には描けない（§8.3）。
- **城壁の下の崖:** 城の頂面の縁は、既存の `platform`（縁 `cliff`、0.25 mの石の帯）で表す。ベクターなので、格子の粗さによらず鉛直に描ける。城壁はこの縁の上に載る。

城の頂面の台地は、岩山の頂の高さ場から決める（§7.2）。頂面の外では、自然の崖の上端と台地の縁がずれないよう、台地の縁を高さ場の急な斜面の上端に合わせて選ぶ。

### 5.3 `CityTerrain.triangles` を読む処理

`field` では地面を規則格子で描くので（§8）、`triangles` に全格子の三角形を入れると、M0の重さの計測に関係なく重くなる。

- `CityTerrain` に、規則格子の記述（`grid`: 原点・間隔・列数・行数・高さの配列）を加える。地面の描画は、`field` のときこれを使う。
- `triangles` は、造成フィーチャーの近くで分けた三角形（台地の縁・擁壁・回廊）だけにする。
- `ruralSuitability.ts` の勾配の判定と `waterMeshes.ts` の水際は、`triangles` ではなく `heightAt` と勾配の関数（`slopeAt`、新設）を使う形に改める。

## 6. 敷地の造成

### 6.1 勾配の区分

建物を建てる場所を、足元の勾配で4つに分ける。

| 区分 | 勾配 | 扱い |
| --- | --- | --- |
| 平坦 | 5%以下 | 地面にそのまま建てる。基礎は足元の最低点まで下ろす（今と同じ） |
| 緩斜面 | 5〜15% | 建物ごとに水平な敷地を造成する。擁壁の高さは3 mまで |
| 急斜面 | 15〜35% | 小さい建物だけを建てる。擁壁の高さは3 mまで。超える区画は建てない |
| 崖・急崖 | 35%超 | 建てない。城の頂面の台地だけが例外 |

区分のしきい値は暫定値で、T3で城下の町の建物の数と見た目を確かめて決め直す。

### 6.2 敷地の高さ

`field` のとき、`foundationAt` は最高点ではなく、切土と盛土を釣り合わせた高さを返す。

1. 建物の足元の多角形の内側で、高さ場を標本化する。
2. 標本の中央値を敷地の高さの候補にする。
3. 前面の道の高さ（`surfaceAt`）との差が、階段で上れる範囲（3 m）を超えるときは、その範囲に収める。
4. 敷地の縁で、地面との差が擁壁の上限（3 m）を超える建物は、その区画に建てない。

城の建物は、城郭の回路ごとに共通の敷地に載せる（`modular-hill-fortress.md` の内郭の造成面と同じ考え方）。

### 6.3 描画

- 敷地は、建物の足元を少し広げた多角形を、敷地の高さで水平に描く。
- 敷地の縁には、敷地の高さから地面の下まで届く擁壁の面（スカート）を付ける。地面の格子と敷地の縁の継ぎ目は、このスカートで隠す。厳密な制約付き三角形分割（CDT）は使わない。
- 切土の側では、擁壁は地面の高さから敷地の高さまで下りる面になる。

## 7. 生成への組み込み

街路と区画の生成は、地形を見ずに作る今の方式を基本とする。城塞を描くのに必要な次の4点だけを、地形に合わせる。

### 7.1 建てられない場所

勾配35%を超える場所（§6.1）を「建てられない」と印を付け、区画と建物の配置で避ける。避けた場所は、岩・林・牧草地として描く。

### 7.2 城の位置

- 城の位置の選び方（`castlePlacement.ts`）は、すでに敷地の高さを見ている（`terrainHeight`）。`field` のときは、これを高さ場で評価する。
- テンプレートで作った岩山の頂のセルを、城のセルの候補として優先する。
- 城のセルの集まりの上を、頂面の台地（縁 `cliff`）にする。高さは、城のセルの中の高さ場の最高値とする（G1の `groundRiseMeters` は、`field` では0を既定にする）。

### 7.3 登城路

既存の `rampPlanning.ts`（`planPlatformRamp`）を使う。登城路の裾は、`heightAt` が高さ場を返すことで、そのまま決まる。崖を巻く道やつづら折りの経路探索の勾配のコストに、高さ場の勾配を入れる。

### 7.4 道の縦断

既存の `roadGrading.ts` を使う。

- 擁壁を持つ文書は段々の町と同じ扱いになり、地面を削らず、階段と坂を築く（§7.15、§7.18）。
- `field` で城の台地しか擁壁を持たない文書では、P2の地面の造成（荷車の道の切土・盛土）を使う。回廊は高さ場の上で評価する。

崖で止めた道（`cliffBreaks`）を迂回させる付け替えは、本設計の範囲外とする。

## 8. 描画

### 8.1 地面のメッシュ

- 地面は、FMGの3D表示と同じく、規則格子の頂点に高さを与えて作る。
- 描画の格子の間隔は 1・2・4・8 m から選ぶ。既定値と規模ごとの上限は、M0の計測で決める。
- 格子は、256×256頂点の区画（チャンク）に分けて作る。区画ごとに作り直せるので、編集で一部だけを更新できる。
- 区画の継ぎ目には、高さの違いで隙間が見えないよう、下へ垂らす面（スカート）を付ける。
- 頂点の色は勾配で決め、45°を超える面を岩の色にする。

### 8.2 詳細度（LOD）

市街と城のまわりの区画は細かい格子、郊外の区画は粗い格子で作る。郊外の格子は、市街の格子の2倍か4倍の間隔にする。初期は、区画ごとに固定の詳細度とし、視点による切り替えはしない。

### 8.3 格子の粗さによる誤差

格子が粗いと、2つの誤差が出る。

1. **自然の崖の角度。** 高さ場の崖は、格子1つ分の水平距離で落ちる斜面にしかならない。格子の間隔を s、崖の高さを h とすると、描ける角度は atan(h / s) までである。

   | 崖の高さ | s = 1 m | s = 2 m | s = 4 m | s = 8 m |
   | --- | --- | --- | --- | --- |
   | 10 m | 84° | 79° | 68° | 51° |
   | 20 m | 87° | 84° | 79° | 68° |
   | 40 m | 89° | 87° | 84° | 79° |

   城壁の下の崖はベクターの台地で鉛直に描くので（§5.2）、この誤差を受けるのは城壁のない自然の崖だけである。

2. **継ぎ目の段差。** 道の帯と敷地の面はベクターで、`heightAt` の正しい高さに載る。地面の格子は、その間の高さを直線で補うので、勾配 g の場所では、継ぎ目でおよそ g × s / 2 の差が出る。

   | 勾配 | s = 1 m | s = 2 m | s = 4 m | s = 8 m |
   | --- | --- | --- | --- | --- |
   | 10% | 0.05 m | 0.1 m | 0.2 m | 0.4 m |
   | 30% | 0.15 m | 0.3 m | 0.6 m | 1.2 m |

   人一人が歩ける最小の道（幅約2 m）の帯の両側が、地面から見て浮くか埋もれる量の目安になる。0.3 mを超えると、斜面の道の縁が目に見えて浮く。道の帯の縁に、地面へ下ろす面を付けて隠す。

### 8.4 2D

2Dの地図には、高さ場から陰影（hillshade）と等高線（既定5 m間隔）を描く。崖は、勾配45°超の範囲にケバを描く。

## 9. パフォーマンスの計測（M0）

### 9.1 規模と格子ごとの量

地面の格子の頂点の数（図枠の一辺 / s + 1 の2乗）。三角形の数は、およそその2倍になる。

| 図枠 | s = 1 m | s = 2 m | s = 4 m | s = 8 m |
| --- | --- | --- | --- | --- |
| micro 300 m | 9.1万 | 2.3万 | 0.58万 | 0.15万 |
| tiny 600 m | 36万 | 9.1万 | 2.3万 | 0.58万 |
| small 1,200 m | 144万 | 36万 | 9.1万 | 2.3万 |
| medium 2,400 m | 576万 | 144万 | 36万 | 9.1万 |
| large 4,800 m | 2,305万 | 576万 | 144万 | 36万 |

メモリの目安:

- 生成の格子は1点4バイトである。small を2 mで持つと 1.4 MB、large を2 mで持つと 23 MB になる。
- 描画のメッシュは、位置と法線（各12バイト）と添字で、1頂点あたり約50バイトになる。144万頂点で約70 MB、576万頂点で約290 MBである。

参考として、今のセル標高の地面（P4の計測）は、tiny で6,805個、small で18,791個の三角形である。

### 9.2 計測する値

| 値 | 測り方 |
| --- | --- |
| 高さ場の生成の時間 | テンプレート `crag` で、規模ごとに5シード |
| 地面のメッシュの構築の時間 | 格子の間隔ごと。チャンクの分割と法線の計算を含む |
| 三角形の数とGPUのメモリ | `renderer.info` の値 |
| 描画の1フレームの時間 | 3D表示で、一定の速さで視点を一周させたときの中央値と95パーセンタイル |
| `foundationAt` の総時間 | 全建物の敷地の高さを決める時間 |
| 継ぎ目の誤差 | 道の中心線と敷地の縁で、メッシュの高さと `heightAt` の差の最大値と95パーセンタイル |
| ワーカーからの転送 | 格子を転送する時間と大きさ |

- 計測には、高さ場と地面のメッシュだけを作るスクリプト（仮名 `npm run ce:terrain-perf`）を新設する。描画の1フレームの時間は、Playwright でCEの3D表示を開いて測る。
- 同じ機械で、同じ日に、基準（今のセル標高の地面）と並べて測る。

### 9.3 決め方

次をすべて満たす最も細かい格子を、規模ごとの既定にする。どの格子でも満たせない規模は、高さ場モードの対象外にする。

- 地面のメッシュの構築が 500 ms 以内
- 1フレームの時間の95パーセンタイルが 16.7 ms 以内
- 継ぎ目の誤差の95パーセンタイルが 0.3 m 以内

目標の値は暫定である。M0の最初の計測で、今のセル標高の地面の値と比べて妥当か確かめ、必要なら決め直す。

計測前の見込みは次のとおりである。この見込みは計測で置き換える。

- tiny は1〜2 m、small は2 m（郊外4 m）が既定になる。
- medium は4 m なら可能性がある。
- large は8 mでも郊外を含めて36万頂点で、市街を細かくすると重くなる。初期は対象外とする。

## 10. 保存

- 文書に、高さ場のレシピだけを保存する: `CityDocument.terrain.field = { version: 1, template, seed, sampleMeters, parts }`。`parts` はテンプレートを展開した部品の列で、手で直せる。
- 高さ場の格子は、読み込み時にレシピから作り直す。保存しない。
- 描画の格子の間隔は表示の設定で、CEの設定（ローカル）に置く。文書には保存しない。
- 旧文書は `field` を持たず、今と同じセル標高の地面になる。

## 11. 段階

| 段階 | 内容 |
| --- | --- |
| M0 | 計測の足場。ノイズだけの高さ場とチャンク分割の地面のメッシュを作り、§9の値を規模と格子ごとに測る。既定の格子と、高さ場モードの最大の規模を決める |
| T1 | 高さ場の生成（部品・テンプレート `crag` と `spur`・FMGとの整合・水際と川）、`TerrainBase` の `field`、`heightAt` の双一次補間、2Dの陰影と等高線、保存 |
| T2 | 地面の3D描画（チャンク・スカート・LOD・勾配の色）、`CityTerrain.grid`、`ruralSuitability` と水面の描画を `slopeAt` へ移す |
| T3 | 敷地の造成（勾配の区分・切土と盛土の釣り合い・擁壁のスカート）、建てられない場所の印 |
| T4 | 崖の上の城塞（岩山の頂を城の候補にする、頂面の台地、登城路、道の縦断） |
| T5 | 受入基準（§1.1）の確認。BVの `Download editable CE hill study` と同じく、編集可能な確認用サンプルを用意する |

M0の結果で、T2のLODの粒度とT3の敷地の標本化の間隔を決め直す。

## 12. 範囲外

- 坂の多い密集市街（長崎型）を描くための、地形に合わせた街路と区画の生成（等高線に沿う区画、勾配をコストにした街路の経路探索）。`ce-terrain-grading-layer.md` §5の4（段を街路生成の制約にする）と合わせて、別の設計で扱う。
- 崖で止めた道の付け替え。
- 高さ場の筆による手の編集。初期は、`parts` の数値を直すことで編集する。
- medium・large の規模（M0の結果次第で範囲に入れる）。

## 13. 採用しない案

- **図枠の全体を1 mの格子で描く:** large では2,305万頂点になり、描画できない。
- **地面を制約付き三角形分割（CDT）で、造成の縁に完全に合わせる:** 正確だが、P4で地面の三角形を回廊に合わせて細分したとき、tiny で97万個・15秒になった。継ぎ目はスカートで隠す。
- **セルの標高を細かくする（セルを小さくする）:** セルは街区のトポロジーも兼ねるので、地形のためだけに細かくすると、街路と区画の生成が変わる。
- **ボクセルや完全な3Dメッシュ:** 自動生成と2Dの編集のどちらとも噛み合わない（`ce-terrain-grading-layer.md` §8）。
