## 実装メモ（2026-10-22）

- 正本は `simulation.extensions.economy.personalCash`。`personalCashLedger.ts` が整数残高・区間分割・移転・保存検証を、`personalCash.ts` が経済と人物の接続を担当する。Characters は `financialLifecycle.ts` の任意ポートだけに依存する。
- `Character.wealth` は旧コードと互換な読み書き可能の投影にした。既存の給与・売買等による書込も同じ口座へ反映し、通貨量には口座だけを計上する。JSON/structuredClone では値として保存され、読込・巻戻し後に `getCharacters()` が現在の正本口座へ再接続する。
- 世界の初期化完了後に、必要役職の集団口座を作る。初期目標は役職別俸給の **6 周期分**。供給元の都市家計の **25%** を予算の上限とし、有給役職全体の定員と目標額で按分する。元首が予算を使い切って他の役職の配分が一律 0 になる旧方式は廃止する。無給の席へ俸給相当の現金は発生させない。
- これは開始配分の初期プロファイルであり、master の個々の乱数額や種族の蓄財額の完全再現ではない。既存通貨の保存を優先し、資金不足時の減額と配分規則は画面で説明する。役職・人物の生成順を予算の優先順位にしない。
- 初期化後に新設された組織の席は 0 の集団口座で始め、以後の有給職の給与を受ける。途中就任で開始時の貯金を再発生させない。
- 給与と基本生活費は、詳細人物と抽象集団の両方へ月ごとに適用する。旧処理から同じ人物へ二重払いしない。生活費・富に応じた支出の係数は既存のものを使い、詳細人物は高級品の購入にも接続する。役職やメモ/AI モードの表示に財布の存否を依存させない。
- 死亡者の現金は遺産として保持し、通貨量から除外しない。生存する既知の子は、Character がなくても相続口座を持てる。不明な相続先の残額は保管し、ギルド親方の `dispersedToPrivateHeirs` も実際の遺産残高として保存する。今回の既定相続は既知の子への均等分配で、時代/地域別の相続法の再現ではない。
- 「人物の詳細を取り外す」は元の個人枠・数値 id・所有品・口座を保持し、再詳細化で接続する。「人物を世界設定から取り消す」は、指定した生存者の口座または元の集計家計へ全残高を移してから取消済みにする。所在不明なら保管口座へ移す。未処理の契約・所有品・保護された詳細は削除を止める。
- 通貨量は詳細人物の財布の重複加算をやめ、個人口座・集団・遺産を数える。口座所在の burg が国境変更で別国家に入った場合は、その所在に従って国家別の集計を移し、世界合計は変えない。中立地や滅亡国等に帰属する個人資金も別の内訳として観測できる。
- 旧保存の正/0 残高はそのまま移行する。既存の有給役職者で 0 の残高を補正したい場合は、Organizations & families の「既存人物の0残高を確認・補正」から人数と家計からの移管額を確認して実行する。旧配分方式で初期資金が 0 になった詳細人物も、この明示補正の対象に含める。補正済みの人物は、後から使い切っても再補填しない。すでに記録が失われた資金は推測で発行しない。
- Economy のチェックを外す操作はデータ消去ではなく停止として扱い、再有効化時に家計や資金を再初期化しない。初回の有効化と、既存市場がある世界の再開を分ける。
- `/observe/wealth` には `personalCash` の total / abstract / estates / unassigned を追加した。設定専用で世界経済から独立した財布の編集画面、家ごとの共有財布の専用編集、完全な相続法・種族別初期資産の較正は別の拡張とし、既存のメモ用人物は世界内の口座を使う。

## レビュー対応（2026-10-22）

`docs/temp/reviews/1022.md` を現行コードと照合した。

- 要修正1は妥当。一括 `characters.clear` は未解決の役職・所有品・装備があれば変更せず、通知に禁止理由と個別操作への案内を表示する（実行関数の結果にも理由を含める）。許可された詳細削除では、口座と PersonSlot の `characterId` を外し、数値 id を保持する。拒否された置換は事前検査で止まるため、それ自体が口座参照を宙に浮かせるわけではない。
- 要修正2の「不正残高を setter が拒否する」は仕様どおり。指摘された売買・研究支援の支払いは、書込前に残高を確認している。負値等を黙って 0 に変更すると、支払先との金額不整合を隠すため、クランプ案は採らない。不正値の拒否時に残高が変わらないことと、既存の支払テストを検証する。
- 要修正3は妥当。遺産は分配先と金額を全件検証してから同期的に一括確定し、分配後の 0 残高で再実行を防ぐ。後から入った残高は新しい分配として処理する。分配ごとの永続トランザクションを増やさず、当該口座の旧分配キーは完了時に削除する。取消処理の一度限りのキーは保持する。
- 要修正4は妥当。全都市の配分と既存人物への割当・家計への返金を作業用台帳で計算し、台帳と支払元の全件検証後に確定する。後続都市に不正値があっても先行都市の家計・プールを変更しない。既存 Character が参照する口座オブジェクトの同一性も維持する。
- 要確認1は妥当。後継者の給与を扱う前に初代の抽象持分を初代個人口座へ切り出し、生死に応じて保持する。詳細化されていない後継者にも口座を作り、同じ席の抽象給与との二重支給を防ぐ。この処理は相続より先に行う。
- 要確認2の指揮官給与は従来も `drawFromMarshalcyThenTreasury` を使用しており、軍務残高→一般国庫の順で支払う仕様を維持する。
- 要確認3は一部妥当。既存経済の再有効化では、財布・在庫を初期化せず市場のキャッシュと領域・既存家計台帳の市場参照を同期する。Characters が無効なら台帳構築を呼ばない。都市・国家の新設に伴う追加の経済生成は、既存の市場追加・領域更新経路に従う。
- 要確認4は妥当。一般人物・政治役職者・潜伏者・ギルド関係者・市場関係者・商会要員の生成を、保存される共通の数値 id 採番へ統一する。バッチ生成も一人ずつ予約する。
- `preparedRoles` の重複を登録時と検証時に防ぐ。旧セーブの実残高を正本へ移した人物は `cashAccountId` によって旧初期資金補填の対象外となるため、二重補填しない。複数人物による同一口座の参照は移行仕様には含めず、保存時の拒否を維持する。

## 1. 解決する問題と採用判断

世界生成時に全 NPC を作る master と、必要時に個人枠を詳細化する現ブランチでは、同じ役職でも所持金に差がある。遅れて詳細化した人物を無一文にせず、人物を多く作った世界だけ通貨が増えることも防ぐ。死亡・詳細削除・人物そのものの削除でも、移管先のない通貨を消さない。

採用するのは **Character とは独立した個人資産口座**である。詳細化前から個人または集団の口座に資金があり、Character の生成はその口座への接続とする。削除も「詳細を取り外す」と「世界から人物を取り消す」を分ける。死亡は口座の破棄ではなく遺産への移行である。

初期金額の目安には master の役職別の算定を利用するが、金額を財布へ無条件加算する処理は再利用しない。新旧の生成方式は同じ初期配分計画を使い、生成タイミングに依存しない通貨量・保有者を持つ。通貨の尺度・俸給の単位は変更しない。

## 3. 保存する量と責務

### 3.1 通貨と資産を区別する

本書の保存対象 M は現金残高の合計。商品・装備・土地・商会持分・債権の評価額を現金へ重ねて足さない。信用枠・未払給与・農民への未払いも現金ではない。国家金庫、家計、市場資本など既存の現金口座の範囲は `stateMoneySupply.ts` の契約を引き継ぐ。

人物操作については `M_after = M_before` を必須とする。造幣・硬貨摩耗・地図外への支払い等、別設計で明示された増減はそれぞれの取引理由で記録し、人物生成の差額をそこへ紛れ込ませない。

### 3.2 集計地域と所有者を分ける

口座には所有者と通貨集計上の所在を別に持たせる。国家への所属、現在の移動先、役職の本拠地から現金を毎回自動で移し替えない。定住・金庫移転等の確定した出来事で集計地域を変更する。国境変更や国家滅亡でも口座を削除しない。

世界集計は `有効国家別の合計 + 中立地/滅亡国等の帰属未確定分` を含める。越境教会の資産も法人・拠点の所在で一度だけ数え、本部と支部、主所属国と活動国へ重複計上しない。地図内での国家間移管は世界の M を変えない。遺産として凍結中の現金も通貨残高に含め、支出可能額とは別表示にする。

### 3.3 モジュールの責務

- Characters: 個人枠の同一性、生没・親族、Character の詳細化/非詳細化。Economy の内部へ直接依存しない。
- Nobility: 就退任・領地・後継役職と、公私を区別する制度情報の供給。
- Economy: 個人/家/集計家計/遺産等の現金口座、移転、収支、通貨量の集計、資金初期配分。
- 共通の拡張 API: 詳細化前後・死亡・詳細削除・人物取消のフック。単なる UI の DOM イベントに精算を任せず、headless とブラウザの双方で同じトランザクションを実行する。

Economy 無効でも Characters のメモ機能は使える。Economy が保持する口座は拡張の無効化で破棄しない。初めて有効化する際は経済の開始処理を一度だけ行い、再有効化を資金初期化の契機にしない。

## 4. 口座・取引モデル

| 要素 | 正本に持つもの |
| --- | --- |
| PersonalCashAccount | accountId、ownerSlotId、balanceMinor、locationRef、状態 active/estate、資金初期化トークン |
| HouseholdCashAccount | 家/家系の id と現金。個人口座・国庫・法人資産と別の所有権 |
| AbstractPersonalPool | 地域・社会階層ごとの未詳細化者の現金合計、対象人口/個人枠範囲、配分版、累積した収支と分割記録 |
| EstateAccount | estateId、故人の ownerSlotId、死亡イベント id、残高、遺産処理の状態と移管済み明細 |
| CashTransfer | transactionId、from/to の型付き口座参照、金額、日時、理由、関連人物/役職/処理イベント id |
| InitializationPlan | 世界ごとの初期配分版・予算・比例配分・適用済みキー。Character の有無に依存しない |

`balanceMinor` は既存表示尺度の 0.01 を整数化した内部残高とする。これは硬貨の種類を増やす意味ではない。既存の金庫等との境界で一度だけ換算し、移転額と配分残額を整数で確定する。現金の負残高は禁止し、債務は別台帳へ記録する。

口座 id は再利用される可能性のある Character の数値 id ではなく、世代を含む安定した PersonSlot id に接続する。役職 id や枠番号は所有者 id にしない。後任は別人物・別口座で、兼任者は同じ個人口座を参照する。

すべての個人をレコード化する必要はない。大きい役職定員や集計人口は AbstractPersonalPool の範囲で保持し、抽象集団から個人を分けるときに合計を保って分割する。集計人口に含まれる一人を詳細化しても人口や労働力を増やさない。

## 5. 初期資金と遅延生成

### 5.1 世界開始時の配分を固定する

1. 役職・必要定員・制度・人口を読み、Character を作らず初期資金計画を作る。
2. `seedMissingCharacterWealth` 等の計算を、副作用のない「目標額の算定」へ分離する。俸給・種族/年齢補正・moneyScale の適用を一箇所で行う。
3. 人物が既に存在する場合も未詳細化の場合も同じ配分計画を適用する。初期化乱数は世界種・個人枠/集団範囲・配分版から分離し、生成順やプリセットの選択で変えない。
4. 初期通貨予算を先に確定し、その内訳として国庫・都市・法人・一般家計・個人の分を配る。個人分を一般家計にも重ねて含めない。既存初期家計の内数として切り出す方式を標準とし、世界開始時の全体予算変更は StartProfile の明示改訂として扱う。
5. 予算より目標額合計が大きい場合は、有給役職全体の比率で一括調整する。端数は安定キー順で配分し、先に生成した人物だけが満額を取る方式にはしない。資金不足を国庫の無制限引落や負残高で埋めない。

master の「元首の初期金の目安」は引き継げるが、全必要席が増えた世界で旧金額を全員に満額保証し、かつ通貨総量も固定することは予算次第で両立しない。UI には目標額・実際の配分額・不足/調整理由を表示する。初期予算の較正と、生成方式による差の解消は別の検証とする。

旧 master の分布との比較は、同じ役職と経済設定での配分目標を比較する。乱数経路が変わるため、旧 Character ごとの金額を完全再現する契約にはしない。

### 5.2 未詳細化者の資金も経済へ参加させる

未生成者の資金を、後から引き出すだけの休眠準備金にはしない。俸給・家計支出・相続等は口座または集団の残高へ適用する。役職の在職情報を給与の正本とし、Character のタイトル表示や `rosterMode` が給与の支払先を決めないようにする。

詳細化済み/未詳細化で給与を二重に払わない。集団から個人へ分割した日から、その個人分を集団の支払い対象・残高・支出から除く。複数の役職を兼ねるとき、制度上の複数収入はあり得るが、同じ役職支払いの二重実行は許さない。

抽象口座の収支と詳細人物の収支は、同じ基礎経済ルールを使う。人物の好み・行動 AI による個別の追加取引まで、非詳細化世界と常に一致するとは要求しない。それらは詳細化時の資金移転とは別の出来事として記録する。

### 5.3 詳細化する時点では残高を引き継ぐ

- 個人口座があれば接続するだけ。Character.wealth の表示はその現在残高を読む。
- 抽象集団に含まれる人なら現在資金の持分を分割し、集団残高を同額減らす。開始時の目標額を、その時点で改めて加算しない。
- 個別に選んだ枠の持分は安定キーと保存された分割規則から決める。一般家計の現在残高は、集団全体への収支を一度適用してから分ける。過去に分割した枠は記録し、同じ枠を再び取り出せないようにする。
- 資金 0 は有効。再読込・再詳細化・プリセット再実行で再配布しない。初期化済みトークンと取引 id で判定する。
- 時間経過後の就任者は就任時の持分・家の資産・実際の前払等から始める。新任者に一律で過去4〜10周期分の俸給を発生させない。実在の未払給与がある場合は、支払元から現金を移して債務を同時に減らす。
- 子供の誕生だけでは通貨を増やさない。贈与・小遣いは親や家の口座からの移転。地図外から来た人物の資金は明示的な域外流入として記録する。

### 5.4 兼任と、同一人物だと後で確定した枠

確定済みの兼任は最初から一つの個人口座に接続する。役職の数を個人口座の数にしない。

すでに別々の資金を持つ二枠を同一人物へ統合する場合、口座を付け替えて片方の残高を落とさない。別の私有資金なら合算移転し、初期配分の重複だった分は元の集計家計へ返す。どちらか不明なら要確認として止める。職位の後任を作る操作で前任者の財布を流用しない。

### 5.5 大きい集団の分割規則

集団を安定した ordinal の区間に分け、区間ごとの現金残高・配分重み・共通の収支履歴を持つ。範囲の生成順ではなく、固定された並びに対する累積重みで各枠の持分を決める。区間残高 B、全重み W、枠の前後の累積重みを w0/w1 とすると、その枠の整数持分は `floor(B × w1 / W) − floor(B × w0 / W)` を基本とする。

一枠を切り出すときは、対象と前後の区間に同じ規則で残高を分割し、残存区間を生成の都合で再正規化しない。分割後も元の累積丸め基準（分母・起点・端数）を保持し、残った区間の残高と人数だけで持分を計算し直さない。すでに切り出した枠へ元区間の資金を再配分しない。切り出し記録は保存し、異なる順序で枠を選んでも同じ持分になることを検証する。特定個人だけへの相続・贈与等が生じた場合は、その時点で軽量な個人口座へ分離する。Character は不要。

共通の給与/支出は抽象区間と切出し済み個人へ同じ基礎規則で適用し、整数の端数の帰属も固定キーで決める。収入の異なる階層、異なる在職期間、異なる支出制度は同じ一様集団へ混ぜない。集団全体の残高を「今回選んだ人数」で割り、選ぶ順番によって持分を変える実装は採らない。

## 6. メモ用人物とシミュレーション用人物

同じ世界に在職する人物をメモ用として詳細化しても、資金は元の個人/集団口座を参照する。メモ用とは人物 AI や設定編集の扱いであり、口座を通貨集計から外す理由にしない。口座の基礎的な収支は世界時間に従う。人物の年齢や名前を固定する錠前と、世界内の口座残高の固定を混同しない。

世界に登場させない構想用人物には、別の「世界経済に参加しない」設定を明示する。その所持金は設定値であり、通貨集計・取引・相続へ入れない。世界へ参加させる時は既存口座・集計家計からの資金配分を確認する。設定値をそのまま現金として発生させない。

## 7. 削除・非詳細化・死亡・相続

| 操作 | 資金と記録の扱い |
| --- | --- |
| 詳細を取り外す | Character の詳細だけを除き、PersonSlot・個人口座・就任/親族履歴を残す。通常は口座移転不要 |
| 再詳細化 | 同じ個人枠と現在残高へ再接続。初期化を繰り返さない |
| 人物を世界設定から取り消す | 就任・家系・契約等を確認し、現金を指定の家/集計家計へ移してから取消済みにする。単に役職の定員を減らして財産を消さない |
| 死亡 | 財産を遺産口座へ移し、個人口座の残高を 0 にする。遺産口座は集計へ含める。死亡履歴は維持 |
| 相続人が詳細化済み | 相続人の個人口座へ移す |
| 相続人が未詳細化 | 軽量な相続人枠の個人口座または家の口座へ移す。名前・容姿等の Character 生成は不要 |
| 相続関係が未確定・係争中 | 遺産管理口座で保管。後から受取先を決め、未処理分だけ移す |
| 死亡者の履歴を整理 | 遺産口座への接続と処理記録は保持。現金残高・未処理権利が参照不能になる物理削除は禁止 |

相続法の完全な再現は今回の範囲外。設定済みの相続人・家を優先し、不明なら遺産管理口座へ保管する安全な既定とする。役職の後任は私産の相続人とは限らない。国庫・部署予算・教会やギルドの法人金庫は代表者が死亡しても法人に残る。

ギルド親方の現行の分配率は当面維持できる。ただし、後任への分とギルドへの返還分に加え、`dispersedToPrivateHeirs` を相続人/家/遺産管理口座へ実際に記帳し、全分配の合計を旧残高に一致させる。一般の相続とギルド独自処理を両方起動して二重精算しない。

装備・商品・商会持分・債権債務・進行中契約は現金と別の権利である。非詳細化では所有参照を個人枠へ維持する。人物取消・死亡では所管モジュールへ移管を要求し、未解決の権利があれば物理削除を止める。本書の実装だけを理由に商品を現金化したり、債務を 0 にしたりはしない。

削除時の移管先の既定は同じ家、なければ元の集計家計。所在や元の家計が不明なら保管口座を作って受け、無条件で国庫へ没収しない。移管先を消す操作自体にも移管を必要とする。取り消した人物の初期化キーは残し、同じ id の復活による二重受給を防ぐ。

## 8. 既存コードへの接続と段階移行

### 8.1 Character.wealth の互換期間

最終的には残高の正本を Economy の口座に一本化し、Character.wealth は互換用の表示/投影にする。現状の `.wealth =` を残したまま別口座にも同額を持たせると、収支の乖離と二重集計が起きる。

移行期間中は、一人ごとに正本の所在を明示する。未移行者は既存 wealth のみ、移行済み者は口座のみを集計し、互換投影は足さない。口座所有者への旧直接書込を検出する開発時の検査を入れる。口座読取・支払・入金・移転を共通サービスへ置換してから、その呼出経路の口座移行を有効にする。

対象は俸給・生活費・高級品購入・市場/商会の利益・護衛報酬・窃盗・賄賂・財政イベント・キャラクター間取引・種族/経歴由来の資金加算等。生成時の経歴が資金を直接足す経路も監査し、配分目標か既存口座からの移転へ置き換える。

### 8.2 初期化・生成・時間送りの入口

- 新規世界: 人口・組織・定員確定 → 経済開始予算と配分 → 口座を含む通貨量から造幣需要を較正 → 任意の人物詳細化。後で人物を作った時に需要の較正をやり直さない。
- 詳細生成: `materializeSlots` と他の人物生成経路が共通の経済フックを呼ぶ。Economy は既存口座を返す/持分を移す。人数バッチの途中失敗でも同じ個人に二重配分しない。
- 死亡: 老化・疾病・戦死等すべての入口で共通精算を呼ぶ。`dead` の変更と遺産への移転は同じトランザクション。死亡だけ先に確定して通貨集計から消す中間状態を外へ出さない。
- 削除: `pruneDeadCharacters`、手動削除、再生成/置換を共通サービスへ通す。未精算・口座未接続なら削除しない。
- 経済周期: 詳細人物と抽象人口の支払い対象を一つの台帳から構成する。Economy と Characters の両方から同じ生活費等を払わない。

### 8.3 トランザクションと保存

口座変更・Character/PersonSlot の参照変更・就任/死亡状態・処理済みキーをまとめて検証してから確定する。支払元と受取先の片側だけを書き込まない。受取先が無効なら変更せず止める。

取引 id は世界・個人・イベント・処理版を含む安定キーにする。再試行は既存結果を返し、同じ id に異なる金額/送金先が来た場合は競合として停止する。初期化済み判定を残高の大小へ戻さない。

口座・分割範囲・遺産・処理済みイベント・初期配分版をアーカイブへ保存し、時間送りの巻き戻し対象にも含める。死亡観察によるロールバックで、死亡だけ戻して資金移転を残すことや、その逆を防ぐ。保存読込時に参照・整数残高・同一所有者の重複・旧投影の二重集計を検証する。

全取引を無期限に保存する必要はないが、完了イベントの重複防止情報は履歴の圧縮後も維持する。詳細ログの圧縮で残高や初期化状態が変わってはならない。

## 9. 旧セーブの移行

| 保存状態 | 移行方針 |
| --- | --- |
| 生存者に正の wealth がある | その額を口座へ移管し、Character 側は投影扱いにする。追加の初期金なし |
| 生存者の wealth が 0 | 0 を保持し、移行済みにする。初期化漏れと使い切りを値だけで区別しない |
| 遅延生成のため初期金がなかった人物 | 明示的な補正計画で、既存の個人/集計家計から配分する。候補・金額・資金源・調整理由を表示する |
| 未詳細化者 | 既存家計の一部を口座/集団へ切り出す。一般家計からは同額を減らす |
| 死亡者に wealth が残る | 遺産へ移管。旧集計は除外していたため、旧表示との増分を「既存の遺産の集計漏れ回復」として報告する |
| すでに削除済み・分配済み扱いで残額の記録もない | 失われた正確な額は復元できない。推測で通貨を作らず、復元不能件数と既知の情報を報告する |
| 通貨量モデルが旧 off | off を保持したまま人物資金の保存を適用できるようにする。造幣・物価モデルの on への変更とは分離 |
| Economy を初めて有効化する世界 | 通常の経済開始予算を一度作り、詳細人物/未詳細化者に同じ計画で配分。既存の所持金設定値の扱いは開始プレビューで明示 |

移行前の正本残高を走査し、`生存者の現金・除外されていた故人の現金・既存の家計等` を分けて監査する。移行が保存すべき量は、表示上の旧集計だけでなく、その時点で実際に記録された現金の合計である。回復した集計漏れを、新規造幣として扱わない。現在の境界から過去の経済を再計算して補償することもしない。

資金源の足りない補正は不足分を明示して全体を按分する。旧 master 相当額へ合わせるための発行が必要なら、それは通常移行と別の明示的な世界設定変更である。既定では実行しない。移行はバックアップ可能なアーカイブ版の更新として一度だけ適用し、繰り返しても同じ残高にする。

## 10. 操作と表示

- 人物詳細: 所持金、家の共有資金、法人資金、未確定の遺産を分ける。共有資金を人物全員の所持金へ足さない。
- 生成プレビュー: 新規人物数に加え、接続する既存資産/集計家計からの移転額、0 の人数、初期目標からの調整を表示する。新しい通貨の発行額は通常 0。
- 詳細削除: 「詳細を取り外す。人物・家系・口座は世界に残る」と説明する。
- 人物取消: 削除対象、就任/家系/契約の扱い、移管元残高、移管先と金額を表示して確定する。移管先未設定では実行不可。
- 死亡/相続: 遺産総額、確定した受取人、未処理額、制度上の後任との違いを確認できるようにする。
- 世界の経済表示: 詳細人物・抽象個人/家計・遺産・帰属未確定の各残高を内訳に追加する。停止/凍結残高を支出可能残高と区別する。

## 11. 数値例

金額は内部尺度の説明用。造幣・摩耗等の別イベントなし。

| 操作 | 集計家計 | 個人口座 | 遺産 | 世界の合計 |
| --- | ---: | ---: | ---: | ---: |
| 開始時。未詳細化者分も家計内にある | 1,000 | 0 | 0 | 1,000 |
| 一人を詳細化し、その人の持分 120 を切り出す | 880 | 120 | 0 | 1,000 |
| Character の詳細を取り外す | 880 | 120 | 0 | 1,000 |
| 再詳細化 | 880 | 120 | 0 | 1,000 |
| 本人が死亡 | 880 | 0 | 120 | 1,000 |
| 詳細化済み相続人へ 30、未詳細化の家族家計へ 90 を渡す | 970 | 30 | 0 | 1,000 |

開始後に給与 20 を得て生活費 8 を払った場合、後から詳細化した人は開始時の 120 ではなく現在の 132 を引き継ぐ。支払元は 20 減り、生活費の受取先は 8 増えているため、これらの取引による世界合計の変化も 0。

## 12. 実装順と検証

1. 正本口座・取引 API・集計上の帰属を追加。旧 wealth の全読書きを棚卸し、口座と旧経路の同時集計を防ぐ。通貨量集計に遺産と帰属未確定分を追加する。
2. 初期金の算定と配分を分離。初期化済みキー、集計家計からの分割、生成経路の共通フックを接続する。既存の直接加算経路を移行する。
3. 抽象口座の基礎収支、就退任、兼任を接続。詳細化有無による二重給与・二重生活費を除く。
4. 死亡・相続・ギルド独自精算・削除/非詳細化・ロールバックを共通取引へ接続する。
5. 旧保存の移行、プレビューと残高内訳、補正レポートを実装する。

各段階は口座変更・呼出経路・集計を一つの切替単位として導入する。全経路の移行前に口座を単なる残高コピーとして本番で二重運用しない。無制限な初期金加算を緊急回避策として先行導入しない。

必要なテスト:

- 同じ世界で「先に全員を詳細化」「一人ずつ詳細化」「未詳細化」の初期配分と通貨合計が一致する。生成プリセットの順序・兼任・再実行で資金が増えない。
- 同じ基礎収支のイベント列を与えたとき、早期詳細化と遅延詳細化で対象者の現在残高が一致する。人物 AI の追加取引は別イベントとして扱う。
- 0 残高・出生・途中就任・新設組織・集団分割の端数・予算不足を扱い、初期化トークンで二重受給を防ぐ。
- 詳細削除→再詳細化、人物取消、死亡→相続、未生成相続人、後任と相続人が別、相続人不明、ギルド親方の全分配で世界合計が保存される。
- 国家 0、国家滅亡、国境変更、越境組織、口座所在の変更で現金が集計から消えない。
- 資産/債務/契約が未処理なら物理削除できない。初期化・送金・死亡の再試行と部分失敗で片側だけの変更を残さない。
- 保存読込と、死亡観察で巻き戻した後の再実行で残高・死亡状態・処理済みキーが揃う。移行を二度行っても増減しない。
- 通貨量モデル on/off、Economy の初回有効化・無効化・再有効化、ブラウザ/headless の経路で同じ保存契約を使う。

観測では各操作の前後に `全現金残高、詳細個人、抽象集団、遺産、帰属未確定、明示された域外流入出/造幣/摩耗` を記録し、説明できない差額を 0 にする。通常の関連テストで検証し、全件テストや長期多シード検証を本設計の作成・通常実装の前提にはしない。
