# キャラクター能力の専門分野・経験・言語設計

更新: 2026-09-07。状態: **専門プロフィール・言語・編集・学習・主要判定への接続を実装済み**。

## 実装状況・操作方法

Charactersの人物詳細 → Skills に専門分野と言語を表示する。数値欄はフォーカスを外すと保存され、空欄（不明）と0（未習得）を区別する。分野追加、地形・兵科・文化等の対象習熟、言語の追加、聞き取り・会話・文字別読解・作文、母語等の習得背景を編集できる。CSVにも詳細値・言語・経験を出力する。

「世界の言語設定」では言語・文字を追加し、使用文字、文化の日常言語比率・文芸語・典礼語、国家の行政・宮廷・外交・承認言語を設定する。国家の生成時に初期言語を生成する。旧地図は言語設定がない限り従来動作を維持し、設定画面を開くだけでは有効化しない。国家再生成でも既存の言語設定を上書きしない。

「座学・訓練」では、選択分野または言語の学習軸と、同じ場所の教師を指定する。教師の詳細熟練50以上・存命・同じ場所・意思疎通を確認し、時間経過で年最大0.25年分を学ぶ。条件を失えば休止する。学習・実務経験・衰退はCharacters独自の時間処理（`characters.expertise`）が担当し、Nobility無効時も動作する。口頭言語は共通語なしの会話学習が可能だが、識字には当該言語の聞き取りも必要。工芸の実技は既存の師弟制度を使う。

| 実装 | 所在・挙動 |
| --- | --- |
| 全9能力の分野カタログ | `src/extensions/characters/specializationCatalog.ts`。本文の分野と既存実技への子分野参照を登録 |
| 個人プロフィール | `Character.specializations`。Character自体がCharactersスライスに保存されるため、人物IDを重ねた別Mapは作らない |
| 世界の言語 | Host所有の `pack.languageWorld`。`.fmg`とlegacy `.map`末尾の任意スロット59で保存 |
| 知識・実技の評価 | `specializations.ts`。不足分のみ概要値を使い、概算の理由を返す。既知の0を概要値で置換しない |
| 軍事 | 連隊指揮の指揮・統率・戦術／艦隊運用、兵科・指揮規模。攻城では攻城技能・統率・都市地形を参照し、実際の参加部隊だけに経験を記録。兵科・指揮規模は損耗前の状態を使う |
| 官職・実務 | 官職適性、退職者の地域貢献、指揮官・外交官・諜報官・管理官の実際の在任期間による専門成長 |
| 外交・謀略 | 和平・関係改善は各国の外交言語での意思疎通、現地の専門通訳候補、交渉適性を確認。外交言語が未指定なら既知言語を使用する。通常の会話・教育に外交言語は強制しない。諜報は情報分析・防諜、奇襲は秘密活動・防諜 |
| 工学・地理 | 造船は造船知識、鉱山調査は自然地理・採鉱、研究・試作バイアスは機械工学知識。既存の物資・設備・技術段階の条件は維持 |
| 芸術・武勇 | 贈答品の種類に応じた陶器・彫刻・音楽等の鑑賞、討伐の護身・戦術。既存の武器熟練ボーナスは二重加算しない |
| 保存検証 | 有限な0〜100値、重複ID、未知分野、言語・文字の対応、世界の文化・国家参照、実技の正本、年の時間配分を検証 |

実装上の調整: 経験はプロフィール内に年・従事割合・活動・役割・結果・由来・対象を保存し、直近10年の詳細と累計従事年数を保持する。在任実務と明示的な学習はそれぞれ年最大0.25、全活動の記録は年合計1以下。新規生成では主専門の近接3分野を知識・実践の異なる比率で初期化し、架空の戦役は生成しない。語学の初期識字は養育環境に基づく。

本文には将来拡張の基準も残す。**全任務の置換、新しい技法の発見・解禁、語族や方言による相互理解、公用語政策による住民分布の長期変化、通訳専用の費用・移動ミッションは未実装**。外交言語政策は外交での使用言語に反映し、個人の言語は対話・教育で参照する。行政・宮廷等の政策は設定・保存の段階であり、すべての行政文書・条約へ言語要件を強制するものではない。現在の実装範囲はこの節を正とする。

[Characters §3](../characters.md#3-能力値-skills) の全9能力を、座学で得る知識、実践技能、経験、対象別の専門性へ分解する。9個の `CharacterSkills` は概況表示・既存処理の互換値として維持し、詳細判定は任務に必要なパラメーターを参照する。

## 1. 既存設計との関係

- [人物表現の改訂](character-expression-revision.md): 動機・性格と遂行能力を区別する原則を継承する。指揮・統率は Martial の専門技能とし、10個目の基本能力 Leadership は追加しない。
- [個人熟練・才能・技法](../individual-skill-mastery-system.md): 実践熟練・適性・技法・組織知の分離と0〜100の上限を継承する。本書は未整理の知識分野・政治実務・対象別経験・言語を補う。
- [知識・技術蓄積](../knowledge-guild-system.md)、[技術開発ロードマップ](../technology-development-roadmap.md): 組織の教育環境、設備、技術普及と個人の能力を接続する。
- [プレイヤーによる技術バイアス](../player-character-technology-bias.md): `personalTechnologyKnowledge` は技術内容を知っていることを表し、実技・言語・設備へのアクセスを保証しない。

現コードの `src/extensions/characters/characterTypes.ts` は9能力を数値で持つ。`src/extensions/economy/generators/individualSkillTypes.ts` の `CharacterDomainSkill` は個人熟練を Economy 所有で保持している。本書の型例は設計時の案を含む。現行の追加型は `specializationTypes.ts` と `src/types/worldLanguages.ts`、実装上の差分は冒頭の実装状況を参照する。

## 2. 共通パラメーター

| パラメーター | 値・単位 | 内容・更新契機 |
| --- | --- | --- |
| `knowledge` | 0〜100 | 原理・教範・歴史・理論の理解。講義、読書、口伝、実験の振り返りで成長 |
| `practice` | 0〜100 | 実務・制作・身体操作を遂行する熟練。訓練、実務、師弟教育で成長 |
| `experience` | 履歴・集計 | 従事期間、役割、任務、環境、結果。熟練と別の実績・成長の根拠 |
| `familiarity` | 対象IDごとに0〜100 | 地形、兵科、地域、文化、制度、流派などへの習熟。現地経験・対象を扱う学習で成長 |
| `techniques` | 技法IDの集合 | 特殊な手順・作風・戦法。前提熟練と師匠・記録へのアクセスを必要とする |
| `aptitude` | 既存の5段階 | 成長速度・高度技法の習得を補助。成果の直接倍率や固定上限にはしない |

知識と実践は独立する。「兵書に詳しいが指揮経験がない」「理論は弱いが制作に熟達」「会話は流暢だが読み書きができない」を成立させる。知識にも実践にも該当しない軸は無理に生成しない。

0は未習得、未保存は未設定・不明であり区別する。数値の目安は0〜19が入門、20〜49が基礎、50〜79が熟練、80〜94が専門家、95〜100が卓越。得点は世界内の到達度であり、未知の技術や未習得言語を扱う許可にはならない。

経験は単なる年数や勝利数を加点し続ける値にしない。敗戦でも振り返りにより学べる一方、従軍しただけでは指揮熟練を得ない。同じ期間を複数の仕事へ全量計上せず、従事割合の合計を1以下にする。

## 3. 全9能力の分解

以下のIDは追加案。各行で知識と実践を別に持ち、対象別の習熟を関連付ける。既存の実技IDとの対応は§7に定める。

### 3.1 Diplomacy（外交）

| 分野ID | 座学・知識 | 実践 | 専門対象・経験 |
| --- | --- | --- | --- |
| `diplomacy.negotiation` | 交渉理論、利害分析、譲歩と代替案 | 交渉、説得、条件調整 | 同盟、和平、通商、婚姻の交渉歴 |
| `diplomacy.protocol` | 儀礼、称号、使節慣行 | 接遇、演説、公式会談 | 宮廷・国家・文化別の儀礼 |
| `diplomacy.treaties` | 国際慣習、条約構造、履行保証 | 条文起草、批准調整、履行確認 | 国境、通商、従属関係の協定 |
| `diplomacy.mediation` | 紛争構造、派閥・宗派関係 | 仲裁、危機交渉、合意形成 | 内乱、捕虜交換、都市紛争 |
| `diplomacy.representation` | 他国の権力構造、外交史 | 情報交換、使節団運営 | 駐在先、任期、接触した制度 |
| `diplomacy.intercultural` | 学識側の文化知識を参照 | 異文化での説明、誤解の修復 | 対象文化IDごとの実務習熟 |

外国語自体は§4の共通レコードを使用し、DiplomacyとLearningに同じ言語能力を二重保存しない。人脈は人物関係を参照し、外交得点だけで知人を生成しない。

### 3.2 Martial（軍事）

| --- | --- | --- | --- |

| `martial.leadership` | 集団心理、規律、士気の維持 | 統率、鼓舞、混乱収拾、兵との信頼形成 | 敗走、長期包囲、補充兵の統合 |

| `martial.intelligence` | 偵察計画、敵情評価、戦況推定 | 偵察部隊への指示、報告統合 | 敵軍編制・戦法への習熟 |

得意地形は平原・森林・丘陵・山岳・砂漠・湿地・都市・河川・沿岸・外洋等、気候は寒冷・酷暑・雨季等を別の対象軸とする。兵科は歩兵・槍兵・弓兵・騎兵・騎射・工兵・砲兵・海軍等の世界内登録IDを参照し、未登場の兵科を生成しない。

実戦経験は戦役ID、担当役割、期間、地形、兵科、指揮規模、結果を記録する。訓練と実戦を識別し、平原の騎兵指揮経験を山岳攻城や艦隊指揮へ全量転用しない。軍事学の知識、作戦立案、命令を出す指揮、兵をまとめる統率は相互に代用しない。本人の武器操作はProwess、築城の構造設計はEngineeringが担当する。

### 3.7 Artistry（芸術）

芸術は分野ごとに `knowledge`（美術史・素材・作風）、`practice`（制作・実演）を分ける。さらに各分野に `appraisal`（鑑賞・真贋・品質評価、0〜100）を持つ。「絵を評価できるが描けない」「陶芸の大家だが音楽には疎い」を表現する。

| 分野ID | 知識・鑑賞対象 | 制作・実演 | 専門対象 |
| --- | --- | --- | --- |
| `artistry.ceramics` | 陶器・磁器、釉薬の表現、窯・産地・作風 | 成形、絵付け、意匠 | 器種、産地、流派 |
| `artistry.painting` | 絵画史、構図、顔料表現 | 素描、彩色、壁画、肖像 | 画材、主題、流派 |

陶器の表現・審美はArtistry、窯の熱制御・材料配合・量産工程はEngineering。造形が同じ作業なら単一の実技を共有し、二重の制作ボーナスを与えない。好み・収集欲・散財の意思はTastesやGreed等で扱う。

## 4. 国家・文化・人物の言語と異文化

### 4.1 世界の言語設定

言語は国家や文化と独立した安定IDを持つ。同じ言語を複数文化・国家が共有でき、ひとつの文化・国家が複数言語を使える。UIの日本語・英語切替や、地名・人名生成の `Culture.base` / `personNameBase` は世界内言語能力の正本にしない。

| レコード | 提案フィールド | 意味 |
| --- | --- | --- |
| `LanguageDefinition` | `id`, `name`, `familyId?`, `scriptIds[]` | 言語、語族、使用文字。文字を持たない言語は空配列 |
| `ScriptDefinition` | `id`, `name` | 文字体系。同じ文字を複数言語で使用可能 |
| `CultureLanguageProfile` | `cultureId`, `languages[{languageId, share}]`, `literaryLanguageIds[]`, `liturgicalLanguageIds[]` | 日常言語の比率（合計1）、文芸・典礼の言語候補 |
| `StateLanguagePolicy` | `stateId`, `administrativeLanguageIds[]`, `courtLanguageIds[]`, `diplomaticLanguageIds[]`, `recognizedLanguageIds[]` | 行政・宮廷・外交で採用する言語と承認する言語 |

国家の言語政策は住民が実際に話す言語の比率ではない。住民の言語分布は構成文化・地域から導出し、必要になれば地域別の上書きを持つ。公用語が未制度化の国家は配列を空にできる。法制度としての公用語が必要なら `officialLanguageIds[]` を別途追加し、宮廷語と同一視しない。

征服・国家分裂・改称で言語IDや個人能力は変化しない。政策変更は教育・行政アクセスへ時間をかけて作用する。語族の近さは学習の補助材料にできるが、同語族・同文字だけで意思疎通可能とはしない。方言の相互理解を導入する場合は明示的な言語対の係数を使う。

### 4.2 個人の言語パラメーター

言語能力は共通プロフィールに一度だけ保存し、学識・外交・芸術・軍事・交易から参照する。

```ts
// 提案スキーマ。配列の言語ID、文字IDの組は一意。
interface CharacterLanguageSkill {
  languageId: string;
  listening: number; // 0..100、聞き取り
  speaking: number;  // 0..100、会話・口頭表現
  literacy: Array<{
    scriptId: string;
    reading: number; // 0..100、読解
    writing: number; // 0..100、作文
  }>;
  acquisition: "native" | "learned" | "heritage";
  lastUsedYear?: number;
}
```

母語は複数可能で、母語話者にも識字を自動付与しない。語学書の学習だけでは会話を同量成長させない。同じ文字を使う言語でも読解・作文は言語ごとに必要とする。典礼語の朗誦だけで日常会話や経典解釈ができるとはしない。

目安は1〜19が単語・定型句、20〜49が日常用途、50〜79が実務、80〜94が高度な議論・文章、95〜100が精密な表現。条約・医学・詩作などは言語得点に加えて当該分野の知識を要求する。閾値は用途ごとの調整値とする。

- 対話のA→Bは `min(A.speaking, B.listening)`、双方向の会話は両方向の小さい方を基準にする。
- 文書は対象言語・文字のreading、起草はwriting、口頭演説はspeakingを使う。
- 通訳は各伝達方向で、話者の発話、通訳の聞き取り・訳出、受け手の聞き取りの最小値を使う。翻訳・通訳の専門熟練と題材知識も要求する。
- 通訳者の有無、時間、費用、秘密を共有する相手の増加を処理する。共通語がなくても通訳経由で交渉可能にする。
- 教材・図面・命令書には言語IDと、文書の場合は文字IDを付ける。口伝・実演では読解を不要にできるが、説明内容の伝達可能性は確認する。

翻訳技能は `learning.translation` の追加専門分野として、原言語・訳出言語・口訳/筆訳を対象にする。多言語話者であることと専門通訳であることを区別する。

### 4.3 異文化への習熟

文化IDごとに、歴史・習俗・制度の `knowledge` と、実際に儀礼・交渉・生活で振る舞う `practice` を保存する。Learningの文化研究とDiplomacyの異文化実務はこの同じレコードの別軸を読む。

滞在、交易、留学、婚姻、使節、移住、教師との学習が成長機会となる。言語習熟と文化理解を同値にせず、母文化も全制度を熟知しているとはしない。異文化への好き嫌い・偏見・信仰・忠誠とは独立し、文化差だけで敵意や交渉拒否を発生させない。

## 5. 任務への適用と9能力の扱い

各任務は利用する分野・軸・対象を定義する。暫定的な評価方式は以下とし、重み・補正上限はタスク定義で管理する。

```text
base = Σ(weight × relevant axis score) / Σ(weight)
effective = clamp(base + bounded contextual adjustment, 0, 100)
```

重みは非負で合計を正とする。対象習熟、健康、地図の鮮度等を状況補正にできる。経験は主に熟練成長と対象習熟の根拠として使い、同じ経験から得た熟練・経験年数・勝利数を三重加点しない。必須言語、技法、材料、設備、資格・アクセス権は別の成立条件とし、平均点で不足を帳消しにしない。最終成果は敵、部下、組織、物資、任務難度にも依存する。

| 任務 | 主な入力 | 区別できる人物像 |
| --- | --- | --- |
| 山岳での撤退指揮 | tactics / command / leadership、山岳習熟、補給、命令の伝達 | 平原騎兵の名将でも山岳戦は不得手 |
| 和平条約の起草 | treaties、law、対象言語のwriting・reading、対象制度 | 会話上手でも法律文書は専門家が必要 |
| 外国陶器の購入・鑑定 | ceramicsのknowledge・appraisal、産地・作風習熟 | 制作できない収集家でも鑑定には強い |
| 鉱山の排水設備建設 | hydraulics / mechanics、担当者のpractice、設備・物資・技術前提 | 原理を知る学者と運転できる技師を分業 |
| 税制改革 | taxation / finance、law、地域制度、行政言語 | 優秀な会計官でも現地の土地法は学習が必要 |

移行期間は既存9値をロード時に再計算しない。詳細対応した任務だけが詳細値を使い、未対応処理は既存値を使用する。任務評価に詳細が足りない場合は利用した旧値を「概算」と明示し、既知の0は旧値で上書きしない。未知の言語は旧Diplomacyから推定して通訳不要にしない。言語機能自体が無効の旧世界は、従来どおり言語判定を行わない。

将来9値を詳細から表示用に導出する場合は、分野の固定重みとカバレッジを別途定義する。未知分野を除いた単純平均で、一つの専門だけ高い人物を万能と表示しない。任務評価に9値を再加算しない。

## 6. 生成・学習・衰退

1. 出自、養育地、家業、教育機会、職歴、活動地域から主専門と少数の副専門を生成する。分野カタログ全件を全人物へ付与しない。
2. 言語は養育環境から母語候補、教育から識字、使節・交易・移住から追加言語を生成する。所属国家や種族だけで言語・学識を固定しない。
3. 座学は教師・教材へのアクセスと伝達手段、実践は任務・訓練時間と環境を必要とする。§2の経験集計から既存熟練設計の逓減付き年次成長へ接続する。
4. 教科書はknowledge、実地訓練はpracticeを主に伸ばす。実務後の振り返りはknowledgeにも寄与できるが、同じ時間の二重計上を避ける。
5. 長期不使用では実技や現地情報の鮮度を緩やかに下げる。知識、言語の受容能力、身体条件は別々の減衰規則を使う。死亡で個人技能は失われるが組織知は直ちに消えない。
6. 保存済みの経歴を根拠なく追加しない。新規生成時の教育背景と、シミュレーション中に実際に起きた戦役・制作・赴任は由来を区別する。

## 7. 保存モデルと既存熟練の一元化

提案する専門プロフィールはCharacters所有の任意スライスとして、人物IDに紐付ける。世界の言語・文字定義と文化・国家の設定はHost所有とし、UIやNobilityは参照する。Economyの既存熟練は当面そのまま維持する。

```ts
interface CharacterSpecializationProfile {
  version: 1;
  characterId: number;
  domains: Array<{
    domainId: string;
    knowledge?: number;
    practice?: number; // 既存熟練を参照する分野では保存禁止
    appraisal?: number; // 芸術分野用
    practiceRef?: { owner: "economy"; domain: string };
  }>;
  familiarities: Array<{
    domainId: string;
    targetKind: "terrain" | "climate" | "troop" | "region" | "culture"
      | "institution" | "weapon" | "artSchool" | "material" | "commandScale";
    targetId: string;
    knowledge?: number;
    practice?: number;
    lastUpdatedYear?: number;
  }>;
  languages: CharacterLanguageSkill[];
  experienceRefs: string[]; // 別の経験台帳を参照するID
}
```

これは最小の形であり、対象種別は各分野の登録カタログに合わせ拡張する。経験台帳は人物ID、分野ID、開始・終了年、従事割合、役割、対象、結果、由来（生成背景/実イベント）と任意のイベントIDを持つ。詳細イベントは既存履歴を参照し、集計と原本の二重更新を避ける。

| 本書の参照先 | 実技の既存正本 |
| --- | --- |
| Prowessの剣術 | `CharacterDomainSkill(domain=swordsmanship).proficiency` |
| Prowessの弓術 | `CharacterDomainSkill(domain=archery).proficiency` |
| Prowessの馬術 | `CharacterDomainSkill(domain=horsemanship).proficiency` |
| Engineeringの鍛造・製錬 | `blacksmithing` / `smelting` の各proficiency |
| 織物・仕立ての製作実技 | `weaving` / `tailoring` の各proficiency |

広い分野に複数の実技がある場合は子分野を登録して個別に参照する。たとえば `engineering.metallurgy.blacksmithing` と `.smelting` を分け、親分野は一覧用にする。技法・適性も既存熟練側のものを正本とし、新プロフィールへ複製しない。既存の技法型は鍛冶向けなので、他分野の技法を実装する際に登録・保存検証も拡張する。

Economy無効時の参照不能は不明として返し、0に変換しない。将来所有をCharactersへ移すならバージョン付きの一回限りの移行と互換アクセサーを用意し、両拡張から同じ熟練を更新しない。

保存検証は値の0〜100制約、有限値、ID参照、一意性、経験期間の前後関係、言語と文字の対応、practiceとpracticeRefの排他を確認する。旧セーブではプロフィール欠落を許容し、ロード時の再抽選・戦歴捏造・全外国語の自動生成を行わない。

## 8. 表示・導入順序・受入条件

人物一覧は9能力を維持し、詳細画面で「知識/実践」「得意な対象」「経験」「言語」を表示する。芸術は鑑賞・制作を分け、言語は聞く・話す・文字別の読む・書くを並べる。概算・未設定・未習得を別表示し、任命・任務画面には選定理由と不足する専門を表示する。

導入順序:

1. 分野カタログ、任意プロフィール、既存熟練の参照、保存検証、閲覧表示。全9能力の定義を登録し、実際に使う分野だけ人物へ付与する。
2. 世界内の言語・文字・国家文化設定、人物の言語・異文化プロフィール、通訳を含む外交の判定。
3. 軍事の指揮・統率・作戦立案、地形・兵科習熟、訓練と実戦の記録を任務評価へ接続。
4. 芸術の制作・鑑賞、工学の個人熟練・組織知・技術前提を鑑定や事業へ接続。
5. 管理・謀略・学識・武勇・地理の各任務へ順次接続し、教育・衰退と表示用集約を調整。

実装時の受入条件:

- 同じMartial総合値でも、座学中心の参謀、統率に強い歴戦指揮官、海軍専門家で任務適性が異なる。
- 地形・兵科・指揮規模が違う任務へ経験が無制限に波及しない。
- 同じDiplomacyでも、会話は得意だが読み書きできない使節と、条約翻訳者を区別できる。通訳を手配すると交渉が成立する。
- 同一国家の複数言語、同一言語を使う複数文化、複数文字、口承言語を保存・再読込できる。
- 国家の征服・言語政策変更でも人物の母語と習熟が勝手に置き換わらない。
- 陶器の鑑定家が自動で名陶工や画家にならず、作陶経験から音楽技能が増えない。
- 蒸気機関の原理を知る人物でも、加工技能・設備・燃料・実証が欠ければ製造・国家普及を達成しない。
- 既存の剣術・鍛造熟練を変更すると詳細表示も一致し、二重の成長・成果補正が発生しない。
- 全9能力で座学と実務の成長が分かれ、未設定と0、旧値による概算が区別される。
- 旧セーブ・拡張無効・参照先消失でも例外や架空の経験を生まず、既存9値を維持する。
