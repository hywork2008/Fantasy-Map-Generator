# Game Mode

## Q1

現時点ではInitial Populationを60%にして人口の飽和自体は抑えていますが、殆ど空白地帯が無く、どこにも満遍なく都市が有って人がいるようでは、戦争はしやすいですが、開拓などの要素が抑えめになって、行動の選択肢が限られてしまうような気がします。

人がまばらな開拓モード、都市が散らばり人がある程度いるモードなど、初期の人口配分や分布のプリセットをいくつか備えるべきかと思いますがどうでしょうか？

## A1

賛成です。ただし「Initial Population 60%」の選択肢を増やすだけでは足りません。これは人口の総量・各セルの飽和度を一律に下げる設定で、分布の形は変えないためです。実際、現行初期化は各セルを概ね `capacity × initialPopulationSaturation` で埋めています。つまり 30% にしても「人の薄い世界」になるだけで、「人のいない開拓地がある世界」にはなりません。

さらに重要なのは、今の人口移動は過密セルから隣接する余裕セルへ移す仕組みで、人口 0 のセルは日次人口シミュレーションの対象外です。したがって、開拓プリセットを入れるなら、初期配置とあわせて「未定住地へ移住して村を作る」処理を追加する必要があります。プリセットだけでは、開拓ゲームプレイは生まれません。

私なら、総人口率とは別に `Initial settlement pattern` を作ります。

| プリセット | 総人口の目安 | 居住地の形 | 主な遊び |
| --- | --- | --- | --- |
| 開拓前線 | 20–35% | 首都・河川・海岸・街道周辺だけに人口を集中。大半は未定住 | 入植、道路、辺境防衛、資源開発 |
| 散在する諸国 | 40–55% | 小都市・村は散るが、山地・森林・乾燥地に空白が残る | 地方統合、交易網、治安、内陸開発 |
| 標準 | 60% | 現状に近い。ほぼ全域に農村、都市は適度に散在 | 戦争・経済・災害の基本モード |
| 密集文明圏 | 75–90% | 河川・沿岸・平地が高密度で、未開地は辺境のみ | 都市経済、疫病、食料危機、政治不安 |

実装上は、各セルの環境収容力 `capacity` 自体は変えず、初期人口を置くための「居住重み」を別に作るのがきれいです。

```text
初期人口 = capacity × 総人口率 × 居住重み
```

居住重みは、首都・既存 Burg・河川・港・道路・高適性セルを中心に距離で減衰させます。開拓前線なら、この重みが閾値未満のセルは人口 0 にします。これで「地図上は国家領だが、人のいない内陸・森林・山地」という、内政で開発できる余白を作れます。

最初の版では、未定住地も国家の領土に残す「国内フロンティア」にするのを勧めます。政治境界まで空白化すると国家・文化・州生成との結び付きが大きく変わりますが、国内フロンティアなら既存の国家構造を壊さずに、

- 開拓団・入植補助金
- 道路・橋・河川港
- 辺境砦と治安維持
- 森林伐採・鉱山・農地開墾
- 災害後の再入植

を内政の使い道にできます。

開拓ロジックは「人口が capacity を超えたら」ではなく、例えば「出発地が 80〜90% を超え、隣接または道路接続先に未定住の高適性地があるなら、一定人数を移住させる」とした方が機能します。ロジスティック成長は capacity に近づくほど鈍るため、100%超過を待つ現行条件だけでは開拓が起きにくいからです。

この方針なら、設定はまずプリセットのみを見せ、内部では次の3軸を持たせるのがよいです。

- `initialPopulationSaturation`: 世界全体でどれだけ人口がいるか
- `settledFootprint`: 何割の適地を初期定住地にするか
- `settlementClustering`: 首都・河川・沿岸へどの程度集中させるか

`manors` は都市数の調整なので、人口分布プリセットとは分離したまま、各プリセットが推奨値を与える形が自然です。

## Q2

`国内フロンティアなら既存の国家構造を壊さず`をあえて壊して、政治境界を空白化し、徐々に領土を広げていく場合の、現在の実装との不整合や課題についてまとめて下さい

可能ですが、これは「人口プリセットの追加」ではなく、**国家の領有モデルを“完成地図”から“開拓可能な世界”へ変える**作業になります。現行実装には部分的な領土変化はありますが、未領有地を継続的に開拓・編入するモデルとしては未完成です。

## 結論

政治境界を空白化するなら、`cells.state = 0` を単なる空白として使うだけでは不足します。少なくとも次の3つを分ける必要があります。

| 概念 | 例 | 現状 |
| --- | --- | --- |
| 定住 | 人口・村・都市があるか | `pop` / `burg` はある |
| 実効支配 | 税・徴兵・防衛を国家が行うか | `cells.state` が担う |
| 領有主張 | 国家は「自国領」とみなしているが未開拓か | 独立した表現がない |

開拓前線を成立させるなら、「国家はまだ支配していない無主地」と「国家が領有を主張するが統治できていない辺境」を区別した方がよいです。

## 現在の実装との主な不整合

| 領域 | 現行の前提 | 空白領土化で起きる問題 | 必要な対応 |
| --- | --- | --- | --- |
| 初期国家領 | States が首都から到達可能な陸地を flood-fill で広く領有する | 人口がなくても国家色で塗られる | State 生成を「定住核・前哨地からの限定領有」に変更 |
| 人口配置 | 全適地セルに `capacity × 初期人口率` を入れる | 人口を薄くしても空白地が作れない | 定住クラスタを作り、非定住セルは人口 0 にする |
| 人口移動 | 過密セルだけが隣接余裕セルへ移住する | 成長は capacity に近づくほど鈍るため、開拓がほぼ始まらない | 80〜90% 飽和などを契機に、未領有・未定住地へ移住する専用処理 |
| 領土拡張 | 人口移動で隣接セルを奪う場合がある | 一セルだけの偶発的な国境変更で、入植・請求・統治の過程がない | 開拓団、前哨地、行政編入という段階的な拡張システム |
| 州 | 州は国家領を前提に Burg から生成される | 空白地に州が生まれない／新領土を編入しても州が更新されない | 未領有地は州外、定住閾値到達後に州へ編入 |
| 経済 | 生産・市場・食料集計がセルの `state` を読む | 無主地の資源・生産・食料を誰が利用・課税するかが曖昧 | 「無主地は採取のみ」「前哨地以降は国家経済へ」の所有段階を定義 |
| 軍事 | 軍備、国境分析、AI は国家間の隣接境界を前提にする | 国家—無主地のフロンティアを防衛・遠征・入植対象として扱えない | 対国家国境と未領有フロンティアを別の対象として分析 |
| 災害 | state 単位で食料不足・救援・人口損失を処理する | 無主地・開拓地での被害と救援主体がない | 開拓地は国家支援圏、無主地は国家集計外とする |
| UI・保存 | 国家・州の編集画面は既存領土を前提にする | 中立地や新領土の編集・表示が不整合 | 領有状態を明示する表示・操作・セーブ移行が必要 |

## 具体的な現行コード上の論点

- [`rankCells()`](/Users/h-yamaguchi/Projects/Fantasy-Map-Generator/src/main.ts:1517) は全適地セルに人口を一律配置します。ここを変えない限り、政治境界だけ空けても「誰もいないが人口 capacity のある土地」にはなりません。

- [`States.expandStates()`](/Users/h-yamaguchi/Projects/Fantasy-Map-Generator/src/generators/states-generator.ts:133) は首都からコスト探索で広域を `cells.state` に割り当てます。人口量は拡張コストにほぼ使わず、土地適性・文化・地形で国境を決めるため、開拓世界の「人が住んだ場所から国家が広がる」というルールと逆です。

- [`simulateDemographics()`](/Users/h-yamaguchi/Projects/Fantasy-Map-Generator/src/generators/demography-simulator.ts:27) は人口 0 のセルを処理せず、移住も過密時だけです。開拓用には、飽和前から移住を選択し、遠隔地・河川・港・街道・安全度を評価する仕組みが必要です。

- 現在も移民が隣国セルを上回ると `cells.state` を変更する経路がありますが、これは「入植」ではなく偶発的な一セル征服です。州、国境線、国家統計、隣接国、行政組織を再集計するライフサイクルには接続されていません。

- [`Provinces.generate()`](/Users/h-yamaguchi/Projects/Fantasy-Map-Generator/src/generators/provinces-generator.ts:65) は国家に属する Burg を起点に州を作ります。未領有地を州外にできる点は使えますが、時間経過で獲得した土地を「辺境領 → 州」へ昇格させる処理はありません。

- 国家統計、徴兵、食料ストレス、財政の多くは `cells.state === stateId` を集計条件にしています。これは正しい前提ですが、開拓段階では「行政支配された人口だけ」を対象にすることを明示しないと、国家財政・軍事力が開拓速度に対して急変します。

- Nobility の占領は [`captureBurg()`](/Users/h-yamaguchi/Projects/Fantasy-Map-Generator/src/extensions/nobility/generators/localDefense.ts:35) で Burg のセルだけを移します。これは都市占領には適していますが、無主地の測量・入植・行政編入には使えません。戦争による占領と、平時の開拓は別操作にすべきです。

## 特に大きい設計課題

### 1. `state = 0` の意味

現在の `0` は、無国家地・中立 Burg・集計上の除外・外交史を保持する `states[0]` といった複数の役割を兼ねています。

開拓モードで使うなら、少なくとも画面・ロジック上は次を分ける必要があります。

```text
無主地          state = 0, claim = 0, settlement = none
国家の辺境主張  state = 0, claim = A, settlement = outpost / none
統治領          state = A, claim = A, settlement = village 以上
占領地          state = B, claim = A, settlement = village 以上
```

ただし、最初の版で `claim` まで入れると範囲が大きくなります。まずは「無主地」と「統治領」だけを導入し、領有主張・係争地は後段にする方が安全です。

### 2. 開拓の最小単位

セルを一つずつ塗るだけでは、見た目にもゲーム性にも弱くなります。おすすめは次の段階です。

```text
無主地
  ↓ 開拓費・移民・安全確保
探検路／前哨地
  ↓ 人口・道路・食料供給の条件を満たす
村落
  ↓ 税・行政・防衛の投資
統治領（state に編入）
  ↓ 複数の Burg と行政能力
州
```

災害との接続も良くなります。前哨地は干魃・野盗・疫病に弱く、穀倉・井戸・道路・砦への投資が「都市を強化する」だけでなく「辺境を国家に定着させる」行為になります。

### 3. 国境を動かした後の再計算

現在、人口シミュレーションが国境変更を通知する経路はありますが、国家・州の統計や隣国関係を毎回更新する仕組みにはなっていません。開拓による編入では少なくとも次をまとめて実行する必要があります。

```text
cells.state 更新
→ state/province 統計更新
→ 隣接国・frontier 再計算
→ 国境・州境・ラベル再描画
→ 経済の市場圏・食料・徴兵対象更新
→ 必要なら道路・交易路再評価
```

これを日次で全件実行すると重いので、「開拓団が到着」「村が成立」「州に昇格」などの離散イベント時だけ実行する設計がよいです。

## 現実的な導入順

1. 初期人口分布をクラスタ化し、未定住セルを人口 0 にする  
   この段階では国境を変えず、開拓対象の可視化だけを行う。

2. States 生成を縮小し、首都・既存都市の周囲だけを統治領にする  
   州は統治領だけに生成する。無主地は `state = 0`、`province = 0`。

3. 年次の「開拓団」システムを導入する  
   treasury、人口余剰、道路・港・安全度、土地適性を消費・判定して、前哨地または村を作る。

4. 村の定着時に国境を一塊で編入する  
   一セルの偶発的変更ではなく、接続した数セルを「行政圏」として state に移す。

5. その後に、領有主張・係争地・植民地州・戦争占領を統合する  
   ここで初めて `claim` や占領状態を導入する。

この順なら、災害・内政・人口・領土拡張が同じ「辺境を維持し、定着させる」動機に収束します。
