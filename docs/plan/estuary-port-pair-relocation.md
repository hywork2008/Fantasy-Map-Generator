# 河口の港町の寄せ過ぎ: 都市の再配置と海岸の整形の改善

状態: 設計(未実装) 2026-10-17。デバッグ API(§7)は実装済み。
関連: [waterfront-town-proximity.md](waterfront-town-proximity.md)、[bridge-skew-policy.md](bridge-skew-policy.md)、[simulation-channel-server.md](simulation-channel-server.md) §16、
`src/generators/burgs-generator.ts`(`riverBankSteps`・`adoptRiverSite`)、`src/runtime/dualPortPlacementTask.ts`、`src/services/dualPortShore.ts`、`src/services/waterfrontSettlement.ts`

## 1. 報告された事例

チャンネル `world-1`(Huetia, seed 787850539)の Szerhir(#11)を CE で開くと、Road #18 の橋が海の上を通り、海の上で直角に曲がる。FMG では Szerhir と隣の Khiachaqoh(#395)のラベルが重なっている。

API(§7)で取った事実:

| 項目 | Szerhir #11 | Khiachaqoh #395 |
| --- | --- | --- |
| 所属セル(`burg.cell`) | 1516(陸、h=22、川 62 の河口セル) | 1518(陸、h=27) |
| haven | 1412(海) | 1412(海) ← 同じ |
| 港 | 海港+河川港(両港) | 海港 |
| 都市の位置があるセル | **1412(海のセル、h=17)** | 1518 |
| セル中心からの移動 | 7.46 単位 = **30.1 km** | 約 3.4 単位 |
| 描いた海岸に対する位置 | **海側**(`drawnShore.onLand = false`、海岸まで 63 m) | 陸 |
| `riverPlacement` | `placed`、`physicalCellId` 1412、`coastConstrained` なし | — |

- 2 都市の距離は 7.9 km。元のセル中心の距離 33.2 km の 0.24 倍。FMG の「1 セル 1 都市」は `cells.burg` の上では守られているが、位置の上では両方が同じ海のセル 1412 の岸(河口)に集まり、実質「1 セル 2 都市」になった。
- Road #18 は 2 点だけの直線 [Khiachaqoh → Szerhir]。川 62 との交差はセル 1412(海のセル)上で、幅 969 m の固定橋。道と川の法線のなす角は概算 49°(上限 30° を超える)。
- 世界全体(`/diagnostics/settlement`): 自分のセルの外にいる都市 6(全部が隣のセルへ、うち 1 件は海のセル)、寄り過ぎの組 2、海の上の川の交差 6。

## 2. 原因

### 2.1 両港の探索に移動の上限がセルで効いていない

`riverBankSteps` は `maxMove = max(3R, セル多角形の半径 × 2)` を使う。セルの半径の 2 倍なので、探索はセルの外まで届く。さらに両港(`dualPortShore`)では探索の起点を「川が海岸に出る点」(`shore.mouth`)に置き換える。河口は普通セルの縁、つまり隣のセルとの境にあるので、都市は所属セルを出て河口に寄る。

`adoptRiverSite` の地点の判定は、セルの多角形ではなく描画用の地形(`session.terrain`)で行う。海岸は描くときに平滑化・フラクタル化されるため、FMG では海(h<20)のセル 1412 にも陸の部分がある。結果として `physicalCellId` に海のセルが入り、そのまま採用された。最後に `settledRiverSite` が「海岸に近づける」(`towardShore`)向きに岸沿いを滑らせ、描いた海岸の外側(海側 63 m)まで出た。

### 2.2 他の都市との間隔を誰も見ていない

- 都市の生成時は `cells.burg` と quadtree で間隔を保つ。しかし再配置(`riverBankSteps`、`dualPortPlacementTask` の `settledRiverSite` / `settledShorePort`)は 1 都市ずつ動かし、他の都市の位置を見ない。
- 海港は haven の岸へ寄る。haven が同じ 2 つの港(1516 と 1518 → 1412)は、同じ岸の同じ辺りへ寄る。

### 2.3 河口では川の多角形が海に突き出る

FMG の川の経路は最後のセルとして海のセル(1412)を持ち、CE の川の多角形(`RegionalRiverGeometry`)もそこまで伸びる。道と川の交差の判定はこの多角形に対して行うので、「川の交差」として固定橋が計画された地点が、描いた海岸では海の中にある(6 件すべて)。CE は橋を直角にしようとして道を曲げるので、海の上で直角に曲がる道になる。

### 2.4 再配置後の道は直角の規則を通っていない

`reconnectRelocatedBurgLandRoutes` は、動いた都市へ道を直線でつなぎ直す。この直線は `bridgeSkewPolicy` の判定を経ないので、川を斜めに渡る(Road #18 は概算 49°)。

## 3. 方針

1. 都市は**自分のセルの陸**から出ない。描いた海岸の陸側にいることを必須にする。
2. 再配置しても、隣の都市との距離を FMG が決めた間隔の一定割合以上に保つ。
3. 港のフラグは「その位置で水際に届くか」で決める。届かないなら、都市を動かすのではなく、フラグを外す。
4. 川の交差は描いた陸の上だけに置く。河口(川が海に出る区間)には橋を架けない。
5. 再配置後の道も `bridgeSkewPolicy` の判定を必ず通す。

## 4. 改善案: FMG での都市の再配置

### 4.1 移動範囲をセルの陸に限る(必須)

- `riverBankSteps` の候補判定(`search.supports`)に「足場(footprint)の全点が、所属セルの多角形の中、かつ描いた海岸の陸側」を加える。`maxMove` はこの制約で実質的に切られるので、値自体は今のままでよい。
- `adoptRiverSite` で `physicalCellId !== cellId` の場合は採用しない(今は隣のセルでも海のセルでも受け入れている)。隣のセルに寄せたい理由はないため、例外は設けない。
- `settledRiverSite` の岸沿いの滑らせ(`towardShore`)と `settledShorePort` にも同じ条件を入れる。`settledShorePort` はすでに「着地点のセルが陸・同じ地形・同じ国」を見ているが、「同じセル」は見ていない。これを「同じセル」に強める。
- 1 セルが小さすぎて都市(半径 R)が入らない場合は、セル境界から R/2 まではみ出すことを許す。ただし、はみ出した先のセルが陸で、都市がないことを条件とする。

### 4.2 都市どうしの間隔(必須)

- 再配置の受け入れ条件に「他の全都市からの距離 ≥ max(0.5 × 元のセル中心の距離, 2 × (R_a + R_b))」を加える。0.5 は経験値。world-1 では寄り過ぎの 2 組(比 0.24・0.44)だけが引っかかる。
- 判定には、確定済みの位置(`dualPortPlacementTask` の `proposals` を含む)を使う。順序で結果が変わらないよう、人口の多い順に確定させる(首都が先に良い岸を取る)。
- 同じ haven を共有する港どうしは、寄せ先の岸の点を haven の岸のうち自分のセルに面した区間に限る。Szerhir と Khiachaqoh はこれだけで別々の岸に分かれる。

### 4.3 港フラグの扱い(両港の降格)

河口の両港は、次の順で決める。

1. 自分のセル(4.1)の中で、海岸から 2R 以内かつ河岸から R+20 m 以内の地点を探す(今の両港の探索と同じ。範囲だけを狭める)。
2. 見つからなければ、セル評価(`getSettlementScore` の海・川の寄与)の大きい方の港だけを残す。今は「海岸探索をやめて普通の川沿い配置へ戻す」だけで、海港のフラグは残っている。そのため、CE では海の見えない「海港」になる。
3. 残した港の岸にも 2R 以内で届かなければ、港のフラグを両方外す(内陸の町。`waterfront-town-proximity.md` §3 の上限と同じ)。

河川港のフラグを外した都市でも、川は CE に描かれる(川を渡る道・橋は残る)。外すのは港の施設(岸壁)と、`waterAccess.port` だけである。

### 4.4 隣の港と統合するか(選択肢、今回は推奨しない)

河口の 2 つの港のうち小さい方を消す案もある。しかし、FMG の都市の数・名前・国の構成が変わり、既存の保存データとの互換性が崩れる。そのため推奨しない。4.2 で離せない組だけを `waterfront-town-proximity.md` の警告(`waterfrontIssues`)に新しい種別 `crowded` として出し、人が判断する。

## 5. 改善案: 海岸の形の整形

### 5.1 河口の海岸を FMG のセルと揃える

描いた海岸(フラクタル)は FMG のセルの境界とずれる。陸のセルに海が食い込むことも、海のセルに陸が張り出すこともある。都市の位置の判定(4.1)は「セルの多角形 ∩ 描いた陸」で行うので、ずれていても安全側になる。ただし、両港の候補が消えやすくなる。

- 河口のセル(`rivers[].mouth`)と、その haven の間の海岸の区間に限って、フラクタルの振幅を 0 にする(直線の海岸)。全体の見た目は変えない。
- これで「川が海に出る点」がセルの境界の上に乗り、河口の都市の候補(海岸と河岸の両方から近い地点)がセルの中に必ず残る。

### 5.2 川の多角形を海岸で切る

- `RegionalRiverGeometry` の水の多角形を、描いた陸の多角形との積で切る。川の最後の海のセルまで伸ばすのをやめる。海に出た後の水は海として扱う。
- `riverRouteCrossings` / `planRiverCrossing` は、切った多角形に対して交差を求める。河口で海に出ている部分を道が横切る場合は、橋ではなく「海を渡る」扱いになる。道の生成時に、その区間を通れないものとする(渡し船にするか、上流に回る)。
- 交差点が描いた陸の外にある川の交差は、生成時の検証で失敗とする(`/diagnostics/settlement` の `crossingsInSea` が 0 になることを受け入れ条件にする)。

### 5.3 河口の橋の位置

河口では川幅が最大になる(world-1 の川 62 は 969 m)。河口の両岸の町を結ぶ道は、河口から上流へ「川幅 × 3」以上離れた、かつ時代の上限内の角度で渡れる地点を探す。見つからなければ渡し船(`ferry`)にする。橋の角度は `bridgeSkewPolicy` に一本化する(AGENTS.md)。

## 6. 道のつなぎ直し

- `reconnectRelocatedBurgLandRoutes` の直線のリンクに、`bridgeSkewPolicy` の判定と「交差点が陸の上」の判定を加える。通らなければ、直線ではなく `generateWorldLandConnections`(道路網の作り直し。今も `landConnectionGeneration` が有効なときは使われている)に任せる。
- 4.1・4.2 が入れば都市の移動距離はセルの中に収まる。そのため、つなぎ直しが川を新しく横切ることも減る。

## 7. デバッグ API(実装済み、2026-10-17)

人が「チャンネルの URL + 都市番号」を共有するだけで、AI がブラウザを開かずに FMG と CE の入力を再現できるようにした。どれも読み取り専用。詳細は [simulation-channel-server.md](simulation-channel-server.md) §16。

| エンドポイント | 内容 |
| --- | --- |
| `GET /api/sim/channels/:id/debug` | 使えるエンドポイントの一覧(AI が最初に読む) |
| `GET …/burgs/:id/context` | 所属セル、都市の下のセル、セル中心からの移動(m)、描いた海岸に対する位置、港の検査(`waterfrontIssues`)、近くの都市、接続する道と川の交差(角度の概算・海の上か) |
| `GET …/burgs/:id/site` | CE が開くときと同じサイト記述子(`getBurgSiteDescriptor`)。CE と同じく道の収束処理を先に走らせる(約 3 秒) |
| `GET …/cells/:id` | セルの多角形・高さ・地形・川・haven・都市・隣接セル・道 |
| `GET …/diagnostics/settlement` | 世界全体の検査: セルの外の都市、寄り過ぎの組、海の上の川の交差、角度の概算が上限を超える交差の数 |

この事例の調査は、`/burgs/11/context` と `/diagnostics/settlement` の 2 回の呼び出しで再現できた。

## 8. 実装計画

| 段階 | 内容 | 受け入れ条件(`/diagnostics/settlement`、River-Port Lab seed 1〜200) |
| --- | --- | --- |
| P1 | 4.1 セルの陸に限る + `adoptRiverSite` の別セルの拒否 | `outsideHomeCell` 0(4.1 の例外を除く) |
| P2 | 4.2 間隔 + 人口順の確定 + 同じ haven の岸の区間分け | `crowdedPairs` 0 |
| P3 | 4.3 両港の降格 | 両港の割合と `waterfrontIssues` の件数を、変更の前後で記録する |
| P4 | 5.2 川の多角形を海岸で切る + 陸の外の交差を拒否 | `crossingsInSea` 0 |
| P5 | 5.1 河口の海岸の直線化 | P3 の両港の割合が、P1 前の値を下回らない |
| P6 | 5.3・6 河口の橋の位置と、つなぎ直しの角度の判定 | CE の道の監査で、角度の上限を超える橋が 0 |

P1・P2 だけで、今回の Szerhir の事例は解消する見込みである(Szerhir はセル 1516 の陸に留まり、Khiachaqoh から離れる)。P4 は、都市の位置と関係なく、河口を横切る道すべてに効く。
