# CEの自由造形モード: BVの建物を地形に置き、ボロノイに頼らず3D都市を作る

作成日: 2026-11-02
状態: F4 実施（2026-11-03）。自由造形の台帳へ、手動と同じ検証で建物を自動配置する（§18）。開いたときは再生成しない。FMG の街路・川・城壁を台帳へ写す変換は別の設計のままである。F3 は §17、F2 は §16、F1 は §15、F0 は §14。彫刻の筆は型だけで、画面は作っていない。GPU 変位は作っていない。medium の既定は変えない。段階表は F4 で終わる。

## 1. 目的

依頼の要点は4つある。

1. 球の一部を切り取ったような、滑らかな山の形（ドーム）の地面の上に、BVの建物を置けるようにする。Generation mode = Terrain はこのような形を作れる一例であり、配置の対象はモードではなく地面の形である。地面が高さ場であれば、作られ方（Terrainの標高、岩山、ノイズ、手動）を問わない。
2. 建物は位置だけでなく向き（東西南北のどちらを向くか）も編集できる。
3. 置くときは、建物の面積に応じた敷地を平らにする。敷地は他の建物の敷地と重ねられない。平らな敷地・水平な道・階段を組み合わせ、坂道に頼らない立体的な都市を造れるようにする。
4. 最終的には、CEの2D・3D表示をこの新しいモード単独で作れるようにする。川や道がセルの辺にしか引けず、標高がボロノイ／ヘックスのセル単位になる制約から離れる。

低負荷で実現するため、ライブラリ選定の水準から設計する（§6）。

### 1.1 受入基準

small（1,200 m）の図枠、高さ場の地面で、次をすべて満たせば合格とする。基準値は暫定で、F0の計測で決め直す。

1. BVの任意の建物を選び、カーソルに追従する足跡（ワイヤーフレーム）を見ながら置ける。足跡は建物の面積と、敷地の余白を表す。
2. 位置の操作と向きの操作を切り替えられる。向きは方位（北0°、時計回り）で数値表示され、N／E／S／Wに吸着できる。左クリックで確定、右クリックとEscで取り消す。
3. 置いた建物の敷地は水平で、建物は浮かず、埋もれない。敷地の縁は擁壁か盛土の斜面になる。
4. 他の建物の敷地（足跡＋余白）に重なる位置には置けない。理由が画面に出る。重なる擁壁・盛土の斜面も同様に置けない。
5. 敷地どうしを水平な道と階段でつなげる。坂道を選ばない場合、道は水平な踊り場と階段の列になる。
6. 建物2,000棟を置いた状態で、3D表示の1フレームの95パーセンタイルが16.7 ms以内。足跡の移動1回あたりの検証が1 ms以内。
7. 置く・動かす・回す・消すがすべてUndo／Redoでき、保存して開き直すと同じ見た目になる。
8. コンソールにエラーが出ない。

## 2. 現状（調べた事実）

読んだコードと設計書から確かめたこと:

- 生成モードは `GenerationSettings.mode?: "city" | "fort" | "terrain"`（`src/city-editor/types/generationSettings.ts`）。画面の文言は `i18n/locales/editors.en.json` の "Terrain & elevation"。
- **高さ場（`field`）はすでにある。** `TerrainBase` は `cells | flat | field`（`types/terrain.ts`）。`terrainField` の生成設定、micro〜smallの図枠、`TerrainFieldRecipe`（部品の列＋シード）、`heightAt`の双一次補間、チャンク分割の地面メッシュ（`city3d/three/terrainFieldMesh.ts`）、2Dの陰影と等高線（`renderers/terrainFieldSvg.ts`）が実装済み（`ce-terrain-field-mode.md`、`ce-terrain-layers.md`）。
- **平らな敷地もすでにある。** `TerrainPlatform` の `role: "pad"`（建物のために斜面を切り出した敷地）、縁の種類 `cliff | slope | wall`、`TerrainRamp`、`CityTerrain.roads.stairs`（急すぎる小道の階段）、`TerrainRiverCorridor`（セルの辺でなくベクターの中心線で持つ川）がある。
- **向き付きの建物配置もすでにある。** `CityElement` は `objectType`（BVのモデルID）・`point`・`rotation`（plan +XからCCW）・`objectScale` を持つ。ただし面（`faceIds`）に属し、操作はセル単位の配置が前提。`PLACEABLE_OBJECTS`（`buildings/placeableObjects.ts`）は攻城兵器・乗り物・水車・井戸だけで、住宅や教会などの建物カタログは入っていない。
- BVの建物の足跡は、`fitBvBuilding`（`city3d/three/bvPlacement.ts`）が区画の予約領域へ当てはめる形でしか使われていない。モデル単体の「足跡の多角形」と「正面の向き」の公開された契約は見つからなかった（未確認）。
- 3Dは three 0.185。BVのモデルは `bvInstances.ts` が不透明・単色の部品を一度だけ焼き、プロトタイプを共有する。品質は Low／High／Ultra（`modelQuality.ts`）。遠景用の粗い立体は `buildings/coarseSolids.ts`。
- 空間索引は、CEのセル用の自前バケット（`controllers/spatialIndex.ts`）だけで、動的に追加・削除できるR木は依存に無い。依存にある幾何ライブラリは delaunator・earcut・polylabel・lineclip・flatqueue・simplify-js。
- 計測済みの数字: 1,200 m・1 m格子（144万頂点）の構築は約230 ms、2 m格子で約50 ms（`ce-terrain-field-mode.md` §9.4）。1フレームの時間は未計測。
- 依頼文の「滑らかな山」は、Terrainモードのセル標高プリセットで作られる形（セルの標高を補間した見え方）を指す。ユーザーの補足により、対象はモードではなくこの形の地面である。コードで滑らかさの原因までは確認していない。
- 高さ場のテンプレートは `noise`・`crag`・`spur`・`meander`・`escarpment` で、球冠のような滑らかなドームの専用テンプレートは無い。部品の `hill`（中心・半径・高さ）はある。

### 2.1 既存の仕組みでは足りない点

| 欲しいこと | 今の状態 | 足りないもの |
| --- | --- | --- |
| BVの建物を自由な位置・向きに置く | `CityElement` は面に属し、足跡も敷地も持たない | 足跡つきの配置、足跡のプレビュー、検証 |
| 建物ごとに平らな敷地を作る | `pad` はあるが、手動の配置と一体ではない | 建物から敷地を作る処理（レベル決定・縁の種類・重なり検査） |
| 他の敷地と重ならない | 検査が無い | 動的な空間索引と、足跡・縁の重なり判定 |
| 水平な道と階段の組み合わせ | 階段は急な小道に自動で付くだけ | 踊り場と階段の列を設計する処理 |
| ボロノイ無しで2D・3Dを作る | 文書の正本が `mesh`（セル）。街路・区画・川・土地利用がセルの辺と面に依存 | セルに頼らない文書の形（§4） |

「セル標高のまま置く」は採用しない。セルは水平な板で、敷地の高さとセルの高さが二重になる（`ce-terrain-grading-layer.md` §7.18、`ce-terrain-layers.md` §2）。置くのは高さ場の上に限る。

滑らかな山の入手経路は2つ設ける。

1. **主経路: ドームのテンプレート `dome`（新設）。** 中心・底の半径・高さ（または球の曲率半径）を指定する球冠で、縁へ向けて接線が水平に近づくなめらかな形にする。既存の `hill` 部品を土台に、球冠の式 `h(r) = H · (1 − r²/R²)` の形（縁で高さ0）を足す。ノイズ（`noise`）を重ねて自然な起伏にもできる。生成パネルの高さ場の選択肢に加える。
2. **補助経路: 既存のTerrainモードのセル標高を高さ場へ変換。** 既存の部品 `coarse`（粗い標本から高さ場を起こす）を使う。変換の品質は §15.2。1,200 m の平坦な格子では coarse 16 m で足りる。主経路は `dome` テンプレートである。

## 3. 方針: 台帳を正本にし、高さ場は派生物にする

| 層 | 持ち主 | 内容 |
| --- | --- | --- |
| 正本: 台帳（ledger） | 文書 | 地形のレシピ、敷地（plot）、建物（placement）、道（way）、川、水面、土地利用の多角形。すべてベクターで、メートルの座標を持つ |
| 派生: 高さ場 | キャッシュ | 台帳から焼いた高さの格子。保存しない。変更された矩形だけ焼き直す |
| 描画 | three | 地面のチャンク、擁壁・基礎のスカート、建物のインスタンス |

- 「どの座標に、どれだけの平面を作ったか」は敷地（plot）が持つ。敷地は台帳の第一級の項目で、セルに紐づかない。
- 高さの問い合わせ（`heightAt`・`foundationAt`・`surfaceAt`）は既存の `CityTerrain` の契約を保つ。既存の3Dメッシュ（道・水・木・橋）がそのまま使える（`ce-terrain-grading-layer.md` §4 の方針と同じ）。
- 生成（自動配置）と手動は、同じ検証関数と同じ台帳を通る。F4（§18）で、自由造形の建物についてこれを実施した。

## 4. データモデル

```ts
/** Saved document of the freeform mode. Metres, local frame, +Y north. */
interface FreeformCity {
  version: 1;
  frame: { extentMeters: number };
  ground: TerrainFieldRecipe;              // existing recipe
  sculpt: SculptStroke[];                  // optional hand edits of the field, replayed in order
  plots: Plot[];
  placements: Placement[];
  ways: Way[];
  rivers: TerrainRiverCorridor[];          // existing type
  zones: LandZone[];                       // forest / farm / park polygons
}

interface Placement {
  id: Id;
  modelId: string;                         // BV model id
  quality?: "low" | "high" | "ultra";
  position: Point;                         // centre of the footprint
  facingDegrees: number;                   // compass: 0 = north, clockwise; where the front faces
  plotId: Id;
}

interface Plot {
  id: Id;
  ownerId: Id;                             // placement id; removed with it
  outline: Point[];                        // footprint oriented box grown by the margin
  levelMeters: number;
  edge: { kind: "wall" } | { kind: "slope"; runMeters: number };
  marginMeters: number;
}

interface Way {
  id: Id;
  centerline: Point[];
  widthMeters: number;
  profile: "slope" | "stepped";            // stepped = level landings joined by flights of steps
  surface: "dirt" | "paved" | "cobble";
}
```

- 向きは方位（北0°・時計回り）で保存し、既存の `CityElement.rotation`（plan +XからCCW）との変換は1つの関数にまとめる。
- 足跡の多角形と正面の向きは、BVの各モデルが持つ必要がある。F0で、`studyBounds`（`building-viewer/physicalScale.ts`）から得られる箱を足跡の既定とし、正面の軸の契約をBVの側に足す（§12の確認事項1）。
- `ground` と `sculpt` だけが地形の正本である。`plots`・`ways`・`rivers` は高さ場の上に重ねる造成で、既存の `TerrainFeature`（`platform`・`riverCorridor`）へそのまま写せる。

### 4.1 既存の文書との共存

最終形は「`mesh`（セル）を持たない文書」だが、一度に移すと街路・区画・川・土地利用を扱う描画と生成のほとんどを作り直すことになる。そこで二段に分ける。

| 段階 | 文書 | 内容 |
| --- | --- | --- |
| 先 | 既存の `CityDocument`（Terrain・高さ場） | 台帳の `plots`・`placements` を `terrain.features` の `pad` と `CityElement`（点・向き・BVのID）へ写して保存する。ボロノイは残るが、建物の配置には使わない |
| 後 | `FreeformCity`（`mesh`なし） | 上記の台帳を正本にする。2D・3Dは台帳から直接描く |

先の段階で依頼の1〜3が成り立つ。後の段階が依頼の4である。台帳の型を先の段階から使うので、移行は保存形式の変換で済む。

## 5. 建物を置く操作

### 5.1 状態

```
Idle ─ choose BV model ─▶ Move ◀─ Tab / Shift ─▶ Rotate
                            │                      │
                  left click: commit      left click: commit
                  right click / Esc: cancel   right click / Esc: cancel
```

- **Move:** 地面の上のカーソル位置に、足跡のワイヤーフレームが追従する。足跡は建物の箱（面積）と、外側の余白の枠（敷地）の二重線。敷地の縁の予定（擁壁／斜面）と平らにするレベルを、線の色と数値で添える。置ける位置は緑、置けない位置は赤で、理由（重なり／勾配／水／崖）を1行出す。
- **Rotate:** Move中の位置を固定し、カーソルの方向へ向きが追従する。向きの矢印を足跡の正面に描く。Ctrl＝15°刻みに吸着、N／E／S／Wの±3°以内は自動で吸着。ホイールで±5°、Alt＋ホイールで±1°。
- 切り替えはTabのトグル、またはShiftを押している間だけRotate（押下の間に離れた位置に置かない）。依頼文の「CtrlやShift」は例なので、キーはF1の実機で確かめて決める。
- 左クリックで確定。Shift＋左クリックは確定して同じ建物を続けて置く。右クリックとEscは取り消し（Rotate中は一段戻さず全体を取り消す）。
- 既存の建物の選択後は同じ足跡のツールが開き、位置・向きを再編集できる。検査に通らない編集は確定できない。数値入力（X・Y・方位）もインスペクタに出す。

### 5.2 検証（`validatePlacement`）

置く位置のたびに実行する。1回の呼び出しは1 ms以内を目標とする。

1. 足跡＋余白の多角形が、既存の敷地と重ならない（粗い判定はR木、細かい判定は分離軸判定。向き付きの箱どうしは凸なので多角形クリッピングは要らない）。
2. 敷地の縁（擁壁の厚み、または盛土の斜面の広がり）が、他の建物の足跡＋余白に届かない。届く場合は、斜面を擁壁に替えて縁を狭める。それでも届くなら置けない。
3. 足元の勾配が区分の上限以内（`ce-terrain-field-mode.md` §6.1 の区分: 平坦5%以下／緩斜面15%まで／急斜面35%まで／それ以上は不可。暫定値）。
4. 擁壁の高さが3 m以内（同 §6.2 の方針）。
5. 水面・川の回廊・崖の帯の上ではない。
6. 道（`ways`）に重ならない。重ねる場合は道の側を付け替える操作として別に扱う。

### 5.3 敷地の作り方（レベルと縁）

- レベル: 足跡＋余白の内側を標本化し、切土と盛土が釣り合う中央値を候補にする（`ce-terrain-field-mode.md` §6.2）。前面の道との差が階段で上れる範囲（3 m）を超えないよう収める。
- 縁: 既定は盛土の斜面（勾配1:2）。隣の敷地が近い、または高さが大きいときは擁壁。擁壁と斜面の選択は台帳に保存し、手で直せる。
- 敷地は台帳の `plots` に入れ、地面には焼き込み（§7）で反映する。建物を消すと敷地も消え、地面はもとの高さ場へ戻る。

### 5.4 道と階段

- **道（way）:** 折れ線で描く。`profile: "slope"` は勾配の上限（荷車10%、登城路8%。`ce-terrain-field-mode.md` §1.1）を守る縦断を、既存の道の縦断の処理で求める。
- **段付き（`stepped`）:** 踊り場と階段の列に分ける。道の中心線の距離ごとに、地面との切土・盛土が最小になる踊り場の高さを1次元の動的計画法で選ぶ。踊り場は最小3 m、階段の1段は蹴上げ0.17 m・踏み面0.30 m、1つの階段列の上りは3 m以内。踊り場の水平面は台帳の敷地と同じ扱い（平らな正確な高さ）で、建物の入口を踊り場へ向けられる。ライブラリは使わず自前で書く。
- **橋:** 川を渡る道は、橋の斜角の基準（`src/utils/bridgeSkewPolicy.ts`、`bridge-skew-policy.md`）に必ず通す。検証を通らない場所には橋を架けず、道を曲げて直角に入るか、別の地点・渡し船とする。この規約は `validateWay` に組み込む（AGENTS.md「河川と橋の角度」）。
- **入口の接続:** 建物の正面に入口点を持たせ、「入口を最寄りの道へつなぐ」操作で、短い小道と階段を提案する。

## 6. ライブラリの選定

方針: 新しい依存は最小にする。既存の依存（three・earcut・delaunator・polylabel）で足りる部分は足さない。足すのは、動的な空間索引だけにする。

| 用途 | 候補 | 判断 | 理由 |
| --- | --- | --- | --- |
| 3D描画 | three 0.185 | 継続 | 既存の全描画が前提。`mergeGeometries`・`InstancedMesh` も既存 |
| 動的な空間索引（敷地・建物・道） | **rbush 4.0.1**（MIT、48 KB、依存は quickselect のみ） | **採用** | 置く・動かす・消すたびに挿入・削除が要る。一括読み込み（bulk load）と範囲検索が速い。型は別（`@types/rbush`）か自前の宣言が要る（未確認） |
| 同上、読み取り専用 | flatbush 4.7.0（ISC、依存は既存の flatqueue） | 不採用 | 構築後に変更できない。ワーカーへの読み取り専用の写しが要るときだけ再検討 |
| 多角形の足跡の重なり | 自前（分離軸判定） | 自前 | 足跡は向き付きの箱（凸）。凹の足跡は凸包で近似する |
| 多角形の論理演算（敷地の和・差） | polygon-clipping 0.15.7（MIT、robust-predicates使用） | **保留** | 凸の箱どうしでは不要。敷地を連結した共通の段にまとめる機能（将来）で必要になったら導入する。martinez-polygon-clipping 0.9.0（MIT、47 KB）は軽いが、浮動小数点の頑健性は polygon-clipping のほうが明示されている |
| 同上 | clipper2-js 1.2.4 | 不採用 | ライセンスがBoost（MITと違い個別確認が要る）、1.8 MB、peerDependenciesにAngularが残る |
| 制約付き三角形分割 | @kninnug/constrainautor 4.1.0（ISC、delaunator上） | **不採用（拡張点として保留）** | 敷地の縁を地面の三角形に完全に合わせられるが、前の設計で地面を回廊に合わせて細分したときに重くなった実績がある（`ce-terrain-field-mode.md` §13）。継ぎ目は擁壁のスカートで隠す方式を続ける。継ぎ目が目立つと分かった場合だけ再検討 |
| 多角形の三角形化 | earcut（既存） | 継続 | 敷地の上面・擁壁のキャップ |
| 地面の可変詳細度 | @mapbox/martini 0.2.0（RTIN）・delatin 0.2.0 | 不採用 | 静的な標高地図向き。編集のたびに再構築が要り、LODの境目に亀裂が出る。遠景だけなら将来検討 |
| 地面の描画（GPUで頂点を変位） | 自前（three のシェーダ差し替え） | **保留** | 頂点の変位は編集部分を更新するだけで済むが、まず下記のCPUチャンク方式で足りるかをF0で測る |
| 3Dの交差判定（選択・地面） | three-mesh-bvh 0.9.17（MIT、展開後2.3 MB） | **不採用** | 地面は高さ場なので、視線を格子に沿って進める（DDA）自前処理で正確に当てられる。建物はR木で平面の箱を絞り、視線と箱の交差で足りる。BV本体の三角形単位の当たり判定は要らない。重い依存を増やさない |
| 雑音 | simplex-noise 4.0.3 | 不採用 | 既存の高さ場の部品が雑音を持つ（`TerrainFieldPart` の `noise`） |
| ワーカーの通信 | comlink 4.4.2 | 不採用 | CEに独自のワーカー通信の型（`types/worker.ts`）がある |
| 物理 | rapier など | 不採用 | 建物の配置に物理は要らない |

結論: **追加する依存は rbush（と型）だけ。** 他は既存の依存と自前の小さい処理で作る。polygon-clipping と constrainautor は、必要が実証された時点で追加する保留枠とする。

### 6.1 描画の負荷設計

低負荷の鍵は、描くものを少ない描画呼び出しにまとめ、編集のたびに変わる範囲を小さくすることである。

- **地面:** 図枠を64 m四方などのチャンクに分け、各チャンクを共有の添字バッファ＋チャンクごとの位置バッファで作る。3段階の詳細度（近い／中間／遠い）をチャンクの四分木で選び、視錐台の外は描かない。1回の編集で焼き直すのは敷地・道・川に触れたチャンクだけ。計測済みの構築速度（144万頂点で約230 ms）から、64 m・1 m格子（約4千頂点）のチャンクの再構築は1 ms未満の見込み（実測は未）。
- **建物:** 既存の `bvInstances.ts` のプロトタイプ共有に乗せる。`InstancedMesh` は全体で1つの視錐台判定になるので、128 m四方の格子ごと・モデルごとに分ける（遠方の格子は描かれない）。遠くの建物は品質をLowか粗い立体（`coarseSolids.ts`）へ落とす。
- **敷地の基礎・擁壁:** 建物ごとに別メッシュにせず、チャンクごとに1つへ結合する。
- **水・道・木:** 既存の描画を使う。変更のあったチャンクの分だけ作り直す。
- **足跡のワイヤーフレーム:** 線のオブジェクト2本を再利用し、移動のたびに位置・向きだけを更新する（割り当てを行わない）。
- **選択の当たり判定:** 地面はDDA、建物はR木の絞り込み。ブラウザの表示を止める処理は1つもワーカーへ出さない（1 ms級）。

## 7. 高さ場への焼き込み

- 高さ場の格子（生成用、既定2 m）を保持し、`plots`・`ways`・`rivers` が触れる矩形（ダーティ矩形）だけを再計算する。
- 敷地の内側は、台帳のレベルの正確な値を使う（焼き込みでなく解析で返す）。`heightAt` は、敷地の内側なら台帳の値、外なら焼いた格子の双一次補間。これで建物の足元が格子の粗さによらず正確になる。
- 縁の斜面は、レベルから外側へ傾斜（勾配1:2）で下り、元の高さ場に戻る位置で止める。擁壁は鉛直面（スカート）で表す。
- 高さ場は保存しない。台帳から作り直す（`ce-terrain-field-mode.md` §10 と同じ）。

## 8. ボロノイを使わない最終形

セルが今持っている責務と、置き換え先:

| セルの責務 | 置き換え |
| --- | --- |
| 地面の高さ | 高さ場（既存の `field`）＋敷地・道の造成 |
| 街区・区画のトポロジー | 敷地（plot）。手動で置く。建物の自動配置は台帳へ置く処理（§18） |

## 12. 未確認事項・リスク

1. **BVの正面の軸と足跡の契約:** F0で決めた（§14.1）。未登録の陸上モデルはローカル +Z を正面とし、コメントで別の軸と書いてあるモデルだけ表に載せる。足跡は `studyBounds` または焼いた原型の軸平行箱の XZ である。
2. **Terrainのセル標高からの変換（補助経路）:** F1で測った（§15.2）。既定の coarse 16 m・標本 2 m では RMS 0.017 m、最大 0.153 m。主経路は `dome` テンプレートである。
2a. **球冠の斜面と敷地:** 1,200 m のテンプレート（半径 450 m、高さ 40 m）では、勾配 0.35 以下が円盤の全体、0.15 以下が 0.7119140625 である（§15.2）。20 m 格子の割合は 0.65 を超えることだけ確かめてあり、格子そのものの分数は記録していない。
3. **three の部分テクスチャ更新:** CPU チャンクの定常フレームが目標を下回ったので、GPU 変位と `copyTextureToTexture` は作っていない（§14.2）。
4. **rbush の型:** 4.0.1 は型を同梱しない。`src/city-editor/types/rbush.d.ts` に自前の宣言を置いた。Vite からの import は計測スクリプトで通った。
5. **1フレームの時間の計測環境:** `requestAnimationFrame` は使わず、描画のあと `gl.finish()` した時間を測った。headless Chromium だが GPU は ANGLE Metal（Apple M4）で、SwiftShader ではない（§14.2）。
6. **敷地の縁が重なる判定の厳しさ:** 擁壁／斜面の広がりまで禁止すると、密集した街が作れない。擁壁への自動切り替えで緩和するが、実機で確かめる。
7. **2D表示の同等性:** 台帳から描く2Dで、現在の2Dと同じ読みやすさを保つ。

## 13. 採用しない案

- **セルのまま敷地を作る:** セルが水平な板で、建物ごとの敷地とずれる。街の立体造形に向かない。
- **ボクセル／完全な3Dメッシュ:** 2Dの編集と噛み合わず、保存も大きい（`ce-terrain-grading-layer.md` §8）。
- **地面を制約付き三角形分割で敷地に完全に合わせる:** 前の設計で重さが実証された。擁壁のスカートで継ぎ目を隠す。
- **three-mesh-bvh で地面を当てる:** 高さ場は格子の走査で正確かつ軽く当てられる。依存と構築時間が増える。
- **建物ごとに別のメッシュを作る:** 2,000棟で描画呼び出しが膨らむ。インスタンスと結合メッシュで抑える。

## 14. F0 の結果（2026-11-02）

### 14.1 足跡と正面

正本は `src/buildings/placementContract.ts`。

- 足跡はモデルのローカルな軸平行箱である。幅は X、奥行きは Z。`studyBounds` の箱も、`bvInstances` が焼いた原型の `bounds` も同じ形で渡す。凹んだ平面は、この段階では箱で近似する。
- 配置位置は足跡の中心。メッシュはヨーの前に、箱の中心と底をその位置とレベルへ移す。`placementPose` がメッシュと足跡の両方の変換である。
- 正面の既定はローカル +Z。住宅・門・中庭の範囲のコメントと一致し、低品質の地中海住宅（正面が +Z、幅 5 m・奥行き 8 m 級）の箱をテストで読んだ。
- 例外は工場のコメントに軸が書いてあるものだけ。`medievalWagon`・`coveredWagon`・`nobleCarriage`・`warWagon`・`batteringRam`・`siegeTower`・`earlyFieldCannon` は +X。`st-georges-chapel` と `basilica-temple` は −X（西正面）。船は船の経路のまま（舳先 +X、回転は平面 +Y から）で、この表には入れない。
- 方位は北 0°・時計回り。`rotationFromFacing` がそれを `CityElement.rotation`（three.js の `rotation.y`、平面 +X から反時計回り）に変える。4 軸と東西南北を、three.js の行列で確かめた。

## 16. F2 の結果（2026-11-02）

道は `FreeformCity` にせず、既存の `CityTerrainLayer.ways` に置く。敷地の pad としては保存しない。読み込み時に足りない道を作り直さない。

- **坂道（`profile: "slope"`）:** 中心線を既存の `gradeRoads` に渡す。荷車は 10%、登城路は 8%。この勾配は歩行の上限以下なので、坂道自体は階段に化けない。縦断は保存した中心線から読み込みのたびに同じ手順で求める。
- **段付き（`profile: "stepped"`）:** 中心線の距離に沿う 1 次元の動的計画法。地面との切土・盛土が小さい高さを選ぶ。踊り場は最小 3 m、蹴上げ 0.17 m、踏み面 0.30 m、1 つの階段列の上りは 3 m（17 段）以内。始点と終点は踊り場にする。緩い坂は 1 つの踊り場になる。高低差が地面からの帯（±6 m）を超えるとき、または両端の敷地高さが違うときに階段が出る。端の高さは 0.17 m の格子に揃えるので、敷地のレベルとは最大で蹴上げの半分だけずれる。踊り場と階段は道に保存し、読み直しても解き直さない。地面の高さは、保存した踊り場を pad と同じ正確な水平面として読み取り時に足す。後から足した踊り場の肩（斜面）は、先の踊り場の上面を埋めない。
- **橋:** `validateWay` が `bridgeSkewPolicy` を通す。土は木造、舗装と石畳は石造。上限を超える斜角と、川の上の屈曲は拒む。道は自動では曲げない。
- **入口:** 建物の正面から最寄りの道へ、幅 2 m の段付きの道を提案する。直線、前方へ出てから曲がる線、横へ避ける線の順に試し、通るものを置く。
- **重なり:** 道の端 1.6 m を除き、敷地の上に道を引けない。新しい敷地が道に乗るときも置けない。
- **画面:** ツールは「道を描く」。クリックで頂点、最後の点の近くか Enter で確定、Backspace で 1 点戻す、右クリックと Esc で取り消し。縦断・路面・勾配・幅を選ぶ。確定した道は 2D に帯と、階段の区間は青い破線で出る。3D は既存の地面の組み立てが踊り場と階段と坂道を足す。配置中の 3D の仮表示は建物のままである。敷地を選ぶと「入口を最寄りの道へつなぐ」。道の一覧から削除できる。Undo／Redo は既存の履歴。セル標高を高さ場にする操作は、すでに描いた道を消さない。
