# 騎兵・艦隊の保有資産制約と船舶所有台帳

| 項目 | 内容 |
| --- | --- |
| 状態 | 設計提案（実装状況監査: 2026-08-14） |
| 対象 | Core military, Economy, Shipbuilding |
| 前提 | Economy と Shipbuilding は任意の組み合わせで有効化できる |

## 1. 決定

- 騎兵は国内の生きた馬・ラクダのうち、民生・商用輸送に割り当てられていない頭数を上限にする。
- 艦隊は Shipbuilding が所有する国家艦艇の海軍要員容量を上限にする。貨物容量を海軍容量へ流用しない。
- 船体（ShipHull）の生成・所有・状態遷移は引き続き Shipbuilding のみが管理する。Economy は商用船体を参照・予約するだけとする。
- 全船舶の所有状況は Shipbuilding の読み取り専用ダイアログで横断表示する。市場の船舶 Goods 在庫は実在船体ではないため、実在船体とは別区分で表示する。
- 商会・商人を実際の所有者として表示するため、ShipHull の運航市場とは独立した経済的所有者を永続化する。名称だけを表示して市場所有を偽装しない。
- 必要な資産を確保できない部隊は削除しない。既存の plannedU と同じ「予定兵力／需要」を使い、調達・繁殖・建造で資産が利用可能になった分だけ現役化する。

この方針により、火器不足時と同じく、保有物が無いのに部隊だけが常設される状態をなくしつつ、需要を失わせない。

## 2. 現在の実装状況

| 領域 | 状態 | 確認した実装 | 不足している接続 |
| --- | --- | --- | --- |
| 馬・ラクダの生体個体群 | 実装済み | faunaPopulation.ts と husbandry.ts がセルごとの家畜頭数を維持し、Horses / Camels Goods もある | 国家・市場別の利用可能頭数を算出していない |
| 騎兵の馬需要 | 部分実装 | faunaPopulation.ts は騎乗型連隊の人数を馬・ラクダの非市場需要へ加える | 需要は個体群維持のシグナルだけで、騎兵編成を制限しない。混成連隊では regiment.type の判定が取りこぼす可能性がある |
| 商用の曳獣 | 部分実装 | 荷馬隊・荷車・荷馬車には必要頭数があり、キャラバンは馬を既定の曳獣として扱う | 車両・運行時に実際の家畜を予約しない。現在の需要は全市場への平均配分である |
| 商用陸上・河川輸送資産 | 実装済み | MerchantTransportLedger が市場ごとの車両・艀の available / reserved / inTransit / maintenance を保持する | 曳獣の状態を同じ台帳へ反映しない |
| 商用海運の実在船体 | 実装済み | Economy は Shipbuilding の市場所有 ShipHull をスナップショットで参照し、出航時に予約、到着・喪失時に返却する | 全市場・全所有者を横断する表示がない |
| 造船所の実在船体 | 実装済み | Shipbuilding は国家・市場所有の ShipHull を完成時に作成し、docked / voyage / cargo / maintenance を管理する | 国家所有船を艦隊兵力へ割り当てない |
| 余剰造船の船舶 Goods | 実装済み | 余剰の商業造船は市場の Ships Good 在庫を増やす | 在庫は未所有の売買可能品であり ShipHull ではない。この区別を UI で明示していない |
| 艦隊 | 未接続 | Core military は港から fleet を生成し、Shipbuilding 完成艦は navalTechBonus.ts を通じて品質ボーナスを与える | 艦隊人数・隻数が国家所有の船体数・能力で上限化されない |
| 商会・商人の資産所有 | 未実装 | MerchantOrganization と市場の merchant entries は存在する | 船体との所有リンクは無く、現状の市場所有を商会・商人所有として数えることはできない |
| 既存 UI | 部分実装 | Market Overview の Transport assets タブは一市場の資産を、Shipyards Overview は造船所ごとの進捗・完成数を表示する | 国家・市場・商会・商人をまたぐ船舶所有台帳がない |

docs/plan/merchant-transport-asset-ledger.md と docs/plan/shipbuilding-ships-good-bridge.md には未実装と読める古い記述がある。今回の設計では、上表のとおり現行ソースを正とする。

## 3. 用語と境界

| 用語 | 意味 |
| --- | --- |
| 生体在庫 | Fauna / husbandry が維持する生きた馬・ラクダ。市場 Goods の在庫とは別物 |
| 利用可能な乗用・曳用家畜 | 生体在庫から民生保留分と既存の商用予約分を除いた、軍・輸送に新規配分できる頭数 |
| 配分 | 家畜個体を追跡せず、国家軍・市場の輸送資産へ集計頭数を予約すること |
| 実在船体 | Shipbuilding の個別 ShipHull。必ず一つの国家または市場に属する |
| 船舶 Goods 在庫 | 余剰造船により市場へ入る、まだ所有者を持たない売買用の船舶 |
| 国家海軍プール | 一国家が海軍へ割り当てた国家所有船体の集合。連隊 ID には結び付けない |
| 経済的所有者 | 実在船体の収益・所有数を受け取る State / Market / MerchantOrganization / Merchant。運航市場とは別に保持する |

個別の馬を作らず集計配分とするのは、Fauna が個体 ID を持たないためである。一方、船は既に個別 ID を持つため、同じ粒度へ落とさない。

## 4. 騎兵と輸送家畜

### 4.1 利用可能頭数

Economy に「家畜利用可能量」投影を追加する。これは新しい生産源や市場在庫を作らず、次を一貫して算出する読み取りモデルである。

1. 国家領内セルの domesticated Horses / Camels を合計する。
2. 市場の陸上輸送資産に必要な曳獣を、市場単位で先に配分する。
3. 飼育・繁殖・生活用の民生保留量を残す。
4. 残りを国家軍の騎兵・騎駱兵へ配分する。

馬が民生・輸送に広く使われる前提は、民生保留量と市場の既存輸送資産への先行配分で表現する。初期生成では、家畜頭数と輸送資産を同じ基準から作り、平時の通常国家が不必要に全騎兵を失わない係数を採用する。これは「全国家を unstocked にする」仕様ではない。

曳獣必要数は、現在 LAND_TRANSPORTS と transport-asset blueprints が持つ requiredDraftAnimals を唯一の定義にする。これら二つの表に数値差があるため、実装時に共有定義へ統合する。車両完成後に曳獣を確保できない場合、車両は消えず awaitingDraft として待機し、利用可能な輸送力だけをキャラバン選択に渡す。

### 4.2 軍への反映

騎乗ユニットは、そのユニット定義を基準に数える。連隊全体の優勢種別で判定せず、混成連隊の u の各ユニットを集計する。

軍事生成・再調整時の順序は以下とする。

1. 人口・地形・軍事設定から騎兵の希望編成を求める。
2. 国家の利用可能な乗用家畜を照会する。
3. 充足できる分を u に置き、超過分を plannedU に残す。
4. 時間進行で繁殖、輸入、輸送配分の解放により余力が出たら、plannedU から現役へ移す。

Economy が無効な場合は、既存の無制限騎兵生成を維持する。任意拡張機能を必須化しないためである。

## 5. 国家艦隊と完成船体

### 5.1 所有権と能力

Shipbuilding の ShipHull を唯一の船体台帳として維持する。市場所有船体は商用輸送専用であり、国家艦隊へ転用しない。国家所有船体だけを国家海軍プールに配分できる。

各 ShipClassDefinition に cargo と別の navalCrewCapacity を追加する。貨物スロットは交易のための単位であり、艦隊の兵員・艦船能力へ転用してはならない。初期値はゲームバランス用の明示的な表として定め、テストで船級ごとの合計を検証する。

国家海軍プールは、国家 ID と船体 ID の対応だけを永続化する。軍の連隊 ID は全軍再生成で変わるため、船体を特定連隊へ直接結び付けない。軍事生成は、プールにある稼働可能な国家所有船体の navalCrewCapacity 合計を fleet の上限として使い、希望編成を超過する分を plannedU.fleet に置く。

### 5.2 状態遷移

- Shipyard 完成時、国家所有船体は未配分の国家海軍プール候補になる。
- 配分済み船体が maintenance の間は海軍上限に寄与しない。docked / voyage の扱いは部隊の稼働モデルと一体で決め、同じ船体を二重計上しない。
- Shipbuilding 無効時は既存の艦隊生成を維持する。Shipbuilding 有効かつ国家船体がゼロのときだけ、艦隊は予定兵力だけを残す。
- 現在の navalTechBonus は完成艦による品質・技術の効果として残し、保有量上限の代替にはしない。

Core military と Shipbuilding の接続は、直接 import ではなく、状態スナップショットを問い合わせる狭いイベント／拡張 API 境界にする。これにより動的拡張機能も host のモジュールグラフへ依存しない。

## 6. 船舶所有台帳ダイアログ

Shipbuilding に読み取り専用の Vessel assets ダイアログを追加する。Shipyards Overview は造船所の作業画面として残し、所有台帳と混ぜない。

現状の ShipHull の直接所有者は state または market だけで、MerchantOrganization と merchant は船体所有と結び付いていない。このまま商会・商人名を補助表示しても、所有数を確認するという要件を満たさない。そのため Shipbuilding の hull lifecycle は変更せず、Economy の永続 slice に「船体 ID → 経済的所有者」を追加する。市場は運航・予約の責務を持ち続け、商会・商人は所有・収益の責務を持つ。

初期割当は、国家造船を state、商業造船を market とする。商会・商人への移転または購入は別操作として明示し、MerchantOrganization や市場商人リストがあるだけで自動的に船の所有者とみなさない。この所有記録は一隻につき一人（または一団体）とし、共有持分はこの段階では扱わない。

表示は次の三つを明確に分離する。

| 区分 | 所有者の表示 | データの正本 | 主な列 |
| --- | --- | --- | --- |
| 国家所有の実在船体 | 国家 | Shipbuilding ShipHull | 母港、船級、docked / voyage / maintenance、国家海軍プールへの配分 |
| 民間所有の実在船体 | 市場（港）・商会・商人 | Shipbuilding ShipHull + Economy の経済的所有者記録 | 母港、船級、docked / voyage / cargo / maintenance、運航市場、商用予約 |
| 未所有の船舶 Goods | 市場在庫 | Economy market goods | 船級、在庫数、販売可能数 |

全表示の集約キーは、経済的所有者種別・所有者・運航市場・母港・船級・状態とする。詳細を開けば個別 ShipHull.id、法的な状態、運航市場、経済的所有者を確認できる。

Shipbuilding は自身の hull snapshot を直接読む。市場名・商会・商人の経済的所有者および船舶 Goods 在庫は Economy へ読み取り要求を送り、スナップショットで受け取る。既存の merchant-hull snapshot / reservation と同様に、両拡張機能間で直接 import は行わない。

## 7. 実装順序

1. **共通定義の整理** — 陸上輸送の曳獣必要数を一箇所へ集約し、国家別・市場別の生体家畜集計を追加する。挙動は変えない。
2. **商用曳獣配分** — MerchantTransportLedger に車両の必要頭数と待機状態を反映し、キャラバン予約・解放へ接続する。
3. **騎兵上限** — 家畜利用可能量投影を軍事生成・時間進行へ接続し、超過騎兵を plannedU として維持する。
4. **国家海軍プール** — navalCrewCapacity、国家船体のプール配分、Shipbuilding からの能力スナップショットを追加する。
5. **艦隊上限** — Core military の fleet を国家海軍プールで制限し、超過分を plannedU.fleet に置く。
6. **民間所有の記録と Vessel assets UI** — Economy に実在船体の経済的所有者記録を追加し、Shipbuilding の所有台帳ダイアログと市場・商会・商人・Goods 在庫スナップショットを追加する。
7. **保存データ移行** — 既存セーブでは初回 reconcile 時に家畜配分と国家海軍プールを導出する。軍連隊 ID を保存キーにしない。

UI は第 6 段階を先行して実装してもよいが、状態・所有権の定義は第 1 / 4 段階と共有する。

## 8. 受入条件とテスト

- 国家の現役騎兵の必要頭数は、当該国家に配分された乗用家畜を超えない。
- 市場の稼働中・予約中の陸上輸送資産の必要頭数は、その市場の配分済み曳獣を超えない。
- 家畜配分は負数にならず、軍・市場・民生保留の合計が生体在庫を超えない。
- plannedU の騎兵・艦隊は資産が増えたときのみ現役化し、資産不足で需要が消えない。
- 国家艦隊の現役 crew は、国家海軍プールの稼働可能な navalCrewCapacity 合計を超えない。
- 一つの ShipHull は一つの経済的所有者と一つの用途だけを持つ。運航市場を維持したまま、市場の cargo 船体を国家艦隊へ配分しない。
- 商会・商人の所有隻数は、明示的な経済的所有者記録からだけ集計する。市場との関係や役職から推測しない。
- 実在船体と市場の船舶 Goods 在庫を合算して実在隻数として表示しない。
- Shipbuilding 無効時と Economy 無効時は、それぞれ既存のフォールバック挙動を維持する。
- 既存の市場船体予約テスト、貨物中の市場船体が通常航海収益を得ないテスト、造船完成イベントのテストを回帰対象に含める。

## 9. 非目標

- 個別の馬・ラクダの ID、売買履歴、血統を導入しない。
- 市場船体を徴発して国家艦隊へ移す制度は導入しない。
- 余剰造船で生まれる市場の船舶 Goods を自動的に ShipHull 化しない。
- 既存の商用船体予約・返却、国家船体の技術ボーナス、Shipyard queue の完成処理を置き換えない。
