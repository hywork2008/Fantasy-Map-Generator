# メッシュなしCE 機能同等化のロードマップ

作成日: 2026-11-09  
状態: P0・P0b・P1・P2a・P2b完了（2026-11-09、[記録](../analytics/ce-meshless-parity-p0-20261109.md)）。P2aで市壁・塔・門・橋、P2bで道路を旧CEの部品で描く。住宅の描画はP3で外観と合わせて行う。P0bの残り2件（海岸・起伏）はP5・P8で扱う。次はP2c（水面・地形・樹木）。門のバービカンは後でオプションとして作る。 P2cの前に、単独起動の敷地をseedで変える作業（川の向き・位置・湾曲、外部道路の本数と方位）と、Generate cityを押すたびにseedを引き直す作業を入れた（2026-11-09）。入力欄でseedを打った時はそのseedを再現する。 続けて道路骨格を放射状から枝分かれ型に改めた：中心まで通す幹線は外部道路と橋の先だけとし、分岐の道は最寄りの既存道路へT字で接続する副道（幅は幹線の0.6倍）とした（2026-11-09）。 P2c-1（平坦な敷地の水面・岸を旧CEの部品で描く）完了（2026-11-09）。P2c-2（樹木の詳細度と季節）は、確かめる樹木を生成するP6（墓地・公園）・P7（森林・景観）で行う。P3a（住宅の壁・屋根・色を旧CEの量塊の規則と`createCityMassing`で描く）完了（2026-11-09）。P3b（高さの変化・高さの上限・建物パターン・外観の型）完了（2026-11-09、`vector-urban-v10`）。P2a〜P3aのブラウザーでの目視も同日に済ませた。建物パターンのlegacy、人口圧による階数の引き上げ、外観の型を選ぶ操作は未対応として残す。P4を区切りに分け、P4a（市壁の形状6種・辺数・材質）を完了した（2026-11-09）。P4b（二重・取り壊し・内側先行）完了（2026-11-09、`vector-urban-v12`）。P4c（稜堡式の町）は単独起動・内陸の敷地で完了（2026-11-09）。川・海岸が工事を横切る稜堡式の町（水門）はP5、FMGの都市の稜堡式の町は固定道路の扱いを決めてから行う。次はP4c-2（通常の市壁の堀）、続いてP4d（町割り4種）、P4e（城・城塞と堀）。起伏の地形はP8で扱う。  
関係する設計: [メッシュなしCE設計](ce-meshless-city-editor.md)、[公開判断](ce-meshless-release-acceptance.md)、[成長型の都市生成](ce-meshless-growth-generation.md)、[街区構造の大規模化](ce-meshless-block-fabric-scaling.md)

## 1. 目的

メッシュなしCEは、メッシュありCEとの違いを「道・川・壁・街区がグリッド（セル）に縛られるか否か」だけにする。都市のランダム生成、生成される施設・景観の種類、3D表示、編集、保存・出力は同等の機能を持たせる。本書は、その同等性を定義し、到達までの段階と受入条件を定める。

## 2. 既存の設計書の点検結果（2026-11-09）

[メッシュなしCE設計](ce-meshless-city-editor.md)（以下、設計）と[公開判断](ce-meshless-release-acceptance.md)（以下、受入）を点検した。設計に従ってM0〜M9を完了しても、メッシュありと同等の機能は得られない。理由は次の4点である。

| # | 点 | 根拠 |
| --- | --- | --- |
| 1 | ランダム生成の同等性が要件になっていない | 設計§12の「新規・FMG起動・生成設定」は「未対応項目の表示」を対応とし、未対応の設定を選べなくすることを認めている。M2〜M9の完了条件は曲線・接続・領域・容量などの契約で、「同じ設定から同じ種類の都市が生成されること」を含まない |
| 2 | 城・港・景観の受入が、生成ではなく変換と手置きによる | 受入の「詳細機能」は、旧CEで生成した防御・港・森林の計画を変換して受け入れたものである。メッシュなしのランダム生成がそれらを作るかは問われていない |
| 3 | 3D表示が共有されていない | 設計§13.1は描画契約を共有し、旧文書をadapterで同じ契約へ写す方針だった。実装はメッシュなし専用の`renderers/vector/scene3d.ts`で、旧CEの`renderers/cityView.ts`が使う`city3d`の部品（市壁・橋・道路・建物の詳細・施設・農地・森林・修道院・桟橋・遠景の住宅・井戸・樹木の季節など）を使っていない。受入の「2D・3D表示 verified」は、同じ採用形状を描くことの確認だけである |
| 4 | 「verified」の意味が同等性ではない | 受入の対応表（[M9 coverage](data/ce-meshless-m9-coverage.json)）の`verified`は「代表入力で契約を確認した」意味である。旧CEと同じ機能が使えることを意味しない |

### 2.1 現状の差（点検で確かめた範囲）

ランダム生成の入力:

- 旧CEは`GenerationSettings`と`SiteConfig`で次を受け取る。
  - 市壁: 形状6種、多角形の辺数、一重・二重・取り壊し、内側先行、材質、海側の扱い。
  - 稜堡式の町: 外堡・乾堀／水堀・街路の型。
  - 町割り: organic・circulade・bram・classic。
  - 施設の有無: 城塞・広場・寺院・港・貧民街。
  - 海岸・川: 海岸線4種、川6種。
  - 地形: 起伏、標高プリセット・地形テンプレート、段丘。
  - 城・堀: 城の設定、堀の有無。
  - 建物: 建物パターン、高さの方針・上限、住宅の外観。
  - その他: 森林の設定、埋葬文化、時代、街道の入口方位、近郊の成長、要塞・地形の各モード。
- メッシュなしの骨格の設定（`VectorGenerationSettings`）は、市壁（なし・長方形・楕円）、道路幅、離隔、街道数だけである。
- メッシュなしの施設住宅の設定（`VectorUrbanSettings`）は、方式・人口・住宅モデル（`house:mediterranean`の1種）・小路・建築率である。
- 旧CEの設定から読むのは、時代・人口・FMGの都市情報・広場と寺院（`seedVectorCivicCentre`）だけである。

ランダム生成が作るもの:

| 要素 | 旧CE | メッシュなし |
| --- | --- | --- |
| 市壁・門・橋・道路・街区・住宅 | 生成する | 生成する |
| 広場・寺院・墓地 | 生成する | 広場・寺院を予約し、墓地を付ける（形と規則は別実装） |
| 二重市壁・稜堡・堀 | 生成する | 編集で作れる。生成しない |
| 城・城塞 | 生成する | 手置きのみ。生成しない |
| 港・船・荷役・倉庫 | 生成する | 手置きと旧文書の変換のみ |
| 市場・同業組合の施設・門前の広場と宿・目印となる建物 | 生成する | 施設モードの職業施設はある。旧CEの配置規則は使っていない |
| 経済的な地区・貧民街 | 生成する | 生成しない |
| 農地・農家の小屋・街道沿いの農家・郊外の土地利用 | 生成する | 手置きの農地領域のみ |
| 森林・公園・井戸 | 生成する | 森林は手置きの領域内で再生成できる。自動の配置はしない |
| 修道院・渡し場・河川港・段丘 | 生成する | 生成しない |
| 住宅の外観（文化・時代別）・高さの変化 | 生成する | 1種の住宅モデル、時代の標準階数のみ |

3D表示: 旧CEは`city3d`の部品で市壁・橋・道路・建物の詳細・施設・農地・森林・修道院・桟橋・遠景の住宅・井戸・樹木の季節を描く。メッシュなしは独自のシーンで、BVモデルの配置、船・クレーン・荷役、景観の樹木、地形を描く。上記の多くを描かない。

上の表は、型・設定・生成の入口・3Dの依存を読んで確かめた範囲である。項目ごとの正確な状態はP0の対応表で確定する。

## 3. 同等性の定義

1. **同じ入力から同じ種類の都市**: 旧CEと同じ`GenerationSettings`、またはFMGの同じ都市情報を受け取り、旧CEが生成するすべての要素の種類を生成する。要素の位置や形の一致は求めない。比べるのは次である。
   - 要素の有無と数。
   - 寸法・面積。
   - 人口と容量。
   - 接続（門・橋・接道）。
   - 時代・技術・文化の条件。
2. **同じ見た目の部品**: 2D・3Dは旧CEと同じ描画部品（`city3d`、BV資産、外観の規則）を使う。メッシュなしの採用形状を、共有の描画契約へ写して描く。
3. **同じ操作**: 生成段階の前後移動、選択・インスペクター、レイヤー・固定、Undo／Redo、保存・共有・出力が、すべての要素に対して使える。
4. **違ってよいもの**: セルに由来する制約と見た目である。セルの辺に沿う道・壁、セル単位の地区の塗り、ヘックスやボロノイの格子線、セル数に基づく設定（例「市壁の外に約12セル」）が該当する。セル数で決めていた量は、メートルや面積で置き換える。
5. **例外の扱い**: 同等にしない要素は、P0の対応表に理由と合意日を記録した場合だけ認める。未記録の未対応は、同等化の未完了として扱う。

## 4. 方針

- **旧CEの生成規則を再利用する**: 外周住宅で`buildOrganicBlocks`を街路街区の実輪郭へ渡した方式（[設計§8.2](ce-meshless-city-editor.md#82-街区小路)）を、他の生成器にも広げる。
  - 対象: 城・港・市場・墓地・農地・森林などの生成器。
  - `Face`やセルIDへの依存を、輪郭・境界条件・用途・seedなどの入力型へ絞る。
  - 新方式独自の規則は作らない。セルを模した仮セルのadapterにはしない（設計§1の方針を維持）。
- **3Dは描画契約を共有する**: 旧CEの`city3d`の部品が読む入力（町の完成形状）を、メッシュなしの採用形状から作る。部品の側にメッシュなしの分岐を入れない。メッシュなし専用の`scene3d.ts`は、共有の部品が揃った時点で置き換える。
- **生成段階は旧CEの段階に対応づける**: 番号は合わせない（設計§9）。旧CEで段階として見えていた工程（市壁、城、港、施設、住宅、農地、森林など）は、メッシュなしでも段階として前後移動できるようにする。
- **固定ケースで比べる**: 同じ設定・同じseedの旧CEとメッシュなしを生成し、§3.1の比較項目を並べる。多数seedの探索はしない。

## 5. 段階

| 段階 | 内容 | 完了条件 |
| --- | --- | --- |
| P0 | 対応表と比較の仕組み | 旧CEの全設定項目、生成要素、3Dの部品、編集操作を1行ずつ列挙し、状態（同等・手置きのみ・変換のみ・未対応）を記録する（`data/ce-meshless-parity.json`）。比較する固定ケースは6〜10件。設定と要素の組を網羅するよう選ぶ。旧CEとメッシュなしを同じ入力で生成し、§3.1の項目を並べる比較スクリプトを作る |
| P0b | P0で見つかった生成の失敗の修正 | 固定ケース8件のすべてで、メッシュなしの生成が成功する。2026-11-09に6件まで成功させた（広場・寺院を人口に合わせる、小さい敷地の大きさの補正、海岸の閉じ方、川の端の折り返し）。残る2件は合成の都市情報を経る入力の海岸（`gate-access`）と、橋のない道路（`unbridged-road`）である |
| P1 | 設定の受け渡し | メッシュなしが`GenerationSettings`と`SiteConfig`の全項目を受け取り、文書の生成設定に保存する。未対応の項目は、P0の表の行と理由を画面に示す。黙って無視しない。2026-11-09完了: `context.requestedSettings`に保存し、生成パネルに未対応の設定を示す。項目名は設定のIDのまま |
| P2 | 3D表示の共有 | メッシュなしの採用形状から共有の描画契約を作り、旧CEの`city3d`の部品で描く。対象は市壁・門・橋・道路・住宅の外観と詳細・施設・遠景の住宅・樹木と季節・地形・水面。選択の論理IDとローカル原点（M9）を保つ。既存の固定ケースで、旧CEと同じ部品が描かれることを確かめる |
| P3 | 住宅の外観と高さ | 文化・時代別の住宅の外観、高さの方針・上限、建物パターンを旧CEの規則で決める。住戸容量の計算は外観と整合させる |
| P4 | 市壁・防御の生成 | 市壁の形状6種と辺数、二重・取り壊し・内側先行、材質、海側、稜堡式の町（外堡・堀・街路の型）、町割り4種、城・城塞の配置と堀を生成する。時代・技術の条件と橋の規約（`bridgeSkewPolicy`）を守る |
| P5 | 水辺の生成 | 海岸線4種、川の型6種、海側の市壁、港（岸壁・船・荷役・クレーン・倉庫）、河川港、渡し場を生成する |
| P6 | 都心と施設の生成 | 広場・市場、寺院・修道院、文化別の墓地、同業組合の施設、門前の広場と宿、目印となる建物、経済的な地区、貧民街を旧CEの規則で生成する。墓地・公園の樹木は旧CEの詳細度の切り替え（`openSpaceTreeLod`）と季節で描く（P2c-2） |
| P7 | 郊外と景観の生成 | 農地・農家の小屋・街道沿いの農家、郊外の土地利用、森林の設定による自動配置、公園、井戸を生成する。森林は旧CEの`forestMeshes`と季節で描く（P2c-2） |
| P8 | 地形 | 起伏、標高プリセット、地形テンプレート、段丘、道路の勾配を生成と3Dに反映する。急な造成境界の鉛直誤差（受入の未受入項目）もここで扱う |
| P9 | 要塞・地形の各モードと残り | 旧CEの`fort`・`terrain`モード、街道の入口方位、近郊の成長など、P0の表に残った行を扱う |
| P10 | 同等性の受入 | P0の固定ケースのすべてで、§3.1の比較項目を満たす。表の全行が「同等」か、合意した例外である |

順序の考え方:

- P2・P3を先に置く。3D表示はすべての生成要素の確認手段で、後の段階の受入が3Dで目視できるようにするため。
- P4〜P7は互いに独立に近い。旧CEの生成器を再利用する範囲ごとに分けた。依存は「市壁→城」「水辺→港の荷役」「施設→市場」のように段階の内側に収めた。
- 各段階は、生成アルゴリズムの版を上げる（設計§11.2）。保存済み文書は保存形状のまま表示し、recipe共有で旧版の結果を新版で再現したものとして扱わない。

## 6. 各段階の共通の進め方

1. P0の対応表で、その段階の行の旧CE側の生成器と、セル・`Face`への依存箇所を特定する。
2. 依存を入力型へ絞る。旧CE側の呼び出しは、元の動作を変えない（旧CEの関連テストと、固定ケースの出力の一致で確かめる）。
3. メッシュなしの生成段階から呼び、採用形状・所有権・接続を文書へ保存する。
4. 2D・3D（P2以降は共有部品）で描き、選択・インスペクター・固定・Undoを通す。
5. 比較スクリプトで、旧CEとの§3.1の項目を記録する（`docs/analytics/`）。

## 7. 受入

- 公開判断（[受入](ce-meshless-release-acceptance.md)）の正式移行条件に、本書のP10を加える。
- 対応表（M9 coverage）の`verified`は契約の確認であり、同等性の判定には本書の`data/ce-meshless-parity.json`を使う。
- 性能の受入（[街区構造の大規模化](ce-meshless-block-fabric-scaling.md)のS4）は2026-11-09に完了とした。同等化で生成器が増えた後の生成時間は、P10で固定ケースを測り直す。

## 8. 既存の設計への影響

- 設計§12の表は、本書の対応表で置き換える。「未対応項目の表示」は、同等化が終わるまでの一時的な扱いとする。
- 設計§13.1の描画契約の共有は、P2で実施する。
- 成長型の都市生成（GM段階）と街区構造の大規模化は、本書と並行して進められる。どちらも本書の生成要素を後から受け入れられる契約を保つ。

## 9. P0の結果（2026-11-09）

- 対応表（[data/ce-meshless-parity.json](data/ce-meshless-parity.json)）は127行である。
  - 内訳: 同等15、部分的23、手置きのみ8、変換のみ4、未対応73、セル固有で対象外4。
- 固定ケース（[data/ce-meshless-parity-cases.json](data/ce-meshless-parity-cases.json)）は8件である。
  - 両方式とも生成できたのは3件だった。3件とも、旧CEにある市場・公園・農地がメッシュなしになかった。
  - 二重市壁・稜堡式の町・circuladeの町割りも生成されなかった。

## 10. 未決事項

- P0の固定ケースは合成入力（旧CEの`defaultGenerationSettings`に設定を重ねたもの）で8件とした。FMGの実都市のケースは、P1でFMGからの起動を扱うときに加えるかを決める。
- 旧CEとの比較で、数・面積の差の許容幅をどう決めるか。セルの粗さに由来する差は、P0の計測で基準を作ってから決める。
- 旧CEの生成器のうち、セルの隣接関係そのものを使うもの（例: セルの塗りで決める地区）の置き換え方。P0で一覧にし、行ごとに決める。
