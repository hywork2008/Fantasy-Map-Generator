# CE Friary（托鉢修道院）の3D表示

作成: 2026-10-21

## 調査結果

BVの`33-friariesModels.ts`には托鉢修道院の固定一式モデルが存在する。一方、CEの生成・SVG表示は`Monastery`の個別の建物ポリゴン、屋根の棟線、回廊、中庭、菜園、樹木、囲壁、門、井戸を利用している。CEの3D処理にはこの修道院を組み立てる経路がなく、`collectWellSites`により井戸だけが表示されていた。

不足しているのは、単純な新規建物モデルよりも、CEの敷地に合わせた組み立てと3Dシーンへの接続である。固定のBVモデルを敷地全体へ引き伸ばすと、教会・生活棟・門・中庭がSVGの位置に一致しない。

## 実装

- `src/buildings/monasteries/friary.ts`をBVとCEの共通組み立て処理とする。BVの固定一式モデルを、CEの`fitMonastery`による固定プレビュー敷地から同じ処理で作るモデルへ更新する。
- CEは`fabric.aerialLandmarks.monasteries`のうち`kind === "friary"`のみを対象とする。生成方法・出現条件・保存形式は変更しない。
- 建物の外形と屋根の向きには生成済みの`polygon`と`ridge`を使う。身廊幅10mを基準に棟高と柱の寸法を敷地の生成倍率へ合わせる。教会屋根はスレート、生活棟は瓦の模式表現とする。
- 小鐘楼は大きな石造塔へ置き換えず、屋根上の木造支柱、梁、露出した鐘、小屋根で表す。
- 回廊は生成済みの外周・中庭の輪郭を使い、穴のある床、内周の柱、4辺の片流れ屋根を作る。中庭を屋根で塞がない。
- 門楼には歩行者用の通路を残す。囲壁は生成済みの**開いた**折れ線を使い、末尾と先頭を結んで入口を塞がない。
- 庭・薬草畑・果樹・井戸も同じ位置へ置く。井戸は共通BVモデルを使い、Friary以外の都市井戸とは所有を分け、既存の井戸描画から重複を除く。
- 傾斜地では敷地全体を同じ基礎標高へ載せ、敷地形状の石造基壇で低い地面との間を埋める。回廊・教会・井戸の高さ関係を維持する。
- `createTownFriaries`は完成した模式モデルを頂点色付きの1メッシュへ統合し、元モデルのリソースを解放する。修道院データと地形が変わった時に再構築し、旧メッシュと終了時のリソースを解放する。

## 検証

- CEの教会外形と屋根、回廊の開口、屋根上に露出した鐘、囲壁・門楼の通路を検証する。
- 回転・移動・縮小した敷地を使い、固定一式モデルで置換していないことを確認する。
- 基礎の接地、描画の統合、リソースの一度だけの解放、井戸の重複除去を検証する。
- 既存の修道院配置、BVモデル契約、鐘の構造クリアランスの関連テストを実行する。
- BVのモデルと、CEの生成済みFriaryデータを使ったブラウザ表示・更新・終了を確認する。

## 範囲

今回はFriaryを対象とする。Abbey・Orthodox monasteryをFriaryの建築で代用しない。室内・精密な宗派別意匠は含めず、建築は模式的な立体表現とする。傾斜地の基壇は単一水平面であり、段状造成の詳細は表現しない。
