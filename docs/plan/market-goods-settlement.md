# 町の産物の委託と、家計が市場から取る品の代金（2026-11-06）

## 1. 背景

[cooper-funds-20261106.md](../analytics/cooper-funds-20261106.md)で、次の2つが分かった。

1. 町（Burg）の産物は、市場が金庫の現金で買い取れる分しか売れない。売れ残りは次の周期に持ち越されず、消える。全体で値打ちの約4分の3が消えている。ビールは、作った量がエールの需要の8〜9割あるのに、飲まれた量は3〜4割である。
2. 家計は、ビール・ワイン・チーズなどの飲み物と食品を、代金を払わずに市場の在庫から取る（`drawHouseholdDemand`）。町の家計の支出は、自分の町の金庫（`burg.treasury`）にまとめて入る（`spendUrbanHouseholdSurplus`）。市場は町から現金で買い取るが、家計が取った分の代金を受け取らない。

## 2. 方針

2つを合わせて直す（ユーザーの決定、2026-11-06）。どちらもSimulation設定（市場の設定）で切り替えられる。

### 2.1 E: 家計が市場から取る品の代金（設定`householdGoodsPayment`）

| 値 | 動き |
| --- | --- |
| `free`（既定） | これまでどおり、代金を払わずに取る。取った品が町からの預かりなら、その分は町に払わずに預かりから外す（§2.2）。 |
| `pay` | 家計は、市場の在庫から取る飲み物と食品の代金を、市場の値段で市場の金庫に払う。払えた分だけ取る。 |

既定は、S2の結果（§3.1）を見て`free`にした（ユーザーの決定、2026-11-06）。今の町の家計の収入では、`pay`にするとエールの大部分が飲まれない。

- 対象: `settleFoodProcessingHouseholds`が家計に配る品。牛乳・チーズ・ぶどう・レーズン・ワイン・りんご・なし・シードル・ペリー・ビール。
- 払う人: 市場の人（町の人と農村の人、`getMarketPeople`と同じ数え方）で代金を分ける。エールは町の人だけで分ける（町の需要だけなので）。
  - 町の分は、それぞれの町の家計（`debitHouseholdWealth`）から、蓄え（`URBAN_HOUSEHOLD_BUFFER_MONTHS`）を超える分の範囲で払う（`getUrbanHouseholdSpendable`）。
  - 農村の分は、市場の農村の家計（`debitRuralHouseholdWealth`）から、財布の毎月5%（`RURAL_HOUSEHOLD_TOWN_SPEND_SHARE`）の範囲で払う。
  - 上限は、主食を先に守るためである。上限の無い形（v1）では、主食を買うお金が減って町の人口が減った（[計測](../analytics/market-goods-settlement-20261106.md)§3の1）。
- 足りない時: 払えなかった分は取らない。払えなかった額を値段で割った量が、満たされない需要になる。
- 町の家計の他の支出（`spendUrbanHouseholdSurplus`）は、蓄えを超える分の20%なので、先に払った分だけ自然に減る。そこに含まれる「エール」と重なる分は、この順番で調整される。

### 2.2 A: 町の産物の委託（設定`craftSalePayment`）

| 値 | 動き |
| --- | --- |
| `consignment`（既定） | 市場は、金庫と町ごとの割り当てで払える分を、これまでどおり現金で買い取る。払えない残りも在庫に入れ、町からの預かり（委託）にする。 |
| `cash` | これまでどおり、現金で買い取れる分だけを受け取る。残りは消える。 |

- 預かりの記録: 市場の金庫に、財ごと・町ごとの預かりの量と値打ち（`craftConsigned`）を持つ。値打ちは預かった時の売り値で、町の売上税を引く前の額である。
- 売れた分: 預かりの品は在庫の中で先に売れたとみなす。毎月の生産の初め（町ごとの割り当ての前）に、預かりの量のうち在庫に残っていない分を売れた分とする。その分の値打ちを、町への未払い（`craftPayables`）に移す。
- 払い: 未払いは、市場の金庫の残高から、新しい買い取りより先に払う。払えない分は翌月に残る。払う時は、ふつうの売りと同じく取引（Deal）として記録し、売上税は国に入る。
- 傷み・盗み・輸出で在庫から出た分も、売れた分に数える。在庫の中で預かりと買い取った品を区別しないためである。
- 組合の取り分: ふつうの売りでは、利幅の一部が組合の金庫に入る。委託の払いでは入れず、全額を町の金庫に入れる。
- 市場の解散: 預かりと未払いは、吸収する市場に引き継ぐ。
- 消えた町への未払いは、払わずに消す。
- 家計が代金を払わずに取った分（`householdGoodsPayment: "free"`）: 家計が在庫から取る時に、その量を預かりから先に外す（`releaseConsignedUnpaid`）。代金が入らないので、町には払わない。外さないと、町への未払いが4年で20万〜52万に積み上がった（§3.1）。

## 3. 段階

| 段階 | 内容 |
| --- | --- |
| S1 | 設定2つ、E、A、関連テスト |
| S2 | 計測: 4枚・48か月（P1の地図）。HEADとの比較で、ビールの飲まれた量、市場の金庫、町の金庫、家計の現金、未払いの積み上がり、都市の人口を見る |
| S3 | 結果の記録、golden |

### 3.1 S2の結果（2026-11-06、[記録](../analytics/market-goods-settlement-20261106.md)）

- v1（上限なし）: エールは需要の6割前後まで飲まれたが、町の人口が12〜16%減った。
- v2（上限あり、今の実装）: 町の人口は変わらない。飲まれたエールは需要の1〜2割で、変更前（3割前後）より減った。
- Aのみ（`householdGoodsPayment: "free"`）: エールは7〜8割まで飲まれ、町の人口も変わらない。町への未払いが増え続ける（4年で20万〜52万）。
- 町の家計の収入では、エールの需要を市場の値段で買えない。
- 決定（2026-11-06）: 既定はAのみ（委託・家計は払わない）とし、家計が払わずに取った預かりの品は町に払わない。Eは設定で選べる形で残す。次に、町の家計の収入とエールの値段の釣り合いを史料と比べて調べる。
- v3（この決定の実装）: 4枚とも、エールは需要の75〜96%まで飲まれた（変更前は23〜61%）。町への未払いは積み上がらず、町の人口は変更前と−0.9%〜+0.7%の差だった。
- 収入の調査: [household-income-20261106.md](../analytics/household-income-20261106.md)。町の家計の収入は主食の割合で見て史料の日雇いと職人の間にあり、エールの値段が主食と比べて史料の約1.7倍、エールの需要（成人300 L）は余裕のある家の量だった。

## 4. 未確定事項

- 預かりの品の値打ちを、預かった時の値段にするか、売れた時の値段にするか。まずは預かった時の値段にする。
- 町の家計の収入とエール・チーズ・ワインなどの値段の釣り合い。釣り合えば、`pay`を既定に戻せるかを計る。
- 買い手のいない品の預かりが増え続ける（4年で5万〜18万の値打ち）。預かる量に上限が要るか。
