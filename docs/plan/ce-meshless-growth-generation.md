# メッシュなしCE 成長型の都市生成

作成日: 2026-11-08  
状態: 設計。GM0から着手する。  
設計元: [メッシュなしCE設計](ce-meshless-city-editor.md) §5・§7・§8・§9・§11、[街区構造の大規模化](ce-meshless-block-fabric-scaling.md)

## 1. 目的

既存CEは、円に近い外壁と市域を先に決め、その内側のセルへ建物を詰める。メッシュなしCEは道・川・壁を曲線と接続で持ち、セルに縛られないため、この順序に従う必要がない。

本書は、現実の村や街の成り立ちに近い次の順序の生成を追加する。

1. 都市の核と、そこへ集まる街道を決める。
2. 核から街道沿いに街区を増やし、人口を収容するまで市街地を広げる。
3. 市壁を作る場合は、その時点の市街地を囲む形を求め、街道との交点を門にする。
4. 市壁の後も人口が足りなければ、壁外の街道沿いに郊外を広げる。
5. 最後に郊外の街道を描画範囲の縁やFMGの道路入口まで延ばす。

市壁は真円である必要がなく、市街地の外形から決める。描画範囲（キャンバス）が足りなければ広げる。既存CEのように外縁の描き込みのためにセルを足す負荷はない。

## 2. 既存の設計との関係

### 2.1 変えないもの

- 曲線・接続・門・橋の契約（§4.2、§7）。門は壁曲線上の参照点と道路ノードの共有であり、壁を後から作っても成立する。
- 橋の斜交規約（`src/utils/bridgeSkewPolicy.ts`）。
- 既存CEの街区構造（§8.2）と、街区単位の記録・安定した街区ID・並列生成（大規模化計画のS2・S3）。
- 施設先行→残地住宅の順序（§8.3）。成長型では街区ごとにこの順序を守る。
- 採用した結果を保存し、読込・描画で解き直さないこと（§4.1）。

### 2.2 2つの生成順序

| 順序 | 用途 | 市域 | 市壁 |
| --- | --- | --- | --- |
| 壁先行（`wall-first`、現行） | 利用者がプリセットや手描きで市壁を決めた都市、壁の形を固定したい場合 | 入力として与える | 先に決め、内側を埋める |
| 成長型（`growth`、本書） | 自動生成の新規都市 | 成長の結果として決まる | 市街地の外形から後で決める |

既存文書の順序は暗黙に切り替えない。新規の自動生成で成長型を既定にするかは、GM2の受入後に決める（§11）。

## 3. 生成の流れ

| 順 | ステージID | 内容 |
| --- | --- | --- |
| 1 | `inputs` | FMG／合成入力、固定線・水域、初期キャンバス |
| 2 | `core` | 都市の核（市場・広場、渡河点、港、城・丘上）と主要街道の取付 |
| 3 | `growth` | 成長段階ごとの街道延長・街路・街区・施設・住宅。段階ごとにチェックポイントを持つ |
| 4 | `wallCircuits` | 市壁を作る段階での外形、門、水門、防御用地 |
| 5 | `suburbs` | 市壁の後の壁外成長。不要なら省略 |
| 6 | `outerRoads` | 郊外の街道を描画範囲の縁・FMG道路入口まで延長 |
| 7 | `landscape` | 農地、森林、墓地等 |
| 8 | `presentation` | 表示仕上げ |

`growth`は成長段階の数だけ内部のチェックポイントを持ち、段階表示ではその段階までの都市を表示する。市壁を作らない場合は4・5を省略する。

### 3.1 核（`core`）

FMGの`suggestedArchetype`（`crossroads`・`riverCrossing`・`harbor`・`hillTop`）と`citadel`・`plaza`・`temple`から核を決める。

- `crossroads`: 街道の交点付近の広場。
- `riverCrossing`: 橋の取付付近。橋は既存の規約で先に確定する。
- `harbor`: 岸壁・荷揚げ場の背後。
- `hillTop`: 城や教会を頂部に置き、斜面に沿って下る。

FMGの固定交差・固定道路は従来どおり保持し、核の位置を合わせるために動かさない。

### 3.2 成長段階（`growth`）

成長は段階の繰り返しで進める。各段階では次を行う。

1. **候補帯を求める。** 既存の市街地の縁から、街区の典型的な奥行（既存CEの外周住宅2列と小路幅から求める）の帯を、到達できる道路に沿って取る。水域・急斜面・保護地・固定施設・既存の市壁と防御用地は除く。
2. **候補を順位付けする。** 核からの道路距離、街道沿いか、地形（勾配・浸水）、水辺の用途条件から費用を求め、費用の低い順に採用する。街道沿いを先に伸ばし（街道沿いの帯状の市街地）、その背後を後から埋める。
3. **街路を作る。** 帯の中に、既存の道路へ接続する街路を作る（`skeletonRoutes`の空き地内の経路探索を再利用する）。街路の交差は接続ノードで明示する。
4. **街区を作る。** 帯から道路面を除いた領域を街区とし、既存CEの街区構造を適用する。
5. **施設と住宅を置く。** 施設モードでは街区ごとに施設を先に予約し、残地に住宅を置く。
6. **収容量を足す。** 必要住戸数に達したら成長を止める。

不変条件:

- 採用した街区は、以後の段階で形を変えない。後の段階の街路は既存の街区を分断しない。これにより、街区IDと街区記録が段階をまたいで安定し、段階表示で街並みが変わらない。
- 各街区は採用した段階番号（`growthStage`）を保存する。段階表示、施設の地区区分、市壁の段階、部分再生成に使う。
- 同じ入力・seedから同じ成長を作る。段階内の街区生成は並列化してよいが、結合順は段階番号と街区IDで決める。
- 最後の段階で収容量が必要数を超える場合は、既存CEの空き地の散らばり（地区ごとの抽選）を保ったまま住宅を減らし、街区は残す。

### 3.3 市壁（`wallCircuits`）

市壁を作る段階（壁の段階）は設定で決める。既定はGM2で決めるが、候補は「必要人口の一定割合に達した段階」とする。

1. 壁の段階までの市街地を和集合し、内部の小さな穴を埋める。
2. 外側へ、壁の内側の空地（壁沿いの通路）、壁厚、外側の空地を合わせた距離だけ広げる。
3. 平滑化し、閉じた曲線（市壁の有機形、§5.1）にする。凹部の深さ・曲率に上限を設け、凹凸の多すぎる壁にしない。設定で、外形を内包する楕円・長方形・正多角形への当てはめも選べるようにする（当てはめ後もプリセットとして保存し、§5.3の曲線変換ができる）。
4. 壁の実体と空地が、既存の建物・施設・固定物・保護地に重ならないことを検証する。重なる場合は広げる距離を増やし、それでも解けなければ理由を示して止める。建物を切る壁は作らない。

門と交差:

- 門は、壁と街道・主要街路の交点に置く。小路や二次的な街路が壁を越える場合は門を作らず、壁の内側の空地の手前で行き止まりにする。
- 近接した交点は、壁の外側で街道を曲げて1つの門へまとめる。門の最小間隔を設ける。FMGの`suggestedGates`は目安として使い、固定交差・固定道路は動かさない。
- 川との交点は水門とする。橋が壁に重なる場合は、既存の`bridge-wall`の検証に従い、橋か壁の位置を変える候補を示す。
- 海・湖の岸では壁を開いた曲線とし、岸で終える（§6.1の開いた防壁）。

二重市壁は、後の段階で2本目の壁を作り、外壁を`parentCircuitId`で関係づける（§5.2）。成長の段階が城壁の時代的な重なりを表す。

### 3.4 郊外（`suburbs`）と郊外の街道（`outerRoads`）

- 壁の段階の後も必要住戸数に足りなければ、壁外の街道沿いに成長を続ける。壁外の街区は内外区分を「外」として保存し、人口容量の内外集計（既存の`capacityInside`・`capacityOutside`）に使う。
- 壁外の成長は門から出る街道沿いを優先し、壁沿いの外側の空地には建てない。
- 最後に、街道を描画範囲の縁またはFMGの道路入口まで延ばす。FMGの道路入口がある場合は、その位置・向きを保つ。

## 4. 描画範囲（キャンバス）

- `frame.extentMeters`は成長に応じて広げる。座標の原点（都市の核）は動かさず、既存の要素の座標を書き換えない。
- 拡張は段階ごとに、成長の縁から余白を見込んで行う。上限は文書の検証上限と性能目標から決める。
- 合成入力・手描きの都市では、そのまま広げる。

FMGから起動した都市:

- FMGから受け取った範囲（`extentMeters`）と、不明領域（`regionalSurface.unknown`）の外の地形・水域・道路は作らない。
- 成長の縁が受け取った範囲に近づいたら、FMGへ広い範囲の入力を要求する。FMGと接続している場合（右クリックからの起動）は要求に`requiredBounds`を付けて再取得する。ファイルから読んだ入力の場合は成長を止め、必要な範囲を示して再出力を案内する。
- 再取得した入力は、元の入力の識別子とrevisionで照合する。固定交差・固定道路・水域が元の入力と変わった場合は、既存の採用結果を保ったまま診断し、勝手に合わせ直さない（§11.1）。
- 範囲を広げられない場合は、未収容人数と理由を報告する（§8.3）。

FMG側の再取得APIは本書で新設する。既存の起動経路（右クリック→CE）は維持する。

## 5. 保存

- 文書に生成順序（`wall-first`／`growth`）と成長の設定を保存する。
- 街区記録（大規模化計画S2）に`growthStage`と内外区分を持たせる。
- 市壁は通常の`VectorPath`（有機形は曲線、当てはめはプリセット）として保存し、壁の段階を由来として記録する。
- 段階表示のチェックポイントは、保存した`growthStage`と市壁の段階から求める。段階ごとに文書全体を複製して保存しない。

## 6. 施設モード

- 施設の地区区分（中心部・郊外・河岸等）を、市壁の内外ではなく成長段階と核からの距離で決める。市壁を作った後は内外区分も使う。
- 危険・悪臭を伴う施設（皮なめし等）は、後の段階・下流・壁外を優先する。
- 施設は街区を採用した時点で予約し、その街区の住宅より先に置く。

## 7. 既存コードへの影響

- `generators/vector/generation/pipeline.ts`: 市壁を市域の外接矩形から作る処理は壁先行用として残し、成長型の流れを別関数にする。壁と道路の交点から門を作る処理は共通化する。
- `generators/vector/generation/urban.ts`: 合成入力だけの市域拡張（最大1.4倍）は、成長型では使わない。
- `generators/vector/generation/routes.ts`: 空き地内の経路探索を、段階ごとの帯で使えるようにする。
- `generators/vector/geometry/`: 和集合・外側への拡張・平滑化による外形生成を追加する。
- `generators/vector/geometry/presets.ts`: 外形を内包する楕円・長方形・正多角形への当てはめを追加する。
- `components/vector/VectorGenerationPanel.ts`: 生成順序、壁の段階、壁の形（有機形／当てはめ）、外側の空地の設定。
- FMG側: 広い範囲の入力の再取得。

## 8. 段階

| 段階 | 内容 | 完了条件 |
| --- | --- | --- |
| GM0 | 合成入力で、核と街道沿いの成長段階、街区、住宅までの試作。壁なし | 1,000・5,000人で未収容0。全街区が道路へ到達できる。段階を進めても既存の街区の形が変わらない |
| GM1 | 段階表示、`growthStage`の保存、キャンバスの拡張 | 段階の前後移動で同じ都市を表示する。拡張で既存要素の座標が変わらない |
| GM2 | 市壁の外形、門、水門、二重市壁、郊外 | 壁が建物・施設・固定物を切らない。門は街道・主要街路の交点だけ。小路が壁を越えない。壁内外の容量を集計する |
| GM3 | FMG入力での核・固定交差の保持と、範囲の再取得 | 固定交差・固定道路が動かない。範囲不足は再取得するか、理由を示して止める |
| GM4 | 施設モードの成長段階による地区区分 | 施設先行・残地住宅の順序を街区ごとに守る |
| GM5 | 編集・部分再生成・受入 | 手動編集後の再生成で、編集した要素と前の段階の街区を保持する |

大規模化計画との順序: S1（2乗の処理の除去）は生成順序に依存しないため先に行う。GM0はS1の後に試作する。S2の街区記録は`growthStage`を含めて設計し、GM1と合わせて実装する。

## 9. 検証

固定入力は半径ではなく人口で指定する。

- 合成入力: 1,000・5,000・20,000人。
- FMG入力: `crossroads`・`riverCrossing`・`harbor`・`hillTop`を各1件。FMGで作る場合はSettlement patternをStandardにする（AGENTS.md）。

確認する指標:

- 市壁の囲む面積と周長の比（真円を1とした値）と、壁内の未利用地の割合。
- 壁と建物・施設・固定物の重なりが0であること。
- 門の数と、門を通らずに壁を越える道路が0であること。
- 全街区の道路への到達性。
- 段階表示で、前の段階の街区・建物が変わらないこと。
- 未収容人数、生成時間、文書長（大規模化計画の目標値）。

テストは変更範囲の関連テストだけを実行し、多数seed探索・全件テストは行わない。2 MBを超える全量出力は`docs/analytics/raw/`へ置き、SHA-256を記録する。

## 10. 採用しないもの

- 成長の途中で既存の街区を作り直して形を整えること。段階表示と安定IDが壊れる。
- 壁の形を真円・正多角形に強制すること。当てはめは選択肢として用意するが、既定は市街地の外形に従う。
- FMGの受け取り範囲外の地形・水域・道路を推測して作ること。

## 11. 未決事項

GM0・GM2の結果を見て、次を決める。

1. 新規の自動生成で成長型を既定にするか。
2. 壁の段階の既定値（必要人口に対する割合）。
3. 郊外の壁外成長を既定で許すか。
4. 外側の空地の幅の既定値と、時代による違い。

## 12. 次に進める作業

大規模化計画のS0・S1を先に進める。その後、GM0として合成入力で核と街道沿いの成長、街区、住宅までを試作し、段階ごとに既存の街区が変わらないことと、1,000・5,000人の収容を確認する。
