# CE meshless: 幾何処理の土台の作り直しによる都市生成の高速化

## 目的

CE meshless の都市生成（Generate city）を、生成の流れ（ステージの順番と役割）は変えずに、全ステージが共通で使う幾何処理の土台を作り直して速くする。

- 都市の見た目と、過去に生成したデータとの互換性は維持しなくてよい（2026-11-20 決定）。
- 幾何の規則（離隔距離、橋の角度 `src/utils/bridgeSkewPolicy.ts`、重なりの許容面積など）は維持する。変えてよいのは「同じ規則をどう判定するか」である。

## 現状（2026-11-20 計測）

### ブラウザ（人口5000、各3回の中央値、ms）

| 設定 | 合計 |
|---|---|
| medieval / compact 川無し・straight・gentle | 1915・1504・1972 |
| medieval-facilities / burgage-dense 川無し・straight・gentle | 2675・2616・4568 |

ステージ別の所要時間は CE の生成パネルの「ステージ別の所要時間」と、Developer tool の console（`[CE meshless] generation …`）で常に確認できる。

### CPU プロファイル（Node、1スレッド、seed 固定12都市、計21.9秒）

| 内訳 | 割合 |
|---|---|
| `regionBoolean`（polygon-clipping による多角形の和・差・積） | 42% |
| ガベージコレクション（多くは上の中間データ） | 14% |
| `assertVectorDocument`（文書全体の検証） | 7% |
| `reserveTanneryRow` | 7% |
| `planPerimeterRequest` | 5% |

`regionBoolean` の呼び出し元は分散している（農地 18%、ギルド 12%、施設区画 約15%、森 6.5%、区画計画 約10%、ほか20か所以上）。呼び出しは2種類に分かれる。

- **判定**: 「重なる面積が閾値を超えるか」「はみ出す面積が閾値を超えるか」だけを知るために、演算結果の多角形をすべて作っている（`regionBoolean(...).some(r => regionArea(r) > eps)` の形、50か所以上）。
- **形状**: 演算結果の形そのものが要る（農地の短冊、土地利用、到達可能な土地、森など）。

## 方針

ステージ構成の作り直しはしない。時間がステージ構成ではなく共通の部品に偏っているためである。次の段階で土台を替え、段階ごとに計測して次へ進むかを決める。

### 段階 A: 重なり・はみ出しの判定を専用の判定関数にする

- `geometry/regions.ts` に `regionsOverlap(a, b, minArea)` と `regionsExceed(a, b, minArea)`（a が b からはみ出す面積が閾値を超えるか）を置く。
- 外接矩形と輪郭の交差判定（既存の `ringSurelyApart`・`ringSurelyInside`）で、演算せずに答えが決まる場合は演算しない。決まらない場合だけ従来の演算に落とす。
- この段階では判定結果は従来と同一になる（演算しない場合も答えが同じ時に限るため）。生成結果のハッシュが変わらないことで確認する。
- 判定の形の呼び出しを、計測で時間の大きい順に置き換える。

### 段階 B: 形状の演算を速い演算に替える

- 段階 A の後に残る形状の演算を、呼び出し元ごとに次のどれかにする。
  - 凸多角形どうし・凸多角形による切り取り（短冊、帯）は凸多角形の切り取り（Sutherland–Hodgman）にする。
  - それ以外は、より速い演算ライブラリへの置き換えを候補とし、計測して決める。
- 結果の形は細部で変わり得る。

### 段階 C: 占有状況を生成全体で共有する

- 道路・水域・敷地・予約地の索引（RBush）と判定用の構造を、ステージごとに作り直さず、生成全体で1つにして配置のたびに更新する。
- 皮なめし場の路地の迂回探索（`routeAround`）の障害物判定を、共有の占有格子の表引きにする。

### 段階 D: 検証とページとの受け渡し

- 生成の途中での文書全体の検証を最後の1回にまとめる。
- ワーカーからページへの結果の受け渡しと、採用・描画の固定費（計 0.4〜0.6 秒）を見直す。

## 計測と確認

- 各段階の前後で、Node の seed 固定比較（straight・gentle 各24都市、medieval-facilities / burgage-dense、人口5000）の合計時間と、ブラウザの6設定×3回を記録する。
- 段階 A は生成結果のハッシュが前後で一致すること。段階 B 以降は生成が失敗しないことと、文書の検証が通ることを確認する。
- 関連するテストを実行する（`src/city-editor/generators/vector/generation/`）。

    - 座標は 2^25 以下の格子に丸める（倍精度で厳密に計算できる範囲）。
    - 結果は入力の正確な座標に戻す。入力の頂点に当たる格子点は元の座標に戻し、交点としてできた頂点は近くの入力の2辺の交点を浮動小数点で計算し直す。どの入力の辺にも乗らない頂点は演算の誤りとみなし、従来の演算に回す。格子のままだと、長い辺で敷地のはみ出しが検証の許容値 1e-5 m² を超えた。

    - 出力は従来の形に揃える。輪は閉じ、外形は反時計回りで穴は時計回り、各輪は最も左下の頂点から始め、穴と多角形はその点の順に並べる。
