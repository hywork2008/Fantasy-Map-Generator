# CE：森林に囲まれた都市と森林描画

作成日：2026-10-28  
状態：F0の計測・接続先調査を実施済み。森林機能の製品実装はF1から。

F0の結果：[ce-forest-f0-20261028.md](../analytics/ce-forest-f0-20261028.md)

## 1. 方針

CE で耕作地を森林へ変え、2D・3D のどちらでも森に囲まれた都市を作れるようにする。

- 森林の範囲を共通の領域データとして決める。描画品質を下げても森林面積や道路の位置は変えない。
- 2D の既定は **緑の面＋林縁の木＋内部の少量の模様**。全域を一本ずつ描く方式は詳細表示の選択肢とする。
- 3D の既定は **近景の立木＋中景の簡略樹木＋遠景の立体的な樹冠の塊**。全域に詳細モデルを並べない。
- 密度は景観の設定、品質は表示負荷の設定として独立させる。森林率を下げて負荷を調整しない。
- 既存都市にも適用でき、都市全体の再生成を必須にしない。Undo/Redo、保存、共有で再現する。

本書の数量・時間目標は実装用の制限・目標であり、森林生態の数値ではない。F0で構造的な負荷を確認したが、実GPUでのフレーム時間の達成はまだ検証していない。

## 3. ユーザー操作と対象範囲

Generate パネルに「周辺景観」を追加する。

| 選択 | 動作 |
| --- | --- |
| 従来 | 現行の農地・景観生成。新フィールドがない旧都市もこれを使う |
| 耕作地を森林化 | 生成対象の耕作地をすべて森林用地へ転換。対象は開放耕地・菜園等の農地区画。一般住宅・公園・墓地は転換しない |
| 森林に囲まれた都市 | 上記に加え、市街と保護領域を除く郊外の陸地を森林化。畑のない都市でも使える |

生成済み都市には同じ設定と「景観を適用」を用意する。新しい seed で市街を作り直さず、土地被覆とそこから派生する農地・森林を更新する。一操作を一履歴にまとめる。

「全耕作地」は農地面積の転換率 100% を指し、樹冠の隙間がゼロという意味ではない。都市内の明示的な農地区も対象になり得るが、他用途の市街セルには植えない。「森林に囲まれた都市」の追加範囲は郊外のみとする。

ロック済みセル・固定施設・手動配置要素は保護する。ロックされた耕作地があれば残し、「対象外の固定耕作地が残っている」件数・面積を表示する。全量転換が必要なユーザーは対象のロックを解除して再適用できる。操作が成功しただけで「全量転換済み」と表示しない。

初版の密度は「疎林／標準／密林」の3段階。2D 表現は「林縁と面／全域に樹木」、3D 品質は「自動／軽量／標準／高品質」とする。3D 品質は住宅の既存モデル品質とは別の森林設定として持ち、詳細な上限は必要時に開く。

## 4. データと生成の分担

### 4.1 保存する正本

新設候補 `types/contracts/forest.ts` に以下を定義する。名称は実装時に既存の契約へ合わせる。

- `CityDocument.forestSettings`：景観モード、密度、生成規則の版。
- `GenerationSettings.forestSettings`：新規生成と再現用の同じ入力。
- `FaceProperties.landCoverOverride?: "forest" | "open"`：セル単位の明示的指定。用途 `ward` と分け、公園を森林の代用品にしない。未設定は景観モードに従う。
- 表示設定：2D 表現と 3D 品質・上限。地図内容とは分けて保存する。共有先の機器に強制する上限にはせず、受信側はより軽い設定を選べる。

初版はセル単位の編集とする。一本ごとの木や農地区画ごとの編集状態は保存しない。「耕作地を森林化」は一時的な農地区画配列を正本にせず、元の耕作可能セルを森林へ割り当てる。そのため畝だけでなく、同じ対象セルの畦畔・休耕部分も森林用地となる。

明示的なセル指定 > 都市全体の景観モード > 従来のバイオーム散布の順で解決する。ただし水域・施設等の保護条件は常に優先する。単なる画面表示の切替では正本を変更しない。

### 4.2 派生する共通計画

`generators/forestPlan.ts` を新設し、`ForestPlan` を両レンダラーへ渡す。

1. 陸地・対象セルと、市街・道路・水域・施設・防御用地の予約領域を収集する。
2. 森林に割り当てたセルを農地生成候補から除き、森林の外周と穴を作る。
3. 隣接する森林セルを結合し、セルの共有辺を林縁から除く。離れた森や道路の両岸は別領域として保持する。
4. 領域を外周＋穴、安定 ID、面積、林縁、空間検索用 bounds として保持する。
5. 領域からチャンクと樹木候補を遅延導出する。seed・世界座標・安定 ID のハッシュで位置・樹種・大きさを決め、カメラや反復順序を乱数の入力にしない。

`forestPlan` は巨大な樹木配列を正本にせず、可視チャンクに必要な候補だけを作る。林縁のサンプル数にも上限を設け、細かいセル境界で無制限に増やさない。面積の集計は表示用に簡略化した輪郭ではなく、除外後の領域で行う。

市街生成 → 防御・施設・道路の予約確定 → 共通の森林用地解決 → 農地と森林の派生計画 → 各描画、の依存順とする。農地経路が複数あるため `buildBlockFabric()` 等の最終組立でも森林との排他条件を検査し、旧農地経路からの再流入を防ぐ。

### 4.3 保護と整合性

- 海・湖・河川の水面には塗りも樹木も作らない。FMG 連携のメッシュ外は、実データで陸と確認できる部分だけを対象とし、no-data を森林にしない。
- 森林に囲まれた都市の追加範囲は、原則として編集メッシュ内の郊外とする。フレーム外周まで広げる場合は regional surface の陸・近隣集落の保護情報を使う。単独 CE でメッシュ外の陸を確定できない部分は初版では塗らない。
- 道幅、路肩、門前、橋詰、港、堀、城壁、防御用空地、建物と敷地内アクセスを除く。既存の予約計画を再利用し、`landscape.ts` の固定余白をすべて森林用の基準としてコピーしない。
- 樹幹の中心だけでなく樹冠半径で判定する。2D は必要に応じ clipPath、3D は樹冠を含む占有範囲の判定を用いる。道路を枝葉で塞がない。
- 公園・墓地・既存の手動樹木とは領域または配置の責務を分け、二重に植えない。
- 農地転換後は畝・生垣・畦道・自動生成の農地小屋を除く。共用の道、固定された小屋、一般の住宅は維持し、農地由来の要素だけを識別して更新する。
- 城壁直下の防御用地は森林化しない。「囲まれる」は都市へ木が接触する意味にはしない。クリアランス変更は後続の独立した仕様とする。
- 地形の標高は既存 `CityTerrain` に従い、林床・樹木の根元・遠景の樹冠高さを同じ地形から導く。

## 5. 2D の描画方式

| 方式 | 見た目と負荷 | 採用方針 |
| --- | --- | --- |
| 全域を一本ずつ描く | 拡大時の情報量が多い。面積に比例して要素が増え、縮小時は木が潰れる | 選択式の詳細表示。可視範囲・総数の上限を適用 |
| 面だけ塗る | 軽いが、草地や用途区画との区別が弱い | 最小品質・極端な縮小時 |
| 面＋林縁の木 | 連続した森に見え、内部の木を省ける | **既定**。内部は共有パターンで控えめに補う |

描画順は林床の面 → 内部の樹冠模様 → 林縁の木 → 道路・施設等。既存の SVG レイヤー構成と照合し、建物やラベルを覆わない位置へ組み込む。穴は複合 path と `fill-rule="evenodd"` 等で保ち、川・道の穴が単純化で塞がらないようにする。

林縁には外周と大きな開口部の周囲に1〜2列の木を、間隔と寸法を揺らして置く。木の丸い輪郭で自然な端を作り、行政境界風の太い囲み線は付けない。内部は林縁の樹冠と同系色で、明暗の少数のパターンを使う。全面が平坦な草地に見える場合だけ少量の内部の木を補う。

SVG の樹木は可能なら共有 `symbol/use` を用いる。ただし `use` の数も DOM の負荷になるため、共有だけを負荷対策としない。画面の縮尺に応じて小さな林縁記号を省き、品質にかかわらず面は残す。エクスポート時はビューポート依存の欠落を避け、保存した表現と有限の出力予算から静的な全景を生成する。

F0では面＋林縁で森林のSVG要素数が約79〜85%減った。初版の森林部分の上限は `detailed` 8,000要素、`light` 3,000要素、`minimal` は面のみとする。上限を超える場合は林縁の木を間引く。

既存のバイオーム散布は明示的な森林領域内で停止する。新しい面の上に従来の木を重ねない。森林以外の岩・草等の景観は従来経路を利用する。

## 6. 3D の描画と負荷制御

### 6.1 三段階の表現

| 段階 | 表現 | 主な対象 |
| --- | --- | --- |
| 近景 | 幹と立体的な樹冠。森林用の軽量LODを作り、樹種・材質・チャンク単位でインスタンス化 | 林縁、カメラに近い森 |
| 中景 | 枝の細部を省いた幹と低ポリゴン樹冠。同じ候補 ID の縮約表現 | 森の内部、少し離れた林縁 |
| 遠景 | 地形に沿った、厚みと起伏のある低ポリゴン樹冠の塊。除外領域の穴を保つ | 俯瞰時の大部分の森 |

林床を緑にするだけでは斜め視点で森に見えないため、遠景でも樹冠の高さと外周の立ち上がりを持たせる。単一の水平板で山や谷をまたがない。billboard／透過 impostor は初版の必須要件にせず、不透明の簡略樹冠で成立するかを先に測る。

LOD は距離だけでなく画面上の大きさを基準にし、境界にヒステリシスを置く。低品質でも林縁の輪郭と木の根元の位置が不自然に移動しないよう、候補の安定した部分集合を使う。樹冠の塊と個別樹木の切替時は重複描画と隙間を検証する。

### 6.2 予算

以下をF0の構造比較に基づく森林分の初版の打切り条件とする。実GPU上のフレーム時間による校正はF3〜F5へ引き継ぐ。

| 品質 | 個別樹木の可視インスタンス数上限 | 森林の可視三角形目安 | 影 |
| --- | ---: | ---: | --- |
| 軽量 | 2,000 | 100,000 | 森林は投影なし |
| 標準 | 8,000 | 300,000 | 近景の一部のみ |
| 高品質 | 20,000 | 800,000 | 近景を予算内で投影 |

主描画の森林draw callsは軽量64・標準128・高品質256まで、影へ提出する森林の三角形は標準50,000・高品質150,000までとする。近景モデルは幹込み256三角形以下、中景は64以下を初期目標とする。F0では既存のシナノキ相当が1本84,098三角形だったため、詳細な既存樹木の全域利用を取りやめる。樹種・色の選択を再利用し、森林用の形状は別LODを用意する。

上限は描けることを保証する数ではなく打切り条件。樹種ごとのモデルの三角形数を調べ、個体数・三角形数の厳しい側を使う。遠景の塊も三角形予算へ含める。影は通常描画と別に計測する。

- 世界座標で固定した128 mの個別樹木チャンクを使い、遠景は256 m単位へまとめる。F0の64・128・256 mの比較では、中都市の128 mは64 mに比べ俯瞰で提出する木が約7%増える代わりにdraw calls見積もりが約70%減った。視錐台外を除き、地図全体を単一 `InstancedMesh` にまとめない。
- 近景と林縁を優先し、予算超過時は内部の個別樹木を先に塊へ置換する。領域の面積は維持する。
- draw call 数は「木の本数」ではなく「可視チャンク × 樹種 × 材質 × LOD」にも依存する。樹種・材質の種類とチャンク数も制限する。
- 既存モデルの geometry/material は共有し、キャッシュ破棄時の所有権を明確にする。切替のたびに樹種モデルを作り直さない。
- 遠景・中景は原則として影を投影しない。既存 `cityView.ts` の shadow map 更新に合わせ、カメラ移動による LOD 更新で影を無制限に再生成しない。
- 自動品質はカメラ操作中の描画時間を採取し、継続した予算超過で一段下げ、回復は遅らせる。描画要求時だけ更新する現行方式を保ち、品質判定だけの常時描画は追加しない。
- 初版の自動品質は標準から開始する。利用者の手動品質を勝手に変更しない。高品質でも総量上限は守る。

### 6.3 更新とキャッシュ

`src/city3d/three/forestMeshes.ts` を新設し、`cityView.ts` に接続する。樹木の選択用オブジェクトは作らず、必要なときだけ領域・セルを選択する。

土地被覆・道路・施設・水域が変わったときは共通計画を無効化する。地形が変わったときは根元と樹冠面を更新し、品質やカメラだけの変更では農地・建物・共通の森林境界を再生成しない。画面を閉じたときは geometry、インスタンス、共有モデルの参照を適切に解放する。

農地の fingerprint に森林入力を含め、スナップショット・overlay・Worker 結果の一致を確認する。森林化前に始まった Worker の結果は request ID と入力キーで棄却し、転換後の都市へ古い畑を戻さない。農地設定が off の場合も、森林指定を消す動作にはしない。

## 7. 互換性・保存・共有

- 新フィールドがない旧 JSON・レシピ・共有リンクは従来の表示と生成を維持する。読み込みだけで森林化しない。
- 列挙値、密度、上限、セル指定を検証する。NaN・Infinity・負値・過大値を通さない。描画用の値は安全な範囲へ正規化する。
- `documentCodec.ts`、共有 codec、生成入力のコピー、履歴、Worker 入力を同じ変更で対応する。再生成と Undo/Redo で森林が消えないことを確認する。
- 木の全位置や GPU 用データは JSON に保存せず、seed と規則版から導く。輪郭簡略化や LOD の変更で土地被覆を変えない。
- 現行 document version は1〜5を受理する。新仕様を旧実装で開くと森林指定が無視され得るため、F1 で共有形式と文書形式の互換性方針を確定し、必要なら version を追加する。既存の施設・高さ場の version 条件を一律に緩めない。
- FMG 連携でも CE 内の景観上書きとして保存する。FMG の人口、耕地面積、食料生産、木材蓄積は変更しない。経済と同期する森林化は関連計画の別工程とする。

## 8. 実装順序と完了条件

| 段階 | 作業 | 完了条件 |

| F0：固定入力と計測 | 小都市・大きめの都市・川や起伏を持つ都市の固定3入力を用意。同じ入力から従来／森林化を比較。樹種モデルの規模と現行農地依存を測る | 同じカメラで2D生成時間・DOM数、3D構築時間・フレーム時間・draw calls・三角形数・影・geometry等を記録。予算とチャンク寸法を確定 |

## 9. 検証と受入条件

### 正しさ

- 全耕作地モードで、保護対象以外の元農地・畝・専用小道・自動小屋が残らない。保護対象の残量は計測できる。
- 森林に囲まれた都市モードで、畑のない郊外セルも森林になる。道路・河川・海岸・門前・施設・防御用地は塞がらない。
- 隣接セルの共有辺に二重の林縁が出ず、離れた森は誤結合しない。外周と穴を両表示で一致させる。
- 同じ seed・入力から同じ候補が得られ、品質切替・カメラ移動で森がランダムに植え直されない。
- 高さ場とセル標高の両方で根元が接地し、起伏をまたぐ樹冠面が浮かない。
- 保存／共有／再生成／Undo/Redo後も設定と対象が再現される。旧入力は旧動作を維持する。
- 森林化前の非同期農地結果が完了しても、畑が復活しない。

### 負荷と見た目

- 2D は「面＋林縁」と「全域樹木」を同じ固定都市で比較し、SVGノード数・構築時間・パン／ズーム時の反応・出力サイズを記録する。
- 3D は同じ端末・解像度・カメラ経路・影設定で、構築時間と操作中のフレーム時間 p50/p95 を記録する。俯瞰・林縁への接近・低い斜め視点を含める。
- 標準品質で操作中の p95 を33 ms以内とすることを初期目標に置く。森林追加前から超える都市は絶対値と追加分を分けて記録する。未達なら表現・既定値を下げてから提供する。
- 樹木数・三角形数・draw calls・影の描画・生成中のメモリ増加を併記する。初回構築とカメラ移動中の負荷を混同しない。
- 同じ都市で品質切替とビュー開閉を繰り返し、geometry・texture数等が継続増加しないことを確認する。GPU実メモリを計れない環境では推定と明記する。
- 画面全景と林縁の拡大画像を2D・3Dで残し、草地との判別、穴の維持、規則的な並び、LODの跳びを確認する。

### 実行するテストの範囲

実装時は変更した段階に必要な関連テストのみを実行する。追加は領域排他・穴・決定性・古い非同期結果の棄却・互換性・資源解放等の重要な振る舞いに限る。

- 新設候補：`generators/forestPlan.test.ts`、`renderers/forestSvg.test.ts`、`src/city3d/three/forestMeshes.test.ts`。
- 既存の関連先：`generators/ruralFields.test.ts`、`services/ruralFieldWorkerClient.test.ts`、`renderers/landscape.test.ts`、`renderers/cityViewRendering.test.ts`、`services/io/documentCodec.test.ts`、`services/io/incomingCity.test.ts`、`generators/history.test.ts`。
- 農地小屋・公園等の変更が必要になった場合だけ、その関連テストを追加実行する。全件テスト・多数seedの検証は行わない。
- FMGから確認する場合は人口を必要とする固定都市を選び、Settlement pattern が Standard であることを確認する。

F0の固定3入力、比較画像、既存負荷、モデル規模、初版の制限、全量JSONのSHA-256は [計測記録](../analytics/ce-forest-f0-20261028.md) に収録した。ソフトウェア描画で時間が丸められたため、33 ms目標の達成は未検証である。再生成可能な2 MB超の全量JSONは `docs/analytics/raw/` へ置く。
