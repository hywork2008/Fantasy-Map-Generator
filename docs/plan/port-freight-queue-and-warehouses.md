## 1. 目的

[long-distance-merchant-reach-capital.md](long-distance-merchant-reach-capital.md) §17 は、運べない荷の予約と、船のない市場の海路を止めた。取り消しは減ったが、次の 2 点が史実と合わない。

- **陸の車両の数で予約を止めている。** 荷車・荷馬車は、お金があれば近くの村から雇えるか、すぐに造れる。経済の規模に合わない少ない車両は、すぐに解消されるはずである。
- **自分の市場の船がなければ海路をしない。** 史実の商人の多くは、自分の船を持たなかった。他人の船の積荷の枠を借り、港の倉庫で次の便を待った。港では、少ない船に荷を積みたい荷主が順番を待つことがよくあった。

本設計は、次の 3 つを決める。

1. 陸: 車両が足りないときは、予約を止めずに車両を雇い足し、運賃を上げる(§3)。
2. 海: 荷は港の倉庫で船を待つ。どの市場の船でも、運賃を払えば積める。積む順は運賃の高い順。待ちすぎた荷は港で売る。荷の溜まった港には、空いた船が回ってくる(§4)。
3. 港の倉庫: 港を持つ都市に、倉庫の収容力(荷の枠)を持たせる。海の交易の量と荷待ちの量で増え、CE は収容力から倉庫の敷地と形を描く。経済と流通網の恩恵を受ける港ほど、大きな倉庫が見える(§5〜§6)。

## 2. 史料の調査

### 2.1 陸: 車両が足りないとき

| 事実 | 設計への読み |
| :--- | :--- |
| 商人は車両を持たず、運送業者を雇うのが普通だった。日本の馬借・車借、ドイツの Fuhrleute、フランスの voiturier。足りないときは、近くの村の農民の馬や車を駆り出した | 車両の不足は、取り消しではなく運賃の上昇として出る |
| 穀物のような嵩物を陸路で遠くへ運ぶと、運賃と飼料代で割に合わなくなった | 陸の量を抑えるのは車両の数ではなく、運賃(既存の距離と運賃の計算)。運賃が上がれば、照合の利益で自然に止まる |
| 収穫期は、牽く家畜と人手が農作業に取られた | 収穫月だけ雇える車両を細くする(任意、§3.3) |

| 待ちきれない荷は、その港で安く売るか、別の港行きの船に回した。元の場所に戻すことはまれだった | 一般 | 期限を過ぎた荷は港の市場で売る(§4.4) |

### 2.4 都市の中での配置

史料から、港の倉庫の配置は次の 5 つの型に分けられる。どの型でも、**倉庫は荷揚げ場のすぐ背後か、水路を敷地に引き込んだ所にある。** 町の中心や市場の広場の近くに大倉庫を置く例はなく、水辺から離れた倉庫は小さく、地元の市場に供する。

| 型 | 内容 | 例 | 水辺からの距離 |
| :--- | :--- | :--- | :--- |
| A 商人の家の倉 | 商人の家の上階・奥・地下を倉庫に使う。港から市場への通りに並ぶ | リューベックの Dielenhaus、アムステルダムの運河沿いの家(破風の巻き上げ梁) | 岸に面するか、岸から市場への通り沿い |
| B 岸の倉庫の列 | 岸の背後に倉庫の棟を並べる。棟は岸に妻(短辺)を向け、奥へ細長く延びることが多い。品目ごとに岸が分かれることがある | Bryggen、Salzspeicher、キングズ・リン、日本橋の河岸 | 岸に接する(0〜数十 m) |
| C 商館(囲い地) | 外国商人や同業の組合が、岸に面した囲い地に倉庫・計量所・宿・会館をまとめる | Fondaco dei Tedeschi、Steelyard、Bryggen | 岸に接し、自前の荷揚げ場を持つ |
| D 国・会社・領主の大倉庫 | 穀物・年貢・会社の荷を集める大きな囲い地。堀割を引き込むか、造船所に接する | Horrea Galbae、浅草御蔵、大坂の蔵屋敷、VOC の海の倉庫 | 岸に接するか、堀割を敷地に引き込む |
| E 囲い込みの船渠 | 船渠を掘り、その岸に多層の倉庫の列を建てる。塀で囲み、税関が見張る | West India Docks | 船渠の岸に接する |

型の出方には次の傾向がある。

- **規模と時代**: 小さな港は A だけ。交易が増えると B が岸に並ぶ。外国商人が集まる港に C ができる。国の穀物や年貢、会社の荷が集まる都市に D ができる。E は 19 世紀の工業化の後。
- **はしけ(艀)**: 大きな船が岸に着けない港では、沖に泊まった船からはしけで荷を運んだ(ロンドンの Pool、江戸の沖の大船と河岸)。倉庫は、深い水の泊地ではなく、はしけが着く内側の川岸・運河の岸(河岸)に並ぶ。
- **陸揚げの規制**: 税関が陸揚げを決まった岸に限ると(Legal Quays)、倉庫はそこに集まり、混み合う。
- **品目**: 穀物は多層の倉、樽物(ワイン・油)は地下か 1 階、材木・石は屋根のない置き場(既存の §5.3 の `timberYard`・`stoneYard`)。

## 3. 陸: 車両を雇い足す

### 3.1 今の仕組み

§17.1 は、出発地の市場の車両の積載 × 30 日を 1 か月の枠・日とし、それを超える予約を `noTransport` で止める。車両の補充は、修理で抜けた分の注文(`queueSimulationReplenishment`)と、計測した輸出量からの補充(`estimateMarketAnnualExportCargoSlots`)による。

### 3.2 変更

| 項目 | 内容 |
| :--- | :--- |
| 雇い足し | 陸の枠・日が足りないときは、足りない分を「雇った車両」として予約する。雇える量は、自前の積載の `LAND_HIRE_SHARE` 倍(案 1.0)まで。雇った分の運賃は、自前の車両の運賃の `LAND_HIRE_FREIGHT_MULTIPLIER` 倍(案 1.5)。照合の利益で運賃の上がった分を見るので、利の薄い嵩物は自然に止まる |
| 雇った車両の扱い | 隊商は、雇った分の積載を自前の車両と同じ種類で持つ。到着したら消える(市場の車両には加えない)。運賃は出発地の都市の運送業者の収入にする(既存の運賃の扱い `freightUnitCost` と同じ) |
| 車両の注文 | 雇った枠・日を市場ごとに記録し、生産の周期の初めに、その分の車両を注文する(修理の分の注文と同じ流れ)。雇い続けるより自前で持つ方が安いので、恒常的な不足は数周期で自前の車両になる |
| 上限を超えた分 | 自前 + 雇える量を超える分は、今と同じく `noTransport` で止める。1 回の照合で何か月分もの嵩物を予約することはなくなる(§16.2 の 398 台分の予約は、自前の積載の 2 倍で止まる) |

### 3.3 収穫月(任意)

収穫月は、雇える量を `LAND_HIRE_SHARE × HARVEST_HIRE_FACTOR`(案 0.5)にする。牽く家畜と人手が農作業に取られることを表す。収穫月の判定は、作物暦([farm-labour-calibration.md](farm-labour-calibration.md))の収穫月を使う。初めの実装では入れず、計測で穀物の流れが偏るときに足す。

## 4. 海: 港で船を待つ

### 4.1 港の荷待ちの台帳

海の区間がある荷は、出発地の市場の港(§17.2 の `merchantHullHomePort` と同じ選び方。港を独立した存在にした後は [fmg-harbour-model.md](fmg-harbour-model.md) の Harbour)で船を待つものとして数える。

- 初めの段階(P2)では、荷は今のまま市場の倉庫(`ExportStagingLot`)にあり、港の都市 `portBurgId` を記録するだけにする。隊商は今のまま、陸と海の区間を 1 つの隊商で進む。
- 後の段階(P4)で、隊商を港で分ける。陸の区間の隊商が港の倉庫に荷を降ろし、海の区間は港の倉庫から船に積む。§5 の倉庫の収容力が、荷の行き場として実際に効くのはこの段階から。

### 4.2 どの船でも積める(運賃積み)

| 項目 | 内容 |
| :--- | :--- |
| 船の持ち主 | 船は今のまま市場の船(造船の拡張の船体、母港あり)。持ち主は変えない |
| 他の市場の荷 | 港に泊まっている船は、持ち主の市場の荷を積んだ後の空きに、ほかの市場の荷を積める。運賃は船の持ち主の市場の運送業者の収入にする |
| 予約の上限 | §17.1 の海の上限を、「自前の船の積載」から「その港に泊まる船と、30 日以内に着く船の積載」にする。持ち主の市場の荷を先に数える |
| 船のない市場 | 港に他の市場の船が来るなら、海路を予約できる。どの船も来ない港だけ、今と同じく止める(`noTransport`) |

### 4.3 積む順

港で船の空きより荷が多いとき、荷の運賃の申し出(枠あたりの価値 × 運賃率)の高い順に積む。同じなら、港に着いた順(浅草御蔵の着いた順の陸揚げ)。高額品が先に積まれ、嵩物が待つ。§17.4 の「嵩物の予約が先に枠を使うと、同じ周期の高額品が止まる」も、これで解く。

### 4.4 待つ間の費用と期限

| 項目 | 内容 |
| :--- | :--- |
| 倉敷料 | 港で待つ荷は、枠・日あたり `PORT_STORAGE_FEE` を港の都市に払う(倉庫の持ち主の収入)。§5 の収容力を超えた荷(岸に積んだ荷、はしけに載せたままの荷)は、倍の倉敷料を払う |
| 傷み | 食料は既存の鮮度と穀物の傷み([grain-storage-life.md](grain-storage-life.md))で傷む。収容力を超えた荷は、傷みを早める(案 1.5 倍) |
| 期限 | 今の上限(荷待ちの最大 + 往復 + 30 日、`getStaleLotDays`)を使う。期限を過ぎた荷は出発地に戻さず、港の都市の市場で売る(地元の価格の `STALE_SALE_DISCOUNT` 倍、案 0.7)。差額は商会の損になる |

### 4.5 空いた船の回航

生産の周期の初めに、港ごとの荷待ちの量(枠)と、船の空き(枠)を比べる。持ち主の市場に積む荷のない船は、荷待ちの多い港へ空船で回る(不定期船)。

- 回る先は、荷待ちの枠 ÷ 泊まっている船の積載の大きい港。回航の日数で割り引く。
- 船の持ち主と母港は変えない。回った先で荷を積み、着いた港で次の荷を探す。
- 1 周期に回る船は、港ごとに空いた船の半分まで(全部の船が同じ港に集まらないように)。

### 4.6 季節(任意)

冬の休航は、今の出港日(`tradeSailSchedule.ts`)に休航の月を足す形で後から入れる。初めの実装では入れない。

### 4.7 船の注文

§17.2 の注文は残すが、きっかけを「自前の船がない」から「港の荷待ちが、泊まる船と着く船の積載の `HULL_ORDER_BACKLOG_MONTHS`(案 2)か月分を超える状態が続く」に変える。回ってくる船で足りる港は、船を注文しない。

## 5. 港の倉庫の収容力

### 5.1 持たせる値

港を持つ都市(`burg.port`。Harbour の実装の後は Harbour)に、倉庫の状態を持たせる。経済の拡張の状態に保存する。

```ts
export interface PortWarehouseState {
  burgId: number;
  /** Cargo slots the port's warehouses hold. Buildings stay when trade falls. */
  capacitySlots: number;
  /** Highest smoothed need seen (slots). Drives expansion. */
  needSlots: number;
  /** Who built the largest share. Picks the CE layout type (§2.4). */
  owner: "merchants" | "merchantHouse" | "state";
  /** Year the last building step finished. */
  lastBuiltYear: number;
}
```

### 5.2 増え方

| 項目 | 内容 |
| :--- | :--- |
| 必要な量 | `need = 港の年間の海の取扱量(積み出し + 陸揚げの枠)× 平均の滞留日数 ÷ 365 + 直近 12 か月の荷待ちの最大`。滞留日数は案 30 日。指数平滑(年 0.3)で `needSlots` に入れる |
| 建てる | `needSlots` が `capacitySlots` を 1 年続けて超えたら、1 棟分(§5.3 の 1 棟の枠)を建てる。費用は枠あたり `PORT_WAREHOUSE_COST_PER_SLOT` で、港の市場の商会の資本から払う。払えなければ建てない |
| 建てる期間 | 1 棟 1 年(案)。建てている間は収容力に数えない |
| 減り方 | 建物は残る。取り扱いが減っても `capacitySlots` は下げない。100 年使われない分だけ、年 1% ずつ減らす(倉庫が住宅や作業場に変わる) |
| 初めの値 | 地図の作成時に、港の都市の人口と市場の中心かどうかから決める(既存の車両の初期値 `landFleetCountsFromBurgScale` と同じ考え方) |
| 持ち主 | 商会の本拠(`merchantHouse: major`)がある都市は `merchantHouse`、外国の商会の支店(外地の商館)が多い都市も `merchantHouse`。国の公共穀倉(`publicWorks.granary`)が大きい首都の港は `state`。ほかは `merchants` |

収容力は、§4.4 の倉敷料の倍額と傷みを避ける量として効く。荷待ちの多い港ほど早く倉庫が増える。

### 5.3 収容力から床と敷地へ

- 床面積 = `capacitySlots × PORT_WAREHOUSE_FLOOR_M2_PER_SLOT`(案 0.8。§5.3 の `warehouse` の 0.8 m²/lot にそろえる)。
- 階数は時代で決める。古代・中世 2〜3 階、近世 3〜4 階、工業化の後 5〜6 階(§2.3 の Bryggen、Fondaco、Zeemagazijn、West India Docks)。
- 敷地 = 床面積 ÷ 階数。1 棟の大きさは型で変える。

| 型 | 1 棟(区画)の敷地の目安 | 根拠 |
| :--- | :--- | :--- |
| B 岸の倉庫の列 | 100〜600 m²(細長い棟) | Bryggen・Salzspeicher の棟。数字は目安で校正の対象 |
| C 商館 | 2,000〜6,000 m²(囲い地全体) | Fondaco(延べ 9,000 m²、4 層)、Steelyard 5,250 m² |
| D 大倉庫 | 5,000 m²〜12 ha(囲い地全体) | Horrea Galbae 21,000 m²、浅草御蔵 約 12 ha |
| E 船渠の倉庫 | 1 棟 2,000〜2,500 m² の列 | West India Docks 約 2,400 m² / 棟 |

### 5.4 型の選び方

| 条件 | 型 |
| :--- | :--- |
| 収容力が 1 棟(B)の最小に満たない | A のみ(港の倉庫は描かない。商人の家の倉で持つ) |
| それ以上 | B |
| 持ち主 `merchantHouse` で、収容力が C の最小以上 | B + C(1 か所) |
| 持ち主 `state` で、収容力が D の最小以上 | B + D(1 か所) |
| 蒸気船の技術を習得し、収容力が E の最小以上 | E(B を置き換える) |

収容力の順位は世界の中で比べ、大きな港の上位ほど C・D が出やすいようにする(交易の恩恵を受ける港に大きな倉庫が見える)。

## 6. CE への受け渡しと配置

### 6.1 データ

`BurgSiteEconomy` に任意のフィールドを足す。任意フィールドの追加なので `DESCRIPTOR_VERSION` は変えない。CE 側の型のコピーも同時に直す。

```ts
export interface SitePortWarehouse {
  capacitySlots: number;
  /** Ground area after storeys (m²). Capped like storage[] (§5.3 of fmg-economy-to-city-editor.md). */
  groundAreaM2: number;
  storeys: number;
  layout: "merchantHouses" | "quayRow" | "compound" | "stateStore" | "dock";
  /** World rank 0..1 of capacitySlots among ports. */
  rank: number;
  /** Slots waiting for a ship now. CE may show stacked goods on the quay when this exceeds capacity. */
  queuedSlots: number;
  /** Top goods by slots through the port (labels). */
  mainGoods: string[];
}
// BurgSiteEconomy.portWarehouse?: SitePortWarehouse
```

在庫から決める今の置き場(`storage[]` の `warehouse`・`granary`)との関係:

- 港の倉庫は建物の量(在庫が空でも残る)、`storage[]` は今の在庫の量。
- 水運で入る(`waterborne`)`warehouse`・`granary` の面積は、港の倉庫の敷地の分だけ差し引く(ギルドの置き場を差し引く `guildCover` と同じ扱い)。残った分だけ今の場所に置く。

### 6.2 配置(今の CE の課題)

今の CE は、港の倉庫を水辺に寄せない。

- `storageYardPlacement.ts` は `harbor` の区画を置き場に使わない(`BLOCKED_WARDS`)。
- `waterborne` の置き場は、川からの距離だけで寄せる。海岸には寄せない。
- `warehouse` は城壁内で町の中心に寄せる(`Math.hypot(spot.centre) * 0.012`)。

§2.4 のとおり、港の倉庫は岸の背後に置く。

| 型 | 置き方 |
| :--- | :--- |
| A | 置かない。岸から市場への通り沿いの商人の家を大きくする(既存の [approach-commerce-quarters.md](approach-commerce-quarters.md) R5) |
| B | `harborFabric.ts` の岸の帯(`quay`)と荷さばき場(`loading-yard`)の背後、岸から 0〜40 m の帯に、岸に妻を向けた細長い棟を並べる。岸の長さに沿って、荷の多い岸から順に埋める |
| C | 岸に面した 1 区画を囲い地にし、中庭を囲む棟と、岸に面した自前の荷揚げ場を持たせる。町の市場の広場に近い岸を選ぶ |
| D | 岸に接する広い区画を選ぶ。城壁の内外は問わない(浅草御蔵は町の外れ)。堀割を引き込む表現は後の段階(P6) |
| E | 産業時代の船渠の表現ができるまで描かない |

- 川の港では、深い水の岸ではなく、はしけが着く内側の河岸に寄せる。
- `harborPreset` は、型 C 以上のとき `warehouse` を既定にする(岸の帯と荷さばき場が広くなる)。
- `queuedSlots` が収容力を超えるときは、荷さばき場に積んだ荷(樽・俵の山)を描く(任意)。

## 9. 未決

- 倉庫の初めの値を、地図の作成時の人口で決めてよいか。古い地図を読み込んだときも同じ式で作る。
- 運賃積みの運賃を、持ち主の市場の運送業者に払うか、船の持分を持つ商会に払うか([corporation.md](corporation.md) の持分の扱いとの関係)。

## 10. 実装(2026-10-19)

### 10.1 実装したこと

### 10.2 設計から変えたこと、実装しなかったこと

- 運賃積みの運賃は、今の運賃と同じく出発地の運送業者の収入のまま(§9 の未決のとおり、船の持ち主に払う形にはしていない)。
- 倉敷料、収容力を超えた荷の傷みの割増、期限を過ぎた荷を港で売ること(§4.4)は入れていない。荷は今のまま出発地の市場の倉庫にあり、期限を過ぎれば出発地の市場に戻る(港はその市場の中にあるので、出発地に戻すことは、港の市場に戻すことと同じ)。
- 倉庫を建てる費用は払わない(お金の校正に影響するため。§7.2 の指標を見てから足す)。
- 船の注文のきっかけは §17.2 のまま。予約できなかった枠は、自前の船も借りられる船もない市場だけに残るので、回ってくる船で足りる港は船を注文しない。
- 隊商を港で分けること(§4.1 の後の段階)、大倉庫の堀割、収穫月(§3.3)、季節の休航(§4.6)、荷さばき場に積んだ荷の描画は入れていない。

### 10.10 荷の見込みへの回航と、母港での係船(2026-10-20)
