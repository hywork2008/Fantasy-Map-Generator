# Crop climate guideの作物に対応するBV果樹追加計画

作成日：2026-10-30

## 1. 目的と派生元

[FMGバイオームのBV未登録樹木タスクリスト](fmg-biome-unregistered-bv-tree-tasks.md) から派生し、FMGの **Crop climate guideに掲載される作物を実らせる樹木**をBVへ追加する。元計画の自然林の樹種調査R01〜R06とは独立して進める。

主対象は未登録のリンゴ・セイヨウナシ・セイヨウスモモ・イチジク・レモン・ヨーロッパグリの6樹種・24品質枠。さらに、ガイドの食用種子作物であるカカオ・コーヒーを後半の2樹種・8品質枠として計画に含める。新規は合計 **8樹種・32品質枠**。登録済みのオリーブ・ナツメヤシは再利用を評価し、新規件数に数えない。

BVでの4品質・登録・作者情報・外観確認までを本計画の実装範囲とする。2026-10-30にF01リンゴ・F02セイヨウナシ・F03セイヨウスモモ・F04イチジク・F05レモン・F06ヨーロッパグリ・F07カカオ・F08アラビカコーヒーの4品質を実装・確認し、新規8樹種32品質枠を全て完了（§8〜§12・§14・§16・§17）。既存2種の再利用評価、P6の最終台帳と後続要件の記録も完了（§18）。CEの果樹園自動配置、FMG・REの表示、経済・作物暦・収量の変更は後続課題とする。

## 5. モデルと登録の設計

### 4品質と果実

- `low / medium / high / ultra` を全種に作る。high／ultraは主要な幹・枝骨格と基準乱数を共有し、mediumはその葉群に沿う房、lowは種を見分けられる樹冠輪郭へ縮約する。
- 初版は「葉があり、代表的な実が付いた栽培成木」の静的な展示モデルとする。収量や季節を再現するものではなく、異なる樹種の実りが同時期に見えることも展示上の約束として説明する。
- high／ultraでは実の形と付き方を識別できるようにする。mediumは果実群の少数の形・色へ縮約し、lowでは小さい果実を省略してよい。実の個数を収穫量へ換算しない。花と成熟果実を識別目的だけで同時に大量配置しない。
- 地表を原点の共通基準とし、4品質で樹高・幹位置・樹冠幅を揃える。寸法は制作前に資料と対象樹形から決定し、BVの `size` は実際の外接寸法を覆う値にする。
- [既存F0基準](../analytics/ce-tree-lod-f0-boreal-20261029.md) のlow≤500、medium≤3,000、high≤25,000、ultra≤120,000三角形を初期目安にする。highのsource配列3 MiB、ultra13 MiBも確認し、果実を含めた実測で超過理由を判断する。
- LODは原則 `selection: "pixels"`・`budget: "bounded"`。果実ごとのdraw callや個別materialを増やさず、葉・木部・果実をまとめ、生成器が資源を解放できる構成にする。

### 登録と意味の分離

1. `src/buildings/landscape/` に種別生成器を作り、共通部品だけを共有する。既存木の色替え・別名登録で完了扱いにしない。
2. `trees.ts` の `TREE_SPECIES`・`TREE_DEFINITIONS` に4品質とLOD寸法を登録する。
3. `treeVariants.ts` に作者と品質ごとの版を登録し、実際の派生に `basedOn`・`credits` を付ける。単独版は現在の暗黙採用を使い、競合版だけをCE採用表で確定する。BVの「CE採用」は版の解決状況であり、CEに果樹園が配置済みという意味ではない。
4. `43-landscape-treesModels.ts` に英語の表示名・学名・寸法・対象樹形・果実の表現・資料を登録し、`src/building-viewer/wikipedia.ts` に対象種の参照を追加する。
5. 現行の `biomes` はCE森林の選択を説明する欄なので、新果樹にはBVだけの段階では付けず、説明に栽培果樹であることを書く。気候適性を推測して自然林バイオームへ追加しない。
6. `landscapeTreeSpecies.ts` の自然林・公園・墓地選択は今回の接続先にしない。新規 `TreeSpecies` 追加で網羅性を要求する既存の型・表があれば、意味を確認して補う。

数値の商品IDや翻訳表示名から樹種を解決する処理は作らない。将来のCE接続では、保存カタログの商品識別と描画樹種の対応を明示する。レンダラーから生産量・気候・土地利用を書き換えない。
