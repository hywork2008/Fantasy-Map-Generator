# 売れ残りの武器の盗難

状態: 2026-10-21 設計と実装。[port-freight-queue-and-warehouses.md](port-freight-queue-and-warehouses.md) §10.31 の計測で、軍の注文が届き終えた後の市場に Arms が 14〜16 ロット、4 年間動かずに残るのを見つけたのがきっかけ。

## 1. ねらい

Arms・Muskets・Artillery は民間の用途がなく、国の武器庫(`MilitaryResources`)の注文にしか引かれない。売れない在庫は倉庫に残り続けるが、今はそれに何も起きない。

- 長い間売れない武器は、都市の民衆の不満が高いか治安が悪いと、盗まれやすくする。
- 盗まれた・行方不明になった武器の数を都市ごとに数え、武装蜂起などが起きたときのリスク要素として持つ。蜂起の仕組みは今のところ無い(読む側は未実装)。

## 2. 決めたこと

| 項目 | 内容 |
| :--- | :--- |
| 対象 | Arms・Muskets・Artillery(`WEAPON_GOOD_NAMES`)。Arrows・Bullets・Gunpowder は国の備蓄に入るので除く |
| 売れ残りの数え方 | 市場の武器ごとに在庫の年齢(月、0〜12 か月以上の 13 区分)を `Market.weaponStockAge` に持つ。毎月、持っている合計を実際の在庫に合わせる。増えた分は新しい在庫、減った分は古い在庫から減ったものとする(買い手も盗人も古いものから取る)。その後、全体の年齢を 1 か月進める |
| 盗まれる在庫 | 6 か月未満は盗まれない。6 か月から 12 か月にかけて重みが 1/7 → 1 に上がる(`getLootableAgeWeight`) |
| 盗まれやすさ | 市場の中心の都市の `discontent`(40 以上で 0 → 100 で 1)と `security`(50 以下で 0 → 0 で 1)のうち大きい方(`getTheftUnrest`)。不満が低く治安が普通の都市(`security` の初期値 50)では盗まれない |
| 月の盗難量 | 盗まれる在庫(重みをかけた量)× 月 3% × 盗まれやすさ。確率ではなく期待値で決める(乱数を使わず、再現できる) |
| 記録 | 市場の在庫から引き、物の流れの台帳に `theft`(`sink`)で記録する。盗まれた量は中心の都市の `armsStolen`(累計)と `armsStolenByGood`(品名ごと)に足す。単位は市場の在庫の単位(ロット) |
| リスク要素の読み方 | `getArmsStolenInState(stateId)` が国ごとの合計を返す。蜂起の仕組みを作るときはこれと `discontent` を読む |
| 呼ぶ所 | 生産の周期の終わり、市場の維持費の精算の後(`production-generator.ts`、2 か所) |

## 3. 仮の値

月 3%、6 か月、不満の下限 40、治安の下限 50 は史料のない仮の値。盗まれた武器が実際に蜂起の力になるまでの扱い(持ち出された武器の持ち主、蜂起の兵の装備への換算)は決めていない。

## 4. 残る課題

- 蜂起(`armsStolen` を読む側)は未実装。
- 盗まれた武器は消えるだけで、盗んだ側の手には渡らない。
- 盗難の量は地図で計測していない。市場 4 の Arms 14〜16 ロットが、不満が高い都市でどれだけ減るかを見る。
- 港で待つ荷・隊商の荷・出発地の倉庫の荷(`ExportStagingLot`)は対象外。市場の在庫だけを数える。
