# 都市のランダム生成で失敗しやすい条件

改善の当たりを付けるための大雑把な並び。完全な出現率ではない。2026-09-28 に、同じ入力格子へシードだけ変えて `generateCityOnDocument` を回した短い試行と、不採用理由のコード（`generate.ts` の `reject`、`explainGeneratedCrossingFailures`）を突き合わせた。

関連: 工程と関数の対応は [generation-process.md](generation-process.md)。

## 読み方

一括生成は最大 8 案まで取り直す（`` `${seed}:junction-retry:N` ``）。ユーザーに「生成に失敗しました」と出るのは 8 案とも不採用のときだけ。それよりずっと多いのは、**1 案が途中で捨てられ、別シードで拾われる**場合である。下の順位はこの不採用案の多さ。町が最後まで残る率は、Tiny の Grid evolution ではこの試行の範囲でほぼ 100% だった。

試した範囲の目安（不採用になった案の件数。町の件数ではない）。

| 設定 | 町 | 不採用案 | 最後まで失敗した町 |
| --- | ---: | ---: | ---: |
| Tiny・evolution・既定（内陸・川1・城壁あり） | 24 | 23 | 0 |
| Tiny・evolution・地形もランダム | 24 | 18 | 0 |
| Micro・evolution・既定 | 16 | 11 | 0 |
| Micro・evolution・地形もランダム | 16 | 17 | 1 |
| Tiny・evolution・内陸・川なし・城壁あり | 12 | 5 | 0 |
| Tiny・evolution・湾・川が海へ・城壁・港 | 12 | 8 | 0 |
| Tiny・evolution・岬・川2・城壁・港 | 12 | 21 | 0 |
| Micro・evolution・岬・川2・城壁なし・港 | 12 | 8 | 0 |
| Small・hex・既定 | 6 | 0 | 0 |

既定は Generate パネルの初期値。海岸なし、川は `through` が 1 本、城壁・広場・寺院・仮設あり、港なし、layout は `auto`。格子は Document の既定に近い Grid evolution。Small の hex は件数が少なく、Voronoi と Medium / Large は測っていない。

## 起きやすい順

### 1. 門が壁を貫く道路と十字にならない

不採用理由 `unconnected-gates`（段階 `gate-routing`）。この試行でいちばん多い。

既定の Tiny では不採用案 23 件中 17 件。内陸で川が無くても残る（12 町で 5 件）。川・海岸が付くと増える。岬に川が 2 本ある Tiny では、交差の崩れとほぼ同数まで増えた。Small の hex 6 件では 0 だった。粗い evolution のセルで、門の 4 方向開口か、その開口を通る道路が作れない、という読みで足りる。

起きる中身は次が混ざる。この試行では内訳を分けていない。

- `openBarrierPassage` が壁頂点を 4 方向の門にできない。次数が足りない、分割しても対角にならない。
- 門候補が川の頂点、他の門に近すぎる、城内と城外の両方へ腕が伸びない、で飛ばされ、計画上の門が道路と結ばれない。
- 道路の A* が壁辺・川辺・寺院の身廊・広場の内部・Bram の核で禁じられた辺を避け、門まで届かない。
- 届いた道路の端が城壁上の門以外で切られ、門が孤立する。

直すなら、門を置く前に「この頂点は城内と城外へ対角で抜け、川から離れている」を満たす頂点だけを候補にし、抜けない門は最初から捨てて別の壁辺へ移す。今は置いたあとに案ごと捨てている。

### 2. 平滑化のあと、城壁と河川の交点が十字でなくなる

不採用理由 `invalid-crossings` のうち、`頂点 … で城壁と河川が交わるが十字交差になっていない` と `城壁と河川が辺 … を共有している`。

既定 Tiny の不採用 23 件中 6 件がこの系統（メッセージの先頭が頂点 4、共有辺 2）。川が城壁を横切る配置で出る。岬・川 2 本では交差検証そのものが 10 件まで増え、うちこの 2 種類が先頭だったものが 5 件。平滑化（`finishCityGeometry`）やその後の頂点移動で、いったん開いた交差の腕が斜めに戻るか、壁と川が再び同じ辺を共有する。

`joinWallRiverCrossings` は計画段階で共有辺を 1 頂点に寄せる。落ちるのはその後の幾何処理。門と川の間隔を縮めない制約はあるが、十字の向きまでは守り切れていない。

直すなら、平滑化の移動候補から「壁と川の入射辺の交互順」を崩すものを除外する。案の再抽選より安い。

### 3. 川が町を分断しているのに、橋の形が仕様に合わない

同じ `invalid-crossings`。メッセージは `橋 … の頂点数が 3 ではない`、`橋に河川と道路の十字交差がない`、`河川が市街地を分断しているが橋がない`。

既定の内陸・川 1 本ではこの試行の先頭メッセージには出ていない。岬・川 2 本の Tiny で、橋の頂点数が 5、分断なのに橋がない、が合わせて 5 件出た。Micro のランダム地形でも橋の頂点数が 5 の案が 1 件あった。川が両岸の市街地を横切るときだけ意味を持つ。川が町の脇を通るだけならこの項はほぼ空く。

`addBridge` は道路–河川–道路の 3 頂点を要求する。平滑化やセル分割のあと、橋グループに余った頂点が付くか、渡河頂点が川の折れ線から外れると不採用になる。

直すなら、仕上げ後に橋グループを「川頂点 1 つと、その法線上の道路 2 辺」へ組み直す。頂点数が 3 でないものを即不採用にしている箇所が、拾える失敗を捨てている。

### 4. 地図の外へ出る道路が本数に届かない

不採用理由 `too-few-external-roads`。仕上げ前（`street-plan`）が多く、仕上げ後（`crossing-validation`）は少ない。

川と城壁の話よりは少ないが、陸が細いときにまとまって出る。Micro のランダム地形では不採用 17 件中 9 件がこれで、その多くは岬だった。城壁なしの岬・川 2 本でも 12 町中 8 件がこの理由だけだった。Tiny の既定（内陸）では 0。Small 以上は最低 2 本、Micro / Tiny は最低 1 本。海を避ける設定では水面へ入った道を切り、陸の門に届かない道は作り直す。岬や湾で陸続きが 1 本だと、2 本目の方位を引き直しても同じ頸に戻る。

8 案の再試行で Tiny は拾えていた。町ごと失敗した 1 件は Micro のランダム地形で、外縁道路不足が主因に見える（16 町中 1）。

直すなら、外縁道路の本数を「陸が窓の辺まで届いている方向の数」で頭打ちにする。岬の町に内陸と同じ 2 本を要求しない。Micro はすでに門予算を海の割合で減らしているが、道路本数の下限はサイズだけを見ている。

### 5. 海が中心を占めて市街地が下限面積に届かない

不採用理由 `urban-area-too-small`。充填全体の面積が `πR²` の 45%（`MIN_SETTLEMENT_AREA_SHARE`）未満。城壁内の割合（Medium 45% / Large 20%）とは別の下限。

この試行では 0 件。コード上は、湾や岬の水面が原点付近を覆い、洪水充填が陸の隅にしか広がらないときに落ちる。ランダム地形でも川と門よりは稀、という置き方でよい。原点を陸に固定している合成立地ではさらに出にくい。

直すなら、水面が中心を含むとき都市半径の中心を残った陸の重心へずらす。下限の引き下げは、海に沈んだ町を成功扱いにするので後回しでよい。

### 6. 粗い格子の面が平滑化で自己交差する

不採用理由 `self-intersecting-faces`。evolution だけを検査している。この試行では 0 件。交差の検証まで進んだ案が、面のねじれで落ちる保険、という位置づけ。

頻度は上の 4 つより低い見込み。出たときは `finishCityGeometry` の移動が粗い面の対角を交差させている。

### 7. ほぼランダム生成では出ないもの

- `invalid-mesh`。辺が短すぎる、面の面積がない、川がメッシュを離れる、門の頂点が壁に無い。編集後の再生成や、開口処理が壊れたときの保険。この試行では 0 件。
- `too-few-faces`。格子の面が 3 未満。Document で格子を作ったあとの生成では起きない。
- `all-attempts-rejected`。上の理由が 8 回続いた結果であり、独立した原因ではない。

## 設定で見るとどこが重いか

| 状況 | 主に捨てられる理由 |
| --- | --- |
| 内陸・川なし・城壁あり | 門の未接続が少し。他はほぼ無い |
| 内陸・川が町を横切る・城壁あり（パネル既定） | 門の未接続が大半。残りは壁と川の交差 |
| 湾・川が海へ出る・城壁・港 | 門の未接続。交差は少数 |
| 岬・川が複数・城壁あり | 門の未接続と、壁・川・橋の交差が同程度。再試行回数も増える |
| 岬・城壁なし | 外へ出る道路の本数 |
| セルが細かい hex | 既定条件ではこの試行で不採用なし。evolution の粗さが 1 と 2 を増やしている |

layout の `auto` は Tiny 以下で circulade / bram / organic を引く。Bram の核は道路を禁じ、スポークの長さも固定なので、門の未接続に混ざる。この試行では layout ごとに分けていない。

## 改善の順番の目安

効果が出やすい順は、上の 1 → 2 → 3 → 4。いずれも「条件を緩めて不正な交差を成功にする」より、「置く前に候補を捨てる」「仕上げ後に橋と交差を組み直す」「陸の幅に対して道路本数を頭打ちにする」側が、今の不採用理由と噛み合う。5 以降は、この試行の範囲では体感の失敗にはほとんど出ていない。
