# City Editor 生成アルゴリズム改善 — 実装計画

`docs/city-editor/改善計画.md` と `docs/city-generator/towngen-comparison.md`（分析）を受けた
フェーズ分けの実装計画。`design.md §8` のマイルストーン（E0–E5）とは独立の **G シリーズ**。

## 決定事項（改善計画より）

| 項目 | 決定 |
| --- | --- |
| 手本 | TownGeneratorTS `Model.ts` / `CurtainWall.ts` / `Topology.ts` / `Voronoi.ts`（GPL・読むだけ・関数単位で再実装） |
| 変更コードの置き場所 | **`src/city-editor/core/gen/`** に再実装。`generate.ts` の `src/city-generator/*` 依存を断つ |
| `src/city-generator/` | **凍結・参照専用**。修正しない。commit `1b7f70188` / `120973c4f` で旧側に入った改良は移植時に City Editor へ持ち込む |
| standalone `/city/` ページ・FMG Burg エディタの `openCityGenerator()` | Phase G6 まで放置（凍結）。切替は最後 |
| 決定論 | 全 stage が `(document, settings, seed, step)` で不変。seed 内部・非表示（既存方針） |
| GPL 境界 | TownGeneratorTS のコードは貼らない。`city-generator`（MIT）からのコピーは可だが改良を旧側へ戻さない |

## フェーズ依存関係

```text
G0 (vendoring / 依存断ち)  ─┬─> G1 (セル整形 + Grid evolution)  ── 本命・土台
                            ├─> G2 (現実性フィルタ + 街道)      ── 最優先バグ
                            ├─> G3 (門オプション)
                            └─> G4 (河川オプション)
G1 ─> G5 (平滑化仕上げ)
G0..G5 ─> G6 (city-generator 撤去 / ページ切替)
```

G0 は全フェーズの前提。G1〜G4 は G0 の後は並行可（対象ファイルがほぼ分かれる）。

**目的**：`src/city-editor/` から `src/city-generator/` への import を 0 にする。挙動は

   `city-generator/core` / `city-generator/site` から**バイト単位でコピー**：

   と `gen/site/{burgSiteDescriptor,presets,siteConfig,siteInput,synthSite}.ts`（5）。

   - ex-`site` の 3 ファイル（`siteConfig` / `siteInput` / `synthSite`）だけ

**受入条件**

## Phase G1 — セル整形の TownGen 型再実装 ＋ Grid evolution ＋ 母点編集（本命）

**目的**：改善計画「TownGeneratorTS のセル整形を for ループ 1 周単位で見たい／Grid evolution
スライダーのセル修正アルゴリズムを改善する為／頂点座標の位置・数を指定・編集したい」を満たす。

**手本**：`Model.buildPatches` [Model.ts:167-222]、`Voronoi.build` / `Voronoi.relax`
[Voronoi.ts:31-207]、`Model.captureGenerationStep("2.1 Delaunay / Voronoi")` [Model.ts:154]、
`SvgMapLayer.drawDraft`（delaunay 赤線＋ sites 赤点）[SvgMapLayer.ts:228-247]、
`TownApp` の "Grid evolution" スライダー。

**対象**

- 新規 `core/gen/patches.ts`・`core/gen/gridEvolution.ts`・`core/gen/voronoi.ts`（コピー済みを流用可）
- `core/document.ts`（`createDocument` の格子ソース切替）
- `ui/CityEditorPage.ts`（Document パネル：スライダー・レイヤートグル・母点入力・Voronoi sites tool）
- `render/svg.ts`（delaunay / voronoi / sites オーバーレイ、grid-evolution `<g>`）
- `core/types.ts`（`Tool` に `"site"` 追加 — design §4.1 に既記載）

**アプローチ**

1. **`gen/patches.ts`**
   - `scatterSites(nPatches, rng)`：`for i in 0..nPatches*8` → `a = sa + √i·5`、
     `r = i===0 ? 0 : 10 + i·(2 + rng())`。中心密・外周疎。窓スケールへ線形マップ
     （TownGen は無次元、City Editor は `frame.extentMeters` に正規化）。
   - `buildIncremental(sites)`：`gen/voronoi.ts` を 1 点ずつ `addPoint`。各追加で
     `{ sites: [...soFar], delaunay: edges(), cells: partition() }` を stage 配列へ push
     （重い場合は「N 点ごと」に間引くオプション。既定は 1 点ごと）。
   - `relaxCentral(voronoi, K, passes)`：距離順先頭 `K` 母点だけ重心へ寄せて `Voronoi.build`
     し直す（TownGen `[0,1,2,nPatches]` = K≈4 相当）。各 pass を stage に push。
   - `orderByRadius()`：`sites.sort(by |p|)`。先頭 `N` を `Cell.site` 順に返し、`meshFromCells`
     が urban 候補を id 昇順で持てるようにする。
2. **`gen/gridEvolution.ts`**：`buildGridEvolution(params, settings) → GridStage[]`
   （`towngen-comparison.md §3.A` の型）。scatter 各点 + Voronoi 各追加 + relax 各 pass +
   （任意で）Lloyd 各 pass。ラベルは `"scatter 42/120"` / `"addPoint 42/120"` /
   `"relax pass 2 (K=4)"` / `"Lloyd 1"`。
3. **`document.ts`**：`createDocument` は `buildGridEvolution(...).at(-1).cells` →
   `meshFromCells`。`buildGrid`（`gen/grid.ts`）は当面 fallback として残すが既定は patches 型。
   `CITY_SIZE_PRESETS` の `cellsAcross` は `nPatches` へ読み替え（`nPatches ≈ (cellsAcross/3.5)²`
   目安、実測で調整）。
4. **Document パネル UI**（Generate パネルの step 行と同じ部品を流用）
   - `nPatches` 数値入力（母点数）。`relax K` と `relax passes` の数値入力。
   - 「Grid evolution」range スライダー ＋ `◀ First / Prev / Next / Last ▶` ＋ ラベル output。
     スクラブ中は `documentState` を触らず、`renderEditorSvg` に stage オーバーレイを渡して
     プレビュー描画（履歴を汚さない）。
   - レイヤートグル：☑ Delaunay ☑ Voronoi ☑ Sites。
   - 「この格子を採用」ボタン：現在 stage の `cells` を `meshFromCells` → 新 `mesh` を
     `history.commit(_, "Rebuild grid")`。feature group がある文書では design §5.1 の移管
     プレビュー（今回は「全 feature 未移管扱い・確認必須」で可）。
5. **Voronoi sites tool**（`tool === "site"`）
   - 母点 add（空きクリック）／ move（ドラッグ）／ delete（右クリック）。
   - 変更のたびに `gen/voronoi.ts` で再計算しプレビュー。`Enter` で確定 → `meshFromCells`。
   - `Face.site` を真実源にし、`meshFromCells` は `cell.site` を受け取れるので既存経路で足りる。
6. **`render/svg.ts`**：`.ce-grid-evolution` `<g>` に delaunay（細い赤線）・voronoi（半透明セル）・
   sites（小円）。`renderEditorSvg` の引数に `gridStage?: GridStage | null` を追加。

**受入条件**

- Document パネルのスライダーで、母点散布 → 逐次 Voronoi → relax → （Lloyd）が
  **for ループ 1 周単位**で前進し、各段の Delaunay 三角形・Voronoi セル・母点が見える。
- `nPatches` を変えるとセル数が比例、`relax K` を 4 → 全点にすると中心以外も動くのが見える。
- Voronoi sites tool で母点を 1 個足す／動かす／消すとセルが即再計算され、`Enter` で
  メッシュが置換され、undo で完全復元。
- 既定の New grid が「中心セル最大・外周セル小」（TownGen 型のサイズ勾配）になる。
- `tsc` 0・`biome`・`vitest` 全緑。ブラウザで console エラー無し。

**テスト**

- `gen/patches.test.ts`：決定論、`nPatches → セル数` 単調、i=0 セルが原点を含む、中心セル面積 >
  外周セル面積（勾配）、`relaxCentral(K=4)` は先頭 4 母点だけ移動。
- `gen/gridEvolution.test.ts`：stage 数 = 散布点数 + Voronoi 追加数 + relax passes（+ Lloyd）、
  隣接 stage 間で `sites` が高々 1 点しか増えない／`relax` stage は座標だけ変わる。
- `CityEditorPage.generate.test.ts` 追記：スライダー DOM、`◀/▶` で stage index が
  `[0, total-1]` にクランプ、「採用」で `mesh.faces` 数が stage の `cells` 数と一致、undo 復元。

**G1 実施結果（2026-09-03）**：**コア完了**。

- 新規 `core/gen/patches.ts`（`scatterPatchSites` = TownGen 螺旋散布を窓へスケール、

**G1 で見送り（→ G1b / 後続、理由を明記）**：

- **Voronoi sites tool（`tool === "site"`：母点の add / move / delete）** ── `nPatches` 入力で
  「数の指定」は満たし、overlay で母点は可視。座標の直接編集はキャンバスのポインタ処理

  `buildPatches` 手本移植＋ステップ可視化＋ tuning という主目的とは分離できるため G1b に切る。

  patches 格子は Document パネルの「採用」で明示的に取り込む。実際の粗さ・見た目を評価して

## Phase G2 — 現実性フィルタ ＋ 街道の伸長方式（最優先バグ）

**目的**：`towngen-comparison.md §2.5 / §3.E`。海の上を街道が通る／海を城内に取り込む／
海にはみ出た建物、を pipeline 末尾で機械的に潰す。街道の遠方点をオプション化。

**手本**：TownGen には海が無いので手本は無い。`walkRiver` の `stop`/`trimAtWater`/`finalizeEnds`
（`gen/riverPath.ts`）を「roads にも同じ防御を」の雛形にする。

**対象**：新規 `core/gen/plausibility.ts`、`core/gen/streets.ts`、`core/gen/geom.ts`
（polyline×polygon クリップ・segment-in-polygon）、`core/generate.ts`（`runPlan` 末尾で適用）、
`ui/CityEditorPage.ts`（Generate パネルに `avoidSea` 等）、新規 `plausibility.test.ts`。

**アプローチ**（`towngen-comparison.md §3.E` の 1〜6）

1. `buildStreets` に `seaNodes: Set<number>`（海セル頂点）を渡し `nonUrban` で ∞ 化。
2. `farNodeFor` の goal が水中なら `goal→gate` 線分 × shoreline 交点の陸側 `cellSize` へ置換。
3. A\* が `null` の門は road を引かず `water:true` に再マーク（quay 描画）。
4. 生成済み `roads`/`arteries` を最終検査：`waterPolygon` 内区間があれば drop か shoreline クリップ。
5. 城壁：`borders` 各辺 mid が水中なら区分を `coast` に、海側は塞がない。建物：`withinCell` に
   `&& !pointInPolygon(centroid(piece), waterPolygon)`。門：外側 `cellSize·1.5` が全 sea なら water gate。
6. road ゼロの land gate が過半なら派生 seed で synth 道路方位を作り直し 1 回リトライ。
7. `GenerationSettings.streets = { farNode: "descriptorEnd"|"radial"|"manualBearings", manualBearings?, avoidSea: true, foldSmoothing: true }` を追加。`avoidSea` で 1〜6 を有効化。

**受入条件**

- 4 海岸シナリオ（straight / bay / cape / 海＋川）× 複数 seed で、road・artery・building・wall の
  いずれの区間も `waterPolygon` を跨がない。
- `avoidSea` を off にすると従来の（跨ぐ）挙動に戻る（切り分け可能）。
- `farNode` 3 モードで街道の遠方端が仕様どおり（記述子端 / 放射 / 手動方位）。
- `tsc` 0・`biome`・`vitest` 全緑。

**テスト**：`plausibility.test.ts`（上記 assert）、`gen/streets.test.ts` 追記
（`seaNodes` を渡すと A\* 経路に海頂点が現れない、`farNode` モード別の端点方位）。

## Phase G3 — 門のオプション化

**目的**：`towngen-comparison.md §2.3 / §3.C`。門本数モデル・間隔・候補・外郭 split を UI から。

**手本**：`CurtainWall.buildGates` [CurtainWall.ts:39-100]（`entrances` = 2 パッチ以上共有の
円周頂点、`do…while(entrances.length>=3)` で 1 個選んで周囲 splice、`outer.shape.split(gate,
farthest)` で外郭割り、`gate.set(smoothVertex(gate))`）。

**対象**：`core/gen/gates.ts`（`placeGates` 移植＋拡張）、`core/gen/site.ts`（`synthSite` 移植、
川 `±90` 追加を「市街横断の川のみ・最大 1 本」に制限）、`ui/CityEditorPage.ts`、`gates.test.ts`。

**アプローチ**

```ts
GenerationSettings.gates = {
  countModel: "shape" | "roads" | "manual",   // 既定 "roads"
  manualCount?: number,
  minSpacingFactor: number,                    // 既定 1.0（弧長 perimeter/(target+1) の係数）
  candidates: "corners" | "anyBorderVertex",   // 既定 "corners"
  outerSplit: boolean,                         // 既定 true
}
```

- `"shape"`：border 頂点で「2 urban セル共有」の角のみ候補、`entrances.length>=3` の間ループ
  しつつ周囲を splice（`CurtainWall` 相当）。本数は形状で決まる（概ね 3〜5）。
- `"roads"`：現状の `target = clamp(round(suggestedGates·0.7), 3, 6) + (wet?1:0)`。
- `"manual"`：`manualCount` をそのまま target に。
- `minSpacingFactor` を `spacing = loopLength/(target+1) · factor` に噛ませ、間引き半径を可変に。
- `candidates:"anyBorderVertex"` は corner フィルタを外す（粗いメッシュで角が足りない時の保険）。
- `outerSplit`：門ごとに外側 rural セルを `splitFace(faceId, gate近傍v, farthest v)` で 1 回割る。
  City Editor は `splitFace` を持つのでメッシュ操作として実装可能。road の抜けを保証。
- `◀/▶` の `generateGateStep` は既存のまま（門 1 個ずつ）。

**受入条件**

- `countModel` 3 種で門数が仕様どおり（shape=形状由来 3〜5、roads=従来、manual=指定値）。
- `minSpacingFactor` を上げると門が減り、等間隔性が上がる。
- `candidates:"corners"` では全門が 2-urban 共有頂点に載る。
- `outerSplit:true` で各門の外に新セルが 1 個でき、その門の road が必ず外周へ抜ける。
- `tsc` 0・`biome`・`vitest` 全緑。`interior.test.ts` 相当の移植テスト緑。

**テスト**：`gen/gates.test.ts`（上記）、`gen/site.test.ts`（川 `±90` 追加が横断川のみ・1 本）。

## Phase G4 — 河川のランダム生成オプション

**目的**：`towngen-comparison.md §2.4 / §3.D`。本数・通過形態・蛇行・合流・幅・追従を UI から。
頂点列＝真実源（design §3.1 / §3.2 B）を厳守し、水域内 river edge を作らない。

**手本**：TownGen に河川は無い。`gen/riverPath.ts walkRiver` と `gen/site.ts synthRivers` の
既存パラメータ（`wander` / `meanderScale` / `corridorPull` / `widths` / `crossesSite`）を露出。

**対象**：`core/gen/rivers.ts`（`walkRiver` ラッパ）、`core/gen/site.ts`（`synthRivers`）、
`core/gen/classifyRiver.ts`、`core/generate.ts`（`applyPlan` の river group 化）、
`ui/CityEditorPage.ts`、`rivers.test.ts`。

**アプローチ**

```ts
GenerationSettings.rivers = {
  count: number,                                 // 0..3
  passage: ("through" | "beside" | "toCoast")[], // 河川ごと。未指定は count と coast から導出
  meander: number,                               // walkGraph の wander、0..1、既定 0.7
  confluence: boolean,                           // 2 本目以降を 1 本目へ合流、既定 false
  widthScale: number,                            // 既定 1.0
  corridorPull: number,                          // 既定 1.5（小さいほど暴れる）
}
```

- `riversForCount` を `passage[]` ベースに一般化（`through` は `synthSite` の through-family、
  `beside` は beside-family、`toCoast` は海がある時のみ有効）。
- `confluence`：2 本目の walk goal を 1 本目の `edgePoints` 上の点に設定。最初に触れた共有
  メッシュ頂点で `RiverGroup.mouth = { kind: "river", targetId: <1本目 group id> }`。下流は別 group。
  `mesh.ts validate` の river 連続性チェックはそのまま通る（共有頂点は実頂点）。
- `meander` / `corridorPull` / `widthScale` を `walkRiver` / `resampleWidths` に直結。
- `applyPlan` の river group 化（`polylineToVertexPath`）は既存のまま。
- `◀/▶` の `generateRiverWalkStep` は既存のまま（複数河川スクラブ対応済み）。

**受入条件**

- `count` どおりの本数。`passage` 別に `classifyRiver` の bank 成分数が変わる
  （`through` で市街が 2 成分に割れる）。
- `meander` を上げると walk の総折れ角が単調増加。
- `confluence:true` で 2 本目の `mouth.vertexId` が 1 本目の頂点列に含まれる。
- どの設定でも `RiverGroup` は water face 接続頂点／map boundary／他 River 終端以外で
  終わらない（`validate` エラー 0）。水域内に導出 edge を持たない。
- `tsc` 0・`biome`・`vitest` 全緑。

**テスト**：`gen/rivers.test.ts`（上記）、`riverPath.test.ts` 相当の移植テスト緑。

## Phase G5 — セル辺の平滑化仕上げ

**目的**：`towngen-comparison.md §2.6 / §3.F`。街路に乗っていない街区境界のカクカクを緩和。
※ G1 が効いていれば影響は小さい ── **まず計測してから着手**。

**手本**：`Model.buildStreets` の `smoothStreet`＝`smoothVertexEq(3)` を共有 `Point` へ書き戻す
[Model.ts:293-298, 334-336]。

**対象**：`core/gen/streets.ts`（`foldArteriesIntoCells` 相当）、`core/gen/edgeGraph.ts`
（`smoothPath` の f 調整）、`core/features.ts`（`smoothFeatureGroup` の generate 直後自動適用）。

**アプローチ**

1. まず G1 後の実メッシュで「街路非接触の短辺総長」「街区境界の総折れ角」を計測ログ。
   改善余地が小さければこのフェーズは skip 判断。
2. `smoothPath` 既定を 2 → 3 反復、または `f` を TownGen の 3 に
   （`(p[i-1] + 3p[i] + p[i+1])/5`）。
3. `runPlan` の S5 後：平滑化した artery/street 頂点を対応メッシュ頂点へ書き戻す。City Editor の
   route は `EdgeRef[]` / 頂点列なので、`smoothFeatureGroup`（`features.ts`）を road/wall/river
   グループへ generate 直後に自動適用する形が最小変更。reserved（border/citadel/gate/river/coast）は
   `pinnedSmoothingVertices` で固定（既存）。
4. 必要なら reserved 以外の全 interior 頂点へ弱 Laplacian 1〜2 パス（新規 `gen/relaxMesh.ts`）。

**受入条件**：街区境界の総折れ角が計測で有意に減少（目安 −30% 以上）、reserved 頂点が不動、
feature group の連続性・`validate` エラー 0、undo 復元。`vitest` 全緑。

**テスト**：`gen/streets.test.ts` 追記（fold 後に street 頂点とメッシュ頂点が一致、reserved 不動）。
