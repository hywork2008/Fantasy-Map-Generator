# 郊外土地利用および街道沿い景観の再定義 設計書

## 1. 背景と課題認識

### 1.1 現状の実装における課題
City Editor（CE）における城壁外（`settlement === "outskirts"`）の土地利用には、以下の構造的課題が存在していた：
1. **網目状の「下書き小道（lanes）」の乱雑な散乱**:
   粗いVoronoiメッシュ/Evolutionメッシュのセル境界や到達性キューに基づき、城内と同様のアルゴリズムで細い路地が網の目状に引かれていた。その結果、本来は一本道であるべき街道の周りに不自然な袋小路や路地網が広がっていた。
2. **不規則・無秩序な住宅パッキング**:
   小道に沿って都市内部と同じテラスハウス（連続住宅）が郊外セル全面に詰め込まれ、中世特有の「街道直付けのまばらな沿道集落」の風情が失われていた。
3. **セル単位で唐突に出現する畑**:
   `ward === "farm"` が確率で割り振られたセル全体に、いきなり境界線もなく縞模様の畝（`openFieldPlots`）が敷き詰められ、街道や城門との位置関係に必然性がなかった。
4. **街道接続先（ApproachBeyond）との非連動**:
   `CityEditorPage.ts` 上で街道ごとに「その先が自国なのか、敵国なのか、同盟国なのか、どの程度の規模の都市があるのか」が詳細に設定・評価可能であるにもかかわらず、その情報が郊外の景観に全く反映されていなかった。

## 2. 中世ヨーロッパ都市周辺の史実背景

中世後期の西欧・中欧における城壁都市周辺の景観は、「防衛の必要性」「都市の市場経済（生鮮品物流）」「伝統的な農業構造」によって、城門と街道を中心とした同心円・リボン状の明快なグラデーションを形成していた。

### ① 防衛クリアランスゾーン（グラシス / 堀周辺）
* **史実**: 城壁および城門の直下（数十〜100m程度）は、防衛側が射界と見通しを確保し、敵軍の伏兵や攻城兵器の接近を早期に発見するため、高木や恒久的な建造物の建築が厳しく禁止されていた。
* **景観**: 水堀・空堀、または放牧草地・見通しの良い芝地（Glacis）。

### ② 街道沿い城外集落（フォールブール / Vorstadt / Faubourg）
* **史実**: 城門を抜けた主要街道沿いには、自然発生的な「リボン状集落（Ribbon development）」が形成された。城壁内は地価が高く、入市税（関税）や門限があったため、以下の施設が街道直付けで並んだ：
  * 商人・旅人向けの**宿屋、馬宿、酒場**
  * 荷車修理、**鍛冶屋**
  * 火災・悪臭リスクのため城内を追われた産業（**皮なめし、染物、レンガ窯**）
  * 衛生上の隔離施設（ハンセン病療養所、施療院）

### ③ 近郊菜園・果樹園（Kitchen Gardens / Enclosed Plots）
* **史実**: 集落の裏手や街道沿いには、主食穀物畑ではなく**「生鮮野菜の菜園」「果樹園」「ブドウ畑」**が広がっていた。
  * **理由**: キャベツ、豆、根菜、果物などの生鮮品は日持ちせず、毎朝都市の市場へ運ぶ必要があったため（近郊園芸）。
  * 都市から排出される大量の人馬の糞尿や有機ゴミを堆肥として手軽に搬出・還元できる場所でもあった。
  * 通行人や放牧家畜の食害・踏み荒らしを防ぐため、**生垣（Hedgerow）や石積み、木製フェンスで囲われた小区画（Enclosures）**となっていた。

### ③ 広大な開放耕地（Open Fields / Strip Farming）
* **史実**: 街道から一歩離れた平野部には、小麦・ライ麦・大麦などを育てる**三圃式農業に基づく広大な開放耕地**が広がっていた。
* **景観**: 境界フェンスのない広大な敷地の中に、**細長い短冊状の畝（Ridge-and-furrow / Furlong）**が整然と並び、プラウ（有輪犂）の旋回を減らすための長大な直線パターンを描いていた。

## 3. 街道接続先（Beyond）に基づく「4つの開発プロファイル」

各街道の `group.beyond` を既存の評価ロジック `evaluateApproachBeyond()` で解析し、得られる「有用性（utilityLevel）」と「防衛脅威度（defenseLevel）」から、沿道の土地利用を4つのプロファイルに分類する。

| プロファイル | 判定条件 | 沿道集落（住宅） | 近郊菜園 | 開放耕地 | 防衛クリアランス |
| :--- | :--- | :--- | :--- | :--- | :--- |
| **A. 幹線交易路<br>(Trade Highway)** | 有用度: high / critical<br>脅威度: safe / low / medium | 長大なリボン集落<br>（門から150〜200m、宿・店が密に連続） | 集落裏手および直後に生垣菜園（幅30m） | 菜園の外側に展開（幅90m） | 標準（25m） |
| **B. 穀倉供給路<br>(Granary Road)** | 役割: granary<br>または 規模: village | 小規模な農家・納屋・集積所（数軒のみ、長さ50m） | 沿道沿いに小規模（幅30m、長さ100m） | **主役**：街道両脇を埋め尽くす長大な畝（幅140m以上） | 標準（25m） |
| **C. 軍事最前線・敵国警戒路<br>(Frontier / Threat)** | 脅威度: critical / high<br>（Enemy, Rival, 要塞など） | **完全排除（0軒）**<br>奇襲防止・視界確保のため建築厳禁 | なし | 作物は作らず低草地・放牧地（荒地） | **大幅拡大（70m）** |
| **D. 地方閑散路<br>(Rural Byway)** | その他<br>（過疎村、中立国、小集落） | まばらな開拓農家（数軒、長さ60m） | 沿道に小さなパッチ状菜園 | 中規模な開放耕地 | やや広め（30m） |

## 4. 空間ゾーニングモデル

街道ポリラインを中心軸（基準線）とし、法線方向へのオフセット帯（バッファ領域）によって空間を美しくゾーニングする。

```
                    [ マップ外縁 / 街道の先 (Beyond) ]
                                    ▲
                                    │ 街道 (Road)
                                    │
    ┌───────────────────────────────┼───────────────────────────────┐
    │     Zone 3: 広大な穀物畑      │     Zone 3: 広大な穀物畑      │ (開放耕地: 長大な畝)
    ├───────────────┬───────────────┼───────────────┬───────────────┤
    │ Zone 2:       │ Zone 1:       │ Zone 1:       │ Zone 2:       │
    │ 生垣菜園      │ 沿道リボン集落│ 沿道リボン集落│ 生垣菜園      │ (近郊園芸 / 宿・鍛冶屋)
    └───────────────┴───────┬───────┴───────┬───────┴───────────────┘
                            │ 街道          │
    [           Zone 0: 防衛クリアランス (無建築・堀・低草地)          ]
    ════════════════════════╪═══════════════╪════════════════════════
                            [ 城門 (Gate) ]
                            [ 外壁 (City Wall) ]
```

### ゾーン定義詳細
1. **Zone 0（防衛クリアランス / 0〜25〜70m）**:
   * 城壁および城門から一定距離内は、いかなる建物・畑も配置しない。
   * プロファイルC（敵国）ではクリアランス幅を 70m に拡大。
2. **Zone 1（沿道リボン集落 / 路肩オフセット + 0〜15m）**:
   * 街道の左右両側に、街道中心線から幅オフセット（道幅/2 + 1.2m）を空けて配置。
   * 街道にファサードを向けた短冊状の建物ロット。網目小道は作らず、直接街道にアクセスする。
3. **Zone 2（近郊菜園・果樹園 / 路肩オフセット + 15〜45m）**:
   * 集落の裏手、または集落が終わった直後の沿道。
   * 生垣で囲われた長方形・台形の小区画の中に、密な畝（間隔 2.5〜3.0m）を描画。
4. **Zone 3（開放耕地・大穀物畑 / 街道から 45〜150m）**:
   * 街道から奥まった領域、または郊外深部。
   * 街道と並行または緩やかに沿う長大な短冊区画に、幅4mの畝（Furlong）を整然と配置。
5. **Zone 4（自然草地・荒地・氾濫原）**:
   * 畑や集落の及ばない領域、川の氾濫原、敵国側のクリアランス外部。

## 5. 生成パイプライン・幾何アルゴリズム設計

### 5.1 街道ポリラインサンプリング
1. `externalGateRoads(document)` から外壁門と接続する街道グループを取得。
2. 頂点列を「城門頂点 → マップ外縁」の順序に整流化。
3. 累積アーク長 $s$ をパラメータとするサンプリング関数を作成し、任意地点での位置 $P(s)$、接線ベクトル $T(s)$、法線ベクトル $N(s)$ を算出。

### 5.2 建築物・農地の配置ロジック
* **建物（BuildingLot）**:
  * 進行距離 $s \in [\text{glacisDistance}, \text{glacisDistance} + \text{villageLength}]$ の範囲でステップ。
  * 左右両側（側ベクトル $\pm N(s)$）に、間口 $10\sim 14\text{m}$、奥行き $12\sim 16\text{m}$ の長方形ポリゴンを生成。
  * `landmark: false, role: "main"` を付与し、重心の属する outskirts face の `faceId` を紐づけ。
* **近郊菜園（Kitchen Gardens）**:
  * 集落裏手または沿道に、幅 $20\sim 30\text{m}$、奥行き $18\sim 25\text{m}$ の囲い地ポリゴンを生成。
  * 内部に接線方向に沿った密な畝線分（rows: Point[][]）を生成。
* **開放耕地（Open Fields）**:
  * 菜園の外側に、幅 $35\sim 60\text{m}$、奥行き $60\sim 120\text{m}$ の長大な短冊ポリゴンを生成。
  * 内部に長大な畝線分を生成し、`FarmPlot` として `fabric.farms` に格納。

### 5.3 安全判定とクリッピング
* マップ境界（`[-extent/2, extent/2]`）の範囲内にクリップ。
* 水域（海・湖）ポリゴンとの内包判定。
* 城壁（wall）セグメントとの交差判定。
* 河川（river）の中心線から `width / 2 + 3`m のバッファを確保。

## 6. 反省点と今後の改善課題（Retrospective）

今回の実装・試作において「出来栄えが不十分」となった要因の分析と、今後の設計で考慮すべき課題：

1. **街道追従幾何とメッシュ（Face/Voronoi）の二重構造**:
   * メッシュのfaceを無視してポリラインから直接長方形の建物・畑を配置したため、既存のCity Editorの「街区（Block）」「区画（Parcel）」「スタイル描画」のシステムと幾何学的に乖離し、浮いて見えてしまった点。
2. **有機的な揺らぎと土地適応の不足**:
   * 単純なオフセット計算による長方形配置にとどまり、地形の等高線、既存の川の蛇行、道自身の曲がり具合に対する有機的な変形（Distortion）が不足していた点。
3. **生垣（Hedgerow）や側溝（Ditch）の独立した視覚表現の欠落**:
   * 中世の景観において重要である「畑と街道を隔てる生垣」「区画の境界フェンス」が単なるポリゴン外枠として描画され、視覚的な説得力（テクスチャ・線幅・影など）が伴わなかった点。
4. **都市内部の密度との対比バランス**:
   * 城壁直下のクリアランスとリボン集落の接続部において、城内の高密度な中世市街地との質感の連続性・コントラストの調整が不十分であった点。

本設計書の内容（史実背景、Beyondプロファイル分類、4層ゾーニング構想）を基礎資料とし、将来の郊外生成アルゴリズム刷新時に上記課題を克服した再設計を行う。

## 7. 市街地コアの確保方式の比較（2026-10-02）

Generateパネルの「市街地コアの確保方式」で切り替える。`GenerationSettings.urbanCoreMode` は `legacy`（従来方式）と `compact`（都市中心部に限定）の2種類。未設定は従来方式で、旧JSON・共有リンクの挙動を維持する。設定は履歴、生成レシピ、共有リンクへ保存する。

修正版は中心からの距離を基準に、半径内の陸セルだけを連結して確保する。目標半径は `cityRadiusMeters * sqrt(城壁内面積割合)`（城壁なしは割合1）。街道方向への引っ張り、対岸の優先度差、郊外リボンの追加、Evolutionの外周剥離を使わない。粗いセル・水域・連結性により輪郭は真円にはならない。`nPatches` は半径内のセル数の上限として使える。

中心部から広場・城郭などの自動配置候補を計画し、③の強調表示も中心部だけを対象とする。手動固定・ロック済みの施設は従来通り保護する。城壁はこの中心部の境界から計画し、既存の河川回避・横断処理を続ける。修正版だけで河川との重なりや全生成失敗が解消することを保証するものではない。

修正版では従来の広い郊外住宅帯をコア確保と一緒に予約しない。郊外の建物・農地は街道と実際の城壁を基準にする土地利用処理が担当する。従来方式は変更せず比較用に残す。
