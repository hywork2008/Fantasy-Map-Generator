# CE アーキテクチャ・リファクタリングのロードマップ

作成日: 2026-10-13
状態: Phase 0完了（2026-10-13）。Phase 1以降は未着手。

Phase 0の成果・既存失敗・基準データは [調査記録](../reviews/1013-ce-refactoring-phase0.md) を参照する。

設計基準は [CEアーキテクチャ規約](../architecture.md)。本書は実装工程と検証・完了条件を管理する。各チェック項目は、コードと検証結果が揃った時に更新する。日数や機械的な行数削減を完了条件にしない。

## 対象と制約

調査時点の主要対象は `core/generate.ts`（6,448行）、`ui/CityEditorPage.ts`（6,368行）、`render/svg.ts`（4,085行）。この数値は2026-10-13の基準であり、現状は各フェーズ開始時に再確認する。ほかのCEファイルも責務・依存に応じて移行する。fixtureや静的データの長さを分割目標にしない。

CEのMPA境界、公開API、保存形式、生成結果を維持する。廃止予定CGのソースは調査・変更しない。橋の規約と共通判定を維持する。アルゴリズム改善、型付き配列への全面移行、DOM構築方式の全面変更、FMG本体への統合は別案件とする。

各フェーズはレビュー可能な小さな変更へ分割する。各変更で動作する状態を保ち、移動・抽出と挙動変更を同じ変更へ混ぜない。

## Phase 1: 低結合の契約・設定・補助処理の抽出

前提: Phase 0。

- [ ] 共有型と内部型を分類し、設定の初期値・正規化、段階定義を抽出する。
- [ ] 独立したメッシュ変換・境界計算を用途に合う生成モジュールへ抽出する。
- [ ] `generate.ts` の既存公開exportを互換窓口として維持する。
- [ ] 新モジュールから互換窓口への逆importを禁止する。

完了条件: 既存利用者が動作し、設定・段階選択・代表生成結果が基準と一致する。新設モジュールにUI依存・循環依存がない。

## Phase 2: 計画処理と生成パイプラインの分割

前提: Phase 1。

- [ ] `runPlan` を地形・都市域・城壁・道路等の意味のある工程に分ける。
- [ ] `pipeline.ts` が工程順序を明示し、各工程の前提・入出力を定義する。
- [ ] 大きな `Plan` の引数を、必要な工程ごとの契約へ段階的に限定する。
- [ ] RNG、走査順、ID、observer通知の順序・内容を維持する。

完了条件: 計画処理をUIなしで実行でき、代表ケースの計画と生成結果が基準に一致する。分割による全体clone・重複計算が増えていない。

## Phase 3: 文書反映・道路完成・再試行の分割

- [ ] 段階プレビューの生成データと、そのキャッシュの解除地点を整理する。

完了条件: 失敗試行が入力や次の試行を汚染せず、固定要素・輸入道路・橋・城壁の契約を維持する。完全生成と各段階プレビューの対応が維持される。橋の閾値・判定が共通規約に集約されている。

## Phase 4: 描画責務の分離

前提: Phase 3。

- [ ] `svg.ts` の建物・水車・渡し船等の生成呼出しを調査し、都市の事実と描画専用計算に分類する。
- [ ] 都市の事実を決める処理を生成または明示的な読み取り専用準備工程へ分離する。
- [ ] 水辺施設、城壁・堀、道路、ランドマーク等の描画を責務別に抽出する。
- [ ] 選択・ホバー・計測・プレビューをoverlaysへ分ける。
- [ ] SVG形状計算とDOM書込、SVG構築と出力調停を分ける。
- [ ] 派生キャッシュのキー・無効化・破棄を定める。保存形式への追加は別変更とする。

完了条件: 描画の前後で文書が変わらず、再描画で要素が蓄積しない。レイヤー順、選択判定、描画品質、単独SVG出力が維持される。代表ケースで再計算と描画性能を確認する。

## Phase 5: UI・編集操作・ライフサイクルの分離

前提: Phase 4。Phase 1以降に独立した小さなUI部品を先行抽出してもよい。

- [ ] Worker・timer・observerのキャンセルと古い結果の反映禁止を確認する。

完了条件: パネルを繰り返し開閉してもlistenerや処理が増えない。閉じても設定を失わず、終了後の非同期処理がDOM・文書へ反映されない。編集・undo/redo・Worker・FMGからのCE起動が維持される。

## 検証の運用

既存手順は [CEテスト](../../tools/ce-test.md) と [CE性能計測](../../tools/ce-performance.md) を参照する。変更範囲のテストから始め、各フェーズ完了時と最終段階で必要な範囲へ広げる。

- CEテストの既存手順: `npx vitest run city-editor --maxWorkers=4`
- 型検査: `npx tsc --noEmit`
- アーキテクチャ検査: `npm run lint:architecture`（CEへの適用範囲はPhase 0/6で確認する）

SVG文字列が変わる場合は原因を確認する。属性順等の非意味差分だけを明示的に除外できるが、ID、座標、レイヤー順、接続、保存値の差を一括正規化して隠さない。決定論・読み取り専用・保存往復・終了後の反映禁止には必要な境界テストを追加する。

各変更の記録には、対象責務、維持する契約、実行した検証、残る互換窓口、追加した長寿命参照の所有者と解除地点を記載する。性能改善が必要と判明した場合は、計測結果を付けて別変更として扱う。
