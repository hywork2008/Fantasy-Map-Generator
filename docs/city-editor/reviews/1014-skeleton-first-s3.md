# 骨格先行生成 Phase S3: 後段の接続とUI

実施日: 2026-10-14
対象: [設計書](../plan/skeleton-first-generation.md) Phase S3
前段: [S2記録](1014-skeleton-first-s2.md)

## 1. 完成した経路

生成パネルに「生成方法」を追加した。既定は従来のメッシュ先行のまま。骨格先行では、外壁の形（自動・有機形・円・楕円・方形・多角形）と多角形の辺数を指定できる。

`generateCityOnDocument` の外側の試行・recipe保存・住宅数の調整を共用し、骨格先行の試行では次の経路を使う。

1. `prepareRun(..., false)` で地形とprogrammeを取得する。入力メッシュのセル化は行わない。
2. `skeleton/toPlan.ts` の `prepareSkeletonRun` と `planSkeletonCity` がK1〜K6を実行し、海、都市域、外壁、門、河川と後段の中間値を作る。
3. 既存の `planRoads` を街路計画とward入力に使い、`planWards` で地区を割り当てる。K4の確定道路・門は仮の道路計画で置換しない。
4. `applyPlan` の骨格用分岐で `applyTerrain` を共用し、`assembly/skeleton.ts` がK6の対応表から壁・川・道路・門を直接反映する。城壁・門・川を再探索・変形する旧assembly工程は通さない。
5. 既存の幾何仕上げ、寺院、fabric、外部道路の意味付け、農地、墓地、港、建物の当てはめを実行する。完成後は既存の編集・undo/redo・描画経路を使う。

文書の `gridKind` は `evolution`、recipeのalgorithmは `skeleton-city-v1`。recipeに方法・壁形状・入力文書・seedを保存する。旧algorithmと方法未指定のrecipeは従来のまま再生する。

保存codecのalgorithm許可と設定検証、共有リンクの設定読込、読込時の生成設定復元も更新した。古いrecipeや共有リンクを開いた際は、新方式の設定が前の文書から残らない。

Worker要求は既存の `GenerationSettings` をそのまま転送するため、通信形式の追加はない。実ブラウザーでWorkerによる方形城壁の完成都市生成を確認した。

## 2. UI・段階プレビュー

- K1入力、K2都市核、K3外壁、K4交差、K5検証、K6メッシュを別の段階一覧に追加した。K1〜K5は空のメッシュに骨格の線を重ね、K6から新しいメッシュを表示する。その後に地区・中心道路・街路・仕上げ・街区・建物・隠蔽が続く（計13段階）。
- 地区の1セルずつのプレビューも骨格先行の計画を使い、メッシュを作り替えながらスクラブしない。
- 文書パネルと生成パネルに、文書パネルのグリッド選択を使わず新しいメッシュを作る旨を表示する。
- 城、二重城壁、堀、Bram/circulade、旧都市域割当・nPatches、別の道路端点指定などの未対応設定は、選択肢・コントロールを理由付きで無効にする。未対応の設定が現在有効なら、まず設定を変更するまで骨格先行の選択肢を無効にする。APIからの要求にも `unsupported-skeleton-settings` を返す。
- 単独生成の初期UIは二重城壁なので、「Town walls / Town walls rings」をSingleにしてから骨格先行を選ぶ。新方式で暗黙の歴史的壁数を読む場合は、対応範囲の単一城壁として表示・生成する。明示的な二重城壁の要求は受け付けない。
- 稜堡式は後続対応の選択肢として無効表示する。未実装の形を別の形に置き換えない。

## 3. S2からの引継ぎと接続で判明した問題

### 3.1 細小面と短い辺

制約に囲まれた1㎡未満の面は、位相を維持して建築対象から外す。完成した `skeleton-city-v1` 文書だけ、検証の面積下限を非建築面で1e-8㎡、辺長下限を1e-5mとする。自己交差は別途検証する。旧文書の1㎡・1mの下限は変えない。保存形式にフィールドは追加していない。

完成文書を返す直前にも `validate` を実行する。道路の不連続などを残して成功扱いにしない。メッシュ置換時は古いfabric・墓地・固定交差への編集済み接続など、旧メッシュに依存する派生情報を持ち越さない。

### 3.2 河川の中心線とFMGの所有権

編集可能な川を反映するには中心線の辺も必要だったため、K6に川岸に加えて中心線の制約を追加した。

ただし、FMGの測量済み河川（fixedCrossings schema 2以降）は、既存の `siteToGeography` と同じ所有規則で扱う。中心線は骨格計算用に保持するが、測量済み水域の上に2本目の編集可能な川を描かない。

Nemyshlでは、簡略化した中心線から求める角度が36.8°、FMGの固定交差の角度は上限内だった。2本目の川を作ると本来の固定交差と別の橋を推定して不採用になった。測量済み水域・橋の入力をそのまま保持する経路へ直し、元の固定道路・交差を変更せず生成・保存できることをfixtureで検証した。橋の上限を緩めていない。

### 3.3 小さな歴史的城壁

Newleighbuなどでは、歴史的な城内面積の割合を適用すると、元の区画寸法でK5の「4区画以上」を満たせなかった。壁の割合やK5の判定を無視せず、新メッシュの種点間隔を必要に応じて細かくする。名目城内面積に5区画が入る間隔を上限とする。完成生成とプレビューで同じ入力正規化を共用する。

比較セットでは9都市が対象だった。該当都市を全件再計測し、生成・検証・再読込が成功した。

### 3.4 枠を出る道路

橋の迂回で窓を出て再入する道路は、K6では複数の `runs` になる。これを平坦な1本の辺列として使うと `Road is not contiguous` が生じた。都市核側から最初に枠へ出る連続区間を編集可能な道路にし、枠外の別区間を無理につながない。tiny川2本のseed 6を回帰テストにした。

### 3.5 墓地の再配置の費用

K6の細かな面を、既存の墓地再配置が多数の候補として調べていた。Hongoをprofilerで確認し、必要な墓地面積に届かない面を境界の計算前に除外する候補集合を、骨格先行だけから渡すようにした。旧方式の候補集合は変更しない。なお、これでも一部のFMG都市は遅く、全体の速度改善を達成したとはしない（§5）。

## 4. 後段の修復処理の診断

`finishSkeletonGeometry` は骨格の頂点を一時的に固定し、各処理の前後で制約の座標・辺の端点・featureGroupを比較する。固定は保存しない。制約やfeatureGroupを変更する修復結果は採用せず、診断に残す。

| 診断 | 単独生成の実行数 | FMG v1対象の実行数 | 制約・featureGroupの変更 |
| --- | ---: | ---: | --- |
| 測量済み河川による壁の切取り | 151 | 86 | 0 |
| 幾何仕上げ（制約頂点を一時固定） | 151 | 86 | 0 |
| 橋の直角化 | 151 | 86 | 0 |
| 門・橋の交差修復 | 151 | 86 | 0 |

単独生成の151回には、後の交差検証で不採用になった試行も含む。全ての完成候補で、骨格の制約を変更する修復はなかった。

メッシュ先行の壁平滑化・河口の開口・壁と川の再経路探索は呼ばない。主要道路のshortcut、新しい河川横断の追加、FMGの接続を後から曲げ直す処理も骨格先行では呼ばない。これらはK4で確定した道路・交差を変更する工程なので、対応表から直接反映する経路の責務に移した。

## 7. 再現手順

`--complete` を検査用CLIに追加した。生成時間、外側の試行番号、骨格の試行数、不採用理由、完成文書の検証・再読込、修復処理の診断をJSONLに記録する。

```sh
node --import tsx scripts/city-editor/skeleton/skeletonLab.ts \
  --out temp/s3/reproduce-standalone.jsonl --seeds 12 --complete \
  --settings '{"generationMethod":"skeleton-first"}' --svg none
node --import tsx scripts/city-editor/skeleton/skeletonLab.ts \
  --out temp/s3/reproduce-fmg.jsonl --csv temp/s0/triviers-inputs.csv \
  --burg "$(cat temp/s0/sample-ids.txt)" --complete \
  --settings '{"generationMethod":"skeleton-first"}' --svg none
npx vitest run src/city-editor/generators/generation/skeleton \
  src/city-editor/components/CityEditorPage.skeleton.test.ts --maxWorkers=2
npx tsc --noEmit
node --import tsx scripts/lint-architecture.ts
```

今回の集計用JSONLは `temp/s3/standalone-verified.jsonl` と `temp/s3/fmg-verified.jsonl`。前者は最終の単独計測と道路run修正後の川2本条件を、後者は最終のFMG計測と細分化・測量済み河川の対象都市の再計測を組み合わせたもの。`temp/` はGit管理外。回帰用Nemyshl入力は `data/fixtures/nemyshl-20261014.json` に保存した。
