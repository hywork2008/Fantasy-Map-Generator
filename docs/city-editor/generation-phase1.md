# 都市生成：第1段階の実装結果

2026-09-17。粗い骨格グリッドと面内の路地・建物生成へ移行するための診断・共通基盤。

## 変更した動作

- 市街地の自動判定は、連結した陸地を実際のポリゴン面積で累積し、`π R²` に達すると止まる。疎密のあるevolutionでも外周の大きなセルに平均面積を引き上げられない。目標の超過は最後の一面分未満。利用可能な連結陸地が不足した場合はそこで終了する。`urbanNPatches` を指定した診断操作は従来どおりセル数で止まる。
- 工程送りは追加セル順だけを保持し、指定されたステップの累積集合を復元する。履歴メモリはO(U²)からO(U)へ。完成生成ではこの履歴を記録しない。
- ブラウザの一括生成と「新しい都市」は専用Workerで実行し、工程表示とキャンセルボタンを出す。キャンセルはWorkerを終了し、元の図面・履歴を保つ。生成中の編集を抑止し、結果到着時にも入力が変わっていないことを確認する。画面の破棄時にもWorkerを終了する。
- 辺検索の索引を、建物生成・Hex整形・共有頂点の平滑化に導入した。索引は各処理内で作成し、トポロジー変更をまたいで再利用しない。可変メッシュに対するグローバルキャッシュは設けない。
- 面積判定変更で検出された回帰を修正した。診断道路が開通不能な河川交点に達した場合は最長の安全な区間を残す。Voronoi整形では直前の面積だけでなく、平滑化前の面積に対する下限も確認する。
- ビルド検証で見つかったCE内の型不整合も修正した。任意の面中心の代替値、橋の型判定、インスペクタの面・辺・建物属性などが対象。

内部路地用のメッシュ細分化は追加していない。骨格改善と、面内で路地・建物を一緒に作る処理は第2段階以降。

## 計測方法

```sh
node --import tsx scripts/benchmarkCityEditor.ts \
  --sizes=small,medium,large \
  --grids=hex,voronoi,evolution \
  --terrains=inland,river,coast \
  --seed=phase1-reference \
  --timeout=20000 \
  --out=/tmp/ce-phase1-final
```

各ケースを独立プロセスで実行する。出力は集計 `report.json`、生成工程の `*-progress.json`、③④⑤および完成図のSVG。タイムアウトは格子作成・診断段階・完成生成・描画を含むケース全体の上限であり、「完成生成だけで20秒」とは解釈しない。処理途中まで生成できたSVGも残る。

集計には格子作成時間、完成生成時間、描画時間、面数・辺数・建物数、建築可能な陸地面積、住宅系の空街区率、道路の最大迂回率、門の対向接続数、メッシュ検証結果を含む。門の対向接続数は交点での局所検証であり、都市全体への到達性を保証する指標ではない。建築可能面積には城外の沿道領域も含み、都市コアの目標面積とは異なる。

コアAPI `generateCityOnDocument` の第4引数で工程観測コールバックを指定できる。`plan-total` / `apply-total` は内訳と重複する集計値なので、全レコードを単純加算しない。工程時間には同期観測処理などの計測負荷が一部含まれる。

UIではルート要素の `city-generation-diagnostics` イベントで生成サンプル配列、`city-render-diagnostics` で描画サンプルを取得できる。これらは保存JSONやUndo履歴に入らない。生成の進捗は工程の完了通知で、百分率ではない。

## 今回の計測結果

固定シードの27ケース中23ケースが完了、4ケースがケース全体20秒の制限に到達。SVGを103枚出力した。出力先は `/tmp/ce-phase1-final`。Node/jsdomの単発計測で、一部はテスト・ビルドと同時実行しているため、ブラウザ性能の保証や厳密な前後比較ではない。

| 条件 | 完成生成 | SVG生成・保存 | 建物数 |
| --- | ---: | ---: | ---: |
| Small evolution・内陸 | 約50ms | 約36ms | 869 |
| Large evolution・内陸 | 約41ms | 約286ms | 16,323 |
| Large evolution・河川 | 約59ms | 約427ms | 20,321 |
| Medium Voronoi・河川 | 約16,051ms | 約253ms | 5,786 |

Large Hex・河川は壁交差点処理後、Large Voronoi・内陸／海岸は平滑化後の街区整形中、Large Voronoi・河川は診断工程中に時間制限へ到達した。Medium Voronoi・内陸でも完成生成約3.85秒のうちVoronoi整形が約2.99秒。骨格面数削減のほか、粗い面へ現行整形を適用するかどうかの見直しが次段階の焦点になる。

面積判定の単独比較では、事前調査と同じ `analysis-grid` のSmall evolution、半径396×0.92mで、実市街地面積が165,620m²から421,761m²へ改善した。目標416,981m²に対して約1.1%の超過で、最後の一面分未満。セル数は34から57へ変わったが、元のグリッドを細分化したわけではない。

辺検索の独立計測（Large Voronoi、26,536辺、100検索）では、全走査約351msに対して索引作成込み約13ms。これは辺検索のみの結果で、完成生成全体の高速化率ではない。

## 検証と制限

- City Editorの全316テストが成功（`vitest run src/city-editor --maxWorkers=2`）。面積の到達・超過限界、陸地不足、明示セル数、決定性、門・橋・建物、工程送り、Workerの完了・キャンセル・エラー、UIのキャンセルとUndoを含む。
- `npm run build` が成功。Worker用の独立アセットも生成された。
- 実ブラウザの接続先が利用できなかったため、Workerの実ブラウザ動作とスクリーンショットの目視確認は未実施。UIテストはjsdomとWorker代替を使用し、SVGは診断用成果物として出力した。
- Worker化の対象は一括生成。①〜⑥の診断操作、建物導出とSVG DOM作成は引き続きメインスレッドで行う。完成図の描画が重い場合は一時停止が残る。
- 面積による判定で、同じシードでも以前と異なる都市になる。巨大な境界セルの部分分割や、市街地外形の改善はまだ行わない。
- グリッド面数が多いLargeを高速化しきる段階ではない。工程計測と中断手段を用意し、次の骨格グリッド設計へ進むための基盤とする。
