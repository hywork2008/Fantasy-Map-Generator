# Grid evolution 自動生成：第2段階

## 実装した構成

Grid evolution の粗いメッシュを骨格として維持し、建物と路地を面内の派生形状として生成する。Largeでも路地や敷地を編集用メッシュへ追加しない。サイズによる実寸の拡大と建物の敷地面積から、同程度のセル数により多くの建物が入る。

- **骨格**：門・橋の接続に必要な面の対角線、主要街道の大きな迂回を解消する対角線だけを局所挿入する。橋は川岸付近で辺を分割し、遠いセル頂点まで橋として変形させない。交差条件と面の自己交差を検証する。
- **補正**：evolutionには細かなVoronoi街区向けの矩形化を適用しない。平滑化の回数と面積減少を制限する。
- **接道**：主要街道から到達できる面をたどり、共有境界に入口を作る。壁・川・固定境界を横切る入口は作らない。面の入口から路地を延ばし、路地に接する領域を再帰分割して建物を配置する。
- **凹面**：面内だけで凸領域に分解し、分解境界にも接続を作る。凹面全体を単一の凸カーネルへ縮めない。極小・細長い残余は建物にしない。
- **離隔と郊外**：壁・川・街道の幅を考慮して後退させる。川に近すぎる建物を除外する。城外の建物は実際の街道沿いに制限する。
- **保存**：`gridKind` と面の `settlement` を保存する。格子種別を持たない旧JSONは従来の生成を保つ。路地は描画時に導出し、道路のFeatureGroupやMesh.edgesには保存しない。

主要実装は `core/gen/blockInfill.ts`、`majorRoadShortcuts.ts`、`core/passages.ts`。Hexagonal / Voronoiは従来の建物生成経路を使用する。

## 検証

- City Editorの25ファイル・335テストが通過。
- 本番ビルド、変更TypeScriptファイルのBiome、差分の空白検査が通過。
- 3シード × 内陸・河川・海岸について、面の自己交差、門の接続、壁・川と道路の共有辺禁止、建物の面内配置・河川離隔を検証。
- 面内路地の連続性、隣接面への接続、凹面、固定境界、再現性、元データ非変更、JSON保存・読込、Undo / Redoを検証。
- SmallとLargeで初期面IDが同じこと、Largeの建物数が増えること、面内生成前後で骨格が変わらないことを検証。
- UIテストではevolutionの完成生成と再生成を確認。

完成SVGと実際のメッシュ辺を赤線で重ねたSVGを `temp/city-editor-phase2/` に保存した。`temp/redline/` のWatabou参考図と同様に、一つの赤いセル内に複数の建物群と路地が入ることを確認できる。Small河川・海岸図とLargeのセル拡大を画像として確認した。実ブラウザでの操作・描画時間は未測定。

## 残る第3段階

地区別の密度調整UI、農地の畝などの描画、地区単位のキャッシュと編集時の失効、低倍率の表示簡略化は今後の対象。現段階では路地・建物を描画時に再計算するため、Largeの詳細生成とSVG描画には建物数に応じた負荷が残る。アルゴリズム版を含む生成入力の完全な保存と、局所編集が無関係な地区へ及ぼす影響の制御も次段階で扱う。
