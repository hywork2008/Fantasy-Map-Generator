# City Editor の完成都市生成

## 操作

1. Document で地図サイズと格子を選び、🆕 で作成する。参照都市のような不規則な街区には **Voronoi** が向く。既存の Hexagonal / Grid evolution 格子にも対応する。
2. Generate で Coast、Rivers、walls / plaza / citadel / port などを選ぶ。港湾都市は Coast を `straight` または `bay`、Rivers を `1`、port を有効にする。
3. **🏘 都市を一括生成**で、城壁、門、城内外の街路、河川の横断箇所、地区、建物を生成する。
4. **🎲 新しい都市**で同じ入力格子・地形設定から別の都市を生成する。一括生成の再実行は元の入力格子を使い、繰り返し平滑化による縮小を防ぐ。
5. **街区の編集表示**、または道路・頂点・地区などの編集ツールで編集用の格子を表示する。Select に戻すと編集後の形状から建物を再計算する。

一括生成は Undo / Redo、JSON 保存・再読込に対応する。①〜⑥とステップ送りは工程の診断表示として残している。工程表示では完成図の仕上げを行わない。

## 実装

- `generateCityOnDocument` は City Editor 自身の生成器を使用する。既存格子を全面的に再生成せず、門と橋を開くための局所的な頂点統合・面分割を行う。
- 完成都市では両岸に市街地を置き、川の横断箇所を開いてから、変更後のメッシュ上で城外→門と門→広場を再経路探索する。道・壁・川の同一辺の重複を禁止し、海を避ける設定では水面に接する道路辺も除外する。
- 市街地の門方向への張り出しを連続的で弱いものに変更。海岸の距離も市街地の到達範囲に収めた。港側の壁は海壁指定を除いて開放する。
- `finishCityGeometry` は共有頂点を平滑化し、近隣街区に変位を伝える。道路の分岐・門の接続を保ち、各頂点移動時に辺の最小長、面の向きと面積、自己交差を検査する。ロックされた頂点・辺・面と手描きの経路は固定する。
- `buildingLots` は街区の内側を道幅・川幅・壁厚に応じて後退させ、長辺に沿う分割で建物区画と路地を作る。水面・公園・空地・予約された広場には建物を置かない。建物は別の固定形状として保存せず、街区から決定論的に導出する。
- 完成図は淡い地色、建物の輪郭、実線の城壁と塔・門、港の桟橋を描く。`appearance: "town"` を保存・履歴に含める。

## 検証と範囲

`gen/completeCity.test.ts` で内陸・直線海岸・湾・岬×3シード、水上配置の禁止、面の自己交差、門の接続、平滑化効果、決定性、ロック、保存と履歴を検査する。UI テストでも一括生成、表示切り替え、再実行、Undo / Redo を検査する。

固定サンプル（格子 `preview`、生成 `reference-town`、Small・内陸・河川なし）では、壁／道路の総絶対折れ角が仕上げ前に比べそれぞれ約93%／98%減少した。この値はサンプル固有で、全地形の保証値ではない。

大きな地図は生成・表示に時間がかかる。開発環境での Voronoi 格子作成を含む計測は Medium 約0.9秒、Large 約10.8秒だった。建物単体の直接編集、地区名の自動命名、参照画像の全装飾の再現は今回の対象外。

`temp/ce1` と `temp/ce2` の出力を見た目の参考にした独立 MIT 実装。TownGeneratorTS の GPL ソースや参照都市の座標を実装に取り込んでいない。開発停止済みの `src/city-generator` は変更していない。

## 門・水門・橋の接続条件

- 門の設置前に壁の隣接頂点を統合するか面を分割し、4辺以上の頂点を確保する。周囲の辺の角度順が壁→通路→壁→通路となることを必須にし、同じ側へ出る2辺は通路と認めない。④の門配置から局所的にメッシュが変わる。
- 壁と川が共有していた辺は削除して隙間にせず、両端を中央付近の1頂点へ統合する。壁2辺と川2辺が交互に集まる交点を維持する。完成図では川を壁の上に描き、川幅に沿って両側の壁を隠す。河道内には塔を描かない。
- 市街地を分断する河川では、通過可能な頂点を作った後、両岸へ伸びる2辺を実際の道路グループ（`gc:bridge-*`）として追加する。経路探索も対角の通路辺に制限する。
- 完成図の平滑化後に交点を再検査する。不完全な門、壁と川の辺の共有、対角でない交差、横断路のない市街地分断を含む結果は成功として返さない。不成立の配置は同じ設定・元の格子から決定論的に最大4案まで試す。
