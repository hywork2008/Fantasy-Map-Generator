# 世界誕生時点の家畜B1: 初期化の実装と固定点の確認（2026-10-29）

[設計書](../plan/livestock-world-birth-herds.md)§5のB1の記録。`src/extensions/economy/generators/worldBirthHerds.ts`の`settleWorldBirthHerds`を、Economyの地図生成の後と、一度も進めていない世界の読込時（`fmg:world-loaded`）に動かす。

1. 人の住むセルの管理された群れ（放牧・庭先）を、収容力の1.0倍で、落ち着いた年齢層（B0）で置く。
2. `DevelopmentPotential.replanWorldBirth`で、その群れに合わせて土地利用と仕事の割り当てを作り直す（年次の更新と同じ式。年の関門と土壌の1年の変化は使わない。ここでの開墾は世界の過去にあたるため、売る木材を生まない）。
3. 草地の合計の変化が1%未満になるまで1〜2を繰り返し（上限12回）、最後に群れを置き直す。
4. 各セルの干草小屋に、そのセルの干草の計画が誕生の月の初めに持つ量を入れる（`stockWorldBirthHay`、前年の夏に作った分）。これがないと、1月に生まれた世界は最初の冬に飢え、給与率の履歴が翌年の収容力を下げた（試行で1301年の牛の収容力が誕生時の0.68倍）。

一度だけ動き、経済のスライスに版を記録する。進めたことのある世界は、群れを置き直さず版だけを記録する。

    NODE_OPTIONS=--max-old-space-size=1900 node --import tsx scripts/auditWorldBirthHerds.mts docs/analytics/inputs/salt-s0-aligned-20261023/world-102.fmg docs/analytics/e1-world-birth-b1-20261029/world-1300-25.json 25 1,12,24

固定入力は進めたことのない世界なので、読込時に初期化が動く。新しく生成した地図での確認は、ヘッドレスのブラウザ（Playwright）がこの環境に入っておらず、できていない。

## 結果（World、千頭・百万ha）

| 時点 | 耕地 | 草地 | 牛 頭数/収容力 | 馬 | 羊 | 山羊 |
| --- | ---: | ---: | --- | --- | --- | --- |
| 変更前 読込直後 | 12.81 | 3.58 | 32 / 526 | 28 / 122 | 192 / 1,767 | 39 / 16 |
| 変更前 1302年1月 | 7.92 | 15.90 | 459 / 1,183 | 119 / 303 | 1,677 / 3,474 | 67 / 150 |
| 誕生時 | 8.20 | 15.65 | 1,245 / 1,245 | 317 / 317 | 3,901 / 3,901 | 147 / 147 |
| 1301年1月 | 7.86 | 15.69 | 1,308 / 1,181 | 330 / 299 | 4,078 / 3,602 | 152 / 129 |
| 1302年1月 | 7.89 | 15.94 | 1,306 / 1,255 | 329 / 317 | 4,026 / 3,701 | 149 / 140 |

- 草地は誕生時の15.65百万haから2年で+2%しか動かず、固定点に近い。変更前は1年目に3.6→14.0百万haへ組み替わっていた。
- 牛は誕生時から収容力の規模にあり、1302年1月に頭数/収容力1.04（年次更新の直後で、その年の子を含む。羊の落ち着いた値1.04〜1.08と同じ）。変更前の1302年は0.39、1312年でも0.75だった。
- 誕生時の繰り返しは、固定入力で約2分余計にかかる（読込から1か月目まで約2.5分）。
- 1301年1月の収容力は誕生時より5〜12%低い。干草を入れても最初の年に少し給与が足りていない（B3で飼料不足を確かめる）。

## テスト

- 単体テスト（`faunaPopulation.test.ts`）：誕生時の群れが収容力の1.0倍で、繁殖層が最も多く、2回目は動かない。
- 関連の単体テスト（faunaPopulation・developmentPotential・livestockFeed・husbandry・tickSystemOrder）117件成功。
- `goldenParity.node.test.ts`・`masterReference.node.test.ts`の3件は失敗するが、変更前（stash）でも同じ3件が失敗しており、この変更によるものではない。この変更で地図の生成時の群れと土地利用が変わるため、goldenを更新する時はこの変更を含めて取り直す必要がある。
