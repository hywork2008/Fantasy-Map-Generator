# 冬前屠畜W1: 生体・解体・保存食の経路と単位監査（2026-10-24）

[共通解体契約](../plan/winter-livestock-slaughter-and-preservation.md#11-w1の共通解体契約と単位照合2026-10-24)を具体化した。現行の生体→保存食と残頭→皮/獣脂は別経路であり、共通の個体由来記録はない。一方、工房が買った生体は市場在庫から引かれるため、同じ市場在庫を通常屠畜がそのまま再消費するという二重控除ではない。

今回、[監査スクリプト](../../scripts/auditSlaughterContracts.mts)と[結果JSON](winter-slaughter-contract-audit-20261024.json)を追加した。新規既定カタログと固定Province/Worldの読込後カタログを照合する。時間送り・prepare・屠畜・製造は実行せず、ロード時の既存移行/派生列修復は行われる。市場単位からの静的な換算であり、実生産量や歴史的歩留まりの観測ではない。ソースハッシュと入力SHA-256を結果に保存する。

## 1. 単位と現行レシピの矛盾

`goodMeasureCatalog.ts`の現行輸送用換算を使用。これは史料による家畜体重・肉量の校正値ではない。包装の風袋を含めない。商品名が一致しても保存カタログのunitが違う場合は換算をnullとし、数値を強制しない。

| 商品 | 現行の1市場単位 |
| --- | --- |
| Cattle / Sheep / Goats / Pig | 各1頭。輸送換算450 / 45 / 40 / 100kg |
| Horses | 25頭、輸送換算11,250kg。食用対象ではない |
| Tallow | 120L×0.9kg/L＝108kg/樽 |
| Leather | 1皮相当のroll、25kg/roll |
| Preserved food | 200/0.43＝465.116279kg/wain。barrelは包装区分であり、1 lot＝120Lという定義ではない |
| Salt | 60kg/bag |
| Rennet | 120L/barrel。適格胃1枚＝0.5L＝1/240barrel（通常の市場牛の適格性は不明） |

既定カタログと両固定入力で、下記の対象レシピ・単位は同じだった。

| 経路 | 入力の換算kg | 出力の換算kg | 判定 |
| --- | ---: | ---: | --- |
| 残頭の牛1頭→獣脂＋皮 | 450 | 360＋25＝385（丸め前） | 全生体重は超えないが、脂360kgを史実の脂量とは認定できない |
| 残頭の羊1頭→獣脂 | 45 | 216 | 入力超過171kg |
| 残頭の山羊1頭→獣脂 | 40 | 216 | 入力超過176kg |
| 残頭の豚1頭→獣脂 | 100 | 216 | 入力超過116kg |
| 牛0.25頭＋Salt1bag→保存食1wain | 172.5 | 465.116279 | 入力超過292.616279kg |
| 羊1頭＋Salt1bag→保存食1wain | 105 | 465.116279 | 入力超過360.116279kg |
| 豚1頭＋Salt1bag→保存食1wain | 160 | 465.116279 | 入力超過305.116279kg |

上の獣脂/皮は全量が有効な場合の旧カタログ上の条件付き出力で、`settleSlaughter`では樽数を小数2桁へ丸める。保存食は基礎1出力lotの比較で、酢を使う別レシピもJSONに記録した。現在`Preserved food`は`hasPhysicalWoodRecipe`に含まれ、技能等の倍率は作業速度側へ適用される。保存食の上記矛盾を出力倍率の二重掛けのせいにはしない。

これらは「輸送換算と旧レシピが物量契約として両立しない」という診断である。現行の家計食料台帳がこのkgをそのまま栄養へ加算しているという主張ではない。樽やwainの容量/単価を不足率に合わせて縮小して矛盾を隠さず、肉量・脂量・加工後出力を校正し、旧在庫の単位移行を分離する。

## 2. 実装経路の照合

| 境界 | 現行の処理 | 共通契約に必要な変更 |
| --- | --- | --- |
| セルの群れ→農村出力 | `drawDomesticatedFaunaOfftake`が年齢群を引き、返すのは市場頭数だけ | 引いた年齢群・実頭数・由来セルを渡す。市場到着時に群れをもう一度引かない |
| 引当後の倍率 | `production-utils.ts`は群れ控除後のamountへ`getModifiers`を掛ける | 倍率は引当前の候補量へ。制約後の実頭数を増幅しない |
| 農村出力のキャッシュ | `buildRuralProductionIndex`で群れ控除を伴う寄与を作り、四半期の量を月次再利用する | 意思決定に使う見積りと実引当を分け、キャッシュした実績を再搬入しない |
| 端数→整数の生体搬入 | 群れを引いた後、`rollLiveAnimalCatch`が市場/集荷町/商品単位で整数化する。元セル・年齢群は残らない | 実引当できた量を超える到着を作らない。端数/保留を物理在庫か期待値として明確に区別 |
| 市場→工房 | `Markets.buy`で在庫と支払を動かし、工房内の材料を製造時に消費 | 購入は所有移転、屠畜は生体消滅という別取引にする。購入だけで屠畜副産物を出さない |
| 生体直接の保存食/Tallow | 生体と塩等をレシピ入力として消費。別の皮・肉を同じ由来へ記録しない | 共通解体後に肉/脂を加工する。副産物を欲しい製品ごとにもう一度作らない |
| 通常屠畜 | `settleSlaughter`が工房処理後の市場残頭を全消費し、旧係数の皮/脂等を生成 | 明示したbatch/頭数を処理。残頭全部を無条件処分しない |
| 家計消費・備蓄 | 保存食品は工房出力や市場在庫を経由し、消費/加工を観測 | 生鮮肉・加工待ち・完成保存食を分け、kgと旧lotを重ねて数えない |

引当後の倍率の例は、同じ羊1市場頭を群れから引いてからNaval/Highlandの1.4倍を掛けると、搬入前の寄与が1.4頭になることである。これはコード上の計算例で、固定地図の年間過大供給量を測った値ではない。Nomadicの豚0.2倍などの縮小側でも、群れの減少と搬入が一致しない。四半期キャッシュと整数化の問題も併存するため、この数値だけを直して生体保存が成立したとはしない。

## 3. 互換と安全な接続順

現行の生体から保存食を作るレシピを、単に共通解体呼出しへ差し替えると、肉量未定義のまま旧wainを生成したり、肉と獣脂の双方へ同じ脂を入れる。今回の監査段階では需要・供給・カタログ・初期在庫を変更しない。

実装は次の順序に固定した。

1. 群れ控除と到着実量の保存を先に直す。倍率・キャッシュ・整数化をまとめて照合し、複数月/同期間再実行でも同じ出荷を再搬入しない。
2. 出荷単位にセル・年齢群・所有者・市場頭数/実頭数を保持する。既存の由来不明市場在庫へ架空の年齢や所有者を付けない。
3. 同じ生体を一度だけ解体する取引と、同じ赤身/脂を一度だけ割り当てる仕組みを接続する。未校正の部位は本番出力にしない。
4. 旧生体直接レシピと残頭処理を同じポリシーで切り替える。旧保存食のlotへ新kgを足さず、物量/価格/口座を伴う移行を行う。
5. 方法別の実材料・労働・完成待ちを接続してから、冬前選択の意思決定へ進む。
