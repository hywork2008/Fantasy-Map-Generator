# 在庫の樽を樽職人の不足に数える（2026-11-10）

[vintage-casks-20261110.md](vintage-casks-20261110.md)で、樽職人が2.7倍作り、樽の在庫が積み上がった。その直しを測った。

## 1. 条件

- 地図は北緯30°の2枚（2102・2103、[barilla-20261108.md](barilla-20261108.md)）、24か月、戦争なし・隊商の略奪なし。2年目（13〜24か月）を集計した。
- base: コミット7690c1f6e（vintage-casks-20261110のnewと同じコード、その出力を使った）。new: 樽職人の空の樽の不足（`getMonthlyHouseholdContainerDemand`）から、市場の在庫の新しい樽も引くようにしたもの。凍結したworktreeで動かした。
- スクリプトは[orchardprobe.mts](cask-stock-20261110/orchardprobe.mts)・[caskprobe.mts](cask-stock-20261110/caskprobe.mts)、実行は[run.sh](cask-stock-20261110/run.sh)。

## 4. 読み取り

- 在庫の樽を数えても、樽を作った量は約1割しか減らなかった（約33万から約30万、変更の前の2.5倍）。在庫は収穫の月に5万まで下がり、冬に18万まで戻る。
- エールを作った量は変わらないのに、エールに使った樽は変更の前の1.8倍になった。空の樽が在庫に戻らず、エールは新しい樽で詰められている。
- 蜂蜜酒は21〜22%で、変更の前（54〜62%）に戻らない。蜂蜜はあるが、醸造に使う量が3分の1になった。蜂蜜酒に使った樽は0になった。理由は分かっていない。
- 取っておく空の樽、樽職人の床、エールと蜂蜜酒の樽の選び方が絡み、量の決まりの直しで釣り合わせられていない。

## 5. 取り置きを外した計測（stockonly）

収穫のための空の樽の取り置き（`getVintageCaskEmptiesTarget`）を外し、在庫の樽を数える直しだけを残した（`sh run.sh <worktree> stockonly`）。比べる相手は樽の変更の前（vintage-labour-20261110のnew）。

| | 2102 変更の前 | stockonly | 2103 変更の前 | stockonly |
| --- | ---: | ---: | ---: | ---: |
| ワイン | 71% | 70% | 72% | 69% |
| シードル | 41% | 38% | 51% | 51% |
| エール | 88% | 88% | 91% | 90% |
| 蜂蜜酒 | 54% | 56% | 62% | 61% |
| 干し葡萄 | 76% | 76% | 76% | 75% |

2103の樽：作った量 121,296 → 120,346、エールに 99,563 → 100,365、在庫は収穫の月に9千まで下がる（変更の前は1.1万）。

- 樽の作り過ぎと蜂蜜酒の落ち込みは無くなり、樽の変更の前とほぼ同じになった。
- 収穫の月の樽の不足とエールの減りは残る。値段を見ない量の決まりを、在庫の月数や利幅で止める見直しで扱う（[drink-price-allocation.md](../plan/drink-price-allocation.md) §6）。
