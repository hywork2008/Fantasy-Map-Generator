# CE森林 F3：3D描画の確認

対象：[実装計画](../plan/ce-forest-surroundings.md)。F0の固定入力のうち、平坦な小都市と川・谷のある小都市の2件を使用した。seed探索や全件試験は行っていない。

## 実装

- 林床と樹冠は、2Dと共通の森林領域から導出する。外周・水域・道路・施設の穴を保持したまま三角形へ分割し、地形の `heightAt()` から各頂点の高さを決める。
- 遠景は256 m単位の樹冠の塊。低い林縁、連続した下層、丸い低ポリゴンの樹冠をまとめて1バッチで描く。単純な水平板だけを森林の代用にしない。樹冠の塊も地形に沿わせ、完全な円形の占有範囲が森林に収まるものだけを追加する。
- 中景・近景は128 m単位でインスタンス化した立木。中景は広葉樹36・針葉樹26三角形、近景は広葉樹104・針葉樹40三角形で、幹と葉を1つのvertex color材質で描く。既存BVの数万三角形の樹木は使わない。
- 個別樹木の根元も同じ地形へ接地し、樹冠の半径で森林境界からの離隔を判定する。水域や道路に葉が張り出す木は作らない。2Dと同じ植生・気温の選択から広葉樹と針葉樹を決める。
- 画面上の大きさとヒステリシスにより、樹冠の塊・中景・近景を切り替える。木の位置と寸法はseed・世界座標に固定し、品質で植え直さない。詳細予算が足りなければその領域を樹冠の塊へ戻す。
- 個別樹木のLODキャッシュは最大24層。採用できないLODのコストも記録し、次の小さなカメラ移動で不採用のメッシュを再作成し続けないようにする。
- 可視チャンクだけでもdraw callsの上限を超える場合は、全森林の樹冠を1つのバッチへまとめた俯瞰用表現に切り替える。森林領域を削って帳尻を合わせない。全景の基盤メッシュ自体は品質と独立に60,000三角形以内を目標に粗密を調整する。
- 近景の一部だけが影を投影する。太陽の既存設定に加え、森林独自の投影量上限を守る。影の投影元が変わったときだけ更新を要求し、250 ms以上の間隔にまとめる。待機中の連続RAFは追加しない。
- `cityView.ts` に組み込み、森林の品質だけの変更やカメラ移動で、市街・農地・水面を再生成しない。地形・森林領域・密度・植生等の変更では森林を再生成し、旧バッファを解放する。

海岸や風車の余白を導出する `forestKeepOut()` を共通化した。2Dの景観描画の副作用に依存せず、3Dでも同じ余白を利用できる。

## 制限と設定の入口

| 品質 | 個別樹木の可視本数上限 | 主描画の三角形上限 | 主描画のdraw calls上限 | 影に提出する三角形上限 |
| --- | ---: | ---: | ---: | ---: |
| light | 2,000 | 100,000 | 64 | 0 |
| standard | 8,000 | 300,000 | 128 | 50,000 |
| high | 20,000 | 800,000 | 256 | 150,000 |

既定はstandard。住宅モデルの品質とは独立した `City3dMountOptions.getForestQuality()` を追加した。UIと保存・自動品質制御はF4で接続する。切替は既存の幾何を再利用し、必要になったLODの軽量プロトタイプを遅延生成する。

上限は森林分の制限であり、都市全体のフレーム時間を保証する値ではない。統計の三角形数・draw callsは可視チャンクの保守的な提出量で、GPUの個別インスタンスの視錐台カリング後の量より多い場合がある。影の値は投影を許可したメッシュの量であり、太陽の影が無効なら実際の影描画は行われない。

## 固定都市での結果

再現：

```sh
node --import tsx scripts/verifyCeForest3d.mts
```

実際の `mountCity3d()` を起動し、2Dの静的SVGから得た森林面積と照合した。元の全量文書がなければ固定レシピから再生成する。各品質で俯瞰・接近を確認し、品質の切替をさらに3巡させて資源数の安定を確認した。

| 入力 | 森林面積（2D・3D一致） | 3D初回mountのCPU時間 | 反復後の常駐geometry数（都市全体） |
| --- | ---: | ---: | --- |
| small-flat | 993,664.5634041692 m² | 496.5 ms | 77 → 77 → 77 |
| small-river-valley | 1,007,722.3141692374 m² | 1,721.5 ms | 85 → 85 → 85 |

mountの前に2Dの森林領域を準備している。時間は既存市街を含む3D全体の同期的な構築時間で、森林だけの時間やGPUの初回描画時間ではない。

## 検証と未検証事項

- 関連4ファイル・25件が成功：新規 `src/city3d/three/forestMeshes.test.ts` の5件、`cityViewRendering.test.ts` の3件、`forestSvg.test.ts` の6件、`forestPlan.test.ts` の11件。再実行分は重複計上しない。
- 林床・樹冠の開口部、地形上の頂点と根元、樹冠半径による離隔、LOD間の位置と寸法の安定、各予算、待機カメラでの無処理、俯瞰のバッチ化、共有資源の一度だけの破棄を確認した。
- 実際のviewで品質とカメラを変えても市街のオブジェクトが維持され、森林を無効にすると専用レイヤーが除去されることを確認した。
- 固定2都市・3品質・2姿勢の全12ケースで2Dとの面積が一致し、本数・三角形・calls・影の上限内。WebGLエラー・context lossなし。品質の反復でgeometry数が増え続けないことを確認した。PNGを目視確認し、俯瞰の樹冠と接近時の立木、川の開口部、地形の起伏を確認した。
- TypeScriptの型検査と変更ファイルのBiomeチェックを実施した。全件テスト・多数seedの試験は行っていない。

環境はApple M4 / Node v22.23.1 / Headless Chromium / 1000×720 / DPR 1。WebGLは **SwiftShaderによるソフトウェア描画**。JSONのCPU submit時間から実GPUのFPSや33 ms目標の達成を判断しない。GPUメモリのバイト数も未実測であり、geometry数の安定はメモリ容量の保証ではない。実GPUでの性能校正と、LODの切替・林縁・配置の自然さの最終調整はF4〜F5へ引き継ぐ。

次はF4：景観モード・密度・生成済み都市への適用、2D表現・3D品質のUIと保存、自動品質の接続を実装する。
