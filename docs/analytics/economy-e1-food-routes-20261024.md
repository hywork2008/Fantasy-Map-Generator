# E1 市場16の食料不足: 港経由の輸入と穀物在庫（2026-10-24）

市場16の不足を、輸入経路・地元生産と作物暦・備蓄・資金に分けて調べた。主な停止原因は**食料輸入が道路だけ/海路だけを探し、内陸の市場中心と港をつなぐ複合経路を使えないこと**だった。経路を直した段階で、固定Worldの最初の12か月の都市穀物不足は0になった。E1全体や長期均衡の完了ではない。

## 修正した契約

`foodImportNetwork.ts`は従来の単独道路/海路があれば維持し、それで到達できない場合に、供給側市場の中心→同じ市場の港→既存海路→到着側市場の港→中心を調べる。港は削除されていない実在の町で、市場所属と道路接続を確認する。陸の各区間は冬季閉鎖を反映した既存グラフを使い、海路がなければ輸入しない。陸区間がある側ごとに既存の港積替え時間を加え、所要日数による損耗と従来の治安損失を適用する。港候補と海路距離は1回の解決内で再利用する。

経路が通ると、既存の在庫処理の問題も露出した。

- 輸出候補を`market.goods`の古い生産累積から選び、実際にはその穀物の保存在庫がない場合があった。新しい`getTransportableStapleCropUnits`で保存桶の実量と共通の輸出上限を使い、輸入ネットワークと混載の両方の選択・積出しへ接続した。場外のoverflowは積まない。品種別台帳がある市場で未記録の品種を選んでも、別の穀物の集計在庫を引き出さない。
- 受取側に初めて届く品種が、既存品種別台帳ではなく集計桶だけへ入る場合があった。品種別管理の市場には新しい品種の桶を作り、既存穀物とともに集計を更新する。次の集計更新で輸入量が消える経路を閉じた。旧集計台帳だけの保存の互換経路は維持する。
- 実際の経路・選択・予算・積載ガードの診断を最新1回分だけ保持し、既存監査の生産ステップで読み取る。残必要量や購入可能量が微小で積載が0へ丸められる場合は`belowQuantityPrecision`とし、実在庫なしと区別する。診断は保存・需要・価格・配分へ使わない。

初期金・人口・在庫・作物係数・食性・家計需要は変更していない。既存の抽象的な食料輸入解決の経路を補った変更であり、船・車両・乗員・運賃・到着待ちを追加したものではない。この輸入解決は従来どおり、生産ステップで出荷側を減らして到着側を即時加算し、所要日数は損耗・治安リスクへ使う。実輸送資産の制約・費用・待ち時間の接続はE6へ残す。

市場16の残高が0へ至る場面があるため、この結果から長期の運転資金の持続性は主張しない。冬季飼料の端点不足率も約49.8%のままで、食料輸入の修正を飼養規模の校正完了と扱わない。36か月の群れ移行実験は今回実施していない。
