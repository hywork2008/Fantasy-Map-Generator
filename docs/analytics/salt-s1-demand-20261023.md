# Salt S1: 家計・加工・家畜の需要接続

2026-10-23。[S0](salt-s0-baseline-20261023.md)の固定した1300年・High Medievalの入力を使用。S1は需要と在庫の引落しを対象とし、製塩の労働・燃料・内陸産地（S2）、家計/国家間の代金（S3）は追加していない。

## 1. 需要の境界

| 対象 | 必要量・補充見込み | 取得・不足の扱い |
| --- | --- | --- |
| 有効国家の家計 | 都市と陸セルの実人口×3.6 kg/人/年÷12 | 従来の国別配送と市場在庫から引落し。都市倍率と人口倍率を別に適用 |
| 無所属の家計 | 同じ人口式。台帳のstateId=0は消費者の集計区分 | 既存の地元市場に属する場合に在庫を受け取る。国家の配送を発注せず、製塩所の所有者・初期能力の計算対象にも加えない。受取できない量は不足 |
| 市場未割当の家計 | 同じ人口式で必要量を計上 | 自動で最寄り市場へ接続したり塩を生成したりせず、全量を不足に計上。`unmarketedPeople`で分母を示す |
| 保存食・チーズ等の加工 | 前回決済以降の実際のSaltの`recipeInput`市場引落しを、次回の補充見込みにする | 人口比例2.4 kgの固定加工枠を廃止。記録済みの材料は再引落ししない。製品中に残った塩を別途の家計購入として再計上しない |
| 放牧家畜 | コホートの実頭数×暫定の年間補給計画値÷12 | 自然由来の控除・市場からの受取・不足を別記。全家計の必要量を確保した残在庫から引落す |

無所属住民が市場に属するかどうかは、S0の人口監査ではまだ分けていなかった。今回、既存の市場セル割当をそのまま利用する。国家に属さないという理由だけで需要を消したり、全員を国家の無料配送対象へ追加したりしない。家計の受取はS3前の従来の物量決済であり、代金支払済みの購入ではない。

加工の記録は、観測コールバックではなく`recordGoodFlow`の実取引記帳で行う。観測が無効でも補充履歴が残り、観測ビューを読むだけでは更新されない。`market.saltProcessingInputBags`は実引落しの累積、`saltProcessingForecastBags`は前回分の補充見込みであり、どちらも商品在庫ではない。決済時に累積を一度だけ移してリセットする。共有市場は人口比で各国家と無所属分へ按分し、市場全体の加工見込みを重複させない。

この見込みは、まだ生産していない設備の潜在需要や、材料取得に失敗した全レシピの受注量ではない。通常製造の`recipeInput`記録は実際の市場からの調達量を表すため、加工失敗後の材料の所在や工房内在庫の全量を説明する企業会計まで解消したことにはしない。

## 2. 家畜の暫定方針

S0で中世の年間購入給塩量は「基準なし」としたため、以下は**史実・生理学の確定値ではなく、補給経路を実装するための暫定計画値**である。家畜の健康・乳量・出生率をこの充足だけで変更しない。

| 種 | 成体相当1頭あたり年間の補給計画（kg） | 根拠と限界 |
| --- | ---: | --- |
| Cattle | 20 | S0で紹介した既往推計の下側を暫定採用。中世の実購入を裏づけたものではない |
| Sheep / Goats | 1.4 | 同上。夏の給塩原典を年間へ外挿した値ではない |
| Horses | 23.333… | 牛20×既存の年間飼料乾物3500/3000による仮の規模換算。馬の史料値ではない |
| Camels | 40 | 牛20×既存の年間飼料乾物6000/3000による仮の規模換算。ラクダの史料値ではない |

対象は既存の共有牧草地・飼料予算の5種。幼齢0.5、繁殖/老齢1の成体相当で月割りし、Faunaの実頭数を使用する。Horsesの市場lot換算25を再適用しない。Pig・Chicken等の非放牧種の飼料中の塩や、軍・商人が独立して所有する輸送資産への追加給塩は、このFaunaの給塩に重ねて足していない。そうした対象の必要量を史実的に校正済みと扱わない。

自然由来の塩を量で追う入力がまだないため、**自然摂取の計上控除は0**。これは自然摂取が存在しないという主張ではなく、飼料の重さや沿岸という条件から無根拠な塩を生成して補給計画を満たさないためである。将来、飼料・飲水・塩場の実際の量を接続する際は、この控除を更新し、同じ源を二度使わない。全ての値は`SALT_LIVESTOCK_ANNUAL_KG`と`SALT_LIVESTOCK_NATURAL_SHARE`、観測JSONの`modelPolicy`に明記する。

市場の受取は`livestockFeed`のSalt sinkとして一度だけ記録する。家畜向けの必要量・自然控除・受取・不足は国家台帳の別フィールドにし、家計の不足へ混ぜない。新たに賃金・現金・無料在庫を追加する実装ではない。

## 3. 保存・互換と検証

- 追加の市場履歴・国家台帳フィールドはoptional。既存セーブでは0から始め、固定2.4 kgを履歴として捏造しない。既存のSalt袋は60 kg、既存の製塩所能力・在庫は保持する。
- 市場の加工履歴2.25 bag・見込み1.5 bagを置いて、保存/再読込で値がそのまま残り、再消費や再換算されないことをNodeホストで確認した。
- `saltLogistics.test.ts` 15件、`goodsFlowObservation.test.ts` 1件、`production-generator.test.ts`・`production-utils.test.ts`・`dairy.test.ts`計47件、合計63件成功。無所属の市場未割当、加工の再消費防止、共有市場の見込み按分、全家計を家畜より先に確保すること、馬の実頭数を含む。型チェック成功。
- 旧来の備蓄テストは、固定加工枠の廃止で生産の操業余力15%だけで備蓄を積む期間が長くなるため、24決済の初期充填後に同じ定常在庫を検証する形へ変更した。許容誤差を広げていない。

## 4. 同じ固定入力の12か月観測

入力・設定・期間はS0の同条件比較と同じ。正式終了データは[Province](salt-s1-province-101-20261023.json)と[World](salt-s1-world-102-20261023.json)。観測schemaVersionは3で、`annualizedKgPerLedgerResident`の分母は今回の国家台帳人口（無所属・市場未割当を含む）の実決済平均である。S0の`annualizedKgPerServedPerson`と分母を黙って同一視しない。

[比較JSON](salt-s1-comparison-20261023.json)に旧/新の集計、国家住民/無所属の内訳、入力・出力ハッシュ、物量照合残を保存した。入力ハッシュ・開始/終了日・worldSettingsの一致、各12標本/12決済、主要ソースのハッシュ一致、家計/家畜の引落しフローと丸め済み台帳の差が1 kg未満であることを確認した。

S0は無所属住民を必要量から除外していたため、「旧必要量との差」を新しく生まれた人口増と扱わない。国家住民の納品を悪化させず、無所属の取得と不足を観測できるようになった。ただしProvinceでは無所属の需要に対して既存能力が足りず、市場在庫が尽き、Saltを使う加工の引落しもS0の0.102 tから0になった。これを需要統合だけで生活経済が改善した結果とはしない。

Worldでは加工投入がS0の19.516 tから19.631 t、国家住民の家計不足が218.439 tから192.927 tになった一方、無所属の不足7.322 tと家畜の不足72.506 tがある。家畜の補給値は暫定なので、この不足を史実の塩欠乏や家畜死亡の量として解釈しない。

市場＋塩専用輸送中を境界とする物量照合残は、Province −0.102 kg、World +341.662 kg（S0は+6.771 / +340.540 kg）。一般の輸送中・海軍への移管等の境界を含む未説明差額は残しており、残差をゼロにする補正は入れていない。国家台帳はbag小数4桁に丸められるため、家計と家畜の需要/受取/不足の合計にはその精度による微小差がある。

## 5. 完了判定と次の作業

S1の需要経路を実装した。無所属・市場未割当を含む家計の必要量、実加工の補充履歴、放牧5種の頭数による補給計画を分離し、同じ塩・共有市場・馬の頭数を二重に使用しない。家畜の暫定値、対象外、自然由来の控除が未計測であることは§2に明示した。史実校正・栄養要求量の確定、経済の均衡を完了としたものではない。

**次はT11 S2（製塩の生産を経済へ入れる）**。今回の不足と旧入力の能力を基準に、作業者・煮詰め燃料・天日製塩の季節性・内陸の産地を接続する。需要に合わせて無条件に能力・原料を追加しない。代金・国家間の精算・無所属の支払主体はS3、追加の史実校正はE7へ引き継ぐ。
