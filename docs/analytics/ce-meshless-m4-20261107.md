# メッシュなしCE M4：入力・固定交差・骨格生成と領域演算

記録日: 2026-11-07  
状態: M4完了。次はM5「用途領域、施設先行配置、住宅、需要・容量」。

設計: [CEメッシュなし都市生成・編集](../plan/ce-meshless-city-editor.md)。前段: [M3記録](ce-meshless-m3-20261107.md)。

## 実装と使い方

メッシュなし画面の「Meshless generation: input → skeleton → land／メッシュなし生成：入力 → 骨格 → 領域」を開く。

1. FMGから開いたCEでは「FMG入力を確認」を選べる。FMG descriptorまたは既存の共有入力JSONをファイルで開くこともできる。単独起動ではseed・半径・河川の有無を指定した合成入力、または現在の手動形状を入力にできる。
2. 入力候補を確認して採用する。新しいFMG／合成入力の採用は現在の文書を置き換える操作であり、取消では元の文書を維持する。手動形状を入力にする操作は既存の線・領域・配置を保持する。
3. 追加道路の幅・離隔・都市内の道路目標点数、seed、自動市壁を指定し、「骨格・領域の生成候補」を選ぶ。入力→骨格と接続→領域と接道の3段階を確認できる。
4. 最終候補を採用する。入力採用と生成結果採用はそれぞれ1回のUndo対象である。採用後も段階を切り替えて表示できる。保存・再読込では採用済み形状を表示し、生成し直さない。

既存のmesh-first／skeleton-first／Freeformの生成処理は従来どおりである。`CityEditorPage`の方式切替境界から現在のdescriptorを専用セッションへ渡す。新しい生成器は`conformingMesh`、セルの分割・統合、既存の`CityDocument.mesh`を使わない。

## 入力の正本と固定交差

`generation/input.ts`でFMG／合成入力を専用文書へ正規化する。

- FMGの座標は既にローカルメートル・+X東／+Y北であり、二重にメートル換算・Y反転しない。再中心化済みの`urbanCenterOffsetMeters`は由来として残し、ローカル形状へもう一度加算しない。元の地図原点と換算係数を保存する。
- descriptor全体をsnapshotとして保持する。気候、地形・高さ場、人口・住戸、文明、経済、道路と隣接都市の情報を欠落させない。M4の骨格計算では高さ場をセルメッシュとして再現しない。
- 元ID・固定交差revision・geometryVersion、共有route ID、far-bank branchを保存する。入力の道路・河川曲線は`imported / fixed`とし、形状snapshotとの一致をnative検証でも確認する。
- 測量済みの水域輪郭を保持し、橋・接続の検証と領域演算にはこの輪郭を使う。橋に対応する河川のwitness曲線とparameterを採用し、見かけの描画幅へ合わせ直さない。元のdescriptorに含まれる河川segments・岸・その他の情報も保存する。
- 橋軸、deck、両岸、approachの元座標をコピーする。道路と対応する取付が一致しなければ拒否し、別位置へ吸着させない。共有するfar-bank branchも同じ固定取付へ明示的に接続する。
- 海岸は入力のshorelineと水側の指定から表示窓の境界へ閉じる。regional water・追加の湖等も保持し、未知の地形は都市領域から除く。都市中心が水域内・市域外・未知領域の場合は診断する。
- 固定交差の必要boundsを表示範囲に残す。測量データが窓外へ延びていても元座標を保存し、描画だけを表示フレームでクリップする。

M0のGothengsfeld固定ケースでは、交差113、河川195、geometryVersion 137、元の541頂点の水域輪郭、共有route 10、固定道路・橋・両岸・取付を保持した。追加試験では共有branch 99を与え、元の取付への接続と座標維持も確認した。

## 骨格と領域

| 実装 | 内容 |
| --- | --- |
| `generation/pipeline.ts` | 入力→壁・開口→橋→道路接続→街区候補。rendererから呼ばれない明示的な生成器 |
| `generation/routes.ts` | 実際の輪郭・入力port・橋の取付を頂点とするvisibility graph。新しい道は乾いた全幅経路、既存橋は固定された通過linkとして扱う |
| `geometry/intersections.ts` | 適応近似で交点候補を探し、原曲線の位置・導関数でanchorを解く。固定曲線を交点へ変形しない |
| `geometry/regions.ts` | polygon-clippingのadapter。union／difference／intersectionを複数外周・穴付きの領域へ適用する |
| `geometry/water.ts` | 測量水域を優先し、手動河川は中心線と幅から評価する共通の水域入力 |
| `validation/generation.ts` | 入力snapshot、所有revision、生成設定、領域・面積・接道、入力段階のnode snapshotの検証 |
| `components/vector/VectorGenerationPanel.ts` | 入力・生成候補、採用・取消、段階表示、診断、遅延ファイル読込の失効 |

都市領域から水域・壁帯・保護用地・既存施設を差し引き、道路の半幅と離隔が収まる経路を求める。水域は橋の既存軸を通る場合だけ越える。壁には道路用の門・水門を明示し、開口が収まらなければ候補を拒否する。市域内の入力道路の水上部分が適法な橋面で覆われない場合も拒否する。橋の角度と渡河長は共通規約、およびFMGのtransport上限で検査する。

道路交点を共有nodeへまとめ、元曲線の範囲として辺を構成する。固定の橋や道路の形は変えない。必須の入力portへ到達できなければ生成を確定しない。追加目標点へ到達できない場合や接道のない土地は診断を付けて保持する。

道路面を差し引いた残地の外周・穴・全成分・面積を保存する。道路面と実際に共有する境界から接道区間を求め、中心側のグラフから到達可能かを記録する。道路グラフが閉路を作らない土地も対象とする。0.5㎡の細い土地を1㎡閾値で捨てず、M5以降へ渡す。M4では施設・住宅を配置せず、土地を架空の建物で埋めない。

### 領域演算の依存追加

穴、重なる輪郭、分離成分を扱うため`polygon-clipping 0.15.7`を追加し、package-lockで固定した。APIと出力の外周／穴・複数成分の契約は[公式README](https://github.com/mfogel/polygon-clipping)を確認した。追加されたパッケージはpolygon-clippingとsplaytreeの2個である。

単体ESMの計測は55,040 bytes、gzip 14,186 bytes。これは依存や共有コードを含むCE全体の増加量を測った値ではない。演算するのは派生領域であり、元の測量輪郭や固定曲線を丸め直さない。入力辺30,000、出力点50,000、単一ring 16,000、経路頂点1,600等の予算を超える場合は明示的に拒否する。都市を均等なセルへ分割して予算内に収める処理は追加していない。

## 保存・再生成・段階表示

native文書を`fmg-vector-city` **v4**へ進めた。v1〜v3の文書は旧schemaで検証してv4へ移行する。旧文書から入力や生成結果を勝手に作らない。未対応のv5は拒否する。

- `site`: 入力の種類・ID・revision、座標系、都市領域、水域、固定形状、固定交差、元descriptor。
- `generation`: アルゴリズム版`vector-skeleton-v1`、設定・seed、入力revision、所有する生成pathのrevision、接続fingerprint、街区候補と接道・到達性、診断、入力段階のnode snapshot。
- 「入力」は生成pathを隠し、元の入力nodeを表示する。「骨格」は確定した線と接続、「領域」は同じrunの街区候補を重ねる。描画で配置や乱数を解き直さない。
- 編集でrevisionが変わった場合は古い領域を隠し、段階切替も再生成まで無効にする。
- 再生成で置き換えるのは、自分が所有し、revision・固定区分・接続が変わっていない自動形状だけである。手動変更・固定・接続変更があれば停止する。手動形状や元の入力を黙って消さない。
- 新しいFMG／合成入力の候補は元文書と別に確認し、採用時だけ置き換える。遅延ファイル読込は他の操作・履歴・破棄後に採用しない。

## 次の段階と実装境界

次はM5として、保存した領域・接道・到達性から用途を決め、施設需要→職業施設の敷地・入口予約→残地住宅の順に進める。人口容量不足は不足として報告し、固定入力や手動市壁を勝手に拡張しない。

M4は小さな入力に対する有界の同期生成である。大都市の性能調整、Workerでの局所再生成・競合／取消、変更対象だけの再計算はM6へ引き継ぐ。複雑な地形で予算や制約に収まらない場合は確定しない。自動橋を置けなければ、その水域を横切る乾いた経路は作らず、必須接続を満たせない場合は停止する。

既存メッシュ都市の建物・全機能の複製変換、3D表示、共有URLはこの段階の対象外であり、既存CEを利用できる状態を維持する。descriptor内の気候・地形・経済等は保存するが、そのすべてを新方式の土地利用・施設・住宅へ適用済みとは扱わない。
