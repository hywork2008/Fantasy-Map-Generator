## 画面からの操作

メッシュなし編集画面の「Connections, gates, bridges and double walls／接続・門・橋・二重壁」を開く。対象の線・区間・位置と、接続元の線・区間・位置を指定する。対象の座標を基準とし、移動して吸着できるのは編集可能な接続元の端点である。内部の点同士は、同じ確定座標にある場合に接続できる。近いだけの点や、見た目の交差は結合しない。

| 操作 | 採用される結果 |
| --- | --- |
| 接続・解除 | 共有nodeと道路の区間グラフ。曲線の区間IDを壊さず、既存曲線上の範囲として辺を作る。分岐・合流は共有nodeを使う |
| 門の作成・置換・移動 | 壁上anchorと道路の取付点を同じnodeへまとめ、開口幅・用途・市壁回路を保存。変更は候補を確認して採用する |
| 水門 | 壁と河川を接続し、通行門と区別する。道路と河川のnodeを混ぜず、渡河は橋の操作へ案内する |
| 門の削除 | 開口を閉じる。門のあるnodeを解除する前には門を削除する |
| 市壁回路 | 閉じた壁を登録し、内壁の親となる外壁を指定する。親子の循環、同一壁の重複登録、接触・はみ出しを拒否する |
| 内壁の候補 | 指定した実距離で中心線を内側へoffsetする。楕円の縦横寸法を減らすだけの縮尺変更は使わない |
| 壁間道路の候補 | 指定した始終点、道路幅、片側離隔で、壁・河川・予約用地・施設を避ける経路を探す。候補の全幅・折れ点・離隔を検査して採用する |
| 直角橋の候補 | 河川上の指定点の法線を橋軸とし、両岸外に全幅の乾いた取付を確保する最短の直線範囲を求める |
| 既存道路上の橋 | 接続元道路の始終anchorで指定した範囲を橋として検査する。水上の屈曲・逆行や不適法な斜交を拒否する |
| 歴史時代・習得技術 | 時代の基準を下回らない技術tierと、石造／木造の共通角度上限を適用する |
| 橋の固定・削除 | 固定した橋と参照する道路・河川の変更を拒否する。削除時は道路自体を残すが、橋面は描かない |

門・橋・内壁・壁間道路は、プレビューと採用を分けた。候補の線は下書きであり、橋面や履歴に追加しない。入力を変えると候補を失効させる。取消・不正候補では保存済み文書を変更しない。採用と関連する参照変更は1回のUndo対象になり、Redoもできる。

## 幾何・接続の実装

- `generators/vector/editing/network.ts`: 接続、道路グラフ、門、市壁回路、橋、内壁、壁間道路のtransaction。道路の端点・共有点・橋の取付点で辺を区切る。同じ区間継ぎ目の別anchor表現は同じ共有nodeへまとめ、影響しない辺のIDを維持する。
- `geometry/network.ts`: 門の開口、接道方向と幅、橋の全範囲・両岸・取付・接線角、交差点の路面補完。門が同じ壁の遠い部分まで切ったり、別の門に重なったりする候補も拒否する。
- `geometry/routing.ts`: 物理offset、包含関係、輪郭の頂点を使ったvisibility graph、道路帯全体の検証。境界とrayの照合にはRBushを使い、都市のセル分割・ヘックス・ボロノイ・メッシュ辺を作らない。
- `validation/document.ts`: 参照・用途・包含・橋・壁間道路の拘束をnative読込と編集確定の両方で検査する。壁や幅を後から変更して、採用済みの壁間道路の離隔や橋の取付が不足する場合も拒否する。
- `renderers/vector/documentSvg.ts`: 明示した門だけ壁帯と中心線をmaskで開口する。道路・河川の上に壁を描き、門がない壁の通過を表示上で補わない。河川の上に描く橋面は検査済みの橋だけとし、橋のない交差には補わない。交差点の路面は同色の帯と共有点の補完面を重ねて結合する。

市壁間の自由空間は外壁帯の内側・内壁帯の外側とする。探索では道路の半幅と離隔で障害物を広げ、候補の道路帯を改めて原形状と照合する。採用後は`wallRoads`に道路と内外回路、必要離隔を保存する。門から壁間道路へは取付道路を使い、共有nodeを明示して接続できる。壁頂点の移動・統合は不要である。

## 文書と共通の橋規約

native形式は`fmg-vector-city` **v3**へ更新した。

- `connections.bridges`: 道路の橋範囲、河川anchor、構造、乾いた取付長、固定区分。
- `connections.wallRoads`: 採用した道路、外壁・内壁回路、必要離隔。
- 門には`kind`と任意の`circuitId`、contextには任意の`bridgeSkewTier`を追加。
- v1／v2は旧schemaで検証してv3へ移行し、現在の幾何・接続検査も行う。未対応のv4、不正参照、不適法な橋は拒否する。元のv1固定fixtureは変更しない。
- bridgeのanchorも、曲線分割・反転・プリセットからの変換で他の永続参照と一緒に更新する。固定橋を黙って回転・短縮しない。

M0で見つかった共通APIの不足を修正した。`src/utils/bridgeSkewPolicy.ts`の`resolveBridgeSkewLimit`は、FMGからの明示値も絶対上限30度に制限する。`withinBridgeSkewLimit`も上限30度を超える判定、非有限値、負の角度を受理しない。石造15度／木造20度、近世25度、斜めアーチ以降30度、推奨10度の表は既存の共通定義を使い、新方式の別表は作っていない。

この変更はFMG・RE・既存CE・Freeformが使う共通関数へ及ぶ。正当な明示値0〜30度は維持し、従来通過し得た45／89／120度の明示値を30度へ制限する。関連する既存の渡河・橋面・城郭・Freeform・REのテストも実行した。

## 実装境界と次の段階

M3は手動の小さな文書で接続・渡河・壁間道路を成立させる段階である。既存CEの自動都市全体をメッシュなしへ置き換えてはいない。任意の線の交差を自動接続したり、橋・通行可能な完成道路へ自動昇格したりしない。FMG入力の採用、全市の骨格生成・到達可能性の評価、残地の領域演算はM4で接続する。

複雑な凹形状のoffsetが分裂・消失する場合は元の壁を保持して理由を表示し、距離の変更または独立した内壁の描画へ案内する。分裂した成分を黙って一つに結ばない。複数成分の候補選択は後続の領域演算で扱う。visibility graphは候補頂点600までとし、それを超える形状は明示的に拒否する。

固定橋が参照する道路・河川は、M3の通常編集では保守的に変更を拒否する。橋を解除して適法な候補として再確認するか、別の線として取付道路を作る。複数制約を解き直す局所編集・拡幅追従はM6へ引き継ぐ。橋を架けられない場合の案内には、取付道路の変更、別地点、渡し船を含むが、渡し船の配置・運行モデルはこの段階では追加しない。
