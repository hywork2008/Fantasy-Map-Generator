# 冬前屠畜と作物残渣給与の実装検証（2026-10-24）

## 実装範囲

[設計§22](../plan/winter-livestock-slaughter-and-preservation.md#22-収穫由来の藁刈跡給与2026-10-24)に基づき、実際の麦類収穫からの残渣発生、排他的な用途留保、農村職業配分への労働要求と、実際の残り労働による回収・刈跡アクセス、私有在庫の保存・損失・失効、品質割引と給与上限、屠畜予測への在庫接続を実装した。Wheat/Rye/Barley/Oatsに限定し、既存の試験設定でのみ新しい由来receiptを作る。既定offは維持する。

残渣量、用途比率、作業量、品質換算は設計仮定で、[原著確認](winter-slaughter-historical-followup-20261024.md)からの直接測定値ではない。他用途20%は飼料から除外する留保であり、実際の敷料・燃料製品を生成しない。輪作休閑の専用区画が未確定のため、焼畑系林地休閑を温帯の休閑地草へ転用していない。

- [Province集計](winter-slaughter-crop-residues-province-20261024.json)

途中で発見した複数lotの給与順序の差を修正し、最終コードで比較を取り直した。期限の短い刈跡を先に使い、次いで古い保管藁を使う。屠畜予測も同じ順序を使い、将来の回収や未予約の刈跡放牧は見込まない。修正前の中断走行は検証値に採用していない。

最初の自然走行では残渣が発生しても作業0だった。[労働要求接続前の診断](winter-slaughter-crop-residues-before-labor-request-20261024.json)として別ソースの結果を保存した。これを受け、作付け・収穫暦と3期間の給与/保管上限から残渣作業を要求し、同じ農村労働供給へ配分する経路まで接続した。人数や飼料の直接加算ではない。

## 判断と次の作業

実収穫→排他配分→有限回収/アクセス→品質割引給与→保存/失効→屠畜予測の経路は接続済みで、明示した在庫・労働を持つ実アーカイブ試験では利用できた。一方、この自然入力での残渣利用・不足改善は実証できていない。既定offと試験係数を維持する。

**次は、通年牧畜と季節作業を一つの年間倍率で止めている農村職業配分を、月別の実作業と同じ住民労働供給で決済できるよう見直す。** 繁忙期の不足は残し、閑散月に実在する余力まで消さないこと、通常管理・採草・食肉準備・残渣の優先と未実行を分けること、穀物労働と重複させないことを検証する。輪作休閑の排他区画化、他用途の実需要配分、史料校正、E1全体の収束は残る。
