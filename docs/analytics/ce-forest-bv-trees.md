# CE 森林：高品質でBV treesモデルを使用

実施日：2026-10-28

## 変更内容

森林品質「高品質」の近景で、BVのtreesカテゴリと同じ `createLandscapeTree()` を使う。既存の幹＋多面体の樹冠だけだった表示に、実際の枝・根・葉・針葉を持つ樹種モデルを接続した。BVカタログの20モデルの生成口を利用し、森林で使う樹種は既存の気候・バイオーム選択に従う。観賞木などを森全体へ無条件に混ぜない。

- Generate → View → 3Dの森林品質を「高品質」にすると近景へ詳細モデルを適用する。住宅モデル品質とは独立する。自動品質が実際にhighへ上がった場合も同じ描画を使う。
- 画面内でよく見える樹冠を優先し、残りを距離と中央からの位置で並べる。近いが画面外にある木だけに詳細予算を使わない。投影サイズ指標60／48と、選択済み候補の余白で切替を安定させる。
- 元の候補の座標・回転・大きさを使い、詳細モデルを候補の半径と高さへ合わせる。最下部を地面へ接地し、樹冠・根・枝の全頂点が元の半径内に収まるよう正規化する。木の位置・森林の面積・道路や水域の開口部は変えない。
- 置換する簡略木のインスタンスだけを縮退させ、詳細木との二重描画を防ぐ。品質を戻した際は元の変換行列を復元する。縮退分も簡略メッシュの提出三角形数へ含め、描画負荷を過小計上しない。
- 追加された針葉樹（スギ・モミ・マツ等）は簡略LODでも針葉樹の形に合わせる。高品質の近景に残る簡略木は滑らかな陰影にする。中景・遠景は軽量な樹木・樹冠の塊を維持する。
- 樹種ごとにモデルを一度だけ構築して共有し、影あり／なしのインスタンスへ分ける。品質変更で再生成しない。森林ビューの破棄時にgeometry・material・インスタンスを解放する。
- UIに近景の詳細表示を説明する文を追加し、計測パネル・JSONに詳細樹木数を記録する。

## 描画量の制御

| 項目 | 上限・方針 |
| --- | --- |
| BV詳細木 | 最大16本、保持する樹種モデルは最大4種類 |
| 高品質の森林全体 | 800,000三角形・256 calls・影150,000三角形 |
| 高品質の簡略木側 | 320,000三角形、影60,000三角形までに抑え、詳細木の余地を確保 |
| 詳細の本数 | 各BVモデルの実際の三角形数と残予算で打切り |
| 標準・軽量 | 従来の簡略モデル。森林範囲は高品質と共通 |

例えばシナノキ相当は1本84,098三角形なので、今回の視点では6本を詳細化した。すべての木を同時にBVモデルへ置換する設定ではない。

## 確認結果

関連6ファイル・36件が成功した。全件テストや多数seedの試験は行っていない。

- `forestMeshes.test.ts` 18件：実際のBVモデルの三角形数との一致、切替時の同一位置と行列の復元、新規12樹種の接続、共有資源の一度だけの解放、森林・影の各予算。
- `forestTreeDetails.test.ts` 1件：近い画面外の木より画面内の樹冠を優先し、簡略インスタンスを復元する。
- `cityViewRendering.test.ts`、`CityEditorPage.forest.test.ts`、`performancePanel.test.ts`、`editorMessages.test.ts`：既存の表示更新・操作・計測・日英表示。
- `npx tsc --noEmit --pretty false`、変更TypeScriptのBiome、`git diff --check` が成功。

新規12樹種の試験はナツメヤシ、アカシア、サクサウル、カポック、ベイスギ、ハンノキ、オリーブ、モミ、マングローブ、タマリスク、ナナカマド、カナリアマツの識別子を使った。各バイオームから実際のBVモデルが選択されることを確認した。
