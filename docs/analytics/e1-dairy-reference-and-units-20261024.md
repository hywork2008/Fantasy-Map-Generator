# E1: 乳製品の史料照合と人口単位の修正（2026-10-24）

[前工程](e1-joint-demand-20261024.md)で判明した乳製品の年換算量について、需要・産出・人口の分母を調べた。史料から確定できる数値と、現行モデルの仮係数を分離し、確実に修正できる人口単位の不整合を直した。

PDFの原文該当ページと出版社のHTML本文・表を確認した。これらの確認では、全住民共通のチーズ25kg/年、飲用乳20L/年、繁殖群の泌乳割合0.375を歴史的な確定値として採用できなかった。この結論は必要量ゼロを意味しない。未確認の地域・家計・単位を推測で埋めて数値を変更しない。

`dairyHistoricalReferences.ts`に原単位・地域/年代・対象個体・出典・未確認事項を登録し、監査ツールから出力する。現在のモデルでは羊/牛の乳量比0.15、山羊/牛0.30で、上記再構成の0.10、0.18に対して1.5倍、約1.667倍。ただし品種・地域・個体の分母が一致しておらず、その倍率を使った全世界の係数修正は行っていない。gallonのL換算、全住民の消費量、歴史校正済み目標頭数はnullのままとする。

## 修正した人口単位

Milkは1市場単位=1,000L。市場の家計需要は実人口を使うが、農村セルの生鮮処理は人口点に`20/12`を掛けていた。これは人口倍率1,000の場合にだけ一致する。同じ1,000人でも、人口点1×倍率1,000では月約1.667市場単位、人口点1,000×倍率1では修正前に約1,666.667単位を要求していた。

- 生鮮需要プロファイルへ`householdDemandReferencePeoplePerPoint`を追加した。標準Milkは基準1,000人を明示する。
- セル側の需要・緊急留保は同じ換算関数を通し、人口倍率/基準人口で補正する。市場単位や20L/年という仮目標自体は変更しない。
- 標準の旧保存Milkは、既知の旧既定率を読み取る際に基準人口を解決する。保存済みオブジェクトを変更せず、任意に編集された旧率や他品目の人口点契約を一括置換しない。
- 明示された基準人口が0や非有限値の場合はエラーにし、未知や不正を需要0として処理しない。

同じ実人口の倍率1/100/1,000での一致、既定倍率での従来量、旧標準/独自率の互換性、保存データの非変更をテストした。MarketsModuleの実セル内配分も倍率別に確認した。

## 食料台帳がない市場の確認

既存World観測の市場17は、12か月目末の観測で初めて現れ、直前の食料決済（1300年12月27日）には存在しなかった。既存の`settleMonthlyFoodConsumption`は、新市場の初回決済で空台帳を作り、手持ち食料と財布を維持して決済する。`foodLedgerLifecycle.integration.test.ts`にもこの契約の回帰試験が存在する。末尾の台帳未生成を、12か月間ずっと供給経路が欠けていた証拠や、その全住民が食べていなかった証拠には使えない。今回この食料ロジックは変更せず、初回世界生成の在庫/現金を再投入する修正もしていない。13か月目の実走は今回の比較範囲外。

## 次工程

乳製品の全世界共通係数の確定をE1の着手条件にしない。次は独立して進められる、牧草地計画の人口比例と耕地保護の判定を見直す。新しい冬季飼料源の追加ではなく、必要頭数・既存土地利用・主食の充足から土地の割当を決める。史料未確認の消費量を理由に群れを一律拡大/縮小せず、E1全体の完了・歴史校正済みの適正頭数は引き続き未認定。
