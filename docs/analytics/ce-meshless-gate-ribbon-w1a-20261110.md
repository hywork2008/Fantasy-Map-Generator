## 1. 変更

| 箇所 | 内容 |
| --- | --- |
| `urbanSizing.ts` | `MESHLESS_TARGET_FILL`（0.8）と`meshlessSiteFillScale`。必要住戸数ごとの実測の充足率の表から、内側が目標の割合で埋まるよう敷地の半径を縮める係数を返す（1以下） |
| `editorInput.ts` | 市壁のある町の敷地の半径に、上の係数と市壁の形の係数（`wallScale`）を掛ける。合成の記述子の経路（海岸など）の土地の見積もりにも同じ係数を掛ける。合成の敷地の半径の下限30 m |
| `wallShape.ts` | 稜堡形の`vectorWallAreaShare`を、稜堡（喉の線より外）を除いた面積で求める。稜堡形の町は他の形より市壁が大きくなる |
| `bastions.ts`（新規） | 稜堡形の市壁の稜堡を`auto-bastion:<n>`の予約地（`kind: "reservation"`）にする。街路・街区・住宅を置かない。道路が通る稜堡（門が稜堡の面にある）は町へ入れなくなるので予約しない |
| `pipeline.ts` | 道路の経路探索の前に稜堡を予約する。再生成の時は前の予約を消す |

計測の試験`gateRibbonObservation.test.ts`に、敷地の大きさの較正（`CE_GATE_RIBBON_CALIBRATE`、円形の市壁×人口14段×2 seed、内側の全区画を建てる）を足した。

## 2. 較正の経過

目標0.9で一度表を作り、実測で1回直した。この段階で、旧市街の市壁・classicの町割り・後期中世の既存の試験が人口の6〜10%を収容できなくなった（`doubleWalls`・`concentricLayout`・`wallShape`の試験）。表は既定の設定（時代の既定、町割りorganic）で測っており、旧市街の市壁や町割りが取る土地は入っていない。街道沿いの帯（W2）ができるまでは、この不足が未収容になるため、目標を0.8に下げた。W2の後に0.9へ上げる。

1,000人前後は2 seedの間で充足率が0.6〜1.3と大きくばらつく（市民の中心・修道院の予約地が人口の段で跳ぶため）。この範囲の表の値は大きめの敷地の側に寄せ、どのseedでも内側に収まるようにした。50戸未満の町は市民の中心の大きさで敷地が決まり、充足率は上がらない。

## 4. 試験

- `npx vitest run city-editor/generators/vector/generation city-editor/components/vector city-editor/renderers/vector city-editor/services/vector city-editor/services/analysis/meshlessStagePerformance.cli.test.ts`: すべて成功。
- 新しい試験: `wallShape.test.ts`の「稜堡の上に住宅を建てず、その分市壁を大きく取る」。
- 公園の木を確かめる4つの試験（`parks`・`openSpace3d`・`treeSeason3d`・`houseLod3d`）は、seed `p7c-c`の町が詰まって木のある公園が無くなったため、木のある公園ができる`p7c-d`に替えた。試験の内容は変えていない。

## 5. 残り

- 門のある稜堡は予約していない。門を幕壁に置くよう市壁の回転を選ぶ処理は、W1で市壁と道路の交差を扱う時に検討する。
- 市壁のない町には較正を掛けていない（本計画の対象外）。
- 目標を0.9へ上げるのはW2の後。
