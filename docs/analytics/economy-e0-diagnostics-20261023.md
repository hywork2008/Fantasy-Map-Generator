# E0 生産不採用・衣服と寝具の実決済診断（2026-10-23）

[E0初回](economy-e0-baseline-20261023.md)の残りのうち、生産候補の不採用理由と衣服・寝具の実決済観測を接続した。経済係数・需要・配分順・手順上限は変更していない。**E0全体は未完了**。乳・肉等の一次生産の観測境界、食料台帳対象外人口、所得層別の未観測範囲が残る。

## 実装と記録の意味

通常製造の診断を既存の`UrbanCraftCapacity.productionDiagnostics`へ保存する。候補を評価した時の`planning`、製造を試みた時の`execution`、都市のループ終了時の`loop`を区別し、商品・制約の組合せごとに回数を集約する。観測を選択・予算・材料取得の入力へ使わない。

- `materials`は実際の計画/実行の材料検査、`technology`は国家の製造可否またはレシピの技術条件、`profitability`は実際の採算検査。調達を実行して失敗した`procurementFailed`を計画時の材料不足と区別する。
- `funds`は実行時の資金上限/取得価格で停止した試行、`domainCap`は与えられた分野作業枠が0だった試行、`outputTarget`は数量目標・出力下限などで停止した試行。数量目標と丸めのどちらかを確定していないものはこの分類より細かく断定しない。
- 衣服・毛布の生産余地が0なら、物理需要0の`noDemand`、予算を伴う需要0の`householdBudget`、それ以外の在庫による`excessStock`を区別する。この検査は家計繊維の経路に限定し、他商品の需要がないことを一律推定しない。
- 正の計画が他候補に負けた場合は`ranking`。採用候補は`primary=null`。採用は納品や有償雇用の成立ではない。
- 代替レシピや下位材料計画で実際に遭遇した失敗を`constraints`へ併記し、最初に遭遇した理由を`primary`とする。成功した計画の途中の失敗を、その候補全体の不採用として数えない。併記理由を足して評価機会数にしない。全代替案を網羅した反実仮想の診断でもない。
- ループ終了は`stepLimit`、作業枠を使用した`otherWork`、それ以外（実行可能計画がない等）の`null`を区別する。回数は都市×生産サイクルの終了回数で、労働者数ではない。
- 製造成功時は同じ記録へ製造lot・実労働人口点・実支払賃金・購入材料費を保存する。運搬資産用の予約作業、委託、家内作業は通常製造の支払へ合算しない。
- 判定できない失敗は`unknown`。汎用の技能・設備不足を判定する検査がない箇所について、それらが十分だったことを意味する0を置かない。

家計側は`TextileLedger.settlementDiagnostics.buyers`へ都市IDまたは農村集団別の必要量・納品・市場購入・実支払・残予算を記録する。自家加工・委託の納品は既存の同じ必要量から引いた値を使う。通常納品は衣服と毛布で同じ家計現金枠を共有する既存の順序を維持する。

未充足量は、①衣服へ使用/留保された予算による`priorityGap`、②残る財布不足`budgetGap`、③購入可能分の品切れ`stockGap`、④残る価格構成・配分・セント丸め等`allocationOrRoundingGap`へ重複しない順序で分ける。有効品と有効な市場価格がない場合は`noPricedRouteGap`とし、不足0にしない。価格基準は有効な市場価格の最安値で、売り切れた安価品と残る高価品の組合せは④へ残り得る。①は衣服へ割り当てた資金を毛布へ回した場合の上限による配分で、供給が存在することの証明ではない。

併存条件は別の`constraints`に記録する。例えば毛布の主因が①でも、実際には予算と在庫の両方が足りなければ`priority/budget/stock`を併記する。これらの件数を未充足量へ加算しない。必要量の分かる家計のみを分母とし、所得層別や市場外家計の必要量が分かることにはしない。

既存観測ビューに`textiles()`を追加し、台帳・委託の材料代/加工賃・都市作業枠を複写する。生産の同期/分割実行の両経路に同じ`production:householdTextiles`観測点を設け、決済直後に採取する。JSON内の市場別生産集計はこの既存台帳からの読取専用派生値。大量の都市別行を二重保存しない。
