# CE meshless 道路経路探索の性能改善（2026-11-08）

[全量検証の性能改善](ce-meshless-validation-tuning-20261108.md)に続き、道路経路探索を改善した。同一固定入力で探索本体は **1,503.00ms → 42.68ms（97.2%短縮）**、生成全体は **3,177.53ms → 1,714.74ms（46.0%短縮）**。生成文書のSHA-256は一致した。

## 条件と計測

- 人口5,000人・シード `b5o620`・河川1本・海岸なし・外壁1重・Organic・Medieval・Age of Exploration・Voronoi/Small・FMG連携なし。中央プラザ・教会・墓地を含む、直前の検証改善と同じ条件。
- Apple M4、darwin 27.0.0、Node v22.23.1、Vitest/jsdom、1 worker。比較用計測は他のテスト・型チェックと同時実行せず、変更前後それぞれ単発測定。多数シード・平均・中央値は扱わない。
- 変更前は2026-11-08 07:23 JST、変更後は07:25 JST。ベースコミットは `7f5ca118d152ea83fc025a628cb1c34e8d134246`。実計測ソースのSHA-256は各JSONの `measurementSources`。
- 従来の `skeleton.road-routing` を、自由領域・接続点準備、探索本体、道路実体化の3区間に分割した。探索本体内の `routingSpans` は内数であり、親の `spans` と合計しない。
- 独立した全量検証は今回も生成後・SVG構築前に実行し、生成＋SVG合計には加えない。ブラウザのlayout/paint、Worker転送、Undo履歴、パネル更新は含まない。

変更前の探索内部では、全候補間の可視グラフ構築が1,479.55ms、最短経路計算が4.79ms。変更後は可視判定と最短経路計算を統合し24.96ms。境界索引作成は2.50ms、候補点作成は15.89ms → 14.94msだった。

## 実装と正しさ

`src/city-editor/generators/vector/generation/routes.ts` で、全候補点の組み合わせの可視判定と隣接リスト作成を先に行う方式を変更した。最短経路探索で、その接続が現在のコストを改善し得る場合だけ、従来の可視・離隔判定を呼ぶ。

- 点の生成と順序、最小コスト点の選択順、改善判定の許容値1e-8を維持する。
- 乾いた接続先は従来の隣接リストと同じ点番号順に処理し、認定済み橋リンクはその後に処理する。同コスト時の経路選択を維持する。
- 可視判定の線分方向も従来の小さい点番号→大きい点番号にそろえる。
- 境界格子・領域内判定・道路幅と離隔・認定済み橋の軸と識別子は維持する。川を直接横断する乾いた接続は引き続き禁止される。
- 検証・描画・保存の処理は変更していない。

試行した境界辺のRBush検索への置換は、同じ出力でも可視グラフ構築が約1,697msへ増えたため採用しなかった。最終実装は既存の境界格子を使う。
