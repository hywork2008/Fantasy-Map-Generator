# 立地の加点を割り引くと、町の数が増える地図がある理由（2026-11-07）

[site-bonus-20261107.md](site-bonus-20261107.md)§5の1の調査。シード2102だけ、H = 25でKが0.91倍に減ったのに、burgsが647から862に増えた。

## 1. 条件

- 地図: site-bonus-20261107のh25とh1の地図（シード2101〜2104）。
- 計測スクリプト: [popcells.mts](town-count-20261107/popcells.mts)。読み取りのみ。バイオームごとに次を数える。
  - 陸のセル、s > 0のセル、文化のあるセル、burgs。
  - 文化ごとに、中心のバイオーム・型・広がりやすさ（expansionism）・セルの数。
- 集計: [summary.txt](town-count-20261107/summary.txt)。

## 2. 町の数の決まり方

Settlement patternがStandardの地図では、`burgs-generator.ts`の`getTownsNumber`（Manorsが自動の時）で町の数が決まる。

- 町の数 = 候補のセルの数 / 5 / (グリッドの密度による係数)。
- 候補のセル = 文化があり、かつ人がいるかs > 0のセル。

文化は`cultures-generator.ts`の`expandCultures`で広がる。

- 文化の中心は、`cells.s`の高い順に、間を空けて選ぶ。
- 文化の型（River・Naval・Hunting・Nomadicなど）は、中心のセルで決まる。広がりやすさは、型ごとの乱数で決まる。
- 広がるのに要る費用は、中心と違うバイオーム・高さ・川・海岸で増える。上限（セル数 × 0.6 × neutralRate）を超えると、それ以上は広がらない。
- 文化の届かないセルは、s > 0でも町の候補にならない。

## 3. 結果

- burgsは、どの地図でも候補のセルの約0.21倍である。町の数は、Kでもs > 0のセルでもなく、文化の届いたセルの数で決まる。
- 2102のH = 1では、s > 0のセルの37%（1,808）に文化が届いていなかった。
  - 寒冷ステップは1,153のうち555、タイガは905のうち326しか届いていない。
  - 一番大きい文化（905セル）は、泥炭地の川沿いの点数の高いセルに中心を置いたRiver型である。River型は、川の無いセルに100の費用を払う。そのため、川の無い寒冷ステップ・タイガにはあまり広がらなかった。
- 2102のH = 25では、泥炭地の点数が下がり、文化の中心が別のセルに移った。
  - タイガのHunting型（1,155セル）と、寒冷ステップのNomadic型（410セル）ができた。どちらも中心と同じバイオームに安く広がる。
  - 文化の届いたセルは4,180（s > 0の92%）になり、町の候補も増えた。
- 2101・2104のH = 25では、逆に文化の届かないセルが増えた（2101は1,274のうち392、2104は2,690のうち916）。

## 4. 結論

- 2102でburgsが増えたのは、Aの式の誤りではない。
  - 文化の中心が移ると、型と広がりやすさが変わる。乱数の順番も変わる。
  - その結果、文化の届く範囲が地図ごとに大きく変わり、町の数も変わる。
- 4枚の合計では、burgsは0.89倍、Kは0.88倍で、ほぼ同じ割合で減っている。
- 町の数が文化の届く範囲で決まるのは、upstreamの仕組みである。Aでは変えない。
  - 文化の届かない土地でも、人は住んでいる（`cells.pop`）。そこに町は無い。
  - 町の数をKなどで決め直すかは、別の設計として扱う。
