# 人口の計算

AIアシスタントに解析させた結果を掲載。

複数国家ではなく、単一国家または州・都市単位の動きを元に、Simulation + RPG的なゲームの環境を作ることを想定して解析。

## AIによる解析結果

Fantasy Map Generator (FMG) における人口と軍隊の計算は、ボトムアップ（小さな単位から大きな単位へ）で積み上げる形でプログラムされています。

やりたいこと（食料生産量、男女比、年齢分布、世帯数、都市面積の算出）は非常に面白く、シミュレーションとして理にかなっています。現在のFMGの内部コードではこれらの細分化されたデータ（年齢や性別など）は保持していないため、実現するにはこの既存の基本人口データをベースに計算式を自作して拡張していく形になります。

以下に、現在のFMGにおける計算の流れと関与する要素を解説します。

---

### 1. 人口計算の流れ（Cells → Burgs → States）

計算は「国(States)から都市(Burgs)」へ割り当てられるのではなく、**「一番細かいマス目(Cells) → 都市(Burgs) → 州・国(States)」** という順番で合算されていきます。

1. **Cells（地方・農村人口 / Rural Population）**
   マップ上のすべてのマス（Cell）に対して、「居住適合度（Suitability：内部変数 `s`）」が計算されます。この適合度とセルの面積を掛け合わせたものが、そのセルの「農村人口のベース値」になります。
2. **Burgs（都市人口 / Urban Population）**
   各都市のベース人口は、その都市があるセルの居住適合度をベース（約5分の1）にして計算されます。そこに、首都であるかどうかのボーナス（1.5倍）や交通網の接続度、ランダムなばらつきが掛け合わされ、都市人口のベース値が決まります。
3. **States / Provinces（国家・州の人口）**
   その国（または州）の領土に含まれている**すべてのセルの「農村人口ベース値」**と、そこに含まれる**すべての都市の「都市人口ベース値」**を単純に足し合わせたものが、国家の総人口のベース値となります。

**※実際の表示人数の計算**
内部で計算されているのはあくまで「抽象的なポイント（ベース値）」です。画面上に表示される実際の総人口は、このベース値に全体設定の `Population rate`（人口レート：通常は1000など）と `Urbanization`（都市化率）を掛け算することで算出されています。

---

### 2. 人口（居住適合度）の計算に関わる主な要素

各セルの人口ベースとなる「居住適合度」は、主に以下の自然環境要素によって決まります（`src/main.ts` の `rankCells` 関数などで処理されています）。

*   **温度 (Temperature) と 降水量 (Moisture) ＝ バイオーム (Biome)**
    これが**最も重要な要素**です。温度と降水量の組み合わせによってそのセルのバイオーム（温帯林、砂漠、ツンドラなど）が決まり、バイオームごとに基礎となる適合度スコアが設定されています。
*   **川の流量 (River Flux)**
    大きな川が流れている（流量が多い）セルほど、適合度に大きなプラスのボーナスが与えられます。
*   **標高 (Elevation/Height)**
    標高が一定（50）を超えると、高くなるにつれてペナルティ（マイナス）がかかり、人口が減ります。
*   **海岸線や水辺の環境 (Coast/Water bodies)**
    *   **プラス要素**: 河口（Estuary）、淡水湖（Freshwater lake）、海辺（Ocean coast）、良港（Safe harbor）は、適合度に大きなプラスボーナスを与えます。
    *   **マイナス要素**: 干上がった湖（Dry lake）や溶岩（Lava）などはペナルティになります。
*   **交通インフラ（※都市の場合）**
    道路（Road）や航路（Sea route）の交差点など、他の地域との接続性（Connectivity）が高い場所は、都市の人口が大きく伸びる仕組みになっています。

---

### 3. 軍隊（Military）人数の計算方法

軍隊（兵士数）も、人口をベースにして計算されます（`src/generators/military-generator.ts`）。

1. **基本の徴兵率（1%）**
   農村および都市のベース人口の「約1%」が、軍隊の基礎人数として計算のスタート地点になります。
2. **文化と宗教によるペナルティ**
   セルや都市の「文化」や「宗教」が、その国家の主流（首都の文化・宗教）と異なる場合、「忠誠心が低い・非主流派である」とみなされ、算出される兵士の数が半分近くに減らされます。
3. **国家の警戒度（Alert rate）**
   国家の「拡張主義（Expansionism）」の強さや、周囲の国との「外交関係」によって警戒度が決まります。周りが敵国ばかり（Enemy）だと警戒度が上がり兵士数が増加し、逆に平和な同盟国（Ally）に囲まれていると兵士数は少なくなります。
4. **地形と部隊種別の相性**
   例えば、遊牧地帯や平原では「騎兵（Mounted）」が多く生成されやすくなり、高山では「歩兵」や「弓兵」が、港町（Haven）があるセルからは「海軍（Naval）」が生成されるなど、地形による倍率補正がかかります。
5. **最終計算**
   これらをすべて掛け合わせ、最後に `Population rate` を掛けることで、最終的な部隊（Platoons / Regiments）の人数が割り出されます。

---

**今後の実装に向けてのアドバイス**

「世帯数」や「男女比」「年齢分布」「必要な農地面積」といった概念を実装する場合、既存のFMGのセーブデータ構造（`pack.cells.pop` や `pack.burgs.population` など）から総人口を取得し、それに現実世界の統計データや中世の人口動態モデルの定数（例：1世帯=平均4.5人、農地1ヘクタールあたりの扶養可能人数など）を掛け合わせる独立したモジュール（拡張機能）を作成するのが最もスマートな形になります。


## 中世の人口動態

ファンタジーマップジェネレーター（FMG）のベースとなっている「中世ヨーロッパ（あるいはそれに近いファンタジー世界）」の人口動態シミュレーションにおいて、基準としてよく用いられる歴史的な統計データや、定番のロジック（ヒューリスティクス）をまとめました。

これらをFMGの人口データに掛け合わせることで、よりリアルな国家のシミュレーションが可能になります。

---

### 1. 都市と農村の比率（都市化率）
中世世界では、少数の都市民を圧倒的多数の農民が支える構造が基本でした。

*   **農村人口（Rural）**: 約 **85% ～ 95%**
*   **都市人口（Urban）**: 約 **5% ～ 15%**
*   （参考）FMGのデフォルト設定でも、都市化率は非常に低く設定されています。人口の大多数は食料生産に従事している必要があります。

### 2. 世帯人数（Households）
「世帯数から住宅の数を求める」ためのベースとなる数字です。中世の家族構造は地域によって異なりますが、一般的なシミュレーションで使われる平均値は以下の通りです。

*   **平均世帯人数**: **4.5人 ～ 5.0人** / 世帯
*   **都市の世帯**: 比較的少なく、4.0人前後。
*   **農村の世帯**: 労働力が必要なため大きく、5.0人 ～ 5.5人前後。
*   **住宅の数**: 基本的に「1世帯＝1家屋」として計算されます。

### 3. 年齢分布（Age Distribution）
中世は「多産多死」の社会であり、現代とは全く異なるピラミッド型の年齢分布を持っています。乳幼児の死亡率が非常に高く、平均寿命は30歳前後とされますが、成人（15歳以上）まで生き残れば50〜60代まで生きる人も珍しくありませんでした。

*   **子供（0〜14歳）**: 約 **30% ～ 40%**
*   **労働力・兵役（15歳〜50歳）**: 約 **50% ～ 55%**
*   **高齢者（50歳以上）**: 約 **5% ～ 10%**

### 4. 男女比（Gender Ratio）
出生時はほぼ1:1ですが、時代背景によって大人の男女比に偏りが出ます。

*   **基本の男女比**: ほぼ **1 : 1** （男性 50% : 女性 50%）
*   **農村部**: ほぼ均等。
*   **都市部**: 働き口（奉公など）を求めて女性が流入しやすく、やや女性が多い傾向がある（男性 45% : 女性 55% など）。
*   **戦時・戦争直後**: 兵士として徴兵される男性の死亡率が高いため、国家単位で女性の比率が高くなります。

### 5. 食料生産と必要な農地面積（Agriculture & Land Area）
「人口から必要な農地を求める」「食料から養える人口を求める」場合、以下の基準値がシミュレーションでよく採用されます（例：S. John Rossの『Medieval Demographics Made Easy』などのTRPG向け統計論考より）。

*   **人口密度**: 1平方マイル（約2.6平方キロ）あたり、約30人 ～ 120人。（気候や土地の肥沃さによる）
*   **1人を養うために必要な農地**: 約 **1.5エーカー ～ 2エーカー** （約6,000㎡ ～ 8,000㎡）。
*   つまり、**1平方マイルの耕作地**で、およそ **180人（農民自身の家族を含む）を養うことができる**という計算が一般的です。
*   **余剰食糧**: 農民1家族（約5人）が一生懸命働いて、自分たちの他に「1〜2人」の非農業従事者（都市の職人、兵士、貴族など）を養える程度の余剰食糧しか生産できませんでした。

### 6. 都市面積と人口密度（Urban Area）
都市の広さを人口や家屋の数から割り出すための基準です。中世の都市は城壁に囲まれており、家々が密集していました。

*   **都市の人口密度**: 1エーカー（約4,000㎡ = 63m×63m）あたり **約60人 ～ 100人**。
*   **1平方キロメートルあたり**: 約 **15,000人 ～ 25,000人**と、現代の東京の人口密度に近いか、それ以上の過密状態でした。

---

### 実装に向けた計算ロジックのアイデア例

もしこれをFMGのスクリプト（拡張機能など）として組む場合、以下のような計算式が考えられます。

```javascript
// 例：ある都市(Burg)のパラメータ算出
const urbanPopulation = burg.population * worldContext.populationRate; // FMGの実人口

// 世帯数と住宅数
const households = Math.floor(urbanPopulation / 4.5);
const requiredHouses = households; 

// 男女比（ざっくり）
const males = Math.floor(urbanPopulation * 0.49);
const females = urbanPopulation - males;

// 必要な農地（ヘクタール換算：1ヘクタール＝約10,000㎡）
// 1人を養うのに約0.8ヘクタール必要と仮定
const requiredFarmingAreaHectares = urbanPopulation * 0.8; 

// 都市の面積（ヘクタール換算）
// 1ヘクタールあたり約200人と仮定（かなり密集）
const urbanAreaHectares = urbanPopulation / 200;
```

これらのデータを用いてUI拡張を行えば、都市をクリックした際に「世帯数：1,200」「必要農地：4,000 ha」「子供の数：1,500人」といった詳細なレポートを表示させることができ、世界観に非常に奥行きが出ます。
