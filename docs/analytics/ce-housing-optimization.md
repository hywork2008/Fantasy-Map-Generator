# CE 高品質住宅と森林適用の最適化

実施日：2026-10-28。F5で残った中都市の約48秒の景観適用と、高品質住宅の描画負荷を改善した。

## 変更

- 高品質の住宅を全域へ一括生成する経路を、常時表示する正確な簡略形状と、近景だけの詳細モデルへ変更した。簡略形状は既存の敷地・壁・階数・屋根形状・色・接地高さを使い、都市の配置や森林面積を変更しない。BVの単体モデルや2D出力の品質は変更しない。
- 近景の詳細は最大64棟・500,000三角形・64 calls。描画時の大きさ80 pxで入り、60 pxで戻るヒステリシスを設け、近い住宅を優先する。
- geometryの新規構築は1フレーム2件まで。待っている住宅には簡略形状を残し、有限の追加フレームで構築する。完了・静止後は更新しない。キャッシュは96層・1,000,000三角形以内に制限する。
- 詳細化した住宅だけ簡略形状の描画インデックスから外す。同じ頂点・インデックスバッファを再利用し、詳細と簡略の壁を二重描画しない。建物indexを維持し、どちらの表示でも選択元の区画を保つ。
- 景観適用等で建物の入力・品質・地形上の基礎高さが等しい場合は、住宅レイヤーを再利用する。道路の変更時は玄関の向きを再評価し、色・敷地・高さ・品質が変われば更新する。
- BVの定義キャッシュは512件で入れ替わるため、オブジェクトの参照同一性だけで照合すると同じ住宅の再生成が起きていた。住宅の仕様と品質を含む明示的な `cacheKey` を使い、定義オブジェクトが作り直されても共有する。指定のない他モデルは従来の参照単位を維持する。最後の所有者で解放する規約も維持する。
- 玄関の向き・モデル仕様はカメラに依存しないのでキャッシュする。入力を再評価するときだけ無効化する。近景の追加装飾は、詳細モデルになった住宅を除外する。
- 計測パネルに詳細住宅数・三角形数、JSONに加えてキャッシュ・構築待ち等の内訳を追加した。

## 実GPUの再計測

Apple M4 / Metal / Chromium 151、1000 × 720、DPR 1、住宅品質high、森林品質standard、影なし。F5の固定3都市を使い、同じビューで従来景観から森林へ適用する。F5の俯瞰・林縁・低視点に、市街へ近づく経路を加えた。各姿勢12フレームのウォームアップ＋64フレームを測定。構築待ちのLOD切替も測定区間から除かない。

時間はms。適用CPUは3D同期処理の1回の測定で、画面操作全体のp95ではない。フレーム間隔はヘッドレスRAF・計測を含み、画面のFPSへは逆算しない。

| 都市 | 森林適用CPU：前 → 後 | 操作間隔p95最大：前 → 後 | 最適化後GPU p95最大 |
| --- | ---: | ---: | ---: |
| 平坦な小都市 | 2,324.5 → 594.6 | 26.2 → 27.0 | 7.5 |
| 平坦な中都市 | 47,960.7 → 2,304.9 | 102.2 → 26.3 | 16.6 |
| 川と谷の小都市 | 5,099.7 → 1,799.2 | 27.0 → 27.7 | 10.2 |

中都市の適用CPUは47,960.7 → 2,304.9 ms（約95.2%減）。俯瞰だけの間隔p95は102.2 → 16.2 ms、市街への接近を含む全4姿勢の最大は26.3 msだった。固定3都市すべてで33 ms以内を確認した。近景では最大64棟を詳細化し、遠景は0棟で全棟の簡略形状を維持する。

## 再現方法

```sh
CE_FOREST_HOUSING=high CE_FOREST_URBAN=1 \
CE_FOREST_OUTPUT=docs/analytics/ce-housing-optimization \
CE_FOREST_RAW_OUTPUT=docs/analytics/raw/ce-housing-optimization \
  node --import tsx scripts/benchmarkCeForestFinal.mts
```

F0のraw固定入力が前提。`CE_FOREST_RAW_OUTPUT` を分け、F5の以前の全量観測を上書きしない。GPU timerが使えない場合やSwiftShaderの場合は停止する。Git基点と入力のSHA-256、各時間列と最大統計は [結果JSON](ce-housing-optimization/results.json) を参照する。

## 確認したテスト

関連8ファイル・39件、型検査、変更TypeScriptのBiomeが成功。全件テスト・多数seedの検証は行っていない。

- `regionalHouseLod.test.ts`：近景の予算・1フレームの構築上限・静止時の停止・地形変更・玄関再判定・完全解放。
- `bvInstances.test.ts`：作り直した定義の共有とbatch化、所有権、キー未指定の独立性、選択ID。
- `regionalHouseMeshes.test.ts`、`cityMeshes.test.ts`、`buildingDetails.test.ts`：既存の形状・接地・描画・色。
- `cityViewRendering.test.ts`：景観を切り替えても等しい住宅レイヤーを再利用し、カメラ／品質更新を必要時に描画する。
- `performancePanel.test.ts`、`editorMessages.test.ts`：計測UIと日英カタログ。

## 残る作業

中都市の景観適用は約2.3秒の同期処理が残る。次に進める場合は、森林領域・農地と施設・都市の派生計画の構築時間をさらに分け、必要な部分だけ非同期化する。別GPU・高DPR・影ありでの追加校正も残る。今回の33 ms達成をそれらの条件へ一般化しない。
