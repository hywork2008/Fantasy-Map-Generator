# CE混交林の予算判定と簡略表示の復元

実施日：2026-10-29。対象：[樹木LOD作製計画](../plan/ce-forest-biome-tree-lod-tasks.md) F5-1。

## 問題と変更

従来は `landscapeTreeSpecies(..., [0, 0])` の1地点だけで、森林全体を品質優先か予算内表示かに分岐していた。原点が品質優先なら全候補に無限の詳細予算を渡し、簡略木の親グループも非表示にした。そのため別の予算方針の木が混在すると、本来の制限を迂回したり、詳細として非採用の候補が消える可能性があった。原点が予算内なら、別の場所の品質優先木まで集合林冠やチャンクの採否に左右された。

`forestMeshes.ts` は候補配置をgeometry生成から分離し、実際に森林内へ収まる候補の樹種から、チャンクごとに品質優先木の有無を判定する。結果のbooleanをキャッシュする。原点への照会は行わない。予算内だけの遠景チャンクでは、候補を調べても立木のgeometryやinstanceを作る必要はない。

品質優先木のあるチャンクは地表と候補を保持し、簡略木を方針ごとに別batchへ分ける。品質優先の簡略batchは行列用としてのみ使い、描画しない。隣接する予算内の木は簡略batchを表示し、採用BVモデルで置換できる場合だけ同じ候補の行列をマスクする。共有の詳細選択処理へは残りの有限予算を渡し、各候補自身のprofileだけが品質優先の例外を使う。

予算内だけのチャンクには既存の集合林冠／middle／nearの予算判定を使う。draw callsによる集合林冠への集約では対象の予算内チャンクだけを結合し、他の品質優先チャンクへ林冠を重ねない。置換したoverview geometryは解放し、現在のものもdispose時に1回だけ解放する。

`forestTreeDetails.ts` は選択した品質優先木の本数を返す。森林統計には簡略表示ですでに数えた予算内の候補へその本数だけを加え、混在時に二重に本数を計上しない。元の行列の復元、作者別の採用、品質の選択方法は従来の仕組みを使う。

## 予算の意味と制限

- 品質優先木は従来どおり距離で選んだ品質を保持する。簡略化無効の場合は従来どおり全樹種をultraとする。4品質のモデル、作者、CE採用版は変更していない。
- 予算内のBV詳細木は有限の残予算で選び、足りなければ低い品質または簡略表示へ戻す。
- 品質優先チャンクの地表と、混在する非採用木の簡略表示は保持する。これらの最低限の表示と品質優先木を含む森林全体は、通常の上限を超える場合がある。後述の1三角形・0 callsという試験入力も、森林全体の達成予算を意味しない。
- 三角形とcallsの統計は、マスクした簡略instanceの元の描画コストも含む保守的な値。GPU側もゼロ行列のinstanceを提出するため、詳細木の本数と単純に比例しない。フレーム時間は別途F5-3／F5-4で測定する。

## 回帰テスト

関連Vitest 2ファイル、重複を除く34件が成功した。

```sh
npx vitest run src/city3d/three/forestMeshes.test.ts src/city3d/three/forestTreeDetails.test.ts
```

既存31件の実行後、新規3件を対象実行し、原点の戻り値だけを変更した既存の予算試験1件も対象実行した。新規混在試験の初回fixtureは樹種境界がチャンク境界と一致していたため、境界をチャンク内部へ移して再確認した。

確認した重要な挙動：

- 未使用の原点が品質優先／予算内のどちらを返しても、同じ実配置に対して同じ表示になる。予算内だけの実配置は、原点が品質優先でも上限を守る。
- 同じ広葉樹の簡略形状を共有する品質優先シナノキと予算内ボダイジュを混在させ、詳細予算を1三角形・0 callsにしても前者は維持、後者は簡略表示を残す。
- 通常予算へ切替後、再び厳格予算へ戻しても全候補の位置・回転・寸法は一致し、重複した配置は0。
- 予算内の90領域を、品質優先チャンクの地表で予約したcallsを差し引いた残予算で集約しても、別チャンクの品質優先木は詳細表示を維持し、overviewにそのチャンクを含めない。現在のoverviewを二重disposeしない。
- 既存の品質3段階、全詳細モード、距離品質、採用切替、5樹種目への移動、影予算、地形・穴・資源解放の関連試験も成功。

変更TypeScript 3ファイルのBiome確認が成功。`npx tsc --noEmit --pretty false` は既存の `src/city-editor/renderers/fogControls.ts(45,36)` のstringとEditorMessageKeyの不一致が残るため失敗し、今回の変更箇所の型エラーはなかった。
