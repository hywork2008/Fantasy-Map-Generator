## 実装

- M4で採用した骨格・領域・接道から、到達できる道路に接続する小路を追加する。街区の接道辺から内側へ伸ばす方式で、ボロノイ／ヘックス／補助セルは作らない。交差する既存道路を横断する候補は採用せず、採用小路の根元は元曲線のanchorを共有する明示接続とする。
- 土地を河岸・商業・工芸・郊外危険業種・住宅の用途候補に分類する。河岸・郊外等の制約と用途の優先順位から施設を配置し、その実寸敷地と入口通路を予約する。その後、予約を除いた残地から住宅の接道候補を取り直す。
- `populationFacilityRequests`の需要・BV資産組立をセル非依存の`buildPopulationFacilityRequests`へ抽出した。旧CEは同じ関数を呼び、既存の需要・建物寸法・配置APIを維持する。5,000人の285工房＋9会館、住居兼工房155戸は変更しない。
- BVの測定済み外形・敷地・入口位置をメートルのまま回転・平行移動する。収めるために縮小しない。仮寸法の施設はprovisionalとして保存・破線表示・集計する。河岸施設は物理水域から50m以内を確認する。
- 住宅は既存BVの`house:mediterranean`を使用する。床面積40㎡・2階・住宅利用率0.85を共通容量式に渡して1棟1住戸とする。住居兼工房の1戸は一度だけ数え、残りの必要戸数を住宅で補う。人口は未収容枠を含めた最大剰余法で整数配分し、総人口を保存する。
- 固定／手動敷地、予約地・公園・農地・森林・墓地、水域、壁、道路、交差点、門の開口を保護する。入口通路も予約地として後続住宅と道路・橋・門の編集から保護する。容量のない既存手動建物は容量を推測せず、診断を残す。
- 自動合成入力だけ、既知の表示フレーム内・元市域の最大1.4倍まで郊外を追加できる。元のsite・固定道路・橋・壁・門の形状は変えない。FMG入力、手動入力、固定／手動の壁ではこの拡張を行わない。市壁なしの郊外業種は元市域半径の外側35%を候補にし、壁がある場合は壁外に限る。
- 小路64本以下、配置1,500件以下、施設／住宅それぞれ候補検査40,000回以下の同期処理。施設需要を減らしたり建物を重ねたりせず、不足・理由・未収容人口を保存する。保存8MiBを超える候補は採用しない。

## ステージと保存

native v5に、採用形状・BV由来寸法・入口・予約地・用途・容量・人口配分・不足とチェックポイントのID一覧を保存する。読込・描画は需要や建物を再生成しない。native v1〜v4をv5に移行し、将来版は拒否する。

| 段階 | 表示対象 |
| --- | --- |
| 1/6 Inputs | 元入力 |
| 2/6 Skeleton and connections | M4骨格・接続 |
| 3/6 Land and frontage | M4土地・接道 |
| 4/6 Blocks and lanes | M5街区・小路。新しい建物なし |
| 5/6 Facilities | 同じ生成で採用した施設だけ |
| 6/6 Housing and completed city | 上記施設と残地住宅 |

`medieval`では施設需要・配置と施設段階を省略し、5段階にする。既存手動配置は各段階で保持する。各チェックポイントの容量・収容人口は、その段階で表示する配置だけから集計する。

生成候補・採用・取消を分離し、採用は履歴1操作。M5再生成は自分の所有する小路と建物だけを作り直す。採用後に形状・接続・固定区分等が変わっていた場合は停止して編集を保護する。M4骨格生成はM5採用文書への直接適用を拒否する。編集後の古い段階キャッシュは表示せず、M6で依存更新を扱う。

## 数値幾何

施設の入口予約を大量に引いた残地で、クリッピング核がほぼ一致する辺を追跡できない場合があった。既知のsweepエラーに限って、派生領域を0.01µm、次に0.1µmで丸めて再試行する。重複した極短辺・同一直線上の冗長点も派生出力で除去する。元曲線・測量水域・固定形状は変更しない。これは5mmの曲線標本精度を十分下回る数値安定化であり、編集セルではない。

残地検証は境界箱による候補絞り込みを行う`simpleContour`を使う。従来の全辺対検査では、離れた同一直線上の辺を浮動小数点の符号だけで交差と誤認するケースがあった。採用配置間の重複はRBushと領域交差面積で検証する。
