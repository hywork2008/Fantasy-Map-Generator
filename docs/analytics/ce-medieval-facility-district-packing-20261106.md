# CE施設付き街区の残地再分割

対象: `medieval-facilities`。計測日: 2026-11-06。
比較相手は同じ作業ツリーの変更前（`allocateBVFacilities` / `populationFacilities` / `blockInfill` をコミット時点に戻した生成）。全量JSONは残していない。再生成入力は下表のテストとフィクスチャである。

## 何を変えたか

- 用途（商業・職人・危険工程・河岸）ごとに街区候補を採点し、各施設は元の要求順のまま、その候補を先に試す。候補で入らない施設は、従来の中心から外側への走査へ戻す。用途順に要求自体を並べ替えると接道フィクスチャで施設が1件落ちたため、要求順は変えない。
- 用途優先の結果が、従来走査で置けた施設を1件でも欠くときは従来結果を残す。
- 人口割当と成長整形の後に、施設に接する残地へ住宅列と明示的な庭を足す。既存の住宅は消さない。18 m²未満または幅3.5 m未満、接道できない残地は庭にする。BV敷地は縮小も変形もしない。
- 非直交の建物外形（F4）は入れない。残る楔は庭として残す。

## 生成時間の上限

同じ計測での `generateCityOnDocument` は、5,000人の固定入力で4.9秒から9.9秒になった。増分は用途候補の二回目の配置と残地再分割である。このケースの上限は12秒とする。1,000人は1.5秒、接道フィクスチャは12.3秒だった。
