## 実装

G01 Notre-Dame de Parisの既存Lowと専用Highを11部品へ分割し、BVで全体／単体と品質を組み合わせて表示できるようにした。HighはLowの装飾追加だけではなく寸法や配置にも差のある既存専用モデルなので、それぞれの形状を別々に照合して維持した。新規High資産を増やす変更ではない。

| 部品 | Low三角形 | High構成内の三角形 | High構成内の部品品質 |
| --- | ---: | ---: | --- |
| 身廊・側廊・側礼拝堂・窓列・側面飛梁・屋根装飾 | 5,940 | 182,332 | High |
| 周歩廊 | 96 | 192 | **Low** |
| 内陣後陣・上部窓 | 96 | 25,072 | High |
| 放射状礼拝堂群 | 504 | 50,099 | High |
| 後陣の放射状飛梁と支持部 | 168 | 4,140 | High |
| 西正面・扉・バラ窓・彫刻・回廊 | 4,594 | 107,120 | High |
| 北西塔 | 1,072 | 13,024 | High |
| 南西塔 | 1,072 | 13,024 | High |
| 北翼廊 | 476 | 82,740 | High |
| 南翼廊 | 476 | 70,340 | High |
| 交差部の尖塔・支持段・人物像 | 1,088 | 17,776 | High |

側面の窓・装飾と飛梁は支持する棟とまとめ、西正面は扉・バラ窓・王像・ギャラリーを一緒に切り替える。鐘楼は塔身・開口のある鐘室・鐘・屋上を一つの部品として保持する。Low／Highで部品IDと並びを共通にしたが、完成形状の任意交換や自由な配置プリセットとはしていない。

Cologne／Salisburyと同じ`landmarks/components/assembly.ts`を使う。専用の`NotreDameKit`で作る部品も共通factoryへ渡せるよう型を一般化し、任意の部品品質の指定を追加した。既存のキット、作者情報、部品台帳、結合後の頂点範囲、所有資源の解放を維持する。ギルドホールの共通寸法・建築・外階段の基盤は変更していない。CEの配置・LOD・描画コードも変更していない。

## High内のLow部品を明示

Highの周歩廊は上下2層で192三角形あるが、既存の単純な`apse`外殻を2つ組み合わせただけで、部品の品質をHighとする詳細を持っていない。親モデルのHighを継承させず、明示的Lowとした。全体Highの説明にもこの制限を追記した。

BVの固有建築の部品選択肢には品質を併記する。例えばHigh全体を選んでいても`Ambulatory · Low`と表示する。全体の選択欄を`Assembly resolution`とし、単体の品質と区別する。周歩廊単体の比較表は「表示中のLowだけを計測」とし、全体Highの565,859三角形としてキャッシュしない。

周歩廊を単体で見ると、単純な半円形の外殻・屋根の重なりも残っている。今回は分割前の形状維持を優先し、この形状の修正と実際のHigh化は次の制作対象とする。Highと表示し直すだけでは完了にしない。

設定の等しい通常Lambert材質をまとめ、UVを除いた。Lowでは非index化により約6.8%増え、Highでは約25.0%減る。CPU常駐属性バッファの測定で、JSオブジェクト・一時領域・GPUメモリ・FPSは含まない。メッシュの削減は三角形の削減ではない。

Highの身廊等182,332、南北翼廊153,080、西正面107,120で全体の約78.2%を占める。周歩廊192三角形は現行Highの主な負荷原因ではない。今後の品質改善と装飾LODの検討を区別する。

ワールド座標・法線を1e-5で丸め、三角形の頂点順・材質設定を含めて、バッチ順を無視した署名を比較した。両品質とも分割前後で一致した。

## 検証と再現

- `npx vitest run src/buildings/landmarks/notreDame.test.ts src/buildings/landmarks/notreDame/highDetail.test.ts src/buildings/landmarks/notreDameParts.test.ts src/buildings/landmarks/cologneParts.test.ts src/buildings/landmarks/salisburyParts.test.ts`：関連5ファイル15件成功。
- 固定署名、三角形数、11部品の品質・作者、台帳と頂点範囲、選択した塔だけの生成、元の位置、資源の独立と一度だけの解放を検証。
- 既存の鐘楼の実開口・中央の柱、奥まった3つの扉、28個の王冠、バラ窓、25本の飛梁、16体の尖塔人物像の検証を維持。材質結合でメッシュ名が変わるため、扉は材質とレイの奥行、細部の数は各factoryの内部結合後の生成結果で確認する。
- 変更した建築・共通処理・関連テスト6ファイルのBiome check、BV mainのformat、`git diff --check`が成功。
- 実BVで全体Low／High、西正面High、鐘楼High／Low、全体High内の周歩廊Low、交差部尖塔High、全体への復帰、カタログ再選択時のリセットを確認。ページエラーと比較値の混入なし。品質表示を選択肢へ追加した後も再確認した。
