# 経済拡張無効時の食料容量近似

2026-10-05更新。年平均気温だけで求めた前回のBria食料キャパシティは撤回し、診断結果を削除した。現在の表は月別気温を適用した農業モデル用である。実装の詳細は [月別作物モデル](monthly-crop-climate-v1.md) を参照する。

## 境界

本体は経済拡張のモジュールを import しない。経済拡張の作物選択・収量計算を呼ぶのは、オフラインの校正ツール `src/extensions/economy/generators/foodClimateCalibration.test.ts` だけとする。

本体は出力済みの `src/data/foodClimateCalibration.json` を補間する。作物追加や経済モデル変更後は再校正する。出力には参照した8ファイルの SHA-256 を保存する。既存の土壌・作物適性を本体が再実行して結果を合わせる方式は採用しない。

## 測定対象

`getCropMix` が月別気温から成熟可能な作期を評価し、生育期平均気温・年間降水・土壌・灌漑補給に合う作物を選ぶ。文化の嗜好と決定的な小変動を含み、通常の主作物と豆類の輪作面積は2:1になる。

`calculateAgriculturalLandProfile` の実際の年収量（kg/播種ha）を測る。作物適性・作物収量倍率・降水係数・作付け回数・灌漑面積割合を含む。技術・肥料・塩害・土壌劣化・災害は基準状態とする。雨水のみと灌漑部分は別々に作物を選び、年収量を面積加重する。

降水値8未満の基本収量0を除去した。0〜8は `0.4 × 降水値 / 8` として連続的に増やし、8以上の係数は維持する。作物固有の最低降水量は引き続き評価する。これはゲーム用の暫定係数で、月次土壌水収支ではない。

スペルトを含む全畑作物を使用する。クリは樹園地生産に属し、現行の主食容量には算入されないため、この主食収量表にも含めない。

## 組み合わせと統計

表のversionは2、modelは `monthly-crop-v1`。本体は年平均気温、月別気温の最大最小差の半分である季節振幅、年間降水、補給水深、灌漑割合、土壌を入力にする。

| 入力 | 標本 |
| --- | --- |
| 気温 | −5〜40°C、1°C刻みの46点 |
| 季節振幅 | 0, 1, 2, 4, 5, 6, 8, 10, 12, 16, 18, 22, 26°C |
| 降水プロキシ | 0, 2, 3, 4, 5, 6, 8, 10, 11, 12, 13, 15, 16, 17, 20, 23, 30, 35, 40, 60, 120, 255 |
| 補給水深プロキシ | 0, 1, 2, 4, 8, 16 |
| 灌漑面積割合 | 0と1を測定し、面積加重で補間 |
| 土壌・文化 | 6土壌、11文化、各文化4セル |

較正には中心気温と振幅から作った12か月の余弦波気温を直接渡す。計 **41,678,208セル条件**。CSVには947,232条件の平均収量・10/90パーセンタイル・作物選択回数を保存する。本体用JSONは947,232個の平均収量と取水目標からなる。文化・セル差は平均化し、本体で個別の作物計画を復元しない。

未使用の小数気温点、補給水深、灌漑割合0.1/0.5と、別の文化・セルIDで **56,430条件**を検証した。振幅には標本軸の値を使っており、全軸の未使用点を網羅する検証ではない。

| 絶対誤差 | kg/播種ha |
| --- | ---: |
| 平均 | 3.98 |
| 95パーセンタイル | 19.06 |
| 最大 | 96.95 |

数値は [検証JSON](food-climate-validation.json) に記録する。成熟や作物切替の境界では大きい誤差が残る。全12か月を振幅へ圧縮すること、軸端での補間制限、年間降水の使用も近似上の制約である。現実の歴史的収量・肥料・災害への精度保証ではない。

JSONは約7.5 MB、監査用CSVは約85 MB。CSVは実行時に読み込まない。モデル変更後は参照ファイルのhashを更新するだけでなく、表を再生成する。

## 本体への適用

`estimatedFoodProduction.ts` は本体側の地形・土地面積と、既存の本体の河川水量配分器を使用する。河川上と隣接セルだけが取水でき、複数セルが同じ河川の水を重複使用しない。流量不明・0なら補給は0。

拡張機能なしでは灌漑投資の実態がないため、村落の低投資シナリオとして指令面積10%、配送効率40%を仮定する。流量1あたり年水量30、河川に残す割合55%は校正対象の経済モデルの基準と対応する。この流量換算は地図用係数であり、実測のm³/sではない。補給量はha×降水プロキシの単位で保持する。灌漑目標の不足水深を満たせる面積だけに届ける。

農業容量は耕作面積×補間した収量×播種割合0.67×可食割合0.65÷年間200 kg/人で近似し、人口ポイントへ換算する。土地予算があれば既存の農地面積を使用し、予算がなければ森林被覆・地形から未開墾面積を除く。農地計画の入力には開墾可能な土地上限と同じ校正収量を渡す。

新規地図の初期容量、拡張無効時の農地計画、地図読み込み後・経済拡張無効化時の容量更新に適用する。経済拡張が有効な時は拡張自身の計算結果を使う。無効化によって保存済みの農地・人口・市場在庫を変更しない。非農業・地下食料容量は維持する。

## 再現コマンド

```sh
FOOD_CLIMATE_CALIBRATE=1 npx vitest run src/extensions/economy/generators/foodClimateCalibration.test.ts
FOOD_CLIMATE_VALIDATE=1 npx vitest run src/extensions/economy/generators/foodClimateCalibration.test.ts
```

表生成と検証は別プロセスで行う。本体の表はモジュール初期化時に読み込まれるため、生成と同じプロセスでは旧表が残る場合がある。通常の同テストはテーブルを書き換えず、未使用条件で誤差を検証する。校正は固定のカタログ・セルID・文化順序で再現可能。`FOOD_CLIMATE_VALIDATE=1` で検証値を `food-climate-validation.json` に保存する。
