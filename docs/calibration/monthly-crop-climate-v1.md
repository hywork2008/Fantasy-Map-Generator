# 月別気温を使う農業モデル v1

2026-10-05。年平均だけによる前回のBria食料キャパシティ再計算結果は撤回し、`bria-food-capacity-rainfall-fix.json` を削除した。本書は月別気温の適用内容を記録する。新しいBriaキャパシティの確定値を報告するものではない。

## 責務

本体の `getCellClimateNormals` / batch reader が浮動小数点の12か月気温を提供する。経済拡張の `seasonalCropClimate.ts` が成熟可能な作期を評価する。本体からこの拡張モジュールを呼ばない。本体が使うのはオフラインで測定した数値表と、作物非依存の気候特徴量だけである。

## 作期の評価

月平均気温を月内の代表気温として、作物の最低生育温度を満たす連続期間を探す。12月から1月への連続も維持し、月の日数と閏年を使う。日別の実際の霜・最高最低気温を再現したモデルではない。

各作期に対して最低成熟日数と `Σ max(0, 月平均気温 − 最低生育温度) × 生育日数` を評価する。両方を満たした時点で成熟し、作期末の収穫期間に収穫重みを配分する。同じ作期から作物適性用の生育期平均気温、収穫月、労働月、作付け回数を求める。不成立の作物は選択候補から除外する。年平均4°Cでも暖かい夏があるセルで春作が成立し、夏が短すぎる／熱量が足りないセルでは成立しない。

作物の既存温度範囲は、生育期平均に対する暫定の適性曲線として使う。年平均資料の値を生育期の実測限界と断定しない。作物の値の較正・品種別の春化／越冬／休眠条件の精緻化は残る。

| 作物群 | 最低作期日数 | 最低積算温度（基準は各calendarの最低生育温度） |
| --- | ---: | ---: |
| 冷涼穀物（スペルトを含む） | 120 | 500°C日 |
| 温暖穀物 | 120 | 900°C日 |
| 豆類 | 150 | 550°C日 |
| 根菜 | 150 | 500°C日 |
| 樹園地・ブドウ（クリを含む） | 180 | 1,000°C日 |

これらは初期のゲーム係数。FAOの[オオムギ資料](https://ecocrop.apps.fao.org/ecocrop/srv/en/cropView?id=1232)は春作と冬作の期間を区別するが、上表の全作物の熱量を保証する資料ではない。冷涼穀物の240日カレンダーだけで春作を排除する状態を解消するため、120日の春作を選べるようにした。冬作の春化やクリの樹齢は、このv1で新たに実装した機能ではない。

二作期が成立すると年収量と労働量にその回数を反映する。収穫重みは一年全体で1に正規化し、二作期のそれぞれで一年分を二重加算しない。連続生産作物も成熟条件を通過した場合に限り通年配分する。コホート移動は全月が生育可能なセルに限定し、寒い月に作期を移さない。

## 経済拡張への接続

- 農地生成・作物選択・年収量: `agriculturalLandUse.ts`。年平均気温の総括収量係数を現代の作物カタログには重ねない。
- 農作業月: 同じ作物計画の労働重みを使う。
- Food Ledgerと通常の作物商品: `production-utils.ts` / `foodProduction.ts`。生産比率は面積比ではなく、適性・収量倍率・作付け回数で重み付けした年収量比とする。その月に収穫する作物だけが市場へ入る。
- 樹園地: `viticulture.ts`。月別気温から成熟期間と収穫・労働月を求める。主食容量へのクリの新規算入は行っていない。
- 部分灌漑: 雨水のみの面積と灌漑面積を分けて作物を選ぶ。灌漑による二作期・追加水量を未灌漑部分へ適用しない。

気候は一回の農業処理で本体のbatch readerを準備し、セル・作物ごとに全地図のハッシュを再計算しない。生産処理は直近の農業処理が準備した気候を使う。年・地図オブジェクトの変更と農業再生成ではreaderを更新する。設定編集時は既存の農業再生成経路で新計画を作る。最小のテスト用world／生成前のworldには12か月同温の気候を与え、旧気候帯の代表温度には戻らない。

## 本体の近似表

表のversionを2、modelを `monthly-crop-v1` に更新し、年平均気温に加えて月別気温の最大最小差の半分（季節振幅）を入力にする。年平均が等しくても季節性が違う条件を別々に測定する。本体の `estimatedFoodProduction.ts` は実セルの月別気温からこの特徴量を得る。

較正では経済拡張に月別気温を直接渡し、土壌・文化・作物・降水・補給水・灌漑割合を変えて、実際の作物選択と年収量を測る。生成と検証は別プロセスとする。再現コマンドと最終的な誤差は [food-climate.md](food-climate.md) と [検証JSON](food-climate-validation.json) に記録する。

振幅への圧縮は数値近似であり、実セルの全12か月値や月別収穫計画の完全再現ではない。降水は引き続き年間の適性と配分水量で評価する。月次土壌水収支、季節降水、積雪融解は未実装なので、これを気候・水モデル全体の完了とは呼ばない。

## 検証

- 年平均4°Cで夏季熱量が足りる春作と、通年4°Cで熱量が不足する春作を区別する。
- 暖かい期間が短すぎる場合、熱量だけが不足する場合を除外する。
- 南半球の年越し作期と北半球の収穫月を確認する。
- 1275相当の本体月別気温から大麦の作期が成立することを検証する。現在の農地面積やキャパシティを合格値として固定しない。
- 部分灌漑の年収量は雨水のみ／全面灌漑の面積加重結果と一致する。
- 年収量と収穫重み、農作業月、商品流入の整合を確認する。
- 新しい気候snapshotでカレンダーを再生成し、閏年にも対応する。
- 拡張有効／無効のどちらでも、年平均だけの旧表を新モデルの較正表として使わない。
