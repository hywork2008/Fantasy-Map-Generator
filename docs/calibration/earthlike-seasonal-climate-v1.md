# 地球型月平均気候v1の実装記録

2026-10-05追記: 本書は気候基盤を実装した時点の記録。農業への月別気温適用と本体近似表の更新は [月別作物モデル](monthly-crop-climate-v1.md) に記録する。以下の未完了一覧は基盤実装時点の状態である。


2026-10-05。計画の気候基盤と本体更新経路の実装記録であり、農業移行・統計表較正の完了報告ではない。

## 実装済み

- `earthlikeClimate.ts`: 計画の緯度別候補振幅、300kmの海岸減衰、内陸20日・海洋45日の位相遅れ。グレゴリオ暦の各月で解析積分し、日数加重年平均を補正する。日別平滑曲線も同じパラメータから評価する。
- `cellClimateNormals.ts`: 本体だけで動くセルAPI。球面上の海岸サンプルをKD木に格納し、最近傍探索する。海岸サンプルは陸地と海洋セルの中心間の球面中点であり、実際のVoronoi辺への厳密な距離ではない。誤差は地図のセル解像度に依存する。
- 小湖と地図外縁は海岸にしない。地域地図の境界までの距離に対して、既知の海岸が近いことを確認できないセルは `C=0.5 / regionalFallback`。全周地図は経度方向の外縁による不確実性判定を省く。
- 地理・気候の内容ハッシュで同月編集を検出する。海岸探索は地理変更時だけ。月平均はFloat32で48バイト/セル、Cは4バイト/セル。気候APIの返す月平均配列はコピーであり、読み手によるキャッシュ書換えを防ぐ。
- 降水換算は既存表示契約の1 proxy unit = 100mmを維持する。換算関数をUI非依存の `precipitationUnits.ts` に分離し、既存 `unitUtils.ts` は再exportする。月別降水は日数比例、`uniformAssumption`。
- 当月表示は初回呼出し日に依存せず、整数へ丸める。生成、レガシーロード、アーカイブのworld.replace、環境フェーズtickから更新する。暖房は共有表示値を使用し、値が未生成のフォールバックも同じ月平均曲線を使う。
- 年平均・人口・在庫・農地は気候再構築で変更しない。派生キャッシュは保存しない。ロードした旧表示値や月バケットでは新モデルの更新を抑止しない。

APIは `getCellClimateNormals(world, gridCellId, year)`。全セルを処理する拡張は `createCellClimateNormalsReader(world, year)` を処理の開始時に一度作成する。readerは同一の地図・設定を処理する間だけ使用し、編集後は再作成する。`extensions/hostCore.ts` から提供する。本体から拡張への依存は加えていない。

## Bria診断

再現コマンド:

```sh
node --import tsx scripts/diagnoseSeasonalClimate.ts \
  'temp/000.savdata/Bria 2026-10-05-18-35.fmg' \
  docs/calibration/bria-seasonal-climate-v1.json
```

[診断JSON](bria-seasonal-climate-v1.json)は元セーブを読取専用で解析したもの。旧12か月値は旧関数を各月21日で評価した浮動小数値であり、過去の月次更新を記録した実測履歴ではない。

5°C超日数は平滑曲線の各日中央の評価値から数えた値であり、観測された無霜日数ではない。1275の保存済み非農業キャパシティは4.935k、保存済み総キャパシティは10.656k。この保存値の差を現在モデルの農業生産として解釈しない。保存データには本体のlandUse内に農地配列がなく、診断JSONのlandUseは空。経済拡張の不成立理由、現在割当農地、潜在面積、RE表示の再現はまだ行っていない。

## 性能

Briaの10,001 gridセル、Nodeでの1回の生成と20回の反復処理で測定。実測値はJSONのperformanceに保存する。初回生成は約76ms、地理・気候ハッシュの確認は約3.6ms/回、当月整数配列の生成は約0.25ms/回。月平均キャッシュ480,048バイト、Cキャッシュ40,004バイト。source文字列配列・WeakMap・KD木構築中の一時メモリはこのバイト数に含めない。KD木は構築完了後に保持しない。

これはブラウザ全体のtick時間や旧実装に対する比較測定ではない。内容ハッシュの確認は同月にもO(n)で行うため、旧実装の月バケットだけのO(1)ゲートより処理が増える。多数セルのAPI読取りで毎セル全体検証を繰り返さないよう、batch readerを使う。

## 未完了の工程

- [NOAAの1991–2020平年値](https://www.ncei.noaa.gov/products/land-based-station/us-climate-normals)と南半球の一次観測資料による地点分割の較正・検証。候補値のMAE3°C基準達成を主張しない。
- 作物別の春作・冬作・スペルト・多年生クリの熱量、成熟日数、休眠・低温要求・樹齢の定義。FAOの[オオムギ資料](https://ecocrop.apps.fao.org/ecocrop/srv/en/cropView?id=1232)は春作90–120日、冬作180–240日を区別するが、これだけでは全作物の成熟熱量を確定できない。
- 作期と年収量・収穫月・労働月を一体化した経済拡張モデル、土壌水収支、灌漑面積別の適性。河川fluxの物理単位をこの実装で確定したものとは扱わない。
- 進行中の作期を保持する保存・移行、二重収穫の防止。
- 新しい気候入力軸によるオフライン較正、未使用標本の誤差評価、本体の近似表とREへの適用。既存 `foodClimateCalibration.json` は旧農業モデル用のまま。
- 拡張切替、RE、製品ブラウザの保存往復と代表地図でのtick性能比較。

基盤実装後、作期・年収量・収穫月・労働月・部分灌漑の接続と本体の再較正を実装した。月次土壌水収支、進行中の作期の保存、観測資料による較正は引き続き未完了。最新状態は上記の月別作物モデルを参照する。
