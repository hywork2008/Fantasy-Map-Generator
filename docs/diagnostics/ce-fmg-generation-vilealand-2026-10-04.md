# Vilealand の FMG → CE 都市生成障害

対象は拡張機能OFFで保存された `temp/000.savdata/Vilealand 2026-10-04-15-32.fmg`。元のFMGと検査入力CSVは変更していない。住宅バッチのdescriptor出力を利用し、削除済み都市とID 0を除く662都市を、CEと同じ初期グリッド・設定・seed、通常の最大8試行で検査した。失敗案プレビューを生成成功として数えていない。

## 再現と結果

| 結果 | 修正前 | 修正後 |
| --- | ---: | ---: |
| 生成成功 | 468 | 644 |
| 通常8試行で失敗 | 194 | 18 |
| タイムアウト・実行エラー | 0 | 0 |

176都市の失敗を解消し、変更前に成功していた都市の新規失敗は0件。残る理由は `unconnected-gates` が10都市、`fmg-road-mismatch` が8都市。城の配置・支線接続による失敗は、このFMGの全都市検査では0件になった。

```sh
npm run housing:export -- "temp/000.savdata/Vilealand 2026-10-04-15-32.fmg" temp/vilealand-ce-inputs.csv
npm run ce:audit -- temp/vilealand-ce-inputs.csv temp/ce-result.jsonl --workers 4
npm run ce:audit -- temp/vilealand-ce-inputs.csv temp/ce-failures.jsonl --failed-from temp/ce-result.jsonl --debug-dir temp/ce-debug
```

実測結果と未解決都市のID・名前・理由・元の街道の水面との重なりは、隣の `ce-fmg-generation-vilealand-2026-10-04.json` に記録する。全試行の探索情報は `temp/vilealand-ce-result.jsonl`、比較前の結果は `temp/vilealand-ce-baseline-all.jsonl` に保存している。JSONLと元のFMGはリポジトリに追加しない。

## 修正した原因

1. 水面の測量範囲と都市フレームが同じ場合、フレーム端の道路の描画幅・端部キャップだけが測量範囲の外にはみ出し、実際には乾いた入口を水面として拒否していた。道路の中心線がフレーム内にある場合だけ、描画範囲の外のキャップを切って判定する。内部の水面、範囲不足、不正な測量データは引き続き拒否する。
2. 城壁のない都市でも、外部アプローチが市街地セルに触れることを禁止していた。壁のない都市では乾いた市街地への進入を認める。河川・水面・城・堀の禁止領域は保持する。
3. 門の候補間隔を確保する間引きで、FMGが指定した残りの入口が消えていた。従来成功していた候補選択を保ち、候補が尽きた場合だけ別の適格な角を選ぶ。さらに測量済み水面によって内向き道路が孤立する門を選ばない。
4. 粗い編集メッシュの最近傍頂点が水面内や全辺禁止の頂点になる場合があった。2セル以内の使用可能な頂点へスナップする。元の入口が乾いている場合は、水面を越えて別の岸へスナップしない。元の入口が濡れている旧街道では近い陸地頂点を選ぶが、水面を横切る接続線は描かず、実際の道路探索には従来の禁止辺を適用する。
5. 小規模な城郭で、サービス棟などが既存の20m²最低面積を下回っていた。小さい棟だけ21m²以上へ調整し、区画内への収まり・棟同士の重なり・城門と庭の接続を引き続き検証する。城の導入失敗には候補辺ごとの具体的な診断を残す。
6. 外部街道が0本で広場もない都市では、城の支線の接続先が空になっていた。居住する中心区画への支線を作り、支線にも道路幅を含めた水面検査を適用する。

指定街道・門の削除や試行回数の増加では成功扱いにしていない。橋の生成規則を緩和していない。斜めの橋や未測量のフレーム外を通る迂回は追加していない。

## 残る失敗の扱い

残る都市では、元の予定街道が測量済み河川と重なり、入口周辺の陸地へのスナップまたは門への乾いた探索経路を確保できない。入口が水面に重なる都市と、入口は乾いていても予定経路に河川横断がある都市を、`inputRoads` と `routing` で区別できる。重なり自体は不正入力の断定ではなく、橋を含む接続に必要な診断情報である。

失敗入力の `fixedCrossings` は橋施設のないv3水面測量であり、CEが使える固定橋の情報がない。次はFMG街道と測量済み河川の整合を取り、安全な直角横断・両岸アプローチを連携入力へ渡すことと、CEの岸別の門・経路選択を検証する必要がある。単に生成試行やフレームを増やす作業とは分ける。段階6全体の性能施策を完了した扱いにはしない。

## 検証

- 提供FMGの完全なshare入力を保存した `src/city-editor/core/fixtures/vilealand-fmg-handoff-20261004.json` で回帰検査。元の街道sourceIndexの一致、外部道路数、メッシュ・城郭・橋交差の検証、城内棟の最低面積を確認した。
- 関連テスト50件、橋の関連テスト19件、型検査、変更ファイルのBiome、legacy UI・world writer・architecture検査を通過した。
- 実際の住宅バッチでID 104の成功とID 26の失敗を確認。失敗の住宅差は空欄になり、具体的な理由と全不採用試行の診断を保存した。
- CLIの途中保存・再開・重複防止・入力変更時の拒否を検査。実処理を1秒でタイムアウトさせた2都市は `generated: null` で保存され、上限を戻した失敗都市の再検査では両方成功した。
- 既存の `castleGeneration.test.ts` の「preserves a locked compound during a generation pass」は変更前のHEADを別ディレクトリで実行しても失敗した。城のロックを保つ再生成の既存障害として残る。今回のFMGからの新規生成の成功件数には含めない。

実ブラウザで全都市の描画を確認した結果ではなく、実際の生成処理をjsdomで実行した結果である。
