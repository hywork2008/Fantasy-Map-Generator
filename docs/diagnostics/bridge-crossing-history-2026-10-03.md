# 河川横断橋の歴史調査とFMGの時代別判定案

調査日: 2026-10-03。対象は河川そのものの長さではなく、道路が川を渡る橋の延長。史実・実測値と、FMGに設定する運用上限案を区別する。

## 結論

中世以前も多径間橋・浮橋による数百mからkm級の横断は存在した。現行の50mを川全体の横断可否に使う仕様は過度に厳しい。ただし、総延長が2kmある橋を、水深の大きい幅2kmの本流へどこでも建設できるという意味にはできない。

時代別に普遍的な「架橋可能な最大河幅」は定義できない。橋脚を建てられる水深・基礎地盤、流速・洪水・河床変動、船の通航、建設資金、保守体制で変わる。FMGには通常生成と特別事業の上限を分けることを提案する。

12km級は前近代の通常の都市橋では渡し場を選ぶ扱いが妥当。現代の橋・高架橋では12km級の実例があり、全時代共通の技術的不可能条件にはできない。

## 長さの定義

- 河幅: 横断地点の水面幅。季節や流路で変化する。
- 支間長: 橋脚・橋台などの支持点間の距離。
- 水上横断長: 道路が実際に水域を通る長さ。斜めに渡ると河幅より長い。
- 橋梁総延長: 水上部分に加えて陸上の取り付け高架・氾濫原上の区間等を含む場合がある。
- 浮橋: 橋脚の代わりに舟等で支える。固定橋と異なる洪水・通航・季節運用の制約がある。

橋脚を置けるなら、短い支間を連ねることで横断長を増やせる。総延長の記録を、支間長の技術上限へ代入してはいけない。

## 黄河とアマゾンから得られる判断条件

蒲津渡は河面の狭さ、緩い流れ等が浮橋に適していたと遺跡の公式説明にある。黄河全域を同じ条件にしてよいわけではない。航行・季節運用・洪水に応じて、浮橋、固定橋、渡し場を使い分ける。

アマゾン流域には現代の大型橋が実在する。幅が大きいというだけで技術的不可能とは判定できない。他方、リオ・ネグロ橋の成立は都市圏接続の具体的な需要・公共投資を伴う。小村の脇を流れる同じ幅の川にも自動的に同じ橋を置く理由にはならない。

FMGでの判断は、河幅・時代に加えて、横断地点の基礎条件、流路安定性、洪水、通航、都市や道路の重要性を加えるのが自然。資料から普遍的な数値を算出できない項目は、ゲーム上の明示的な近似として扱う。

## 時代別の運用上限候補

**次の数値は史実の世界記録・物理的最大値ではなく、実例を踏まえて提案するFMG用の暫定値。通常欄も平均的な橋長ではなく、自動生成で検討する上限。** 基礎条件が不明の場合は保守的に扱う。

| 設定 | 通常の自動生成で検討する横断長上限 | 特別事業で検討する範囲の上端 | 条件・根拠 |
| --- | ---: | ---: | --- |
| classicalAntiquity | 300m | 1,500m | ローマ等の土木組織を持つ国家はkm級の多径間橋を可能にする |
| earlyMedieval | 300m | 1,500m | 地域差が大きい。ローマ技術の継承・中国等の土木体制を条件にする |
| highMedieval | 500m | 2,500m | 安平橋。ただし多数の基礎を施工できる河口・浅水部等の条件が必要 |
| lateMedieval | 750m | 2,500m | 同じ多径間技術と資金動員。全河川に無条件適用しない |
| ageOfExploration | 1,000m | 2,500m | 石・木の多径間橋と浮橋。湿地上の超長大通路は別枠 |
| maritimeEra | 1,000m | 2,500m | 近世の恒久橋。通航と洗掘・洪水の制約を残す |
| preIndustrialEra | 1,500m | 3,000m | 鉄鎖吊橋等が利用可能。大支間は橋種に応じて判定 |
| steamEra | 2,500m | 4,000m | 蒸気施工機械・鉄橋。ヴィクトリア橋を基準例にする |
| industrialChemistryEra | 3,500m | 6,000m | 鋼・コンクリート・近代的な基礎施工を条件にする |
| petroleumEra | 5,000m | 10,000m | 大規模な道路投資と施工体制を条件にする |
| rocketryEra | 5,000m | 15,000m | 特別事業に現代の長大河口橋を含める。12kmは通常生成せず特別枠 |

後半の上端は特定の年代の「最大記録」を主張する値ではない。特別事業の寸法を許容するための検討範囲であり、上限内でも水深・支持条件・需要を満たさなければ架橋しない。湿地高架の6〜8kmや取り付け道路を含む17kmの例を、水域横断長の上限を一律に引き上げる根拠には使わない。

固定橋と浮橋の上限は最終実装では別にする。今回の確実な一次資料だけで時代別の浮橋最大長を一意に確定することはできないため、同じ表の値を浮橋へそのまま流用しない。

## FMG/CEの実装への提案

現状の `transport.maxBridgeSpanMeters` は、名前は支間長なのに実際には河川の幅全体と比較される。少なくとも以下を分ける。

1. `maxCrossingLengthMeters`: 通常の横断総延長上限。
2. `maxExceptionalCrossingLengthMeters`: 国家・大都市・幹線等の特別事業の上限。
3. `maxSingleSpanMeters`: 支間長。石アーチ・木梁・吊橋等の橋種別に評価する。
4. `supportsInWaterAllowed` / 橋種: 水中橋脚を置けるか、固定橋か浮橋か。条件不明を自動的に「置ける」とはしない。

これは新規フィールドの設計案であり、現行のデータ型に追加済みではない。

- 横断長は都市窓内の最大河幅ではなく、**道路の横断地点の両岸・交差角度**から求める。幅wに対して岸と道路がなす角θなら、単純な平行岸では横断長≈w/|sin θ|。曲線・島・複数水路では実際の幾何で測る。
- 橋脚を置ける場合は総延長と支間長を別々にチェックする。支間50mの橋でも複数径間で数百mを渡せる。
- 支持条件が不明な1〜2kmを、通常の村の木橋として無条件に生成しない。特別事業または浮橋・渡し場の候補にする。
- 12kmは全時代で通常の都市橋から外す。前近代は渡し場等、現代は条件を満たす特別事業だけ検討する。
- 97m程度のLeonは、50m超という理由だけで不可にせず、複数径間の通常橋を検討可能にする。実際の架橋には横断地点・橋脚等の条件も必要。
- 橋の可否は河川を描く形式と分離する。「架橋不可だから河川線を消して粗い水面セルへ変換する」という現在の結合は、次の都市生成修正で解消する。
- 既存shareに50mが保存されているため、デフォルト変更だけでは過去リンクを直せない。古いフィールドの意味・移行、FMG/CE/CG間の型の同期を明示する。

## 定数変更の実装（2026-10-03）

通常生成の上限を上表の値へ変更し、`src/utils/bridgeCrossingPolicy.ts` に一元化した。新規FMG descriptorは `transport.maxBridgeCrossingMeters` を出力する。CEはこの新しい明示値を優先し、旧 `maxBridgeSpanMeters` が50mまたは1,000mの場合は旧生成定数として時代別上限へ移行する。それ以外の有効な旧カスタム値は維持する。旧カスタム値が偶然50/1,000mの場合は旧定数と識別できないので、新フィールドで再指定する。未知・未指定の時代は300m。

これは通常の複数径間橋の横断上限で、単一支間の上限ではない。特別事業、浮橋別の能力、水深・基礎地盤、道路横断地点の実長計測は次の設計段階。CGはこのtransportを型として受け取るが、現状生成では参照しない。住宅比較JSON/CSVには実効上限を出力し、旧span名の列も互換用に残す。

架橋可否と水面表現の分離等、都市生成の幾何処理は今回変更していない。

### 実装後の検証

定数・旧入力の移行・FMG descriptor・CE入力・CSV・share読み込みの5ファイル51テストとTypeScript型検査、アーキテクチャ検査が通過。Leon（Oconland burg 4）は1,000mの上限で生成完了（入力2,286住宅、出力2,379住宅）。97mの川は架橋可能、12kmは通常対象外となる。

一方、住宅比較の既存テストではAlyatland burg 207（Goz'hass）が8案すべて不採用となる。単独再実行でも失敗し、同じ都市を旧50mポリシーで生成する一時的な比較テストは成功したため、上限変更によって表面化する都市生成の回帰である。定数を元に戻して隠さず、次の都市生成修正で対応する。生成全体の広範囲テストは長時間終了しなかったため中断しており、全テスト成功とはしていない。
