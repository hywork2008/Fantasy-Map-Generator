# Leon（Oconland、burg ID 4）の河川と城壁の調査

対象: `temp/Oconland 2026-10-03-11-51.fmg`、添付されたCity Editor shareリンク。

## 結論

池状の水面はFMGの湖ではなく、河川をCEが粗い都市セルに変換した結果である。描画される水域と城壁を切る水域が一致していないため、川が見えない場所にも城壁の欠落が生じ得る。加えてFMG→CEの受け渡しは川を町に近づけるため平行移動しており、FMGの位置関係をそのまま保存する設計ではない。

添付shareとアーカイブから現在のコードで再抽出したshareをそれぞれ生成したところ、同じ河川入力・水面セル・城壁構成で再現した。保存リンクだけの古いデータや、画面の表示不具合ではない。

## CEの原因

1. `src/city-editor/core/gen/site/siteInput.ts` の `unbridgeableOnSite` は、範囲内の最大幅と時代別の許容橋長を比較する。Leonは最大97m > 50mで、都市セル上の川なのでwide channelへ変換される。
2. `extractWideChannels` は川をconsumedに登録する。`extractRivers` がその川を除くため、通常の連続した河川の線は生成されない。`buildChannel` は範囲内最大幅を使った水路ポリゴンを作る。
3. `src/city-editor/core/generate.ts` の `applyWideChannels` は「セルの中心が水路ポリゴン内か」だけでセル全体を水にする。水路は幅約97mだが、都市メッシュは街区用の粗い114面。水路がセルを横切っても中心が外なら陸地のままで、中心が内ならセル全体が水になる。
4. この時点で水面は3面・2連結成分になっている。段階①の出力と最終出力で同じなので、後段の建物生成や描画処理が池を作っているわけではない。
5. `applyPlan` は水面セルをwater="sea"として保存する。`src/city-editor/render/svg.ts` はその面の輪郭を水面として描く。正確な水路ポリゴンの細長い連続形状は描画されない。
6. 一方、城壁は `splitDryWallRuns(loop.points, loop.segments, plan.waterPolygon)` により水路ポリゴンとの交差で切る（`generate.ts`）。城壁が避ける連続した水路と、画面に見える離れた水面セルが違う。セル化による粗い岸の輪郭も都市・城壁計画に影響する。

城壁には道路の門や城塞との接続に由来する切れ目もあるため、画像のすべての切れ目をこの不具合と断定してはいけない。ここで確認した不整合は、河川の入力が連続しているのに水面が非連結であり、城壁の水域判定が別形状を使っている点。

## FMGの原因・関連事項

`src/services/burgSiteDescriptor.ts` の `collectRivers` は、river.cellsにburg.cellが含まれると `snappedToBank` を適用する。FMGは都市のマーカーを川岸へずらし、川を誇張して描いているため、都市規模のCEでも川岸の町になるようにする既存の補正。

Leonでは補正前の中心線距離658.2mを、川幅の半分31.6m + 都市半径の30%（140.1m）=171.7mへ縮める。局所座標（x=東、y=北）での平行移動は約(-149.0m, +463.2m)、移動量約486.5m。町の半径467mより大きい。

道路と地形を同じ量だけ動かす処理ではないため、「FMGの町・川・道路の相対位置を厳密に反映する」要件には合わない。池化を修正してもこの差は残る。

また、代表幅63.2mは最接近セグメントの開始頂点の幅で、町に最も近い位置の幅を補間していない。CEは範囲内最大幅97mを水路全体に使う。これらの幅の扱いは受け渡しの改善候補。ただしLeonは代表幅でも50mを超えるので、この代表幅の差だけを直してもwide channelへの分岐は変わらない。

FMGの `Rivers.getRiverPath` はCatmull-Rom曲線で川岸を描くが、descriptorはmeandering点を折れ線としてクリップする。町が曲がり角にあるケースでは、描画曲線と受け渡す折れ線の距離・方向に差が出る可能性がある。今回の池化の原因としては確定しておらず、位置補正を見直す際に確認すべき項目。

`burg.type="Lake"` は都市の分類名で、水域生成に用いる湖の形状ではない。`downstream.terminal="lake"` も遠方の終端情報であり、今回の池はその湖を配置した結果ではない。

## 切り分け実験

| 条件 | 結果 |
| --- | --- |
| 添付shareをそのまま生成 | 水面3面・2成分、river groupなし |
| FMGから再抽出して生成 | 同じ結果 |
| FMGの平行移動を逆算して戻す | 水面セルの位置は変わるが3面・2成分、river groupなし |
| 許容橋長だけ1,000mに変更する診断用入力 | wide channel分岐を通らず、river groupが1本生成される |

最後の実験は処理分岐の確認であり、時代の許容橋長を増やす修正の提案ではない。

## 推奨する修正順序

1. **CEの水域表現を統一する。** 水路の連続ポリゴンをCityDocumentに保持し、描画・建物・道路・城壁で同じ形状を使う。中心点によるセル全体の水面化だけに依存しない。街区を水路で分割する方式、または街区と独立した水域形状を保持する方式を検討する。
2. **橋の可否と川の表現を分離する。** 50mを超えることは橋を架けない理由にはなるが、川を連続して表示しない理由にしてはいけない。広い川はその両岸を保存し、道路には渡し場等を適用する。
3. **FMGの川岸補正を見直す。** 実座標に基づくriver bankと町の位置、誇張された表示上の位置を区別する。補正なしの実形状を保持し、補正方針を明示する。河川のみ移動する補正を残す場合は道路との交差関係の再計算も必要。
4. **川幅・曲線の受け渡しを改善する。** 最接近点の幅を補間し、可変幅と両岸をCEでも利用する。FMGの表示曲線とdescriptorの折れ線の違いを別途検証する。
5. **回帰テストを追加する。** Leonのような50m超・100m程度の川、粗いevolutionメッシュ、曲がり角の町を対象に、水路の連続性と描画・城壁・道路の水域一致を検証する。既存のkm級河川テストは水面が存在することを確認するが、細いwide channelの連続性までは保証していない。
