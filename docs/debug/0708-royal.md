ご質問の2つの事象は、いずれも現在の軍事AI（拡張機能のNobility等）の仕様・ハードコードされたロジックによるものです。

現在のコードベース（`timeEngine.ts`, `localSkirmish.ts`, `regimentMovement.ts`）を調査した結果、それぞれの理由は以下のようになります。

### 1. State 2の第5連隊が敵地で「待機状態（waiting）」なのはなぜか？

連隊の `actionStatus` は毎ターンの最初に必ず `"waiting"` にリセットされ、**そのターン中に局地戦（Skirmish）などの戦闘イベントが発生した場合のみ `"battled"` に切り替わる**仕様になっています（`timeEngine.ts` 89行目）。
敵地にいるにも関わらず戦闘が発生せず「待機」のままになっているのは、以下のいずれかの条件によって交戦がスキップされているためです。

* **孤立保護ロジック（Isolation Protection）が働いているため**:
  現在の局地戦AIには、「自軍が敵より劣勢であっても、後方に味方の増援が届く範囲にいる場合は、無駄な消耗戦（毎日の局地戦）を避けて包囲戦などの本格的な処理を待つ」という仕様があります（`localSkirmish.ts` 218行目 `hasExternalReinforcement`）。このため、一時的に睨み合いのような状態（waiting）になります。
* **直接の交戦圏内に「敵の正規軍（連隊）」がいないため**:
  敵地（敵のセル）であっても、交戦半径（`SKIRMISH_CONTACT_RADIUS`）内に直接ぶつかる敵の「連隊（Regiment）」ユニットがいなければ局地戦は発生しません。
* **遭遇している敵が「近衛（Capital Guard）」であるため**:
  後述の通り、近衛部隊は局地戦からシステム的に除外されているため、相手が近衛だと戦闘が発生せず、結果としてこちらも待機状態のままになります。

### 2. State 1の近衛（Royal Guard）が敵の真っ只中でじっとしているのはなぜか？

近衛部隊（`isCapitalGuard: true` の連隊）は、**軍事AIの移動・戦闘システムから明示的に除外（無視）される仕様**になっているからです。

* **自動移動から除外**:
  `src/generators/regimentMovement.ts` の `advanceAllRegimentMovement` ループ内で、近衛部隊は一番最初にスキップされ、経路探索や反応移動を一切行いません（614行目 `if (r.isCapitalGuard) continue;`）。
* **局地戦から除外**:
  `src/extensions/nobility/generators/localSkirmish.ts` の局地戦処理でも、近衛部隊は攻撃側・防御側の双方の対象リストから完全にフィルタリングされて除外されます（196〜201行目）。

そのため、ユーザーのUI操作（ドラッグ＆ドロップ等）や何らかのイベントで首都から外へ移動してしまった場合、AIが「防衛のために攻撃する」「安全な首都へ退却する」といった判断を一切行わなくなり、結果として敵の真っ只中に取り残されても「ただそこにいるだけ（じっとしている）」という状態になってしまいます。

## 3. 調整

### 3.1

孤立保護ロジックは、自軍の兵数が敵の数より上であれば援軍を待たず戦うよう修正する。
周りの敵の合計の1.5倍以上なら戦う。
相手がCapital Guardなら積極的に狙う。

### 3.2

Capital GuardはCapitalの外に出されたらCapitalに戻る。
Capital Guardには王や皇帝が必ず混じるものとする。
為政者は捕まえる事が出来る。
誤って殺してしまう事もある。
友好国のCapital Guardへは攻撃しない。
敵対国のCapital Guardへは積極的に攻撃する。
